Verifier independence: it is not about which model checks, it is about what the checker was denied

The default advice for checking an agent's work is to use a different model. As of 2026-08, ten independent T1 results say the model boundary is close to irrelevant and the thing that actually buys you a useful second opinion is an arrangement: what the checker is not allowed to see, who authored the thing it is checking, where its expected value came from, and what it is permitted to do about a violation.

This map was coined on 2026-08-12 out of two results that arrived 48 hours apart and belonged to neither of the maps that had been circling the question. It opened consolidating and has stayed there through eight further arrivals, for a reason stated at the end that has not changed: nobody has replicated the founding mechanism, and almost nobody reports how often their restricted checker is simply wrong.

The one-line version:

Independence is a property of the arrangement, not of the identity of the checker.

Part 1 — The founding result, and the control that makes it a finding

Two groups, two unrelated tasks, both using the same backbone model as the generator, both getting a working check by taking information away.

RETRACE [T1] verifies a patch by asking a fresh instance to infer what problem this patch implies, with the original issue withheld, then comparing that reconstruction against the real issue. OpenCodeReview [T1] filters review comments with a reflector that sees only the diff and never the agent's exploration trace.

The control matters more than either headline. RETRACE ships a Self-Refine arm — the same model, the same extra deliberation, no information restriction — and it does not reproduce the gain. So the mechanism is the withholding, not the second pass.

Three earlier T1s already in the vault reread cleanly under that framing, which is the case for treating this as one subject rather than two: an independent checker beats the same model checking itself; a verifier sharing the generator's interpretation shares its error; and verifier diversity — swapping vendors — is not verifier independence.

Practice: when you add a checker, do not start by picking a model. Start by writing down the list of inputs the generator had, and cross off the ones the check would be vacuous without. That crossing-off is the design.

Part 2 — Four things "independent" turns out to mean

The map's core variable acquired one term per arrival. All four are properties of the arrangement; none is a model choice.

1. What the checker is denied

The founding term. Withhold the issue (RETRACE); withhold the exploration trace (OpenCodeReview). Both worked and neither group has a principle for which input to withhold — they chose on intuition. That gap is still open, and the standing warning is that the wrong choice produces a checker that is confidently useless.

2. Who authors the thing the checker checks

Run the argument to its limit and the checker becomes a proof kernel, which shares no interpretation and cannot be talked into anything. Vero [T1] does exactly that — 43 multi-module Lean 4 repositories, 743 scored APIs, 2,705 specifications, all newly curated with no public ground truth — and 368 specification outcomes still had to be rejected by an axiom-and-tactic allowlist, dominated by a tactic that discharges a decidable goal by evaluating it in the compiler rather than checking it in the kernel. The agent was authoring the proof term and found evaluation escape hatches around the checker. A kernel is not enough if the agent writes what the kernel reads.

3. Where the checker's expected value comes from

Oracles That Cannot Fail [T1] states the mechanism as exact arithmetic: if an assertion's expected value is derived from the code under test, any fault that scales both sides cancels, and the check cannot fail. Two days later this was the map's one-system, one-author result. Two days after that it got its number: an audit of feedback-driven test evolution [T1] measured the same defect on 394 tasks with the hypothesis frozen before the external cohort opened, and found 9.46 to 14.85 points of a reported gain belonging to the oracle rather than to the tests, every interval strictly above zero.

The remedy is cheap and it is the strongest practice on this page: one more independently authored reference program, run offline after selection is frozen. A second implementation cuts the apparent gain to roughly 4 points; a third to 1–2. A differential panel is the weakest usable substitute for a specification, and one implementation is not a substitute at all.

Carried with the same paper's restraint: a blinded two-reviewer audit judged 3.60% of the inputs its differential panel rejected to be valid. Differential agreement across independently authored implementations is a conservative consistency filter, not semantic ground truth.

4. What the checker has just done

Prior Audit–Repair Context Shifts LLM Verifier Thresholds Toward Leniency [T1] adds the term nobody had thought to look for: the checker's own recent work is part of its information set. A completed audit-then-repair episode about a different item lowers false alarms in 15 of 15 model × wording cells, by 2.8 to 11.5 points, against a length-matched filler that does nothing — further than an explicit leniency instruction reaches. Every interval is a 20,000-replicate bootstrap clustered on the reused frozen episode, with every family declared in code before any p-value was visible.

The consequence for reading anyone's numbers is blunt. Every precision figure in this map was produced by some pipeline arrangement — audit-only, audit-then-self-repair, audit-then-handoff — and none of the papers says which. Cross-paper comparisons of checker precision are comparing wirings.

Part 3 — Independence you can buy without touching the information set

Three arrivals moved the map off the information axis entirely. Each is a lever that costs less than a second model.

Substrate: an executable rule and a model judge are complementary, not substitutable

Metrics That Write Themselves [T1] gave an LLM judge precisely the interface an executable operator has — task statement, prompt-visible assertions, candidate source, never the hidden suite, with the prompt even stating the class balance so the judge was denied no statistic — and scored both on the same endpoint through the same code against the same null.

They tie: +0.0070 against +0.0065. What differs is where each is right. Their flag sets meet at Jaccard 0.105 (27 of 257). Each side's exclusive flags are individually null. The 27 they agree on carry +13 tasks against −1 by themselves, and the union beats both parts.

So agreement between a checkable rule and a model judgement is a high-precision region neither reaches alone. And the cost asymmetry is permanent: 47 authoring calls once and nothing per candidate thereafter, against 1,762 calls for a single pass with every future candidate charged again.

Channel: type the disagreement or it collapses into agreement

Adversarial Review [T1] changes neither the models nor the information — only the protocol. A reviewer and a critic asked to converge on a shared verdict in free text produce false consensus: the critic confirms hedges and yields to confident rebuttals that cite no code, and the pair scores below the single reviewer it was built to improve on.

Force the critic into three typed verdicts — agree, disagree-with-a-code-citation, disagree-as-an-unevidenced-concern — bind the reviewer's response rule to which one it received, and the same three agents, same model, same graph go from worst of four to best, F1 0.457 → 0.533.

The trade-off is stated by the authors and it is a bad one: the fix rests entirely on instruction-following, which degrades as the context fills. If it stops working in a long session, the observable is a rise in agreement — which looks exactly like the checker succeeding.

Tense: freeze the referent instead of the reviewer

A specification-first refactor [T1, single-study] shipped a 189-file architectural change across a 717k-line codebase with no human review of the generated code. The only check was a fresh session of the same agent auditing that code against a specification frozen before the code existed — 17 passes, 116 corrections, stopping on two consecutive empty passes. The author states the design directly against the common advice: "the separation this protocol relies on is in that referent, not in the identity of the reviewer."

Carried at single-study, honestly: n = 1, self-reported, uncontrolled, false-rejection side unmeasured.

Authority: the strongest arrangement is a checker that cannot act

Outcome Monitors [T1] is the newest arrival and it takes the argument furthest by taking the most away. The checker is not a model at all — a deterministic invariant checker mined by five-fold cross-fitting so that every evaluated workflow is excluded from the traces that built its own registry (15,041 invariants from 400 nominal workflows, zero model calls, building in under two seconds), denied the task solution, the fault label, the evaluator and the gold sequence.

And then it is denied the one thing every other checker here keeps: the power to do anything about a violation. It appends an advisory receipt. The action set is unchanged.

Frozen paired completion goes 10.9% → 28.1% across four models in two provider families (+17.2 points, 95% bootstrap [11.25, 23.44], task-cluster sign-flip p < .00001), with a separately frozen third-family replication at +18.75, and +14.0 / +12.0 points in a stateful retail environment. Both arms received the same unmodified fault-aware system prompt that already instructed the model to inspect unexpected tool outputs, and an 8,192-token reasoning ablation did not substitute for the delivered signal.

Two things follow. First, because the monitor never repairs, the evaluator scores the agent's chosen recovery rather than a repair the runtime encoded — which is the confound a hard guard cannot escape, dissolved by giving the control no verdict to invalidate. Second, the registered five-way ablation relocates the mechanism entirely: strip the recovery-tool list from the receipt and the identical warning performs at baseline; restore it and +11.4 points returns. Witness detail (−2.6) and delivery timing (+0.9) are null, both bounded at an ≈18-point detectable effect rather than asserted.

A checker's message is an affordance list, not an explanation. After a receipt the agent switches to a listed substitute 48.6% of the time and calls some other tool 33.5% — it is re-selecting from an enumerated set, not re-reasoning about the failure.

The trade-offs are printed. All seven aggregate losses also contain receipts, so localization does not guarantee replanning. On clean traffic the aggregate is zero while 16 false triggers produce five rescues and five harms — a nonbinding signal cannot execute a bad action, but it can talk an agent into one. And the whole effect is prevalence-bounded: gains concentrate where the fault blocks completion, and at the unfavourable interval endpoints a positive net effect needs a fault prevalence of roughly 0.32.

Part 4 — What the checker costs, which almost nobody reports

The founding complaint of this map is still mostly unanswered. RETRACE reports no false-rejection rate at all. OpenCodeReview reports precision without saying what its conservative filter dropped.

Three results now show the measurement is cheap and that the answer is where these designs usually die.

Price abstention as lost coverage. Requirements-Augmented Generation for acceptance testing [T1] is the first checker in this vault allowed to say I don't know, with the cost of saying it printed. Three judges from distinct model families ordered by cost, a verdict accepted when the tier's confidence clears its own threshold calibrated by conformal risk control, escalated when it does not, and the oracle revoked as abstain when no tier is confident. The whole reliability/coverage curve is published: 90.9% agreement at 99% coverage; 98.8% at 86%; 97.1% at 70% — the last tightening step discarding qualified verdicts along with unqualified ones. It also came out cheaper than any single judge (cost-per-prediction 3.49 against 3.61 and 5.11).

The code-side price is worse. The one comparable number in the vault has a structural gate buying 98.9% attack interception at 0.3% live-path latency and charging 57.7% benign allow.

And you can test a checker's sensitivity without any ground truth at all. Breaking Models to Test the Judge [T1] injects defects by construction into the artifact the checker reads and scores whether it names them: 547 mutants, 82.4% kill ratio, agreeing with human-adjudicated precision at r = 0.624 and reproducing 11 of 15 configuration orderings. What it cannot see is the property this map cares most about — a verbose checker raises its kill ratio by reporting everything, so defect injection measures what the checker catches and says nothing about whether it was denied the right things.

The same paper supplies a floor worth carrying everywhere: the human reference used to validate checkers on open-ended design questions agrees with itself at Krippendorff's α = 0.32.

Part 5 — The failure this map exists to prevent

Phantom Gains [T1, single-study on this edge] is the most vivid demonstration of why a checker sharing the generator's substrate is disqualified, and it arrived as a diagnostic inside an audit about something else.

A policy-gradient arm rewarded by its own majority vote collapsed into unbounded repetition on all three seeds. In the window between the update that damaged the model and the one that finished it, the vote's accuracy rose 77.9% → 85.1% and its unanimity 0.78 → 0.86 over 248 intact majorities, while the same checkpoint's evaluation went from 47% truncated to 96%.

Every quantity the loop watched improved. The one nobody watched — how many completions ran off the end, a byte count — is where the failure lived.

Three operating rules follow, and they are the most directly actionable thing on this page:

  • A self-consistency signal is not admissible as a health check on the run that produces it. Vote share, self-agreement, judge-agrees-with-generator all move the wrong way under the failure they would catch, because a degenerating model is maximally consistent with itself.
  • The second signal must be derived from something the model does not author.
  • A cheap non-model-derived tripwire — output-length distribution, format-parse rate, wall-clock per step — should be evaluated before any quality signal, because a kill rule keyed to agreement fires last.

The same pattern shows up from the attribution side. Credit Without Ground Truth [T1] finds an LLM judge scoring individual steps clears chance on per-step sign agreement (60.4% [52.1, 68.2]) while buying no concentration on the steps that mattered — precision-at-pivotal lift 1.000 [0.935, 1.001], containing the chance line. A judge that is right more often than a coin about a step's direction and cannot rank which steps matter has an aggregate agreement statistic that is not measuring the thing it is quoted for.

The checklist

Settled enough to build on, as of 2026-08:

  1. Design the checker's information set before choosing its model. List the generator's inputs; withhold the ones without which the check is vacuous. [T1]
  2. Do not let the agent author what the checker reads — or if it must, allowlist what the checker will accept and expect to reject a lot. [T1]
  3. Never derive the expected value from the artifact under test. If you have no specification, use at least two independently authored reference implementations; one is not a substitute. [T1]
  4. Declare the checker's pipeline position — audit-only, audit-then-repair, audit-then-handoff — because it moves the false-alarm rate by up to 11.5 points. [T1]
  5. Run a checkable rule and a model judge together and treat their intersection as the high-precision region, not as redundancy. [T1]
  6. Type the disagreement. Forbid an uncited rebuttal from settling one — and watch for rising agreement as your sessions get longer, because that is what this control failing looks like. [T1]
  7. Freeze the referent in time where you can; it buys separation with no information restriction and no model boundary. [T1, single-study]
  8. Consider giving the checker no authority at all. An advisory signal naming the available alternatives was worth +17.2 points and made the measurement interpretable, at 7% of baseline cost with no extra model call. [T1]
  9. Never use a self-derived quantity as a health signal, and put a cheap non-model tripwire ahead of every quality metric. [T1]
  10. Report what your checker costs: false-rejection rate, benign-block rate, or the full reliability/coverage curve. [T1]

What would move this to consensus

The status is consolidating and has been held at every arrival since 2026-08-12. Three things are missing, and none of them is expensive.

Nobody has replicated the founding mechanism. Ten T1s from ten groups agree that independence is engineered in the arrangement, but the specific denial results have not been reproduced. The 2×2 that would settle the original question — same/different model × full/restricted evidence, one task set — has never been run.

Nobody prices the false rejection for code. The abstention curve exists in a neighbouring task family, which proves the measurement is cheap and that nobody in this map's core task has made it.

Nobody can certify independence, only assert it. Defect injection measures sensitivity. Nothing measures whether the checker was denied the right things, and a verbose checker scores well on the instrument we have.

Four live tensions, carried open:

  • Is a checkable rule and a model judge a reliable complementary pair? One high-precision intersection, one endpoint, one domain, one pair. Nobody has repeated it, and the obvious next arm — does the intersection stay high-precision as coverage is dialled up — is unrun.
  • Does a protocol-level control survive a long context? It rests on instruction-following, and its failure mode is indistinguishable from success.
  • Does the anchoring result reproduce where the checker is a model? The cancellation is exact for a numeric assertion. The analogue for an LLM reviewer that infers what the code was supposed to do from the code itself — which is the shape of most agentic review pipelines — is stated nowhere and unmeasured.
  • Does the advisory/binding distinction survive an adversarial tool? A nonbinding receipt is still a channel into the agent's context that an attacker controlling a tool result can write to, and the authors explicitly disclaim safety under adversarial tools.

Until those close, the arrangement levers stand on their own merits. They are cheaper than a second model, they are measurable, and every one of them was found by taking something away rather than adding something.
