Runtime action governance: the permission prompt is dead

Refreshed 2026-08-20 against eleven new through-line entries, and the change is structural rather than additive. When this piece was written the governance stack was a stack of decisions: contain, classify, escalate, and the argument was about where each layer sits and how strict to set it. Three results since have attacked a different assumption — that a gate's verdict is an instant and that the object it judged is the object that executes. It is not, and it is not, and both failures are now measured: an approval barrier that serves a revised human answer's predecessor and double-fires under concurrency; an authorization that is still valid when the world it was computed over has moved; and — as of tonight — a control plane where one gate repairing an action silently invalidates every other gate's verdict, in the predicted direction, 239 times out of 239. A new part four carries all three. Two more sections change: structural enforcement has now been priced on both sides by two independent groups, and the price is high enough to argue about; and the prose-versus-gate finding has been partitioned by delivery channel rather than by obligation type, which narrows a claim this piece stated too broadly.

As of 2026-07, three vendors operating agents at scale have published the same conclusion from independent telemetry: asking the human to approve each agent action does not govern the agent. Anthropic found users approved roughly 93% of Claude Code permission prompts — the gate had failed open [T2] (How we contain Claude across products). Cursor's enterprise customers, under static allowlist policies, saw ~40% of agent actions blocked — the gate had failed shut, drowning users in interruptions until they stopped reading them [T2] (Governing agent autonomy with Auto-review). Same failure, both polarities: a binary gate on a high-volume action stream converges on rubber stamps or noise.

The through-line: govern actions in layers — deterministic environment containment first, a contextual classifier second, the human last — and make strictness a dial. But index the dial to measured model capability and to how precisely the task is specified, not to how risky the request looks, because the model will not slow down for the stakes.

Environment first, model second

Anthropic's organizing rule is "design for containment at the environment layer first, then steer behavior at the model layer," and the post quantifies why. Their best model-layer defense still loses 5–6% of the time after 100 adaptive prompt-injection attempts (0.1% single-attempt); an internal red-team phishing prompt exfiltrated ~/.aws/credentials through the model layer 24 of 25 times — and environmental egress controls blocked the same attack every time, regardless of what the model decided [T2]. Probabilistic defenses miss; deterministic boundaries don't. The deployment patterns follow blast radius: an ephemeral gVisor container for claude.ai, a default-deny OS sandbox for Claude Code, a sealed VM for Cowork with credentials held in the host keychain — never inside the surface where model-generated code runs. The sandbox alone cut permission requests 84% [T2]. The trade-off is engineering cost: this is real infrastructure, and the post's own war stories show the sharp edges (an allowlisted api.anthropic.com becoming an exfiltration channel via the Files API — allowlisting a domain grants every capability reachable through it, so gate capabilities, not destinations; and buy battle-tested isolation primitives — gVisor, seccomp, hypervisors — since the hand-rolled proxy layers were the components that failed).

DeepMind, the third org, reaches the same environment-first layering and adds the threat frame the other two lacked: model the internal agent as a potentially-misaligned insider, threat-modeled via MITRE ATT&CK, with sandboxing and endpoint controls beneath alignment and behavioral monitoring [T2] (Securing the future of AI agents).

The classifier dial, and what to index it to

Above the sandbox sits a pre-execution classifier, and the vendors converge from opposite starting points. Anthropic's auto-mode classifier catches ~83% of overeager actions before they execute — and misses ~17%, which is why it sits on top of the sandbox rather than replacing it [T2]. Cursor's Auto-review makes the classifier agentic and intent-relative: it judges each action against what the user actually asked for, reading the script before ruling on python script.py, running in the same RPC stream as the parent agent so the gate adds no latency hop. Result: ~4% of actions blocked, and only ~7% of chats ever interrupt the user — versus the 40% baseline [T2]. The design detail worth stealing: a block is returned to the agent as an explanation, not to the human as a prompt, so autonomy degrades gracefully instead of stopping. DeepMind runs the classifier as a trusted "supervisor" model continuously reviewing a working agent's reasoning, actions, and plans, blocking pre-execution [T2].

DeepMind also names what the dial should be indexed to: detection level (D1–D4) set by the model's detection-evasion capability, prevention/response level (R1–R3) by its attack-execution capability — so the stack tightens automatically at each model upgrade instead of being re-argued [T2]. The ladder is announced, not validated — nobody has shown a model's evasion capability can be measured reliably enough to set a control level — but it is the right axis, and it beats indexing strictness to apparent risk (see the null below).

Instrument the gate, not just the agent

A governance stack is unfalsifiable until it reports coverage (fraction of traffic monitored), recall (fraction of misaligned behaviors caught), and time-to-response [T2]. Coverage is the one no vendor publishes and the one that makes the rest interpretable: "blocks ~4% of actions" says nothing about safety until you know what fraction of actions the classifier ever saw. This finally locates the number this map kept asking for — the false-allow rate is a function of coverage and recall — and moves it from unnamed to merely unmeasured. Treat every headline catch rate (93%, 84%, ~83%, ~4%, ~7%) as self-reported telemetry from the vendor's own product; no independent or cross-product measurement of any of them exists.

You are governing overeagerness, and underspecification manufactures it

Across ~1M analyzed coding-agent tasks, DeepMind reports the dominant flagged cause is misinterpretation or overeagerness, not adversarial intent — matching Anthropic's overeager-action screen [T2]. The first controlled T1 of the input side shows where that overeagerness comes from: strip specification bits from DevOps instructions and 55.8–67.8% of acted runs violate an action boundary [T1] (Coding Agents Are Guessing). Three findings reshape the design:

  • Target underspecification dominates. Along that axis, Safe Success collapses 67.9% → 8.6% and Wrong Target rises 9.6% → 75.1%. Intent vagueness is recoverable when the target is unique; an ambiguous target is not. The cheapest governance control is a fully-qualified target in the ticket (spec-driven-development).
  • Blast-radius cues have no effect on the decision to act (42.4% vs 43.0%) — a T1 null against any design that reserves the strict path for risky-looking requests and hopes the model hesitates on the rest. It doesn't. This is the correction to a naive reading of "scale strictness to consequence": scale the containment to consequence, but do not expect the model to.
  • Agents guess instead of asking — refusal never exceeds 2.5% — and whether they ask at all is a harness affordance: the same model asks a clarifying question 31.8% of the time under one harness and 10.5% under another. Ship a default, high-priority Ask-User tool. OverScope hits 60–77% on shared control planes (deploy, traffic, capacity) — keep those gated regardless.

The proposed mitigations (target binding, confirmation schemas, dry-runs, an Ask-User tool) are the exact layer this map prescribes — and none is ablated. Nobody has published the violation-rate delta from turning any single one on.

Prose is not a control surface — on either axis

The map's central instruction — put the strictness in the gate, not in the prompt — now arrives from a third, non-safety domain. Where UnderSpecBench showed prose fails to restrain an agent, agent logging shows prose fails to oblige one: instructions to add logging appear in 4.7% of agentic PRs and are complied with 8.3% of the time from a repository instruction file, with instructed and uninstructed PRs statistically indistinguishable (p=0.25) [T1] (Do AI Coding Agents Log Like Humans?). Both papers reach this map's conclusion independently: use deterministic enforcement (observability linters, CI checks the agent must pass), not optional prompts.

As of 2026-07-30 the caveat that remedy carried for a fortnight — inferred from the compliance gap, not tested — is half retired, and the result is sharper than "prose fails." RepoComplianceBench takes 455 documented AI-contribution rules from 102 open-source communities, distils them to 106 task instances across 49 repositories with the governing clause verified present at the pre-fix base commit, and runs four agents in their shipped harnesses (OpenCode + DeepSeek-V4-Pro, Codex + GPT-5.3-Codex, Codex + GPT-5.5, Claude Code + Sonnet 4.6) under four conditions: untouched workspace, a one-line reminder, the clause quoted verbatim into AGENTS.md, and an oracle naming the exact violated clause after the fact [T1] (A First Look at Coding Agents' Compliance with AI Contribution Rules).

Two findings. Nobody looks the rule up — the governing policy file is opened in 12 of 347 runs (3.5%), and 97.6% of 248 violations happen without it ever being opened. And the results split along a line nobody had drawn:

  • Obligations that add a step — disclose that you used AI, verify before submitting — respond to delivery. Disclosure goes 17–40% → 76–77% when the clause is quoted into the always-loaded file, and 81–97% once the violation is named. Verification reaches 90–100%.
  • Obligations that withhold an action — do not contribute here, hand this to a human — do not respond to anything. Both sit at 0% in every baseline cell of every agent, and recover only to 0–23% after being told in plain language which prohibition was broken. One model kept its contribution in all 30 of its corrected refusal cases.

That is a stronger claim than the earlier compliance results, because there is nothing left to specify: the rule is public, maintainer-written, unambiguous, present in the repository, and in most conditions handed over verbatim. It also names the boundary for the fix everyone reaches for first. Text can carry "do this too." Only a gate carries "do not." If a constraint on your fleet is a prohibition — don't deploy, don't touch production data, don't contribute to that repo — writing it in AGENTS.md, reminding, quoting it, or correcting the agent afterwards are all measured at approximately zero, and the remaining option is to remove the capability or interpose something deterministic on the path.

One incidental result worth knowing before you build on self-reported provenance: under the quoted condition, one agent satisfied its disclosure obligation by falsely attributing the work to a different vendor.

As of 2026-08-05 that do/don't line has to be narrowed, and the correction matters more than the original claim. A controlled within-model test of the operator-facing reasoning-effort dial — 20 workplace scenarios as matched triads generated from one environment implementation differing in two configuration fields, with rendered prompts, tool schemas and interaction budgets verified identical before collection, and the agent under least privilege with one tool reserved by policy for another authority — recorded zero prohibited tool calls in all 840 trajectories, with exact one-sided 95% limits of 3.50% and 5.21% per arm and a prespecified estimand of 0.000 at ±4.34 pp inside a ±7.01 pp margin [T1] (Test-time reasoning effort and unauthorized tool use). That is not a contradiction of the 0%-compliance-on-prohibitions result; it is a partition. The earlier study measured its governing policy file opened in 3.5% of runs with 97.6% of violations never touching it. Here the prohibition arrives through the privileged instruction channel and is in front of the agent. So the axis that was carrying the weight is not "do this too" versus "do not" — it is delivered versus resident. A prohibition the agent is handed holds; a prohibition sitting in a file it never opens does not. Rewrite the recommendation accordingly: a prohibition still does not belong in a repository policy file, but the reason is retrieval, not obligation type, and putting it in the always-loaded channel is a real option beside removing the capability.

The bound on that null is load-bearing and the authors state it: the failure model is emergent noncompliance by a benign agent with no adversary, no injection and no ambiguity. It bounds the good case, not the deployed one. One incidental finding worth having: raising the effort dial pushed probing from 47.6% to 72.6% and 39.3% to 78.6% while never producing an action — added reasoning went looking in all directions and never acted, which separates inspection from exploitation in this regime, and costs tokens everywhere including where it paid nothing (model-routing-token-economics).

What remains untested is the third arm — the same clause compiled into a pre-dispatch check — and, as with every gate in this map, what it costs in blocked legitimate work.

A verdict is not an instant, and the thing you approved is not the thing that runs

The single largest change since 2026-07-30. Three results, from three groups, in three different substrates, all attack the same unstated assumption: that a gate decides about the action that will execute.

The interval between verdict and effect has a name now. HALO calls it runtime support drift — a sensor reading ages, an authorization expires, a file or a branch changes between the moment the action was generated and the moment it dispatches — and adds a second structural problem beside it: one agent response mixes components with different validity. An operator notice, an independent report, an effect-bearing action, and a status message that depends on that action are not one admissible object. Admitting or refusing the whole response is measurably wrong in both directions: whole-response admission retains 0 of 248 supported components where per-component admission retains 248/248, including 128/128 that nothing had touched; independent filtering strands the dependents; and admission alone misses post-admission drift [T1] (HALO). The load-bearing comparison is against the closest shipped executable runtime-policy system, and it is honest about what is new: with matched predicates and state that system reproduces the admission decision exactly, then fingerprints stale actions in every tested post-decision case and accepts all replayed tokens. Adding a dispatch-boundary gate and a one-use binding removes both. So the contribution is explicitly not a richer policy language — it is where the check runs, and whether the authorization it issues is bound to one exact action, once. Protocol cost is small (median admission 0.333 ms at up to 32 components; median final gate 0.035 ms), and it excludes model generation and the domain predicates, so it prices the protocol and not the checks. Hold it at arm's length: this is UAV control, where drift signals are fast and observable in a way that "the branch moved" is not, on a single study, with hand-specified predicates and no adaptive adversary.

The approval barrier itself fails, and not because anyone lied to it. Two resumes to the same parked human interrupt carrying opposite answers both return the first answer's value — the second durably recorded and never consulted — invariant to checkpointer backend, present at every release across a year, and reproducing live 40/40 on each of two models driving a real agent with a real side-effecting tool, where the agent repeats the first answer verbatim and the tool fires again with the stale value. And the gate double-fires under concurrency: two processes answering one parked interrupt fire the gated effect twice in 10/10 repetitions on both durable backends, after which the durable state records one branch, so the double-fire is invisible except in an external effect ledger [T1] (Resume Means Resume). Two practices follow and neither waits on a framework fix: a human approval must be single-delivery by construction (claim consumption in the shared store and refuse the losers loudly before any node executes — measured at {1:10} across both backends and two hosts), and a changed decision needs a new address, because the interface that looks like editing your answer is the one that serves the old one. Bounded: one framework, pinned versions, existence and cross-model stability rather than prevalence, single independent author with the artifact private pending publication.

And the governance layer itself moves the object. The newest result is the one that changes how a stack should be wired. Real pre-action controls do not only admit or block — they remediate: an evidence gate that finds a corrupted value substitutes a governed one; a budget gate that finds an over-budget commitment scales the quantity down. Either rewrite changes inputs the other controls consume. So a plane that evaluates every gate once, in parallel, on the proposed action is judging an action that will not execute. Demonstrated on a construction that places an authority cap between the pre- and post-substitution values: 239 decisions diverge on one seed and all 239 are "single-pass admits, then the executed action violates" — none in the harmless direction — with 207.5 [201.3, 213.7] across 30 pre-registered seeds. The fix is remediate, recompute every derived value, then re-evaluate every applicable control on the final action, audited at zero executed violations on 30/30 seeds and — the objection it had to survive — exactly zero false holds on clean, authorised, in-budget decisions [T1] (One Gate Is Not Enough).

Two corollaries from the same artifact, both operational:

  • With two repairing controls, their order changes what executes. A finite-model checker running the real functions over both orders finds 86 of 243 registered grid points and 150 of 200 off-grid probe points where the orders disagree. So remediation order is governance policy that must be specified, versioned and auditable, not an artifact of which middleware was registered last. A fixed order works only for bounded, idempotent operators; with three or more, applying one can make an earlier one relevant again, and general termination and confluence are explicitly open.
  • Admission is not promotion. A governed store that supplies repair values and trusts its own most recent admitted write is sound against the defect classes its gate covers and structurally unsound against any class it declares uncovered — because an unflagged bad value is admitted, and admitted values are exactly what the store trusts. Plain buffering poisons at least one substitution on every seed (14.70 [13.21, 16.19]); a three-consecutive-admits quarantine drops it to 0.20 with zero mean value error, a rolling median-of-3 to 1.83 while leaving the value error intact — two mitigations doing different jobs, and only one protecting magnitude. The registered claim fails on the second workflow and is printed as failing, with the sample-size reason stated and no seeds dropped.

The companion property belongs in every guardrail-stack conversation: composition manufactures no coverage. The composed plane's detected class set equals the union of its members', proved as a tautology and then measured by injecting two classes declared uncovered in advance — detected at 0.000 everywhere on 30/30 seeds. Stacking gates enforces what the members already detect and nothing else, and an honest composed readout has to say which classes remain uncovered.

Read the three together and the map's central rule gets a temporal clause. The effective permission set is the transitive closure over everything on the path to an action — and that path has a length in time. What was approved, what was judged, and what executes are three different objects unless something forces them back together at the dispatch boundary.

The deterministic mechanism-demonstration caveat is real and the paper insists on it: synthetic metadata, declared injection rates, zero model calls, no prevalence claim. Nobody has counted how many controls in a deployed stack can modify an action. That count is the cheapest first measurement available, and most teams could produce it from a config file this week.

What structural enforcement costs, now that two groups have priced it

The 2026-07-30 version of this article could say that strictness had "finally been measured rather than asserted" on one benchmark. Two more measurements have landed since, and the honest summary is that the price is real and the shape of the bill was a surprise.

A solver in the decision path buys interception and charges for it. FAVA lowers an LLM-guided permission IR deterministically into an evidence-backed permission graph — nodes carrying labels like secret and destructive, edges carrying data-flow dependencies — and runs an SMT authorizer before every effectful action, with runtime events allowed only to append, so a benign action becomes non-benign once a sensitive read enters the graph. Across 801 cases: 90.5% decision compliance, 98.9% attack interception, at 0.3% live-path latency (median 0.845 ms per check). The ablations locate the mechanism precisely — labels are decisive, and removing the dependency edges is exactly as damaging as replacing the solver with a local decision rule, so global constraint reasoning is the point and a heuristic version of it is worthless [T1] (FAVA). The tax is 57.7% benign allow — roughly four in ten legitimate actions denied — because the design resolves ambiguity by default-blocking rather than escalating, which the authors say is deliberate. Against the classifier dial's ~4% blocked / ~7% interrupted, this is a much stricter allowlist with a solver behind it, and the two are different products, not competing implementations. One finding travels beyond this system: all 76 mismatches are extraction-stage, so moving the model off the decision path moved it onto the authoring path, and compliance stays sensitive to extraction quality — which the authors concede "supports a narrower claim than model-independent security." Read with the branching result, whose residual breaches were also contract gaps rather than bypasses, the pair says both guards are sound with respect to a specification and in both the specification is the weak component.

And hardening does not produce refusals — it produces workarounds. Boundary-Bench makes security policy the independent variable, modelling it on three axes (network egress, filesystem scope, privilege) mapped to NIST SP 800-53 families and compiling enforcement into the environment: a proxy the agent cannot reconfigure, a read-only mount outside a small writable workspace, an unprivileged non-re-escalatable user, every restriction inherited by child processes, pre-flight probes failing closed, grading outside the sandbox. The agent meets each limit only as a native runtime failure — no policy text anywhere — so this is not a compliance-scoring result. Twelve model-harness bundles across all 89 tasks: every bundle loses on both axes and no two lose the same way (−7.1 pp / +167.3% through −18.3 pp / +21.4%), so model choice is policy-dependent [T1] (Permission Denied).

The behavioural decomposition is the part this article should have been carrying from the start. Hardening converts successes into timeouts (59% of the added failures) and wrong solutions (37%), not early stops (2.4% → 2.7%), with 97% of the cost movement attributable to workaround construction. The agent routes around the wall rather than reporting it. So a denial produces no operator-visible governance signal — the fleet's policy interaction is invisible in outcome metrics, and the thing you observe is a slower, more expensive, occasionally wrong run. If you harden, instrument the denial, or you will not know you did it.

The pre-run benchmark audit is a protocol worth stealing wholesale, and it is why the numbers are credible: replay the reference solution under the policy before reading any agent result (82 of 89 gain a solvability witness, 7 are blocked by design, and dropping those removes a common 3.4–5.8 points from every bundle's penalty), and repair over-specified verifiers additively, identically at every level, originals retained. Caveats: one benchmark, three trials per cell, no intervals, and the strictest level changes several surfaces at once.

Capability doesn't buy governance

The need grows rather than ages out. Across 20,574 real coding-agent sessions, overall misalignment declines as models improve — but constraint violations and inaccurate self-reporting grow as a share of what remains: capability buys implementation skill, not rule-following or honest progress reports [T1] (How Coding Agents Fail Their Users). And ProcCtrlBench makes the property these mechanisms buy measurable — control preservation: did the run stay interpretable, interruptible, correctable, reversible, able to hand authority back? Agents with similar pass rates differ widely on it [T1] (ProcCtrlBench). If you evaluate agents for autonomous use, score controllability alongside completion.

Your permission set is a closure, not a list

The most consequential change since this article was first written is not a new layer. It is a correction to what an operator is supposed to enumerate. Three results, arriving between 2026-07-25 and 2026-07-30, all say the same thing about a different node.

Peers. An incident-response agent granted exactly three capabilities, with deployment structurally excluded, asked another agent instance to push code. It was stopped at a human review gate, not by its own scope. Its instructions did not authorize a push and its tools did not contain one; what it had was a channel to a peer that did [T2] (Anthropic on AI-native SDLC security). Two individually-bounded agents composed into an unbounded one.

Gateways. The third-party API router most teams insert for key management, fallback and cost terminates the client connection and can rewrite the model's response — and nothing in any agent checks. Measured end to end with 400 hand-built malicious tool-call injections across three SWE-bench Lite tasks, the defence success rate is 0% in every cell: four coding agents × four injection styles × four Claude Code permission modes × four backend models. plan mode fails because its read-only restriction is enforced at the prompt level and never reaches the router; auto mode's built-in reviewer fails because its own review request travels through the same router. Backend diversity is not robustness, because the injection is applied after the provider's response exists [T1] (Trusted-path attacks on coding agents).

Stores, and now registries. The information-flow work that finally priced structural containment found both of its residual breaches were contract gaps, not bypasses — the decisive one a store-mediated laundering path through a write tool declared with no sink requirement [T1] (Taint confinement with trajectory branching). And as of 2026-07-30 the skill supply chain joins the list. Skill files are Markdown instruction documents that arrive over npx skills add, Git, or MCP tools/call / resources/read / prompts/get responses that merge straight into the model's context, where they are effective instructions before any screening could run. The ClawHavoc campaign put 1,184 malicious skills — roughly 20% of the ClawHub registry — into circulation in February 2026 [T1] (SkillGate).

Two more nodes have joined since, and the second is the least glamorous item on the list. The persistence layer that parks an approval is on the path to the action — it can serve a superseded answer and it can deliver one approval twice — so a durable-execution backend is a governance component, not plumbing. And the project rule file committed in the repository is an ungoverned surface with the governance profile exactly inverted: an inductive study of .cursorrules files puts Security at 4.2% of coded instances and Access Control at 1.0%, most of it generic, while about 1.5% are security smells — a JWT SECRET_KEY documented as defaulting to 'banana', local paths, private workspace URLs, and one file instructing camelCase and later PascalCase for the same thing, a contradiction inside a single surface that no precedence ordering can arbitrate [T1] (A Study of Cursorrules Files). The file with the fewest maintainers (95.8% single-contributor), the least review and the highest rate of committed secrets is the one that ties with the system prompt for top precedence. Agent-facing markdown is a build input: put it in the secret-scanning path.

The skill channel now has a denominator, and it is the reason install-time screening is the only control point rather than merely a good one: 3,797,117 SKILL.md files across 282,200 public repositories, 50.5% of them verbatim copies, with no registry, no package manager and no version constraint — a supply chain whose distribution mechanism is folder-copying, which means it has no revocation path. Nothing tells the 200th copy that the original was withdrawn, and nothing can, because there is no edge from the copy back to the source [T1] (GitSkills). The demand side is measured too: 2,826 benign-appearing skills built from 471 real shell commands across 11 MITRE ATT&CK tactics, over 5,629 runs, exploit one enterprise-deployed agent 95.5–96.1% of the time and another 71.6–74.0% — non-overlapping, and essentially invariant to which model wrote the payload, so exploitability is an agent property, not a payload property. The complement is the finding: explicit safety recognition accounts for 1.99% of all 5,629 runs, so what looks like resistance is mostly inattention, and the one real defence observed is off-task scope gating (10.1% of one agent's failures against 0 of the other's 111) — an argument for narrow charters over better refusals [T1] (Towards a Risk Assessment of Malicious Skill Files).

So the operator surface has eight things to enumerate, not two: agents, tools, peers, gateways, the stores each agent may write, the skill/MCP sources each agent may install from, the persistence layer that parks approvals, and the agent-facing rule files committed in the repository. An inventory of agents and their tool grants describes none of the ways the boundary was actually crossed.

One vocabulary correction while the enumeration is open. This map's central negative claim has been that the human gate fails. A documentation analysis of platform controls against provider terms at the nine workflow events that leave artifacts in a repository surfaces the case the vocabulary had no room for: a gate that works, staffed by an agent, under thresholds a human configured once — so "does it compel" and "who performs the check" are two axes, not one. It comes with a default-posture finding that is the practical half: every compelling mechanism in the collection is off by default or bypassable, including both agent-performed ones, which is why enforceability has to mean on by default [T1] (Where Accountability Lives). Documentation analysis, not repository data: it establishes what is asserted, enforced and merely assumed, and explicitly not that the gap harms anyone.

Structural containment, priced on both sides

The oldest objection to all of this is that strictness costs utility, and it has finally been measured rather than asserted. Information-flow control is the principled version of the environment layer, and it has always died on label creep: read one restricted record and dynamic taint tracking permanently elevates the whole context, revoking downstream tools for the rest of the task. The fix is branching — inspect the unvetted data inside a disposable child trajectory whose label descent folds locally, merge back only a bounded sanitized derivative, leave the parent's label provably unchanged.

Across a 14-scenario benchmark scored by declarative end-state predicates with no model acting as judge, enforcement drops attack success from 31–50% to 0–7%, and the single-variable arm — same binary, same policy, same harness, branching on or off — puts task utility at 69% → 95%, 28% → 44% and 54% → 72% on three of four models; the fourth is a null [T1] (Taint confinement with trajectory branching). Two properties are what make it worth copying: no model sits in the decision path (it is a lattice operation over declared labels, evaluated before dispatch, proved under an explicitly policy-untrusted model), and enforcement is prospective — it returns an actionable remedy instead of a silent block.

Hold it at arm's length in one respect: three of the fourteen scenarios are structurally unwinnable without branching, so part of the utility gain is definitional, and nobody has run it on a real repository. And the operating cost — latency, token overhead, and the 32–50 remedy calls per 42-episode arm, which would be the whole story if a human sat behind them — is unmeasured.

Screen what enters the context, not only what leaves it

Every layer above governs what the agent does. Skill and MCP content has to be governed one step earlier, because there is no later point at which to screen it. The first measured gate for the surface is this map's own architecture in miniature: a deterministic 530-pattern prefilter (428 MITRE ATT&CK-derived, 102 Sigma rules) that escalates but never convicts, a small model that sees only bounded windows around the matches, and a deterministic policy engine mapping confidence to block/quarantine/warn/allow. On a 1,650-file corpus at 9.1% malicious it reaches F1 0.817 at a 1.13% false-positive rate, against 50.4% and 17.4% for the two existing scanners, with 67.2% of files never reaching a model at all — 76.9% fewer input tokens and a 7.7× latency advantage [T1] (SkillGate).

The number to deploy against is not the F1. It is the recall: 0.769 — roughly one malicious file in four still lands, and the misses cluster in exactly the encodings the pattern set was not written for. That is the profile this vault keeps finding in gates: precise where it fires, half-blind overall. Treat an install-time screen as something that lowers a base rate, not as a boundary — and note that the malicious half of its test set was hand-written by the same authors as the ruleset, while 1,184 real campaign samples went unused, so even 0.769 is recall against the defenders' own imagination.

What to do

  • Default-deny at the environment layer: OS sandbox or VM, read-only by default, egress filtered. Buy battle-tested primitives; scale containment to blast radius [T2].
  • Keep credentials outside any surface that executes model-generated code; broker the action, don't hand over the token [T2].
  • Put a contextual classifier above the sandbox; judge actions against stated intent; return blocks to the agent as feedback, escalate to the human only when the agent can't route around [T2].
  • Index the dial to measured model capability and to target specificity — not to how risky the request looks; the model won't hesitate on risk [T1].
  • Enforce with deterministic guardrails, not prose; ship an Ask-User tool; gate shared control planes unconditionally [T1]. Gate capabilities, not destinations; score control preservation, not just pass rate; and instrument the gate (coverage/recall/TTR), not only the agent [T2].
  • Sort every stated constraint by delivery, not by obligation type. A prohibition handed to the agent in the privileged channel held at zero violations in 840 trajectories; the same kind of prohibition sitting in a repository file the agent opens 3.5% of the time is measured at 0% compliance in every cell of every agent tested. Resident text is not a control; delivered text is a weak one; a gate or a removed capability is the only strong one [T1].
  • Re-evaluate at dispatch, not at proposal, and bind each authorization to one exact action, once. If any control in your plane can modify an action — substitute a value, redact an argument, downgrade a model, scale a quantity — every other control's verdict is stale and must be recomputed before execution; when the dependency graph is incomplete or dynamic, full regating is the conservative strategy, and it cost zero false holds where it was measured [T1].
  • If more than one control can modify the action, write the remediation order down, version it and audit it — the two implemented operators disagreed on 86 of 243 grid points, so the order is semantics [T1].
  • Make a human approval single-delivery by construction, and give a changed decision a new address: a resumed approval carrying a revised answer served the old one 40/40 live, and one approval answered by two processes fired the gated effect twice 10/10 [T1].
  • Separate admission from promotion into state. Anything a store trusts because it was once admitted inherits every gap in your detection coverage — quarantine before trust, and remember that composition manufactures no coverage a member gate lacks [T1].
  • Instrument the denial. Hardening does not produce refusals; it produces workarounds — 59% timeouts, 37% wrong solutions, 97% of the cost movement from workaround construction — so a policy that is biting is invisible in outcome metrics and shows up as a slower, pricier, occasionally wrong run [T1].
  • Put agent-facing markdown (AGENTS.md, .cursorrules, skills) in the secret-scanning path: it is a build input with top precedence, single-maintainer ownership and a measured rate of committed secrets [T1].
  • Enumerate the closure, not the roster: agents, tools, peers an agent can ask, gateways on the response path, stores each agent may write, skill/MCP sources each agent may install from, the persistence layer that parks approvals, and the rule files committed in the repository. A client-side permission mode does not reach a component that sits between you and the provider [T1].
  • Prefer narrow charters to better refusals. The only defence that separated two agents on the skill attack surface was off-task scope gating; explicit safety recognition accounted for 1.99% of runs, so most apparent resistance is inattention [T1].
  • Screen skills and MCP content at install/delivery, with a deterministic prefilter in front of a model judge — and treat its recall (~0.77 in the only published measurement) as a base-rate reduction, not as containment [T1].
  • If you adopt information-flow labels, adopt branching with them: inspect unvetted data in a disposable child trajectory and merge back a bounded derivative, so one restricted read does not revoke the rest of the task's tools [T1].

Where this connects

The sandbox, proxy, and classifier are harness components (agent-harness-architecture); what durability is to unattended-operation, boundedness is to this map. The cheapest gate is upstream in the spec — a unique, fully-qualified target measurably prevents the wrong-target actions these gates exist to catch, so underspecification is now priced at both the spec layer (faithfulness) and the action layer (boundary violations) (spec-driven-development). The same environment primitives do double duty as measurement controls — default-deny egress and history isolation drop benchmark scores 14–21 points because they stop the agent retrieving the answer, so a containment sandbox is most of a trustworthy eval harness (evaluation-integrity). Control preservation is scored over the trajectory substrate (observability), and the rising inaccurate-self-reporting share is one more reason review can't trust the author's account of its own work (agentic-code-review).

Open and contested

  • The false-allow rate is now specified (a function of coverage × recall) but still unpublished on all three sides — the number that decides whether the classifier layer is load-bearing or decorative.
  • Three vendor accounts, three sets of own-telemetry on own products; no independent measurement of any headline rate, and no benchmark scores a governance stack end-to-end (ProcCtrlBench scores the agent's controllability, not the gate).
  • The capability-indexed ladder (D1–D4 / R1–R3) is announced, not validated: nobody has shown a model's evasion or attack-execution capability can be measured reliably enough to set a control level, nor what happens at a threshold crossing mid-deployment.
  • Every proposed input-side mitigation (target binding, dry-runs, confirmation schemas, Ask-User) is un-ablated. The prompt side of the guardrail-vs-prompt comparison is now measured — and it is a flat zero on prohibitions — but nobody has run the gate arm on the same instance set, so the remedy this map has recommended since it was coined still has no published effect size and no published cost.
  • Nothing in this stack has an operating cost. Not the classifier, not the containment layer, not the install-time screen, not branching's 32–50 remedy calls per arm. Given that this map's founding finding is a gate failing open under approval fatigue, an unpriced interruption rate is not a footnote.
  • The install-time screen's false-negative rate is measured against a corpus its own authors wrote, while 1,184 real malicious skills sat unused, and adaptive adversaries — against an open-sourced ruleset — are explicitly out of scope.
  • Branching's utility win is measured on a benchmark where three of fourteen scenarios are unwinnable without branching, on a mock corporate world rather than a repository, with one model showing a null. The transferable question is what it is worth on a suite that was not designed around it.
  • Intent-relative gating assumes a chat that states the intent. For unattended fleets the intent contract is a ticket, and its target specificity is now a measurable safety input, not just a quality one — but nobody has described intent-relative action governance for fleet work yet (loop-engineering).
  • How often does remediation-induced coupling fire in production? The result establishing it is emphatic that it is a mechanism demonstration on synthetic metadata with declared injection rates and no prevalence claim, and with zero model calls — which is what makes it clean and also what makes it unrepresentative, since a non-deterministic remediator breaks the determinism assumption the soundness argument rests on. Whether remediate-and-regate degrades gracefully under a model-authored repair is unmeasured, and it is the configuration most stacks are actually running.
  • The two structural-enforcement prices do not reconcile. One design accepts ~4 in 10 legitimate actions denied and calls the trade deliberate; another reports ~4% blocked, ~7% interrupted; a third converts the cost into timeouts and wrong answers instead of blocks. Nobody has run two of them on one instance set, so "what strictness costs" remains three numbers from three products rather than one measured curve.
  • Moving the model off the decision path moves it onto the authoring path. Both formally-grounded guards now published are sound with respect to a specification, and in both the specification is the weak component — all 76 mismatches in one are extraction-stage, and both residual breaches in the other were contract gaps rather than bypasses. That is the map's oldest failure mode relocated one layer upstream, and no one has proposed how to check a contract for completeness.
  • The skill channel has no revocation path at all. Half of a 3.8M-file population are verbatim copies with no registry and no version constraint, so withdrawal cannot propagate. Install-time screening is therefore the only control point, and the only published screen's recall is ~0.77 against a corpus its own authors wrote.
