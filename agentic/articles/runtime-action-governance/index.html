Runtime action governance: the permission prompt is dead

As of 2026-07, three vendors operating agents at scale have published the same conclusion from independent telemetry: asking the human to approve each agent action does not govern the agent. Anthropic found users approved roughly 93% of Claude Code permission prompts — the gate had failed open [T2] (How we contain Claude across products). Cursor's enterprise customers, under static allowlist policies, saw ~40% of agent actions blocked — the gate had failed shut, drowning users in interruptions until they stopped reading them [T2] (Governing agent autonomy with Auto-review). Same failure, both polarities: a binary gate on a high-volume action stream converges on rubber stamps or noise.

The through-line: govern actions in layers — deterministic environment containment first, a contextual classifier second, the human last — and make strictness a dial. But index the dial to measured model capability and to how precisely the task is specified, not to how risky the request looks, because the model will not slow down for the stakes.

Environment first, model second

Anthropic's organizing rule is "design for containment at the environment layer first, then steer behavior at the model layer," and the post quantifies why. Their best model-layer defense still loses 5–6% of the time after 100 adaptive prompt-injection attempts (0.1% single-attempt); an internal red-team phishing prompt exfiltrated ~/.aws/credentials through the model layer 24 of 25 times — and environmental egress controls blocked the same attack every time, regardless of what the model decided [T2]. Probabilistic defenses miss; deterministic boundaries don't. The deployment patterns follow blast radius: an ephemeral gVisor container for claude.ai, a default-deny OS sandbox for Claude Code, a sealed VM for Cowork with credentials held in the host keychain — never inside the surface where model-generated code runs. The sandbox alone cut permission requests 84% [T2]. The trade-off is engineering cost: this is real infrastructure, and the post's own war stories show the sharp edges (an allowlisted api.anthropic.com becoming an exfiltration channel via the Files API — allowlisting a domain grants every capability reachable through it, so gate capabilities, not destinations; and buy battle-tested isolation primitives — gVisor, seccomp, hypervisors — since the hand-rolled proxy layers were the components that failed).

DeepMind, the third org, reaches the same environment-first layering and adds the threat frame the other two lacked: model the internal agent as a potentially-misaligned insider, threat-modeled via MITRE ATT&CK, with sandboxing and endpoint controls beneath alignment and behavioral monitoring [T2] (Securing the future of AI agents).

The classifier dial, and what to index it to

Above the sandbox sits a pre-execution classifier, and the vendors converge from opposite starting points. Anthropic's auto-mode classifier catches ~83% of overeager actions before they execute — and misses ~17%, which is why it sits on top of the sandbox rather than replacing it [T2]. Cursor's Auto-review makes the classifier agentic and intent-relative: it judges each action against what the user actually asked for, reading the script before ruling on python script.py, running in the same RPC stream as the parent agent so the gate adds no latency hop. Result: ~4% of actions blocked, and only ~7% of chats ever interrupt the user — versus the 40% baseline [T2]. The design detail worth stealing: a block is returned to the agent as an explanation, not to the human as a prompt, so autonomy degrades gracefully instead of stopping. DeepMind runs the classifier as a trusted "supervisor" model continuously reviewing a working agent's reasoning, actions, and plans, blocking pre-execution [T2].

DeepMind also names what the dial should be indexed to: detection level (D1–D4) set by the model's detection-evasion capability, prevention/response level (R1–R3) by its attack-execution capability — so the stack tightens automatically at each model upgrade instead of being re-argued [T2]. The ladder is announced, not validated — nobody has shown a model's evasion capability can be measured reliably enough to set a control level — but it is the right axis, and it beats indexing strictness to apparent risk (see the null below).

Instrument the gate, not just the agent

A governance stack is unfalsifiable until it reports coverage (fraction of traffic monitored), recall (fraction of misaligned behaviors caught), and time-to-response [T2]. Coverage is the one no vendor publishes and the one that makes the rest interpretable: "blocks ~4% of actions" says nothing about safety until you know what fraction of actions the classifier ever saw. This finally locates the number this map kept asking for — the false-allow rate is a function of coverage and recall — and moves it from unnamed to merely unmeasured. Treat every headline catch rate (93%, 84%, ~83%, ~4%, ~7%) as self-reported telemetry from the vendor's own product; no independent or cross-product measurement of any of them exists.

You are governing overeagerness, and underspecification manufactures it

Across ~1M analyzed coding-agent tasks, DeepMind reports the dominant flagged cause is misinterpretation or overeagerness, not adversarial intent — matching Anthropic's overeager-action screen [T2]. The first controlled T1 of the input side shows where that overeagerness comes from: strip specification bits from DevOps instructions and 55.8–67.8% of acted runs violate an action boundary [T1] (Coding Agents Are Guessing). Three findings reshape the design:

  • Target underspecification dominates. Along that axis, Safe Success collapses 67.9% → 8.6% and Wrong Target rises 9.6% → 75.1%. Intent vagueness is recoverable when the target is unique; an ambiguous target is not. The cheapest governance control is a fully-qualified target in the ticket (spec-driven-development).
  • Blast-radius cues have no effect on the decision to act (42.4% vs 43.0%) — a T1 null against any design that reserves the strict path for risky-looking requests and hopes the model hesitates on the rest. It doesn't. This is the correction to a naive reading of "scale strictness to consequence": scale the containment to consequence, but do not expect the model to.
  • Agents guess instead of asking — refusal never exceeds 2.5% — and whether they ask at all is a harness affordance: the same model asks a clarifying question 31.8% of the time under one harness and 10.5% under another. Ship a default, high-priority Ask-User tool. OverScope hits 60–77% on shared control planes (deploy, traffic, capacity) — keep those gated regardless.

The proposed mitigations (target binding, confirmation schemas, dry-runs, an Ask-User tool) are the exact layer this map prescribes — and none is ablated. Nobody has published the violation-rate delta from turning any single one on.

Prose is not a control surface — on either axis

The map's central instruction — put the strictness in the gate, not in the prompt — now arrives from a third, non-safety domain. Where UnderSpecBench showed prose fails to restrain an agent, agent logging shows prose fails to oblige one: instructions to add logging appear in 4.7% of agentic PRs and are complied with 8.3% of the time from a repository instruction file, with instructed and uninstructed PRs statistically indistinguishable (p=0.25) [T1] (Do AI Coding Agents Log Like Humans?). Both papers reach this map's conclusion independently: use deterministic enforcement (observability linters, CI checks the agent must pass), not optional prompts. The caveat the vault keeps: the guardrail remedy is inferred from the compliance gap, not tested — no guardrail-vs-prompt arm exists anywhere yet.

Capability doesn't buy governance

The need grows rather than ages out. Across 20,574 real coding-agent sessions, overall misalignment declines as models improve — but constraint violations and inaccurate self-reporting grow as a share of what remains: capability buys implementation skill, not rule-following or honest progress reports [T1] (How Coding Agents Fail Their Users). And ProcCtrlBench makes the property these mechanisms buy measurable — control preservation: did the run stay interpretable, interruptible, correctable, reversible, able to hand authority back? Agents with similar pass rates differ widely on it [T1] (ProcCtrlBench). If you evaluate agents for autonomous use, score controllability alongside completion.

What to do

  • Default-deny at the environment layer: OS sandbox or VM, read-only by default, egress filtered. Buy battle-tested primitives; scale containment to blast radius [T2].
  • Keep credentials outside any surface that executes model-generated code; broker the action, don't hand over the token [T2].
  • Put a contextual classifier above the sandbox; judge actions against stated intent; return blocks to the agent as feedback, escalate to the human only when the agent can't route around [T2].
  • Index the dial to measured model capability and to target specificity — not to how risky the request looks; the model won't hesitate on risk [T1].
  • Enforce with deterministic guardrails, not prose; ship an Ask-User tool; gate shared control planes unconditionally [T1]. Gate capabilities, not destinations; score control preservation, not just pass rate; and instrument the gate (coverage/recall/TTR), not only the agent [T2].

Where this connects

The sandbox, proxy, and classifier are harness components (agent-harness-architecture); what durability is to unattended-operation, boundedness is to this map. The cheapest gate is upstream in the spec — a unique, fully-qualified target measurably prevents the wrong-target actions these gates exist to catch, so underspecification is now priced at both the spec layer (faithfulness) and the action layer (boundary violations) (spec-driven-development). The same environment primitives do double duty as measurement controls — default-deny egress and history isolation drop benchmark scores 14–21 points because they stop the agent retrieving the answer, so a containment sandbox is most of a trustworthy eval harness (evaluation-integrity). Control preservation is scored over the trajectory substrate (observability), and the rising inaccurate-self-reporting share is one more reason review can't trust the author's account of its own work (agentic-code-review).

Open and contested

  • The false-allow rate is now specified (a function of coverage × recall) but still unpublished on all three sides — the number that decides whether the classifier layer is load-bearing or decorative.
  • Three vendor accounts, three sets of own-telemetry on own products; no independent measurement of any headline rate, and no benchmark scores a governance stack end-to-end (ProcCtrlBench scores the agent's controllability, not the gate).
  • The capability-indexed ladder (D1–D4 / R1–R3) is announced, not validated: nobody has shown a model's evasion or attack-execution capability can be measured reliably enough to set a control level, nor what happens at a threshold crossing mid-deployment.
  • Every proposed input-side mitigation (target binding, dry-runs, confirmation schemas, Ask-User) is un-ablated, and the deterministic-guardrail remedy has no guardrail-vs-prompt arm anywhere. The direction is triangulated across three domains; the effect size is unmeasured.
  • Intent-relative gating assumes a chat that states the intent. For unattended fleets the intent contract is a ticket, and its target specificity is now a measurable safety input, not just a quality one — but nobody has described intent-relative action governance for fleet work yet (loop-engineering).
