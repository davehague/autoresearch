Grade the trajectory, not the answer — and stop trusting the step-level ranking

As of 2026-08, the useful unit of agent observability is not the final answer. A run can end "correct" while resting on a broken intermediate step, and a long run can be right for the first stage and useless by the last. Independent groups working at every granularity — reasoning spans, pipeline stages, harness components, provider responses, whole sessions — land on the same move: stop scoring the outcome, audit the run against the evidence it gathered.

That much is settled. The second half of this piece's original thesis is not, as of 2026-08-22. The practice of localizing the first wrong step rests on a step-level signal that can rank which steps mattered, and an audit against causal ground truth now finds that no such signal in agentic use ranks better than the same scores with their step-assignment shuffled. The evidence half of the argument stands; the ranking half is in contest, and this refresh separates them rather than splitting the difference. The new section is "The step-level ranking is placebo-level against causal ground truth" below; everything before it about claims-versus-evidence auditing, silent failure, layered watchers and evidence defence is unaffected.

Three further things have changed since this piece was last refreshed in mid-August, and each cuts against comfort in a different direction.

The instrument's error rate now looks like a property of the task, not of any one tool. Strict first-wrong-step attribution is right 28.8–38.0% of the time. An agent handed a live telemetry stack and full source names every root cause of an incident 25.3% of the time. Diagnosing an injected provider fault from the full trace tops out at 55.5%. Three unrelated subjects, three research groups, one band — which says the ceiling belongs to the class of problem rather than to a weak diagnostician.

The right architecture for a watcher is now settled enough to state as a rule. Layer by whether an invariant exists: deterministic recomputation where you can recompute, a cheap model-free behavioural signal for drift and looping, an LLM as escalation rather than default. Two independent groups reached it from opposite ends this month, and one of them ran it on frontier coding agents for eight cents an instance.

And there is a hole underneath all of it. Every trace is a record of a run against a system nobody wrote down. The tooling versions the prompt and traces the execution; it represents the configuration nowhere.

The through-line: an agent's own trajectory is the evidence; audit the run against it, and defend that evidence, because everything in the stack is quietly eroding it. Where you localize a first wrong step, treat it as a hypothesis rather than a fact — and as of 2026-08-22, treat any per-step ranking under it as unestablished until it has been checked against a shuffled control.

Why outcome monitoring cannot work: silence is the modal failure

The strongest argument for this whole map is not a method result. Across 255 hand-labeled agent-reactive bugs, the largest symptom class is Silent Errors at 108/255 (42.4%): the agent runs normally, produces a fluent answer or a modified workspace, and no exception, warning, retry, or non-zero exit fires. Crash is 71 (27.8%), Error-in-Output 34, Retry Loop 33, Hang 9 [T1] (Understanding Agent-Reactive Bugs at the Model-Harness Boundary).

The cross-tabulation is sharper than the headline. The two triggers that most reliably go silent are exactly the claims-versus-evidence mismatches this map proposes auditing: task-instruction non-compliance is silent in 81% of cases and statement fabrication in 90%. And note the sampling direction — a crash gets noticed and filed; a quiet wrong answer may never be attributed to the agent at all — so 42.4% is a lower bound.

That number now has a controlled counterpart. Injecting known API faults into agent systems, 21.82–65.71% of induced failures surface nothing to the user, worst in conversational patterns [T1] (AgentChaos) — the same modal-silence shape, measured under a cause the experimenters chose rather than inferred from filed reports.

The same shape shows up on the human side of the loop. In a field study of three production review agents across 341 repositories, only 1,056 of 15,652 unresolved comments drew any reply, so 93% of non-adoption is silent [T1] ("Go Home Copilot, You're Drunk"). And the status flag lies in the other direction: 114 of 470 sampled discussions are comments the developer acted on and never marked resolved. Instrument adoption from a lifecycle marker alone and you undercount by construction.

Practical consequence: any monitor keyed on exceptions, exit codes, or a lifecycle flag is watching the minority case. The signal has to come from comparing what the agent said against what its run actually did.

Score the first wrong step — and treat the answer as a hypothesis

Deep-research agents are the clean demonstration. TELBench reframes evaluation around first-wrong-step localization across 1,000 instances and 2,790 annotated trajectories, and DRIFT localizes the break by auditing each of the agent's claims against the evidence its own run gathered — flagging claims that reach the answer path unsupported or contradicted — for up to a 30-point gain in localization accuracy [T1] (Where Do Deep-Research Agents Go Wrong?). Don't judge each reasoning span for surface plausibility; track claims and bind each to evidence in the log.

The field also has a shared vocabulary for what an audit finds: an ontology of 11 process-defect types in 4 categories over a unified trajectory representation, plus a control-preservation axis (interpretable / interruptible / correctable / reversible), with agents at similar pass rates differing widely on process quality [T1] (ProcCtrlBench).

The instrument reports its own precision, and it is a minority. Strict agent-and-step accuracy is 28.8% on a 9B backbone and 38.0% on a 27B one; naming the right agent alone reaches 56.0%, and landing within one step reaches 44.0% [T1] (AgentDebugX). So the honest statement of this map's core practice is that a majority of attributions are wrong and it is still the best move available.

What is new is that the same ceiling now shows up twice more, on subjects sharing nothing with that one. Best root-cause accuracy against a live instrumented microservice system is 25.3% on medium incidents and 10.0% on hard ones [T1] (ORCA-Bench). Diagnosing an injected provider-side API fault from the full trace reaches 52.45% / 55.5% (fault type / step) for a rule-based diagnoser and 47.25% / 53.52% for an LLM-based one, neither clearing 56% [T1] (AgentChaos). Three groups, three tasks, one band.

That is not a reason to stop attributing. It is a reason to be careful about what consumes the output. Anything downstream that treats an attribution as ground truth — a training signal, a regression label, an automated rollback — is consuming a minority-correct estimate, which is the same failure shape as a self-improving harness bounded by its own proxy judge (harness-self-evolution).

The step-level ranking is placebo-level against causal ground truth

This is the section that puts the rest of the map's attribution half in contest, and it arrived on 2026-08-22 [T1] (Credit Without Ground Truth).

Every step-level instrument above is graded against annotated step correctness. The audit's opening move is to point out that correctness is not the quantity anyone wants. A correct step can contribute nothing — the trajectory was already determined — and an incorrect step can be pivotal, because it opened the state recovery came from. What a debugging loop, a training signal or a rollback rule pays for is contribution, and nobody had measured whether the signals track it.

The instrument for measuring it is executed replay: at each decision point, re-sample four alternative actions the policy itself supports, roll each forward to completion, and difference the outcome distribution against at least three replays of the factual action. The realized continuation is never used as the factual estimate. Nothing in the construction consults the signals under audit.

Against that ground truth, in a replayable single-agent tool environment, with the verdict order frozen and signed before collection:

  • An LLM judge, the outcome-conditioned log-probability ratio, and the policy's own confidence are each indistinguishable from their own marginal-matched shuffled control — in two model families, under two generations of the instrument, on three measurements sharing no estimator and no failure mode. The finding is not that credit anti-tracks contribution. It is that nothing separates a trained scorer's ranking from the same scores with their step-assignment destroyed.
  • One face of the judge does clear chance and buys nothing. Per-step sign agreement is 60.4% (interval excluding 50%). Precision-at-pivotal lift is 1.000, interval containing the chance line — the judge is better than a coin about whether a step helped and no better than chance at concentrating on the steps that mattered. The implicit family's lift is 0.940, sitting entirely below chance.
  • The mechanism is identified rather than guessed, and it is worse than noise. Implicit credit tracks the policy's own probability of the action it is scoring at rank correlation +0.75 (replicating at +0.70 in a second family, registered as a directional prediction before the data). Fluency carries 2.37× the regression weight of the causal increment, and once fluency is conditioned out the partial correlation with contribution is −0.004 (p = 0.87). The worked case is the one to remember: a policy that repeats the same failed action four times, after the environment has already answered Nothing happens., is scored at confidence > 0.9999 on the very turns replay judges pivotal. A stuck loop is the most predictable region of a trajectory, so any instrument built on the model's own certainty aims itself away from the place an agent has stopped making progress.

Two facts about the ground truth itself scope every replay-based method, this one included:

  • Causal contribution is sparse. 30.5% of measurable turns carry any effect; the per-turn noise floor is exactly zero at 86.0% of them. Most of a trajectory is causally inert, so "found the step that mattered" is a much higher bar than accuracy-against-annotations implies.
  • Measurability is a property of the (policy, environment) pair. The fraction of turns with no policy-supported counterfactual is 13.1% for one 7B policy and 26.8% for a similar-scale 8B one — a factor of two, non-overlapping intervals, driven by probability-mass concentration rather than capability — while the harder-to-measure family carries more causal signal where measurement is possible (38.3% vs 30.5% pivotal). You cannot assume a replay audit transfers between models.

What to actually do differently. Three things, none of which require accepting the null:

  1. Run the shuffle. Any per-step scorer you rely on can be checked in an afternoon: shuffle its scores within each trajectory, preserving the marginal exactly, and compare. If the shuffled version ranks as well, the scorer is not doing what you are paying it for. This is the cheapest instrument check in the whole map.
  2. Do not route on confidence and call it triage. A confidence-only router in the same study cut judge calls by 13.1% per turn and 14.0% per trajectory and recovered pivotal turns at chance — for exactly the mechanism above. The authors released the rule with its negative result attached so it would not be repurposed as a detector. Use it as a cost knob; do not use it to decide what to look at.
  3. Keep the evidence layer and stop stacking on the ranking layer. Auditing claims against gathered evidence takes no damage here. What should stop is treating a step-level score as a label for anything downstream — a training target, a regression classifier, an automated rollback point.

The scope, honestly. One replayable single-agent tool environment, two ~7–8B policies, 50 and 28 trajectories, and the study's own training experiment is underpowered by its authors' account (minimum detectable effect ≈11.8 points against a ±3-point equivalence band, disclosed as their pre-registration failure). It is not a coding-agent result, and repository-level trajectories may behave differently. But the audit survived its own instrument being repaired mid-study — a chat-template defect was found, quantified at 12.0 points predicted against 12.3 measured, and the full arm re-executed, moving the measurability map materially and not one verdict class — and it agrees with the earlier accuracy-side finding (28.8–38.0% strict attribution) from a direction that removes the possibility that the annotations were the problem. That is a live contest, not a settled reversal, and the experiment that would decide it — executed replay over repository-level coding trajectories — is the highest-value unrun study in this map.

Layer the watchers by whether an invariant exists

The field's reflex when an agent might be going wrong is to add an observer, usually a second model on every step. Measured head-to-head on the same episodes, that is the wrong default.

A one-class monitor over observable step telemetry — a deterministic hash embedding, token-uncertainty aggregates, action metadata, fitted on healthy runs only — costs about 200 microseconds per step and works on the classes with no invariant to recompute: looping 0.48–1.00, goal drift 0.66–0.86, tool cascade 0.17–1.00 across nine real corpora. But it carries two burdens: a per-deployment healthy null (calibrated on one model family and deployed on another it sits at chance, AUROC 0.527 against 0.885 recalibrated on itself) and a residual false-alarm rate. Three deterministic checks carry neither — recompute the run's stated total from the tool results it actually received, confirm every required call was made, validate each result against the shapes its tool can return — and beat it: 60% detection (96% with coverage) at 0 of 63 false positives against 54% at 17%, transferring across model families with nothing retuned (110 of 110 at 0 of 10), and catching 26 of 26 provoked fabrications, a class the learned monitor cannot be scored on at all [T1] (Where Does Agent Failure Telemetry Come From?).

So: a shape check at every tool return, deterministic recomputation at every asserted figure, a cheap behavioural monitor for drift and looping, an LLM judge as escalation. Not because the judge is expensive, but because judge and monitor fail on different classes.

That architecture was assembled entirely on 3B–8B locally-served models. It has now been run on frontier coding agents and it pays: +5.00 to +15.24 points (average +9.9) across three executors × two SWE-bench variants for $0.08 per instance, with a monitor that contains no model at all — it pattern-matches two structural views of the live trajectory into ten named drifts, five of them blocking the pending action before execution [T1] (LivePlan). Three things in it change practice:

  • Advice beats re-planning. The re-planning baseline falls below the unmodified agent on two of three models at two to three times the cost, with 12–26 resolved→unresolved regressions against LivePlan's 2–7. The correction wants to be as local as the error.
  • Triggering beats scheduling. Firing the same advisor every five steps touches 97.7–99.6% of instances at 3.25–7.38 interventions each and scores 2.3–5.3 points lower at higher cost. The detector's job is to suppress advice into healthy trajectories, not to find opportunities.
  • Drift is the normal state. 86.16% and 78.33% of unmodified trajectories carry at least one — which is exactly why an outcome-keyed monitor sees none of it.

The authors state the ceiling themselves, and it is the honest limit on all of this machinery: in nearly all of LivePlan's own resolved→unresolved regressions, the root cause is not bad advice or late intervention but the executor's inability to follow correct guidance.

Close the loop: attribute, then rerun from the attributed point

Organize debugging as Detect → Attribute → Recover → Rerun, with the rerun starting from the attributed checkpoint, and you repair 13 of 73 failed runs against Reflexion's 6, AutoManual's 5 and CRITIC's 4 — overall accuracy 55.8% → 63.6%, with the largest gain on multi-hop tasks (48.8 → 61.6) [T1] (AgentDebugX). All three baselines repair from the visible failure, which sits on average ten steps downstream of the cause.

Two implementation details are worth stealing regardless of domain: deterministic rule packs run first, with LLM judgment escalated to only what the rules cannot decide; and attribution is a cost ladder, not a strategy — heuristics, one whole-trace pass, binary search, per-step inspection, budgeted ensembles at 12.8K tokens against 8.1K for a single pass. The trade-off is stated plainly: the +7.8 points bundle attribution with the rerun, so the two are not separately priced, and the attribution advantage disappears on hosted backbones — meaning the machinery is partly compensation for a weak diagnostician.

The audit window is measured, and correction lands early in it

The error that decides a failed run lands at a median of step 7 out of ~27, while the first observable failure signal trails it by ~10 steps — from the largest manual failure anatomy to date, 1,794 trajectories and 63k+ annotated steps, 7 frontier models × 3 scaffolds, κ 0.78–0.94 [T1] (Failure as a Process). Two findings redirect the effort:

  • 57.9% of decisive errors are epistemic — the agent misused information already in its own trajectory (false premises alone are 30.7% of all failures). The catching evidence was in context.
  • 71% of successful runs also hit errors. Recovery, not error avoidance, separates outcomes.

That window now has its first confirmation from an intervention that actually recovered runs: across all 244 unresolved→resolved flips, the first intervention landed within the first third of the trajectory, and 74.6% needed several (mean 3.70) [T1] (LivePlan). Correction is early and repeated, not a late rescue.

At the session level the same move yields a kill signal: grading a whole run distribution (23,392 episodes, 396 tasks, 10 models) produces a Meltdown Onset Point past which an unattended run is not recovering and should be killed, with frontier models melting down on up to 19% of long runs [T1] (Beyond pass@1). Localize the break to debug; find the meltdown point to know when to stop.

Calibrate on the field distribution, not on the dashboard's default unit

One sampled week of production coding-agent telemetry — 13.5M sessions, 95.1M turns, 3.2M users, 760.5M LLM calls, 774.7M tool calls — says the unit almost every agent dashboard displays is the wrong one [T1] (Agentic Coding in the Wild). Three properties change what an operator should watch:

  • Load is agent-generated. Each user message unfolds into an average of 6.6 autonomous LLM calls, an 87% / 13% agent-to-user split. A view keyed on the user prompt is showing 13% of what the system did. The informative unit is the turn, and a turn is a whole trajectory.
  • Everything is heavy-tailed. Median session 3 turns / 15 calls / 4.2 minutes against a mean of 6.1 / 40.6 / 62.6 minutes (14.9× on duration, P90 above three hours); median turn 3 calls / 160.2K prompt tokens against a P90 near 16 calls and over 1M tokens. Alerting or budgeting on the mean describes almost no real session.
  • Populations differ 50×. Five user archetypes spanning 23K to 1.1M tokens per turn, with different tool mixes and idle profiles. One SLO across that spread is tuned for nobody.

Two structural facts to hold when reading any trajectory: time and tokens are inverted — LLM execution is 85.4% of wall-clock and 48% of prompt tokens, tool calls 4.7% of time and 28% of tokens — so a latency profile and a token profile of the same session accuse different components; and execution is overwhelmingly serial (36.7% of turns strictly, median concurrency 1.15, 93% of tool batches a single invocation). The caveat is load-bearing for this map specifically: this is telemetry, not trajectories. No prompt text, outputs, tool arguments, source, correctness or failure labels. It calibrates expectations; it audits nothing.

The agent as consumer of an observability stack

A third limb opened in August: not observing the agent, and not the agent degrading what it builds, but the agent reading a telemetry stack to diagnose an incident. The first benchmark to put general-purpose coding agents against a live OpenTelemetry-instrumented microservice system — six days and ~50 GB of real metrics, logs and traces through Prometheus/Jaeger/OpenSearch, full source access, 1,079 tasks, expert-SRE ground truth, judge re-scored at κ_w 0.90 — reports best root-cause accuracy 25.3% on Medium and 10.0% on Hard, with hallucinated root causes running 7% to 40% across models on identical inputs [T1] (ORCA-Bench).

The failure has a shape rather than a rate. Agents lock onto the loudest symptom and stop, so accuracy degrades with the number of concurrent causes rather than with the difficulty of any one. In a six-fault scenario, three models each named exactly one cause — all three different — and missed the rest. Not a shared blind spot: five partial, non-overlapping pictures of one incident.

Two operational findings come from the same runs, and both are harness-fixable:

  • The evidence worth most is the evidence agents look at least. Ablating source access while leaving telemetry intact costs 9–16 accuracy points for every model and spikes hallucination for every model — yet those agents spend 16–20% of commands reading source against 70–72% on telemetry.
  • 26–40% of telemetry calls error out or return empty, dominated by empty. An empty query result is a plausible substitute for "this service is healthy" — the fail-loud pathology arriving on the agent's inputs rather than its outputs.

So force a code-orientation pass before hypothesis formation, and make empty results loud. Both are harness changes, not model choices (agent-harness-architecture).

You can replay what the agent did; you cannot say what the agent was

Every method in this piece assumes a statement of what the system was configured to be when the trajectory was produced. Nobody ships one. Across five platforms practitioners actually use — LangSmith, Langfuse, Helicone, Braintrust, PromptLayer — prompt versioning, execution tracing, observability, evaluation and lineage are supported or partly supported everywhere, and framework-independent configuration model, configuration graph, immutable baseline, configuration lifecycle, dependency model, governed revisions, state propagation and governance semantics are marked "not provided as a first-class capability" in all five columns [T1] (Agentic Configuration Management).

Four design moves are worth taking whether or not the proposed model ships:

  • Separate configuration from runtime. Configuration is the intended, versioned structure; a run is one execution of it. Runtime observations may enrich governance information and may not modify governed configuration, with provenance mapping every runtime entity back to the revision that produced it and a replayable ordered event log.
  • Use immutable revisions with stable logical identity, so "the reviewer agent" and "the reviewer agent as it was on Tuesday" are both nameable.
  • Keep quality, assurance, impact and eligibility apart, so absence of evidence is not read as poor quality and a dependency's lifecycle state does not propagate to its parent. Only impact propagates.
  • Compute impact transitively. On a graph built to contain a two-level dependency, one-hop traversal found 6 of 9 affected items and fixed-point propagation found 9 of 9 — the misses reached through an intermediate revision. Deterministic across five repetitions, and scope-independent at three iterations for local, intermediate and global changes alike.

Read it as a design with a conformance test, not as an outcome. The 27 governance scenarios compare behaviour against expectations pre-specified by the same author from the same model — the paper says so — the quantitative campaign runs on graphs of 11 and 13 items, the 61.5–84.6% inspection-scope reduction counts configuration elements and explicitly not human effort, and nothing measures whether a governed configuration produces better agent outcomes. It also covers three orchestration frameworks and no file-based coding harness, which is exactly where the configuration is unmaintained markdown (context-engineering).

Observability as actuator — and its measured ceilings

The trajectory signal doesn't have to end at a diagnosis. Make a harness observable — represent editable components explicitly, distill trajectories into an evidence corpus, pair each proposed change with a prediction verified against outcome — and the same evidence that localizes failures drives a control loop that improves the system: 69.7% → 77.0% on Terminal-Bench 2 at 12% fewer tokens [T1] (Agentic Harness Engineering). A second group runs the loop with no labels at all, scoring candidates on execution-derived proxies [T1] (TTHE).

Three ceilings, in increasing order of how much they should worry you.

The judge is miscalibrated. TTHE's trace-driven judge commits a 50% harness when a 64% one sat in the pool it inspected. Trajectory evidence can drive the loop; it cannot tell the loop which way is up.

The most reliable consumer of a trajectory may not be a model at all. A hierarchical counterfactual search over the temporal structure of an agent's edits strips 17.9–32.9% of its patch while preserving the oracle on 99.1% of repairs, matching exhaustive delta debugging at 1.9× fewer validations [T1] (TRIM). No model reads the trajectory — which is why it never returns an invalid result, where prompting the agent with the same trajectory fails 3.8–44.9% of the time.

Component telemetry beats run telemetry for deciding what to fix. Instrumenting a production verification loop end to end yields catch rate 0.20, fix rate 0.75, false-alarm rate ≈0 — and those three numbers say where the next point of reliability lives: raising catch was worth up to +8 pp, raising fix at most +0.5 pp [T3] (Where Does Agent Reliability Come From?). Vendor self-evaluation, single run, and the 32 missed errors are not coded by failure locus.

Defend the evidence: five ways the substrate erodes

Every method above assumes the run's evidence survives into the record. Five sources now say it often doesn't, and they are worth reading as one story.

Compaction removes it, as a switch rather than a gradient. A killed process's exit code was in context, yet the summary promoted its partial stdout to "confirmed results" that persisted across sessions [T3] (Compaction as Epistemic Failure). A later probe found that across 246 summaries no summary ever carried a strict subset of ten planted facts, and that when task state decayed into an invented phase numbering, every subsequent summary restated the confabulation [T3] (Delivery, Not Storage). Post-compaction, your audit runs on beliefs.

Some failures are silent by construction. When an agent mis-resolves an entity and a later step looks up something derived from it, the derived resolution is internally consistent given the wrong carried state. Drift hits 18% of eligible workflows with the per-step error rate rising 8% → 28% by step 3, detectable only by an independent re-derivation from the original request [T1] (Binding Drift). Relatedly, 86.4% of failed runs in one controlled study close with an explicit success message [T3] (How Agent Skills Fail under Long Contexts).

Your instrument will substitute a plausible value unless you make it halt. In a pre-registered study, three silent-corruption mechanisms were caught mechanically before any number reached a results file. The one that reached the counted data was an output-token ceiling that truncated replies and recorded them under an unrelated-sounding rejection note: no crash, no error, only a plausible wrong number. It inverted the study's headline finding and fell only to an adversarial review of the completed analysis [T1] (Adversarial Test-Hardening for AI-Written Code). The repair is mechanical and portable: one ceiling value read by both the request and a check; a reply at the ceiling raising a truncation error that is never retried; the round recorded honestly with its real billed cost and the raw truncated reply archived; a truncation at a measurement-defining step failing the cell as missing data. Under the repaired instrument the same mechanism fired three more times within days and was scored rather than laundered — the event was never the problem, the laundering was.

The provider response path erodes it too, and inverts damage against diagnosability. Injecting API faults into agent systems, truncation is worth up to 52.63 points of damage and is named by a rule-based diagnoser 4.30% of the time, against timeouts at 91.04% [T1] (AgentChaos). A truncated reply is well-formed and merely stops. The low inter-method agreement on the costly classes (κ 0.098–0.372 on omission and value faults, against 0.813–0.907 on crashes) is direct evidence for a layered posture rather than for picking a winner.

And an intermediary can rewrite it on purpose. A third-party API router sits on the trusted path between an agent and its provider and can modify the response before the agent acts. At subtler intervention levels it rewrites the visible explanation to agree with the injected tool call, leaving no explicit edit boundary — so the forged action sits in the trajectory, consistent with its own narrative, and a claims-versus-evidence audit passes [T1] (Where Is the Cost of Third-Party API Routers in Agentic Software Development?). The one artifact that would separate the tampered world from the honest one is the provider-side record of what was actually generated, and nobody logs it.

The transcript is a rendering, not a recording

One more erosion, and it sits underneath every instrument above. A real coding-agent harness compacts, summarises and re-serializes its interaction history between turns, so the stored transcript does not necessarily decode back to the token sequence the model actually generated [T1] (LEGO-RL). Anything finer-grained than "which tools were called in what order" is reading a reconstruction. The fix is architectural and requires no change to a harness you do not own: capture at the model-serving boundary with an in-process proxy, before harness-side history management touches anything. Verified rather than asserted — rollout-versus-recompute log-probability correlation stays at or above 0.998 median on every scaffold and never falls below 0.989.

The negative control is the part worth stealing. An intermediate implementation introduced a systematic one-position offset between each token and its captured metadata. That version scored worse than disabling the mechanism entirely, and it was undetectable by checking that the mechanism was active — the system appeared to work. Only a direct comparison of the captured values against the source's own online selections separated them.

"The capture is enabled" and "the capture is correct" are different assertions, and only the second needs an independent measurement against the thing being captured. Alignment and completeness are also independent failures: a system can have perfect alignment with incomplete capture, or complete capture with systematic misalignment. That is the same four-question integrity taxonomy the credit audit above derived from its own pipeline incidents, reached independently — which is the closest thing this map has to a cross-check on its own instrumentation advice.

The other half: the agent won't instrument what it builds

Across 4,550 agentic vs 3,276 human PRs in 81 repos, agents change logging less often than humans in 58.4% of repositories, and their apparent higher density is mostly a PR-size artifact — control for size and it collapses to 1.64 vs 1.59 logs per 1,000 LOC [T1] (Do AI Coding Agents Log Like Humans?). Agents match human practice in try/catch — the mechanical, pattern-matchable case — and diverge most in conditional branches (46.7% similar) and loops (41.5% similar), exactly where a human decides from context that a maintainer will need to know what happened.

Prose doesn't fix it: logging instructions appear in 4.7% of cases and are complied with 8.3% of the time from a repository context file, with instructed and uninstructed PRs statistically indistinguishable (p=0.25). Use deterministic guardrails — observability linters, CI checks — not instructions (runtime-action-governance). And humans silently backfill 72.5% of the missing instrumentation off-review, so the debt is real and invisible in the merge record (agentic-code-review).

No incidents, no MTTR, no time-to-diagnose against agent-authored code. The gap is measured; that it hurts is inferred.

Where this connects

Trajectory grading is the review-side sibling of "don't trust the agent's 'done'" in agentic-code-review, and the merge/reject label is itself a mislocalized grade (only 35.7% of rejections are genuine agent failure). A harness evaluator that catches a broken step before it ships (agent-harness-architecture) is the constructive counterpart to localizing it afterwards. The trajectory substrate is also a measurement instrument: it is what reveals that 57% of one agent's benchmark wins retrieved the answer rather than derived it (evaluation-integrity), and a reconstructability twin asks whether a captured trace even licenses the decision a score claims — finding the replay precondition unmet in every real public trace it checked [T1] (Agent-Safety Evaluations as Load-Bearing Evidence). Cost per stage is itself an observability signal (model-routing-token-economics).

One reason teams instrument this heavily is less flattering than a design principle: the offline gate does not exist. Among ten senior practitioners, half running agents in production, 70% cite observability, 50% name OpenTelemetry-style tracing, and 50% run continuous evaluation across model updates via reruns and trace inspection — which is the closest thing any of them has to a release gate and is a post-change measurement. Meanwhile 80% raise non-functional concerns against 7.5% of 2,572 labelled open-source tests touching any [T1] (Tangent). The named gap is actionable: every platform exposes trajectories, tool calls and environment transitions, and none treats them as first-class test targets, so what is missing is an assertion vocabulary over traces rather than more instrumentation (ci-cd-for-agents).

Open and contested

  • The step-level ranking is now contested outright, not merely imprecise. Against causal ground truth from executed replay, every credit signal in agentic use is indistinguishable from its own shuffled control, and the mechanism — credit echoing the policy's fluency at +0.75 while retaining −0.004 of the causal signal — makes it anti-informative exactly where an agent is stuck. The decisive unrun experiment is executed replay over repository-level coding trajectories; until then this is one tool environment and two ~7–8B policies against a body of accuracy-side work that agrees with it.
  • The attribution ceiling now looks structural. 28.8–38.0% on multi-agent step attribution, 25.3% on live-system root cause, 47–56% on injected provider faults. Three unrelated tasks, one band. Nobody has explained the common cause, and nothing downstream should treat an attribution as a label. Read with the bullet above, the two readings are different: one says the instrument is right a minority of the time, the other says its ordering may carry no information at all. Nobody has run a study that distinguishes them.
  • Replay auditability does not transfer between models. The no-counterfactual rate differs by a factor of two between two similar-scale policies, and the harder-to-measure one carries more causal signal. Any attribution benchmark built on one policy is reporting a property of that pair.
  • Nobody has audited a capture layer they did not write. A token-level capture with a one-position offset scored below no capture at all and passed every check that the mechanism was enabled. The obvious generalisation — that trajectory tooling in production is silently misaligned somewhere — is untested.
  • Enumeration, not detection, is the binding constraint on agentic incident work — agents name the loudest cause and stop. The obvious remedy (force the agent to enumerate before committing) is unrun.
  • Nobody has a shared metric. The mechanism replicates cross-org across reasoning spans, pipeline stages, harness components, provider responses and whole sessions, while no single localization metric is shared. "Grade the trajectory" is settled; "measure it thus" is not.
  • The layered architecture has no cross-layer accounting. Deterministic checks, behavioural monitor and LLM judge each have measured precision; nobody reports what the stack catches and at what combined false-alarm rate.
  • Nobody records what the system was. Configuration governance is proposed and conformance-tested on 11-item graphs by a single author, with no users and no outcome measure. Until a trace can be joined to an immutable statement of the configuration that produced it, every replay is against a system reconstructed from memory.
  • The actuator loop's judge stays unsolved. Miscalibrated at 50% committed vs 64% available, and label-free there is no ground-truth gate to fall back on.
  • Only one half of the map is priced. Agent under-instrumentation is measured as a behavior; its downstream cost (incidents, MTTR, debugging time) is unmeasured. The recursion — does first-wrong-step localization degrade in agent-authored code? — is a stated, unrun prediction, and the cheapest experiment in this map.
  • Production telemetry is prescribed but unmeasured. No detection rate, no time-to-response, no false-positive burden, no log-volume accounting at agent-authored throughput.
  • Effect sizes are each their setup's — 30 points on deep-research, +9.9 on SWE-bench under one advisor, the step-7/lag-10 window on Terminal-Bench, 13/73 repairs on GAIA. The durable claims are directional.
