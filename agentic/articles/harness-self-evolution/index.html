Can the harness improve itself? Everything is settled except the one thing you'd buy it for

As of 2026-08, the mechanics of automated harness improvement are largely worked out. We know what a self-improving harness has to read (raw execution traces, not summaries). We know which parts are worth editing (structure — tools, middleware, memory; not prompt wording). We know the ways its acceptance step fails and the fix for each. We know which half of the loop is actually doing the work. We know a step upstream of the whole thing is weak enough to confound the results. We know what the loop quietly writes into its own memory when nobody checks. And there is a product category selling the finished idea.

What we do not know is the one thing the pitch rests on:

Does a search over harness configurations beat spending the same budget on the agent?

Eleven consecutive arrivals between 2026-08-08 and 2026-08-26 have reported real held-out generalization and none has run that control. Not one. Across three research communities, on harnesses, skills, metrics and test archives, in enterprise environments and coding benchmarks — the transfer question keeps getting answered harder and the budget question keeps not getting asked. That is no longer an omission per paper. It is a gap in the field's protocol, and it is the reason this map's status is contested rather than consolidating despite an accumulating pile of positive results.

Two things have changed since this piece was first written on 2026-08-08, and both raise the bar rather than lowering it.

First, a second group ran the matched-budget comparison on an adjacent object and found against the loop again. Auditing and Decomposing Feedback-Driven Evolution [T1] audits a self-evolving test generator, then charges it the same candidate budget as plain resampling. The operator loses by 6.01–18.83 points in every model×cohort condition, with all four paired intervals strictly below zero — and its apparent 10–13 point advantage turns out to have been the single-reference oracle rather than the search. A test archive is not a harness and the authors say so, so this does not settle the contest. It raises the prior, and it hands over a protocol worth adopting whole: audit the oracle, then match the budget, then look at the operator. In the reverse order the budget question is never reached.

Second, the adjacent literature got the audit this one is still waiting for, and it inverted seven conclusions. Phantom Gains [T1] re-examined self-improvement by weight update — the sibling field to harness search — against proper frozen controls, and seven reported findings did not survive. The transferable demand is the same structural complaint the compute-matched objection makes, arriving from a second direction: a loop that reports "the evolved artifact is better" against no frozen control, on one seed, at one checkpoint count, is reporting an unknown mixture of effect and instrument.

This map forked out of the agent harness architecture map on 2026-08-05. That map asks how a harness should be built; this one asks whether it can build itself. The split is a boundary between a design claim and an optimization claim: every hand-engineered lever over there is judged by whether it improves an agent, and every claim here is judged by whether a search over levers beats spending the same budget elsewhere.

Part 1 — What is settled

These hold regardless of how the contest resolves. Most are things to do; two are things to stop assuming.

The regression filter, not the search, is the product

This is the most useful thing to arrive since August, and it inverts what a harness-search pitch sells you.

AutoSaddler [T1] reports +9.0 / +9.6 / +10.0 points over base harnesses on GAIA2, SWE-Bench Pro and Terminal-Bench 2.0 under disjoint train/dev/test task groups. Then it decomposes the gain, and the decomposition is the finding: both arms fix the same things. Removing the held-out regression filter costs 11.4 points, entirely through regression on previously-passing scenarios (−0.24 against +0.16 points per iteration). The same over-scoped hook patch appears in both arms and survives in only one.

So the search is not where the value is. The value is in the gate that refuses to install a fix that breaks something else — which is a much cheaper thing to build than a search, and a much easier thing to add to a harness you already maintain by hand.

This is the same shape as the replay-driven verification result from 2026-08-08, promoted from a mechanism to a decomposition. And it rhymes with what the repair-loop literature found in a different setting: the value is in knowing when not to install the fix.

Take the gate. You do not have to take the search to get it.

Give the optimizer raw traces — summarizing the feedback is worse than not compressing it

This inverts a habit. Meta-Harness [T1] ran an information ablation holding proposer, search procedure and budget fixed, varying only what the proposer may read:

What the proposer seesMedianBest
Scores only34.641.3
Scores plus an LLM summary34.938.7
Full execution-trace access50.056.7

The summarized condition is worse than raw scores on best-candidate accuracy. It spent tokens and removed signal.

What makes trace access practical is the interface: a filesystem the proposer queries with grep and cat rather than a prompt it is handed — 10.0 MTok/iteration of available diagnostics against 0.002–0.026 for every prior text optimizer, a median 82 files read per iteration.

The mechanism is horizon. A storage or retrieval decision surfaces as a failure many steps later, so compression removes exactly the evidence needed to trace back to it. This does not contradict the vault's summarization findings, which measure an agent executing. The rule that reconciles them: compress what the actor carries forward; preserve what the diagnostician can reach back for.

Most of your validation set cannot tell your candidates apart

Task-CoEvolve [T1] set out to make harness search cheaper and produced two things more useful than the method.

The measurement: over 70% of a harness search's validation pool cannot discriminate its candidates. The discriminative band is 10–24%, and its composition drifts as the harness improves — the tasks that separated your candidates at iteration 1 are not the ones that separate them at iteration 10.

The ablation: rotating the evaluation subset each iteration accounts for 1.0 of a 2.1-point total gain, and on the arm with a real held-out split, a 20%-budget search beats full-set search — with the authors naming validation-set overfitting as the reason. So stop treating full-set search as a ceiling; it is partly an overfitting mechanism wearing a thoroughness costume.

Two honest limits travel with it. The full-set estimator's rank correlation with truth is 0.62 at a 20% budget and 0.13 at 7% — at the extreme it prevents a bad pick rather than ranking. And per-candidate task count is fixed before any of that candidate's results are seen, so the search can neither stop early on a loser nor spend more to separate two close candidates.

One rider for anyone budgeting a search: three protocols at one nominal budget spent 0.7M / 1.2M / 3.2M input tokens per trial. A task-count budget is not a cost budget.

Gate every accepted edit — twice, on two different questions

Two failure modes, both measured, both with cheap fixes.

The optimizer can invent the failure it fixes. Phantom Guardrails [T1] built a deterministic micro-lab where the correct self-edit is no action. Proposers fabricated guardrails for nonexistent rules in 15/60 runs when all-legal input carried a rule-shaped pattern (0/60 on featureless input). Three conditions were each necessary: a rule-shaped pattern in the data, an unstated rule-set completeness, and failure-presupposing instructions. Under suppression-only acceptance the phantom enters monotonically and can never be demerited, because a no-op guard is invisible to the metric. The fix is cheap and ablation-clean: warrant-aware acceptance, where a self-edit lands only with oracle-confirmed failing-episode citations. Fabrication 0/60, all rounds.

And an edit that cites a real failure can still break something else. Learning Globally Reusable Skills for Coding Agents [T1] attacks the level out: skill evolution is normally a sequence of local updates, one failure, one patch, admitted unverified — and a proposal generated in isolation invalidates assumptions siblings rely on. Their example is tightening a repository-exploration skill to truncate file output, which silently breaks downstream analysis skills that assumed complete contents.

The regression is not intrinsic to accumulating skills. It is the price of admitting updates without replaying what they might break — which AutoSaddler has since measured at 11.4 points on a different object.

The implementation detail is worth stealing wholesale: the skill bank is versioned with a git worktree, traces and replay outcomes in SQLite, so concurrent evolution runs cannot interfere and every accepted version is reproducible. A self-modifying artifact needs a rollback story.

Deletion needs its own instrument — a generic edit will not do it

SkillProx [T1] is the first to treat removal as a first-class operation with its own gates. Forward stage: diagnosis-driven edits re-executed on the batch that produced them, accepted only on non-decreasing hard and mean-cell accuracy. Backward stage: decompose the artifact into auditable units, compute each unit's ablation effect once and freeze it, then validate removals one at a time under structural, complexity and two accuracy gates with a soft compression cap.

The ablation says both halves matter: −1.5 points without closed-loop diagnosis, −2.5 without the removal stage. And the audit is designed to over-nominate so the gate can refuse — five units flagged, one survived; the worked removal costs 3.12% of the artifact and buys 46% → 54% validation hard accuracy.

The corollary matters for anyone whose agent writes to a memory file: an append-only regime is the rational response to lost rationale, because deleting safely costs O(2ⁿ) counterfactual probes where adding costs O(1), and CLAUDE.md deletion hazard falls with age at −0.032 per commit [T1]. The same source finds that across three maintainer tiers a more capable maintainer ratchets harder — excess rising +67.7% → +571.9%. If capability makes the ratchet worse in humans, an evolving agent is not the exception.

Stop assuming the loop can find the edit site

Harness Handbook [T1] measures a step upstream of everything above. Modification requests describe behavior; repositories are organized by files. Unaided, a strong planner reaches 38.3% symbol-level localization F1 on a 2,267-file production harness. A generated behavior-centric index whose every candidate is re-verified against live source lifts that to 57.1%, at 8.6–12.7% fewer planner tokens, with gains concentrated on search-hostile (+33.3 pp) and cross-file (+20.0 pp) requests.

An evolution loop that cannot find the edit site is not a fair test of whether evolutionary search works. Carry it at single-study strength: the dependent variable is an LLM-judged edit plan, nothing applied or tested, and the two judges disagree by roughly 2× on one system's magnitude.

Stop assuming the gains are capability

One Recipe, Many Harnesses [T1] is the first study here to read the evolved artifact instead of scoring it — one recipe held fixed across 8 languages × 3 models, every edit routed through a typed failure signal and recorded as a falsifiable contract. The finding: gains are compensation for recoverable execution defects, with no observed capability extension. The two null regions are predictions of that mechanism rather than exceptions to it — Python at a 5.6% defect rate gains nothing, and one small model installs no test-file rule at all.

Reuse is bounded by an ecosystem margin measured three independent ways at 20–40%, with the boundary falling where a discipline stops being a free consequence of the target's own execution chain.

And the practical planning move that falls out: count your defect profile before building anything. It is label-free and it tells you whether there is anything here for you to win.

And stop assuming personalization is the lever

Do Personalized Skills Help Coding Agents? [T1] runs the baseline skill-evolution work rarely runs — a skill pooled across everyone's traces. Over 206 replayable sessions from 13 developers: a skill from a developer's own history scores +0.97 (p = .399), a skill from a randomly chosen other developer scores +0.92 (p = .451), and the pooled skill scores +3.78 (p = .063) — the only condition with a win rate above half. Personalization overtakes pooling only once ≥6 task-relevant sessions exist.

The binding constraint on trace-distilled skills is corpus size, not distillation quality. A loop optimizing against a narrow trace corpus is fitting noise, and the cheap comparison beats the sophisticated one.

Part 2 — The contest, stated honestly

The case against

Two T1s landed together on 2026-07-18 and the map downgraded on both.

Rethinking the Evaluation of Harness Evolution for Agents [T1] makes an argument that is methodological and hard to escape: harness evolution is itself a search procedure that repeatedly runs and revises candidates, so crediting its gain over a single-shot baseline conflates the design discovered with the compute spent discovering it. Match feedback and inference budget across arms on Terminal-Bench 2.1:

ArmScore
Harness evolution67.4
Direct sampling baseline68.2
Harness scaling71.8
Parallel sampling72.3

And the decisive number is generalization: held-out tasks gain +0.6 points, and +0.0 on one of the three models.

Independently, the human version fares no better. How Scaffolding Evolution Shapes Coding Agent Quality [T1] froze the model and tracked 35 sequential releases of one production CLI scaffolding against 50 stratified SWE-bench Verified tasks: resolve rate swings 23.0%–39.0% with no significant trend (ρ = 0.208, p = 0.231), while average tokens rise 391K → 668K (+70%) monotonically.

Note carefully what survives. Harness scaling still beat the baseline (71.8 vs 68.2), so structural search is not worthless. The refuted claim is narrower and sharper: the evolutionary loop does not beat a dumber use of the same compute.

The case for keeps getting stronger on the wrong axis

Since 2026-08-08 the positive results have improved substantially — on transfer, which was never the disputed half.

The strictest protocol yet. StarHarness [T1] stratifies the evolution pool by baseline failure behavior, splits it into proposer-visible search tasks and proposer-hidden selection tasks with matched score, failure-mode and verifier-pass distributions, and reserves held-out tasks that touch neither proposal nor acceptance. Leakage is closed in the protocol's construction rather than by instructing the proposer — and the authors name what they are correcting: a prior meta-harness system used held-out sets for classification and math while searching and reporting final performance on the same 89-task benchmark.

The results are the strongest transfer evidence this map has: 20–35 points after only 4–12 accepted changes; held-out gains at 70%, 69% and 127% of the evolution-set gains; and twelve frozen cross-model transfer rows, every one positive, +10.7 to +46.3 points, from one artifact evolved against one model and applied with no re-evolution.

It also does something none of the prior ten did. The gains come with cost per task falling — 17% / 53% / 29% — with turns and tool calls roughly halved, verifier pass rate 34.5% → 72.8%, and total guardrail violations falling 33 → 4. This is not a score bought with more sampling.

And it answers the budget question not at all. The evolution budget is never compared against spending the same budget on test-time scaling or a stronger model. The prompt-optimization comparison is labelled descriptive by the authors. Patch-level contributions are twice stated to be unisolable. All three environments are tool-rich enterprise settings with programmatic verifiers — the domain most favourable to interface repair and least like the coding domain where the objection was raised.

Transfer has a measured boundary, reported honestly. StateM [T1] ran the same frozen artifact across three transfer distances and published all three: cross-generation transfer works and gains more than it did at home; exact transfer across a provider boundary is negative and costs $37.02 to repair; and frozen held-out transfer across task families is +0.55 macro in aggregate — a mixture of +12.21, +9.21, −2.78 and −3.70. An aggregate that averages a large win against a real regression is not a transfer result; it is two results wearing one number.

What the loop learns when you are not looking

Three findings arrived after this article was first written that change what "it works" would even mean.

The loop absorbs the evaluator's conventions and stores them as universal practice. StateM's genuinely new material is a hazard rather than a verdict: failure-driven optimization is a channel by which the evaluator's undocumented semantics enter the harness — and it operates inside a declared construction boundary that forbids reading the verifier. The loop does not need to read the grader to learn the grader's habits; the feedback is enough.

The utility number cannot distinguish a better configuration from a retained shortcut. Practice Makes Unsafe [T1] versions skill state across four agent frameworks and six evolution methods on a shared backbone, resetting conversation, workspace, process namespace and tool session per cell so the library is the only channel. 21 of 21 evolved configurations author unsafe artifacts, 19 retrieve, 19 contaminate, 15 carry over into a clean session. And the number that lands directly on this map: benign utility beats the non-evolving arm in 15 of 21 settings while malicious attack success beats it in 17. Three malicious tasks lift pooled carryover harm 16.0% → 35.3%, and mixing benign work into the same updates does not erase it. Removing skill retirement re-retrieves 100/106 and 44/44 already-flagged skills.

The governance requirement that follows is not optional and is cheap: a persistent update must be observable, attributable and revocable.

Undirected authoring is measurably dead. Metrics That Write Themselves [T1] measures the authoring request as a design variable: 295 artifacts, 9 hits against 14.75 expected by chance, no discoveries surviving correction. Asking with a counterexample and widening the interface when a target resists are each individually necessary — 336 narrow-interface attempts admitted none, against 6 of 27 at the wider one — and an exhausted run returns an insufficiency certificate rather than nothing. The evolved artifact there is a metric rather than a harness, and it too has no compute-matched control.

The production shape, with the search deleted

The first production evidence on this map does not run a search at all. Claude on call [T2] describes an incident log the agent appends to, plus a recurrence-based promotion rule that graduates entries into versioned investigation skills — promotion by observed recurrence and human review rather than by an automated gate. It reports no effect size, so it cannot move the status in either direction. It does describe a shape the contest has been ignoring, and one that sidesteps every failure mode in Part 1: nothing is admitted until it has happened more than once and a person has looked at it.

The operative rule

One question does most of the work when you read any harness-search result, including a good one:

Ask which distribution the number was measured on, and demand the compute-matched control. A gain measured on the tasks the search optimized against is a search-set number, whatever else it is. And when a paper reports an aggregate transfer number, ask for the per-family breakdown before you believe it — StateM's +0.55 contained two double-digit wins and two regressions.

Two practices that need no resolution of the contest:

Pin your scaffolding version like you pin your model. Thirty-five releases with a frozen model swung resolve rate 16 points with no trend — a range exceeding most claimed model-to-model gaps in this vault.

If you adopt one thing from this literature, adopt the regression gate. It is 11.4 points of the measured effect, it is the cheapest component to build, and it works whether or not you ever run a search.

Part 3 — The product category arrived first

Mid-2026 saw a meta-harness layer ship from unrelated vendors: an orchestration tier above Claude Code, Codex, Cursor, OpenCode, Hermes and Pi — Omnigent [T2], Apache 2.0, alpha — plus a metaharness generator [T3] that mints bespoke per-repo harnesses across six runtimes on the thesis "the model is replaceable; the harness is the product."

The load-bearing promise is composition: combine multiple models, harnesses, and techniques without rewriting code. Set that against what this vault's best-replicated finding says results do when a harness swaps: 8.6-point mean shift with rank-order change, a security outcome reversing 10/10 → 9/30, a context pack worth double digits under one harness and zero under another, a byte-identical skill library read on 99–100% of tasks under one stack and 0–1% under another.

A uniform API makes harnesses substitutable at the call site, not equivalent in outcome — and no product in the category measures the gap.

Treat harness portability as a migration, not a configuration change, and re-run your evaluation on the target pair. The settling experiment is cheap and nobody has run it: one workload, two harnesses, one mediating layer, publish the delta.

Demand the matched-budget held-out number, the mutation-acceptance warrant, and the revocation story before adopting a self-improving harness. The generator ships the self-evolution loop this map cannot validate with no acceptance criterion, no held-out split and no warrant published — the last being exactly the intervention that drove fabrication 15/60 → 0/60. Add the third item as of 2026-08-23: if the loop writes durable state and you cannot enumerate, attribute and retire what it wrote, you are running a system whose utility metric provably cannot tell improvement from a retained shortcut.

The governance tier survives the pair thesis. Policy at three scopes, spend caps that pause rather than kill, mandatory OS sandboxing — all enforced at the runner, below the prompt, on the dispatch path the harness already mediates. That does not require harnesses to be equivalent, only wrapped.

What would move this

The map is contested and the resolving experiments are all cheap, which is the frustrating part. Nothing on this list is a new research programme.

  • The matched-budget held-out arm, on coding. Run harness evolution against compute-matched Best-of-N with disjoint search and evaluation task sets, and report the held-out number. Two groups have now run a matched-budget comparison and found against the loop, on Terminal-Bench and on a test archive. Eleven consecutive positive results have not run it. The benchmark that would host the missing arm exists and meters budget in evaluation calls and case passes; it still has no entrant.
  • The same comparison with the regression filter ablated on both sides, now that the filter is measured at 11.4 of the points. If the gate is the gain, the honest comparison is gate plus search against gate plus sampling — and nobody has run that either.
  • A compute-matched arm on StarHarness's protocol, which is the strictest partition anyone has built. It is the run that would settle the transfer half beyond argument and finally test the budget half, and the apparatus is already assembled.
  • The interchangeability delta: one workload, two harnesses, one meta-harness layer, publish the number.

Until then, the buildable parts stand on their own: make the harness observable, hand the optimizer raw traces rather than summaries, edit structure rather than prompt wording, rotate your validation subset instead of trusting the full set, gate every accepted change on a real cited failure and a replay of what it might break, give deletion its own instrument, keep what the loop writes revocable, and version the artifact so you can roll it back. Those are worth doing whether or not the search beats the sampler — and on the current evidence, the gate is worth more than the search.
