The right amount of self-generated reference context is task-dependent — localization wants breadth, text-reading wants precision — echoing this map's code-representation finding in a visual register

This map's acquisition pipeline governs the stage before an agent reasons over material already in its window: finding it, choosing what enters, structuring the corpus so the choosing is possible. Every prior source in this map addresses text-shaped material (code representations, retrieved artifacts, runtime-validity checks); this source adds a visual acquisition instance the map has not yet carried — an agent can treat its own repository as a renderable visual knowledge base and generate fresh reference screenshots from the current, potentially-buggy codebase state, with no external bug-free ground truth needed, to compensate for information a degraded input screenshot has lost.

The result that matters most for this map's existing pipeline argument is not that reference images help (they do, substantially, closing roughly half the localization gap degradation opens at the worst tested resolution) but that how much context to acquire reverses depending on which downstream step is the bottleneck: file localization benefits from the full five-image catalog and gets nothing from a single best-matching reference, while text recognition does the opposite, because non-matching images become noise the VLM must discount. This is the same task-dependent acquisition-payoff shape this map's code-representation-workflow source already established in a textual register (representation choice helps at the bottleneck stage and washes out or reverses elsewhere) — now shown to hold for a visual representation choice as well, which is new information for the map's general claim that "how much context to acquire" has no single correct answer independent of which step is bottlenecked.

Bounds: [T1, suggestive; single repository (scratch-gui), single agent framework (mini-swe-agent), single model backend (GPT-5.4) and configuration (temp 0, one run per condition); 36 synthetically injected bug instances rather than naturally occurring degraded reports; five-image reference catalog is small and predefined, so the top-1-vs-all-five reversal may not hold at the larger, noisier catalog sizes the authors themselves flag as needing retrieval; localization accuracy reported independent of whether the resulting patch is correct.]
