Reproducibility is a property of the harness, not of the task

This map's standing position is that a cheap measurement of an agent is usually measuring something else — the harness (agent-benchmarks-underdisclose-their-harness), the benchmark's own defects (benchmark-defects-suppress-scores-not-only-inflate-them), the best iteration rather than the trajectory (cumulative-best-hides-the-iteration-where-it-got-worse). This adds a prerequisite that sits underneath all of them: before you can measure whether an intervention fixed a failure, you have to be able to produce that failure again, and on long-horizon multi-agent tasks the default method does so about two thirds of the time at one attempt and 41% across three.

That number is the quiet scandal in it. Every repair result in this literature is computed on a base rate where a third of the "repaired" cases were never reproduced in the first place. Whatever the treatment effect is, it is being estimated on a population that partly did not exist.

What replay buys, and what it cannot. Reconstructing the prefix from recorded logs is exact — 100% by content hash — and it lifts reproduction to 80.78% / 52.43%. It cannot make the rest deterministic, and the paper is careful to name why rather than reporting the improvement and stopping. The anchor node and everything after it stay live, so model sampling still varies (three attempts rebuilding identical prefixes and producing three different unsupported answers with no intervening tool calls) and so does the world (HTTP 200 in the source run, HTTP 429 on replay). Neither of those is fixable by better recording; they are properties of what an agent run is. The honest form of the claim is that replay converts a fully-resampled trajectory into a partially-resampled one, and reports the boundary.

The scaling result is what makes it a design rule rather than a tool note. The advantage grows with reusable history: about +7 to +10 points where only two or three nodes precede the failure, rising to +26 or +27 where nine or more do. Most cases in this dataset are short-prefix (71.08% reuse 2–3 nodes), which understates the method on exactly the long-horizon unattended work where reproduction matters most. So the more a run resembles the thing this atlas cares about — hours of accumulated tool calls, not a three-step exchange — the more of it is recoverable, and the less of a repair claim rests on luck.

The instrument's own error is reported instead of assumed, which is the part the map should keep: the reproduction labels come from an LLM judge, a stratified secondary audit gives a 3.30% confirmed-disagreement rate against a 6.96% combined sensitivity ceiling, and all five confirmed disagreements were false negatives — genuine reproductions marked as different failures. The measured error runs against the reported result rather than in its favour.

Bounds. Two benchmarks, three frameworks, one model at temperature zero, web-agent and assistant tasks rather than repository work. Replay requires the harness to have recorded an event graph with content-hashed nodes in the first place, which is an instrumentation precondition most deployed agent stacks do not meet — the finding is as much a specification for what a harness must log as it is a result about reproduction rates.
