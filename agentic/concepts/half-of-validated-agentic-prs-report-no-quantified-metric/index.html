A large-N empirical baseline shows agentic PRs aren't worse at validating their performance claims than humans are -- both groups under-measure at nearly the same rate, which reframes this map's "is agentic evidence weaker" question as "is anyone's evidence strong enough"

This map's evaluation-integrity question has mostly been asked about benchmarks, judges, and leaderboards — is the scoring instrument trustworthy. This source asks it one step upstream, at the point where a PR author (human or agent) first claims a change helped: does the claim come with a measurement? The headline shape is not "agents are worse" — it is parity in a shared failure mode. Agentic and human-authored performance PRs report some validation at statistically indistinguishable rates (82.3% vs 80.6%), but when the regex-extracted metric layer (RQ4) is laid under that validation layer (RQ3), roughly half the "validated" PRs in both groups never name a latency, throughput, memory, or other quantified figure — 50.9% agentic, 52.4% human. "Validation evidence" as a reported category is therefore a much weaker signal than it sounds: it includes a large bloc of PRs whose evidence is static reasoning about why a change should help, carrying no number a reviewer or a future audit could check against reality.

The one place the two groups genuinely diverge is evidence type, not evidence presence: agentic PRs validate 46.1% of the time via benchmarks against 57.2% for humans, leaning instead on static-reasoning claims (asymptotic/algorithmic arguments with no runtime measurement) — consistent with an agent defaulting to an argument it can construct without executing code, cheaper to produce and unauditable without re-running it. And the double-standard finding is a small but sharp asymmetry: human authors apply looser validation standards to code-smell refactorings (changes whose benefit is easier to reason about from the diff alone) than to resource-targeting optimizations, while agentic PRs apply the same standard to both — plausibly because an agent has no notion of "this one's obviously fine," just a validation habit it applies uniformly.

Interaction edge: this sits one step upstream of mutation-analysis-finds-verification-suite-blind-spots and this map's broader proxy-reliability strand — those ask whether an existing check can be trusted; this source asks whether a check was ever run and reported at all, at the point a contribution enters review. It also bears directly on agentic-code-review's reviewer-trust thread: a reviewer (human or agentic) evaluating a performance PR is, half the time by this source's numbers, evaluating a claim with no number behind it — the review gate is only as strong as what it's being asked to check. Scope: this is report-level characterization (what PRs say), not independent re-execution of the claimed optimizations, so it cannot distinguish an unmeasured-but-true improvement from an unmeasured-and-false one — the map's standing "is the number itself correct" question remains open at a layer this source doesn't reach.
