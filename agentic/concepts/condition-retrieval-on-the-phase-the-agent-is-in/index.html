Retrieval has a phase parameter, and it was being held constant

This map's retrieval results have all optimized a single policy: retrieve just in time rather than preloading (just-in-time-context-retrieval), prune and summarize rather than carry everything (prune-and-summarize-beats-full-history), prefer dynamic assembly to static packs (dynamic-context-beats-static-preloading), prune toward the goal rather than generically (goal-hinted-pruning-beats-generic-compression). Every one of them asks what is the right retrieval policy and answers with one policy.

This says the right policy is a function of where the agent is. Exploration and backtracking get a large budget weighted toward diversity — the agent needs breadth and does not yet know what matters. Implementation gets the smallest budget (12k against exploration's 20k) weighted toward the graph signal and anchored on the edit site — the agent knows exactly what it is doing and additional variety is noise. The same maximal-marginal-relevance machinery, re-parameterized four times over the run.

That is goal-hinted-pruning-beats-generic-compression taken one step further: the hint is not the task's goal, which is constant, but the current sub-goal, which is not. And it inverts a natural intuition — the phase where the agent is doing the most consequential work is the phase where it should be given the least context.

Two implementation details are portable regardless of the result. Edit and file-touch metadata are grounded in the executed command, not the model's claim about what it did, which is gate-the-edit-on-evidence-observed-not-claimed applied to the memory's own contents — a memory built from the agent's narration would carry its fabrications forward. And retrieved state is injected as a marker-delimited block appended to the most recent tool-result message, preserving tool-call pairing so the conversation stays in-distribution, firing only when plan state changes, with a novelty filter suppressing already-surfaced nodes. Most memory scaffolds inject a synthetic turn; this one does not perturb the conversational shape the model was trained on, which is a plausible part of why it avoids the degradation memory-scaffolds-can-degrade-long-horizon-agents found across ten models.

The effect this map cares about most is the window one. Context-window exhaustion falls 6.7% → 3.0% while mean trajectory length rises 47.3 → 51.9 steps — longer runs that exhaust the window less often, which is context-is-a-finite-decaying-resource managed rather than merely conserved. Retrieval here is entirely lexical-plus-graph with no model call, so this is not a compression result: nothing summarizes, and nothing can launder (compaction-selection-is-all-or-nothing).

Caveats: the memory-only arm is worth +8.3 instances and the coupled system +25.0, so most of the value is in the coupling with the planner rather than in the retrieval policy alone (plan-and-memory-are-superadditive) — the phase-conditioning cannot be separately priced from the planner that supplies the phase. λ = 0.7, the 0.5/0.5 relevance weights and the per-phase budgets were fixed from pilots and never ablated, so nothing here says these are the right numbers, only that conditioning on phase at all is worth doing. One 30B model for the headline, Python only, and the graph signal's import parsing is Python-specific.
