Evaluation alone does not decide whether unsafe execution ends -- the archive's memory of an old pass/fail verdict can outvote a correct repair sitting right next to it

This map's self-evolution sub-thread (2) -- can self-modification be governed? -- has mostly carried attack-side evidence: adversaries poisoning benchmarks, in-context skill hazards, trusting-trust attacks on the self-evaluation loop. This source supplies something different and more mundane: a failure mode that requires no adversary at all, just an unremarkable environment change and an unexamined piece of search- loop plumbing. A program can pass every test a team wrote, and a later, legitimate change to what "authorized" means can make it unsafe without anyone touching its code -- the frozen founder facing the identical new dependency proves the environment change alone did not force the failure; the optimization did. That is this map's search-pays question (sub-thread 1) and its governance question (sub-thread 2) meeting at one data point: whatever efficiency gain the optimized program bought, it bought by implicitly assuming the authorization surface would not move.

The sharper mechanism is in the archive, not the editor. A self-evolving system that keeps a scored history of candidates will, by default, let an old high score outrank a fresh correct repair that's sitting in the same archive -- 22 of 48 histories here, every single one with the fix already available and unused. This is a readout problem wearing a search problem's clothes: nothing about the search failed, the selection mechanism was reading a stale ledger. The fix measured here is almost embarrassingly cheap relative to the size of the failure it closes -- refresh the stored scores before resuming search, which replaces the failed program with an existing repair before the editor ever generates new code. This is a concrete, measurable instance of this map's standing concern about judges and selection (the self-evolving harness is "bounded above by the judge that picks its own improvements," harness-self-evolution-is-capped-by-its-proxy-judge): here the judge isn't even miscalibrated in the usual sense, it's just looking at old data.

A second, procedurally distinct persistence route needs no archive and no new dependency at all: when every proposal and the incumbent all fail validation under an unchanged contract, a bare "keep" rule leaves the known-failed program running, where a founder-fallback rule would restore the last known-correct state. Two independent ways to get the same symptom (an unsafe program kept active) is exactly the shape this map's governance sub-thread needs more of -- most of the prior self-evolution-safety evidence here is one mechanism per source; this paper finds two in one testbed and keeps them analytically separate via matched comparisons.

The utility question this map's contest (sub-thread 1, does the search pay) keeps needing answered honestly also gets a clean answer here, on the governance side: preserving safety was not a tax on the efficiency gain. The core trajectory study, with current-contract validation plus validated rollback, ends with fully correct endpoints while retaining >43% mean service-cost savings (excluding validation expenditure). Validated safety and useful RSI are not shown here to be in tension — they just require checking what will run under today's contract rather than trusting what passed yesterday's.

Interaction edge: unattended-operation — the "keep the last-known-good state and pause or roll back rather than run the detected-bad one" pattern is this map's version of that map's own standing externalized-run-state discipline, applied to a self-modifying agent's own code rather than to task progress.

Interaction edge: runtime-action-governance — the new-dependency failure mode (a cached local authorization check surviving an upstream revocation) is a concrete instance of exactly the kind of authority-continuity gap that map tracks at the action layer; here it arrives one layer up, at the layer that decides which version of the agent gets to act at all.

Scope: fixed LLM editors throughout (no jointly co-evolving editor), initially-correct founders only, externally-specified contracts, and validators assumed correct within tested conditions — the paper does not test what happens when the validator itself is wrong or gamed. Built on unmodified third-party search infrastructure (OpenEvolve + DGM) rather than a bespoke optimizer, which cuts against the risk that the persistence finding is an artifact of a toy search loop the authors built to fail this way.
