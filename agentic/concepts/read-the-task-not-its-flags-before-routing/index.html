Misleading flags are worse than no flags

The result that makes this worth a note is not that a model router beats a keyword router. It is the middle row, and it is the row that would have been left out of most papers.

A keyword-and-flag heuristic is perfect on aligned cases (100%) and scores 0% on adversarial ones — below the 20% a fixed router achieves by always choosing the same action with no signal at all. Misleading metadata is worse than none, because it is acted on. Then a TF-IDF router with no model and no learned weights, matching the task description against fixed per-route prototypes, clears every adversarial case (100%) while giving back a few aligned ones (88%) where the flags really were the cleaner signal.

So the sharp line is what the router reads, not how much intelligence it brings. Any router that reads the request clears the adversarial set; flag matching alone collapses. That reframes the operational question from "is an LLM router worth the latency and the tokens" — the framing every orchestration vendor uses — to "is my router looking at the request or at labels someone attached to it."

This is the coordination map's substrate argument at the dispatch step. The map's live hypothesis is that the coordination tax is raw, unvalidated state routed through a serializing controller (verified-shared-state-beats-orchestrator-routing, event-passing-beats-shared-context-in-agent-fleets). A complexity flag is precisely raw derived state: something upstream summarized the task into a token, the router consumed the token instead of the task, and the summary was wrong. It rhymes closely with the model-routing finding that a router should scout the repository rather than read the issue text (route-after-scouting-the-repository-not-from-the-issue-text) and with the general result that routing decisions must be learned from rollouts rather than asserted (a-routing-policy-must-be-learned-from-rollouts). Two literatures, same shape: the cheap proxy the router was given is the thing that fails.

The practical steer is small and immediately actionable for anyone running a dispatch layer: if your orchestrator routes on tags, complexity scores, file-extension rules or an upstream classifier's label, the cheapest improvement available is not a smarter router — it is giving the existing one the request text. And the cheapest test is this paper's design: build a small adversarial set where the flags and the intent deliberately disagree, and check whether your router does worse than always picking one route.

Bounds are real and the authors state them first. 26 author-labelled cases, no second annotator and no inter-annotator κ; the diagnostic saturates for a capable model, so it isolates when keyword routing fails rather than grading difficulty; the adversarial set is deliberately a worst case for flag matching, so the 0% is a designed floor rather than a field rate. The larger workflow-suite evaluation the harness was built to host — where a graded comparison and the "when does routing pay off" question would actually be answered — is future work. Read this as a mechanism isolation, not as a routing benchmark (a-routing-claim-needs-a-no-router-ablation is the arm this diagnostic does not run: nobody checked what sending everything to the most common route with the rest of the pipeline intact would score beyond the 23% fixed baseline).
