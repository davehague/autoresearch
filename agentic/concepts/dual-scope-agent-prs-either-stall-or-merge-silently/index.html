This map's contest has been fought almost entirely on test-suite strictness; this is the first source to show the backstop can be structurally absent — not weak, absent — for exactly the PRs where a wrong change reaches production fastest

Every standing crack-in-the-backstop finding on this map — undetected coverage gaps, co-generated test/fix correlation, flaky agent tests — presupposes there is a gate being evaluated, just one that's leakier than it looks. This source measures PRs that touch deployment infrastructure (CI/CD manifests, containers, provisioning) and finds a population where, 43-56% of the time when matched against application-only controls, no human review happens at all: zero comments, zero iterations, closing in under 30 minutes. A green local-sandbox test run — the thing every position in this map's contest argues about the strictness of — says nothing about whether a changed GitHub Actions workflow or Terraform manifest is correct, and infrastructure changes are exactly the content this source finds merging most silently.

The causal isolation of agent identity (OR=0.363, independent of change content) is the map's sharpest evidence yet that the gate's porousness is partly about who submitted the change, not only what changed — directly extending agentic-code-review's own social-variance finding (submitter attributes carrying 69-76% of merge-outcome explanatory power, self-integration multiplying agentic merge odds ~5,419×) from the general merge-outcome question to the specific review-presence question, and from arbitrary PR content to infrastructure-touching content where a review absence costs the most.

The bimodal split (slow when reviewed, fast and silent when not) is itself the finding, not a contradiction: it means the same category of change produces a safety-relevant delay tax for the subset that gets looked at and a near-zero-latency, zero-scrutiny path for the rest — a worse version of this map's 2026-08-19 "aggregate is a net over two-sided churn" lesson from evaluation-integrity, here applied to review presence rather than to score deltas.

Bounds: severe data attrition specific to Claude Code in AIDev (94.50% of Claude PRs lost to API payload limits) means the paper's own AIDev per-agent dual-scope-prevalence numbers for Claude Code are explicitly flagged as an artifact requiring MOSAIC-based imputation; matching is on file counts rather than lines of code, and developer intent, prompt iteration, and offline communication are all unobserved; the human baseline (MOSAIC) may itself include undisclosed AI assistance, which the authors argue biases the measured agent-vs-human gap conservative rather than inflated; MOSAIC's 80 matched pairs leave limited power and no subdomain-level breakdown; results are scoped to a June-July 2025 cohort, specific model versions, and repos with >100 GitHub stars.

Interaction edge → agentic-code-review: the review-odds regression (agent identity OR=0.363, independent of content) is a directly comparable quantity to that map's own submitter-identity merge-odds findings — the two sources measure different outcomes (review presence vs. merge outcome) on different populations but the same underlying mechanism, and a head-to-head comparison of effect sizes is now a cheap cross-map experiment.
