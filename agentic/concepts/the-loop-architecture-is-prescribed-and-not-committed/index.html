The loops are real. The architecture around them is a belief held in blog posts.

This map's practitioner half has been accumulating a prescription: a trigger, a machine-checkable stop condition, durable state outside the context window, an independent verifier, budgets with a kill switch, binding constraints on what an unattended run may change, and defined escalation points. This is the first measurement with a denominator, and the prescription and the practice come apart cleanly along one line: configuration is committed, runtime state is not.

Triggers are the common case — 253 repositories, and all but one of 323 occurrences is a GitHub Actions workflow. Everything downstream of the trigger is missing as a committed artifact. Zero stop conditions. Zero verifier subagents linked to a loop. Zero budgets. Zero cost logs with measured values. Two candidate state files, both rejected on inspection as unrelated "loop" vocabulary. And of 1,334 plausible state files with real commit histories across 637 repositories, none shows the append-only run-log shape the discourse prescribes; cadence and authorship co-occur on exactly one file in the entire corpus.

Which zeros mean what, because the paper is careful and the distinction decides the reading. Parallel isolation is genuinely untraceable — worktrees are local, and the 3,507 repositories with claude/-prefixed branches reflect ordinary agent use rather than loop isolation. The empty goal row is partly a rule artifact: manual annotation found a stop-condition mechanism somewhere in 55 of 256 inspected repositories, mostly as terminal states or retry caps written into committed prompts, which a fixed-phrase matcher will not see. But state, verifiers, budgets and cost logs are absent from version control, and the behavioral signals agree independently. Since loops demonstrably run in these repositories, their state is either outside version control or in files the candidate names do not cover — and the study cannot separate those two. That is the honest limit of the finding.

What it does establish, and this is the part with teeth for anyone running a loop: the artifacts you would need to audit a loop after the fact — what it was supposed to stop at, what checked it, what it was allowed to change, what it cost — are the ones nobody commits. A loop whose trigger is in git and whose stop condition, verifier, and budget are in a vendor UI or a shell profile is a loop that cannot be reviewed, diffed, or reproduced. This is the-durable-unit-needs-a-contract-not-a-checkpoint's argument arriving as a census rather than as advice — and it is why "verifier theater", the failure mode the discourse names most loudly, is hard to detect from outside: there is no artifact to inspect.

Two verification lessons from the method itself, both independent of the loop question:

  1. A successful workflow run is not evidence that an agent ran. One repository's hourly Gemini triage logged 6,290 successful runs with zero agent executions, because its gating issue search matched nothing. The authors had to amend their codebook mid-study: a run counts only with a step duration long enough for real work, or with produced output. Anyone monitoring their own scheduled agents on exit code alone is measuring the same nothing.
  2. Fast automatic review can be a personal account setting invisible to the repository. In 95 of 159 repositories with measurable review timing, Copilot reviews arrive within minutes and cluster on individual authors' PRs — the signature of a standing per-account auto-request, which the study deliberately refuses to count as project adoption.

Bounds — and the recall hole is the big one. The heuristics have measured precision (0.868) and no measurable recall, because estimating false negatives would require repositories known not to run loops and no such set exists. A loop leaving no committed trace — a tool-native /loop scheduler, a local cron entry, private infrastructure — is invisible by construction. 0.59% is a floor on committed-trace loops in public GitHub, not an estimate of how many people run loops. Public repositories only, one snapshot, and Claude Code accounts for 189 of the 217 confirmed, so the tool mix is not a market share.
