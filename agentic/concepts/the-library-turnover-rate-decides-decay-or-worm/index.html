An epidemic threshold in a config value

This map's practice is built on externalized, durable state — make the project persistent rather than the agent (make-the-project-persistent-not-the-agent), keep the run's state outside the process, put the agent on the pager and not on the gate (put-the-agent-on-the-pager-not-on-the-gate). Persistence is the thing that lets an unattended agent run for weeks instead of minutes. This is the first measurement of persistence as a transmission medium, and it comes with a threshold.

The finding is that a durable store which the agent both reads from and writes to is a population, and a defect in it behaves like one. Hold the model, the attack and the library size fixed and vary only how much of the library is swapped for fresh entries each round: at a quarter turnover the infection dies back to its seed rate and never grows; at half it amplifies to a stable plateau where infected entries arrive exactly as fast as benign replacements dilute them; at three quarters it exceeds that plateau and is still climbing when the experiment ends. The authors formalize it as a branching process with a reproduction-number proxy over copy propensity and reach, which is the right shape — sub-critical, critical, super-critical, with the operator sitting on the dial.

Why this is an operations finding and not a security one. Nobody sets a skill-library replacement rate for epidemiological reasons. It is a housekeeping value — how aggressively to retire stale tools, how much churn a growing library tolerates — and the natural instinct for an unattended system is that more turnover is healthier, because it clears out accumulated junk. That instinct is exactly backwards for this failure mode: faster replacement is what tips a decaying infection into a self-sustaining one, because it keeps feeding the retrieval pool with fresh slots that the agent's own copies compete to fill.

And the parameter you would reach for first is the one that does nothing. Attack rate saturates in the seed count by about eight plants (19.6% at one, 41.8% at eight, 43.1% at sixteen), and a single seed at a 0.4% poisoning rate already produces 19.6%. Hardening the admission side — making it harder to plant — buys almost nothing, because retrieval saturates and the per-retrieval copy rate is a model property. The lever with a threshold in it is the turnover rate; the lever everyone reaches for is the seed count.

The mechanism connects back to what makes a persistent store useful at all: in the persistent condition the in-context rate rises from 78% toward 100% as the library fills with the agent's own copies. The store gets better at surfacing its most-represented content, which is the property you built it for, operating on content you did not intend.

The general lesson for this map is broader than skills, and worth carrying forward as a question rather than a claim: any unattended loop with a read-write durable store — memory, skills, learned rules, cached plans — has a turnover rate, and nobody has measured where the critical value sits for the ones that are not skill libraries.

Bounds. One model for the sweep, one attack, one skill-memory implementation, five simulated rounds — this is a controlled cascade, not an observed production deployment. The threshold's location is specific to that configuration and the paper does not claim the numeric values transport; what transports is the existence of a threshold and which parameter controls it. Whether the same dynamic appears in non-adversarial degradation (an-unguarded-skill-pool-peaks-then-degrades found a peak-then-decline shape with no attacker) is untested and is the obvious next experiment.
