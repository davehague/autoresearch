A proxy that grades honestly, read as a claim it never made

This map's catalogue is mostly proxies that misgrade the agent, always optimistically: merge labels, pass@1, LLM judges, self-report, benchmark speedups, paired architectural deltas. This is a different shape and the map should carry it separately. Resolved rate is not broken. It measures functional repair, it measures it correctly, and it is then reported as model progress — a claim about the code, not about the count. Hold the tasks fixed and the code does not improve: median paired difference of zero on every static measure in both model families, nothing surviving multiple-comparison correction, and slightly higher peak memory for the later models. Two axes moved in the headline; only one of them moved in reality.

The methodological artefact is the more transferable half. On the full resolved sets — each model scored on the instances it happened to solve, which is how every leaderboard comparison is constructed — CodeQL produced a significant difference at p = 0.039. Match the instances and it disappears, because the sets are not comparable populations: 57 of the 71 instances both Claude models solved came from Django, while 31 of the 62 that only the later model solved came from SymPy, and the exclusive sets differ significantly from the common set on gold-patch CPU time and memory. A difference attributed to model quality was task composition. That is a general hazard for any capability comparison scored on per-model success sets, and it has an easy remedy — match, then compare — that almost nobody applies.

The paper does something rarer still, and the vault should cite it for this specifically. Most paired differences are literally zero, so the authors compute the smallest two-sided p-value their test could have reached given the number of non-zero pairs — about 0.063 and 0.125 — and state that a reported p = 1.000 "did not constitute evidence that the two models were equal." A null result and a null instrument, separated and both published. That belongs beside skewed-label-bases-inflate-classifier-headlines (a headline F1 of 0.958 against a 0.957 majority baseline) and coordination-deltas-need-a-measured-noise-floor (protocols made inert before either mechanism could act, still disagreeing by up to 18 pp): three papers, three domains, one discipline — establish what your comparison would show under no effect before reading what it shows.

Two secondary readings worth keeping. Regressions outnumber improvements by roughly an order of magnitude in every model under both tools, on patches that passed the benchmark's tests — so the population a green build certifies is one where degradation is the common non-neutral outcome. And the two static tools disagree about the same patches, with the gold human baseline reversing their ordering entirely (CodeQL flags 50.5% of human patches as regressions, CodeScene 19.6%). Neither is "the" quality axis; a study reporting one is reporting a tool's opinion.

Caveats: the model pairs differ in tier and reasoning configuration, not only release date, so each is a case study rather than a generation test; a $0.50 per-instance cap may bind unevenly; the matched design says nothing about the additional instances the later models resolve, which is where the resolved-rate gain actually lives; CodeQL net change is confounded by code movement, so it is a change in the report rather than in semantics; resource measurements cover only the paths SWE-bench tests exercise; and the prompt asked for functional repair, so this measures quality produced incidentally, not a model's ability to optimize quality when asked.
