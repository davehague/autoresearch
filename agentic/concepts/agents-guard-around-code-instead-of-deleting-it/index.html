It found the code, it just would not cut it

The localization ladder is the whole argument in three numbers. Given a line the developer removed, a frontier model edits the right file 92.5–94.4% of the time and the enclosing function, class or module 68.1–74.4% of the time — and removes the exact line 44.6–51.6% of the time. The drop from file to scope is localization. The further 21–28 point drop, occurring after the model has already edited the enclosing scope, is not.

What it writes instead is a guard. Keep the logic the developer deleted, add a condition that handles the reported case, and let execution route around the old path. 29.0% of all passing patches do this. Isolate the behaviour completely — supply the whole file, make deletion the entire task, remove cross-file localization and any replacement work, score with a deterministic occurrence-aware evaluator and no judge — and the best of twelve models still fails one task in five.

For review, the operative detail is which guard it writes. The dominant structural form, 221 of 550 typed pairs (40.2%), is Retained Path as Live Fallback: the new condition handles the reported input and the developer-removed logic stays the default path for everything else. That is not dead code a linter will flag and not a comment a reader can skip. It is a live branch, and a reviewer cannot approve the diff without reading both paths and deciding whether both are still needed — on a patch that is larger than the human one in 61.1% of pairs, at a median ratio of 1.67×.

This is the same species as the map's existing measured maintenance tax and it composes with it. CodeSlop is the search that produced the fix surviving into the fix, 17.9–32.9% of an agent patch (codeslop-is-the-search-surviving-into-the-patch). Guard-and-Go is the code the fix was meant to retire surviving into the fix. Both inflate the artifact, both are invisible to a behavioural gate, and churn on functionally correct patches already tracks maintainability degradation at ρ 0.30–0.48 (patch-churn-predicts-quality-degradation). The map has held since its founding that reviewers of agent PRs spend their attention on the maintenance surface rather than primarily on logic bugs (agentic-pr-review-targets-more-than-correctness), and that maintainers reject already-passing agent PRs citing verbosity and departure from convention. This names one concrete generator of that verbosity and sizes it.

The mitigation ladder is the practical part, and it rules out the cheap fix. An explicit no-workaround instruction — tell the model not to do this — moves success by −2.5 to +2.5 points. A region pointer moves it 0.0 to 7.0. Only handing over the exact spans moves every model, by 6.5 to 31.5. So this is not a misread instruction and not a search failure: what is missing is knowledge of where the removal ends. Which is the map's installability finding restated in a new domain — a correction's effect tracks how constrained it is, from 0.97 for a fixed stop token down to 0.14–0.71 for open-ended prose. "Delete rather than guard" is an open-ended correction and behaves like one.

And constraining it surfaces the opposite failure. Handed exact spans, GPT-5.6 Sol's invalid-edit rate barely moves (16.0% → 16.5%) while Qwen3-235B's rises from 20.5% to 26.0% as retention falls — the model now deletes past the boundary or adds code instead. A single pass rate cannot tell which side moved. For anyone tuning an authoring agent against this, that means the metric to watch is the mechanism split, not the success rate: models trade incomplete deletion for over-deletion at roughly one-for-one, and a 7B post-training pilot reproduced the same exchange (incomplete deletion −13.9 points, of which 6.7 became complete-but-invalid edits and over-deletion alone rose 6.2).

Bounds. The in-the-wild patches come from leaderboard submissions with uncontrolled decoding, all predating December 2025 — which is why the deletion-sensitive retrofit uses fresh generations from four current models. Guard-and-Go labels come from an LLM classifier required to cite lines from the supplied diffs, with unsupported labels rejected; a closed coder assigned a structural form to 550 of 684 pairs and declined on the other 134. The developer patch is a behavioural reference, not the unique correct repair, so an individual mismatch is not by itself an error — the claim rests on the pattern recurring across five models and 2,358 pairs. Patch size alone does not prove the added code unnecessary; read with the strategy labels it shows a subtractive repair becoming a larger additive one.
