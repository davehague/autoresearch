A benchmark's cheap before/after differential test can both pass the wrong input and fail to catch a task whose "fixed" version still has the bug — CyberGym's own numbers move when both are checked

A new, cleanly-mechanistic instance of evaluation-integrity's benchmark-and-contamination-validity sub-thread (1): CyberGym's differential-pass criterion (crashes the vulnerable version, doesn't crash the fixed version) is a cheap executable proxy for "the agent reproduced the reported vulnerability," and this audit shows the proxy diverges from the target in both directions it could. First, task materials themselves can be internally inconsistent with the reference defect — in the largest category (coverage inconsistency, 205 of 338 flagged tasks), the delivered "fixed" version the checker scores against still contains a defect matching the task description, so a PoC that reaches it can be wrongly rejected even though it demonstrates the right defect, or wrongly accepted for the wrong reason. Second, independently of material consistency, a submitted PoC can satisfy the differential test while triggering a defect other than the one the task is actually about — the HarfBuzz arvo-12312 worked example (PoC hits an unrelated CFF-parser index bug, passes only because the fixed version happens to also patch that unrelated bug) makes concrete what the 89-non-target-verdict aggregate number means. The 3.7% non-target rate inside materially-consistent tasks is the finding that matters most for generalization: it shows identity failure isn't just a downstream symptom of bad task construction, it's a separate property of what the agent's submission actually hits, so repairing task materials alone would not close the gap.

The generalizable lesson for this map: any benchmark that scores agentic work with a before/after differential oracle (crashes/doesn't-crash, fails/passes, before-score/after-score) inherits both failure modes shown here — task materials that silently misidentify the target, and submissions that satisfy the oracle's letter while missing its intent — unless it separately audits consistency of its task-construction materials and the identity of what gets accepted. harness-as-score-confound's use of 21 CyberGym Level-0 instances as external-transfer corroboration (harness-matters-vulnerability-discovery) is Level-0 (vulnerable source only, no description), which is less exposed to the joint-mismatch/misleading-description identity failure modes measured here (those require a description to be wrong), but not to the coverage-inconsistency failure mode (a defect-retaining "fixed" version is level-independent) — a caveat worth carrying forward on that corroboration, not a reason to discount it.
