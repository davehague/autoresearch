Independence buys a different blind spot; headroom buys a catch

The map reached independence of the observer as the active ingredient in a review gate from three results that never varied capability: reviewer monoculture correlating with higher smell prevalence, the 6 → 2 collapse in rescues when observe/compare returns to the generating model (structure-outweighs-the-verification-step), and a cross-model checker beating self-checking 79% to 71% (an-independent-checker-beats-the-same-model-checking-itself). This is the first grid to vary both, and independence alone does not survive it.

The most independent available condition — the weaker model reviewing the stronger model's draft — is the only significantly harmful cell, fixing 3 and breaking 13. The least independent condition on the weaker writer — the model reviewing its own draft — is significantly positive at +12.9 pp. Read together with the strongest cell (+18.1 pp, the stronger model reviewing the weaker one's draft), the ordering is capability-shaped, not independence-shaped.

The reconciliation, and it matters for where you spend. The cross-model-checker result that established independence was measured on a task with an external anchor: re-derive the target from the original request and compare. There the auditor needs only to be uncorrelated, which is why a smaller model auditing a frontier one worked. Here the reviewer must find a defect by inspection with no execution, no tests, and nothing to re-derive from. When the check has an external ground truth, buy independence. When the check is a judgment call, you are buying capability, and a cheap independent reviewer is worse than none.

The practical test is cheap and nobody runs it: before deploying a reviewer, run it on drafts you know already pass and count the regressions. A gate that rewrites 13 correct solutions per 106 to catch 3 new ones is negative value, and its resolution rate would look fine (grade-the-reviewer-on-what-the-author-fixed) because every rewrite it lands is a resolution.

Caveats: competitive-programming tasks rather than repository-scale review; a single static pass with no execution, tests, memory or iteration; n = 116, one run per condition, so nothing here is floored (coordination-deltas-need-a-measured-noise-floor); two models only; and the authors state the design cannot separate review direction from the baseline capability gap and read the ordering as descriptive rather than causal. Suggestive for the headroom claim, single-study for magnitudes.
