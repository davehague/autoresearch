Bookkeeping looks reversible, and it is not

The reason skill admission has escaped scrutiny is a plausible intuition: writing an entry into a pool is bookkeeping, and bookkeeping can be undone. Delete the bad row later. The measurement says the second half of that is false, and the argument is structural rather than empirical.

Skills are distilled conditioned on the pool that was live at the time — formally S_r ∼ π(· | M_{r−1}). A defective skill admitted in round 3 is therefore reference material for everything written in rounds 4 and 5. Its flawed reasoning survives in descendants that never name it, so removing the source is strictly weaker than removing the source together with its lineage. The authors' worked case is small enough to hold: one git-conflict skill distilled at R3 seeded two derived skills at R4 covering merge and rebase workflows; after source-only rollback both survived and kept failing 4 of 7 git-related held-out tasks.

The decomposition is the finding. Of a 12.3-point collapse: source-only removal buys back 1.7, full-lineage oracle cleanup a further 5.0, and 5.6 points cannot be recovered at all — the loss is baked into the pool's state rather than carried by a few removable entries. And the middle number is not available to anyone: it requires knowing which skills were in context when each skill was written, and shipped skill libraries do not record it. So a real operator's ceiling is the 1.7, and the honest reading of "we'll audit the skill bank and remove what's hurting us" is that it recovers about an eighth of what the contamination cost.

This is why the gate has to sit before the write, and it changes what "detection" is worth. Most of this vault's defensive machinery is detection-then-remediation — attribute the failure, then rerun (close-the-loop-from-attribution-to-rerun); flag the bad artifact, then fix it. Here better detection converges on the oracle, and the oracle still leaves nearly half the damage in place. The pre-commit gate exceeds that ceiling by 15.3 points. That is a different class of argument from "gating is more efficient": it says post-hoc curation is bounded below the intervention no matter how good your detector gets.

The shape generalizes past skill banks, and it is worth naming for anyone running a self-modifying artifact. Any store whose future writes are conditioned on its current contents has this property. A memory system that summarizes over prior summaries, a context file regenerated from a repository that includes the previous context file, an evolved harness whose next mutation is proposed by reading the current one — all inherit "removing the source does not remove its consequences." The vault's existing instances of the pattern are about fidelity rather than contamination (compaction-can-launder-killed-process-output, persisted-state-without-revalidation-amplifies-errors), but they are the same lineage argument, and the mitigation is the same one: the admission point is the last place the defect can still be stopped (pre-write-admission-buys-reliability-by-serializing, gate-a-skill-update-on-a-replay-of-what-it-might-break).

The cheap operational takeaway, if you ship a skill bank and are not ready to build a gate: record the provenance you would need to recover. Which skills were in context when each skill was written is one extra field, it is free at write time, and it is the difference between the 1.7 and the 6.7. The paper's system also versions its bank in a git worktree with replay outcomes in SQLite — the same instinct as last week's arrival, from a different group.

Rebutted by: a-batch-level-admission-gate-is-not-a-complete-filter — on the unconditional half of the claim. A second group's batch-level admission gate still admitted negative-utility material by their own measurement, and their post-hoc removal recovered real points (−2.5 pp when the removal stage is ablated; one section's removal moving validation hard accuracy 46% → 54%). The tension resolves into a scope condition rather than a contradiction: the recovery gap measured here is entirely the descendant lineage, so removal is bounded below gating exactly where the removed material conditioned later writes, and not where it is inert reference text inside a single artifact. Which regime you are in is decided by provenance — which is the field this note already says nobody records.

Bounds. One benchmark, one backbone, 50 evolution tasks, and the 12.3-point collapse it decomposes is itself a single trajectory whose per-round intervals overlap (an-unguarded-skill-pool-peaks-then-degrades carries that caveat in full). The irreversibility argument is structural and does not depend on the size of the number; the specific split of 1.7 / 5.0 / 5.6 does.
