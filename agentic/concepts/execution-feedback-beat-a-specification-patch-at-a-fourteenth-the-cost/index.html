Two ways to tell an agent it was wrong, priced against each other on the same failures

This map keeps finding that the repair signal's source matters more than its volume. Here that comparison is run as a pre-registered head-to-head with a cost column, which is rare enough to carry on its own.

The two arms answer the same question — the code is broken, what do you feed back — from the two places this vault's maps sit. Execution feedback: give each implementer its own psql stderr, one round. Specification patch: fix the document the implementers read, one round. Same failures, same panel, registered expectations fixed in advance for both.

Execution feedback: $0.03, broken-code errors 85 → 46, both registered expectations confirmed. Specification patch: $0.41, all three registered expectations failed. Roughly 1/14 of the inference cost for the arm that worked. That is the same shape as evidence-quality-feedback-mostly-works-by-prompting and gate-the-edit-on-evidence-observed-not-claimed — an observed failure outperforms an authored description of what should have happened — with the price attached, which turns a design preference into a routing decision.

The scope condition is the reason this is not just "execution feedback wins," and the authors measured it in both directions. Specification patching was effective when the added rule arbitrated between plausible defaults — where the implementer had no strong opinion and needed a decision — and ineffective when it contradicted a strong implementer prior. That maps cleanly onto what a-specification-buys-executability-not-agreement found at scale: the decisions a specification pins are mostly ones the implementers already agree on, so the rules with the most leverage are exactly the ones fighting a prior, and those are the ones patching cannot move. A document is a weak instrument for overruling a model's habits; an error message is a strong one.

The two mechanisms own disjoint divergence buckets, which makes them complementary rather than competing — the same relationship an-executable-check-and-a-model-judge-fail-on-different-inputs reports for checkers. And the leftover is the useful part of the taxonomy: a third bucket of roughly 60 events of missing behaviour is owned by neither, because a specification cannot make the absence visible and an execution loop never trips on code that quietly does not raise. Its natural owner is a test that asserts the error fires — which is this map's standing argument for make-the-agent-write-the-contract-before-the-test arriving as a gap rather than as a preference.

The wider context in the same study reinforces the direction. Adding ≈1,900 tokens of guidance on how to consume the specification moved compliance −2.3 pp; relocating one byte-identical sentence moved it 19% → 42% (put-the-rule-in-the-dominant-structure-once). Where document-side intervention pays, it pays through structure, not through volume — and where the loop can observe the failure directly, the loop is cheaper.

Scope. One repair round, one migration domain, two implementers on a fixed panel, one model era. The cost ratio is list price on this task shape, not a general figure.
