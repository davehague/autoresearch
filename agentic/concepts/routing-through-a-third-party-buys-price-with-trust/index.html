The first entry in this ledger priced in trust rather than dollars

Everything this map has accumulated prices routing in money: budget-aware sequential allocation cutting cost 6–73.5% (route-the-session-not-the-query), a production classifier trained on live traffic reporting 60% savings (route-with-a-classifier-trained-on-live-traffic), prompt caching inverting cloud-versus-local economics (prompt-caching-inverts-cloud-versus-local-economics), a learned recovery router at 35% of always-escalate's cost, cheap configurations relocating cost into repair labor (cheaper-inference-relocates-cost-into-repair-labor). This adds a column the ledger did not have.

The mechanism is structural, not a vulnerability class. A third-party router terminates the client connection and reconnects to the provider, so it holds plaintext system prompts, repository context, tool specifications and tool-call payloads, and it can modify the response before the agent acts on it. No agent verifies that the response it consumed is the one the provider produced. Under that condition every client-side control measured — permission modes, plan mode, allowlists, in-agent review — reads zero (an-intermediary-on-the-response-path-voids-client-side-gates).

The distinction that decides a deployment: a first-party router, where a vendor routes inside its own product and its own trust boundary, does not create this gap. A third-party aggregator does — and it is precisely the aggregator that makes multi-provider cheap-tier routing convenient, which is the design this map's own findings keep recommending. So the cost-optimal architecture and the integrity-optimal architecture point in opposite directions, and nobody has priced the difference. What would settle it is the quantity nobody publishes: the delta between an aggregator's price and a first-party or self-hosted-gateway price, set against the population base rate of tampering. The 428-router survey gives a numerator for the second half and no denominator.

This also relocates a known cost. cheaper-inference-relocates-cost-into-repair-labor found the cheap configuration paying for itself in fix commits. This is a second relocation: the cheap configuration paying for itself in an unpriced integrity liability, which — unlike repair labor — has no smooth expected value and is not visible in any operational metric the deployment collects.

Caveats: the security study is a controlled instrument (400 hand-built injections, three tasks) rather than a prevalence estimate; the population numbers come from a cited prior survey. The economic side of the tradeoff is unmeasured here — no paper prices the aggregator discount against the integrity risk.
