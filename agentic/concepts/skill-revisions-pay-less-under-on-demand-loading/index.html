The persist-and-deliver discipline, measured at the level of a single edited line

This map's sub-thread (1) asks what an agent holds and how reliably it is delivered. Agent Skills are the sharpest instance of "deliver, don't hold" this map has: progressive disclosure means the name and description sit in the system prompt permanently, and the body — the actual rules — enters context only when the harness decides the Skill is needed. This paper is the first to isolate what one edit to that body does, holding model and request fixed and swapping only old-vs-new Skill text on the same probe.

The headline transfer is positive and real: a rule that names a command or path the old Skill didn't mention measurably changes behavior — not just in a single answer (+0.41 compliance) but through an entire multi-turn sandboxed episode (+0.23 action rate, +0.10 final correctness), and the effect holds across six independent model-generation ladders without a capability trend. That is useful ammunition against the map's standing skepticism that a Skill's prose mostly doesn't matter.

But the number that should set expectations for a real deployment is the on-demand one. Every number above is measured with the Skill's body always shown — the demo condition, not the production one. The moment loading becomes conditional on the harness's own judgment that the Skill is needed, the gain roughly halves for agents (51% retained) and drops further for open models (38%), and the drop is not explained by the model failing to notice the rule (uptake stays at 62-81% even as the effect shrinks). This is a concrete, quantified instance of the gap between "the context contains the right text" and "the agent acts on it," which is exactly this map's standing distinction between availability and use — previously measured for facts at long context distance, now measured for an instruction the harness itself chooses whether to surface at all.

The cost finding closes a loop this map has been circling: carrying a Skill's body costs 37-57% more tokens regardless of whether the specific rule in it helps this request — the overhead is structural (bigger context window to read), not amortized against the value delivered. Combined with the on-demand retention numbers, the practical guidance sharpens: a maintainer editing a Skill is paying close to full freight on every load, for a behavioral change that a real harness will only partially deliver.

Does not move this map's status — single research group, one revision-extraction pipeline with real precision/recall limits (κ=0.70 on content classification, extractor recall as low as 0.13-0.21 for some reference types), and every effect is explicitly conditional on a request that needs the rule (the authors' own back-of-envelope discount for how often real requests need a specific rule drops the expected gain roughly 4x). But it is the map's first study to hold model and request fixed while varying only a Skill revision, rather than Skill-vs-no-Skill at one frozen version — the natural complement to this map's existing on-demand-loading and progressive-disclosure findings.
