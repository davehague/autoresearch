The test suite and the specification are different sieves, and the harder problem this map already knows about — an agent cannot be trusted to author the thing that checks it — recurs one level up, in the specification itself

This map's core claim is that independence is a property of the arrangement, not the identity of the checker — and one of its four provenance terms is who authors the thing the checker checks (a-kernel-checked-proof-still-needs-an-axiom-allowlist, the Lean-kernel result where an agent authoring its own proof term needed an axiom allowlist to stop it exploiting evaluation escape hatches). SWE-Proof measures the same term on ordinary SWE-bench-style patches rather than formal proofs, and the two halves of its result are the map's provenance argument stated twice, at two different points in the pipeline. First: when Benchproofer's own audited construction pipeline writes the specification, formal verification is strictly stricter than a held-out test suite — 25-50% of patches a test suite calls "done" fail a machine-checked specification, and having a correct specification to prove against is worth 10 points of resolution rate. Second, and this is the finding that belongs on this map specifically: when the model being evaluated is asked to write its own specification instead of receiving Benchproofer's, it gains nothing at all over not verifying anything, because self-authored specifications are unfaithful 38% of the time (62% pass rate) — the same failure this map calls "the agent games the oracle it's given the pen to write." A specification is, in this map's vocabulary, exactly a checker; letting the agent author its own checker reproduces the axiom-allowlist problem in natural-language-adjacent form, without a kernel to catch the escape.

The size of the gap (0 pp gained self-authored, 10 pp gained pipeline-verified) is this map's clearest evidence yet that "let the model write a spec and then satisfy it" is not a cheap substitute for external verification — it is the null result the map's independence thesis predicts. Faithfulness, not detection, is named as the dominant failure mode: a specification that correctly constrains part of the required behavior and silently leaves the rest free is the natural-language cousin of a checker denied nothing, checking nothing that matters.

Bounds worth carrying forward: the paper does not decompose the 25-50% counterexample rate into "genuinely wrong patch" versus "legitimately underspecified original issue," so how much of that number is test-suite blindness versus formal-spec-versus-real-intent mismatch is unresolved — a question this map's existing referent-independence findings (the-referent-not-the-reviewer-carries-the-separation) would predict matters. And the specification-quality audit is the paper's own instrument, not an independent adjudicator, so the 62% pass rate inherits whatever blind spots that audit has.
