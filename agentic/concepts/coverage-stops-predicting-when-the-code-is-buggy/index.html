Show the model the defect and the defect becomes the specification

Defects4J Lang-14, StringUtils.equals. Given the fixed implementation, the model writes assertTrue(StringUtils.equals("abc", new StringBuilder("abc"))) — the intended CharSequence semantics. Given the buggy implementation, which delegates to cs1.equals(cs2) and therefore returns false across CharSequence types, the same model with the same prompt template writes assertFalse(...). It read the faulty behaviour as intended and encoded it in the assertion. That test can execute every changed line, report high coverage, and certify the bug.

This is why the map's most natural remedy needs a scope condition. After the 2026-07-22 finding that the existing human suite executes no changed line at all in 64.8% of Python agentic PRs, the implied policy was a diff-coverage threshold computed outside the agent (a-passing-suite-does-not-mean-a-tested-change). That threshold remains defensible as a floor — it catches the vacuous case. It is not a quality signal for the suite in front of you, and in the bug-fixing setting it is not a signal at all.

The paper's second contribution is a granularity discipline the literature omits, and it changes the reading of the whole prior literature (see proxy-metrics-rank-models-not-suites): report the correlation at every level — pooled across models, within a model, and across models — because coverage is strongly informative at one level (r ≈ 0.86 across models) and near-zero at the next.

Two smaller corrections to inherited practice. Coverage criteria are not interchangeable for machine-written suites: under accumulated aggregation, modified-condition coverage correlates only weakly with statement and branch coverage, so the 2014 advice to pick the cheapest criterion does not carry over — report several. And compile/pass rate is a cost measure, not an effectiveness measure: a higher fraction of compiling tests means less of the generation budget was wasted on unusable output, nothing about fault-finding power.

Read with fail-to-pass-does-not-constrain-the-fix, the map now has three separate proxies for a machine-written gate — presence, reach, and fail-to-pass — each measuring something real and none measuring what it is used for. The two 2026-07 papers converge on the same exit without citing each other: grade the test against something the generator did not see, which in practice means adversarial mutants of the current patch and writing the reproduction test before the fix with source files off-limits (agents-build-to-the-oracle-you-expose).

Caveats: Java and Defects4J only, one prompt template, temperature 0, white-box prompting with the code-under-test as primary input; the inter-model view rests on 13 data points. Developer-written Defects4J oracles may be in training data, though the systematic buggy-versus-fixed divergence argues against pure memorization.
