This map has named the harness, the scaffold, the serving wrapper and the inference backend as layers where the apparatus can confound a score; this is the first arrival to put the benchmark's own scoring code — the oracle — on that list, and to show the configuration layer (policy/tool-description/error-string text) moves the measurement too

Every prior arrival on this map treated the harness as a black box sitting between the model and the reported number — a scaffold, a wrapper, a runtime — and asked whether swapping it moved the score. This source asks a structurally different question: is the thing that grades the run itself reliable? The answer, demonstrated rather than argued, is no — not categorically, but concretely, on a benchmark this vault and the field both treat as settled infrastructure. Env.calculate_reward() resets the environment database to build its ground-truth comparison hash and never restores it. A harness that scores an episode immediately after the agent finishes never notices, because it reads the state the agent actually left. A harness that scores the episode later — after the session has closed — reads the reference solution's footprint instead, and silently converts an agent's correct or incorrect action into whichever label the oracle's own bookkeeping bug happens to produce. The author's own replay-based correction turns that into a number: 94.3% measured success is 65.5% once the database is read cleanly. That is not a capability difference. It is the apparatus term this map has been quantifying, found one layer deeper than any prior source here — in the test oracle's own state handling, not in the scaffold around the agent.

The configuration-dependence finding extends the map a second, separate way. This map's existing arrivals have mostly swapped a whole harness, a whole scaffold, or a whole inference backend and measured the resulting score delta. This source instead holds the model and harness fixed and varies three documents everyone treats as part of the agent's fixed configuration — its policy text, its tool descriptions, and the strings its tools return on error — and finds all three move how often the agent's own trajectory degenerates, even though the user simulator's language alone produces no resolved difference in aggregate pass rate. The map's remedy ("disclose the layer and run at least one arm outside it") gets a harder version here: these are documents nobody thinks of as part of "the harness" at all, and the effect's own internal ordering (tool descriptions largest, error strings smallest) reverses sign in a second task domain — the author's own caution, and consistent with this map's practice of reading a single exploratory ordering as bounded to where it was measured rather than as a general ranking.

Why this holds the status rather than moving it. The oracle-integrity method is validated on the implementations studied — one primary benchmark (τ-bench), a second task domain, and a synthetic domain — and the author explicitly declines to claim a general-purpose framework, reporting a portability failure on a second, independently implemented benchmark as a named negative result rather than omitting it. That is exactly the posture this map rewards: a single-author, single-primary-benchmark study with its limits stated plainly extends the map's catalogue of apparatus layers without yet being independent replication of this specific defect class on a second oracle. Interaction edge: evaluation-integrity — the parent map's standing worry that "a number describes the instrument as much as the agent" gets its sharpest instance yet here: an oracle bug, not a judge, a label, or a contaminated benchmark, inflating a production-grade benchmark's own headline success rate by 29 points.
