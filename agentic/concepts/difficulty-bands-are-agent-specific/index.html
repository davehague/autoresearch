A null can belong to the task set, not the treatment

This map's discipline is find the null before reading the headline — a paired floor before an architecture delta (coordination-deltas-need-a-measured-noise-floor), a majority-class baseline before an F1 (skewed-label-bases-inflate-classifier-headlines), a content-free placebo before crediting feedback (a-retry-study-needs-a-placebo-arm). This is the mirror image, and the vault has not carried it: a reported null needs the same scrutiny as a reported effect, because a task set with no dynamic range on the agent you ran cannot produce one either way.

The measurement is direct. Run the same 15 real tasks on two frontier agents from different providers. Difficulty broadly transfers — ρ = 0.75 — but the informative band does not. Six tasks are borderline for exactly one agent; six differ in floor/ceiling status. On roughly 40% of the set, whichever agent would have revealed an effect is not the one under test; the other sees a task that is already always-pass or always-fail, where no manipulation can move anything. That is enough to reconcile two published studies that disagreed about whether repository context files help, without either being wrong: they drew tasks from different agents' informative bands.

The scaling arithmetic is the operationally useful half, and it points the opposite way from common practice. At n = 17 tasks × 3 repeats even a 30 pp true effect is caught only 57% of the time. Getting to 80% power on a 10 pp effect needs 120–200 tasks. And raising repeats from 3 to 10 at fixed n moves power from 13% to 58% for a 15 pp effect — a poor trade, because task-level variance dominates run-level variance. The instinct to buy confidence with repeats is buying the wrong thing.

Two practices follow, and they are cheap. Screen the borderline band per agent before an ablation, so the set has dynamic range on the agent that will run it. And when reporting an equivalence claim, state whether it is powered or merely descriptive — a TOST bound computed on a bootstrap at n = 15 bounds what was observed, and does not license "no effect exists."

Read against harness-asymmetry-manufactures-model-differences, the pair covers both signs of the same hazard: there an undetected apparatus asymmetry manufactured a difference between two models; here a task-set/agent mismatch manufactures its absence. In both cases the number is real and the thing it is attributed to is not the thing that produced it. Note also the small portability lesson from the same source, which is this failure at metric level: an effort classifier keyed on turn count silently reclassified every task on one agent as trivial, because that agent emits exactly one turn-completion event per session no matter how much work it does — eight tasks of 18–51 tool calls were dropped until the metric was recomputed on tool calls (benchmarks-conflate-model-harness-and-penalize-alternatives).

Caveats: measured on two agents, three Python repositories and 15 shared tasks, so the 40% band mismatch is one estimate from a small sample rather than a rate to quote. The power simulation assumes binary outcomes with the observed task-level variance structure and does not model cross-agent correlation. Single author, and the reconciliation of the two prior studies is offered as a hypothesis — their exact task sets were not available.
