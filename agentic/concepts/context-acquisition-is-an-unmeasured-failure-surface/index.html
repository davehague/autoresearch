A third of the time the agent never opened the file, and no benchmark reports that

Coding agents are graded at the end: did the patch pass. That measurement absorbs an earlier stage whose failures are invisible in it. Before an agent can reason about a change it has to decide which repository files enter the model at all — through repo maps, grep, indexes, iterative reads — and nothing measures whether it succeeds.

Measured here, on real logged trajectories with real tools against frozen base-commit repositories, it fails outright on 27–35% of samples: the agent never touches any file the task required. The comforting statistic — median first hit at step 2 or 3 — is conditional on eventually hitting, so its denominator excludes exactly the failures. Interactive exploration does not dissolve the retrieval problem; it converts it into a cost, and on a quarter to a third of tasks it does not pay off.

Agentic relevance is not semantic similarity, and that is the design point. A PR describes an implementation change while the useful context is a regression test. A review comment names one file while the missing constraint lives in another module. A failure trace names a stack frame while the root cause is an implementation file that looks nothing like the error text. The benchmark operationalizes this in four tasks — code2test, comment2context, trace2code, edit2ripple — and deliberately does not count the given file, the visible stack frames, or the anchor as successes. Of 287 taxonomy-covered samples, 272 (94.8%) carry more than one relevance relation, so this is not a single retrieval problem wearing four hats.

This extends the map's 2026-07-22 boundary rather than contesting it. That result found packaged progressive disclosure buying context, not intelligence — worth nothing where the agent already navigates raw source well, decisive only once the corpus outgrows the harness's native search (progressive-disclosure-buys-context-not-intelligence). It made the harness's own search ability a named term in every context result and left it unmeasured. Here it is measured. It also composes with re-derive-file-state-instead-of-storing-snapshots: if the working set averages 2.66–7.81 files and the useful part of each is under 5% of it, then cheap re-reading and correct ranking are additive wins, not substitutes.

Two diagnostics keep the claim honest in both directions. The file-versus-span gap says a file-level hit is document reachability, not localization — median 27 useful lines inside a median 515-line file, line F1 under 0.03 for every method, and the leaderboard ordering changes when you score spans. That is the granularity discipline this vault adopted for coverage (proxy-metrics-rank-models-not-suites), arriving now for retrieval. And the 2×2 complementarity matrix refuses the tidy story: static retrieval finds gold the agent never touches on 12.5–17.8% of samples, and interaction finds gold the retriever misses on 7.7–22.0%. These are two failure surfaces, not one, and installing a retriever does not close the second.

The controlled arm is small but points the right way, and it is conservative by construction because random non-gold context already helps (+0.0215 File F1 — more context and prompt perturbation move the outcome by themselves). Against that control, retrieval-derived seeds add ~0.075 File F1, reach gold earlier, and do it with fewer post-seed tool calls and read tokens (RRF: 5.42 calls / 1,857 tokens against random's 8.49 / 3,682) — better context is cheaper to act on, not just better. Oracle gold context adds 0.3115 and rescues every no-seed miss, which is the size of the remaining headroom.

Caveats: 427 samples over 25 repositories with four repositories carrying 58.8% of positives — the repository-macro view reverses some leaderboard positions; six languages; gold sets are evidence-traceable but not exhaustive, so an unlabelled-but-useful file counts as a miss. The seed intervention is one trajectory per sample-arm pair with no exposed temperature or seed, and its paired deltas show seeded runs worsening 28.9–35.6% of samples — the authors call it a descriptive pilot and warn against ranking retrieval arms by it. The authors also decline to report any correlation with patch success, because no mapping from these workflow-derived rows to executable repair instances exists.
