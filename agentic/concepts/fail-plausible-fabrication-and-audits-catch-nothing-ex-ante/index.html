Tests and governance checks stayed green through most incidents; a human reading the output caught 70% of them

This is close to a first-party analog of what this map has so far only argued for in the abstract: what does an unattended fleet need when nobody is watching. One author's scheduled-job runtime — comparable in shape to the fleets this atlas's reader operates — ran 4,286 unit tests and 827 declarative governance checks and still needed a human reading its output to catch 70% of the silent failures that occurred. The paper's sharpest number is the audit-effectiveness split: a retrospective look at 15 incidents found the governance layer would have prevented 0% of them ex-ante, while catching 87% ex-post once a fix defined what to check for — "audits are regression engines, not prediction engines," because they encode the past and 80% of incidents involved a dimension the audit had never conceived of. That is a direct, quantified caution against treating a green governance dashboard as evidence an unattended run is healthy, which is exactly the posture reliability-and-capability-rankings-diverge and this map's durable-state practices assume without measuring.

The five-class taxonomy's Class D — fail-plausible fabrication, where the LLM doesn't fail to report an error but actively narrates a fluent, false account in its place (a Unicode bug narrated as "industry analysis of a Hugging Face platform crisis") — names a failure mode this vault has tracked only piecemeal, as an instance of gray failure's differential observability pushed one step further: the observer isn't just blind, it's being told a plausible story. For a scheduled fleet with no human in the loop by design, a class of failure that actively produces a convincing wrong report is a sharper threat model than a silent one, since it can pass a human's spot-check too, not just an automated gate's.

Incident latency (13 hours to 60 days) tracked component-seam locations — deployment topology, cross-script contracts, observer-observed coupling, where by construction no test runs — rather than code complexity, which is a candidate explanation for why this map's durable-state and observability patterns (event logs, work queues derived from disk state) may not by themselves close the gap: they make state recoverable, not necessarily legible to a test that was never written to look at the seam.

Bounds

Single author, single system, self-diagnosed postmortems with no independent adjudication, eight-week observation window, no comparison arm against an equivalent system lacking the described defenses. Openly a draft (v0.3), not peer-reviewed. Numbers (70%, 0%/87%) are computed over a small incident set (22 and 15 respectively) from one operator's own system — suggestive of a mechanism, not a measured population rate.
