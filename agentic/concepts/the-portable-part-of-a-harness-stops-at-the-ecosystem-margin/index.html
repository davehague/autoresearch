The playbook travels; the build command does not

Two levels, one artifact. Parse each evolved harness into units and tag every unit twice — the abstract concept it enforces ("localize from the test output", "minimal diff", "verify before submitting") and any concrete ecosystem marker it names (a build tool, a test-path glob, a header layout). Cross-language overlap at the concept level is 0.55; at the marker level it is 0.12. Harnesses evolved in isolation rediscover the same disciplines and express them through almost entirely disjoint machinery.

The size of the non-portable part is measured three independent ways and they agree. By content, 20–40% of each harness is ecosystem-specific. By distillation — strip all instantiation, aggregate every evolved memory rule into ten generic guidelines, deploy that memory-only harness unchanged — retention of native gain splits into two regimes: generic targets (JavaScript 1.13, Go 1.08) where the stripped harness is indistinguishable from native and per-language specialization buys nothing, and ecosystem-heavy targets (Java 0.68, C++ 0.65, TypeScript 0.48, Rust 0.45) where half to a third of the gain is simply gone. By transplantation — deploy language A's harness on language B — transfer is positive in 18 of 20 pairs and short of native in 14. Textual, distillation and transplantation all land on the same 20–40%.

The failure mechanism is worth memorizing, because it is a general trap. A JavaScript-evolved harness carries "run the failing test before submitting" and no compile-verification step — interpreted JavaScript has nothing to compile. On C++ and Java that omission is harmless: running the test entails building, so the generic rule silently supplies compile verification and the gap never opens. On TypeScript the entailment breaks — test runners routinely transpile without type-checking, so a patch runs its tests green while tsc rejects it and the grader type-checks. The harness ships patches that never build, and it fails silently because the rule it does have looks sufficient.

So the portability boundary is not interpreted-versus-compiled, or scripting-versus-systems, or any property you can read off a language. It is the point at which a discipline stops being a free consequence of the environment's own execution chain. Every reusable playbook has a set of guarantees it is silently outsourcing to the environment it was born in, and the transfer fails wherever the new environment does not happen to provide them.

That is the same shape as a-playbook-transfers-only-as-far-as-its-assumptions, which found a context artifact keeping its task heuristics and losing its stopping rule under a runtime shift — and it strengthens that result by naming what class of assumption breaks first and giving an a-priori test for it. It also sharpens discovered-harnesses-transfer-off-the-search-distribution: the transferable fraction is not a mystery constant, it is the complement of the ecosystem margin, and you can estimate it by asking which of your harness's rules name a tool.

The practical ordering. universal ≤ transplant < native on ecosystem-heavy targets — a foreign specialist beats a stripped generalist because at least it has concrete machinery, even the wrong language's. On generic targets the order reverses (JS transplant 0.20 vs distilled 1.13): foreign ecosystem baggage is dead weight or actively harmful. So the reuse decision is not "how similar are these targets" but "how much of the discipline does this target's toolchain give away for free". Native re-evolution stays necessary for complex ecosystems.

Bounds. Concept tags come from an LLM rubric with imperfect granularity that splits near-synonyms and deflates overlap, so the claim rests on the gap between the two levels rather than the absolute value at either. Structural analysis is restricted to the 14 cells where the loop produced a gain. Retention ρ is unstable where the native gain is small (Rust is flagged for exactly this; Python is undefined). One domain — repository-level code repair — and one recipe. Whether "ecosystem" generalizes past programming-language toolchains to, say, a company's internal deployment stack is untested and is the interesting open question.
