The record could not tell an architectural guarantee from an accident

Every source on this map so far has measured a bounded absence — no delivery platform emits a content-addressed identity of the behavioral tuple (no-delivery-platform-emits-the-identity-its-assurance-claim-needs), no harness produces a record an outsider can check (no-harness-produces-a-record-an-outsider-can-check), no observability platform represents the configuration as a first-class object (govern-the-agents-configuration-as-a-versioned-object). All of those ask whether the record exists. This asks something narrower and, for an operator, more immediate: when the record does not exist, what is a correct-looking system actually telling you?

The answer here is: nothing you can act on. A recovered build was probed against exactly the property its successor architecture was designed to guarantee — that the freely-editable persona cannot reach governed execution — and it passed, 5/5 on tool sequence, state-transition path and structural contract fields, with directed instructions 0/3 honored. A positive control on the general execution surface honored the same class of instruction, so the probe worked and the isolation was real. Then the author did the thing that turns a pass into a finding: wired the persona into the governed path explicitly, and execution changed 2/2 on both models tested. The isolation was not enforced by anything. It was the shape of the current wiring.

The author's own gloss is the claim: the pre-separation path was "decoupled from the persona by omission, not by construction — an unwritten implementation fact that a later wiring change could reverse," and the architecture's contribution is to make that isolation "a written, audited rule: the restrictive domain is faceless by rule, not by default." Note what he declines to claim, which is what makes it usable: "This is not a measured win … We report no paired contrast." A weaker paper would have printed the 5/5 as evidence that separation was unnecessary, or as evidence that it was.

Why this belongs on this map rather than in a governance folder. The map's question is whether anyone other than the runtime can establish what ran. This adds a rung underneath the four already there: whether the record can distinguish a property that is enforced from one that merely obtains. Both look identical in every artifact the system produces — the audit log, the approval chain, the structural contract fields are byte-identical in the passing and the injectable configurations. The only thing that separates them is a rule someone wrote down, and rules-as-artifacts is precisely the object govern-the-agents-configuration-as-a-versioned-object found represented nowhere. It is also the same gap the-approval-artifact-never-recorded-that-anyone-judged measures at the approval boundary — the record carries that a thing happened and never the judgement that made it required.

The second detail worth keeping. In the explicit-injection probe, tool sequence and approval count stayed constant while free-text fields changed: once connected, injected text affects how the artifact is phrased, not orchestration or governance. And in the separated implementation, an A/A probe with no persona change produced the same class of free-text divergence — so model nondeterminism and persona contamination are indistinguishable in unstructured fields, and the only fields where the isolation claim is checkable are the hard-asserted structural ones. Any trace-isolation claim over free-text output is unfalsifiable without an A/A arm.

Bounds, which are severe and stated. One development/pilot deployment, one domain, one team, operated by the author's own team, with audit data from a test rather than production deployment. No comparative evaluation and no paired contrast; the necessity argument is carried by an explicitly non-formal proposition rather than a measurement. R = 0 is a designed outcome, not a discovery — a non-zero value would be an implementation defect. The S1–S4 structural checks are code-level reviews rather than runtime tests, and the paper is careful not to conflate the two evidence types. Single-occurrence anomalies have weak statistical attribution. And the validation surfaced its own hole: there is no written rule anywhere in the case mapping a persona change to a re-validation obligation, which is why a re-validation rate is not an observable on either arm.
