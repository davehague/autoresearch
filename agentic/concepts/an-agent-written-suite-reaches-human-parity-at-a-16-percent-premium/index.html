The first time this map's agent-written gate is compared to the gate it replaces

This map's contest is how strictly CI should block agent-authored code, and its most uncomfortable finding is that when the agent writes the gate, the gate is correlated with the artifact it gates — cogenerated-tests-and-fixes-fail-together, half-of-an-agents-own-passing-checks-cannot-see-the-bug, agent-written-tests-miss-the-lines-they-add, lazy-generation-caps-agent-test-coverage. Every one of those compares an agent to itself or to another agent. None compares it to the human suite it is standing in for. This does, on 90 production bugs, against the tests a Google engineer actually shipped with the fix.

Parity, roughly. Judged blind and pairwise, the contract-grounded agent's suites are rated overall superior in 56.7% of cases against the developer-written originals — which is a statement about a distribution, not a victory, and the paper reads it correctly as "on par or marginally better." Against the baseline agent the margin is large and consistent: 77.8% overall, with edge-case coverage at 83.3%.

The named strengths and weaknesses matter more than the percentages, because they say what a team should still route to a human. Agent strengths: narrower high-precision assertions, minimized boilerplate through localized factory helpers, systematic verification of the negative error paths the contract dictates, and — a genuine surprise — more robust concurrency constructs than the human tests, which occasionally used non-deterministic waits. Agent weaknesses: humans still win on exhaustive validation of complex algorithmic scenarios (intricate state transitions, timezones) which the agent handles superficially, and humans strictly respect public-API encapsulation where the agent occasionally resorts to reflection-based hacks (invokePrivateMethod) to bypass it. That last one is the maintenance-surface concern this vault keeps raising in a new place: a suite that reaches through encapsulation passes today and pins implementation detail forever.

The cost line is the part that changes a build/buy decision. The contract phase costs +38.0% total tokens — input +36.2% because the specification is prepended to the synthesis context, output +59.1% because the agent must emit the document and writes bigger suites. But it finds +9 unique bugs (48 → 57), so tokens per unique bug detected rise only 1.16×. A 38% bill increase for an 18.8% yield increase is not obviously worth it on a spreadsheet; a 16% increase in unit cost of found defects generally is. Which of those two framings a team uses is the whole decision, and this is the rare source that prints both.

The escape taxonomy is directly usable as a checklist. Of the runs where the contract was correctly captured and the bug still escaped: inadequate input data (37) — overly simplistic happy-path inputs with no edge-case triggers such as nulls or specific timezones; omitted scenarios (36) — ignoring explicit statements in the agent's own specification; weak or missing assertions (20) — executing the buggy path but failing to verify the state mutation, or asserting too broadly; flawed test logic (12) — race conditions, over-mocking, missing trigger actions; invalid code (5). Three of those five are synthesis discipline failures rather than understanding failures, which means they are the kind of thing a second pass or a lint rule could catch — and it locates where the remaining headroom is for anyone trying to raise an agent-written gate above 63.2% detection.

One methodological note worth carrying past this source. The judging protocol is unusually careful for an LLM-as-judge result: a stronger model evaluating a weaker model's output to blunt self-preference, randomized order, anonymized origins, five independent invocations with a strict majority and explicit ties, and a reported self-agreement rate (≥90%) with a tie rate (≤5.6%) so the reader can see how much of the verdict is stable. That is close to the minimum bar this vault's evaluation-integrity work has been asking for, and almost no source that uses a judge clears it.

Bounds. Quality is judged by a model, not by engineers, and the human comparison inherits that entirely — 56.7% is a judge's opinion of parity, not a maintenance outcome. One model family, one monorepo with its own style guides, bug fixes limited to a single production file, and greenfield generation with the existing suite stripped (which is favourable to the agent, since the human suite was written incrementally against a real history and the agent gets a clean slate against a finished implementation). Historical-bug detection is a regression protocol and not a measurement of finding new defects. The human-in-the-loop curation step the framework supports was bypassed, so this is the fully autonomous floor.
