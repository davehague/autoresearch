The stopping decision is the one place the agent should not be believed

This vault's most durable finding about agent self-report is that the final claim is the least reliable artifact (the-agents-final-report-is-its-least-reliable-artifact), that lifecycle markers are claims rather than states (treat-agent-output-as-a-claim-not-lifecycle-state), and that 38 of 44 failed runs still close with an explicit success message. The loop-engineering consequence has been stated as a principle — gate the edit on evidence observed, not claimed (gate-the-edit-on-evidence-observed-not-claimed) — without a price on doing it at the stopping decision specifically.

The price is a stratified comparison, which is what makes it credible. The same system, same model, same run: where a validated reproduction script exists the gain is +10.3 pp; where it does not, the identical plan-and-memory machinery is worth +3.8 pp. The loop discipline pays either way, and hardening the completion predicate against a rerun roughly triples it.

The implementation is worth stating exactly, because the value is in the asymmetry rather than in the reruns. The script is rerun after every file-mutating edit, and then: in the verification step a zero return code counts only if the latest verdict is not fail, and the terminal verification sub-task cannot complete while the issue still reproduces. The agent is not being asked to consider the evidence. It is being denied the ability to declare victory over it. Where no valid script could be extracted the system falls back to the ungated predicate rather than blocking, which is what makes this a deployable gate rather than a coverage requirement.

The verdict's error profile is the part to internalize before shipping this. The script passes on 18 of 20 resolved trajectories — as a positive signal it is trustworthy — but fails on only 5 of 18 unresolved ones. A reproduction script that stops reproducing is decent evidence the bug is fixed; a reproduction script that passes is weak evidence the task is done, because the run can be wrong in ways the script was never written to see. This is the same shape as fail-to-pass-does-not-constrain-the-fix and half-of-an-agents-own-passing-checks-cannot-see-the-bug on the CI side: the artifact demonstrates the defect is gone and says nothing about what else changed. Use it to block, not to certify.

The system-level effect is visible in the give-up statistics: empty-patch exits fall 8.3% → 2.7% overall. An agent that cannot close on a self-report either keeps working or backtracks, and the revert-then-refix recovery count rises 1.46× accordingly (plan-and-memory-are-superadditive).

Caveats: the armed and unarmed strata are not randomized — a script is extractable only for mechanically reproducible issues (crashes, traces, wrong outputs), so the armed stratum is selected, and it starts from a lower baseline (24.3% against 29.8%), which is consistent with those issues being harder but leaves headroom as a competing explanation for the larger gain. Scripts were extracted by the same Qwen model that runs the agent, from issue text alone, and validated only for reproducing the pre-edit failure. First-seed paired run for the stratification (the three-run protocol covers the headline and the factorial, not this split). All patches are graded by the official harness, so verdict errors cannot inflate the resolved count.
