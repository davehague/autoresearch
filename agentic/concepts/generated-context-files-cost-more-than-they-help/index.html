Generated context files cost more than they help

The first controlled test of the field's most-recommended artifact. Four agents (Claude Code + Sonnet-4.5, Codex + GPT-5.2 and GPT-5.1-mini, Qwen Code + Qwen3-30b-coder) × three settings (no context file / LLM-generated / developer-written) × two suites (SWE-bench Lite; AGENTbench — 138 tasks from 12 niche repos with real developer-committed context files). LLM-generated context files reduce success (−0.5% Lite, −2% AGENTbench) while raising inference cost 20–23%. Developer-written files improve success +4% on average, still at up to +19% cost. Generated files only helped (+2.7%) when the repo's documentation was artificially deleted — they are mostly a lossy copy of the README.

Mechanism: agents follow the instructions and explore/test more (the cost), but repository overviews don't shorten the path to relevant code — the agent finds it about as fast by itself. What earns its tokens is the content an agent cannot infer: non-standard build/test commands, repo-specific conventions. This pushes back on the blanket "run init, commit the file" advice every vendor ships, while sharpening rather than refuting agents-md-is-a-map-not-a-manual — OpenAI's working pattern is a hand-maintained table of contents over CI-linted docs, which lives on the developer-written side of this split.

For context-engineering's live tension this is a fourth data point with the same shape: task-anchored external context helps (track-the-spec-in-external-state, goal-hinted-pruning-beats-generic-compression, developer-written files here); task-blind generated context hurts (memory-scaffolds-can-degrade-long-horizon-agents, generated overviews here). The discriminating variable keeps landing on: does the artifact encode what the task needs that the agent can't already see?

Caveats: Python-only; success-rate-only (instruction-following may pay off on unmeasured axes like convention adherence); small deltas relative to run variance, though direction was consistent across agents.
