A specialist search loop is cheaper on both axes — and the two axes disagree about who is second

The map's 2026-07-22 controlled test made the harness's own search ability a named term in every context result: packaged progressive disclosure adds nothing where the agent already navigates raw source well, and becomes decisive only once the corpus outgrows native search (progressive-disclosure-buys-context-not-intelligence). This is a vendor building a product on exactly that term, and its own framing concedes the boundary: the pitch is turns and context window, not finding what a grep loop cannot.

So read it as an efficiency result, which is what it measures. The mechanism claim — "a general coding agent carries a large context window and a broad instruction set into every search" — is restrict-the-tool-surface-to-cut-cost-not-capability applied to a subagent instead of a tool list, and it rhymes with the T1 finding that a mature harness's accumulated instructions are compensation the model no longer needs (strip-the-prompt-when-the-model-improves). It is the second organization to report a purpose-built index beating an agent's native search on cost (structural-index-beats-grep-at-lower-cost).

The finding worth carrying forward is the ordering inversion the post does not comment on. The two losing strategies lose on different axes: local search is the slowest (2.19×) yet the cheaper of the two (1.32×), while the MCP-tools agent is nearly as fast as the specialist (1.14×) and the most expensive (1.63×). A delegated tool call spends tokens to save turns; a local grep loop spends turns to save tokens. Latency and token cost are therefore not interchangeable proxies for "retrieval efficiency", and a harness tuned on one will pick a different winner than a harness tuned on the other. This is a concrete instance of charge-every-search-method-the-same-budget with the budget having two denominations.

The load-bearing weakness is that quality is asserted. A retrieval strategy that returns less is trivially faster and cheaper, so "comparable result quality" is the entire claim and it carries no number. The vault's own complaint about agent benchmarks has been that 0 of 8 disclose cost (agent-benchmarks-underdisclose-their-harness); this is the same failure with the columns swapped — time and cost to two decimals, quality omitted (retrieval-benchmarks-omit-the-quality-axis).

Caveats: T2 vendor post announcing its own paid product, in beta. No task set, repository names or sizes, agent, model, run count, or intervals disclosed. All figures are self-relative, so nothing ports. Single-study; the efficiency ordering is the transferable part, the magnitudes are not.
