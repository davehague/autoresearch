The gate that stops everything is only as good as its false-positive rate, and nobody knew theirs

This map holds that agent commits should pass the same CI gate as human commits (gate-agent-commits-on-the-same-ci-as-humans) and that blocking gates should be relaxed as agent throughput rises (relax-blocking-gates-when-throughput-is-agentic). Both prescriptions assume the gate's verdicts mean something. This is the first source here from an organization that made a gate universal and then had to answer the second-order question, and their answer is a measurement program rather than a tuning program.

The failure mode they name is the one this vault has been circling. A check that fires often without indicating a real problem is worse than no check, because it trains its owner to ignore it — the same claim a-falling-false-alarm-rate-reads-as-a-better-reviewer makes about review agents, and review-agent-precision-is-a-tunable-not-a-given makes about precision dials. What this source adds is the third consequence, the one usually left out of the alert-fatigue argument: noise reduces velocity structurally. Every false positive pauses or rolls back a deployment, lengthening the queue behind it and pushing more partially-deployed states into the fleet. And it reduces on-call carrying capacity, because investigating false alarms is on-call work that produces no learning — which the authors observe is the kind that drives engineers to file paperwork to delete the check.

The trap, stated once and worth repeating verbatim in any gate design review: tuning for noise naively trades one failure mode for another, because a check loose enough never to fire is not catching anything either. Precision and recall are both quality dimensions and they trade off. What is needed is a way to measure and steer the trade-off rather than react to whichever side is complaining loudest.

Two mechanisms are directly portable to an agent fleet.

First, label the verdicts from outcomes you already have. The daily pipeline joins three streams — the verdicts the gate issued, the deployment outcomes that followed, and a corpus of explicit and implicit ground truth including whether a rollback was followed by a re-attempt of the same change. That last one is the trick: it is a free, already-logged proxy for "the gate was wrong", requiring no annotation. Any loop that gates agent output and records what happened next has the same signal available and is almost certainly not computing it. It is verifier-catch-and-false-alarm-rates-are-measurable applied at fleet scale with a labelling scheme that does not need a human in it.

Second, make the trade-off visible at edit time. Knowing a check is bad is not enough; the owner has to be able to fix it without breaking what it protects. Replaying a candidate definition against 30 days of retained history covering both quiet days and known incidents shows the owner how the new definition would have behaved before it ships. The authors' framing — edit time is the only point at which the owner is in a position to act on the trade-off — is a design principle, and their note on why it worked is the sharper half: it presented the choice concretely ("this many past incidents caught, this many past false alarms produced") rather than as a pair of abstract metrics. That is the same shape as gate-a-skill-update-on-a-replay-of-what-it-might-break, reached independently in a non-agent setting.

Bounds. This is an industrial experience report, not a controlled study. The 12.1% → 2.7% is a one-year before/after with no control fleet, attributed to a program with at least six named components (per-check catalog, backtesting, better defaults, topology-aware metric publication, severity-aware verdicts, sociotechnical work), none separately attributed. The independent 500-failure audit is a genuine strength but validates the measurement of the false-positive rate, not the causal claim about what reduced it. No fleet-wide recall figure is reported — which is precisely the number that would say whether the precision gain cost anything, and its absence is conspicuous in a paper whose central argument is that both dimensions must be steered together. Ground-truth labels are partly implicit proxies that the report does not validate. The incident-prevention claim is qualitative throughout, with no count and no denominator. And nothing here involves agents: SHC gates human- and pipeline-authored change, and applying it to agent-authored change is this vault's extrapolation, not the paper's.
