The response is not the unit of decision

Gate design in this vault has quietly assumed the response is atomic: a tool call is allowed or denied, a diff is approved or rejected, a classifier scores the action. Modern agent replies are not atomic. One structured response can carry an operator notice, an independent sensor or status report, an effect-bearing action, and a message whose meaning depends on that action having been dispatched. Those four components do not share a validity state, and treating them as if they do fails in whichever direction you pick — 0 of 248 supported components survive an all-or-nothing policy, while independent per-component filtering leaves dependents alive without the prerequisite they were written against.

The middle path needs one thing the agent must supply: declared prerequisite references between typed components. The protocol refuses to infer types or dependencies from free text, and that refusal is the load-bearing design choice. It makes admission a graph closure — keep every component that is still supported and whose declared prerequisites are still supported — rather than an inference problem, which is why the conformance evidence can be exhaustive over small graphs at all.

That makes this a harness contract before it is a policy. The response schema has to carry component identity, type, payload and prerequisite edges; a harness that accepts free-form text with tool calls sprinkled through it cannot do partial admission at any price, no matter how good its policy engine. It belongs with design-the-tool-interface-instead-of-showing-examples and compile-the-procedure-into-the-harness: the safety property is bought by the interface, not by the checker.

Cost is not the obstacle. Admission over graphs of up to 32 components runs at a median 0.333 ms (p95 0.453 ms), and the ablation attributes distinct, non-overlapping failures to each removed mechanism — retention, dependency closure, and the post-admission recheck (recheck-the-action-at-the-dispatch-boundary) each cover a failure the others do not. That is a real decomposition rather than an ensemble that improves in aggregate.

Bounded the same way its sibling is. The demonstration is UAV operation, and no software-engineering task is evaluated. The near-perfect denominators are protocol-conformance and replay results — the question asked is "does the implementation match the specified protocol", not "how often does this help a real agent" — and the paper is explicit about that. Whether a coding agent's response even decomposes this way is untested: the natural components of a coding turn (an explanation, a patch, a shell command, a claim about what the patch does) have dependency structure that is real but far less crisply declarable than a flight action and its status message. Authors' own system, own reduced variants, hand-specified domain predicates, no preregistration.
