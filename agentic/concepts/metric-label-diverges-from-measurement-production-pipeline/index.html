Three ways a number can be "numerically correct" and still measure something other than its label

This map's evidence-source diversity and judge-reliability threads have mostly asked whether a proxy metric ranks the right thing. This source asks a logically prior question about one production system: does the metric's label describe what its computation actually does. All three findings pass a narrow correctness bar (the arithmetic is right) while failing a broader validity bar (the number answers a different question than the one its name implies). The routing-pass-rate case is a denominator problem masquerading as a clean pass rate: cases explicitly exempted from gating are still counted toward the 80.6% headline, so "zero gating failures" and "27 of 139 failed" are both true statements about the same report, describing different populations. The duration case is a units problem: a sentinel value used to represent "the client gave up and we clamped the recorded duration to the integer maximum" gets pooled with genuine completion times before a percentile is computed, and the authors are explicit that the result is "a stratum contrast, not a treatment effect" — this is the same failure mode this map has seen from missing-value imputation elsewhere, but arriving via an integer overflow sentinel rather than a null.

The compaction-reduction case is the sharpest of the three because it is a scoping choice rather than a data artifact: "94.39% token reduction" is arithmetically exact for the follow-up call alone, and arithmetically exact that the combined-call reduction is 46.54% — the discrepancy is entirely about which unit of work the metric is scoped to, with no wrong number anywhere in the chain. A team reporting the first figure is not lying; it is answering "how much smaller is the second call" rather than "how much cheaper did compaction make this interaction," and the two questions have different practical stakes for anyone pricing the feature.

Confirms rather than promotes: this is one production pipeline (Praxa AI), not independently reproduced end to end, and the compaction pilot is a single trajectory with no variance estimate. But the methodology — independent re-derivation, an LLM-adjudicated disagreement pass, finite-completion bounds for missing data rather than imputation — is unusually rigorous for a single-system audit, which is why it earns T2 (a primary engineering post from the team operating the system) rather than resting on T3 practitioner-writeup grounds.

Bounds: single production system; historical provider runs not independently reproduced; direct Langfuse traces and Cloudflare APIs unavailable during the audit; database extracts are non-atomic and mutable, so this describes a snapshot rather than a controlled experiment; no claim of state-of-the-art performance or algorithmic advance is made.

Interaction edges: observability — the sentinel-value latency contamination is a logging/ instrumentation pitfall (an abandoned-call timeout encoded as a data value rather than a distinct status) that this map's telemetry-quality thread should carry. model-routing-token-economics — the compaction-reduction scoping question (which call boundary a cost metric is measured across) is directly relevant to how this map's token/cost deltas should be scoped and reported.
