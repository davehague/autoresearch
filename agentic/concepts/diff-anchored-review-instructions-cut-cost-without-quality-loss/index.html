The regression wasn't the tools — it was letting a review agent behave like a general coding agent

This map's verifier-efficacy strand has mostly asked whether a review agent catches the right things (precision, recall, judged relevance). This source is a diagnosis-and-fix story about how the agent gets there: GitHub's own trajectory instrumentation caught a review-quality regression that final scores alone didn't show — a review agent equipped with better/more general tools was "browsing a repository instead of investigating a pull request," accumulating speculative context the way a general coding agent would rather than staying anchored to the bounded diff a reviewer is actually being asked to judge.

The fix was purely instructional, not architectural: force every investigation step to start from the diff, narrow with grep/glob before reading, confirm exact evidence with view, and on a failed search retry with a simpler query rather than guessing at neighboring file paths. Behavior changed from exploratory to diff-anchored, and cost dropped ~20% with the team reporting no quality signal that would block shipping.

This is a companion result to the Sourcegraph adoption playbook already on this map (retrieval-is-the-lever-a-vendor-playbook-oversells-against-this-maps-own-controlled-result), which argues more retrieval/context is the fix for cross-cutting misses. This source is the other side of the same coin: *unbounded context-gathering is itself a cost and behavior failure mode independent of whether the retrieved context is later useful — the fix here was not adding retrieval, it was constraining where the agent was allowed to look for it. A reviewer needs to gather more context than a diff alone provides (the Sourcegraph claim) while also not gathering it by browsing indiscriminately (this claim) — the two are compatible, and the discipline is in the search strategy, not the search scope.

Bounds

Single vendor's internal benchmark and internal cost accounting, no released dataset, no independent replication, no ablation isolating which specific instruction clause did the work. This is a report of one before/after instruction rewrite, not a controlled study of tool-richness-versus-behavior in general — carried at suggestive rather than strong for that reason, T2 vendor engineering practice.
