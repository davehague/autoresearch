Compaction, notes, and sub-agents extend the horizon

Three patterns keep an agent working past one context window. Compaction: when the history nears the limit, summarize and reinitialize — Claude Code preserves architectural decisions, unresolved bugs, and implementation details while discarding redundant tool output, then continues with the summary plus the ~5 most recently touched files (the "lightest touch" variant is tool-result clearing). Structured note-taking: the agent writes state to external memory and re-reads it after a reset (the Pokémon agent tracks tallies across thousands of steps); Anthropic shipped a file-based memory tool for this. Sub-agent architectures: each sub-agent explores with a clean window and returns only a distilled 1,000–2,000-token summary to a lead agent that synthesizes — reported as a substantial improvement over single-agent systems on complex research.

Selection guidance from the source: compaction for extensive back-and-forth; note-taking for iterative work with clear milestones; multi-agent for parallel exploration. These are the operational answer to context-is-a-finite-decaying-resource, and they connect directly to unattended operation, where the durable unit is exactly this externalized state (durable-session-logs-enable-crash-recovery).

Rebutted by (added 2026-07-29, connect). This note is the map's oldest consensus on context management and it acknowledged none of the pushback that has since accumulated against each of its three patterns. Compaction: compaction-selection-is-all-or-nothing finds it does not degrade gracefully — whole blocks are selected, planted operational facts drop entirely at the first boundary, and a fact that re-enters survives about one further pass; compaction-can-launder-killed-process-output finds it has no epistemics, promoting a killed process's partial output into a durable "confirmed result." Note-taking: memory-scaffolds-can-degrade-long-horizon-agents degraded performance across all 10 models tested, and memory-delivery-not-storage explains why a store the agent must choose to read is not a memory system at all — voluntary retrieval rounds to zero even when pre-seeded. The surviving form is narrower than "note-taking": deterministic harness-side delivery at a cued moment, of contract-like state rather than session history (persist-the-contract-not-the-conversation). Sub-agents: chainswe-summarization-compounds-maintenance-errors finds delegation degrading more than retaining full history in multi-bug maintenance.

So the source's selection guidance survives as a taxonomy while all three of its recommendations have been narrowed or contradicted by later T1 work. The reconciliation the vault keeps circling and has not tested: structured external state about the task's contract helps; lossy recall of the agent's own history hurts. Treat this note as the origin of the patterns, not as current advice.
