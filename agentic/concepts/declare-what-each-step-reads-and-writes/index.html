The reason prose does not govern is not that it is vague — it is that it has no variable scoping

This map's standing position is that the specification is a contract held outside the agent and re-presented at each decision it governs. Everything it has accumulated is about delivery: hold it externally (track-the-spec-in-external-state), restate it at the completion decision (re-delivery-governs-procedure-not-permission), don't let it emerge in pieces (emergent-specs-corrupt-the-artifact). This source supplies the missing account of why re-delivery is needed at all, and it is more specific — and more fixable — than "long context degrades".

A prose workflow is a program in which every intermediate is a global. Each step inherits every result produced before it, and the dependency is invisible at the operation boundary, so the executor must infer which prior result the step meant from a context that also holds the ones it did not mean. The motivating case is exact: a referral decision that should key on recent acute utilization, in a context that also contains the doctor's chronic-care request and chronic-condition evidence, resolved by attending to the wrong one. That is not ambiguity in the instruction. The instruction is unambiguous; the scope is not.

The negative controls are what make this a finding rather than a tool paper. Two obvious alternatives were tried and neither closes the gap. Rewriting the prose into a clearer skill document (SkillCreator) moves one executor 16 points and another zero — which is the signature of a fix aimed at the wrong layer, and it converges with the-specs-format-is-not-what-pays, the preregistered null on notation. And decomposing the prose into subagent calls without declaring the artifact boundary does not help either: the paper's Figure 2 shows the step-by-step version still handing one subagent the referral info, the utilization, the medical records and the route conditions together. Splitting text into smaller contexts moves the selection problem; it does not remove it. What removes it is naming, per step, what it reads and what it writes.

Where this lands relative to compile-the-procedure-into-the-harness. That note's split is determinacy — a step moves into program structure when its output is a function of its inputs, and the model is never asked whether to run it. This one is orthogonal and composes with it: the local action of a compiled step here is still a natural-language instruction executed by an agent, and only the data dependencies and control transfers become explicit. So the two describe different things you can take away from the model — whether the step fires versus what the step may see — and this source shows the second is worth 23 points on its own, with domain judgement left inside the step.

The validator is the transferable engineering. Compilation is LLM-driven, so faithfulness cannot be asserted from syntax, and the ablation prices that honestly at 16 points. Three mechanisms are worth stealing wholesale. A join type check catches an obligation prose reliably hides — "if the risk score is high, retrieve the medical record" followed by "cross-check the utilization" leaves the record unavailable on the low-risk path — and forces the mismatch into the open. Inductive decomposition turns one unverifiable global claim into local obligations along the program structure. And dry-run simulation enumerates scenarios by predicate coverage, then runs the source and the compiled version independently with neither given the oracle label, and treats disagreement between the two traces as the signal. That last one is the same move as an-evidence-reversed-mirror-separates-the-rule-from-the-resemblance applied to a translation: you cannot check the output against a truth you do not have, so you check two derivations against each other. The case study localizes a real defect this way — a compiled branch that checked whether a referral message exists where the source required a qualifying source.

Related: a-specification-buys-executability-not-agreement — that result found a complete specification buys code that loads and not agreement, because the pinned decisions were already shared defaults; this is the complementary case where the specification is procedural and what it buys is the executor doing the steps in the intended order on the intended inputs. an-explicit-artifact-boundary-narrows-the-cross-model-spread carries the reliability half of the same source. split-the-executable-spec-into-path-and-behavior for the prior decomposition of an executable spec on this map. serial-workflows-collapse-in-production for the failure mode this is aimed at.

Bounds. Eleven domains from two benchmark families, at most 50 instances each, all under a single harness — the harness term is held fixed, not measured, so nothing here says how much of the 23 points survives a different runner. No significance testing on the resolve-rate comparisons. The reliability results live on the Medical domain only (see the sibling note). The compiler leaves an LLM inside each step, and the authors show plainly where that bites: on domains whose difficulty is judgement rather than enforcement — distinguishing a typo from fabricated business information — every representation sits at 50–64% and compilation buys nothing. The claim is scoped to enforcement, and the paper reports the domains where enforcement is not the bottleneck rather than dropping them.
