HumanEval/89: the report was true, and it un-fixed the bug in five seeds out of five

The code applies a Caesar shift of 12. A revision correctly changes it to 4. The orchestrator then hands the model a failure trace generated from the previous program — a report containing valid inputs and valid expected outputs, every fact in it accurate. The model reverts the shift to 12. Five seeds, five reversions. Nothing in the payload was wrong; what was wrong was the envelope's silent claim that these facts describe the code in front of you.

That is the whole mechanism, and it is why this study insists on writing evidence as (h_source, h_suite, payload) and calling it state-aligned only when h_source equals the hash of the current state. A mismatch may trigger a refresh, a no-op, or an escalation. It may never directly trigger a patch.

Why the discovery curve hides it. Pass@k and best-of-k report ever-correct, which rises monotonically here — 0.820 to 0.853 — over exactly the interval where current correctness falls fifteen points. The transition algebra makes the stopping rule explicit: with α = P(wrong→right) and β = P(right→wrong) under evidence e, the expected change in correctness is (1−q)α − qβ, so continuation has negative expected value once q > α/(α+β). The licence for another round is a property of your current state, not of your remaining budget. Loop depth only changes the number of transition opportunities; the kernel decides their sign — which is why the shape is evidence-specific rather than a generic depth penalty (current-binary runs 0.700/0.700/0.720, stale-trace 0.687/0.713/0.660, no-evidence 0.687/0.687/0.707).

This extends the within-agent limb rather than contesting it. stop-on-the-sign-of-the-marginal-gain and repair-loops-have-an-interior-optimum established that an unvalidated loop is negative value and that stopping on marginal gain beats stopping on votes. That was about the verifier. This is a second, separable failure a good verifier does not fix: the loop can destroy work it already has, and the harm is clustered rather than diffuse — all 7B correct-state harm sits in 4 of 27 tasks, spreading to 12 of 27 at 14B — which is why the paper computes task-level and not branch-level uncertainty.

It is also the same variable context-engineering separated on 2026-07-28. There, storing a file read and its observation together in an append-only trajectory made a mutable thing immutable, and re-deriving from the source each cycle won on every axis (re-derive-file-state-instead-of-storing-snapshots); the counterweight was that pinning a resolved reference amplifies wrong actions 3.0× (persisted-state-without-revalidation-amplifies-errors). This is the same operation applied to a verdict rather than a file: a stale verdict is a pinned resolution, and the fix is the same hash check. It also names the same failure the vault has recorded in compaction, where a killed process's partial stdout became "confirmed results" (compaction-can-launder-killed-process-output) — the pathology in all three is an observation that outlives the state it was true about.

Read the intervention arms honestly. Every mechanically enforceable guard here — state binding, typed Keep | Patch | Escalate actions, a last-known-good checkpoint that invalid actions can never overwrite, fresh recertification of the completion state — is a safety mechanism that trades against liveness. Replay shows binding intercepting every stale-condition harm. Prospectively, the same bundle costs seven repairs from wrong starts and fails its pre-registered non-inferiority criterion; the repository factorial removes every unsafe completion and the only sound one. The authors are explicit that the reference implementation is an executable specification and conformance artifact, not evidence of improved repair competence. Carry the obligations; do not carry a net win that was not demonstrated.

One free win needs no trade-off at all. All five 7B current-trace harms on HumanEval/137 were responses containing only STATUS: DONE and no code. A fail-closed parser that maps an unparseable action to Keep rather than treating it as an invalid patch retains the correct checkpoint in every recorded branch — a harness edit, not a model edit (structure-outweighs-the-verification-step).

Caveats: public HumanEval tasks plausibly in training data; 27 tasks selected for observed 7B repairability, so absolute rates do not generalize; all six 7B contrasts and five of six 14B contrasts are non-significant after Holm correction, and the +17.0-point cross-coder interaction is suggestive only (p = 0.3615), so no capacity claim is supported. Forced revision is deliberately not an adaptive policy. Repository arms are floor-limited at 0–2.1% baseline sound completion across four stacks.
