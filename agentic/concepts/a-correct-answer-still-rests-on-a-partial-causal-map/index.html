The number went up and the causal map did not — measured against an annotated propagation path rather than against a label

Limb (1) of this map — audit the claim against the evidence the run actually gathered — has been holding steady while limb (2) took two independent hits. This arrival lands squarely on limb (1) and is the strongest confirmation it has received, because it does something none of the previous sources could: it grades the agent against manually annotated causal structure rather than against a final label or an annotator's opinion of which step mattered.

The construction is the contribution. For each incident the authors annotate the service-level fault-propagation path — the route by which the fault reaches the observed symptom — defining a fault-impact surface of services and directed edges. Agent runs are normalized into messages, telemetry queries and returned results, then scored on two granularities against that surface: Node F1 (did it find the anomalous services) and Edge F1 (did it recover how the fault propagated between them). The distinction is not cosmetic: identifying anomalous nodes requires only detecting aberrant telemetry, while recovering directed edges requires inferring propagation, and the authors call the second the harder and more discriminative capability.

Three separations follow, and each is a different way for a final score to lie.

The ceiling separation. Edge F1 never exceeds 0.67 in any row, including the row that reaches 90.0% Acc@1. Even the correctly localized runs rest on partial causal maps. An SRE reading "the root cause is service X" from a system with Edge F1 0.6 is reading a conclusion whose supporting route is roughly half-reconstructed, and the final answer carries no signal about which half.

The intervention separation. Swapping the backbone model lifts Acc@1 by 10.8 points and moves correct-run Node F1 by 0.01 and Edge F1 by −0.01. The thing that got better is the answer selection; the thing that did not is the causal understanding underneath it. This is the sharpest instance this map has of a headline metric and a process metric responding to the same intervention in different directions — and it is exactly the shape localize-first-wrong-step-not-final-answer predicted and measure-whether-evidence-reconstructs-the-claim formalized as a reconstructability check.

The failure separation. From correct to incorrect runs, node identification falls 16–32% and edge reconstruction falls 43–67%. So a failing run is usually not a run that saw nothing — it detected most of the anomalous services and then failed to chain them. That is a diagnostic a final-answer metric cannot express and an operator can act on.

The behavioural half explains the mechanism and it is the vault's own thesis. Correct runs reprobe — requery on-path services at the same depth — while incorrect runs stray, wander and retrace, oscillating on and off the fault-impact surface. But the two backbones navigate in similar proportions; where they diverge is evidence grounding: the stronger model acts on the prior result on 54.3% of rounds against 24.9%. Incorrect runs more often ignore what came back or hit empty queries. So the discriminating variable is not how much the agent searched but whether each round was conditioned on the last one's return — which is gate-the-edit-on-evidence-observed-not-claimed measured as a rate rather than prescribed as a rule.

And the taxonomy converts into a control. Wrong diagnoses reduce to three evidence-handling families — decisive evidence never gathered, gathered but misread, or overridden by ungrounded reasoning — and each is mapped to a specific check frozen before the validation runs. Wrapping the diagnostic core in a Grounder (survey available observations before localizing) and a Verifier (audit the diagnosis against them) raises Acc@1 43.5% → 52.5% on a held-out backbone model, dataset and service topology, with gains on all nine fault types. The ablation is near-additive — Grounder alone +4.5, Verifier alone +4.1, both +9.0 — and pointedly does not track budget: the costliest arm gains least. One of the Verifier's frozen checks is worth carrying verbatim into any monitoring agent: establish a baseline before relying on any signal; if the error or latency already exists in the normal window, it is chronic background and cannot be the root-cause anchor.

Bounds. The characterization rests on a single topology (RCABench's TrainTicket), a fixed sample and the chosen agents; DiagGuard's transfer to a held-out model, dataset and topology partly mitigates this but is one transfer. Each characterization configuration is run once with no significance testing — the authors label those differences indicative and reserve mean±sd over five runs for the validation only, so every number in the Node/Edge F1 table inherits that caveat. Process labels rest on manual annotation plus LLM-assisted classification plus human review; fixed protocols, double coding and released artifacts reduce but do not eliminate annotation subjectivity and judge bias, which is the standing caution about grading a trajectory with a model. The behavioural analysis excludes two of the six frameworks entirely (no comparable traces). And the domain supplies something a coding agent's domain does not: a service-dependency graph that someone already maintains, which is what makes a propagation path annotatable. Whether an equivalent fault-impact surface can be defined for repository-level repair is the open question this arrival hands the map.
