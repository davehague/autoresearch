The extra lines are not free, and now there are two independent methods saying so

Two days apart, from unrelated groups using unrelated methods, this map gained both halves of a single claim. codeslop-is-the-search-surviving-into-the-patch found that 17.9–32.9% of an agent patch is the exploration that produced the fix, still present in the diff, strippable by counterfactual search over the repair trajectory at 99.1% oracle preservation — with eighteen SWE-bench patches minimizing into the human patch. That is a claim about what the surplus is. This is a claim about what the surplus costs: on functionally correct patches, churn correlates with maintainability degradation at ρ 0.30–0.48 and with added static-analysis findings at 0.31, all surviving Holm correction.

Put together, the instruction stops being aesthetic. The map's comprehension-debt thread — code accepted before anyone can explain or maintain it, 82% practitioner agreement, both proposed exits rated the lowest-scoring practices in their own study — has needed a lever that automates, and TRIM supplied one. This says the lever pays in a second currency: the diff you strip is not just harder to read, it is measurably more likely to be degrading structure. A smaller patch is a better patch, and the claim now rests on artifact composition and on outcome measurement rather than on either alone.

The honest complication is that patch size is not a generation trend. On the matched set the later Claude model wrote smaller patches than its predecessor (median 3 lines vs 6, fewer files, fewer hunks) while the later DeepSeek model wrote larger ones (6.5 vs 4, more hunks). So churn is a per-model — and, per the vault's harness-model pair thesis, presumably per-stack — behaviour, not something that improves on its own with model generation. Nobody is going to grow out of this. It has to be measured and gated, which is the argument for putting a diff-size or diff-coverage signal in the review path rather than hoping.

Two boundaries on the causal reading, both of which the source states. The association is correlational and cannot be separated from model behaviour — a model that writes larger patches may differ in other ways that drive the degradation. And CodeQL "added findings" are confounded by code movement: relocate a block and the same rule is recorded as removed at the old site and added at the new one, which mechanically correlates with churn. The CodeScene half is the sturdier of the two, since Code Health delta is a structural measure of the modified files rather than a location-sensitive rule count.

For anyone pointing a reviewer at agent code, this composes with the map's other 2026-07-22 finding — that error-handling paths are the worst-covered construct in agentic PRs (try/catch bodies missing 81–86%) — into a concrete triage order: size of the diff, then the paths the suite never executed. Neither requires reading the whole change first.

Caveats: SWE-bench Lite, Python-only bug repair, four models across two families with pairs differing in tier as well as release date; a $0.50 per-instance cost cap; improvements are harder to record than regressions by construction under the CodeScene worst-file rule, which the authors flag; and the correlation is measured only on patches that already passed the tests.
