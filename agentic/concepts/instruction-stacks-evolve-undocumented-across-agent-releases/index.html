What a coding agent actually sends the model on its first turn is mostly tool definitions, not the system prompt — and more than half of what changes there release-over-release has no recorded reason

Most of this map's (and this vault's) standing-instruction and precedence findings treat "the system prompt" as a stand-in for everything the harness injects ahead of a user's request. This source instruments the real wire request across five production coding agents and finds that framing is incomplete: for three of the five agents studied, tool definitions — not the system prompt — occupy the largest share of the first request's token budget. A rule, a prohibition, or a style guideline that lives in a skill description or a CLAUDE.md file is competing for the model's attention against a tool-definition block that is, in most of these harnesses, larger than the instructions themselves.

The undocumented-drift finding is the sharper one for anyone auditing a fleet of agents over time: tracing changes across the four open-source agents back to commit history and release notes, only 48% of examined revisions to the instruction stack carry a verifiable, documented motivation. The majority of what ships into every subsequent model call arrived without a recorded reason a later engineer — or an auditing script — could check against. Revisions aren't smooth drift; they cluster into occasional concentrated bursts that touch tool-use instructions, attribution language, and coding style together. And despite each agent's wording becoming more distinct release over release, the capabilities the wording encodes substantially converge across agents — convergent function, divergent phrasing.

Interaction — unattended-operation and the standing-instruction thread: this map and the agentic atlas's own backlog carry a running question about whether CLAUDE.md-style rule files are stale scaffolding nobody revisits (2026-08-14 census: 67.3% never modified after creation) and about where in the precedence order a rule actually needs to live to be obeyed (system prompt and project file tie for top precedence; skill and tool descriptions lose, per the 2026-08-13 arrival). This source adds a third, previously uncounted layer competing for the same attention budget: a tool-definition block that in most of these harnesses is both larger than the instructions and less scrutinized than either, since it usually isn't something a human author reviews line-by-line the way a CLAUDE.md is.

Interaction — context-engineering: "what gets delivered" (sub-thread 1) now has to account for tool definitions as a standing, usually-largest occupant of the delivered budget, independent of anything compaction or truncation does to tool results later in a session.

Bounds: change-motivation tracing depends on the completeness of each open-source project's public commit history, so the 48% figure is a floor on documented motivation, not a ceiling on undocumented arbitrariness; the study characterizes composition and change cadence, not downstream task-success impact of any specific revision; four of five agents are open-source, so the method cannot be applied identically to the fifth (Claude Code's private source).
