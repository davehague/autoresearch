The hardest instances are hard for the wrong reason

This map's catalogue is mostly about proxies that misgrade the agent, and mostly optimistically — the merge label, pass@1, the judge, resolved rate, and above all retrieval (benchmark-scores-inflate-when-agents-can-retrieve-the-fix). This defect sits a layer upstream of all of them, in the construction of the instance, and it runs the other way: an agent that correctly solves the problem it was given fails an instance whose oracle tests three problems it was never told about. The vault's only prior case of a benchmark under-crediting a model is fix-the-eval-before-trusting-the-score, which was one org's anecdote about grader rigidity. This is the population-scale version with a named mechanism.

The mechanism is the pipeline itself. Extract the issue reference from a PR description, take the issue text as the problem statement, take the PR's tests as the oracle — and assume the PR addresses exactly that issue and the issue fully specifies the PR. Real repositories break that assumption routinely: maintainers bundle fixes, patches introduce bugs and get corrected later, requirements get settled in the discussion thread rather than the description, test patches assert literal strings that exist only in the implementation.

The distribution is the finding, not the 13.6%. Misalignment falls monotonically with how many agents solve an instance — 41.2% among the 34 that none of 131 leaderboard agents ever solved, 5.7% among those solved by over a hundred. The never-resolved tail is what everyone gestures at when arguing how far agents are from real maintenance work, and two-fifths of it is a broken pairing. That does not mean agents are better than reported; it means the residual is contaminated, and any honest statement about the frontier has to exclude the instances whose requirements were never stated. Read with constrain-the-eval-environment-to-measure-capability and benchmarks-conflate-model-harness-and-penalize-alternatives, the pattern generalizes: the tails of a benchmark are where its construction defects accumulate, because a defect that makes an instance unsolvable-as-specified never gets corrected by anyone succeeding at it.

The curation result is the second useful half, and it is a warning about the standard remedy. Human curation is what separates Verified (13.6%) from SWE-Gym (44.3%), and it works — on the patterns a curator can see in the task text. Underspecification and over-strict literal assertions drop by five and three times. The defects that require tracing a PR's relationship to other PRs — a gold patch that was itself buggy, a patch supplementing an earlier one already in the base commit — stay flat at 6–8% across curated and uncurated alike. Reading the task text catches the defects visible in the task text; the rest need repository history, which is why an automated checker with API access is the proposed fix.

Caveats. Prevalence comes from manual coding by two annotators with a third resolving disagreements, and the taxonomy was derived from the same 500 instances it characterizes — a well-documented classification of one corpus, not a validated instrument. The SWE-Gym and Multilingual rates rest partly on the paper's own detector rather than exhaustive hand-audit, so a detector validated against annotators is being used to estimate prevalence; defensible at κ = 0.91 on binary judgments, still a chained inference. Several patterns are judgment calls with defensible alternatives — whether a PR resolving a superset of the stated issue is a defect or simply a harder task, whether inheriting an earlier PR's work is misalignment or normal repository state.
