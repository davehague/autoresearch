Functional correctness and environment correctness are measuring different things, and the agents this map already distrusts on CI-blocking strictness also can't agree with themselves on what a task needs installed

This map's standing contest is how strict a CI gate should be for agent-authored code, with the backstop argument resting on agents eventually producing code that passes. This source supplies a layer underneath that argument that the map has not previously measured: even when the functional gate passes (near-100% eventual execution success after repair), the environment specification behind that passing run is close to arbitrary. Three agents given the identical task declare dependency sets that agree with each other 7-14% of the time by Jaccard similarity, and are in complete disagreement 53.3% of the time on average — meaning more than half the time, no two agents share a single declared package for the same task. The unanimous-consensus rate across all three agents is exactly 0% in every language tested. This is not a capability-tier or recency effect: the paper states newer agents show no meaningful improvement, which rules out "this resolves itself as models scale" as an answer this map could otherwise reach for.

The practical CI implication is specific: a pipeline that locks dependencies from whatever an agent declared on a given run is locking in a near-random draw from the agent's declaration distribution, not a stable artifact — and the failure is invisible to the functional test suite a CI gate usually runs, since repair loops patch execution errors without correcting the manifest's accuracy against what the program actually needs. The JavaScript numbers are the starkest instance: about 49% of declared packages are phantom (never used) and about 62% of runtime-necessary packages are hidden (never declared) — a gap that would show up as a slow, confusing supply-chain drift (unused attack surface, missing transitive pins) rather than as a build failure, exactly the kind of defect a blocking functional gate is not positioned to catch and a permissive gate has no mechanism to flag either. This sharpens rather than resolves the map's CI-strictness contest: it adds a concrete, measured failure class that neither pole of the existing debate (strict blocking vs. permissive-with- triage) was built to address, because both poles are reasoning about test results, not manifest accuracy.

Scope: three specific commercial agents, fifty task templates per language, a single snapshot in time rather than a longitudinal study of whether declaration quality improves with repeated runs; C++'s near-zero accuracy score is partly a measurement artifact of treating compile-time/header-only dependencies as runtime-absent, which the authors flag themselves.
