Same six models, two harnesses, two different leaderboards

the-harness-shifts-benchmark-rank-order and no-harness-ordering-holds-across-models established this on issue resolution. The open question was whether it was a property of that task — long-horizon, tool-heavy, many opportunities for a scaffold to matter — or a general property of agentic evaluation. Here it is on a shorter, more bounded task with an expert-verified ground truth, and it is if anything more severe.

Claude-4.6-Opus is first of six under one review system and near the bottom under the other. Not degraded — reordered. And Claude-4.8-Opus does the reverse: it is the strongest backend under Claude Code (14.13%) and among the weakest under OpenCodeReview (17.90%, tied last). Two models from the same vendor, one generation apart, swap places when the surrounding pipeline changes. The margin that should end the argument: the weakest configuration of the better system beats the strongest configuration of the worse one, so the system term dominates the model term across the entire model set tested.

The regimes are system-owned, which is the diagnostic part. Precision sits at 25–38% for all six backends under one system and 7–16% under another. A model does not carry a precision with it; it inherits one from the loop it is running in. Same for cost — 352K–743K tokens per PR under one, 1.2M–5.7M under the other, for the same models on the same PRs. Anyone benchmarking "which model is the best reviewer" without fixing the harness is measuring the harness, which is exactly the confound attribute-performance-to-the-stack-not-the-model and agent-benchmarks-underdisclose-their-harness exist to name.

What this changes for a reader picking a review tool. The vendor comparison people actually want — Claude Code versus Codex versus a purpose-built pipeline — is decidable, and this study makes it, but the model comparison inside it is not portable. If you switch review harnesses you should re-run your model selection, because your previous ranking was a joint measurement and only one of the two terms moved. That is re-examine-the-harness-when-the-model-changes run in the other direction: re-examine the model when the harness changes.

Bounds. This is a comparison of two shipped review commands against one purpose-built system, with the purpose-built system's authors also authoring the benchmark — a self-evaluation arrangement an-evaluator-sharing-its-reference-solver-cannot-be-self-checked warns about, and the rank-instability finding is the part least sensitive to it since it is a within-system comparison across models. Rankings are computed from a single reported mean per cell with no per-cell confidence interval, so adjacent ranks (17.90% vs 17.90%, 20.40% vs 21.00%) are not separable and the strong claim rests on the wide gaps. Codex appears on one backend only. Sampling parameters are held identical across systems, which is the right control and the one that licenses reading the difference as design.
