Every approval gate in this vault has a time-of-check-to-time-of-use window

The map's approval evidence argues about who decides: a contextual classifier (gate-actions-with-a-contextual-classifier-dial), a tiring human (permission-prompts-fail-open-under-fatigue), an independent confirmer (gate-irreversible-actions-on-independent-confirmation), a formally verified effect gate (external-effect-gate-closes-the-sibling-leak-with-formal-verification). All of them decide once, at generation or approval time. None of them asks what happens to that verdict during the interval before the action actually leaves.

The comparator makes the point better than the system does. Given the same component-scoped predicates and the same current state, an existing executable policy engine reproduces this protocol's admission decision exactly — and then produces dispatch fingerprints for stale actions in every tested post-decision case, and accepts replayed authorization tokens. Same expressiveness, same verdict, different outcome. What closed it was not a richer rule language but two structural properties: the authorization is bound to one exact action and spendable once, and it is re-validated at the boundary where the effect crosses into the external system.

The price is negligible where it matters: a median 0.035 ms at the dispatch gate with sixteen direct dependencies and thirty-two footprint fields, p95 0.061 ms. That measurement excludes evaluating the domain predicates themselves, which is where a repository-scale version would actually spend its time — but the protocol overhead is not the obstacle.

The recovery rule is the part worth stealing. A blocked action is never reactivated. It can only be replaced by a fresh candidate that arrives with current evidence, a later generation, a new one-use token and an unused sequence number. That forecloses the whole class of failure where a retry re-uses an approval granted for a world that no longer exists, and it makes replay attacks structurally uninteresting rather than something a filter has to catch.

This converges with the vault's evidence-freshness thread from an unrelated substrate. gate-lifecycle-claims-on-fresh-hash-bound-evidence and bind-evidence-to-the-state-it-describes hold that a claim is admissible only while the artifact it was computed over is unchanged; treat-agent-output-as-a-claim-not-lifecycle-state holds that the agent's assertion is never the state itself. This is the same principle applied to authorization: a permission is computed over a state and decays with it. Two groups, two domains, one rule — bind the token to the state, and re-check at the boundary where it is spent. For an unattended fleet the reading is direct, because that is where the check-to-use window is longest and nobody is watching to notice the world moved.

The domain gap is the reason this is single-study. The evidence is UAV control — PX4 software-in-the-loop, Gazebo, a physical Crazyflie — where drift signals are physical, fast and easy to observe. A coding agent's staleness is "the branch moved", "the file changed", "the lock expired": a different clock, and usually harder to detect than an aged setpoint. The transfer is stated as a condition (multiple components, checkable support, a runtime-controlled interface) and demonstrated on no software task at all. The near-perfect denominators are conformance-and-replay results rather than open-world success rates, which the paper states plainly. Domain predicates are hand-specified per catalog, so their completeness is assumed, not measured — the limit prospective-enforcement-is-only-as-complete-as-its-contracts already names for this map. Authors' own system against their own reduced variants, no preregistration, no adaptive adversary.
