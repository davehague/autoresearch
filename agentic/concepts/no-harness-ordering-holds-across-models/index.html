No harness ordering holds across models — so there is nothing to correct for

the-harness-shifts-benchmark-rank-order gave this map its first distribution instead of an existence proof: seven models, 260 tasks, two harnesses, mean absolute shift 8.6 points and rank order changing. It carried two caveats the vault recorded at the time — two harnesses only, one of them the publishing vendor's own product.

Both are now answered from outside. This is a different benchmark, a different task domain (multilingual enterprise workflows rather than coding subsets), a different team, four harnesses, and none of them published by the authors. The finding reproduces and comes out larger: every model run under at least two harnesses spreads ≥ 0.08 Pass@1, Claude Opus 4.8 spans 0.209 on a single swap (0.921 → 0.712), and the paper's own summary of the range is 8–21 points. Two independent groups, two benchmarks, six harnesses between them, same conclusion.

The new part: the ordering is not stable

The prior result establishes that swapping the harness moves the number. This one establishes that you cannot learn the harness ranking and apply it. ClaudeCode is best or tied-best for every model where it was run — including the open-weight models, which is what rules out reading it as a vendor pairing effect — but below the top the ordering rearranges by model: Codex beats Hermes for DeepSeek-v4-Flash, while Hermes is competitive with OpenClaw only for the Qwen family. The single near-tie in the whole plot (Qwen-Agent-World at 0.762 under both OpenClaw and Hermes) is called out by the authors as the exception rather than the rule.

That closes a loophole a reader might otherwise take. If the harness term were a per-harness offset, the field could publish a harness correction table and carry on. It is an interaction between harness and model, so a score measured on someone else's harness is not adjustable into a score on yours — it is simply a different measurement. This is harness-interchangeability-is-asserted-not-measured with the non-equivalence now measured across four scaffolds rather than asserted, and it is why attribute-performance-to-the-stack-not-the-model is the only safe attribution.

What the paper does about it

Rather than pick a harness and report one leaderboard, the authors publish the full model×harness matrix and organize every table by harness so model comparisons are read off within a fixed scaffold. That is agent-benchmarks-underdisclose-their-harness's remedy — ship the harness with the number — executed by a benchmark author unprompted, and it is the first instance the vault has of the disclosure rule being followed rather than recommended.

Bounds. The grid is not fully crossed: Codex carries one entry, and the Claude family was never run under Codex or Hermes, so "ClaudeCode is best or tied-best" is a claim over a partial grid. nruns varies 1–3 across entries with no intervals reported, so the smaller spreads are less well separated from run-to-run noise than the 0.209 one. And the benchmark is enterprise workflow work, not repository maintenance — the ordinal claim transfers, the magnitudes are this benchmark's.
