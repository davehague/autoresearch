Code quality calibrated against human maintainability also predicts the metered inference cost of multi-agent review — the first study to connect CodeHealth to agentic review token cost, and the first to separate that cost from PR size rather than assume one explains the other

Technical-debt research has linked low code quality to higher human maintenance cost for over thirty years, and CodeHealth (CH) specifically has been validated as a predictor of human maintenance effort and of AI defect-injection risk. Whether the same quality signal also governs the metered token cost an organization pays when it routes review through a multi-agent LLM pipeline had never been measured — teams budgeting refactoring investment on human-effort evidence had no evidence the same quality also governs what agents now reviewing that code cost to run.

This pre-registered (OSF, filed before the main collection) study answers it directly: fitted separately for each of three LLMs on the same 465-PR sample, the coefficient on baseline CH is negative with a 95% CI excluding zero for all three — the pre-registered conjunctive success criterion. One CH point buys 3.5-6.1% lower total review-and-fix tokens, holding footprint, language and repository constant. The design's central contribution is ruling out the obvious confound: because token consumption scales mechanically with diff size, an apparent CH-cost relationship could simply reflect unhealthy code arriving in larger PRs. The study was built under equipoise to test this directly (PR footprint as a mediator candidate, not a covariate to adjust away), and baseline CH turns out essentially unrelated to PR footprint in the achieved sample — the effect is direct, not an artifact of size.

Where the association lives, from exploratory (not pre-registered) analysis: it concentrates in the review stage — agents reviewing unhealthy code take more turns and consume more context without producing more review comments — and a size-adjusted refit (scored-file size rather than PR footprint) absorbs the association entirely, which the authors interpret as mediation by file size: unhealthy code tends to live in larger files, and it's the whole file an agent reads, not the diff, that drives cost. This sharpens rather than contradicts the map's keeping-PRs-small heuristic: the case for refactoring extends to agent-reviewed code specifically when it changes file structure and size, not merely the score.

Methodological discipline worth carrying alongside the result: two earlier pilots (21 and 37 PRs) were discarded and the two distinct sampling failures that killed them are named and designed around in the main collection — CH aliased with PR size in pilot 1, 92% single-repository concentration in pilot 2's unhealthy tier. The main collection's joint CH-by-footprint stratification plus hard per-repository caps (≤2 PRs/repo/cell, ≤9/repo total) is a transferable design pattern for any future agentic-PR observational study sampling from a concentrated dataset like AIDev (one repository supplies 39.3% of the candidate pool).

Bounds: associational, not causal — CH is not randomized. Three LLMs, one frozen four-reviewer-plus-fix harness, AIDev's curated (≥100-star) tier — agent-authored PRs in established open-source projects, not human-authored or private/legacy code. Cross-LLM token totals are not comparable (cache-regime differences registered as a reason not to pool), so the result is three separate within-LLM confirmations rather than one pooled effect. Not yet independently replicated.
