The enforcement is sound, sub-millisecond, and blocks 42% of the work

Two weeks ago this map's prescription — put the enforcement below the prompt layer, with no model in the decision path — had one implementation behind it. It now has two, built by different groups on different formalisms, landing in the same band. APPA confines taint by branching into a disposable child trajectory and merging back a bounded derivative, with a lattice operation over declared labels evaluated before dispatch (confine-the-taint-in-a-branch-not-the-parent-context). FAVA compiles the task into an append-only permission graph and runs an SMT solver against policy immediately before every effectful action. Attack interception: 98.9%.

The cost side is what this note exists for, because it is the half the layered-defence literature keeps leaving out and the half that decides whether anyone can run it. The gateway fails closed whenever the solver finds no forbidden flow but the risk posture is still sensitive, dangerous or ambiguous — and the benign allow rate is 57.7%. Four legitimate actions in ten are denied.

Put that next to this map's own history and the problem is immediate. The founding finding is that binary permission prompts fail open under approval fatigue, with users approving ~93% of what they are asked (permission-prompts-fail-open-under-fatigue). The prescribed fix is explicitly a dial, not a switch: a contextual pre-execution classifier blocking ~4% of actions and interrupting ~7% of chats, against ~40% interruption under static allowlists (gate-actions-with-a-contextual-classifier-dial). FAVA sits at 42% — on the allowlist side of that comparison, with a solver behind it. A gate at that rate does not get tuned, it gets routed around, and routing around the gate is how approval fatigue happened in the first place.

The fix is not more enforcement, and the authors name it without building it: their design "resolves scope ambiguity via default blocking rather than human intervention." The unrun variant sends the ambiguous bucket to a person instead of to deny, which converts a utility cost into an audit-budget cost — a currency this vault can now price, since a scarce human auditing a fleet has a measurable point past which their oversight buys nothing (vacuous-oversight-has-a-measurable-threshold). That is the real design question this pair of papers opens: not whether the guard is sound, but how much ambiguity you can afford to escalate.

The ablations are worth keeping for a separate reason. Removing the dependency edges and swapping the SMT solver for a local decision rule produce identical regressions (25.8% / 61.6%). The solver is not a formal-methods flourish on top of a working heuristic — it is the mechanism that propagates taint across multi-hop operations, and a cheap local substitute for it does none of the work. Against that, the cost of the real thing is nothing: 0.845 ms median authorization, 0.3% end-to-end overhead on the live path. The expensive-looking component is cheap and load-bearing; the cheap substitute is worthless. That is a useful default for anyone tempted to approximate a gate.

Bounds: benchmark suites rather than production traffic; two of the baselines are best-effort reimplementations of systems whose code is unavailable, and one (ActPlane) is acknowledged to be evaluated outside its native scope; the 100% cells sit on a labeled diagnostic where benchmark trace evidence is pre-attached to violating nodes, so the 801-case aggregate is the honest headline. The prototype is a per-instance gateway, not a verified compiler — concurrent tool calls, shell ASTs and TOCTOU races are abstracted away, which is a live gap given that this vault has already recorded a sibling effect committing inside an approval wait (durable-execution-engines-do-not-supply-barrier-semantics).
