Audit the benchmark against the environment before you read a single agent score

This map's recurring lesson is that a benchmark's defects move scores in both directions and that the instrument has to be audited before the result is interpreted (benchmark-defects-suppress-scores-not-only-inflate-them, fix-the-eval-before-trusting-the-score, a-unanimous-agent-failure-flags-a-broken-task, removing-defective-instances-reshuffles-the-leaderboard). Those audits ask whether the task is well-posed. This adds a variable none of them controls: whether the task is well-posed in the environment you are running it in.

The procedure is three steps and costs nothing but replays.

Establish solvability. Replay the benchmark's own reference solution under the target environment. Where it still passes, the task is unaffected. Where it does not, try to author a compliant reference; if one exists, the task is affected; if none does, the task is blocked by design — the environment forecloses something the task requires. Here: 50 unaffected, 32 affected, 7 blocked. The seven are guaranteed failures for every agent alike, and removing them raises every bundle's hardened success by 3.4 to 5.8 points — a roughly common five-to-seven-point penalty that looks like agent degradation and is not. What remains still discriminates, and more honestly: the spread narrows from 7.1–18.3 points to 2.4–13.5.

Repair over-specified verifiers, additively and symmetrically. Five verifiers asserted an incidental detail the environment blocks and the task never required — one demanded a specific installation path for a tool that only needed to be available. Repairs may only broaden an assertion, run identically at every condition including the control, and keep original outcomes for audit. Two of the five recovered (0.0% → 80.6% and 0.0% → 19.4%), both with the same shape: the agent had built the required tool in its writable workspace, where the check never looked. Three did not move, which is the evidence that the repairs corrected checks rather than inflating scores — and one of those three is a genuine environmental failure (every bundle installed the sampler and computed correct posterior means; none made the installation visible to a second process). This is name-the-failing-check-not-the-finding applied to the verifier itself, and a cleaner protocol than most vault sources manage: broaden-only, applied at every level, originals retained.

Then use the partition as a predictor. The affected/unaffected split, computed before any agent runs, forecasts both currencies. Cost inflates 1.75× / 2.59× on the affected subset against 1.18× / 1.14× on the unaffected one. Success falls 70.3% → 54.5% on the affected subset against 73.8% → 71.8% — noise — on the unaffected one, with 83.5% of all additional failures and all of the trajectory lengthening concentrated on the 32 affected tasks. The control arm is what makes this an evaluation result rather than a difficulty observation: the two subsets have nearly identical control success rates, so the divergence is not a hidden difficulty split. It appears only once the environment is enforced.

The transferable rule is general beyond security policy. Any environmental change a benchmark was not designed under — a sandbox, an offline mirror, a pinned toolchain, a corporate proxy — partitions the task set into a slice it invalidates and a slice it does not, and the reference solution is a free probe for which is which. Reporting a score under such an environment without that partition mixes three distinct quantities: agent capability, environmental tax, and tasks the environment made impossible. It composes directly with constrain-the-eval-environment-to-measure-capability — that note argues for constraining the environment to measure capability honestly; this one supplies the audit that keeps the constrained measurement interpretable.

Bounds. One benchmark, three trials per cell. The 32 author-written reference solutions and the five verifier repairs are the authors' judgment, disclosed with originals kept for audit but not independently replicated. The bootstrap intervals quantify within-subset uncertainty and are explicitly not a test of the between-subset difference. "Affected" describes reference-solution evidence, not every agent trajectory — an agent can take a policy-affected path on an unaffected task, which is consistent with the small residual inflation there.
