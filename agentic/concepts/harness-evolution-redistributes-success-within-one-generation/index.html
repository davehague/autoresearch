Task-coverage churn is a property of evolving against outcome feedback at all, not only of evolving across different task types later

This map's strongest prior forgetting evidence (continual-harness-evolution-causes-catastrophic-forgetting) required a harness to be evolved sequentially against a different task type before losing earlier competence. This source finds the same shape -- gain some, lose some -- inside a single evolution run, holding the task domain fixed, across four independently-designed evolution recipes and two harness-editing philosophies. That generalizes the forgetting concern from "cross-task-type continuation" to "evolution itself redistributes success," which is a structurally harder objection for any future compute-matched-control study to clear: the control would need to show not just that evolving beats not-evolving on net, but that it does so without quietly trading away tasks the Seed already handled. The paper's own mechanism breakdown adds a second, independent finding this map has not carried before: the native selection step inside a self-evolution loop does not reliably identify which parent has the most room to improve -- on general tasks it is measurably worse than picking a parent at random. That is a selection-proxy failure sitting one level upstream of this map's judge/metric concerns, inside the loop's own "which artifact do we improve next" decision.
