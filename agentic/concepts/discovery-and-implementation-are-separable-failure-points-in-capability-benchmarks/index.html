Withholding the spec and separately instrumenting discovery versus implementation turns "the agent failed" into "the agent failed to find it, failed to understand it, or failed to build it" — and these fail independently

Every evaluation of a capability benchmark on this map has to answer two questions before its number can be trusted: is the ground truth contaminated, and does the grading instrument actually measure the construct it claims to. SWE-Recreation answers both by construction rather than by post-hoc audit. Contamination resistance comes from the task shape itself: the agent interacts with a real, possibly-previously-seen application purely as a black box (rendered pixels, pointer/keyboard, no DOM/source/logs/back-end, enforced by the runtime) — so even if a target application is in an agent's training data, that knowledge cannot substitute for genuinely discovering the behavior through the interface, because the replica is graded on functional behavior reproduced through the same black-box interface, not on code similarity to any known implementation.

Grading reliability comes from splitting one judgment into two separately-instrumented ones: a fixed functional judge (excluded from the evaluated pool) grades whether a hidden workflow is reproduced, citing pixel evidence per grade, while an entirely separate post-hoc coverage judge — run on exploration keyframes only, with no influence on the agent or the functional grade — estimates whether the agent ever evidenced reaching a given requirement at all. This lets the paper show something a single pass/fail grade cannot: visible interaction is not useful interaction (one system has a higher effective-action rate than another yet lower fidelity), and some requirement classes fail even where exploration is well-evidenced (mathematical-dependency requirements on the web split) — meaning the bottleneck there is implementation, not discovery. This decomposition — never-discovered vs. discovered-but-unimplemented vs. implemented-wrong — is a template this map should check future capability benchmarks against: a single aggregate score conflates at least three distinct failure modes that a benchmark construction can separate cheaply if it instruments for them from the start.

Graded as an open question rather than confirming or contesting an existing claim on this map, because its central contribution is methodological (how to build a contamination-resistant, decomposed capability benchmark) rather than a result that confirms or pushes back on an existing measured claim here. The judge-reliability check itself is thin — a 20-sample manual spot-check by four experts, not an independent large-scale audit — and the judge model shares lineage with the systems it grades, a shared-blind-spot risk the authors do not rule out.
