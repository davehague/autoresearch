Agent-written tests improve the average and miss the diff

The presence of a test file in an agentic PR carries almost no information. Agent-written tests do lift diff coverage significantly on average — the aggregate is real and statistically clean — but the gain is carried by roughly one PR in three (Java) or one in four (Python), and in the rest the tests do nothing for the lines the agent just wrote.

The two failure shapes are different enough to require different gates. In Java, agents in non-improving PRs delete 2.6× more tests than they add, or edit only the bodies of existing tests — changing behaviour under the suite without extending it. In Python, the inverse: three-quarters of non-improving PRs do add new tests, which then exercise some other code than the diff. The first is a regression risk a reviewer can catch by diffing test counts; the second is invisible without measuring coverage, which is why the authors' prescription is a coverage-aware feedback loop that checks whether the agent's own added lines are exercised by its own added tests before the PR is opened.

The construct-level result is directly actionable and sits on the review side as well as the gate side: error handling is the weakest spot in both languages — try/catch bodies miss 86.0% (Java) and 81.0% (Python), throw/raise 67.5% and 82.3% — regardless of whether the agent added tests. So untested exception paths are the highest-yield place to point a reviewer, sharpening agentic-pr-review-targets-more-than-correctness's finding that reviewer attention diffuses across docs, style, and tests. It is also a candidate mechanism for the post-merge bill: agentic code draws 49% more corrective maintenance and 51% more bug fixes (agentic-code-carries-higher-corrective-maintenance) with no mechanism attached, and unexercised failure paths are a plausible one.

This composes with rather than contradicts agent-tests-trade-stability-for-edge-coverage, which found agent tests doubling human edge-case variety on static analysis. Both can hold: the agent enumerates boundary inputs more patiently than a human while failing to reach its own new lines. Static variety and executed diff coverage are different quantities, and this is the one that decides whether a regression is caught.

Caveats: line coverage, merged PRs only, buildable repositories only, with the Java sample skewed toward smaller projects; the paper reports that the gain is absent without diagnosing why, which it names as open.
