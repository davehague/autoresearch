The context file is not where the missing thing was

Every prior result in this map's context-file thread measured whether the file's instructions were obeyed. generated-context-files-cost-more-than-they-help compared an authoring method, instructions-fail-to-govern-non-functional-requirements measured compliance with an unscored requirement at 8.3%, re-delivery-governs-procedure-not-permission split obligations into procedural and permission classes at 76–100% and 0%. This measures something else: whether the file's knowledge was ever the binding constraint. On generic, naturalistic context files it was not.

The design earns the null. Both agents receive context through exactly one channel with the workspace copy deleted, so each strategy delivers only what it explicitly provides. The floor/ceiling objection is answered directly — on the borderline band, where an extra fact could plausibly flip an outcome, context scores worse. And the inert-manipulation objection is answered by the strongest single result here: on 36 re-runs of the two conventionally-closest near-misses, the real unmodified AGENTS.md never converts a near-miss to a pass on either agent. The files rate Good/Excellent on the author's own rubric and they do perturb behaviour; they simply do not supply the thing that gates these tasks.

The triage says what does. The near-misses need a union-expansion optimization implemented without a correctness bug, proactive token refresh chosen over reactive retry, a known rule wired into the right check, type-narrowing through isinstance + assert. None of these is a knowable repository fact. The agent was not lost; it was not good enough yet.

This reconciles with the map rather than contradicting it. Yesterday's partition held that a context file can carry do this too and cannot carry do not. This adds a third bin underneath both: "here is how this repository works" is a class of content the agent mostly does not need, because on merged-PR work the binding constraint is implementation rather than orientation. So the sharpened rule is that a context file earns its place through the obligations it carries, not the description it provides — and obligations survive only when they are task-anchored and procedural. The one piece of description that measurably changed behaviour here is consistent with that: an operational warning that the full suite takes over twenty minutes, which is an instruction wearing a fact's clothes, and which cut blind full-suite runs monotonically with dose (3.67 → 2.44 → 1.67 per cell).

The honest read of the practical implication, which the author states and this vault should keep attached: effort spent on generic context documents likely pays less than effort spent on task decomposition, tooling, or example-driven prompting — and whether purpose-built, task-specific context that the agent provably cannot infer would help is untested here and remains open.

Bounded hard. Three Python repositories and 15–17 tasks give an MDE above 30 pp, so the TOST bound is a descriptive equivalence claim, not a powered one; a real 10 pp benefit would be invisible (difficulty-bands-are-agent-specific carries the power arithmetic). The SELECTIVE corpus is ~10× and ~18× the AGENTS.md on two of three repositories, confounding delivery channel with corpus — in the direction that favoured SELECTIVE, which still converted nothing. ALWAYS_ON injects every turn, which is stronger than a file an agent reads once, so "guaranteed presence doesn't help, therefore natural discovery can't" is an inference and not a measurement. Single author, model-version snapshot (claude-sonnet-4-6, gpt-5.5), naturalistic files only.
