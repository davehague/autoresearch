The rule already said re-deliver at the decision it governs — this does it every cycle, for the codebase

The map's rule as of 2026-07-25 is persist the contract, deliver it, and re-deliver it at the decision it governs (persist-the-contract-not-the-conversation, memory-delivery-not-storage, restate-the-checks-externally-at-completion). Every data point behind it concerns task requirements — specs, obligations, checklists. This applies the same operation to the other half of what an agent holds in its head: the state of the code it is editing.

The default architecture pins that state without anyone deciding to. read_file and its observation are stored together, so the file's bytes at the moment of reading become an immutable entry in the chronological history. Files are mutable; histories are not. The consequences are two named failure modes: duplicate reads (26% of all reads on one model-benchmark pair), each appending another full copy and compounding the growth that caused the re-read, and stale-context writes, where a string replacement targets text that has already changed and the recovery costs another read plus a diagnosis cycle.

The fix keeps a registry rather than a history: a sync_file call adds the file to a synced set and returns only a marker, and a sync phase before each reasoning cycle re-reads every registered file and injects its current contents in one dedicated block. At most one copy of each file, always current, by construction. It is close to free — the synced set averages 2.66–7.81 files and a local file read is a millisecond operation against an LLM call, so end-to-end runtime falls rather than rising.

This separates a variable the map had confounded. On 2026-07-24 a T1 found that pinning a resolved reference — the intuitive "resolve once, carry it forward" fix — eliminated drift and amplified wrong actions 3.0× (up to 8.5×), worst on the strongest model, taking strict workflow success from 29.2% to 0.0% (persisted-state-without-revalidation-amplifies-errors). Read alone, that indicts persistence. Read against this, the real variable is pinned versus re-derived: an append-only trajectory is a pinned resolution, and replacing it with a re-derivation from the authoritative source each cycle improves every axis measured. The clause the map should carry is deliver state, and re-derive it from the source rather than carrying the reading — with the practical corollary that where the source is a file on disk, re-derivation costs no model call at all.

Two further notes. It is upstream of every compression technique rather than competing with them — sliding windows, summarization, observation masking and trajectory reduction all compress content that has already entered the history, and this prevents the single largest source of that content from entering; combining them is strictly better than either. And the effect is largest on the strongest model (Sonnet 4.5, −37.3% cycles, −50.4% input tokens), because stronger models run longer trajectories — so unlike most harness scaffolding (separate-durable-scaffolding-from-model-compensation), this one's value grows with the model rather than being optimized away by it.

Caveats: this is an efficiency paper — pass@1 is a guardrail, and the deltas (−1.22 to +1.39 points) sit within single-run noise, so the honest claim is "does not hurt." Whole-file synchronization only; on very large files the sync block is a fixed recurring cost, and partial or region-level sync is future work. The baseline is a minimum-viable agent distilled from 14 production agents' tool sets, not a shipped harness. Synced context changes every cycle, which limits prompt-cache reuse on that block — a disclosed and unmeasured interaction with prompt-caching-inverts-cloud-versus-local-economics.
