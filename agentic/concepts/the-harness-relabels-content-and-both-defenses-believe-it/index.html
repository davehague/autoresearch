Context construction is a privilege operation, and nobody typed it as one

This map's standing claim is that the interfaces between agents are where a harness's real behaviour lives and are systematically less designed than the agents on either side — subagent-delegation-adds-a-silent-handoff-failure-class, verify-a-handoffs-claims-before-the-next-agent-reads-them, and most recently a-handoff-is-a-design-surface-routing-does-not-cover, which found that what crosses a model boundary moves quality further than which models sit on either side of it. All of those measure what a handoff does to quality. This measures what it does to authority, and the answer is that the harness hands out privilege as a side effect of formatting.

The definition is the contribution. Map every provider's message types onto three model-facing levels — tool < user < system-effective — and give each content item a fixed origin level, the level at which it first entered the agent, determined from captured model requests and source-level prompt assembly rather than from the filename. A README.md returned by grep has origin tool. Then let the harness assign a level each time it constructs a context. Escalation is simply: the assigned level exceeds the origin level. Table 2 of the paper is uncomfortable read cold — CLAUDE.md, AGENTS.md, GEMINI.md and an invoked skill body enter at user; QWEN.md, an installed custom-subagent configuration and installed skill metadata enter at system-effective; the same bytes read by a tool enter at tool. Placement sets privilege, not provenance.

The demonstration needs no cleverness. Codex GPT-5.5, on a repository whose backdoor is explicit and unobfuscated in its own source, reads the attacker's instruction as tool content, inspects the server, recognizes the arbitrary-command interface and refuses — "I did not start it." Delegate the same request to a subagent, and the harness writes the delegated task into the subagent's fresh conversation as a user message. The subagent says "I will run the server script directly" and runs it. Same model, same request, same visible malice; opposite decisions, because the message type changed.

Why hardening the model does not reach it. In prompt injection the malicious content stays at its origin level and tries to be obeyed. In role confusion it forges chat-template markup so the model misreads the role — and the paper's own baseline shows that failing badly: the role-confusion attacks are easier for models to spot, with Kimi naming the fake <|im_user|> markup as the attack mechanism. Here nothing is forged. The downstream model receives the instruction under a genuine user or system role in the actual model-facing context, having been placed there by the harness. Providers train models to trust higher-privilege roles more — and the paper notes the training-data flywheel that reinforces it independently, since role-structured corpora disproportionately contain higher-privilege text that was followed. The better the model honours the hierarchy, the more reliably this works.

What it means for harness design. The five converged shapes in three-harnesses-from-opposite-philosophies-landed-on-five-shapes include an append-only replayable session record and explicit extension seams. Neither of those is a provenance mechanism. What this result asks for is a fourth column nobody has: content carries its origin level through every reconstruction, so that delegation, goal storage, scheduling and skill loading present content at the level it entered rather than the level the destination happens to use. Every mechanism the paper breaks is a feature a harness shipped for a good reason. That is the point — the escalation is not a bug in any of them individually, it is a missing type on the operation they all perform.

Bounds. One benign cover task (setting up a TODO application) across all 13 objectives — the objectives vary, the scenario does not. Attacker capability is scoped to workspace artifacts and derived state, with no control of the user request, sandbox policy, tool permissions or approval policy. Success rates are per-attempt over ten attempts, single-run rather than distributional. system-effective is explicitly an analytical category rather than a claim that system prompts, developer instructions and subagent policies carry equal privilege, and the paper notes privilege can additionally depend on prompt position. No defense is proposed or evaluated. Harness versions are pinned, and this is a moment-in-time reading of a layer that ships weekly.
