Same working set, twelve times the bill, and the bill buys nothing

This map's largest recent arrival was the-scaffolding-outspends-the-tool-interface — a 28× spread across seven scaffoldings on one fixed task with the model held constant, larger than the model price spread every allocator here is denominated in. This is the same term measured a different way, and it adds the part that makes it a routing decision rather than a curiosity: the expensive configurations are not buying anything.

The design is unusually clean because outcome is held at ceiling by construction. All 144 trials pass every test. Within that, peak per-turn context varies 1.8× — every configuration puts about the same amount in front of the model at any one moment — while cumulative input varies 12.8×. Five tool calls at the cheapest, seventy-nine at the most expensive; an agentic loop resends its conversation each turn, so the spread is a refetch rate, not a capacity difference. Reasoning tokens are ≤0.46% of input and explain none of it. The working set is similar and the rate at which it is rebuilt is not.

The obvious follow-up — do the expensive ones earn it when the facts are harder to reach? — is the one the first sweep cannot answer, since coverage sits at ceiling everywhere. So they withheld k of eight required facts and reran. Every configuration loses exactly the proportion withheld, and no two differ by more than three points at any level, while Haiku spends 5,730,807 cumulative input tokens to reach the 100% Opus reaches on 459,122. Spending more does not recover more when the facts are withheld, and does not recover more when they are present.

The authors decline to convert this into a cost ratio, and the reason is a warning this map should carry. Cache reads dominate every total and are billed far below fresh input; vendors price caching differently; and on uncached input the ordering does not survive — 22 uncached tokens at the cheapest configuration against 163,236 at the most expensive. So the 12.8× is a token-throughput fact, and the dollar fact underneath it depends on the cache lifecycle, which is exactly the-agent-token-bill-is-a-cache-lifecycle-problem. Anyone converting a token spread to a spend spread without stating which of the two they mean is reporting a different number than they think.

For an operator this composes into a concrete audit: at fixed model and fixed task outcome, the refetch rate is a free variable, it is measurable from the run's own logs, and it does not trade against correctness. That is a cheaper lever than solve-sets-are-nested-so-route-for-cost-not-accuracy and it sits underneath it — routing chooses which model pays, this chooses how many times it pays for the same content. It also gives a-code-execution-interface-buys-tokens-and-sells-consistency a control it lacked: any tool-interface saving should be measured against the refetch spread of the harness it was measured in, or it is a measurement of the harness.

The bound is the same one that bounds the whole source: six configurations on migration-shaped workloads with coverage at ceiling, and the vendor-comparable accounting is explicitly not comparable as reported.
