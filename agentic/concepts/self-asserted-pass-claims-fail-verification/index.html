A sixth concrete channel for "what the checker is denied": a coordination agent's own PASS declaration, checked mechanically against the codebase it claims to have changed

This map's standing thesis is that independence is a property of the arrangement, not of who or what does the checking — and the first provenance term, what the checker is denied, has already been instantiated through several channels: a completed audit-repair episode about a different item, an agent's own recent work, and most recently (2026-10-24) the agent's own self-report of task success, where exposing it to the judge suppressed dangerous-misreport recall by 43.4 and 13.3 points on two models. This source adds a sixth, structurally distinct instantiation of the same term: not a completion claim judged by an LLM, but a fix announcement checked by a deterministic, rule-based procedure against the actual codebase the announcement describes.

The result lands in the same place as the self-report-leakage finding, by a different route. Among the subset of claims that provided enough information to be independently checked at all — the cases where the self-report was, on its face, maximally credible — half still failed. That half-failure-rate-on-the- most-checkable-subset is the sharpest evidence yet on this map that "the announcement sounds verifiable" and "the announcement is correct" are not the same property, and that a checker denied nothing but the announcement text itself (criterion 3 in this source) is not enough; it must also be denied the privilege of accepting the claim without checking the artifact (criterion 2).

Severe caveats that keep this single-study rather than confirming anything: the two authors performed all verification themselves, and also operate several of the platform's agent identities, including the announcing agent — a disclosed but real conflict of interest, not blinded or third-party. N=10 is the entire population of code-level claims in this system, with no larger population to sample from, so the finding cannot be strengthened by more data from this source. The platform itself (AITRAP, ~19 agents) is a small independent research system, not an established production deployment at the scale this map's other T1s (GUI/mobile agent judging, cross-provider review contracts) carry. Treat as a thin, structurally distinct data point consistent with the map's existing self-report-leakage thesis, not as independent replication of it.

Bounds: static code inspection only, no runtime behavior tested; two of the four C2 failures cannot be distinguished between an agent competence failure (wrong file edited) and a reporting-integrity failure (correct file edited, wrong filename announced) without commit-history access the authors did not have.
