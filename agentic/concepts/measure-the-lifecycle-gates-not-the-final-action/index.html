Six systems looked clean because nothing happened to retrieve the thing they had written down

This map's contested limb is per-step attribution — whether any signal can say which step in a trajectory mattered. This is the same problem relocated from inside a trajectory to across them, and it has a cleaner answer, because the gates are structural rather than statistical.

An unsafe procedure has to survive four transitions to hurt anyone: it must be authored into the library, it must export across the session boundary, it must be retrieved on a later task, and it must execute into harm. Measuring only the last one merges all four. The study's headline is exactly that merge coming apart: 21 configurations author, 19 retrieve, 19 contaminate, 15 carry over. So six configurations would be reported as clean by a terminal harm rate while holding a risky artifact that happened not to be selected, or was selected and did not land on that probe.

The authors state the consequence in the form that makes it an instrumentation requirement rather than an observation: "a terminal ASR cannot distinguish a safe library from an unsafe artifact that was not retrieved." Non-retrieval is not a safety property. It is a sampling outcome, and the next probe re-rolls it.

Two design details make the measurement honest and both are portable to any fleet's own instrumentation. Denominators are fixed — 225/225/75 — so a missing task, missing judge result or missing retrieval event contributes zero rather than shrinking the denominator. This is the discipline scoreable-runs-are-a-separate-denominator asks for, applied where it is easiest to get wrong: a monitoring pipeline that drops events it could not classify reports a falling harm rate as its own coverage degrades. And state isolation is enforced per cell — new conversation, workspace, process namespace and tool session, with only the versioned skill store advancing — so an observed carryover has exactly one channel it could have come through.

The attribution result is the operational payoff and it is measured as its own ablation. Linking each harmful outcome back to the skill that was retrieved records 108/110 and 99/99 eligible cases. Remove that link while holding the final carryover number matched, and everything else gets worse: contamination nearly doubles, benign utility drops, and useful reuse drops hardest (40.67% → 32.00%). The same terminal metric, bought with worse behaviour throughout — which is this map's recurring finding (an-aggregate-gain-and-a-reliable-regression-coexist-in-every-cell, a-guard-can-raise-the-outcome-score-and-lower-procedural-validity) arriving in the persistence layer.

For anyone running a fleet with a persistent skill or memory layer the checklist is short and this study supplies each item's justification: log what the adaptation wrote, log what crossed the session boundary, log what was retrieved, and attribute outcomes back to the retrieved item. Without the middle two, a clean harm rate is unfalsifiable; without the fourth, you cannot act on a bad one. It is audit-agent-claims-against-trajectory-evidence extended past the trajectory to the state the trajectory left behind.
