Four kinds of "done", and only two of them are evidence

This vault's oldest operational rule is never accept an agent's own report that it is finished. The rule is easy to state and hard to implement, because the moment you build a structured control layer the agent's self-report acquires a schema, a field name and a timestamp, and starts looking like a verdict. This design refuses that conflation explicitly, and the taxonomy is the reusable part.

  • command / predicate — evaluated by the host, independently reproducible, subject only to the correctness of the command or predicate.
  • manual — requires an explicit operator or user decision.
  • checklist / message — require the agent to acknowledge specified obligations, and "remain forms of structured self-attestation."
  • llm_review — adds a separate semantic judgment, and "does not constitute deterministic verification."

The authors' stated purpose for the split is exactly this vault's concern: it "prevents a receipt or model declaration from being treated as proof merely because it appears in a structured field." Everything the runtime does with a check is downstream of which tier it sits in — the host can evaluate the executable ones directly, and conditions needing semantic judgment are recorded as auditable attestations that may trigger further review rather than being counted as evidence.

The measured payoff is concentrated where a claim moves tiers. configure-git-webserver is the clean case: 0/5 → 5/5, with the paper stating flatly that no new component-level capability was added. The baseline agent could already configure Git, SSH, hooks and an HTTP server; it scored zero because it did not reliably preserve and validate the required end-to-end live state before declaring completion. Gating final handoff on a materialized clone–commit–push–curl path replaces "the agent says it works" with "the host observed it working," and keeps the run in a repairable state if the verification itself perturbs the environment. The same shape repeats across every large mover: preservation before a destructive operation, contract satisfaction before committing a transformation, readiness before a service handoff.

Two structural details make the gate real rather than advisory. The transition protocol is pre-commit and ordered — edge validity, then exit checks, then persistence, then edge guards, and the state commits and the history appends only if every required step succeeded, so a failure leaves the run in the source state with the unmet condition inspectable rather than propagating silently. And the runtime distinguishes paused on an unresolved external condition from complete in a terminal state, so an agent that cannot proceed is not counted as one that finished. That last distinction is the operational counterpart of the-agent-either-reports-blocked-or-fabricates-and-that-is-a-model-property: whether the model says it is blocked is a model property, but whether the system records blocked-versus-done is a harness decision, and this one makes it.

The scope of the guarantee, stated by the authors and worth carrying verbatim. StateM "provides control points, not a correctness oracle." Its guarantees are strongest where a transition condition can be checked independently by a command, predicate or human. It can prevent a configured requirement from being silently skipped, and it cannot detect a missing requirement that neither the runbook nor the agent introduces. Recovery is scoped too: it can restore the recorded control state and re-execute configured recovery steps, and it cannot reconstruct work that was never persisted, restore hidden model context, or reverse arbitrary external side effects — hooks run with host permissions and should be idempotent. Calling the protocol checked, logged and recoverable rather than transactional is the right level of claim, and this vault has ingested plenty of work that would have called it the latter.

Bounds. The task-level table associates each gain with the control active in that task and the paper says plainly that the association is not a component ablation — nothing here isolates the check taxonomy from the state-local context refresh or the versioned practices sharing the same runbook. Single benchmark, five trials per cell, no intervals.
