Agent specifications are versioned engineering artifacts

This map's core claim is that the specification is a contract that must be held outside the agent (track-the-spec-in-external-state). That was established for the spec of the work. This extends it one level up: for people building agents, the spec of the agent — its prompts, skills, context definitions, and scaffold behavior — is now the primary engineering artifact, because "an SE agent's capability is determined largely by these specifications rather than by hand-written code."

The practice that follows is concrete and cheap to copy. P17: written "for the agent to read… it has to be versioned together with the code — when you commit, you commit the Markdown too. It becomes a new software-engineering artifact." Teams report maintaining system prompts under version control with tests on top of them, and requirements documents now serve "a dual audience: human teams and the agents that consume them as input," which pushes teams to make specs more explicit and agent-readable.

Two connections matter. First, this is the same instruction as make-agent-facing-rules-enforceable-not-conventional arriving from the authoring side rather than the enforcement side: if the Markdown is a build input, it needs review, versioning, and tests like any other build input. Second, it sits in useful tension with the vault's warning about generated context: developer-written context files gain, generated ones lose (generated-context-files-cost-more-than-they-help). A hand-authored, reviewed, version-controlled agent spec is squarely on the good side of that line — and the practitioner data is the first evidence anyone treats it that way in production.

Note that this is one of the study's lower-rated shifts (mean 3.90 against 4.46 for the review-burden shift), which is itself informative: the practice is real but not yet universal.

Caveats: self-report; no inter-rater reliability; the claim describes teams building agents, which may not transfer to teams merely using them; 15 of 20 interviewees at big tech; Feb–May 2026; survey Likert items carry no confidence intervals and 55 of 80 respondents came via a paid panel.
