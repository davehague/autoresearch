Instructions fail to govern non-functional requirements

This is the fifth data point in context-engineering's live tension, and the first with a different shape. The four before it asked whether a context artifact improves outcomes. This one asks whether the instructions inside it are obeyed at all — and for a cross-cutting, non-functional requirement the answer is 8.3% when the instruction arrives via a repository context file (3 of 36 add-requests honored). Instructed and uninstructed PRs are statistically indistinguishable in their logging behavior (χ²=1.32, p=0.25). The instruction channel is not merely weak; on this evidence it is not a channel.

Read against generated-context-files-cost-more-than-they-help — which found, measuring task success on SWE-bench-style work, that "agents do follow instructions in context files" — the two results reconcile exactly one way: agents honor context that bears on the task they are being scored on, and drop context about properties nobody is scoring. Logging is the cleanest possible test of that hypothesis, because it is never in the acceptance criteria and always in the maintenance bill. So the map's task-anchored hypothesis sharpens from task-anchored context helps to something more demanding: context is honored in proportion to how task-anchored it is — and the corollary is that AGENTS.md is the wrong home for any requirement you actually need enforced.

That is the same sentence runtime-action-governance reached from the safety side — underspecified-targets-drive-unsafe-actions's instruction was put the strictness in the gate, not in hope — now generalized off the safety axis onto ordinary quality attributes. The mechanism (prose is not a control) is identical; the domain is new; and here the failure is silent and un-gated rather than loud and blast-radius-shaped. The authors' own conclusion is the same one: "relying on optional prompts is insufficient to ensure observability," and they recommend deterministic enforcement — observability linters and CI checks the agent must pass before opening a PR.

Caveats that matter. That guardrail recommendation is an inference from the compliance gap, not a tested intervention — the study has no guardrail-vs-prompt arm, so "linters would fix it" is a hypothesis with a motive, not a result. The context-window objection is pre-empted but not eliminated: the authors argue the agents involved have 128k+ windows and compaction, so non-compliance "is more likely a behavioral alignment issue than a resource limitation" — an argument, not a measurement. The headline 67% figure is stated four times without its arithmetic shown in one place; it best reconciles to the n=15 issue-level subset (5/15 compliant). And the 100% compliance for removal requests is flagged by the authors themselves as likely vacuous — agents may simply never have added the statements they are credited with removing.
