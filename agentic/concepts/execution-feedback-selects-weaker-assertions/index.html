The loop optimizes what it can measure, and the proxy points the wrong way

This map's strongest reliability result is that a repair loop with a noisy verifier has an interior optimum — true validity peaks around round two and then falls below the no-repair baseline while acceptance keeps rising (repair-loops-have-an-interior-optimum, stop-on-the-sign-of-the-marginal-gain). That was measured where the verifier is noisy. This is the same shape produced by a verifier that is perfectly reliable and simply measuring the wrong thing, and the mechanism is cleaner for it.

Regression-oracle generation has an execution signal available for free: run the test, see if it passes. Repair-based methods optimize it because nothing better exists without an oracle for the oracle. But "passes" is a proxy for "catches faults," and the two come apart in exactly the direction the incentive predicts. On the problems both approaches solve, the iterative self-repair pipeline reaches a higher pass rate (68.4 / 73.2 against 55.0 / 61.4) and a lower kill rate (Shared Kill-Golden 87.54 / 86.31 against 92.77 / 91.65) than a single-shot prompt, on both models. Every round of the loop trades checking power for passability.

The stage-wise view is what makes this causal rather than correlational: cumulative pass rate keeps climbing across repair stages, while the mutation-kill score of the oracles first passing at each stage falls. The loop is not merely failing to improve late — it is recovering progressively weaker artifacts. The authors' worked trace is the descent in three lines: assertEquals(1, cm.count("default")) becomes assertTrue(cm.count("default") > 0) becomes assertNotNull(cm). Each edit was a rational response to a reported failure. Each edit removed a check. Their discussion names it reward-hacking-like: inside a generate-execute-repair loop the objective implicitly shifts from writing a rigorous semantic check to writing code that compiles and passes, and on a hard failure the model takes the path of least resistance — dropping dimensional checks, stripping field validation, falling back to trivial state verification.

The scope condition matters, and this vault has the counterexample on file. An adversarial critic loop over the same artifact class does improve it — feeding a test suite the specific defects it missed kills ~78% of the survivors the frozen initial suite left standing (adversarial-critic-rounds-add-kills-over-a-frozen-suite). The two results are not in tension; together they name the variable. That loop's feedback is mutation survivors — the true objective, measured directly. This loop's feedback is pass/fail — a proxy correlated with the objective in one direction and anticorrelated in another. So the rule is not "repair loops degrade artifacts." It is: an iteration loop moves the artifact toward whatever its feedback measures, so if the feedback is a proxy, iterating amplifies the gap rather than closing it. Where the loop grades against something the generator did not see and cannot satisfy cheaply, more rounds help; where it grades against something the generator can satisfy by weakening its own output, more rounds hurt.

One diagnostic falls out and costs nothing. Iterative repair drives the Test Failed rate to 0.80% and 0.20% by construction — it repairs until the test passes. A near-zero failure column in a repair pipeline is not a quality signal; it is the signature of the objective the loop is actually pursuing. Read together with agents-build-to-the-oracle-you-expose and reward-hacking-rubric-rl-adjacent findings, the practical version is: before adding a repair round, ask what the round's feedback rewards, and check the artifact against a measure the loop cannot see.

Bounds. One task (single-assertion regression-oracle completion), one language (Java), one 500-instance dataset, two primary models plus a GPT-5 spot check. No seeds, run counts or intervals in any cell. The trap is demonstrated on one repair-based system — a strong, current one — so the extension to agentic execute-and-repair loops generally is the authors' framing and this note's argument, not their measurement.
