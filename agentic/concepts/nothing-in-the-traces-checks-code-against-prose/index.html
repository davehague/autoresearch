Prose was never observed functioning as a specification, and after reading it the agent is less likely to run the check

This is the sharpest negative result in the source, and it lands on a belief this vault has been circling without ever measuring: that written guidance governs an agent's next action.

The mechanism nobody has seen. The assumed loop is read → act → check. At the adjacent transition, P(edit code | read doc) is 0.002 — three occurrences in 1,328 reads. Widening to a three-event horizon leaves it unresolved rather than confirmed: the unadjusted lift is 1.05 with an interval spanning unity, and the stage-adjusted odds ratio is 1.33 [1.09, 1.62]. The two estimates disagree about whether the association exists at all, and the authors report both rather than picking the flattering one. What a read is actually followed by is another read or reasoning.

And the check is anti-correlated. Within three events of consulting documentation the agent runs a test at 0.23× and a build at 0.15× the base rate, and both survive stage adjustment (OR 0.39 and 0.25). This is the only downstream association robust to both specifications, and its sign is negative. Under the paper's operational definitions, Validate — consultation followed by a test or build — has zero events, as does Escalate. So does Verify as an interaction type, along with Compare and Follow-reference.

Why this matters to the vault's standing model. make-agent-facing-rules-enforceable-not-conventional argued that a rule stated as a convention does not govern and must be made mechanically checkable. This is the behavioural confirmation at corpus scale: there is no observed moment in which an agent holds prose up against code. It is the same shape as a-loaded-skill-is-not-a-retained-requirement and restate-the-checks-externally-at-completion — delivered text is not a live obligation — measured here on the whole documentation surface rather than on one skill or one requirements list. The two mechanisms the authors offer and refuse to choose between are both worth holding: agents may be externalising reasoning into files because the window is bounded, making documentation working memory rather than reference, which would make this a context-engineering result about context-is-a-finite-decaying-resource; or they may skip prose validation because a cheaper oracle, the test suite, is available directly, which would make it rational rather than a defect.

The design consequence is executable, not better-written, documentation. The authors' own forward proposal — labelled a hypothesis for intervention studies, not a finding — is that making a documentation check observable plausibly requires artefacts an agent can run: runnable examples, doctests, schema contracts. That is split-the-executable-spec-into-path-and-behavior and build-the-oracle-from-requirements-not-from-expected-outputs arriving from the documentation side, and it is the cheapest unrun experiment this map now carries: hand a repository executable documentation, hold everything else fixed, and see whether a Validate edge appears at all.

Read the negative result at its actual strength. Zero observed validation events is not zero validation. The instrument sees repository-local, path-resolvable file operations; it cannot see reasoning, in-source docstrings, model weights, or a browser. Checking may well happen inside a reasoning block. What the finding licenses is narrower and still useful: verifiability is not currently a behaviour you can point at, so a documentation programme justified by it is justified by an assumption.

Bounds. Transition probabilities are first-order and cannot detect longer-range or reasoning-mediated influence; the three-event lift is the mitigation and it disagrees with itself across specifications. The stage-adjustment model is a logistic GEE clustered by session adjusting for stage, within-session position, log session length and agent family — a reasonable set, not a proof of no confounding, and the discrepancy between adjusted and unadjusted estimates is exactly the stage confounding the authors flagged as a threat. Zero-event stages are zeros for the defined patterns. Documentation is path-identified, so in-source prose is invisible. No multiple-comparison correction across strata. Opt-in telemetry, 87% one agent family, observational design throughout — nothing here shows that changing documentation changes behaviour.
