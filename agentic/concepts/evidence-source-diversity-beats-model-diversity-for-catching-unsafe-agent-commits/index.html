Independence is measured, not assumed — and this source measures exactly the arrangement verifier-independence already argues matters

This map's standing claim is that "independence is a property of the arrangement rather than of the identity of the checker" — what a checker is denied, who authors what it checks, where its expected value comes from. VP-CONTROL instruments that arrangement directly at an agent's commit boundary (the point where a proposed state-changing action — schema migration, snapshot promotion, access revocation — is checked before it executes) with a factorial design built to separate the two candidate sources of "another opinion": a different model reading the same evidence, versus the same model reading independently-sourced evidence. The evidence-source effect is roughly 3.6x the model-diversity effect in this benchmark, and the paper's own mechanistic story explains why: two verifier calls reading the same stale replica or cache can agree on the same wrong state no matter how different the models are, so "add another verifier" silently assumes independent evidence that a shared upstream lineage does not supply. The rule-based control arm (model-side errors independent by construction) reproduces the qualitative pattern, which locates the effect in the evidence plumbing rather than in one specific pair of LLMs — a second, architecturally distinct confirmation of the map's single argument rather than a new object.

The live-execution arm adds a boundary this map has not previously carried in quantified form: a verification mechanism that reads evidence before a concurrent write can be defeated regardless of how independent that evidence is, because the check and the commit are different transactions. A full atomic guard — the predicate checked inside the same transaction that applies the effect — commits zero unsafe effects across 216 episodes; a partial guard commits exactly the effects outside what it declares (9 of 9). This sharpens rather than contradicts the map's argument: independence of evidence source controls one failure mode (a stale shared upstream), and atomicity of enforcement controls a different, temporally-defined failure mode (a race between check and write) that no amount of source independence closes on its own.

Interaction edges: ci-cd-for-agents — this is a directly-priced instance of the map's "how strict should CI blocking be for agent code" contest: a cost-aware portfolio controller using only deployment-observable metadata improves the risk-cost frontier over any fixed verification policy, but calibration transfer fails on unseen fault families (16-26% realized risk against a 5% target), a concrete price attached to the strict pole. runtime-action-governance — the atomic-guard result is a database-transaction-level instance of this map's "enforce permission below the prompt, in layers" argument: the guard is enforcement that does not depend on any model call succeeding, at the layer closest to the actual state-changing effect.

Bounds: actor and verifier checkpoints are quantized 4-10B open-weight models run on one laptop, and actors almost never abstain, so the study primarily evaluates the gate rather than actor calibration — external validity to frontier-model actors/verifiers is untested. The external FinQA transfer check fails to reproduce the source effect with small verifiers on corrupted tables (source independence only helps once a verifier is competent for the evidence and task), so the paper explicitly makes no cross-domain claim. The live arm uses one loopback service, twelve business contracts, and one writer process — distributed services, correlated human decisions, adversarial faults, and long-horizon coordination are named as open evaluations, not measured here. Calibration is an approximate cluster-adjusted Wilson bound, not a finite-sample safety certificate.
