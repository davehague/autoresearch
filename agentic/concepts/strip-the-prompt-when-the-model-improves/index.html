Most of your system prompt is scar tissue

This map has held harness-model-assumptions-go-stale and re-examine-the-harness-when-the-model-changes since 2026-07-05 as cross-org practice with no magnitude attached. Here is one: four fifths of the system prompt of the most-used coding harness in the world, deleted on a model upgrade, reported as costless on the vendor's own coding evals.

The mechanism named is not token cost. It is conflict: the prompt carried "leave documentation as appropriate" and "DO NOT add comments" at the same time, so every run spent capability reconciling a contradiction nobody had noticed accumulating. The prescribed replacement is a relative standard rather than an enumerated prohibition — "write code that reads like the surrounding code: match its comment density, naming, and idiom" in place of a comment-length rule. The vendor's word for the removal is unhobbling, and the premise is that guardrails written to contain a weaker model become overhead against a stronger one.

Two things this composes with. First, removal as a harness edit — the map's 2026-07-22 note, from codeslop-is-the-search-surviving-into-the-patch, that stripping a third of an agent's patch by trajectory search preserves 99.1% of oracle behaviour. Same operation at a different layer: there, the artifact carries the search that produced it; here, the prompt carries the models that preceded it. Neither is found by generation; both are found by search over what can be deleted. Second, it inverts the usual reading of harness-is-tuned-per-model-and-version. Per-model tuning is normally imagined as adding the right scaffolding for a new model's quirks. The largest single edit reported by anyone doing it is subtraction.

The honest limit is that the number is unfalsifiable as published. "No measurable loss on our coding evaluations" names no eval, no delta, no interval — the disclosure gap agent-benchmarks-underdisclose-their-harness measures on academic papers, arriving from the vendor side, about the vendor's own harness. And the claim is by construction model-specific: its premise is that the right prompt is a function of the model, so a team on a smaller or older model that deletes 80% of its scaffolding is not following this finding, it is contradicting it. What transfers is the operation and its scale — treat a model upgrade as an occasion to search for deletions, and expect the answer to be large.
