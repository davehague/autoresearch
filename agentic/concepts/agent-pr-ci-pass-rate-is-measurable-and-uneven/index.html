Agent PRs fail CI at rates worth knowing — but the spread isn't a model ranking

The first at-scale look at agent-authored pull requests meeting a real CI gate: 61,837 GitHub Actions workflow runs, 2,355 repositories, five agents. Copilot and Codex pass ~93–94%; Claude, Devin and Cursor land lower. 3,067 failed agentic PRs sort into 13 failure categories.

Both gate-agent-commits-on-the-same-ci-as-humans (Sourcegraph) and relax-blocking-gates-when-throughput-is-agentic (OpenAI) have been arguing about the merge gate with no outcome data on either side since 2026-07-08. This is the first outcome data. It does not adjudicate them — it measures what CI catches, not what escapes past it, and the escape rate is the quantity the dispute actually turns on — but the era of arguing about agent CI with zero numbers is over.

Read the per-agent spread with care. Nothing in the study controls for task difficulty, repository, or the prompt behind the PR; the five agents are not doing the same work. This is a comparison of deployments in the wild, not a controlled model comparison, and treating the 94% as "Codex is better" is exactly the harness-inside-the-number error evaluation-integrity exists to flag (constrain-the-eval-environment-to-measure-capability). What the number does support: a team can measure this for itself cheaply, and should, because it is the cheapest available signal on whether its own agent pipeline is degrading — which is the finding in ci-reliability-degrades-as-agent-pr-volume-rises.

Caveat: observational; the AIDev repo population self-selects toward projects that permit bot PRs. "Workflow success" is a CI pass, not a merge, and certainly not a shipped defect.
