The field standardized on a text file before it standardized on anything executable

This map's composition sub-thread already holds a corpus-scale finding that harness assembly is a measurable property distinct from harness performance — the 3,171-repository security-defect census (agent-harness-architecture's "unlockfiled dependency layer" bullet). This source reads the same kind of population from a different angle: not what's wrong with what teams assemble, but what they reach for at all. The answer is unambiguous by an order of magnitude — a plain-text convention file (CLAUDE.md / AGENTS.md / copilot-instructions.md) is present in roughly two out of five repos that configure any agentic tool, while the two mechanisms that let an agent act differently rather than merely read differently — Skills and Subagents — sit at 4.6-5.5% each, more than a year after both shipped. Zero observed use of persistent subagent memory is the sharpest single number here: the feature exists, is documented, and this 2,853-repository sample contains not one repository using it.

The AGENTS.md figure is the more structurally interesting one. 17.3% of repositories configure AGENTS.md with no tool-specific artifact alongside it — not "in addition to" CLAUDE.md or copilot-instructions.md, but instead of them. Read against the Context-Files/Rules negative co-occurrence (Cramér's V -0.41), the picture is teams picking one governing-instruction surface rather than layering several, and a meaningful fraction of them picking the vendor-neutral one on purpose. This is a corpus-observed instance of the interoperability bet this vault's context-engineering work has been tracking from the vendor-announcement side; here it shows up as behavior. Interaction edge: context-engineering carries the standing-instruction-adherence and precedence findings this census does not test (it measures presence of a file, not whether the file governs anything) — this source supplies the population-scale adoption denominator those findings have been missing, and the two should be read together rather than as competing claims about the same object.
