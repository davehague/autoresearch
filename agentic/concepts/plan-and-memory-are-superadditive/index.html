The scaffolds this vault evaluates one at a time were never separable

This map's long-horizon limb says failure is a state problem rather than a step-count problem (long-horizon-failure-is-state-not-steps), and the vault's memory results have been ambivalent: generic memory scaffolds degrade all ten models tested (memory-scaffolds-can-degrade-long-horizon-agents), delivery beats storage (memory-delivery-not-storage), and a context renewal does not discharge an obligation (context-renewal-does-not-discharge-a-completed-obligation). Planning results sit in a separate pile. Every one of those measured a scaffold alone, against a bare loop.

A clean 2 × 2 factorial says that was the wrong experiment. Planner alone is worth +6.3 instances, memory alone +8.3, the two together +25.0 — an interaction of +10.3 beyond additive, F(1,8) = 10.92, p = 0.011. Roughly forty percent of the effect exists only in the coupling and is invisible to any study that ablates one component at a time. That is a methodological finding as much as a design one: this vault's habit of pricing scaffolds individually systematically understates the ones whose value is relational.

What the coupling actually is is worth stating concretely, because "we integrated planning and memory" is otherwise a slogan. Four boundary crossings: the current phase selects the retrieval policy (exploration and backtracking get a large diversity-favouring budget, implementation a small graph-weighted one focused on the edit site, with per-phase token budgets 20k/16k/12k/16k/20k); the active sub-task's keywords seed the retrieval anchor; memory-derived statistics are what stuck detection reads (edit counts, read saturation at 15 reads without an edit, 8 normalized repeated actions); and the issue-reproduction verdict updates verification state. The plan tells memory what to fetch; memory tells the plan it has failed.

The mechanism numbers agree with the story, which is what separates this from a tuning result. Failed-action recurrence halves (0.50×), empty-patch exits fall to a third (8.3% → 2.7%), context-window exhaustion to under half (6.7% → 3.0%), and revert-then-refix recoveries rise 1.46× — the loop is not solving harder problems, it is failing to waste itself, which is fix-the-loop-not-the-artifact with a ledger.

Most of the machinery has no model in it. One LLM call per episode decomposes the issue; phase detection, stuck detection, hysteresis and retrieval are all deterministic. That places it beside compile-the-procedure-into-the-harness and move-task-difficulty-from-the-model-to-the-harness rather than beside the prompting literature — and it is why a +5.0 pp gain arrives without a cost story to argue about.

The statistical conduct deserves separate credit and is unusual enough here to be worth copying: three runs per arm because FP8 serving is not bit-reproducible even at temperature 0, an instance-level cluster bootstrap with a percentile 95% CI [+14.3, +35.7], McNemar tests on matched runs, and a balanced factorial for the ablation with an explicit interaction contrast — against a harness-matched baseline rather than a published leaderboard number.

Caveats: the headline is one 30B open-weight model; the API-model, OpenHands and TerminalWorld arms are single-run generality probes and the authors label them as such. Gains concentrate on the difficulty tiers the base model can nearly reach (+12 under 15 minutes, +17 at 15 min–1 h, +2 at 1–4 h, 0 above 4 h) — the hard tail moves for neither arm. Resolved status is an operational proxy; patches can pass tests and diverge from maintainer intent. And the factorial isolates the planner and memory only, leaving the execution-grounding and edit-integrity contributions unestimated.
