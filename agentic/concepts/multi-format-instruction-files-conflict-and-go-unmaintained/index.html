A multi-format instruction surface conflicts with itself 1 time in 6, and the single-format version is usually touched once and never again

This map and runtime-action-governance already carry two separate findings about the project instruction file: stale-instruction-files-override-code shows an agent will follow a stale rule over correct code 90.1% of the time absent an explicit override, and the-instruction-file-is-an-ungoverned-security-surface shows the file that wins that precedence fight is also the one nobody reviews — written once by a single contributor 95.8% of the time (the-project-rule-file-is-written-once-and-abandoned) and 67.3% never edited again. This source supplies the ecosystem-scale denominator those single-corpus findings needed: mined from 1,000 repositories and 3,387 files across all four major formats at once, it confirms the maintenance pattern independently (40.4% touched exactly once here, against 67.3% never touched at all in the .cursorrules/.mdc sample) and adds a failure mode neither prior finding could see from inside a single format — what happens once a repository runs more than one.

Running two or more formats is common, not rare, among the repositories popular enough to bother: 42.2% of instruction-bearing repositories in the higher-popularity group carry AGENTS.md and CLAUDE.md, or either alongside Copilot instructions or Cursor rules. That is a deliberate choice to serve multiple agent products from the same repository, and it creates exactly the opportunity a-skill-description-loses-the-conflicts-it-wins-alone already measured a resolution mechanism for within one file — except here the conflict is between two separately-maintained, top-precedence surfaces, and the precedence ordering that result establishes has nothing to say about which of two instruction files wins when both think they're the only one. In a manual check of the sections that overlap across those multi-format repositories, 16.1% actively disagree — not merely drift apart in emphasis, but give the agent contradictory guidance on the same question. Unlike the within-file inconsistency the-instruction-file-is-an-ungoverned-security-surface found (one file specifying camelCase and later PascalCase), this conflict has no single author who could have caught it, because the two halves are often authored by different people targeting different products at different times.

The template result is the constructive half, and it is bounded by the same gap this map keeps finding between structure and correctness. Ten Required, four Gap, and two Recommended categories, derived from prevalence and addition-ratio analysis across the corpus, raise structural coverage from 18.7% to 82.8% when an author is handed the template explicitly — a cheap, high-leverage intervention if a team wants a more complete file. But the companion generation benchmark names the ceiling on automating this instead of asking a human to use the template: the best method (retrieval-augmented generation) tops out at ROUGE-1 F1 0.459 on full-file similarity, and a 278-instance manual review of its category-level output finds only 19.4% fully preserved the original developer's intent, with 61.2% partial and the remainder wrong. A template with good category coverage is not the same thing as a file that says what the project actually needs said — coverage is a shape metric, and this result is the gap between shape and content stated with numbers attached.

Bounds. 1,000 repositories is a cross-sectional convenience sample of whatever was public and indexed, not stratified or longitudinal — there is no claim here about causation (does running two formats cause more conflicts, or do larger/older projects that accumulate multiple formats also accumulate more content to disagree) and no claim about which format "wins" when an agent encounters both. The 16.1% conflict rate comes from manual comparison of a subset of overlapping sections, not an automated full-corpus audit, so it likely undercounts subtler disagreements a reviewer missed. The template's categories are derived from observed prevalence, not from a controlled study tying specific categories to measured agent-behavior improvements — it describes what files commonly contain, not what they should contain to work better, though the two are presumably correlated.
