Silent is the default failure mode, and it is invisible to the layer that is supposed to catch it

Every component-level health check in a compound AI pipeline — the shape this map already treats as the default unattended-operation substrate — measures its own latency, error rate, and uptime. None of those is where this paper's incidents actually live. A scheduled re-indexing job silently swapped the embedding model; cosine similarity between query and retrieved documents dropped from a mean of 0.78 to 0.41; the retriever kept returning k results; the generator kept producing fluent text; every health check stayed green for nine days. That is the modal incident, not the exception — 51% of the 150-incident corpus is this shape, and the gap between detecting a silent failure (4.2 days) and detecting a crash (12 minutes) is roughly three orders of magnitude.

This sharpens — and partially answers a mechanism gap in — this map's own service-mesh-reliability-assumptions-break-for-agent-delegation, which found that conventional circuit breakers assume idempotence, latency-as-failure-signal, and free discards, none of which hold for agent delegation. This paper's circuit breakers are a different adaptation of the same primitive: they trip on semantic quality metrics (output coherence, retrieval relevance) rather than HTTP status, because "most AI failures return 200 OK with degraded content." That is not a refutation of the delegation-specific failure modes the earlier source found — this testbed is a RAG/tool/orchestrator pipeline, not a multi-step agent-delegation system, and the authors never claim their breaker generalizes to that substrate — but it is independent evidence that the fix for a component-boundary reliability problem is instrumenting the semantic boundary, not the transport boundary, which is the same diagnosis the delegation paper reached from incident analysis rather than controlled fault injection.

What is new and well-measured here: the resilience-pattern catalog is the map's first controlled, fault-injection-validated (not incident-observed) measurement of which interventions close the silent-failure gap and by how much, on a testbed built for exactly this purpose — 23 injection scenarios, one per taxonomy mode, 100 trials each with 95% CIs. The combined-pattern result (3+ patterns, 71% MTTR reduction) is the sharpest number: no single pattern reaches even 40% coverage of failure modes alone, so the practical guidance is defense-in-depth across the boundary types, not a best pattern to adopt.

What stays open: this is a two-author study on one self-built 6-component testbed, measured against a naive unstructured-monitoring baseline rather than standard retry-with-backoff (which the authors flag as the stronger comparison and leave unrun), and the fault injection never ran in live production or on a 20+-component or nested-agent-hierarchy architecture. It does not move this map's status — single-study, no independent replication, and a different system class (compound pipelines) than the agent-delegation incidents the map's existing durable-state facet is built from — but it is convergent evidence, from a different measurement method, for the same standing claim: health checks that evaluate components in isolation cannot see a failure that exists only in the relationship between them.
