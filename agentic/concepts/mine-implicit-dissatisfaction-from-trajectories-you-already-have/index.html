The failure was logged; nobody was reading it as a diagnosis

This map's method is auditing agents from trajectory-level evidence, and its results so far mostly concern detecting that a run went wrong (first-wrong-step-attribution-is-mostly-wrong, a-tiny-monitor-prices-a-doomed-trajectory, the-correction-window-is-the-first-third-of-the-trajectory). This adds a use for the same artifact after the run is over: the stored trajectory says which piece of standing context caused the failure, if you read it backwards.

The signal is free and nobody collects it. The claim is that user corrections, rephrasing, escalation language and abandonment are already sitting in production logs at roughly twice the frequency of explicit satisfaction signals, and are richer — no thumbs-down button, no annotation budget, no labelling pass. That is a genuinely cheap input for a loop, and it is the part of this system most worth stealing.

The attribution method is a compression worth noting. Rather than walking a computational graph node by node, the whole trajectory is presented in one LLM call in reverse temporal order — response → tool outputs → thinking → inputs — with the expected-versus-actual delta supplied as the loss signal, so the model looks for the earliest node inconsistent with the delta rather than the latest one that propagated it. The mechanism it exploits is that the agent's own chain-of-thought names its sources ("According to the KB…"), which makes the trace self-indexing. Reported as 16× fewer calls than iterative attribution at equivalent accuracy, and 72.7% node accuracy with 85% in the top three.

The honest half of the paper is its detector result. A one-line prompt — "is the user dissatisfied? output true/false" — matched a carefully structured eight-category signal taxonomy exactly: precision, recall and F1 all 1.0 in both arms. The authors say plainly that the taxonomy provides richer downstream diagnostics and no accuracy improvement for the classification it was built for. A perfect score in both arms on 75 traces is more likely a statement about how unambiguous synthetic dissatisfaction is than a capability claim, and it is the strongest available reason to distrust the rest of the numbers on this dataset.

Which is the caveat this map should attach hardest: the traces are simulated and the faults were injected by the same team that annotated the ground truth. What survives is the architecture and the input — implicit dissatisfaction as a free diagnostic signal, and reverse-order single-pass attribution as a cheap way to consume it. The accuracies do not survive as estimates of anything a production system would see, and no production deployment is reported anywhere in the paper despite the system being built for one.

Bounds. 60 traces, bootstrap intervals over 20 points wide, no seeds or repeated runs, no model named for any stage. Single-session analysis only; cross-session aggregation of recurring failure modes is named as future work. Nothing measures the human-approval step the architecture routes every recommendation through.
