An agent needs the bytes, and which bytes it needs changed since last turn

goal-hinted-pruning-beats-generic-compression established that pruning anchored to what the agent needs right now beats generic perplexity-based compression, and that generic compression destroys code structure. This extends it in two directions and adds a warning about how to read the numbers.

The first extension is a named property rather than a technique. Extractive — the compressor selects spans and does not rewrite them — is what makes compression compatible with an editing agent, and it is measured: 96% of emitted identifiers, paths and numbers were already present in the input, holding at 96.2% off the training distribution. A paraphrasing compressor can be excellent at prose and still break every exact-match edit downstream. The gateway keeps [SEG] markers so any original span can be pulled back byte-exact on demand, which makes the compression lossy on the wire but recoverable when the agent needs the untouched bytes — the pattern compaction-selection-is-all-or-nothing shows is otherwise unavailable.

The second is a finding about where intent acts. Told the agent's current task, the model does not retain more; it retains differently — choosing which lines survive inside a segment it was going to keep anyway. That is a more specific claim than "task-aware compression helps," and it is the mechanism by which twice the compression does not cost twice the quality: the extra aggression is spent on stale context the current intent does not touch.

The statistical discipline is why this grades strong, and it argues against its own headline. Quality-retained is a ratio of two proportions over 300 instances, and its 95% interval spans roughly ±20–30% of its own value — so 86.5% is consistent with anything from the high 60s to slightly above parity. The authors therefore refuse two claims their own table would support: the 0.9-point gap to the mid-tier compressor is not a gap (separating it would need ~10⁵ instances per arm), and the 7-point gap to the frontier compressor is suggestive, not measured. What is well determined is the compression rate, because it aggregates millions of tokens rather than one binary outcome per instance. Read the first column as a result and the second as a floor.

Three reporting choices worth adopting wholesale. They predicted the in-distribution regime would compress harder at equal quality; it compressed slightly less and retained more, and they report both directions "because only one of them is a result." They keep all 300 instances in the denominator so an unapplied patch counts unresolved, and explicitly decline to quote the 92.8% that excluding apply failures would give — "apply failure is a real cost of compression here, not a harness artifact: it is 3× more common on the compressed arm." And they give two aggregations with a caution: macro-averaged 27.8% versus corpus-level 21.7%, differing because the largest files compress hardest, and the corpus figure is the one that predicts a token bill.

The limitation that lands on the operator. Identifier retention is a tendency, not a guarantee — roughly 60% of identifier-like tokens in a segment do not survive, by design — so a production deployment should run a presence check for the current target identifier on the compressed output and fall back to the original segment on failure. And the dominant known gap is under-dropping: drop recall 0.24 against an always-keep policy's 0.59, meaning there is compression still on the table, not that too much is being thrown away.

Bounds. Single-shot harness over 300 SWE-bench Lite instances — one API call, no tools, no turns — which bounds comprehension under compression and says nothing about multi-turn agent cost or exact-match editing in a live loop; the authors defer that to a companion paper. Python-heavy training distribution, other languages unbenchmarked. Supervised distillation of one teacher, inheriting its policy including a four-level importance scheme that collapses to two effective bands, so a deployment cannot dial compression per level. Line reflow can break an exact-match edit unless the surrounding gateway realigns it.
