PR acceptance resists prediction at submission time

Read this one through AUC, not F1 — the paper's headline "F1 above 0.95" is what a majority-class baseline scores at a ~91.8% merged base rate (skewed-label-bases-inflate-classifier-headlines). The honest result is that a leakage-aware model with PR text structure, repository popularity, temporal signals, lightweight diff statistics, and keyword intent tags reaches AUC 0.676, falling to 0.609 when the contributor populations are balanced. Better than chance; nowhere near determined.

The value is in composition. This map already holds that merge outcome is socially determined — submitter attributes carry 69–76% of explanatory power and self-integration multiplies agentic merge odds ~5,419× (merge-outcomes-are-dominated-by-who-submitted) — and that the label misdescribes the work, since only 35.7% of rejections are genuine agent failure (rejection-labels-overstate-agent-error). This paper attacks the same target from the opposite side, asking whether the artifact predicts the label, and answers no. Put together: merge outcome is weakly determined by the change and strongly determined by who submitted it. That is a stronger statement than either result alone and one more reason not to benchmark or reward agents on merge rate.

One secondary signal is consistent with the social reading rather than a code-quality reading: for acceptance, text and metadata features (body length, title length) rank above raw diff-size measures, while for review effort the ranking flips to diff variables. How a PR is presented tracks acceptance better than what it changes. The authors correctly refuse a causal reading, and so should any use of this — but the direction matches the submitter-dominance finding.

Caveats, and they are substantial. The paper reports no dataset characteristics at all — no PR count, no agent/human split, no repository count, no date window, and no list of which agents produced the agent PRs — so the population behind these numbers is unspecified. The advertised human-only and agent-only breakdowns are never reported as numbers, only as one qualitative sentence, which means the human-vs-agent comparison in the title is unsupported. Feature importances appear as a single chart with no values. Single corpus (AIDev), single study.
