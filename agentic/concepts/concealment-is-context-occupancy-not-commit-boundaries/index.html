The window, not the history

This map has spent a month arguing that the reviewer agent has become the gate and that nobody measures its false-negative side. PRWeaver measures it, and the number that matters is not the raw miss rate but the variable the miss rate responds to — because that variable is a harness setting, not a model property.

The intuitive story about a distributed attack is that it hides in the seams: split the malicious change across commits and each PR looks innocent, so the reviewer never sees the whole. That story is measured here and it is wrong. Rendering the same verified attack as one PR versus one-component-per-PR moves detection by at most five points in all six auditor–model configurations. Commit boundaries are not where the concealment lives.

What does move it is co-residence. Two conditions dominate. Interleaving genuine upstream PRs between the components costs 5–13 points at N=16 and grows with N. Fusing each component into a genuine upstream diff under a description that plausibly accounts for both costs 10–18. And the sharpest cut is the review protocol: at N=24, an auditor reviewing PR-by-PR loses 8–11 points against its own N=0 baseline, while an auditor handed the whole release window in one context loses 39–45, bottoming out at 16–22% detection.

The history ablation isolates the claim. Hide the attack-bearing predecessors — disable history-inspection commands while preserving the current tree and the reviewed diff — and detection falls only 4–11 points. So the auditor was not failing for want of access to the past. It fails when the past is in the room.

That inverts a natural remedy. This vault's reviewing-one-pr-at-a-time-cannot-see-what-two-do-together establishes that per-change gates miss cross-change interaction, and the obvious fix is to widen the review unit — show the reviewer the queue, the window, the history. PRWeaver says widening the window is the condition under which concealment works best. The two are not contradictory: BulkPR-Bench asks whether an agent can recover consequential relations it is asked to look for, PRWeaver asks whether an agent notices an attack it is not looking for. Widening the unit helps the first and hurts the second, which means "give the reviewer more context" is not a direction, it is a trade whose sign depends on whether the reviewer has been told what to look for.

The mechanism the paper declines to attribute internally is worth naming as a hypothesis, because this vault has independent evidence for it. Benign material co-resident with the target is exactly the condition under which a-skill-description-acts-without-being-invoked and a-standing-policy-decays-into-one-more-retrieved-source both fire — resident context competes for the same attention as the thing you need attended to. Carrier fusion adds the narrative half: the PR description supplies a purpose that accounts for the diff, which is measure-drift-from-intent-not-just-defects-in-the-diff read from the attacker's side. A stated intent that explains the change is precisely what an intent-checking reviewer is built to accept.

Practical reading. If you run a reviewer agent as a security gate, the review unit is a security parameter and the safer setting is the narrower one. Per-PR review at N=24 retains 50–60% where whole-window retains 16–22% on identical content. Repository history should be a tool the reviewer may call, not material pre-loaded into its window. And no configuration here is safe: the best cell in the study evades 21% of the time with the entire attack in a single PR.

Bounds. One run per cell, so the dose curve carries no intervals — the monotone trend is supported by its consistency across three auditors and four doses rather than by per-point precision. Ten repositories, almost all Python web frameworks. The attacks are agent-synthesized under execution-based admission and two-reviewer plausibility annotation, not historical incidents, so they are realistic-by-construction rather than realistic-by-provenance.
