Context-compaction summaries can keep the right facts and still can't finish the task, because what they lose is progress state, not information

Compact-Bench's matched-continuation design is what makes this separable: the same repository snapshot continues down two arms — full history (PRE) and summary-only (POST) — with everything else held fixed (agent, tools, 8-step budget), scored by the repository's own FAIL_TO_PASS tests. That lets the authors measure "did the continuation succeed" and "did the summary retain the right facts" as genuinely independent quantities instead of inferring one from the other.

They diverge sharply. The best LLM summarizer backbone retains at most 16.0% of recurring details (paths, commit SHAs, PR/issue IDs, error types, key-value pairs) as literal substrings across a compaction boundary; a purely mechanical anchor-index reference — no LLM judgment involved — retains 79.1%. That is a roughly 5x gap between an LLM deciding what mattered and a deterministic index of what appeared, and it lands squarely on this vault's recurring theme that validated or structured state outperforms free-text summarization, here applied to the compaction step itself rather than an inter-agent handoff.

But the paper's sharper finding is that retention alone doesn't predict task success. Summaries that correctly keep the target file path and the relevant code strings can still produce a continuation that fails the repair, because the missing ingredient is progress state — what has already been tried, what remains — not the kind of literal fact a retention metric is built to check for. One repair in the Task-Preservation set is damaged by 13 of 14 summarizer backbones; another is damaged under every one of 5 prompts tested — evidence that some of this failure mode is structural to compaction-by-summarization as a technique, not a property of any one summarizer's quality.

A related, separately-named failure shows up in the 106 real production compaction chains: some summaries describe already-completed file writes as still pending — a confabulation about prior progress, distinct from simply omitting a detail, and arguably more dangerous because it actively misleads the continuation rather than leaving a gap.

Bounds: results depend on the specific repairs, the continuation agent, and the 8-step budget tested; detail-retention scores measure only literal string recurrence (semantically-equivalent rephrasing is undercounted, not credited); production-boundary estimates (15.7%) rest on a small, non-static session subset; private session payloads are not released, though scoring code, configurations, and outcome tables are.
