The context that works is the one that was measured first

This map's standing result about non-functional instructions is bleak: prohibitions delivered as text achieve 0% compliance where procedures reach 76–100% (re-delivery-governs-procedure-not-permission), instructions about logging are complied with 8.3% of the time from a repository context file (instructions-fail-to-govern-non-functional-requirements), and generic context files do not move correctness at all (generic-context-files-do-not-move-correctness). "Write efficient code" is exactly the kind of instruction that literature predicts will do nothing.

It does almost nothing: general quality feedback moves static efficiency findings 1.26 → 1.22, a 4.69% reduction against a baseline of 1.28. Naming the specific defect categories — copy-and-allocation overhead, interface-and-coupling burden, the two that account for 82% of the excess in this codebase — moves it to 1.12, a 12.50% reduction, with the measured efficiency score rising 0.294 → 0.342 → 0.385 across the three stages. Roughly three times the effect for the same delivery mechanism and a longer prompt.

The distinction that makes this actionable is not "specific beats vague," which is folklore. It is that the specific categories were not authored, they were measured: a taxonomy built by collapsing the codebase's own static checks, refined on stratified samples by two independent annotators with expert review, and frozen before the analysis ran. The instruction works because it names a defect class that was empirically shown to be the one this generator produces in this repository — which makes the artifact a finding delivered as context, not advice. That is the constructive counterpart to generated-context-files-cost-more-than-they-help: an LLM-written context file loses points, and a context file distilled from the organization's own defect distribution gains them.

It also sits on the enforceable side of this vault's split. The categories here describe what the output should not contain and are checkable by a static analyzer after the fact, which is the condition make-agent-facing-rules-enforceable-not-conventional identifies — as opposed to a prohibition on an action, which is the class that reliably fails to bind.

Carried as suggestive, and the bounds matter. Fifty functions, three runs, one language, one organization's taxonomy — the categories transfer only as far as the defect distribution does, and the authors say plainly that "category definitions and downstream associations should not be assumed universal across languages/organizations." The benchmark was selected for containing target-category findings, so this measures the ceiling on the population where the intervention is relevant rather than its expected value over a normal change stream. It is a reimplementation task with inputs, outputs and intended logic held fixed, not open-ended authoring. And there is no measurement of what the extra instruction cost elsewhere — nothing checks whether steering hard on efficiency degraded readability or correctness.
