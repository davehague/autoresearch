Running two vendors is not running two opinions

This vault keeps meeting the same mechanism in different clothes. A reproduction test and the fix written in one trajectory fail together at 1.87× the independence rate, because both come from one reading of the bug (cogenerated-tests-and-fixes-fail-together). A verifier built to be narration-blind, state-grounded and anti-capture still inherits the agent's error, because it re-derives from the same source under the same interpretation (a-verifier-sharing-the-interpretation-shares-the-error). Each time, the shared thing was a trajectory, a prompt, or a source document — something a careful architecture could plausibly separate.

Here the shared thing is the item. Six models across two providers answer the same benchmark questions independently, with no shared context, no shared trajectory, and nothing passing between them — and their errors still correlate at 0.33–0.85 in latent units across families. Then the decomposition: condition on leave-out item difficulty and the lineage excess is indistinguishable from zero in both benchmarks, −0.009 [−0.064, 0.047] and 0.023 [−0.035, 0.086]. A hosted model correlates 0.27–0.88 with five open-weight ones. Given how hard the question is, knowing which base model produced the answer adds nothing.

The direct consequence is for the diversity control this map has been endorsing. Anthropic runs multiple narrowly-scoped reviewers in separate context windows precisely so they do not share blind spots (run-several-scoped-reviewers-not-one-mega-agent); a prior measurement had already found that model-family diversity is a poor proxy for verifier independence (verifier-diversity-is-not-verifier-independence). This puts a number on the negative half at population scale and across providers: the family axis is empty. Whatever the scoped-reviewer design buys, it is not buying decorrelation by virtue of the models being different — it has to be buying it through scope, context boundary, or a genuinely different route to the answer. That also explains why the one reliably independent check this vault has measured worked: it re-derived the target from the original request rather than from the agent's output (an-independent-checker-beats-the-same-model-checking-itself) — a different reading, not a different vendor.

Correlation cuts both ways for anyone auditing a fleet. As a threat it defeats budgeting: clustered errors push expected uncaught failures from 7.59 to 9.31 as ρ rises, because a fixed budget cannot absorb a round where everything fails at once. As a resource it is the only thing left once self-reported confidence turns out to be uninformative (confidence-ranked-auditing-flips-worse-than-random) — auditing one agent becomes evidence about its siblings, worth 3.47 risk units against random at high correlation. That mechanism has a precondition worth stating for anyone running a fleet on a moving stack: it requires persistent error profiles, and collapses to 0.29 when persistence is removed. A fleet you fine-tune or re-point at a new model version frequently gets an attenuated version of the only signal it has left.

One useful detail against the binary framing of "family": inside Qwen3, correlation grades by size adjacency (4B↔8B at 0.72/0.93) rather than by membership (0.6B↔{4B,8B} at 0.39–0.61). Capability tier predicts co-failure better than ancestry does.

Bounds: six question-answering models on GSM8K and HotpotQA at temperature 0, not coding agents on repository tasks — the mechanism transfers, the magnitudes are not a coding-fleet estimate. Correlation is measured on aligned items, which the authors flag as an upper bound for fleets whose agents process different inputs, and is quoted in latent units conditional on the Gaussian copula, extrapolated at high error rates. One proprietary model is a robustness point, not a sample of hosted models.
