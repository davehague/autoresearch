The transferable object gets more abstract as the distance grows

This map has two results about what an evolved harness carries with it, and they disagree about where the boundary sits because they were measuring different distances. the-portable-part-of-a-harness-stops-at-the-ecosystem-margin measured language distance and found 20–40% of each harness ecosystem-bound, with the failure mechanism being a discipline that was a free consequence of one environment's execution chain and is not a free consequence of another's. harness-optimization-separates-models-more-than-scaffolds measured the optimizer and found the model term 1.8× the scaffold term. This measures model distance on a fixed task set, and it produces an ordering rather than a threshold.

Zero distance is the same model: +9.0 points. One generation inside the same family, with the profile frozen before any target-model outcome was observed: +10.4, and the transfer is larger than the original gain. A cheaper tier of the same family gets +8.7 and ends up above the reference score of the expensive tier — which is the operationally interesting cell, because it is the one where a harness investment substitutes for a model-tier purchase.

Cross the provider boundary and the same artifact is worse than nothing: 82.7% → 82.0%. Not attenuated, not flat — negative. The paper's own explanation is that because the runtime preserves substantial autonomy in the base agent, provider-specific behaviour stays consequential even with the task set and the control interface held fixed. That is no-harness-ordering-holds-across-models arriving inside a single artifact's transfer curve rather than across a grid, and it is why a "we ported our scaffold" claim needs its own arm.

What does survive is the layer above the practices: the generic runtime, the high-level runbook structure, the routing strategy, the failure-analysis loop, and the human-specified golden rules (prefer minimal reusable control; route from visible task semantics rather than task identity; separate development feedback from frozen evaluation). Starting from those, provider-specific re-derivation cost $37.02 and recovered +5.39 points over the DeepSeek baseline. So the practical shape is the method is portable and the artifact is not, and the artifact is cheap enough to rebuild that this is a mild tax rather than a blocker.

The reading for anyone maintaining a harness across models. Freeze-and-ship is safe for a version bump inside a vendor's family and is a live regression risk across vendors — which means a multi-provider fleet needs the profile treated as a per-provider artifact with its own held-out evaluation, not as a shared config. The corollary for reading published harness results is harsher: a transfer claim measured within one family is not evidence about transfer, and the field's harness papers overwhelmingly evaluate inside one family.

Bounds. One benchmark, one cross-provider pair, and the negative cell is a single 445-trial configuration with no interval. "Frozen" means zero target-model runbook changes and not zero evaluation cost. And the whole comparison inherits this source's standing limitation: the measured object is the runtime plus an evolved benchmark-adapted profile, and there is no compute-matched control anywhere in the paper — so it answers the generalization half of this map's 2026-07-18 objection for a sixth time and the budget half not at all.
