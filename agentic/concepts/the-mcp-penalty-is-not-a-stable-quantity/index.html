The 35× figure is one draw from a distribution with no centre

The received number is that MCP costs roughly an order of magnitude more than command-line tool use, most often cited as 35×. Three practitioner reports put it between about 3× and 35×; none is peer-reviewed, all come from the same community, and each used a different scaffolding on a different workload with conditions reported too loosely to reproduce.

The controlled version does not resolve. Restricting to the thirteen cells where one scaffolding ran one model in both arms and completed both, the paired ratios span 0.43× to 29.06×, median 0.93×. Nine of the thirteen sit between 0.61 and 1.30 — inside the 1.5× run-to-run spread the same study measured by repeating every locally-served configuration three times. Four lie outside it, and not in the same direction: two Codex pairs at 2.27 and 29.06 and one opencode pair at 1.79 where MCP cost more, one Claude Code pair at 0.43 where it cost less than half.

That shape is the finding. Outliers on both sides make the verdict inconclusive rather than null, and a bimodal distribution is precisely what produces the published disagreement — each report samples a few points and publishes one of them as the value. Anyone quoting a multiplier for MCP is quoting their own cell.

A mechanism candidate, offered as a hypothesis. The one MCP-capable scaffolding whose MCP arm was cheap sends 7 tool schemas per request (a gateway pair plus on-demand fetch of the other 42); the four expensive ones transmit the server's full 44-schema catalogue with every request, a 3.1× median difference on the same server exposing the same operations. The authors decline to claim it, because one scaffolding sits on the on-demand side and delivery method is confounded with everything else about it. If it holds, the cost belongs to eager catalogue delivery, a scaffolding choice, not to the protocol.

Rebutted: this pushes back on restrict-the-tool-surface-to-cut-cost-not-capability. That result — collapsing an agent to a single execute_code channel is tied on pass rate and cheaper in three of four cells — remains standing as an intervention result on two agents and two regimes. What does not survive is the generalization to "the tool surface is a spend lever" as a stable term: across seven scaffoldings, varying the interface is unresolvable against noise while varying the scaffolding carrying it is a factor of 28 (the-scaffolding-outspends-the-tool-interface). Both can be true — a within-scaffolding surface edit can pay while the between-scaffolding term dwarfs it — but this map should stop quoting interface-level cost multipliers as if they transferred.

One thing the arms do separate on, and it is not the frequency of failure. Both failed three of nineteen runs in the main matrix and 25 of 29 completed in the replication — yet 12.9% of the money spent on MCP runs bought no completed work against 2.2% on the CLI side, because the MCP failures landed on expensive cells. Set the smallest model aside and the parity dissolves entirely: one failure of fourteen on the CLI against three of fourteen on MCP, wasted-cost shares 0.3% against 18.7%. That split is post hoc, on six failures, and should be read to one significant figure.

Bounds. One task, one domain with a mature CLI client; a domain where MCP exposes an operation with no CLI equivalent would plausibly favour it. Hosted configurations are largely single-run. Modelled costs at one price list. The delivery-method mechanism rests on four completed runs of one scaffolding against twelve of four others.
