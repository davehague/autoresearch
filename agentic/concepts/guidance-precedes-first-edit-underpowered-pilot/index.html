The first attempt to instrument exactly when a coding agent's first file mutation happens, relative to when guidance arrives — underpowered by its own admission, but a real instrumentation gap this map's PAUSE finding left open

This map's PAUSE arrival (pause-steers-agents-before-first-edit) shows a single planning intervention timed right before an agent's first source-code edit beats both a rule-triggered advisor and, at a fraction of the cost, a periodic overseer. PAUSE's own design assumes the intervention point ("before the first edit") is a clean, identifiable event — but nothing in that line of work directly instruments the exact filesystem-mutation timestamp against the guidance-delivery timestamp. This source attempts exactly that: auditing five candidate harness events (policy assignment, request eligibility, trigger, plan delivery, observed source-content change) and hashing Python files before and after each action on local agents (Qwen2.5-Coder 14B) running public software issues.

The result, honestly scoped: of a 76-arm pilot, only 15 arms produced an observed Python source change across seven tasks and three repositories — short of the author's own prespecified 20-arm coverage target, so this is explicitly an underpowered study by its own design. Within that small sample, guidance preceded every observed first change — the timing assumption PAUSE's mechanism depends on held in every case measurable here — but every one of those changes went through a structured editor tool, so the result says nothing about shell-first writes that bypass that tool, and of the seven changed arms that passed the paper's own regression-selection check, four used incomplete regression lists, which weakens even that smaller claim further.

Why it's worth carrying on this map despite the weak power: it is this vault's first attempt at instrumenting the exact first-mutation moment rather than inferring timing from trajectory logs after the fact, which is the gap PAUSE's own evaluation left open. The author is explicit that the data do not show planning improves repair correctness and do not cover shell-first writes — this note should be read as a single-study, likely-underpowered first measurement of a timing assumption, not as independent confirmation of PAUSE's mechanism or its effect sizes.

Bounds: fell short of its own prespecified coverage target (15 of a planned 20 arms); single model, single author, seven tasks, three repositories; restricted to structured-editor-tool writes; the author states the timing claim is "testable only within the stated source scope."
