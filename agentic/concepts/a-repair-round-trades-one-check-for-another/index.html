The interior optimum again, on a loop with a deterministic verifier

repair-loops-have-an-interior-optimum is this map's sharpest result and also its most fragile: a verify-repair loop damages correct work faster than it fixes broken work once both the verifier and the repairer are noisy, so true validity peaks around round two and collapses afterwards while verifier acceptance keeps rising. It was a stress-injected simulation with a learned process-reward verifier, and the obvious objection was that the whole effect lived in verifier noise — give the loop a deterministic checker and there is nothing to be fooled by.

This is that experiment, in production shape. The verifier is Checkov: a static rule engine, no model, no noise, thirty CIS check IDs that either fire or do not. The loop still degrades. At least one security regression in 13.8% of scenarios (3.3% under the strict definition the authors defend), the raw pass rate peaking at iteration 4 and falling at 5, and the recommendation to stop at iteration 3. So the interior optimum is not an artifact of verifier noise. It survives when the only noisy component is the repairer, and the mechanism is visible: the model is shown one failing rule, edits the resource, and the edit takes a different rule with it.

The texture is more useful than the rate.

  • It is not transient. Only 36.6% of regressions self-correct — mean 1.2 iterations later — so nearly two thirds are still broken when the loop stops. And 28.5% of scenarios oscillate, a check going pass → fail → pass, concentrated in IAM rules. Oscillation is the signature this map has been missing: it means the loop is not converging on anything, it is cycling between two configurations that each satisfy a different subset. fix-the-loop-not-the-artifact is the right response and this is what it looks like when nobody does.
  • It concentrates where the rules interact. Access control dominates the loose count (38.5%), with three IAM checks alone accounting for 886 events, a third of all regressions — permissions being the place where fixing one thing genuinely changes another. Under the strict definition the ordering shifts to networking and encryption, which is a reminder that even the location of the damage is partly a measurement choice.
  • It is early. Peak per-transition rates at 1→2 and 2→3, not at the end. Whatever budget you set, most of the damage is already done by round three — the same window the-correction-window-is-the-first-third-of-the-trajectory identified for steering.
  • It is cheap to detect. Regression transitions carry 2.6× the churn (140.1 vs 53.8 lines changed, d = 0.90) and far higher check volatility (11.55 vs 2.38, d = 1.49). Both are computable from the diff without rerunning the scanner, which makes this an operational gate rather than an observation: a repair round that touches 2–3× the usual number of lines is the round to hold for review. That composes directly with patch-churn-predicts-quality-degradation, which found the same signal on agent-authored patches from an entirely different corpus, and with stop-on-the-sign-of-the-marginal-gain, which had the stopping rule but no cheap per-round predictor to trigger it.

The counterweight is that a full 4× of the headline is definitional — 13.8% loose, 3.3% strict — and the apparent 17.3× model difference evaporates entirely under the strict rule. That half of the paper is carried at cumulative-best-hides-the-iteration-where-it-got-worse; read alongside it, the honest summary is "repair rounds do break passing checks, at single-digit percentages, and everything above single digits was the ruler."

Bounds. Terraform and Checkov only; other IaC languages and other scanners may distribute this differently, and Checkov is a proxy for security rather than security. AWS-only scenarios from a December 2024 corpus, two models both a generation behind the frontier, one run per configuration so no variance estimate, 13% of cells missing to API errors. Root-cause classification was automated with hand-set thresholds and never validated against human labels, so the why behind these transitions is the weakest part of the paper. And the loop here has no memory of prior rounds' failures beyond the current scan output — a loop that carried the full regression history might not oscillate, and nothing here tests that.
