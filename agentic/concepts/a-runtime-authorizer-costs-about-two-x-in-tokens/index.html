Governance is a token line item, and the rejection is the expensive part

This map prices allocation decisions: which model acts (route-after-scouting-the-repository-not-from-the-issue-text), how many iterations it gets, what a compression step costs against the tokens it saves (an-api-compressor-competes-with-the-tokens-it-saves), and most recently what a mid-run model switch costs (escalating-mid-run-can-cost-more-than-starting-over). Every one of those prices something the agent does. Nobody has priced the thing sitting between the agent and its tools, and safety papers in this area almost never report a cost column at all.

The number is roughly 2×: total input tokens 1.91× the undefended agent on the standard benchmark and 2.21× on the dynamic one. That is a defensible price for taking attack success from ~16% and ~31% to under 0.63%, and the authors position it as a non-dominated operating point on (cost, utility, risk) rather than as the cheapest defense — but the decomposition is the finding, not the multiplier.

Half the cost is not the guard. Agent-side input rises 13.54K → 17.01K and 19.74K → 25.75K, with call counts rising 4.25 → 4.87 and 5.55 → 6.55. That increase is not the authorizer thinking; it is the agent replanning after a rejection. A control layer that refuses a call returns control to the model, which then pays full price to find another route to the same goal. So the cost of a gate is not its own inference budget — it is its inference budget plus the rework its refusals generate, and the rework is charged at the working model's rate rather than the guard's.

That is the same structural point as the handoff tax, one layer down. escalating-mid-run-can-cost-more-than-starting-over found the receiver pays to read a trajectory it did not write; here the agent pays to re-derive a path it already had. Both are transition costs the products that ship these mechanisms do not display, and both are invisible in the metric everyone reports.

And the multiplier tracks exactly the property that motivates the control. Both the guard-side and agent-side costs are higher on the dynamic benchmark, because more dynamic objects and environmental feedback mean more execution context needed for each authorization decision and a harder replanning problem after each rejection. The tasks that most need a runtime authorizer — long, open-ended, heavily dependent on what tools return — are the tasks where it costs the most. Any capacity model that assumes governance overhead is a flat percentage will underestimate it on precisely the workloads it is bought for.

The operator reading. If a defense's refusal rate is a tunable, it is also a spend dial, and it is not monotone with safety: the same paper's ablation shows removing the argument-level veto raises both utility measures while raising attack success, and removing the positive evidence store lowers attack success while costing 10–13 points of utility and, by implication, more replanning. Tuning a gate on a security metric alone will move the token bill in a direction nobody is watching.

Bounds. Token counts on attack tasks with one backbone (GPT-4o-mini), two benchmarks, averaged. Latency is not reported at all — deliberately, since it is dominated by network conditions, model scheduling and deployment configuration — so wall-clock cost, which is what an operator often actually feels, is unmeasured here. Output tokens and cached-prefix effects are not broken out in a way that would let anyone convert this to dollars at current prices, and the multiplier is over input tokens rather than billed cost. One authorizer design; the decomposition into guard cost plus replanning cost should generalize to any refusing control layer, but the split between the two halves will not.
