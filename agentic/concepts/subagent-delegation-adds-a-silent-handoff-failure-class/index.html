The quality number nobody had published, and it goes the other way

This vault carried the delegated-search design on efficiency evidence with the quality axis explicitly missing. The vendor result behind delegate-search-to-a-specialist-loop reported time and cost to two decimals and asserted "comparable result quality" with no number attached — a gap that note named as its load-bearing weakness, and that retrieval-benchmarks-omit-the-quality-axis generalized. This is that number, measured on 720 questions × four models with a human-validated judge, and it does not come out comparable.

Pooled Pass 65.2% for a flat ReAct agent over a pre-built vector index against 46.2% for the hierarchical delegating agent, with the delegating design also producing more outright Fails for every model. The effect is consistent in direction across all four models and survives FDR correction in every case, though it is honestly heterogeneous in size: modest for the Gemini 2.5 pair (Cliff's δ ≈ 0.14), moderate for Qwen3-235B (0.235), and large only for Gemini 3 Flash (0.760). Because Pass is a fixed cutoff, the authors sweep it from 50 to 90; the magnitude moves a lot and the ordering never does — the smallest gap anywhere on the grid is 3.8 pp. Semantic led on 14 of 15 repositories, on all five quality dimensions, and on all four question types. The margin narrows with repository size (ρ = −0.69, p = 0.004) but does not cross even at ~861 KLoC, and the authors are careful to call that a narrowing rather than a crossover they have located.

The failure taxonomy is why this belongs in this map rather than only in a scoreboard. Coding every failed run on two orthogonal axes — mechanism (what behaviour caused it) and symptom (what was wrong with the answer) — shows delegation did not redistribute existing failures. It created a class: coordination breakdown at the planner↔subagent handoff, 41.8% of the delegating architecture's failures and 0% of the flat one's, since a flat retrieval agent has no handoff to break. The association is not merely definitional — restricting to the five mechanisms available to both architectures still leaves χ² = 147.2, V = 0.35. Meanwhile symptom is only weakly associated with architecture (V = 0.16): the two designs produce wrong answers of similar shape by different mechanisms, which is exactly the condition under which an outcome metric cannot tell you which architecture you are debugging.

And the new class fails silently. The mechanism→symptom mapping is near-deterministic for several codes: a non-terminating loop flows almost entirely to no answer (mean judge score 3.3), an evidence-gathering failure to a visibly incomplete one (18.8), but coordination breakdown fans mostly to a confident answer about the wrong entity, scoring near thirty alongside the other content mechanisms. It is loud in the trace and quiet in the output. That is the same shape as the-agents-final-report-is-its-least-reliable-artifact and verify-a-handoffs-claims-before-the-next-agent-reads-them, now with a measured share attached: the condensed result a subagent returns is a claim the planner adopts without evidence, and one in six of the delegating architecture's total runs ends in a fluent wrong answer traceable to that adoption.

The cost side removes the usual consolation. Delegation is 7.0% of the delegating agent's tool calls but opens the subagent trajectories in which 68.8% of all its tool calls are made — the isolation is real, and so is its bill. Input tokens run ~34K per question against ~761K for the widest model pair, and a correct answer costs $0.32 against $0.74, so the delegating design sits off the accuracy-cost frontier entirely rather than trading one for the other.

What this does and does not overturn. Context rot is real and this study does not deny it; the design addresses a genuine problem. What it shows is that the protection is not free, and on read-only questions over a repository that can be indexed, retrieval was both stronger and cheaper. The boundary is stated by the authors and worth keeping attached: this is question answering, not code modification; the index exists because the corpus is indexable; and both harnesses are LangChain defaults rather than the tuned commercial implementations (Claude Code, Codex, Antigravity) whose adoption motivates the study. So the result indicts the paradigm as a practitioner first runs it, and leaves open whether a vendor's tuned handoff contract closes the 41.8%.

Judge validity is unusually well established for a study of this kind — three blind professional engineers on 800 answers, panel Fleiss' κ 0.81, human-majority-versus-judge Cohen's κ 0.74 and Pearson r 0.83, with agreement slightly lower on the longer delegating answers, a bias that would favour them on a length-preferring judge (llm-judges-have-exploitable-biases).

Bounds. One benchmark, one language, 15 repositories, four models; the effect is driven disproportionately by one model while the other three are small, consistent and significant. One fixed retrieval configuration. Failure coding is LLM-performed with a validated human subsample. Costs use one price sheet at one time, with token counts reported alongside.
