The tax shows up with one subagent, on a task with no state to write

This map's refined hypothesis is that the coordination tax is not shared-versus-private context but raw, unvalidated state routed through a serializing controller — unit size × validation × routing (verified-shared-state-beats-orchestrator-routing, event-passing-beats-shared-context-in-agent-fleets). The evidence for it has come from agent fleets on SWE-shaped tasks with contamination caveats and no measured noise floor (coordination-deltas-need-a-measured-noise-floor). This is the same tax measured at the smallest possible scale — one planner, one subagent — on a task class where the confounds mostly do not apply: read-only question answering, nothing written, no patch to contaminate, the same model on both sides of the comparison, paired within model.

It still shows up. 65.2% against 46.2% Pass, consistent in direction across four models, significant in all four after correction, at 2.3× the cost per correct answer. And the mechanism matches the map's hypothesis component for component. The subagent works in an isolated window and returns a condensed result — a summary, not evidence. The planner adopts it without validation. That is precisely "raw, unvalidated state routed through a serializing controller," and the failure coding finds it is where the architecture breaks: 41.8% of its failures are coordination breakdowns at the handoff, a class the flat architecture cannot have.

Which sharpens the map's own prescription rather than contradicting it. The two positive fleet results this map carries both won by not doing this — one passing events instead of pooling raw state, the other sharing verified ~100-token gists whose admission-time verification is worth 4.9 points in ablation. The missing ingredient in the delegating design measured here is the same one: nothing checks the subagent's memo before the planner acts on it (verify-a-handoffs-claims-before-the-next-agent-reads-them, gate-the-edit-on-evidence-observed-not-claimed). The design that fails is not "delegation"; it is delegation without admission control.

Two secondary observations worth carrying. Delegation is only 7.0% of the delegating agent's tool calls but opens the trajectories in which 68.8% of them run — so a small number of routing decisions determines where almost all the work happens, which is what makes an unvalidated handoff so leveraged. And in both architectures, longer trajectories associate with lower pass rates, consistent with this map's standing interior-optimum finding (repair-loops-have-an-interior-optimum, failed-recoveries-burn-compute-not-terminate) — more steps is not more thoroughness.

What this does not settle. It is one task class (read-only QA over an indexable repository), so it says nothing about coordination on write-heavy work where the alternative to delegation is a single context carrying every file. It uses framework-default harnesses rather than the commercial implementations that popularized the pattern, so a tuned handoff contract is untested. And this map's own standing demand applies to it as much as to any coordination claim: no noise floor was measured (a-coordination-arm-needs-an-always-serial-reference) — though the paired within-model design, 720 questions per condition, threshold sweep and FDR correction put it well above the single-run deltas that demand usually targets, and the flat arm is the always-serial reference.

Bounds. One benchmark, one language, 15 repositories, four models; the effect is large in one model and small though consistent in the other three. Judge validated against three blind professional engineers (panel Fleiss' κ 0.81, human-vs-judge κ 0.74, r 0.83). Costs from one price sheet at one time.
