The filesystem is the durable state

This map's headline claim — make the externalized run state, not the process, the durable unit — is now attested by four orgs at four layers: an infrastructure event log (durable-session-logs-enable-crash-recovery), repo artifacts plus git (initialize-once-then-iterate-incrementally), tracker state (make-the-issue-tracker-the-control-plane), and a workflow engine (durable-workflow-engine-runs-the-agent-loop, reliability ~90% → ~99%). A fifth layer arrives here, and it is the one that costs nothing: the work queue is computed from disk state, and "done" is defined as the output file existing.

Notice what that buys. The queue is not a durable data structure that has to survive a crash — it is a derivation recomputed from the filesystem whenever the orchestrator restarts, so there is no state to lose and no reconciliation step. Every other attested layer engineers durability; this one arranges for the question not to arise. On a 1M-LOC migration run by hundreds of agents that is the difference between a recovery procedure and no recovery procedure.

The one thing it does need is a serialization point for the mechanical operation: a build daemon batches patches and rebuilds so parallel workers cannot race. That is the correct division and it matches fix-the-loop-not-the-artifact — serialize the compile, never the knowledge.

Where it fits against the map's 2026-07-19 boundary is worth stating, because the boundary applies here too. durable-execution-engines-do-not-supply-barrier-semantics split the guarantee in two: surviving a crash and being unable to act while suspended are separate properties. A disk-derived queue is at the easy end of the first and supplies nothing at all of the second — there is no pause primitive in "the file exists," and a worker mid-write is exactly the state the definition of done cannot see. So this is a cheap answer to resumability, not to boundedness, and the map's open question about how the layers compose now has a fifth entry whose approval boundary has never been probed.

Caveats: T2 practice narrative, no control arm, and the task class supplies the property. A migration is unusually amenable to file-existence completion because each unit of work has exactly one output artifact and a compiler to check it. Ordinary feature work does not decompose that way, and "the file exists" is a weaker completion predicate the moment the output is a change rather than a creation — the same gap treat-agent-output-as-a-claim-not-lifecycle-state closes with hash-bound evidence.
