The gate held and the note is still wrong

This map's practice has converged on moving enforcement below the prompt (enforce-high-risk-constraints-below-the-prompt-layer), gating irreversible actions on independent confirmation (gate-irreversible-actions-on-independent-confirmation), and accepting that a permission prompt fails open under fatigue (permission-prompts-fail-open-under-fatigue). Every one of those is a control at the action boundary, and this result says they work — soft authorization checking cuts forbidden action from 85.2% to 1.6%, and hard authorization, external permission lookup and human approval all reach zero.

Then it says something the map has not accounted for. Read the same table across the columns the gate does not touch: artifact preservation stays at 4.7% and complete-field representation at 10.9% under every one of those controls, to the decimal. The gate stopped this action. The handoff note that lost the constraint is unchanged, still sitting in the workflow, still the thing the next consumer reads. Containment is an endpoint property with an endpoint lifetime; preservation is a state property that persists.

Why this matters here rather than only in the context map. The vault already holds that an action-local gate cannot reach an ordered requirement (an-action-local-gate-cannot-reach-an-ordered-requirement) — a gate that fires on a proposed mutation has nothing to intercept in the procedural steps that precede it. This is the adjacent failure and arguably the more common one: the gate can reach the action, fires correctly, and still leaves the governing state degraded upstream of every future decision. The two together bound what an action gate can be asked to do. It is the last line, not the record.

The repair result is unusually clean and unusually honest about what it does not show. Restoring all four fields — stop status, unresolved prerequisite, responsible authority, admissible fallback — takes preservation to 100% and forbidden action to 0%, from a base of 4.7% and 85.2%. But every single-field-omission arm fails preservation outright, and the endpoint effects split in a way the authors refuse to over-read: omitting the explicit stop label collapses executor blocker recognition to 40.6% and lets 7.0% forbidden action back in, while omitting prerequisite, owner or fallback produces zero forbidden action in this executor setting. Label-only repair drives forbidden action to zero while leaving 73.4% deactivation; prerequisite-only repair leaves 73.4% forbidden action. So the all-field effect is identified and the relative necessity ranking among fields is not — which is exactly the thing an implementer would want and should not take from this paper.

The design consequence is a two-layer one, and it maps onto a separation this map already respects between the write and the read (a-persistent-update-must-be-revocable): repair the artifact so the state keeps governing across interfaces, and gate the commit so residual degradation cannot fire. Neither substitutes for the other, and a system that has only the gate will pass its own tests while its coordination surface quietly stops binding.

Bounds. Synthetic enterprise tasks with pre-identified safety blockers, artifact-only executors under a default-allow policy — a default-deny executor would move the endpoint numbers substantially and the paper does not test one. The four-field representation is this blocker class's operationalization. Production prevalence is a separate estimand.
