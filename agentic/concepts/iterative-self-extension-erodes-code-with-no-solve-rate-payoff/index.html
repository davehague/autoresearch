A better first prompt buys a better intercept, not a better slope — and this map's long-horizon-state strand just gained the second source it was missing

This map's sub-thread declaration has been holding "long-horizon loop state discipline" as a standing third-strand candidate, short a second separating source (loop-engineering declaration, reviewed 2026-08-26 @ 54 bullets: "the standing third candidate is long-horizon loop state discipline, still short a second separating source"). SlopCodeBench measures the same underlying phenomenon this map's within-agent-repair-loop strand already tracks — quality decaying as an agent iterates on its own output over a long horizon — but at a different artifact layer: not skill-pool or harness-configuration decay (an-unguarded-skill-pool-peaks-then-degrades, on harness-self-evolution), but the code itself, decaying as the same agent repeatedly extends the same codebase across an evolving spec.

The mechanism is structural, not a training or prompting gap. Erosion (complexity concentrating into fewer, harder-to-touch functions) and verbosity (redundant/duplicated code) both climb across checkpoints on the large majority of trajectories, while the same metrics measured on 48 actively-maintained human repositories stay flat — including a temporal control specifically ruling out "the human baseline is itself LLM-contaminated" (pre/post-ChatGPT-era commits differ by only 0.014 median verbosity). That flat human comparison line is what turns "agents produce messier code over time" from an anecdote into a measured divergence from an achievable baseline.

The prompt-intervention result is the one worth generalizing. Telling the agent up front to plan first and avoid "slop" improves checkpoint-one quality by a real margin (34.5% less verbose) but "the degradation lines for Anti-Slop track the baseline slope almost exactly" — the fix moves the starting point, not the trend. That's a sharper and more useful claim than "prompting helps a little": it says a class of fix that only touches the first turn of a long-horizon loop cannot be expected to arrest degradation that accumulates during the loop, no matter how much it improves the first turn. Anything in this map's within-agent-repair-loop strand that relies on a one-time system-prompt improvement inherits this ceiling.

No agent, across 11 models and one fixed harness per model, solves any of the 20 problems end-to-end — a stronger null than most benchmarks in this vault report, and worth reading alongside harness-as-score-confound's standing caution: each model ran behind exactly one predetermined harness/scaffold, so harness choice and model capability are not separated here, and a different scaffold could shift both the solve rates and the erosion slopes.

Bounds. Python track only (cost-constrained, despite a language-agnostic design). The 20-problem set is authored by the paper's own team rather than mined from real repository history, so problem selection could favor tasks that happen to induce erosion. One harness configuration per model, so this cannot separate "the model degrades" from "this particular scaffold degrades." Code, data and a public leaderboard released at scbench.ai.
