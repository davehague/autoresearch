The authority boundary is not "code versus infrastructure" — it is "can this be ramped back"

This map's standing question is what an unattended fleet needs when nobody is watching, and its accumulated answer has three facets: durable externalized state, an operator surface, and credential and identity governance. This arrival is a production instance of all three at once, and its contribution is a cleaner statement of the authority boundary than the vault has had.

The naive reading of "the agent may touch infrastructure but not code" is wrong, and the actual split is more useful. The agent acts alone where the action is ramped, observable and undoable: feature flags and canary traffic (with a verification step before a flag moves), draining and cordoning cluster nodes, scaling instructions during a demand surge. It proposes where the action is not: code fixes leave as pull requests a human reviews and merges, and it never deploys directly. Note what that puts on each side. Cordoning a node is a production infrastructure change with immediate blast radius — and it is reversible in seconds, so the agent does it. A merged patch is small, and it is not, so the agent does not. That is keep-the-agent-interruptible-and-reversible used as an authorization rule rather than as a design goal, and it is the sharpest version of the principle this vault has recorded.

The corollary a fleet operator should take: the way to widen an unattended agent's authority is not to trust it more, it is to make more of your actions ramped. Most deployments here sit behind feature flags precisely so that the interesting resolution action is a dial rather than a switch.

The rest of the shape is this map's checklist, instantiated. Identity is a service account with scoped tool access via connectors, which is keep-credentials-outside-the-agent-sandbox and the treat-internal-agents-as-principals argument in production form. The operator surface is the on-call Slack channel, which doubles as the agent's memory — meaning the conversation is the durable state, with the versioned skills in GitHub as the standing-instruction layer beside it. And verification closes the loop through the same connectors used to investigate: the agent confirms the fix landed rather than reporting that it applied one, which is treat-agent-output-as-a-claim-not-lifecycle-state and ground-completion-in-a-rerun-not-a-self-report holding at the incident level.

The limits the vendor states are more informative than the capabilities. The agent does not always get the initial analysis right, and the described mode is not autonomy but "multi-player mode" — either party can steer the investigation or propose a hypothesis mid-incident. Report formatting is called out as team-specific taste, "human communication, not plumbing", which is an admission that the operator surface does not generalize the way the investigation logic does: the fan-out over dependencies transfers, the way you write it up for your team does not. And resolution capabilities vary by team, which means the authority boundary above is one org's calibration and not a portable setting.
