The mandate executes because it is program structure, not because it was stated forcefully

This vault has spent a month narrowing what text can make an agent do. The rule grew clause by clause — persist the contract (persist-the-contract-not-the-conversation), deliver it (memory-delivery-not-storage), re-deliver it at the decision it governs (restate-the-checks-externally-at-completion) — and then hit a wall: re-delivery-governs-procedure-not-permission found verbatim delivery lifting procedural compliance to 76–100% and leaving prohibitions flat at 0%. This measures the same wall from inside the best case for text. The model opted into the procedure, the procedure states its rule emphatically ("skip any step is lying, not verifying"), and compliance is 56%.

So the prose ceiling is not a delivery failure and does not close by writing the instruction harder. The paper's diagnosis is that a skill is described to the runtime and never encoded in it, so the model reconstructs the control flow on every run — and the steps it drops are the mechanical ones (fetch the state, run the check, commit the file: steps whose execution is a function of their inputs), while the steps that survive are the open-ended ones where the model was asked to write something and did.

The remedy is to make the determined half unskippable by making it structure. A mandatory rule becomes an ability bound to node entry, so the walker cannot pass the node without executing it and the model is never consulted; evidence objects are populated by code, so a success flag is computed rather than claimed and cannot be asserted; a forbidden action becomes an absent path, because a model cannot route to a node that does not exist — which is what "hand prohibitions to a deterministic guard" (enforce-high-risk-constraints-below-the-prompt-layer) looks like when the guard is the program's own shape. What decides the split is one question, the Owner test: is this step's output a function of its inputs? It deliberately does not ask whether a model could perform the step — a model can perform almost any step — but whether the inputs determine the result, since model-owned nodes are the only places a run can deviate.

Two things keep this from being a slogan about replacing agents with programs. First, the enforceable share is 37% and varies 32–44% by family: it is a property of the skill, not of the compiler, and the honest report is a coverage number rather than a guarantee. Second, the declared limit is cohesion — a rule describing an adaptive tool-using activity ("explore until you find the module," "iterate until the test passes") must stay one unit, because decomposing it into a fixed call sequence destroys the observe-and-adapt loop that made it work. Over-constraining judgment is stated as being as damaging as under-constraining mechanism, which is the same boundary declarative-structure-outperforms-the-model-it-replaces and move-task-difficulty-from-the-model-to-the-harness have been circling without a criterion. The Owner test is a criterion.

Cost inverts the usual objection. The harness is cheaper on 24 of 32 skills at 0.58× median, because a compiled harness does not re-read a long prose document at every step and each model-owned slot gets only the context its scope assigns. Where it is dearer the reason is instructive rather than damning: the expensive minority are precisely the adaptive-loop skills the harness runs faithfully and the prose agent truncated, so part of prose's apparent economy is the price of work it did not do.

Caveats. Mandate statuses come from a model judge — constrained to a four-way typed decision against a fixed reference procedure, with unreached mandates excluded, but a judge nonetheless, and this map holds harness-self-evolution-is-capped-by-its-proxy-judge against that pattern. Nine runs per skill per arm; 30 skills weighted toward document production, process and compliance, so 86% is not a portable constant. Artifact quality is deliberately not scored as a separate axis, so this says the procedure ran, not that the output was better. And there is no matched-cost comparison against the lighter-weight alternatives — runtime monitors, action guards, separately maintained rule languages — which the paper distinguishes on the ground that they can veto a wrong action but cannot cause a required one.
