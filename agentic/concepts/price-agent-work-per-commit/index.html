Dollars per commit is the denominator the ledger has been missing

Every cost figure this map carries is priced in a unit chosen by whoever ran the experiment: dollars per million processed tokens (prompt-caching-inverts-cloud-versus-local-economics), per solve (structural-index-beats-grep-at-lower-cost), per task (restrict-the-tool-surface-to-cut-cost-not-capability), per instance, or as a whole-project total (route-the-premium-model-to-the-governing-role). None of them is what an engineering organization budgets against, and each hides a different failure channel.

Per-commit folds the hidden channels in. A configuration that burns three abandoned trajectories before landing a change pays for four and commits one; a per-token comparison charges it for four and calls it thorough. This is the accounting failed-recoveries-burn-compute-not-terminate says you need and cheaper-inference-relocates-cost-into-repair-labor says is easy to get wrong — a cheap configuration whose fix-commit ratio rises from 45.9% to 74.9% is producing more commits, not more work, so per-commit is not automatically the honest unit either.

The unit only works if quality per commit is held. The published table ranks a routed configuration below both single-model configurations ($4.63 and $6.76 against $7.34 and $12.69) while reporting quality separately and qualitatively. That is the same gap this vault flagged in the same vendor's swarm economics post two days earlier: equal-terminal-quality is doing heavy lifting in a price comparison where nobody read the output (resolve-rate-gains-do-not-carry-quality-gains). Per-commit cost with per-commit quality is the pair; either alone is a half-ledger.

Carried as a measurement convention worth adopting, not as a validated magnitude. T2 vendor disclosure; one deployment; commit quality unmeasured; the denominator's definition (what counts as a commit, over what window) is not published.
