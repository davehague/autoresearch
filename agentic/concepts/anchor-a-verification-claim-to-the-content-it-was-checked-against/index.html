What is missing announces itself; what is stale does not

This map's rule has grown one clause at a time — persist the contract, deliver it, re-deliver it at the decision it governs, price the resident half, and re-derive state from its source rather than carrying your reading of it (re-derive-file-state-instead-of-storing-snapshots). The re-derive clause was established on files an agent reads, where the source is on disk and costs no model call. This extends it to the thing an agent produces rather than consumes: a verification result. A note saying "checked behaviour 41 against the reference" survives an upstream change perfectly. Every import still resolves, the project still compiles, and one entry in a lookup table now holds a different value, so the claim is false and nothing in the workspace says so.

The granularity is the mechanism, not an implementation detail. In the seven test worlds, marking every behaviour that imports from a changed file flags 81–91 of 96 when the artifact-level truth is 14–18 — about 5.1× over-invalidation, which is a review queue nobody will work. The fix is identity at the level the behaviour actually reads: a canonicalized (store, path, subpath) triple, so two constants in one module are two artifacts. Alias resolution belongs in the identity function rather than in a helper, because a consumer name that re-exports a definition gives one artifact two identities and a leaf change becomes invisible to a claim anchored on the alias. The testbed reports that indirection was the most frequently reported source of difficulty.

The result is bounded to judgment and the authors bound it themselves. On the smaller model the effect is unambiguous — ANCHOR beats both controls in all seven worlds, at the floor p the design can reach. On the stronger model ANCHOR is perfect and the controls reach the ceiling often enough that the preregistered contrasts cannot resolve; the authors report this as failure to support rather than as evidence of no effect, and print the attainable minimum p at the surviving n. What the session artifacts show is a mechanism worth naming: the Sonnet controls reconstructed the artifact baseline inside the session — parsing the reference, resolving aliases, diffing against the port's own data — and the Haiku controls attempted the same route and mostly failed to complete it without a result-compromising error. So the exploratory reading is that anchored memory externalizes an in-session re-derivation, which is the same trade re-derive-file-state-instead-of-storing-snapshots makes when it puts the re-read in the harness.

Classification is not repair, and the study is careful about it. ANCHOR·Haiku's median repair rate is 10.0% while every Sonnet condition repairs most repairable vectors. One ANCHOR session classified all 17 drifted behaviours perfectly and then destroyed the port, taking its acceptance score from 520 to 0 of 576. A record of what is no longer provable identifies potential damage; it does not stop an agent causing more.

Bounds. Generated worlds rather than a real repository — deliberately, to get behaviour-to-artifact ground truth, close the version-history oracle (19 of 24 sessions in an early round simply diffed the previous commit), and defeat recall — but the authors state re-derivation is unusually tractable there: literal data recoverable by static parsing, pure aliases, a reference that fits in one session. One observation per cell, so world difficulty and model nondeterminism are confounded. One model family, two tiers, one round each, with the Sonnet identifier undated and therefore not snapshot-reproducible. Stale compiled bytecode leaked an older reference state in all retained workspaces — two control sessions used it and scored exactly as that state predicts, so the leak depresses control scores and weakens the Sonnet null further. Cost was not measured at all: transcript persistence failed, so the lookup-versus-reconstruction account is a mechanism hypothesis with no efficiency claim behind it.
