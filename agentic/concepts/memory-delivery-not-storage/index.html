Memory is a delivery problem, not a storage problem

The vault's memory thread has been arguing about what to persist. Generic memory scaffolds degraded all ten models tested on long horizons; an external tracker of the specification recovered 90% of a faithfulness gap; persisting the contract and discarding session reasoning reached 96% completion against 71% for full history (persist-the-contract-not-the-conversation). Every one of those results varies the content. This varies the delivery and holds content fixed — and finds that the right content, sitting in a connected store the agent knows about, contributes nothing at all. Zero calls in 114 turns is not low adoption; it is the mechanism not firing.

The framing that makes this actionable is content plane versus control plane. A content-plane memory system adds material to the context — files, instructions, protocols — and then depends on model compliance to convert that material into memory. A control-plane system participates in constructing the context: it decides deterministically what enters the window and when. Everything the vault has measured about agent-facing documentation is a content-plane intervention scored on its compliance rate, which is why the numbers keep coming back small — AGENTS.md files that lose 0.5–2 points at +20–23% cost, repository context files hitting 8.3% compliance on a cross-cutting requirement (instructions-fail-to-govern-non-functional-requirements). The compliance rate is the failure.

Two design consequences follow, and the second is the one people get wrong. First, delivery must be evaluated by the harness, not chosen by the model — the trigger conditions here (path, symbol, semantic, event, temporal) are checked deterministically with an audit log, which is why the false-alarm count is zero and auditable rather than merely low. That is the same principle as patch-minimization-is-search-not-generation: where a well-defined mechanical operation exists, removing the model from the path is the reliability win. Second, injection does not replace the agent's initiative, it creates it: the only voluntary memory operations observed anywhere in the corpus happened after and because of a delivery. Giving an agent memory tools and expecting it to build the habit is backwards.

The claim's boundary is capture. This measures retrieval and delivery; every note in every arm was seeded by the operator, and the paper names automatic capture as its unevaluated half. So the supported instruction is narrower than "solve agent memory" — it is stop scoring your memory system on what it stores, and start scoring it on what arrives.

Caveats: single author, who also wrote the implementation under test; n = 1–3 per arm across 12 graded runs; one corpus, one task family, one agent product; the value table prices the tool platform rather than memory delivery, and the paper marks it so. Two of five trigger types never fired in a graded run. Direction, not magnitude.
