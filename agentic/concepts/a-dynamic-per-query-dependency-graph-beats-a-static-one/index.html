The graph doesn't need to exist before the question does

This map already carries the claim that retriever structure is a lever — a static structural index (embeddings + a graph of definitions/call edges + lexical) beats grep-style retrieval at lower cost (structural-index-beats-grep-at-lower-cost). DyRetriever tests the next question that claim leaves open: does the graph need to be built once, in full, ahead of time? Here it doesn't. An LLM starts from candidate entry points and traces outward per query (select a candidate, visit it, expand its dependencies from its own source and imports), capped at ten hops, with a existence-verification pass that discards any named function the post-processor can't find in the repository — the paper's answer to expand-step hallucination. The resulting partial, per-query graph beats retrieval over a fully materialized static graph (RepoScope) on Pass@1 by double digits on both benchmarks, and does so in a fraction of the wall-clock time, because it never pays to index the whole repository up front.

The ablation is the most useful part for calibrating where the value actually comes from. Losing the dynamic-graph mechanism entirely (falling back to a weaker retrieval source) costs far more than losing the multi-hop reasoning step (single-hop only) — -16.0%/-51.1% versus -6.0%/-9.6% relative Pass@1. So the load-bearing design choice is query-conditioned graph construction itself, not the depth of the walk once you're doing it that way; a shallow dynamic trace already captures most of the value a deep one adds. This reframes the static-vs-dynamic question this map hasn't directly asked before: structural-index-beats-grep-at-lower-cost shows a pre-built graph beats no graph; DyRetriever shows a per-query graph beats a pre-built one — on Pass@1, and while being far cheaper to build (10.2× faster indexing, because there's no repository-wide index to build), though the per-query LLM tracing itself costs 1.95–2.43× more tokens than a lighter static-retrieval pass. Net: you trade upfront indexing cost for marginal per-query cost, and on these two benchmarks that trade wins on quality too, not just economics.

Generalizability arm: swapping the traced context into other retrieval backbones (BM25, RLCoder, AlignCoder) improves each of them, so the dynamic trace behaves like reusable evidence rather than a retriever-specific artifact — closer in kind to re-derive-file-state-instead-of-storing-snapshots than to a competing end-to-end system.
