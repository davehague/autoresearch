The repair loop has an interior optimum, and acceptance hides the far side of it

This map has treated the loop as a coordination problem between agents — topology, substrate, unit size, validation, routing. This is the within-agent iteration loop, and it arrives at the map's own lesson from a new direction: what a loop is worth is set by validation quality, not by iteration count. The map already prices the unvalidated case for coordination — independent agents amplify errors 17.2× while a validating orchestrator holds 4.4×. Here the analogous quantity is the verifier's discrimination, and below a threshold the loop is not merely useless but actively destructive, ending far below the no-repair baseline in six settings of eight.

Two details make this more than a stress-test artifact. First, the mechanism is path dependence: an independent-resampling control at the same token budget shows no comparable decline, so the damage comes from repeatedly rewriting the same candidate, not from sampling variance. Second, the raw label statistics are independent of any stopping rule — 55% of correct plans get repaired into incorrect ones, and 24% of those damaging repairs win majority acceptance. That is the failure the loop cannot see from inside: acceptance rises while validity falls, which is why round budgets calibrated on "the verifier is happier now" run past the optimum by construction.

It lands directly against the vault's most recent loop finding, and the tension is productive rather than contradictory. review-revise-loop-lifts-resolve-most-on-weak-generators found the same generate-review-revise structure lifting a weak generator 27.5% → 56.9%, with the revise step as the active ingredient. The reconciling variable is verifier quality relative to generator quality: SWE-Review's reviewer is scored against executable tests in the generator's own domain; these stress settings pair 3–8B open models with deliberately degraded verifiers. Both agree the loop is not self-justifying. The synthesis to carry: measure the verifier's discrimination before granting the loop a budget, and if you cannot measure it, stop early — the asymmetry is severe.

Caveats, and they are load-bearing. The headline is a deliberately adversarial setting (prompt mismatch injected mid-loop) on GSM8K with Qwen2.5-3B; generators and verifiers are 3–8B open-weight models, not frontier agents with executable oracles, and the damage magnitudes should not be carried across. The favourable setting behaves as optimists expect (fixed repair 0.875 beats calibrated stopping's 0.845), which the authors print themselves. Code generation and tool use appear only in the robustness table, and the tool-use cell stays flat under a near-inert repair operator — so the SWE-shaped evidence is the thinnest part.

Rebutted by: stop-when-two-audits-against-a-frozen-referent-come-back-empty — a seventeen-round repair loop that showed no degradation and terminated on two consecutive empty passes, which locates the interior optimum in self-referential verification rather than in iteration count: there the verifier compared against a document frozen before the artifact existed, so verifier noise could not drift toward the artifact. The scope condition it proposes is that this result holds where the checker judges the candidate on its own merits, and may not where a stationary external referent supplies the fixed point. It is n = 1, self-reported and uncontrolled, so read it as a testable boundary rather than a correction.
