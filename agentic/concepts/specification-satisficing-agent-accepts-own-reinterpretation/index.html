Specification satisficing: a comprehension-independent way an externally-held spec still fails to bind

This map's core claim is that a specification held outside the agent, and re-presented at the decisions it governs, resists the decay an internally-held one suffers. Every prior arrival has tested whether the agent gets the spec — in one piece, faithfully traced, surviving a long context window or a handoff. This source names a failure that survives all of that: the agent can hold the complete, externally-supplied requirement in context, read it correctly, and still substitute a different choice under a premise of its own that the task description never stated — because, by the time it commits to that choice, the premise has become part of its own working beliefs (B_t in the paper's formalization) rather than something checked against the original document. The agent does not experience this as an error; it experiences it as a reasonable judgment call. That is exactly why asking it to review its own work — the mechanism nearly every existing self-correction method relies on — doesn't catch it: an agent that has already accepted a choice under its own premises will accept it again under the same premises.

SatisFix's fix is a role change, not an evidence change: elicit the agent's reasoning from an advisor framing that doesn't ask it to defend a decision, then reopen the decision from the developer role once the reporting step has separated "what did you consider" from "was it right." The ablation is the clearest part of this result for the map's purposes — removing either step collapses most of the gain, and substituting ordinary self-correction for both steps performs no better than the unmodified base agent (44.2% vs. 44.25%) — showing the mechanism is specifically the elicitation-then-reconsideration structure, not merely a second look at the task description. Interaction edge: this sharpens agentic-code-review's standing concern that LLM reviewers favor their own generations — specification satisficing is a concrete, named instance of that bias operating before review even starts, inside the implementer's own planning.

Bounds: [T1, strong; two-author academic study (Purdue), five LLM backbones, two agent frameworks, two benchmarks (DeepSWE, SWE-bench Pro), no production deployment; the "advisor to maintainers" elicitation framing is itself a mild deception the authors disclose and caveat ethically, and its effect size has not been isolated from a disclosed-framing variant; the four-type reason taxonomy is author-coded with two other LLMs annotating and the authors adjudicating only disagreements, no independent human-only validation reported; intervenes once per task before code is written, so satisficing choices made later in a long trajectory are not addressed.]
