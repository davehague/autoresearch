Ask what bug this patch implies, without letting the checker read the bug report

Once a coding agent produces a patch, it holds no independent signal about whether that patch addresses the reported problem — and a plausible-but-wrong patch can pass the agent's own reproduction tests. The two standing answers both leave the gap open. Iterative self-refinement reviews the patch under the interpretation that produced it, so it cannot catch an error originating in that interpretation. Inference-time scaling broadens the candidate pool without assessing any single candidate.

The construction here is worth stating precisely because the direction is the whole idea. Forward reconstruction builds an explicit repair rationale from the issue plus the trajectory — ordinary, and it helps. Backward reconstruction infers, from the patch and its trajectory alone, with no access to the original issue, a description of the problem this patch appears to solve, then compares that reconstruction against the actual issue to yield an alignment verdict. A reconciliation stage checks the forward rationale against the patch, diagnoses where they diverge, and emits either a submission or targeted revision guidance.

The control is what makes it a finding rather than a system. Self-Refine, at a comparable inference budget on the same scaffold, degrades both backbones (−1.4 and −1.8 pp) while this gains 7.0 and 3.6. Same model, same rough token spend, opposite sign. So the mechanism is not more thinking; it is thinking that was denied an input. That is the same variable the-checker-should-see-less-than-the-generator isolates from the code-review side on the same weekend, by a different group on a different task, and it is why an-independent-checker-beats-the-same-model-checking-itself should probably be read as being about evidence flow rather than about model identity — here the backward reconstructor is the same model as the generator and still works, because it was starved of the issue text.

There is a second, subtler property. Withholding the issue makes the check non-vacuous by construction: the reconstructor cannot restate the goal it was handed, so agreement between its output and the real issue is evidence rather than echo. That is the concrete answer to the failure vacuous-oversight-has-a-measurable-threshold names, and it is cheaper than the alternatives — the verification prompt is 2.3× larger and costs less because it re-reads material already in the prefix (see a-verification-pass-is-cheap-when-it-is-cache-shaped).

Where it stops. Pass@1 on SWE-bench Verified is still a test-oracle metric, so the paper's claim that this signal works where no oracle exists is an argument from construction, not a measurement — nobody ran it on a task without fail-to-pass tests. Scaffold transfer is measured on a 120-issue subset, so those larger deltas carry small-sample variance. Every added component uses the agent's own backbone, so this establishes an information boundary and says nothing about whether a model boundary would add to it or interfere. And the false-rejection rate is never reported: no number says how often a correct patch is sent back for revision, which is the cost side of every gate (an-smt-gate-buys-interception-with-a-false-block-tax prices the analogous trade elsewhere).
