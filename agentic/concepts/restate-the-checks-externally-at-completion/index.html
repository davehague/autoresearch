A generic self-check inherits the omission it is checking for

The cheapest intervention this map carries. Change nothing but the completion instruction: ask the agent to "mechanically validate every explicit constraint" and it passes 5/10; hand it the frozen list of all 24 obligations and it passes 10/10, 240/240 checks (Fisher p = 0.0325). The prompts differ by 649 characters, so length is not a plausible explanation. All five generic failures are real requirement violations — four omit the same required array that generation omitted — and none is a checker or parser fault.

The stated mechanism is the transferable part: a self-generated validator is generated from the same degraded task representation that produced the artifact. If the required array has already dropped out of the agent's active worklist (a-loaded-skill-is-not-a-retained-requirement), the checklist the agent writes for itself omits it too, and the agent then runs a JSON parser, spot-checks some fields, and declares all constraints satisfied. Restating the frozen list gives the final phase a requirement source independent of the agent's current summary.

That is the vault's independence-of-observer property, arriving on a plane where it had not been measured. an-independent-checker-beats-the-same-model-checking-itself varied the verifier's identity (79% vs 71% recovery, within a point of an oracle). structure-outweighs-the-verification-step moved observe/compare onto the generating model and watched rescues fall 6 → 2. This varies neither the model nor the architecture — only whether the verifier reads a frozen external list or its own recollection — and gets the same sign. Independence is not only about which model checks; it is about which artifact the check is derived from.

It also extends the map's memory rule one step. The rule is persist the contract — and deliver it (persist-the-contract-not-the-conversation, memory-delivery-not-storage). This measures a third property of the same contract: when it is delivered. A skill loaded at turn zero and a checklist restated at completion are the same 24 obligations; only the delivery point differs, and it is worth 5/10 against 10/10. The operational form for any harness: re-inject the acceptance criteria at the decision they govern, deterministically, and do not ask the agent to reconstruct them.

The reviewer-side reading is immediate and worth testing: "review this carefully" is the generic self-check, a named checklist is the detailed one. Read with reviewers-underplan-and-overvalidate (heavy validation effort marks the reviews that fail), the sharper claim is that validation effort without an external requirement source is what fails.

Caveats: T3, one task, one model, one long-context construction, n = 10 per arm — ten successes do not prove a zero failure rate and the Wilson upper bound is 27.8%. The study does not isolate which checklist item or formatting property produces the gain, and the intervention is prompt-level only: the contract-aware runtime the author's research plan proposed was never built. Non-preregistered. Replication on independent tasks is the obvious and cheap next step.
