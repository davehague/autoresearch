Separate durable scaffolding from model compensation

This map has held since 2026-07-05 that harness assumptions go stale and the harness should be stripped on every model upgrade (harness-model-assumptions-go-stale, re-examine-the-harness-when-the-model-changes) — good advice with no decision rule attached, so in practice it means "re-examine everything," which nobody does. Practitioners supply the partition.

The challenge they name is "change nothing, change everything": provider-side model updates — sometimes unannounced — rewrite an agent's planning and tool use while code, prompts, tools, and workflows are untouched (80% agree, mean 4.03). P17: "You have not changed anything, but a model-version change may cause the whole system to regress or improve… Mechanisms built around the model's previous weaknesses can then become redundant." P14 reaches for the Bitter Lesson: "once the model became stronger, those mechanisms turned into shackles that constrained its performance." P18, compactly: "Today's design pattern may be tomorrow's anti-pattern."

The rule, from P17: context management, context compression, and fast verification will not be replaced by the next model release; shallow, surface-level scaffolding may be replaced directly. That is a testable partition and it is consistent with what the vault has independently found durable — the tool-surface and cost work (restrict-the-tool-surface-to-cut-cost-not-capability), the generator/evaluator split (separate-the-generator-from-the-evaluator), and just-in-time retrieval (just-in-time-context-retrieval) have all survived multiple model generations, while model-specific prompt workarounds are exactly what Anthropic and Cursor report deleting.

It also gives the contested self-evolution limb a cheap sanity check. If an automated harness optimizer is mostly discovering compensations for the current model's weaknesses, its gains should evaporate on the next model — which is one candidate explanation for why harness evolution transfers only +0.6 points to held-out tasks (harness-evolution-underperforms-matched-budget-test-time-scaling). Nobody has tested this: the experiment is to re-evaluate an evolved harness after a model upgrade and see which edits survive.

Caveats: the practice draws the study's middle support (67.9%), not its strongest; the partition is one senior practitioner's articulation validated by survey agreement, not a measured classification with outcomes attached; self-report, no inter-rater reliability, big-tech-skewed, Feb–May 2026.
