A mechanical oracle closes the judgment channel and leaves the plumbing wide open

The design was correct on the axis everyone worries about. A Tester model wrote tests, rule-based mutation named the survivors, a Critic model wrote tests to kill them, and every verdict was rendered by pytest and mutmut — no model ever scored another model's output, so the self-preference bias that undermines LLM-as-judge protocols (llm-judges-have-exploitable-biases) had no channel at all.

The bias entered one level out. The API wrapper for one provider carried an undetected output-token ceiling. Replies at the ceiling were truncated and rejected under an unrelated-sounding note, crediting zero kills. The ceiling applied to every call on that wrapper — but it only bit on verbose replies, and verbosity is a property of the model, so the failure was correlated with the arm under test. A treatment-independent flake would not preferentially depress one arm; this one could, and it produced a clean, well-formatted, overwhelming p-value with nothing in it to indicate that it measured the harness rather than the models.

The generalization the study draws is the transferable part, and it is not about token caps. A comparison is only as neutral as the apparatus that runs it. Any dimension on which the harness treats two models differently and which correlates with the outcome will manufacture an effect: a timeout that one model's longer runs hit, a retry policy, a rate limit, a parser that tolerates one model's formatting quirks, a serving-stack difference. This vault already holds that the harness is a named term in a model's score (the-harness-shifts-benchmark-rank-order, attribute-performance-to-the-stack-not-the-model); this says it is a named term in the comparison's apparatus too, one layer further out than anyone reports.

Two practices follow, and the study argues for both by having needed both. Pre-registration enforced by tooling — the runner mechanically refuses to execute unless the committed protocol is byte-identical to repository HEAD, so the gap between the pre-declared analysis and the corrected one is itself a dated, visible record. And fail-closed instrumentation (fail-loud-instrumentation-over-plausible-substitutes): the defect survived three mechanical gates that had already caught a sandbox crash and a test-collection scoping bug, precisely because it emitted no crash and no error. It was caught by an adversarial cross-model review of the completed analysis — independent-review-catches-bugs-in-the-measurement-code-itself applied at a level above the code, and a residual asymmetry the authors disclose rather than paper over: truncation is mechanically detected only for the provider that declares a cap, so a server-side truncation on the other provider would still be laundered.

The map's existing discipline is to validate the grader in both directions before the run (validate-the-judge-before-you-trust-the-migration). This adds the clause it was missing: validate the plumbing around the grader, and require it to halt rather than substitute.

Caveats: one incident, receipted in full, on a four-subject study; the general claim is a mechanism argument supported by one vivid instance plus three detected recurrences, not a prevalence estimate.
