Files were never outputs; they are the broadcast channel, and they are cheap for the same reason

This map prices the levers that move an agent bill — model choice, caching, scaffolding, tool interface. For multi-agent work it has had almost nothing, because the published fleet numbers are output counts rather than instrumented costs. Here is the first controlled measurement of a coordination channel as a cost lever, and it turns out to be a large one with a sign that flips.

The economics are structural. A direct message reaches one recipient, so telling a team of eight something means paying for it eight times; a file is written once and can be read by many, in any order, after any delay, across process boundaries. Mandating that all inter-agent state pass through files therefore substitutes a one-to-many channel for a one-to-one one — and on work whose teams would otherwise reconcile a shared specification by messaging each other, that cuts run-level output tokens by about 42% at eight agents, with cached throughput falling in step so the saving is not an artifact of the output-only view.

On chain-shaped work the same rule costs money. Where each agent owns consecutive pipeline steps, the files already carry the coordination — each step's output is read by the next — so mandating more file traffic only adds overhead: +17% at four agents, +10% at eight, and at sixteen agents on a fully decomposed chain it roughly doubles per-run tokens and more than triples file reads for identical success. The direction of the difference is the finding, and it makes the rule conditional rather than universal.

The scaling view is what makes this act on the-quadratic-cost-of-a-team-is-mostly-a-handshake rather than merely sit beside it. The near-quadratic growth belongs to the message channel specifically. Route the same coordination through files and the distributed task's total-coordination exponent falls from 1.70–2.11 to 1.12–1.32, and on the cleanest arm to n^0.98 — linear within error. The authors are careful that the linearisation comes from switching the message channel off rather than from files being intrinsically linear, since the file-read channel alone still grows at ~1.7 there.

The operational rule is diagnosable, not just conditional. Look at what the team's own coordination graph does when left alone: if the traffic is message-heavy, mandate files and save; if it already flows through files, leave it alone. And the timing result gives a free tell — teams on chain-shaped work write files first under every policy, at 12–14%, even though their prompt explicitly asks them to coordinate through messages. A sequential task settles its interfaces by writing them down whatever it is told, which means the instruction was never the binding constraint and the file policy is the only lever that moves it.

This composes with event-passing-beats-shared-context-in-agent-fleets rather than contradicting it: that claim is about not sharing a window; this is about which channel carries the deltas once you have stopped. And it sharpens the-agent-token-bill-is-a-cache-lifecycle-problem — the cached throughput moves with the policy too, so a coordination-channel change is a cache-shaped change, not merely an output-shaped one.

The bound the authors state plainly: the per-channel token bars are proxies on two different bases (message length against a turn's output shared across its tool calls) and show direction only. The run-level output figures, which carry the 42%, come from the model's reported totals and are independent of that division. Reported totals exclude cached context, which is the bulk of the throughput, and the runs were collected on a subscription with no per-token metering — so these are token reductions, not a priced bill.
