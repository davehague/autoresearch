Up to a third of an agent patch is the search, not the fix

CodeSlop is defined functionally rather than stylistically: not verbose or duplicated code, but removable functional redundancy — changes that can be deleted while the repair still passes. A patch can be readable, well-structured, and free of duplication and still be a third slop. The cause is mechanical and requires no failure of the model: while iterating toward green, an agent accumulates exploratory edits, and once the tests pass nothing in the loop asks it to take them back.

This map has been collecting the symptoms of an oversized review surface without a mechanism. Reviewer attention diffuses across docs, refactoring, style, and tests rather than logic (agentic-pr-review-targets-more-than-correctness); humans backfill agent code silently and off-review (humans-silently-repair-agent-code-outside-review); acceptance is weakly determined by the change itself (pr-acceptance-resists-prediction-at-submission-time); and practitioners name comprehension debt — code merged before anyone can explain it — as a widely agreed problem with no accepted exit (comprehension-debt-outpaces-review-capacity). Here is a mechanism for a real share of that surface, and an intervention: strip the search residue deterministically before a human reads the diff.

That matters because of what the map established two days earlier: review effort is barely predictable (R² = 0.12) so triage cannot relieve a capacity shortage (review-effort-is-organizational-not-artifact-determined), and the remaining levers were reviewer supply, reviewer diversity, and enforcement moved into gates. Shrinking the artifact is a fourth lever, and unlike the others it is automatable. The strongest evidence that the removed lines really were noise: on 18 SWE-bench instances the minimized patch became the human patch, and in the motivating kernel case the three surviving lines were the ground-truth fix.

Caveats: post-processing on successful repairs only — it makes patches smaller, not more correct — and it needs the trajectory plus a reliable validation oracle to re-run, which the vault's own evidence says agentic code frequently lacks (a-passing-suite-does-not-mean-a-tested-change). The smallest removable unit is one atomic edit action, so within-edit redundancy survives and ΔSlop is a conservative lower bound. Live-kBench equivalence is judged partly by a majority-vote LLM judge with the crash reproducer as the hard gate; SWE-bench uses the hidden suite. Two domains: C kernel and Python repositories.
