The layer you can afford to add is not the layer that is wrong

This map has spent two months establishing that performance attributes to the stack rather than the model (attribute-performance-to-the-stack-not-the-model, decompose-the-harness-into-separately-liftable-layers). The layers have been enumerated but never ordered. This monograph supplies the ordering and, with it, the reason layer-by-layer improvement so often fails to show up end to end.

The chain runs measurement → grading → containment and recovery → retrieval and context → review and accountability → allocation and cost, and each layer determines what the next is entitled to believe. A weak measurement becomes a confident grade. A weak grade admits unsafe work. An incomplete recovery record enters retrieval as though it were complete. Missing context makes a reviewer look ineffective. An invalid review signal steers the next tranche of work toward the wrong configuration — and back into the measurement layer.

The asymmetry is the useful part. Downstream machinery is cheap to add and is evaluated through the upstream instrument, so it cannot repair it:

  • more samples cannot repair a task distribution that excludes production work;
  • more judges cannot repair a rubric that experts apply inconsistently;
  • more agents cannot repair a retrieval boundary that treats an empty result as authoritative.

Each of those is a claim this vault has already established independently — a benchmark that measures the wrong workload (benchmarks-conflate-model-harness-and-penalize-alternatives), a rubric humans cannot apply consistently (the-human-reference-for-design-critique-is-itself-unreliable), an empty retrieval taken as authority (context-acquisition-is-an-unmeasured-failure-surface) — and the contribution is naming them as one failure shape with a direction. It is also the sharpest available argument against the fleet reflex: when a system underperforms, adding an agent is the cheapest move available and is almost never the layer at fault.

The framing underneath is that coding agents are evaluated as models and deployed as production systems. Once a run can outlive the process that started it, wait on another service, compete with another run, mutate shared code, or publish a durable external effect, reliability stops being a model property. The monograph is careful that this is not new — Osterweil's process-as-software (1987), Choi and Scacchi's software factory (1991) — and that autonomous workers change the failure model rather than the problem: today's workers are nondeterministic, edit persistent code, call external services, run concurrently, and can claim completion incorrectly. One cited measurement makes the last one concrete: across 1,750 trajectories, one model submitted work in 100% of its trials and resolved 44% under an external oracle, which is ground-completion-in-a-rerun-not-a-self-report with a number attached.

Bounds and grade. T3: a single-author structured review, adjudicated by one person, with author-operated systems used as illustrations and explicitly barred from supporting a general recommendation alone. The chain is a framework rather than a measured result — no experiment establishes that repairing an earlier layer yields more than repairing a later one, only that the later cannot substitute. Its own catalog carries the self-report that operational urgency and evidence strength are nearly uncorrelated (urgency-and-evidence-strength-are-nearly-uncorrelated).
