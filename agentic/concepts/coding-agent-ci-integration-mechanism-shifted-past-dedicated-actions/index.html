How much of CI is agentic, by what mechanism, and how durably — a population-scale read this map's strict-vs-relaxed contest hasn't had

This map's existing evidence is almost entirely about the strict-vs-relaxed gating contest and the price of testing or reviewing agent-authored changes; it has not had a population-scale read on how much of real-world CI is agentic at all, or by what mechanism. GHAgentCI supplies that foundational layer and finds the integration mechanism itself is non-stationary: the share mediated by dedicated, vendor-documented GitHub Actions is falling fast as CLI invocation and gh-aw-compiled workflows take share, which matters for the map's own evidence base going forward — any future census or detector that watches only for dedicated action references is watching a shrinking fraction of the practice.

The safeguard-declaration pattern is the number most directly relevant to this map's governance-adjacent concerns: the highest-risk trigger combination measured here (pull_request_target, fork-submitted code running with repository secrets potentially available) is restricted only 55% of the time — barely above the 50.8% network-policy rate for a different, lower-stakes mechanism, meaning declared governance is not obviously tracking risk level. This interacts with agent-harness-architecture's composition sub-thread (which independently found committed agent-configuration files under-governed relative to GitHub Actions workflows in the same repository population, a 67x permission-scoping gap): this paper extends that same thin-governance pattern specifically into CI-embedded agent invocation, on a population that substantially overlaps the files that sub-thread already tracks, and it is the first source here with a time dimension (quarterly trend, Kaplan- Meier retention) rather than a single snapshot.

Bounds: [T2, suggestive-to-strong by evidence kind; purely observational — no outcome or incident data connecting a declared-safeguard gap to an actual security event; relies on a documentation-derived catalogue of 12 named agents, may miss unrecognized wrappers or external reusable workflows (a separate keyword-selected sample found an unrelated 5.5% missed-invocation rate, not a general recall estimate); SEART-based sampling excludes small/inactive repositories; default-branch, first-parent traversal only.]
