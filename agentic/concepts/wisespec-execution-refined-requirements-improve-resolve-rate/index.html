The map's elicit-then-synthesize instruction gets an automated, execution-verified version of the spec-quality step — no human review, the check is whether the resulting code passes tests the specification implies

This map's practice is built on two findings about what an agent cannot do to a specification: agents-are-weak-at-spec-critique (44.4% on design-proposal defects) and emergent-specs-corrupt-the-artifact (an incrementally-delivered spec degrades faithfulness), both read as "therefore a human writes and reviews it." elicit-the-spec-in-its-own-phase-before-synthesis partially complicated that reading — a dedicated spec agent, doing nothing but exploration, is productive at writing SPEC.md even though the same agent is weak at critiquing one, because exploring and judging are different jobs. WiseSpec extends that finding one step further: instead of writing a specification once and handing it to synthesis, it treats specification refinement as an execution-based loop — generate code from the current spec, run the tests it implies, and read any failure back as a Conflict, Omission or Ambiguity in the specification rather than only a code bug. This is a different quality mechanism than anything else on this map: converge-the-spec-against-the-code-before-freezing-it re-audits a specification against source code across 14-17 human-run cycles; WiseSpec re-audits a specification against its own generated code's test results, automatically, with no human in the loop and no reference implementation to compare against.

The result composes with the map's standing instruction rather than contradicting it: WiseSpec does not claim to replace human spec review, and the map's a-specification-buys-executability-not-agreement null (a complete spec buys executability, not agreement or correctness) is a live caveat here too — %Applied improvements (11-63%) are consistently larger than %Resolved improvements (2-29%), meaning a meaningful share of what WiseSpec's refinement loop buys is code that runs rather than code that is behaviorally correct, the same gap that null names. What it adds concretely: a nine-attribute/seventeen-sub-attribute DSL for what the agent extracts from repository context, and a scalable, execution-gated way to catch defects in that extraction without a human reading the artifact — useful specifically for the automated half of a pipeline where human review is not yet in the loop, or as a pre-filter before it is.

Scope: single-author study on 100-instance random subsets of three SWE-bench variants (not full benchmarks), no ablation separating the DSL schema's contribution from the execution-refinement loop's, and — as with every source this map carries whose endpoint is test-pass rather than independently audited correctness — contract coverage of what the specification actually captures is not itself verified against ground truth. No independent replication yet.
