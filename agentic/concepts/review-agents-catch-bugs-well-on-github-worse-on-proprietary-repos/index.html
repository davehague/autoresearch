This map has measured review-agent precision and capacity for months; CRBugBench is the first controlled recall instrument — and it locates the bottleneck between "looked in the right place" and "got it right," not between "looked" and "didn't look"

This map's standing material is almost entirely about review-agent precision (resolution rate, false-alarm rate, independence) and about human review capacity collapsing under agent throughput. CRBugBench supplies something neither strand has had: a controlled recall instrument against a known-bug ground truth, mined the same way the map's own capacity-collapse evidence was — from real merged PRs and real post-merge fixes, not a synthetic benchmark. Read against the "lights-off" framing in the paper's own title, this is squarely this map's and unattended-operation's shared question: could an automated reviewer alone be the gate, and at what recall?

The trajectory breakdown is the most load-bearing number for this map specifically, because it names where detection fails rather than just how often: 95.6% of runs inspect the file where the bug lives, 80.2% produce a finding about that file, and only 56.2% land on the correct diagnosis. That 80.2%→56.2% drop is a judgment failure on material the agent already has in front of it — the same shape this map's own groundability-not-scale-predicts-weak-reviewer-reliability and a-review-runtime-can-silently-miscount-its-own-completions findings describe: navigation is not the binding constraint, interpretation is.

The proprietary-repo gap is this map's first direct evidence that capacity-collapse findings (observed almost entirely on open-source/GitHub-scale data) may understate the problem at exactly the repos — large proprietary monorepos — where the capacity-ceiling papers' "silent approval" dynamic was measured. Lower diff-visibility and higher context-dependency on industry code mean a review agent's already-imperfect recall gets worse precisely where a human reviewer's bandwidth is already most strained.

Bounds: the benchmark measures recall of pre-identified, already-known bugs under an LLM-judge panel (human agreement κ=0.89, not independently re-verified by this map); ground-truth construction (SZZ bug-inducing-commit tracing, LLM-filtered threads) carries its own noise the authors flag; the proprietary track's full replication package is not public, so its headline "-25.5%" figure cannot be independently checked at the per-model level this map would need to compare against its open-source numbers.
