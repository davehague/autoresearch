The cheapest way to get a zero-variance arm is to have nothing stochastic in it

This map's hardest practical problem is that the disciplines it prescribes are unaffordable. A paired noise floor requires re-running both arms many times (coordination-deltas-need-a-measured-noise-floor); ordering two configurations at Δ ≈ 0.18 with σ ≈ 0.3 needs k ≈ 46 (control-the-data-draw-before-the-seed); practitioners name trustworthy evaluation as priced out rather than merely hard (price-agent-work-per-commit). So an instrument that removes the stochasticity instead of averaging it away is worth attention on cost grounds alone.

A deterministic simulator has σ_eval = 0 by construction — two plans differing by 0.01 differ by 0.01, forever — which is the strongest available form of the frozen-shared-state discipline this map adopted on 2026-07-28 (adversarial-critic-rounds-add-kills-over-a-frozen-suite). At 1.3% of the tokens, the still-unrun architecture sweeps in this vault become weekend experiments with real execution reserved for confirming a winner. That is the contribution: not a truth oracle, a screen.

What makes it a well-behaved instance of a shape this map usually records failing is that the authors bound it themselves, in three ways this map should reward:

  • They publish the leave-one-model-out sensitivity. The headline r = 0.816 rests on six model-level points; drop one and it falls to 0.421 with p = 0.50, or rises to 0.949. A correlation on six points with that spread is a promising instrument, not a validated one, and the paper prints the table that says so.
  • They demote what does not replicate. Simulated time and token predictions correlate at −0.264 and −0.607 with real outcomes, so they are reported as diagnostics rather than scores. The reason is its own finding: real wall-clock is nearly uncorrelated across execution frameworks (r = −0.104), and the time-token relationship is inconsistent within them. Resource usage is a property of the framework, not the model — so any agent cost comparison that does not name the framework is unfalsifiable, the same disclosure failure this map measured at 0.38/1.0 for agent benchmarks (agent-benchmarks-underdisclose-their-harness, attribute-performance-to-the-stack-not-the-model).
  • They publish the mechanism ablation that shows how narrow the instrument is. Remove the missing-transfer penalty and the benchmark's discriminative power essentially vanishes (a 0.247 quality gap becomes 0.011). A benchmark reporting the single mechanism that carries its own signal is doing the reader's adversarial reading for them.

The honest limit sits exactly where the ablation points. An architecture comparison run here is a comparison of declared information routing under an assumed loss model — the loss model being a geometric mean of parent qualities raised to a per-subtask compression sensitivity, with a chosen λ for a missing transfer. Nothing validates that kernel against real degradation. So the instrument screens plans; it cannot adjudicate whether the real coordination tax has the shape it assumes, and using it to do so would be the same category error as reading a proxy at the wrong granularity (proxy-metrics-rank-models-not-suites, speedup-is-an-environment-conditioned-claim).

One secondary use is worth flagging because it is cheap: task-conditioned model selection. Ranking six models by simulated signals picks the true best model first 61.5% of the time against 38.6% for a baseline that ranks by real scores on every other task — and the gap closes by Top-3. So its value is early filtering for a specific task without prior real executions, not a leaderboard (route-the-session-not-the-query).

Caveats: six validation models, one real-execution framework for the primary correlation and three more for the robustness check, with the weakest at 0.39.
