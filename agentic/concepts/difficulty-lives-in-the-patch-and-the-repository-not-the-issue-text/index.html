Diffusion of the edit and size of the search space decide it; the prose is a tiebreaker in the band where nothing else is deciding

The ablation is the paper, and it is worth reading carefully because it can be over-read in either direction.

The structural half. Patch features alone (AUC 0.846) and repository features alone (0.839) each do almost all the work, and together they land within 0.002 AUC of the full model. The three features that carry it — lines deleted, number of hunks, and mean unchanged lines between consecutive hunks — are 29% of total SHAP mass, all monotone negative, and the third is the interesting one: it is a measure of how far apart the edit sites are, not how big the edit is. That reproduces the just-in-time defect-prediction literature's own finding that diffusion beats volume, now in the agentic setting. Ranks 4–14 are entirely repository structure, contributing independently of the patch trio, and the leading feature interactions are all patch × repo pairs. The worked example makes the interaction concrete: the hardest task in the set has only moderate patch volume, and its second-largest negative contributor is root-level directory breadth — moderate fragmentation in a wide repository is enough to drive predicted success to 0.013.

The linguistic half, stated at its real strength. Twenty-seven features operationalising the requirements-engineering taxonomy of ambiguity — coordination, attachment, referential — plus cohesion and syntactic complexity, reach AUC 0.599 alone and add nothing measurable once structure is present. That is a genuine negative result about these features, and the authors bound it precisely: their features measure the structural conditions for ambiguity, not ambiguity. The RE literature distinguishes nocuous ambiguity, where readers genuinely diverge, from innocuous, where domain context resolves it, and a path-and-parse-tree feature cannot tell them apart. So this is a necessary-but-not-sufficient proxy, it upper-bounds its own predictive power, and the low signal is exactly what you would expect. It is not evidence that specification quality does not matter.

Which is why the mid-band result is the one to carry. Aggregate importance suppresses composition. Stratify by predicted probability and the picture changes: for tasks near the population mean, where structural signals roughly cancel, a prompt feature is among the top five contributors 70.3% of the time, against 26.8% for easy tasks and 6.8% for hard ones — and the ratio of the largest prompt contribution to the largest structural one roughly doubles. No single prompt feature drives it; three different ambiguity markers each appear in about a tenth of mid-band tasks. Difficulty is layered: structure decides the extremes, and language decides in the band structure abandons.

How this composes with the rest of the vault. It confirms rather than contradicts the-specs-format-is-not-what-pays — surface form is not the lever — while leaving spec-driven-development's core claim untouched, because that map is about a contract held outside the agent and re-presented at the decision it governs, which is a different object from the linguistic surface of a GitHub issue. It also sharpens route-after-scouting-the-repository-not-from-the-issue-text with an independent measurement of the same asymmetry, and gives move-task-difficulty-from-the-model-to-the-harness a target: if hunk gap and directory breadth are what bind, then localisation tooling and multi-site edit coordination are where harness effort buys the most, not prompt rewriting.

The uncomfortable implication for benchmark construction. If difficulty is dominated by patch diffusion and repository scale, then a suite assembled without controlling those two axes has an uncontrolled difficulty distribution, and a solve-rate delta between two agents can be a difference in where their successes fall along it. That is benchmark-misalignment-concentrates-in-the-unresolved-tail with a mechanism attached, and it is the argument for report-the-delta-inside-a-difficulty-band.

Bounds. One agent (Qwen3-Coder-480B) in one scaffold (OpenHands), and the authors flag that repository-scale sensitivity is this agent's navigation strategy showing through — an agent with a different localisation approach may rank the features differently. Python-centric repositories, so absolute importances for Python-file and pytest-convention features may not transfer. Patch features come from the gold patch, a proxy that can diverge from what the agent actually had to reason through. Contamination is unaddressed. And the prompt-feature null is a null about a specific deterministic feature set: whether an LLM-judged nocuous/innocuous classification recovers signal is explicitly left open.
