A version integer behind a mutable pointer is a promise, and the record has no way to check it

The absence measured in no-delivery-platform-emits-the-identity-its-assurance-claim-needs would be a smaller problem if nothing were filling the space. Something is. Sixteen of twenty-seven agent platforms now version the behavioral tuple by default — and they do it nominally, with a counter or a name in front of a pointer that can move.

A nominal determination inherits the nominal layer's failure mode, and the failure mode is not hypothetical at either layer below. The software supply chain spent a decade on it for package identity: expectations bind to names, provenance binds to digests, and names drift. The AI supply chain measured it for model identity: on the largest model registry, 40.87% of model-weight changes were unrepresented in either the name or the documentation. This is that problem reappearing intact one layer up, at the behavioral tuple, being resolved the same way a third time.

The gloss cells are the part to read twice, because each is a specific way a version lies. A revision that pins storage URIs rather than bytes, with fields outside the versioned set mutating across all revisions. A deployment that is immutable while a team-level routing rule rewrites which model actually serves, with no redeployment — the tuple drifting underneath an unchanged deployment identity, which is precisely the case a version number is powerless to detect. Immutability as stated policy with no digest to check the policy against. A publish history that permits deleting old versions. Each of those platforms would truthfully answer "yes, we version that."

For anyone building on a managed agent platform, the practical reading is a boundary. Pinning a version buys you the vendor's assertion that the tuple did not change — which is worth something operationally and nothing evidentially. If you need to be able to show later that the thing you evaluated is the thing that ran, the record you need is one you build yourself: the paper's own instrument was first written against an operating estate that had built itself a bespoke content-addressed binding artifact, "which is exactly what no surveyed platform emits by default."

The clock is the honest part. The finding expires rather than fails: standardization efforts converging on tuple representation are in flight, one platform already content-addresses a partial tuple slice by default, and a disclosure-side study over nine API providers and seven inference hosts independently found no provider publishing information that lets an external party verify the artifact being served is the one the documentation refers to. Pressure is arriving from two directions at once.

Bounds. The 16 of 27 count is an upper bound by the survey's own generosity rule: where documentation overstates emission the grade errs affirmative. It grades documentation, not behavior.
