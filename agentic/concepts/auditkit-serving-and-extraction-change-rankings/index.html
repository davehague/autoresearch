A general-purpose evaluation library's own worked examples independently reproduce this vault's harness-as-score-confound thesis at two different layers — answer parsing and serving backend — using nothing more exotic than its own documentation case studies

This map's sub-thread (1), benchmark & contamination validity, and this vault's harness-as-score-confound map both track how measurement apparatus below the model can move a reported score. AuditKIT is not primarily a research finding — it's an evaluation library — but its seven case studies function as small, clean confirmations of exactly this thesis, run by a team with no stake in any one benchmark's outcome. The extraction-method case study is a near-ideal minimal demonstration: identical model outputs, and changing only whether a regex pulls the answer out of the response text moves one model from last place to competitive. The serving-route case study extends the confound to the layer this vault's harness-as-score-confound map has recently started tracking (inference-backend/serving-stack effects): the same weights through four different serving routes answer identical factual probes with different correctness.

What distinguishes this source from a typical confound-detection paper is that it treats these as named, expected hazards baked into its own tool design rather than surprising findings — the library's unscored-vs-failed distinction and its explicit flagging of quantization and judge-family confounds in its own financial-QA case study are evidence the confound-awareness this vault has been assembling piecemeal is becoming infrastructure, not just a research literature. That is worth the map's attention less as a new effect size than as a signal: if a general evaluation library ships these confounds as documented case studies by default, benchmark authors have less excuse to omit the same disclosures.

Bounds: demonstrations bundled with a tool release rather than a systematic survey of how often these confounds appear in published benchmarks; small per-case-study samples (as few as 100 items); the library's own metric and backend implementations are asserted correct rather than independently audited here, so it is evidence of the pattern, not a new population-level estimate of its prevalence.
