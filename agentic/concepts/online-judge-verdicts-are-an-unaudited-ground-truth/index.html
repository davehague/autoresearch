The gold label is an instrument, and nobody calibrates it

Everything in this map is about a measurement of an agent being untrustworthy: a contaminated benchmark, an undisclosed harness, a biased judge, a proxy that ranks the wrong thing. This sits one layer underneath all of it. The online-judge verdict is what decides which programs a dataset calls correct. It sets contestant ratings, it labels the corpora that code models train on, and it grounds the execution-based reward signals used to train them. Prior audits had warned that official suites accept buggy submissions; this one measures it with a certification procedure and publishes the ledger.

Within a 20,375-submission accepted sample, 589 submissions are verified buggy — they fail on a legal input under an audited expected output, and the official hidden suite passed them. That is 2.9% of the audited accepted class, from one auditing arm; running the same certification across five agents yields a deduplicated floor of 906, a floor rather than an estimate because dropped candidates are never regenerated. The findings do not reduce to a handful of copied solutions: mechanical source-token clustering finds 578 near-clone-distinct clusters among the 589.

The number survives the obvious attacks on it, because the paper attacks them first. The funnel is published in full: 746 exclusives, minus official timeout catches, minus nondeterministic runs, minus 125 consensus corrections where a larger vote made the reference oracle rather than the submission the outlier, minus 15 floating-point tolerance artifacts. Independently written reference solvers re-adjudicated all 589 in isolated scratch — blind to expected/got values and to the buggy source — and disagreed with 0 oracle outputs. A signed human-adjudicated stratified sample of 203 findings produced 0 overturns, bounding the false-discovery rate at 1.87%.

Read beside perf-benchmark-reference-patches-are-unstable, the pair is the sharper claim. There the reference patch of three performance benchmarks fails its own validity rules on 18–92% of tasks. Here the reference verdict of an online judge is wrong on 2.9% of its positive class. Two groups, two benchmark families, two different kinds of gold, and the same conclusion: the ground truth is an unvalidated measuring device. Everything this map already says about proxies applies one level down, and the consequence is worse there — a contaminated benchmark inflates a score you can discount, while a mislabelled training reward teaches the wrong thing silently.

What keeps this from being merely alarming is that the same work shows the audit is affordable. Off-the-shelf coding agents, seeing only the problem statement and one reference solution and never the submissions they will kill, build suites that come within 1.7pp of re-judged official coverage on the bugs those suites do catch (0.919–0.932 against 0.936), where budget-matched random generation trails by 10.9pp. The official suites remain the stronger single judge — they reject 1,136 submissions the agent's suites miss, and the paper says so plainly. The claim is complementarity: suite adequacy is checkable, so stop assuming it.

Bounds. Competitive programming, C++, single-answer problems only — multi-answer and special-judge problems are excluded by construction, and nothing here transfers directly to repository-scale suites. The 2.9% is a rate within one platform's sampled accepted pool (the first 200 accepted submissions per problem, 8.9% of the available accepted C++ submissions), not a rate for code datasets in general. The consensus oracle is a procedure that can be wrong and was, on 125 flags concentrated in a single problem, caught only because a larger vote was run. No formal preregistration; a pre-execution plan designated two of five engines confirmatory and the five-engine panel is reported as descriptive.
