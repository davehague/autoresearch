Judging a spec and discovering one are different jobs

This map's contract-outside-the-agent claim rests on two findings about what the agent cannot do: it cannot critique a specification (agents-are-weak-at-spec-critique, 44.4% on design-proposal defects) and cannot retain one delivered in pieces (emergent-specs-corrupt-the-artifact, single-shot beating incremental on 16/20 papers). Both have been read as therefore a human writes the spec. That reading merges two capabilities. Judging a specification requires the design taste the agent lacks; discovering one requires systematic probing of an observable system, which is exactly the kind of tedious enumeration an agent is good at — provided something in the environment can answer behavioural questions.

Given such an oracle, the split pays on every model tested and the mechanism is measured rather than assumed. Binary exploration coverage rises 9.4–18.5% on all four models, and the decomposition attributes it to the phase and not to luck: the dedicated spec agent covers 54.9–58.3% against the synthesis agent's 31.2–51.3%, and their union barely exceeds the spec agent alone. An agent that can code will stop exploring and start coding, every time, before its behavioural model is complete.

The tail is the result worth carrying. A lift in mean partial-credit pass rate is compatible with many programs being slightly less wrong. Instead, near-perfect reconstructions triple at the ≥90% threshold and quadruple at ≥95%, with non-overlapping confidence intervals at both. The intervention moves programs into the "basically correct" band rather than nudging the middle.

The failure vignettes name the same disease this map already tracks. An agent reads a typed signature at turn 4 and, implementing that function at turn 57, emits an untyped variadic — the requirement was observed, was right, and had stopped governing. That is a-loaded-skill-is-not-a-retained-requirement on a fifty-turn delay, and where restate-the-checks-externally-at-completion answers it by re-presenting the contract at the decision, this answers it by writing the contract to a durable artifact that a fresh context reads. Both are the same move: take the requirement out of the trajectory. Note that the synthesis agent receives SPEC.md and explicitly not the spec agent's reasoning or tool output — the phase boundary is a context boundary.

Read alongside emergent-specs-corrupt-the-artifact this is the same axis measured from the opposite end by an independent group. There, requirements held constant and delivery varied showed that a spec arriving in pieces degrades the build. Here, model held constant and phase structure varied shows that a spec finished before the build begins improves it. The practice sharpens from the human writes the spec to the spec is completed in its own phase, by whoever can observe the behaviour, and handed over whole.

The scope condition is severe and non-negotiable. An execute-only binary is a perfect, cheap, deterministic oracle available on demand — the most favourable possible setting for elicitation, and precisely what a real feature request lacks. The authors concede that the paradigm degrades pronouncedly at repository scale. So this is evidence about elicitation given a probe-able oracle, and the open question it raises for this map is what plays the binary's role when the target does not exist yet: a legacy system, a reference implementation, a production log, or nothing at all. Further bounds: one scaffold, same model in both phases, no matched-budget arm (the confound is answered indirectly, by 100% of baseline runs self-terminating early rather than exhausting their budget), no repeated runs per instance and so no seed variance, deterministic CLI programs only, and 48–130% higher cost.
