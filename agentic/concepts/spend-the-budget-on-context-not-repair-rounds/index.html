Buy prefill, not decode — the same budget bought better tests without a single repair round

This map's tests thread keeps landing on the same conclusion from different angles: the agent's own passing suite is not evidence (a-passing-suite-does-not-mean-a-tested-change, half-of-an-agents-own-passing-checks-cannot-see-the-bug), and the remedy is to grade against something the generator did not produce (adversarial-critic-rounds-add-kills-over-a-frozen-suite, certify-the-killing-input-before-you-call-it-a-bug). This adds the cheaper half of the remedy: give the generator better grounding before it writes, instead of better feedback after.

The result is a clean sweep on both quality axes. Against the iterative self-repair baseline, the non-iterative context-first pipeline raises pass rate 68.4 → 80.8 (Qwen3-Coder-30B) and 73.2 → 88.2 (GPT-5-mini) and raises mutation kill rate 59.00 → 73.20 and 61.56 → 78.17 — while execution-feedback-selects-weaker-assertions shows the iterative loop buying its pass rate by giving the kill rate away. Runtime errors, the thing repair rounds exist to fix, fall from 28.4% to 7.4% and from 25.4% to 4.2% without any repair round: better context prevented the errors the loop was there to clean up.

The cost structure is the transferable engineering. Completion tokens collapse by roughly an order of magnitude — 1,474.63 → 148.16 and 1,941.51 → 163.74 per instance — while prompt tokens fall slightly rather than rising. Wall-clock drops up to 77%, and total API cost across all 500 instances runs $0.87 against $3.13. The mechanism is one this vault should generalize: decode is the expensive, latency-bound phase; prefill is the cheap, parallel one. An iterative loop spends in the expensive currency by construction, because each round is another generation. Moving the same budget into a one-shot, information-dense prompt buys more and costs less.

And the design detail that makes it hold up in production: the token-heavy static context is anchored at the head of the prompt so the prefix stays stable across phases, maximizing KV-cache hits. That is why the larger prompt achieves higher cache utilization than the iterative baseline's shorter one, and it is the same lever the-agent-token-bill-is-a-cache-lifecycle-problem finds dominating the production bill and prompt-caching-inverts-cloud-versus-local-economics prices. Context assembly is a cache-layout decision, not only a relevance decision.

Two ablations bound the enthusiasm usefully. More dynamic data is not better data: dumping all available local-variable values performs worse than intent-driven selective extraction — raw runtime state is noise, which rhymes with goal-hinted-pruning-beats-generic-compression and just-in-time-context-retrieval. And dynamic context alone performs poorly without static anchors; the authors describe the static half as "the blueprint for intent" rather than a dependency-resolution convenience. The composition is what works: structure first, then selectively retrieved state against it.

The honest scope. This is one artifact type — a single regression assertion completing a given test prefix — in one language, on one dataset. It is not a claim that agentic loops should be replaced by one-shot prompts generally; the loop's value elsewhere in this map rests on feedback the generator cannot satisfy cheaply. What it does establish, with cost receipts, is that "add another repair round" and "assemble better context" are competing uses of the same budget, and on this task the second dominates on quality, latency and price simultaneously — a comparison almost no agentic-loop paper runs.

Bounds. One task, one language, one 500-instance dataset, single-assertion setting only; two primary models plus a GPT-5 spot check. No seeds, run counts or confidence intervals for any cell. Model tendencies diverge unexplained — on the 273 problems both models pass, the smaller open model produces stronger assertions (Shared KG 92.17 vs 90.14), which the authors read as the larger model preferring runnable oracles over strict ones.
