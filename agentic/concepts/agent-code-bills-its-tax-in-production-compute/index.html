A second ledger, denominated in serving compute rather than tokens

Everything on this map is priced in the currency the agent spends: tokens, calls, dollars per instance, cache hit rate. The implicit accounting is that an agent's cost is the cost of the run. cheaper-inference-relocates-cost-into-repair-labor opened a second column by pointing at human hours downstream. This opens a third, and it is the one a platform bill actually shows: the code the agent wrote runs, forever, on your fleet.

Measured on production traffic across a year with function-level observability, AI-heavy functions grew to 1.31× their baseline compute cost where human-written functions grew to 1.25× — a 5% relative penalty — and to 1.36× vs 1.25× on memory, 8% relative. The execution-profile shift explains it without appeal to any quality judgment: AI functions moved +0.88% toward direct on-CPU execution while human functions moved −2.57%, a 3.46% relative gap, with time in optimized libraries (absl/gtl) falling nearly twice as fast for AI code. That is the runtime signature of the static finding upstream — explicit loops at ~2.0× the human rate, standard-library calls at ~0.4×, copy-and-allocation findings at 1.39× (what-escapes-the-review-gate-is-efficiency-not-correctness).

The reason this belongs on the routing map rather than only on a quality map is that it changes the sign of a common trade. This vault's economics results generally say cheaper generation is a win to be banked (solve-sets-are-nested-so-route-for-cost-not-accuracy, route-the-premium-model-to-the-governing-role). A 5–8% standing compute penalty on the resulting code is a recurring cost against a one-off saving, and for anything that runs at scale the recurring side wins on a horizon of weeks. The honest framing of an agent's unit economics therefore has three terms — generation tokens, human repair time, and serving compute — and only the first is on anyone's dashboard.

The practice this supports is narrow and cheap: for hot paths, the marginal generation spend that gets the algorithm called instead of the loop written is trivially recovered. The paper's own intervention arm is the demonstration — category-specific feedback moved an efficiency score 0.294 → 0.385 for one extra prompt stage (name-the-defect-category-not-just-the-quality-bar).

Caveats: one organization, one language, deliberately chosen for its performance sensitivity, so the magnitude is not portable — a service dominated by network wait will not see 5%. The cohorts are matched (~6k per side) but the study is observational and the authors decline causal claims; AI-authored functions are shorter (11 LOC vs 15) but sit in larger, more greenfield changes, and function-level attribution inherits the revision-mapping choices they flag under construct validity. And the divergence is measured over a window in which the model mix changed continuously, so this is the profile of a rolling production ecosystem rather than of any one model.
