Renewing the window is not retiring the obligation

This map's context limb has a strong prior in one direction: a growing transcript is the enemy, and the remedies are compaction, external notes, sub-agents, and fresh invocations for residual work. LoopsBench is the first benchmark that can price those remedies against the thing they are supposed to protect, because it is the first to keep completed work live. Once a development unit's tests pass, they stay enforced for the rest of the run, so the score has a term for "you broke what you already finished."

The four-profile comparison is the result. Context-budget rounds per run span nearly 8× — Claude dynamic workflows at 97.96, Claude Code goal mode at 34.69, Codex goal mode at 32.76, the Ralph loop at 13.24 — and regression events are visible in every one. Worse for the intuition: the most aggressive renewer has both the highest resolve rate (24.11%) and the highest regressions per run (0.36). Distributing work across narrower worker contexts genuinely reduces dependence on a single transcript, and it does not substitute for tracking what has already been satisfied when the workers return.

That reconciles two things this vault has held separately. compaction-selection-is-all-or-nothing found that no summary ever carried a strict subset of planted facts and the first boundary dropped everything; carry-the-edits-not-the-narrative-across-a-restart and persist-the-contract-not-the-conversation say what to keep. LoopsBench says the category those rules are missing: an obligation is neither a fact nor a contract clause you were handed at the start. It is something the run created by satisfying it, and it has to be re-delivered as an active constraint on every later edit. Nothing in a compaction policy knows that a test which passed at layer 2 is still binding at layer 6, because nothing wrote it down as a requirement.

The testing column says why the agents cannot supply it themselves. Agent-authored test counts run 11–28 per task against native suites for tasks whose median gold patch is 5,499 lines. So earlier obligations are protected by whatever the harness happens to enforce, not by anything the loop built. That composes with agent-written-tests-miss-the-lines-they-add and lazy-generation-caps-agent-test-coverage: the loop that will break its own earlier work is the same loop that will not have written the regression test that catches it.

Read the Regression Rate column carefully — the paper does, and this is the honest bit. mini-swe-agent posts 0.24% and Claude Code 7.11%, which reads as the minimal harness having better discipline until you notice that Reg is measured over passing obligations, and mini-swe-agent resolves 7.14% where Claude Code resolves 17.86%. A loop that satisfies little has little to regress. This is the selection-effect twin of the vault's scoreable-runs-are-a-separate-denominator rule, arriving inside a headline metric: the denominator is produced by the arm under test.

What to build. The externalized plan checklist re-injected every turn is already in this vault as a long-horizon computer-use pattern; LoopsBench says the checklist needs a second section that only grows — what is now true and must stay true — and that it must survive compaction as deliberately as the plan does. And the cheap version of the measurement transfers immediately: if your loop compacts or restarts, keep the tests of everything it has already completed running on every subsequent cycle. That is not regression testing as CI hygiene; it is the only instrument that can tell you whether context renewal cost you anything.

Bounds. RQ3 compares four representative loop runs, not a controlled ablation of renewal policy with everything else held fixed — the profiles differ in orchestration as well as in renewal cadence, so the "renewal does not remove regression pressure" claim is an existence result across profiles rather than a measured null for renewal specifically. Regressions can also reflect the deliberately limited checkpoint feedback the runtime gives. Metrics are tied to the released suite, so they measure executable obligations rather than semantic preservation.
