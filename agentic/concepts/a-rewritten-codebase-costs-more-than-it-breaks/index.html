The bill notices the refactor before the pass rate does

An agent's cost is usually treated as a function of the task and the model. This is a controlled measurement of a third term: the shape of the code it is reading. Rewrite a repository into a semantically equivalent form — same tests, same oracle, ~7% of source lines touched — and the agent pays more to do the same work.

The control that makes it a cost claim rather than a failure claim is the restriction to instances the agent resolved in both conditions. Long doomed trajectories are the obvious way to inflate a token bill, and they are excluded. Within successful runs, cost rises in all eight SWE-bench Verified configurations, from 4.0% to 22.9%, with every interval excluding zero.

Steps and cost do not move together, and the gap is the finding. Step overhead never exceeds 9.9% while cost overhead reaches 22.9%, and cost per step rises in twelve of sixteen configurations with input tokens per step rising in thirteen of sixteen among resolved runs. The agent is not taking more turns; it is carrying more context on each turn — longer files, heavier reading, more of the repository pulled in per action. For anyone budgeting a fleet, that is the difference between a step cap (which would not catch this) and a token cap (which would).

One configuration inverts the shape and is worth reading as a mechanism sample. Opus under the simpler scaffold on Verified responds to perturbation by taking fewer steps — uniformly, on every instance, mean −19.8% and as much as −39% — while output tokens per step more than double (median +101%) and input tokens per step fall 17%. Fewer, denser actions. Net: +30.4% cost per step, +4.0% total. The same model on the other benchmark shows almost none of it (−1.29% steps), so this is not a model trait; it is a model-scaffold-workload cell, which is the same jaggedness that governs the quality side (robustness-ranks-differently-under-every-scaffold).

Where the money lands is scaffold-shaped. On the harder benchmark the entire effort penalty is concentrated in the richer scaffold — all four OpenCode configurations pay 8.8–12.6% with intervals excluding zero while the four simpler-scaffold configurations sit near zero, and on resolved instances the OpenCode configurations pay 4.6–7.2% more per step while the simpler one is flat or slightly cheaper. The richer scaffold's extra retrieval surface is exactly the surface the rewrite perturbs, and it bills for it.

The practical reading. A codebase does not have to be adversarial to cost you. Ordinary refactoring — renaming locals, restructuring conditionals, splitting string literals, the things a linter or a teammate does routinely — is enough to move an agent's bill by a fifth on tasks it still completes. So a cost-per-task figure measured on a frozen benchmark snapshot is a floor for the same task on a repository that has since been touched, and a per-repository cost baseline drifts for reasons that have nothing to do with the model or the task. Bounds. Qwen is served locally and priced at published third-party rates purely to keep models comparable; the same schedule is applied to both conditions of an instance, so the relative change is internally consistent but the absolute figure for that model is a convention. 54 instances, temperature 1.0, no fixed seed. Cost is token cost only — no wall-clock, no infrastructure, no human time.
