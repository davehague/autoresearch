Two ways to spend a bigger budget, and only one of them compounds

This map keeps finding interior optima — repair-loops-have-an-interior-optimum, the same shape for corrective steering, the same shape for round count under a deterministic checker. Those all measure a loop that revisits one artifact. This measures the other way to spend budget: independent re-runs, and what a scaffold does to their marginal value.

The finding is that the gap between two agents on the same model widens with k. At one run the contract-first agent is +4.2 points and the difference is not significant; at five it is +9.8 and significant, having passed marginal significance at three. If the scaffold were simply making the agent better at the thing it already did, the gap would be flat in k — a constant advantage per draw. A widening gap means each additional draw is exploring somewhere the baseline's draws do not, which is the definition of search rather than resampling.

The distributional signature backs the interpretation rather than resting on the trend. Per-bug detection is strongly bi-modal: bugs are caught in almost every run or in almost none, and 65.6% of them sit at one of the two extremes for the baseline. The scaffold moves that to 57.8%, and the movement is specifically out of the 0% bucket into the 20–80% conditional region — previously-impossible bugs becoming sometimes-possible. That is the mechanism by which extra draws start paying: a bug at 0% has no k that helps, and a bug at 20% is worth five draws. It is also the reason for the wide confidence intervals on both arms, and the authors say so instead of leaving the reader to wonder.

Read against resampling-headroom-is-inverse-to-capability, which found best-of-3 recovering +0.007 for a saturated leader and +0.10 to +0.21 for mid-tier entries, this is the same fact from the intervention side: resampling headroom is not a fixed property of the model, it is a property of how much of the task distribution sits at exactly zero — and a scaffold that moves mass off zero creates headroom that repeated sampling can then convert. The two levers are complementary and neither is a substitute for the other.

A validity control keeps this from being an artefact. pass@k — the rate at which the generated suite compiles and passes on the fixed code — is flat across the whole ladder (94.4% vs 94.2% at k=1; 98.9% for both at k=5). So the widening gap is not one arm producing more usable output as k grows; both produce valid code at the same rate and differ only in what that code checks. That is the control this vault usually finds missing.

The budget arithmetic is favourable but not free. The scaffold costs +38.0% total tokens and +59.1% output tokens, and buys +9 unique bugs (48 → 57), so tokens per unique bug detected rise only 1.16× while the absolute yield rises 18.8%. In this map's terms that is a rare thing: a loop intervention whose cost per unit of found work goes up by less than its yield, which is the opposite of the pattern failure-quadruples-the-compute-of-a-turn and failed-recoveries-burn-compute-not-terminate keep reporting for repair rounds. Whether it holds past k=5 is unmeasured — the ladder stops there and the gap is still widening.

Bounds. One model family, one organisation's codebase, 90 bugs whose fixes touch a single file. Bi-modality is measured over five runs per bug, so the 0%/100% buckets are coarse. McNemar's p bounces non-monotonically across the ladder (0.3075, 0.4545, 0.0574, 0.0352, 0.0352) because it is testing discordant pairs at each k rather than a trend, and no test of the widening itself is reported — the monotonicity is descriptive. And the whole comparison is against a baseline that already uses chain-of-thought natively, not against no reasoning.
