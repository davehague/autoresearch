A harness doesn't just add or subtract points from a model's score -- it can flip which of two models is better, and the flip is large enough (38 points) that a single-harness leaderboard comparison is measuring the pairing, not either model

This map's founding claim is that a benchmark score is a property of the model-harness pair, not the model alone. Every prior source here measured that as a magnitude effect: a harness swap moves one model's score by some number of points (8-21, 26, 54, and so on). This source is the first to measure the same phenomenon as a rank effect at scale: in a fully crossed 4-harness x 5-model x 3-benchmark grid (66 configurations, 6,204 trajectories — the largest such grid this map has ingested), the question "which model is better" gets a different answer depending on which harness both are run under, for four of the five models tested. The Claude-vs-GPT reversal on Terminal-Bench 4 (+7.94pp under OpenHands, -30.16pp under PI) is not a small wobble around a stable ranking; it is a 38-point swing in the sign of the comparison, on the same benchmark, same two models, same study.

This closes a specific evidentiary gap the map's Status held below consensus for: the two largest prior grids were two and four harnesses on one benchmark each (claw-swe-bench-adapter-and-harness-variance being the five-harness, single-benchmark instance). This source adds a 4-harness grid crossed with three benchmarks rather than one, which is the first evidence that the pairing effect is not an artifact of a single benchmark's idiosyncrasies — the ranking instability recurs across TUA-Bench, ALE-CLI, and Terminal-Bench 4 independently. It also adds a finding none of this map's existing sources carry: no vendor's own harness reliably gets the best out of its own model — own-vendor pairing is not even a weak heuristic here, which matters directly for anyone reading a vendor's self-reported benchmark number as a model capability claim rather than a pairing claim.

The trajectory-attribution sub-study (93.75% of repair attempts model-initiated, not harness-prompted) adds a mechanism note this map hasn't carried: harness choice matters less for whether a model attempts recovery than for what happens once it does — closer to this map's NanoHarness ablation finding (harness-benefit-shrinks-with-model-strength-then-flips-by-task-type) that opposing harness components can cancel into a near-null, since a harness that scaffolds recovery well but otherwise interferes could present as a wash in aggregate while still reversing specific model pairings.

Status held at consolidating, not promoted: this is one more large factorial grid, not independent replication of this exact reversal by a second group, run-to-run variance is unmeasured (single run per cell), and the field's published practice — single-harness leaderboard comparisons reported as model capability — has still not moved.

Rebutted by: harness-noise-floor-swallows-pass-rate-effect — a rerun-calibrated design on different harnesses/benchmarks finds harness-swap flips the same share of tasks as rerunning the identical configuration, i.e. the unmeasured variance this note itself flags may be large enough to swallow reversals of this kind; not a same-system retest, so this note's own reversal is not directly retested, only its generalizability.
