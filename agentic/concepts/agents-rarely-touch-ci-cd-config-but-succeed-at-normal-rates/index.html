Agents are cautious about touching the pipeline that gates them, and when one agent isn't cautious about it, reviewers trust it more, not less

This map's contest is how strict CI blocking should be for agent-authored code — this source supplies the base-rate data nobody had for the other direction: how often, and how well, do agents touch the CI/CD configuration itself? Rarely (3.25% of all agent changes across 8,031 PRs / 1,605 repos), and almost always through one surface (96.77% GitHub Actions specifically). Build-success rate on those touches is statistically indistinguishable from ordinary code changes (75.59% vs 74.87% across 99,930 workflow runs) — the mechanical reliability signal shows no CI/CD-specific weakness in aggregate, even though three individual agents do show significantly higher success specifically when touching CI/CD.

The sharper finding is the merge-rate split. Agentic PRs touching CI/CD merge slightly less often than other agentic PRs overall (67.77% vs 71.80%) — consistent with reviewers treating pipeline changes as higher-stakes — except Copilot, whose CI/CD-touching PRs merge 15.63 percentage points more often than its own non-CI/CD baseline, the only agent measured running in the opposite direction. Because build-success rates don't show Copilot's CI/CD changes as mechanically superior in the aggregate, the reversal reads as a trust signal (reviewer confidence in this specific agent for this specific surface) rather than a demonstrated quality difference — the same merge-label-is-social caveat this vault has applied elsewhere to acceptance-rate data (agentic-code-review's merge-label variance-decomposition finding: submitter attributes carry the majority of merge-outcome variance).

For this map's contest specifically: this is neutral evidence on strictness, not a data point for either pole. It says agents self-select into low CI/CD-touch behavior already (3.25%), which narrows how much a stricter or looser CI/CD-specific gate would actually change in practice — the surface this data covers is small relative to the total agent-authored change volume.

Bounds

Single-author observational mining study, no controlled comparison, no causal test of why Copilot's CI/CD merge rate is higher (reviewer trust, PR framing, and actual configuration quality are live untested candidates). GitHub-Actions-dominated sample (96.77%) limits generalization to other CI ecosystems. Merge rate and build success point in different directions for Copilot specifically, and the paper does not adjudicate which a reader should weight more heavily as "agent CI/CD competence."
