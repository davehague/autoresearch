A rules file is not advice; it is an override, and nobody measured what a wrong one costs

Coverage counts a required fact as present or absent, which leaves no room for two present facts that disagree. This workload puts them in disagreement on purpose: a written engineering standard states a rule, and working code in the same repository demonstrates the opposite. Both sit in the window. Neither is evicted. Tasks arrive one at a time, each gated on the previous handler existing, so the agent can neither read ahead nor satisfy the set with one template.

The document wins completely — 39 trials, every contested decision, two harnesses, three model tiers. The obvious alternative, that the model simply writes sensible code and the standard happens to agree, is ruled out by inverting the workload: with the document demanding the worse practice, the agent writes camelCase handlers, indexes payloads directly, divides money into floats, calls the naive clock, and interpolates its log messages. No prior produces that combination by accident.

Then the practical question the conflict result raises and does not answer: project conventions are routinely committed to repositories and routinely go out of date, so what does a wrong one cost? Three conditions on one scale, 3,385 scored decisions:

what the agent hasdecisions written the better way
a standard agreeing with the code100%
only code demonstrating the convention33%
a standard demanding the worse form0%

The endpoints have no variance at all. Ten of ten correct-standard trials write every decision the better way; ten of ten stale-standard trials write none.

This is the sharpest actionable result in the source, and it lands directly on this map's rule-file thread. the-project-rule-file-is-written-once-and-abandoned measured the population — 67.3% of project rule files never edited after creation, 40.7% created within a day of the repository — and read it as a maintenance problem. This prices it. A file written once against a codebase that has since moved is not merely stale advice the agent might discount; it is an override that costs more than deleting the file, because it suppresses the inference the agent would otherwise draw from the code in front of it. The 33% middle row is the floor a repository has for free. A wrong standard takes it to zero.

It also gives an-agentic-context-file-grows-until-someone-bulldozes-it its missing consequence. That thread established that instructions accumulate because nobody can license a deletion, and deletion-hazard-falls-because-the-rationale-decayed identified the missing input as why. The reason to fix that is now measured: the accumulated instruction is not inert ballast competing for attention, it is authoritative, and its authority does not decay with its accuracy. It composes with make-agent-facing-rules-enforceable-not-conventional from the opposite direction — an unenforceable rule is followed anyway, which is exactly the problem when the rule is wrong.

Two limits worth carrying. The 39-trial conflict result is a perfect separation, so its lower bound stays wide at 0.91 even with no dissenting trial. And the cells do not separate authority from modality or read order — whether the document wins because it is a standard, because it is prose rather than code, or because of where it sat is untested, and the authors leave it open. That distinction decides whether the fix is "keep the convention file current" or "stop shipping prose conventions at all."
