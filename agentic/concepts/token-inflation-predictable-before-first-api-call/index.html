The router's real unit cost is retries, not tokens — and which queries will retry is knowable for free before the first call

This map has priced which model acts, for how many iterations, and when to switch mid-run, all under the assumption that a call's advertised per-token price is the thing being budgeted. This source names the gap between that assumption and the workflow's actual cost: token inflation, C_true(m,x) / C_direct(m,x), the ratio of everything spent across every retry to what the first call alone cost. Systems that route on C_direct — the paper names FrugalGPT specifically — can underestimate real cost by more than 2x on hard tasks, because retry-heavy queries are exactly the ones a per-call price hides.

The more useful result for this map's own open question ("still no evidence on routing quality" — whether a policy is blind to the tail) is that inflation is predictable before spending a token: CoT Branching Entropy, computed by sampling a handful of reasoning chains locally and measuring how much their answers disagree, reaches AUROC 0.887 for flagging queries headed for a costly retry cascade — entirely offline, no API spend required to make the routing decision. That converts "hard queries cost more" from a fact discovered after the bill arrives into a signal available before the first paid call, which is a genuinely new capability against this map's standing routing methods (SeqRoute's budget MDP, SCATE's coverage-plateau stopping rule), neither of which has a pre-execution difficulty signal of this kind.

The fresh-vs-cascaded escalation result — forwarding a failed reasoning chain to a stronger model costs it 34.8 accuracy points versus re-prompting fresh — is a quantified, mechanism-level instance of a pattern this vault has seen only qualitatively: a contaminated or failed trajectory actively degrades the next attempt, it doesn't just fail to help. Most production escalation patterns (raise the model tier, keep the conversation) do the cascading thing by default; this result says the default is actively counterproductive, not merely inefficient.

Bounds

Evaluated on GSM8K and HotpotQA-style QA/reasoning — general benchmarks, not coding or tool-use agent trajectories, where retry structure (test-fix loops, tool-call repair, multi-turn state) may inflate differently than single-shot reasoning retries. Escalation threshold (2x predicted inflation) and sampling width (K=3 chains) are fixed, not swept. No accounting for the context-window cost of the failed chain itself when comparing fresh vs. cascaded escalation — only the downstream accuracy effect is measured.
