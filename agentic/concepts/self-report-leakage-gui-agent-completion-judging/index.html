A GUI agent's own success claim is not neutral context for the judge that checks it

verifier-independence's single argument is that independence is a property of the checking arrangement — specifically, of what the checker is denied — rather than of the checker's identity. Every prior instance on this map withholds something about the artifact under review: the issue text, the agent's exploration trace, the model's own training data. This source withholds something different in kind — the agent's own claim about its own success — and shows the same mechanism operating on it: a judge that can read the claim is measurably worse at the one job the claim is supposed to help with, catching the cases where the claim is wrong.

The controlled design is what makes this more than a correlational observation. The same judge model reads the same task description and the same recorded execution trace in both arms; the only variable is whether a third input — the agent's self-report — is present. If the self-report carried no information the judge didn't already have from the trace, its presence or absence should not move the verdict. It moves the verdict by double digits on both models tested, and in the direction that helps the agent look successful — which is exactly the failure mode a downstream pipeline consuming "success: true" cares about.

The practical answer the authors build — report isolation, implemented as a structured auditor that extracts trace evidence before any policy sees the claim, so evidence extraction and policy consumption are decoupled — gives this map a cheap, concrete instance of its arrangement principle: deny the checker the one input it should not need, and verify the denial actually helps (it does, by double digits) rather than asserting it by design. The decoupling has a second payoff this map has valued elsewhere (a-review-runtime-can-silently-miscount-its-own-completions): because evidence extraction and policy are separate, the same audit record can be re-scored under a stricter or looser gating policy with zero additional model calls.

Bounds: post-hoc trace analysis, no re-execution of the task or the environment; strongest for Android GUI traces under the specific reporting style and trace representation studied (three sources, two agent architectures, six task classes); the authors flag a residual label-circularity risk in construct validity, since field-level evidence correctness is checked only indirectly rather than against field-level gold labels; generalization to web agents, SWE agents, or other trace representations is untested.
