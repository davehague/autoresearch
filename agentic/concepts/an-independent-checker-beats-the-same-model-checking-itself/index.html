Who checks matters, and it is cheap to get right

This is the third arrival at the same property in nine days, by three different methods on three different objects, and it is time the vault carried it as a design rule rather than an observation. A production agent that moved its observe/compare stage back onto the model that generated the artifact saw rescues fall from 6 to 2 (structure-outweighs-the-verification-step). A calibrated stopping rule turned out to be governed by verifier discrimination rather than by the repairer's competence (stop-on-the-sign-of-the-marginal-gain). Here the protocol is otherwise identical between arms and only the checker's identity changes: same instruction, same candidate list, same correction rule — self-verification recovers 71% of injected errors, cross-verification 79%.

Two features make this the most quotable of the three. First, the winning verifier is smaller than what it checks. Nova Micro re-verifying Claude Opus 4.5 is a cheap model auditing a frontier one, and it works, because the job is not to be smarter — it is to re-derive the target from the original request without inheriting the acting model's committed state. Independence is doing the work, not capability. Second, it is model-independent: near-oracle recovery on all eight backends, so this is not a quirk of one pairing.

The mechanism explains the self-check's weakness better than a generic "models are bad at self-critique" story. The error being recovered is not in reasoning — the agent's logic is sound given what it holds — it is in reference. The agent recalls its prior binding correctly; the binding is simply wrong. Self-reflection cannot detect that, because internal state is entirely consistent. Only a re-derivation from the original request, by something that never saw the intermediate state, has the information to disagree. That generalizes past entity binding to any carried commitment: a checker that reads the agent's state is checking the wrong thing.

The honest cost is over-clarification, and the study does not hide it: wrong actions fall ~5× while clarifying steps roughly triple and strict workflow success dips from 29.2% to 25.2%. On these deliberately ambiguous tasks the authors argue asking is correct behaviour, and the accounting depends on your action's reversibility — which is precisely the runtime-action-governance framing. For an irreversible write, a 4-point completion cost against a 5× reduction in wrong actions is not a close call. For a cheap retry, it might be.

Caveats: synthetic entities, 3–8 step workflows, one provider, one fixed injection phrasing; the oracle is an approximate rather than strict upper bound (it corrects only the primary carry slot, which is why the cross-verifier beats it on some models); bootstrap CIs but no formal hypothesis tests. Labeling clarification under an injected state conflict as "over-clarification" may be too harsh, as the authors note.

Scope condition (added 2026-07-29, connect) — "independence" names four different things, and the vault's results only conflict when they are conflated. Three notes push back on this one and none was acknowledged here, because each is really about a different axis:

  1. Independent weights — a different model. What this note measures, and where it wins.
  2. Independent narration — a verifier that inspects the artifact rather than the agent's account of it. a-verifier-sharing-the-interpretation-shares-the-error: high-precision, low-recall, and it cannot adjudicate value, because re-deriving from the same source under the same interpretation reproduces the error. Narration-independence is not interpretation-independence.
  3. Independent errors — statistically uncorrelated failures. verifier-diversity-is-not-verifier-independence: the cross-family verifier was the worst of three, error dependence shifts with the acceptance operating point, and the product-of-errors argument holds only at zero dependence. So a vendor diff is not evidence of independence; error correlation at your coverage point is.
  4. Independent capability — enough headroom to add something. reviewer-value-tracks-capability-headroom: the sign flips with headroom, so a weak independent reviewer on a strong draft is a significant net loss.

The reconciliation this note's own result suggests: what it buys is re-derivation from an external anchor (the original instruction), not independence as such — which is why a much smaller model suffices here and fails in (4), where the reviewer must supply judgment with no anchor to re-derive from. Practical rule: if there is an external anchor to re-derive from, buy cheap independent weights; if there is not, you are buying capability and headroom decides the sign. Stated here for the first time and untested as a discriminator.
