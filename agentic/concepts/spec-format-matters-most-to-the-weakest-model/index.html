The spec's format is a lever that only weak models need pulled

This map's core claim is that the specification must be held outside the agent as a durable, external contract. This source adds a dimension the map hasn't carried before: given an external spec exists, its representation format is itself a variable, and its effect is concentrated almost entirely on non-frontier models. Holding identical architectural information constant and varying only format across five representations (prose, Mermaid+constraints+ADRs, OpenAPI+Mermaid, C4/Structurizr DSL, TypeScript interface contracts + ArchUnit-style rules), a frontier model's quality barely moves (Sonnet 4.6: 0.17-point spread on a 10-point scale) while a mid-tier model's swings 10–14× more (Gemini Pro: 2.42). On the weakest model tested, switching prose to typed interfaces triples route coverage (33%→100%) on the same information — because a typed interface is already code the model can implement directly, where prose requires inferring component boundaries first.

This sharpens rather than contradicts the map's standing claim that the spec's existence outside the agent is what matters — frontier models here largely don't care how that external contract is written, so "hold the spec outside the agent" remains the dominant lever. But for the deployment case this vault's other threads increasingly care about — cost-optimized or weaker models, at scale, where per-run economics matter — the finding reframes the specification as a compensating investment: a team running a cheaper model needs to spend more on how the spec is represented, not less, to reach the quality a frontier model gets from prose alone. That is a concrete operational rule this map didn't previously carry: format quality and model strength trade off, so the same specification-authoring budget buys unequal returns depending on which model consumes it.

Also worth flagging for agent-harness-architecture/harness-as-score-confound: a model that never self-validates (Gemini Flash ran zero demo scripts across 15 trials, stopping after ~12 turns unverified) can still receive a compliance-metric score — the paper's own words, "a concrete deployment risk invisible in benchmark scores." A format that raises an automated metric while validation behavior stays at 0% is a case this vault's harness-confound thread should watch for again.

Bounds

n=3 per cell in a 5×6 design, individually underpowered, no significance testing — the author's own "exploratory finding" label. Proprietary models only. One system of moderate complexity (7 components, 25 routes); larger systems might widen format sensitivity even on frontier models. Same person authored all five specifications, so relative format quality may not match what teams typically produce. Judge is Sonnet 4.6 throughout — same-family judge bias for Claude's own scores is not established either way.
