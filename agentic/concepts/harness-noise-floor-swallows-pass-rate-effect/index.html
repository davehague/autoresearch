The map's flagship reversal/magnitude claims about harness-driven pass-rate swings have not yet been tested against a measured rerun-noise floor, and the one study designed specifically to do that finds the pass-rate effect mostly vanishes into the noise it calibrates -- while the cost effect this map also tracks survives intact

Nearly every source in this map that reports a harness-driven pass-rate swing does so from one run per cell, and several of their own concept notes already flag "single run per configuration, variance unmeasured" as an open caveat (model-harness-pairing-reverses-rankings-not-just-shifts-them: "run-to-run variance is unmeasured (single run per cell)"). This source is the first in this map built specifically to close that gap: it runs ten rerun pairs of identical configurations on SWE-bench Verified to measure the noise floor directly, then compares the harness-swap effect against it on the same tasks and models. The result does not replace the map's central thesis (score is a property of the model-harness pair) so much as it puts a number on how much of the pass-rate side of that thesis survives noise calibration: on the hard-45 subset, swapping harness and rerunning the same harness flip the identical 13% share of tasks, and the tasks a harness wins in one run are not the tasks it wins in the next -- the signature of noise, not of a stable harness effect. On the larger 447-task pool, the heaviest harness (Claude Code) and the lightest (mini-SWE-agent) land within five points of each other.

This is a genuine push-back on the specific sub-claim that harness choice reliably reverses or materially shifts pass rate at a fixed model -- most directly against model-harness-pairing-reverses-rankings-not-just-shifts-them's headline 38-point Claude-vs-GPT reversal, though the two studies use different harnesses and benchmarks (OpenHands/PI/openJiuwen/DeepSeek-Harness on TUA-Bench/ALE-CLI/Terminal-Bench-4 there, vs. Claude Code/mini-SWE-agent/OpenCode on SWE-bench Verified here), so this is a methodological-confound push-back (the rebutted study's own variance is unmeasured) in the sense this vault's evidence model privileges, not a same-system replication failure. It does not touch this map's cost thesis at all -- if anything it strengthens it, with an independent, cleanly attributed account of where the 3x cost spread comes from (fixed per-call preamble size, multiplied by step count) that this map had not previously had decomposed this precisely. And its one surviving pass-rate effect (OpenCode's loss) is consistent with this map's running pattern that named harness effects are mostly failure modes (context-window stops, step caps, tool incompatibility) rather than genuine capability gains -- the paper states this explicitly: every harness effect it can name is a way to lose a task, none is a way to win one.

Scope this map should carry forward: this is one three-harness, five-model, single-benchmark study: it does not retest the specific reversals reported elsewhere in this map (different harnesses entirely), so it bounds the generalizability of the reversal claim rather than directly falsifying it on the same systems. The open question this leaves for the map: does the 38-point Claude-vs-GPT reversal on Terminal-Bench 4 survive a rerun-noise calibration of its own, or would it shrink the way this study's pass-rate comparisons did?
