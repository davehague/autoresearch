Coordinate by passing events, not by sharing a context pool

icat-agent replaces the shared context pool of conventional multi-agent scaffolds with synchronous, event-based message passing between decentralized agents — nothing is shared, things are sent — and it wins on precisely the task class where coordination was supposed to lose.

This is a direct push-back on multi-agent-helps-only-decomposable-tasks and coordination-saturates-as-the-single-agent-improves, both T1, both from the same 260-configuration sweep. That sweep found tool-heavy software-engineering tasks the most coordination-penalized cell in its table (β = −0.330, p < 0.001) and found the multi-agent premium inverting once a single agent passes ~45%. icat-agent coordinates on SWE tasks, from a 59.1% baseline, and gains 8.3 points while spending less money. Two T1s, opposite signs, same task class: loop-engineering stays contested, but the question has moved.

The mechanistic hypothesis both papers jointly suggest — and neither tested — is that the measured penalty is not a tax on coordination but on shared context. Every topology in the scaling sweep moves state through a common pool; its worst performer (Independent, −70.0%, 17.2× error amplification) is the one with no validation on that pool. If contamination of the shared window is the mechanism, then isolate-and-merge-parallel-agent-work worked for the same reason icat-agent does: a git worktree is event-passing with a filesystem for a mailbox, and neither lets one agent's confusion leak into another's window. The decisive experiment is cheap and unrun: re-run the sweep with a shared-context arm and an event-passing arm.

Caveat that keeps this from settling anything: the gains are measured on SWE-bench Verified and Pro, and benchmark-scores-inflate-when-agents-can-retrieve-the-fix says 63% of one frontier agent's SWE-bench Pro successes retrieved the fix rather than deriving it. icat-agent's low-quality-issue branch explores more before patching, which could make it better at retrieval rather than better at engineering — and the benchmark cannot tell those apart. The paper reports no egress constraint or .git strip (constrain-the-eval-environment-to-measure-capability). The cost win survives that objection; the capability win does not. No ablation separates event-passing from adaptive pivoting (scaffold-topology-should-adapt-to-task-quality), so the 8.3 points belong to the pair.
