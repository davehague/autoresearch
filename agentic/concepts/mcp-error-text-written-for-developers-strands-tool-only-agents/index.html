A capability increase that makes a model follow written instructions more faithfully makes it worse at recovering from bad instructions -- the harness's job is to filter what the model is told to do, not just what it is told happened

Tool-call output is context the harness delivers verbatim by default, and this source measures what happens when that delivered text assumes a reader the receiving agent is not. Web-API error messages were written for a human developer who can act outside the failed call; most MCP servers are thin wrappers of those same APIs (88.6% of 116 official servers backed fully or partly by REST APIs), so the error text an agent reads was never written for it. The controlled replay isolates the mechanism cleanly — same saved environment state, same task, only the error text varies — and finds the failure is not that models ignore bad advice; they follow it, and the more capable, more instruction-literal the model, the more completely. This is a persist-and-deliver-discipline finding in the specific sense this map's sub-thread (1) already tracks: the fix that works ("agent developers can filter unhelpful instructions before the model reads them," recovering 82% of the credential-loss case) is a harness-side content edit applied to tool output before it enters context, structurally the same move as the map's other persist-and-deliver interventions — just applied to a different content class (tool-call error output) than facts or working requirements.

Interaction edge: harness-as-score-confound — this is a clean instance of that map's standing question (does a score describe the agent or the apparatus it ran inside) with the sign flipped from what that map's other sources typically find: a fixed, unchanged harness-level design choice (unfiltered developer-oriented error text) makes a more capable model look worse at recovery, not because it reasons more poorly but because it takes the harness's bad advice more seriously. Any evaluation that scores tool-use recovery while treating MCP servers' shipped error text as neutral infrastructure is measuring this confound rather than raw agent capability.

Interaction edge: agent-harness-architecture — the paper's own remedy taxonomy splits cleanly along this map's harness/tool-design axis: the MCP-developer-side fix (name a callable tool in the error message instead of an unusable instruction) is a tool-design lever; the agent-developer-side fix (filter the step pre-read) is a harness-design lever. Both are measured, both work, and they are independent of each other — a harness author gets the 82% recovery figure even with zero cooperation from the MCP server author.

Scope: five OpenAI models only (no Anthropic or open-weight models), despite the paper's own claim resting partly on a cross-vendor trend both OpenAI and Anthropic report in their newest releases; scenarios replay BFCL's synthetic multi-turn tasks rather than sampled production agent traffic; the 150-server error-message coding was performed by an LLM (OpenAI Codex) following a released codebook, with no reported human inter-rater check.
