This map's 2026-08-17 finding (retrieval precision degrades 29.6%->3.3% from 5 to 100 skill candidates while outcome holds flat) gets a second, independent measurement at 10x the scale, with the mechanism now isolated: the skill stays recognizable, it is choosing it while also executing that degrades

This map's standing clause — "ground-truth overlap measures the annotation, not the acquisition," earned when a skill library exposed whole at execution time dropped actual-use precision from 29.6% to 3.3% between five and a hundred candidates while downstream success held roughly flat — gets its most direct replication yet, at ten times the candidate-library scale this map has previously carried (up to 1,000 irrelevant skills here, versus 100 there) and with a controlled design that separates why the decline happens rather than only measuring that it does. Loaded-skill recall for the one golden skill a task actually needs falls from 73.6% to 27.4%, and the zero-load rate — the agent opens nothing at all — rises from 9.3% to 51.6%. That confirms this map's acquisition-stage thesis (acquisition is a separately-scoreable failure surface, independent of whether the model is capable) at a scale no prior source here reached.

The new mechanism result is what makes this more than a replication. This map's 2026-08-21 arrival found agents open skills that are 60.5% self-authored with almost no observed cross-checking against reference material — a behavioral account of what agents actually do with acquired material. This source adds the missing causal half for the specific case of skill libraries: holding the same model fixed and asking it only to select (never execute) the right skill from the identical growing library, recall stays flat at 73.9% — the model still recognizes the relevant skill as relevant, at any library size tested. The decline appears only once choosing competes with solving the task during execution. That rules out the simplest explanation (the model just can't tell the right skill apart from a thousand distractors anymore) and replaces it with a sharper one this map did not previously carry: implicit, execution-time routing is a second, separable capability from relevance judgment, and it is the one that degrades.

The mitigation result extends this map's serving-stage design clause. This map already argues that what reaches the window and how it's chosen are stages of one pipeline, and that pre-built retrieval structure pays conditionally. Explicit preselection — adding a retrieval step before execution rather than trusting the agent to route implicitly mid-task — recovers recall fully (73.9%), matching the selection-only ceiling exactly. That is a clean instance of this map's acquisition/selection boundary: moving the choice out of execution and into a dedicated upstream stage is what fixes it, not giving the agent a bigger context window or a better prompt. The description-masking result sharpens the mechanism further — hiding only the text of irrelevant skills (not removing them from the library) is nearly as effective as full preselection, which the authors read as evidence the collapse is driven by semantic interference among descriptions specifically, not mere library size.

Interaction edge: agent-harness-architecture and runtime-action-governance — skill libraries at the scale this paper tests (thousands of entries) are exactly the substrate those maps' skill-governance and skill-supply-chain findings (co-installation conflicts, cross-session artifact trust) assume exists; this source supplies the retrieval-failure half of "a large skill library is hard to use safely," independent of either map's trust/security angle.

Bounds: SkillsBench only (82 tasks), one skill-definition format (Anthropic's progressive-disclosure Agent Skills design); preselection methods are compared on coverage/latency trade-offs rather than one being declared universally best; no cross-benchmark replication yet.
