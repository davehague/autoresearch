Both guards are sound, and both are only as good as the sentence someone asked a model to compile

This map arrived at a property on 2026-07-29 and has now watched two independent groups build it: no model in the decision path. APPA evaluates a lattice operation over declared labels before dispatch, proved under an explicitly policy-untrusted model (confine-the-taint-in-a-branch-not-the-parent-context). FAVA runs an SMT solver over an append-only permission graph immediately before any effectful action (an-smt-gate-buys-interception-with-a-false-block-tax). Different formalisms, same architecture, comparable interception.

Read their failure analyses side by side and a pattern appears that neither paper claims on its own. Neither system's residual failures are enforcement failures. APPA's two breaches are contract gaps — the decisive one a store-mediated laundering path through a write tool declared with no sink requirement (prospective-enforcement-is-only-as-complete-as-its-contracts). FAVA's 76 mismatches are all extraction failures, with the solver never wrong about the graph it was given: content quoted in a message labeled as though the agent had generated it, repository-specific obligations that never reached the graph at all, and correct labels attached to coarsely-resolved recipients so a local write looks like an external sink.

So the model has not been removed from the guard. It has been moved from deciding to authoring, and that is where the errors now live. The gain is real and should not be understated — an authoring error is inspectable, versionable, testable and reusable in a way a per-decision inference is not, and FAVA's backend-swap experiment shows the graph validator and authorizer survive changing the extractor. But the authors are careful, and this vault should be too: final compliance "remains sensitive to extraction quality," which supports "a narrower claim than model-independent security."

The shape is one this vault keeps meeting. A verifier built to be narration-blind and state-grounded still inherited the agent's error, because it re-derived from the same source under the same interpretation (a-verifier-sharing-the-interpretation-shares-the-error). Here the guard is structurally independent of the agent's execution — and its policy was written by a model reading the same task description the agent read. Independence of mechanism is not independence of interpretation, now demonstrated one layer further up.

Two consequences for anyone deploying a guard of this kind. The extracted policy is a reviewable artifact and should be reviewed — it is the component the whole guarantee rests on, it is produced once per task rather than per action, and it is the cheapest thing in the stack to put a human on. Whatever budget goes to inspecting agent behaviour is better spent inspecting the permission graph. And provenance is the specific missing primitive: FAVA's largest false-positive family is the inability to distinguish content the agent mentioned from content the agent produced, which is a data-flow distinction the graph does not currently carry. That is the same gap in a different register as the vault's finding that evidence must be bound to the state it describes (bind-evidence-to-the-state-it-describes).

Bounds: two systems, benchmark suites rather than production traffic, and the cross-reading is this vault's synthesis rather than either paper's claim. FAVA's own limitations note that unobserved tool effects, missing data-flow edges and vague human intent all yield false negatives through the same upstream channel, and that the prototype abstracts away concurrency, shell ASTs and TOCTOU races.
