The trajectory records everything and asserts nothing about what's still true

Long-horizon agents accumulate hundreds of actions and observations, but nothing in that record marks which observations still describe the repository as it currently stands. Before every decision the model has to infer execution status from raw history — has this file changed since I read it, did that command already run, is this test result still valid — and when the inference fails, the agent acts on stale content or burns a turn re-doing settled work.

Ledger externalizes that inference into a small deterministic state machine sitting outside the model. Two design choices matter more than the headline numbers. First, the mechanism never calls a model: state transitions are rule-matching over structured trajectory events (a file read, an edit, a test run), so the layer adds zero inference cost and zero prompt-injection surface of its own. Second, the two paths are cleanly separated by what they buy: inform (a compact state summary appended to the prompt) is mostly an efficiency lever — it lets the agent stop re-deriving what it already knows, which is why it carries most of the token and cost savings — while govern (intercepting a proposed command and substituting a cached valid result, or nudging on likely repetition) is mostly a resolution lever, because it changes what the agent is allowed to do, not just what it's told. On GPT-5 mini, govern alone already reaches the full system's Pass@1; on MiniMax M2.5, inform alone barely moves resolution (75.8% -> 77.0%) while govern alone does almost all the work (-> 80.4%).

This lands in context-engineering's persist-and-deliver strand as a new instance of a familiar shape — hold state outside the agent, re-present it where it governs a decision — but with two properties the map's existing persist-and-deliver sources don't share: the persisted object is the agent's own execution status, not a task specification or a set of constraints, and the delivery mechanism enforces rather than merely informs (govern can substitute an action's outcome, not just describe context around it). That puts it adjacent to gate-the-edit-on-evidence-observed-not-claimed in context-retrieval-and-acquisition — both intercept an action deterministically from structured trajectory events with no model in the decision path — but ECLoop gates on whether required evidence was gathered, while Ledger gates on whether an already-gathered result is still valid; the two are complementary stages (haven't looked vs. looked-but-stale) rather than competing mechanisms. [T1 — one benchmark, one language, one primary scaffold, single run per configuration with no seed variance, a fixed hand-tuned rule set rather than a learned policy]
