The regression this map measured, priced as the cost of not having a rejection gate

Two caps sit on this map's self-evolution limb, and both are about acceptance: a proxy judge that prefers outputs which execute cleanly and are wrong (harness-self-evolution-is-capped-by-its-proxy-judge), and an optimizer that fabricates the failure it fixes, defeated by requiring oracle-confirmed failing-episode citations before an edit lands (harness-optimizers-fabricate-failures-to-fix). Alongside them the vault carries the empirical shape of the damage: an evolved skill set regresses about as much as it gains (skills-regress-as-much-as-they-gain, skills-regression-tax).

This puts a number on the fix. The failure mode is named precisely — existing frameworks treat evolution as "a sequence of local updates," so a proposal generated in isolation can invalidate assumptions other skills depend on (the authors' example: tightening a repository-exploration skill to truncate file output silently breaks the downstream analysis skills that assumed complete contents), while a per-failure edit overfits to the case that produced it. Three mechanisms answer it: an explicit Skill Relation Graph co-evolved with the bank, cluster-based consolidation that abstracts reusable capability from local updates rather than admitting each proposal verbatim, and replay-driven verification that rejects an update which regresses prior episodes.

The ablation is the load-bearing result, because it separates the two halves and neither dominates. Removing the relation graph costs 4 and 11 F1 points; removing consolidation-plus-replay costs 4 and 16. So the regression tax is not an intrinsic property of accumulating skills — it is the price of admitting updates without checking what they break. That is harness-optimizers-fabricate-failures-to-fix's warrant-aware acceptance generalized from "cite the failure you are fixing" to "replay the episodes you might break," and it is the same shape as this vault's most reliable engineering advice everywhere else: an admission gate in front of durable state (pre-write-admission-buys-reliability-by-serializing, admit-an-agent-response-per-component-not-whole).

The protocol deserves as much attention as the numbers. Evaluation is one-project-held-out: all cases from one project are held out while the remaining projects evolve the bank, so no evaluated focal method or bug report is ever seen during evolution. That is a genuine generalization design, and it is what this map's downgrade demanded — the 2026-07-18 objection was that harness evolution's published gains were "search compute plus overfitting to the search set," with held-out transfer of +0.6 points (harness-evolution-underperforms-matched-budget-test-time-scaling). Here transfer is the only thing measured, on two coding-adjacent tasks, across two independently-implemented harnesses, plus a deployment on an industrial agent (F1 0.43 → 0.71) whose starting point already beat both open-source agents.

It does not un-contest the map, and the reason is specific. There is no compute-matched control. GSE is compared against other evolution frameworks and against human-authored skills, never against spending the same evolution budget on test-time sampling — which is the exact comparison that produced the downgrade. By this map's own operative rule (ask which distribution the number was measured on, and demand the compute-matched control), this source answers the first question well and the second not at all. The two tasks are also quality-assurance shaped — write a failing test, classify a report — rather than repository-modification tasks, so it does not speak to resolve rates.

The cost accounting is unusually complete for this literature and mildly surprising. Evolution costs +12.28% over the cheaper baseline, but downstream execution is where skills are actually paid for: every skill method raises per-case token consumption over the bare agent by roughly a quarter, and the consolidated bank is the cheapest of the four to carry (+21.2% against +25.4% to +26.8%). Consolidation is a token intervention as well as a quality one — a bank that abstracts instead of accumulating is smaller to load.

One implementation detail worth stealing regardless of the result: the skill bank is versioned with a git worktree, with traces, replay outcomes and update states in SQLite, so concurrent evolution runs cannot interfere and every accepted skill version is reproducible. A self-modifying artifact needs a rollback story; this one has it, which is more than the shipping products in harness-self-evolution-shipped-ahead-of-its-evidence publish.

Bounds. Two tasks, two languages, one underlying LLM for every agent and technique, datasets of 108 and 500 cases, no seeds, run counts, variance or confidence intervals in any cell. IndustrialBugs is proprietary and the internal agent undescribed, so the strongest deployment number is the least reproducible one.
