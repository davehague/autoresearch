The agent's own green check, replayed on the unfixed code

Take every command a repair agent runs after its first edit. Snapshot the working tree at that exact instant, strip out the production changes so only the test artefacts remain, and run the same command again on the original buggy code. If it passes there too, the agent learned nothing about the bug it was assigned.

Do that 3,730 times and 46.0% of the positive results come back blind. Not wrong — the checks run, the assertions hold, the exit code is zero. They simply confirm that the patch did not break anything, which is a different question from whether the patch fixed anything. In 23.8% of baseline rollouts that is the only kind of positive evidence in the trajectory when the agent decides it is done.

The reason this had gone unmeasured is that it is invisible from either end. The benchmark harness looks only at the final patch. Prior trajectory work counted how often agents write tests and found the rate similar in successful and failed runs — abundant, unpredictive, and never evaluated for what the tests actually prove. The gap sits in the middle, and closing it needs a counterfactual the agent never observes: the same check on a state it never visited.

The second number is the one to carry into practice. Of the 1,377 events that behave the way real bug-discriminating evidence should — fail on the buggy code, pass on the candidate — 26.9% also fail on the developer's gold fix. Their discriminating power is a property of the agent's particular patch, not of the defect. Promote such a test into an acceptance gate and it rejects correct alternative repairs. This vault has been arguing hard for exactly that promotion: grade the reproduction test against adversarial mutants (adversarial-critic-rounds-add-kills-over-a-frozen-suite), write it before the fix, and treat fail-to-pass as necessary but not sufficient (fail-to-pass-does-not-constrain-the-fix). This adds the constraint from the other side. A quarter of the tests clearing the fail-to-pass bar are overfitted to the first patch that happened to work — and outside a benchmark there is no gold fix to detect it with.

For ci-cd-for-agents this completes a three-part audit of what a green result means. The human suite frequently never executes the changed line at all (agent-written-tests-miss-the-lines-they-add). A test that does reach it can still admit a patch that suppresses the symptom (fail-to-pass-does-not-constrain-the-fix). And now: the checks the agent runs on its own initiative, which are the ones actually driving its decision to stop, are blind to the bug about half the time. All three failures are cheap to detect and none of them is detectable from inside the trajectory, which is the map's standing argument for measuring the gate from outside the agent (a-passing-suite-does-not-mean-a-tested-change).

The operational move is small. The replay costs 11 seconds at the median, needs no model call, and requires only that the harness retain the base commit and be able to separate test edits from production edits — which any agent runtime that can produce a diff already can. What it buys is not a better test. It is the missing bit of state: whether the green thing the agent just saw is evidence or decoration.

Bounds worth keeping attached. The measurement starts at the first production edit, so exploratory checks written before any editing are outside the population — the authors note this would make 46.0% an overstatement of the trajectory-wide rate. Roles are assigned against the gold fix as reference standard, which is noisy where the gold patch is incomplete or several valid repairs exist. One model family, two Python benchmarks. And the phenomenon is not uniform across models: baseline evidence-inadequate closure is 40.5% on gpt-5.6-terra against 18.9% on gpt-5.6-sol on the same tasks, and falls to 8.3% when the scaffold forces an explicit verification phase — which is itself the cheapest known mitigation and the strongest argument in the paper for structuring the loop rather than instrumenting it.
