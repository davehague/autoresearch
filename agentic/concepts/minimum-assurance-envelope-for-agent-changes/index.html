What should a gate hand an agent making its next change: not everything, not nothing, but the minimum sufficient evidence subset — and getting this wrong silently overcertifies

This map has accumulated a long thread on gate design (blocking strictness, diff-coverage floors, adversarial mutant testing, risk-tiered automation) but has treated "what evidence backs this obligation" as roughly binary — a check passed or it didn't. This source names the harder version of the question underneath: when an agent returns to code with an accumulated history of prior tests, type checks, and analyses, which subset of that history still certifies the specific obligations the next change touches, especially when an obligation requires more than one piece of evidence together (a conjunctive requirement, e.g. "injection detected AND mediated ⟹ commit-safe")? Modeling this as a typed hypergraph rather than a flat checklist is what exposes the failure mode: the FLAT ablation — the natural first instinct of "just keep the tests that are still green" — silently overcertifies exactly where a conjunction was required, at a rate (135/267 evaluations, 3,765 false roots) too high to dismiss as an edge case. The infeasibility result (one Rust obligation has no sufficient envelope in the retained evidence) is a concrete instance of a principle this vault otherwise argues for only informally: a gate should be able to say "I cannot certify this" rather than silently pass with stale or insufficient evidence.

Carried as an open question, not a settled practice. The author is explicit about the gap: no measurement yet of whether an agent given a minimal envelope performs any differently — faster, more accurately, more cheaply — than one given the full evidence history or none at all. Obligations and inference rules are supplied externally; automatic discovery of what a change actually obligates is unsolved. And the benchmark, while real, is synthetic and single-author — the three case studies are illustrative, not a production deployment. The decisive next experiment this map is missing: run agents on real changes with (a) full evidence history, (b) a computed minimum envelope, and (c) no prior evidence, and measure task outcome and cost across the three arms.
