Six thousand comments to find four hundred real ones

The headline of this comparison is the F1 gap. The number a team should actually plan around is 5,980. That is how many review comments one shipped agent produced across 200 pull requests — thirty per PR — to surface 435 findings that matched expert ground truth. Precision 7.23%. Thirteen comments read for every one worth reading.

This is the failure mode reviewer-agent-only-review-halves-the-merge-rate observed from the outcome side (60% of rejected agent-only PRs carrying a signal-to-noise ratio below 30%) now measured at the comment level with an expert-verified denominator. And it is the reason resolution-rate-is-not-precision is a distinction worth keeping: an agent that comments on everything will always look better on recall and always be worse to work with, because the vetting cost lands on the human and can exceed the review it replaced.

The diagnostic value is that the regime belongs to the system, not the model. Across six backends from four providers, the general-purpose agent sits at 7–16% precision and the constrained pipeline sits at 25–38%; the same model moves between those bands when the harness changes. So a team seeing thirty comments per PR should not conclude their model is weak or their diffs are messy — they should conclude their reviewer has no mechanism deciding what not to say. That mechanism is what review-agent-precision-is-a-tunable-not-a-given argues can be set deliberately, and the-checker-should-see-less-than-the-generator is one way to set it.

There is a third regime, and it is not the safe one. Codex's review produced 266 comments at 27.82% precision — respectable precision — but 4.92% recall, apparently terminating early on most PRs. So the two failure directions are both live in shipped tools: say everything and be unusable, or say almost nothing and be invisible. Neither is a tuning failure of the model; both are properties of the loop's stopping behaviour, which is the same variable repair-loops-have-an-interior-optimum identifies inside the repair loop and stop-on-the-sign-of-the-marginal-gain proposes a rule for.

The practical read: instrument comments-per-PR alongside catch rate. It is free to collect, it moves before quality does, and it distinguishes a reviewer that is working from one that is padding.

Bounds. Precision is measured against a fixed expert-verified ground-truth set via LLM-judged semantic matching, so a correct comment about something the annotators did not flag is scored as a false positive — the true precision of every system is higher than reported, and the gap between systems is the durable quantity, not the level. Both baselines run their shipped default review commands with no prompt tuning or rule configuration. No human-preference or downstream-fix-rate measurement is taken, so "worse to work with" is inferred from precision rather than observed; grade-the-reviewer-on-what-the-author-fixed is still the missing arm.
