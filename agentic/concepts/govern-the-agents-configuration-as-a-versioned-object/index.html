You can replay what the agent did; you cannot say what the agent was

This map's argument is that agents should be audited from trajectory-level evidence rather than from outcomes — what was gathered against what was claimed, where the first wrong step happened, whether the instrumentation fails loud. Every result in it assumes something the field has quietly not built: a statement of what the system was configured to be at the moment the trajectory was produced. This names that gap and makes it checkable.

The capability audit is the part worth carrying even if the proposed model never ships. Across five platforms practitioners actually use, prompt versioning is universal, tracing is universal, lineage and evaluation are near-universal — and framework-independent configuration model, configuration graph, immutable baseline, configuration lifecycle, dependency model, governed revisions, state propagation and governance semantics are absent from all five. Not partial. Absent. So the industry standard for "what was this agent" is a versioned prompt plus a trace, which describes one component and one run.

Four design moves are worth stealing independently of the model:

Configuration–runtime separation. Configuration is the intended, versioned structure; runtime is one execution of it. Runtime observations may enrich governance information and may not modify governed configuration. Provenance maps every runtime entity back to the revision that produced it, and the ordered event log replays deterministically. That is the missing half of ground-the-agent-in-state-not-its-rendering, applied to the agent rather than to its task.

Immutable revisions with stable logical identity. A configuration item keeps one conceptual identity while each of its states is separately addressable by revision id and content digest, so "the reviewer agent" and "the reviewer agent as it was on Tuesday" are different, both nameable. This is agent-specifications-are-versioned-engineering-artifacts taken past "commit the markdown too" into an addressing scheme.

Four dimensions kept apart — quality, assurance, impact, eligibility — explicitly so that absence of evidence is not read as poor quality and a dependency's lifecycle state does not propagate to its parent. Only impact propagates. That distinction is one this vault's own status vocabulary makes and most tooling does not.

Semantic projection. Framework-specific interpretation is confined to an adapter boundary; the governance kernel sees a canonical graph. In the evaluation this held across three deliberately different introspection regimes — LangGraph exposes its workflow graph directly, CrewAI cannot be fully introspected statically and needs adapter-declared metadata for part of its topology, the OpenAI Agents SDK exposes delegation through handoffs.

Bounds, and they are the reason this is a design and not a result. The 27 scenarios compare observed behaviour against expectations pre-specified by the same author from the same model — the paper says so, calling it "scenario-based evidence of model coverage and implementation conformance rather than an independent empirical validation." Single author, single organisation, no users, no production deployment, no comparison against a team doing configuration management by hand, and no measurement anywhere that a governed configuration produces better agent outcomes. Three orchestration frameworks, none of them a file-based coding harness — nothing here touches Claude Code, Codex or Cursor, where the configuration is markdown in a repository and the population evidence says it is barely maintained at all (the-project-rule-file-is-written-once-and-abandoned).
