Discovered harnesses transfer off the search distribution — outside coding

agent-harness-architecture downgraded its harness-improvement limb to contested on 2026-07-18 on a specific, well-aimed objection: under matched feedback and inference budgets, harness evolution lost to plain test-time scaling on Terminal-Bench 2.1 and transferred +0.6 points to held-out tasks, so the published gains looked like search compute plus overfitting to the search set (harness-evolution-underperforms-matched-budget-test-time-scaling). That objection has two halves — matched budget and held-out generalization — and this result answers both, in two of three domains, while leaving the third exactly as contested as it was.

Matched budget. Best-of-N is included explicitly as "a compute-matched control for whether search matters at all": independent samples from the seed, same evaluation budget, no search structure. It reaches 34.0 median / 44.2 best; the searched harness reaches 50.0 / 56.7. Structure in the search bought something a dumber use of the same compute did not (charge-every-search-method-the-same-budget).

Held-out generalization. Two clean tests. Nine classification datasets never seen during search: 73.1% average against ACE's 70.2%, best-in-class on 6 of 9, at fewer context tokens — and notably, naively adding more few-shot examples hurt on 7 of 9, so the discovered harness is not just "more context." Then the sharper one: a single retrieval harness discovered on olympiad math with GPT-OSS-20B, evaluated on 200 previously unseen IMO-level problems across five held-out models, improves every one of them, +4.7 on average. A harness that transfers to models it was never searched against is durable scaffolding rather than compensation for one model's quirks — which is the distinction separate-durable-scaffolding-from-model-compensation asks for and rarely gets measured, and it is the opposite result from harness-is-tuned-per-model-and-version's per-model-retuning thesis holding at this layer.

And where it does not. On TerminalBench-2 — agentic coding, the domain where the matched-budget critique was actually measured — search and final evaluation both run on the same 89 tasks. The authors frame this deliberately as a "discovery problem," defend it (public writeups already iterate against this benchmark; the set is small and expensive enough that a split would weaken the search signal), and audit for leakage by manual inspection and regex. That catches copied strings; it does not catch a harness shaped to the task distribution (benchmark-scores-inflate-when-agents-can-retrieve-the-fix, search-time-leakage-inflates-web-agent-scores, constrain-the-eval-environment-to-measure-capability). The 76.4 on Opus 4.6 and 37.6 on Haiku 4.5 are therefore search-set numbers, and the leaderboard they sit in is partly unauditable — the one higher-scoring entry could not be reproduced from its public code (agent-benchmarks-underdisclose-their-harness).

The practical reading for a builder: harness search is now worth trying, and the thing to demand of any result — including this one — is which distribution the number was measured on. Ask for the compute-matched control and the off-distribution transfer; if the answer is "we searched and scored on the same set," you have a discovery result, not a generalization result, and the two are priced differently.

Caveats: one proposer agent (Claude Code on Opus 4.6) across all runs, so the transfer result is itself unreplicated across proposers (the-harness-shifts-benchmark-rank-order). The OOD margin is +2.9 with no confidence interval. The math transfer is a single discovered harness, and the search-set corpus was deduplicated and decontaminated against the evaluation sets by string-prefix filter plus manual inspection — better than most, still not a guarantee. Search cost is reported only as "a few hours of wall clock," with no token or dollar accounting (agent-cost-spans-orders-of-magnitude).
