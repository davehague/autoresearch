A third axis for the allocator

Every allocation result on this map decides between things the model does: which tier answers this turn, how many repair rounds to buy, when to stop paying for a run. the-scaffolding-outspends-the-tool-interface moved the question one layer out — the scaffolding driving the calls is the biggest line item and it is fixed before the allocator wakes up. This moves it out again and gives the layer a price.

The numbers are stark enough to be worth restating plainly. Direct frozen transfer of a GPT-developed control profile to a cheap DeepSeek model is negative (82.7% → 82.0%), so the harness investment here is genuinely an investment and not a copy. $37.02 of provider-specific adaptation, starting from the same runtime, runbook structure, applicable controls and golden rules, takes that model to 88.09% on the full suite under standard timeouts. The complete final-score evidence costs $15.20 in realized API charges. The matched public GPT-5.6 Sol max submission reports $574.68 at a raw score of 83.37%.

The reading for a routing policy: the menu has never been "which model," it has been "which model under which control layer," and the second choice moves both axes of the frontier at once. That is move-task-difficulty-from-the-model-to-the-harness with a receipt — the cheap tier can be manufactured rather than picked off a slate, and here the manufacturing cost is under $40 and amortizes across every subsequent run.

Three things stop this being a clean $-per-point figure. First, the paper is careful that the numbers being compared come from different accounting: its own submission's $1,062.95 is the pipeline's API-equivalent model-cost estimate, while the whole campaign ran on a personal flat-rate Codex Pro subscription using under $125 of a $200 budget. So one side of the headline comparison is metered-equivalent and the other is realized, which is exactly the failure pricing-model-errors-are-invisible-in-the-final-number warns about, disclosed here rather than hidden. Second, the $37.02 is one provider adaptation on one benchmark by authors who had already built the runtime; it is a marginal cost, not a build cost, and the build cost is unreported. Third, the reference row's own adjudication moves it — the $574.68 submission reads 83.37% raw and 76.18% after adjudication, and the 88.8% Sol max figure the DeepSeek aggregate is compared against comes from a different evaluation entirely, which the authors state and plot separately.

There is a second cost fact underneath the headline that this map should carry independently: the extra spend a harness buys is not proportional to what it recovers. harnesses-pay-an-order-of-magnitude-for-the-same-working-set found 144 trials that all pass every test spreading 12.8× in cumulative input tokens, with the expensive configurations recovering nothing extra when facts were withheld. Here the same asymmetry runs in the useful direction: a cheap model under a good control layer reaches a frontier-adjacent score at 1/38 of the frontier's bill. Put together, the two say the token bill is close to uninformative about outcome quality in both directions, which is a bleak thing to say about the field's default cost axis and a very good reason to price the control layer separately from the calls it makes.

Bounds. One benchmark, one provider pair, one cross-provider adaptation, single configurations per cell with no intervals. The descriptive 88.76% aggregate mixes a standard-timeout run with an extended-timeout run for one task and the paper labels it descriptive. No compute-matched control anywhere in the source.
