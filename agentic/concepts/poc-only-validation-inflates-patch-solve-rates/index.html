Checking "does the crash still reproduce" is not checking "was the vulnerability fixed," and the gap nearly doubles every solve rate

PatchBench's core move is methodological: pick vulnerabilities whose true fix sits outside the crash stack trace, then transplant them into new repositories and mutate the surrounding code so an agent can't pass by recognizing the historical fix. Even with pattern-matching suppressed, the gap between "the exploit no longer crashes it" (PoC-only validation) and "the root cause was fixed" (semantic validation) is large and consistent across all 11 agents tested — PoC pass rates run 46.5%–98.1% while root-cause-validated solve rates run 29.6%–59.2%, a 1.83x average inflation. Every single agent's PoC number is comfortably above its real solve rate; this is not a tail effect on weak agents, it holds at the top of the field too (Codex+GPT-5.6 Sol: 97.2% PoC vs 59.2% solved).

The second finding sharpens why: 25% of agent patches are similar enough to the historical developer patch to raise memorization concerns, despite the transplantation and mutation designed specifically to break pattern-matching. Symptom-suppression (patching the crash site without addressing the underlying flaw) and memorization are two distinct ways a benchmark can overcount capability, and PatchBench's design targets the first without eliminating the second.

For evaluation-integrity this is a security-domain instance of the same proxy-validity family as ci-cd-for-agents's and this map's other proxy failures — a cheap, executable-looking signal (the exploit stops crashing) stands in for a harder-to-check property (the actual defect is gone), and the gap is large enough (1.83x) to change which agent looks best. It also extends memorization-probes-saturate-at-scale's territory: transplantation + mutation is a stronger memorization defense than a probe, and it still finds a quarter of patches suspect.

Bounds

Memorization is inferred from patch similarity to the historical fix, not from training-data access — the authors are explicit this raises awareness rather than proving inclusion, especially for proprietary models whose corpora are unknown. No reference-patched repository exists at real deployment time, so PatchBench's semantic validator is a research artifact, not something a production pipeline can run as-is. Scope is C/C++ only. The authors flag their own contamination risk if PatchBench's tasks end up in future training runs.
