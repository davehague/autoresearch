Screen skill files before they enter the context

A skill file is a Markdown instruction document, not source code, so conventional static analysis does not see it — and it arrives over a path (npx skills add, a Git clone, or MCP tools/call / resources/read / prompts/get) that merges it straight into the model's context, where it is already an effective command. There is no later point at which to screen it. That makes install-time screening the only screening point that exists, and this is the first gate for the surface with measured numbers on both sides.

It belongs to this map's layered posture rather than beside it. The architecture is contain-at-the-environment-layer-first and gate-actions-with-a-contextual-classifier-dial moved one step upstream: a deterministic 530-pattern prefilter absorbs two-thirds of the traffic at ~139 ms and defers every verdict to a model that only ever sees bounded windows around the matches. It also extends the closure argument the map reached on 2026-07-28 — the effective permission set is the transitive closure over everything on the path to an action (an-intermediary-on-the-response-path-voids-client-side-gates, least-agency-blocks-an-agent-that-recruits-another-agent). A skill registry is a node on that path that most operators classify as configuration rather than as a capability grant, which is exactly how a fifth of a registry came to be malicious without anyone's threat model updating. The operator surface gains a sixth thing to enumerate, after agents, tools, peers, gateways and stores: the skill and MCP sources each agent may install from.

Carry the recall, not the F1. 0.769 recall means roughly one malicious file in four passes, and the misses concentrate in the encodings the pattern set was not written for — RSA-modular obfuscation, zero-width characters. That is this vault's recurring gate profile: high precision, low sensitivity, a flattering headline metric and a dark side nobody prices (verifier-catch-and-false-alarm-rates-are-measurable). Deploy it as something that lowers a base rate, not as a boundary.

Caveats, and they are heavy: the malicious half is hand-crafted by the authors rather than drawn from the 1,184 real ClawHavoc samples, so recall is measured against the authors' own imagination of the threat and the baselines are scored on the same synthetic corpus. The judge is nondeterministic (per-run false positives 7–20 across three runs); one judge backend only; threshold and window budget fixed on a held-out development set. Explicitly out of scope: post-execution attacks, in-the-wild campaigns, and adaptive adversaries who reverse-engineer the ruleset — which is open-sourced.
