Gate agent commits on the same CI as humans

Sourcegraph's verification stance is deliberately un-special: agents get no relaxed path. "No agent commits land without passing the same checks that human commits have applied." The workflow wraps the autonomous edit/plan/test loop in human-grade gates — review the diff with rigor (read it, run it locally, check unit tests), pass the identical CI, and audit afterward, "treat[ing] the agent like a contractor with commit rights." The motivation is volume as much as trust: 84% of large enterprise accounts saw a steady increase in lines of code after AI rollout, so the human role shifts from writing lines to "steering and verifying many concurrent runs" — which only scales if the gate, not human reading, is the backstop.

This is the CI/CD counterpart to the review-side discipline in review-the-diff-and-search-all-usages and the structural reason the harness world builds an internal evaluator (separate-the-generator-from-the-evaluator): whether the gate is a CI pipeline or a second agent, the principle is the same — don't let the author's self-assessment be the merge criterion.

Rebutted by, and one rebuttal that cuts the other way (added 2026-07-29, connect). Two notes push back and neither was acknowledged here, which left this side of the vault's contested ci-cd-for-agents reading as settled. relax-blocking-gates-when-throughput-is-agentic is the direct contradiction: where agent throughput far exceeds human attention, strict blocking gates flip from safety net to bottleneck, and OpenAI's agent-first repo deliberately runs minimal blocking checks. Note the disagreement is narrower than it looks — both sides agree machines are the backstop; they differ on blocking semantics, i.e. whether every check must pass before merge. And a sharper problem for this note specifically: a-passing-suite-does-not-mean-a-tested-change shows "the same CI as humans" is a null operation wherever the human suite never reached the changed code — a green build on an agentic PR is not evidence the change was tested, so parity with a gate that does not execute the diff buys nothing. Pair it with agent-written-tests-miss-the-lines-they-add and the parity principle needs a precondition: the same CI, plus a diff-coverage requirement the human baseline never had to meet.

The one result that supports relaxation's premise is also the one that undercuts it: ci-reliability-degrades-as-agent-pr-volume-rises prices the load-bearing assumption that a failing check is cheap because a follow-up run fixes it — CI success rate falls as agentic PR volume climbs. tier-the-codebase-and-earn-automation-in-shadow-mode is the third answer neither vendor offered. Nobody on either side has published defect-escape rates, so this stays contested.
