Constrain the review agent at three points and it stops flailing

This map already holds that scoping beats autonomy — run-several-scoped-reviewers-not-one-mega-agent, rank-the-diff-instead-of-commenting-everywhere, review-the-diff-and-search-all-usages. What was missing was a head-to-head against the tools people actually run, on expert-verified ground truth, at a size that settles it. This is that experiment, and the margin is not subtle: every one of six model backends does better inside the constrained pipeline than the best backend does inside a general-purpose coding agent's review command.

Where the determinism goes matters more than how much of it there is. The three injections are placed at points where variance has no upside:

  • Dispatch. Which files get reviewed and against which checklist is resolved by a four-tier rule chain (ad-hoc → project → user-global → built-in language defaults), glob-matched first-match-wins, with explicit replace or merge semantics against the system defaults. The same PR always yields the same assignment. Nothing about triage benefits from creativity, and leaving it to the agent both varies across runs and silently skips files governed by project standards.
  • Exploration. A fixed six-tool set with bounded outputs rather than a shell — capped line counts, capped match counts, a timeout — so no single call can saturate the window. This is restrict-the-tool-surface-to-cut-cost-not-capability measured at production scale, and it is the direct answer to the token-snowball dynamic that the-agent-token-bill-is-a-cache-lifecycle-problem prices from the billing side. Cross-file reasoning survives: file_read_diff exposes other changed files on demand, so the locality bound breaks without unbounded exploration.
  • Anchoring. Comment line numbers are resolved by a three-stage fallback (match against new-side hunks → search the full file → LLM-assisted relocation) instead of trusting the agent's reported location. A finding on the wrong line is a false positive to the human reading it.

Parallelism is chosen at the file level for a stated reason. One monolithic agent over the whole changeset keeps coherence and costs superlinearly in change size; per-hunk partitioning maximizes parallelism and fragments the change. One SubAgent per file is the granularity where a coherent unit of review still fits one context, with cross-file dependencies recovered on demand rather than pre-loaded. That is decompose-and-dispatch-to-parallel-subagents with the unit chosen by the artifact rather than by convenience.

The cost result is the one that changes deployment decisions. 385K tokens against 5,664K, 1m23s against 13m06s, for 2.17× the SEM-F1. Savings come from structuring exploration rather than eliminating it — no triage overhead, no unbounded tool output, no monolithic context accumulation. At that ratio agentic review stops being a premium feature you meter and becomes something you can run on every PR, which is the precondition for everything automated-review-displaces-human-review-at-scale describes.

Bounds. SEM-F1 is adjudicated by an LLM judge (Qwen3-235B-A22B-Instruct, five runs averaged), so a genuinely useful comment matching no ground-truth item counts against the system, and actionability, clarity and severity are unmeasured — the ranking is more trustworthy than the absolute numbers, and the absolute numbers are low (the best system matches a fifth of expert comments). Both baselines are run through their shipped commands rather than tuned, which is the fair comparison for a deployment decision and an unfair one for a capability claim. Ten languages, 50 repositories, no domain-specific languages. Authors are the vendor of the winning system and of the benchmark it wins on — AACR-Bench shares authors with this paper, which is precisely the arrangement an-evaluator-sharing-its-reference-solver-cannot-be-self-checked warns about, and it is not addressed here.
