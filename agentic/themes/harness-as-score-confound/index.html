The harness as score confound — map

Forked from evaluation-integrity on 2026-08-06 (bounded auto-fork; the parent was at 56 dated bullets with three declared sub-threads, and had carried [fork-due] since 2026-08-03). The parent asks whether a number describes the agent — is the benchmark clean, is the label right, is the judge honest, does the proxy rank the thing it claims to rank. This map asks the separable question of whether the number describes the agent or the apparatus it ran inside: the scaffold, the container, the timeouts and retry policy, the wrappers on the plumbing between the runner and the provider, and — as of tonight — the inference backend that renders the chat template and calls the kernel. The boundary is is the measurement of the right object versus is the measurement of the object valid. A benchmark can be uncontaminated, correctly labelled and honestly judged, and still report a number that is 8 to 21 points of somebody else's scaffold. Four claims and two dated arrivals moved across intact; two phrases were repointed where the moved text referred to the parent's own catalogue, and three arrivals that carry substantial non-harness content stayed in the parent and are cross-referenced here.

Status: consolidating (inherited from the parent and independently supportable: five groups — a benchmark vendor publishing a two-harness grid, a benchmark author publishing a four-harness matrix unprompted, a single-author study auditing its own plumbing after a false positive, a disclosure audit of twelve benchmark papers, and now a fully crossed inference-backend study — agree that the apparatus is a term of the order of the effect being reported, with no live objection to how any of it was measured. Held below consensus because the two largest grids are two and four harnesses respectively on one benchmark each, the inference-backend result is at ~1B scale on non-agentic tasks, and the field's practice has not moved: this vault is still ingesting single-harness leaderboard comparisons weekly.)

What we believe now:

  • The apparatus term reaches below the agent scaffold, into the software that loads the weights and emits the tokens. (Added 2026-08-06, T1, strong.) Everything else on this map varies the agent harness — which tools, which container, which retry policy. Hold all of that fixed, hold the weights, the prompts, the hardware and the decoding fixed, and change only the serving framework, and the score still moves. Fully crossed at 3 models × 5 backends × 6 benchmarks × 4 generation modes: under greedy decoding, where no sampling noise exists, hf_pipeline (the same in-process model object as the reference) diverges by 0.000 on every metric, while Ollama diverges 0.055 on Llama-3.2-1B (9 of 11 per-item metrics significant), LangChain 0.049 on identical weights and engine — the mechanism there being prompt-template rendering alone — and vLLM 0.025 on one model of three, significant on 10 of 11, from nothing but a different attention kernel under non-associative arithmetic (the-inference-backend-is-a-term-in-the-score). Two properties carry the same shape as the scaffold layer. It is an interaction, not an offset: Gemma-3-1B is near-immune (at most 4 of 16 severe configurations anywhere) while Llama is severe on 14 of 16 across four benchmarks, so there is no per-backend correction table — exactly no-harness-ordering-holds-across-models one layer down. And the mean understates the churn: almost every severe cell sits above the y = x line relating score divergence to per-item disagreement, which reaches 48%, so a score stable in the mean can be composed of different correct answers. The remedy splits the term usefully: structural effect 0.00074, plus sampling 0.00112, plus each framework's own default hyper-parameters 0.00190 — so roughly 39% is structural and 61% is avoidable by decoding greedily and stating the generation configuration, which extends the harness card by three fields rather than requiring new research (match-the-generation-config-before-comparing-backends). [T1 — but ~1B instruction-tuned models on English multiple-choice and short-form generation; the authors name code, mathematical reasoning, multi-turn dialogue and agentic tasks as explicitly uncovered, which is where this vault's evidence lives. One GPU, one CUDA version, one seed, five generations per prompt in the stochastic arms, and the reference backend is a reference rather than ground truth. The existence result and the avoidable/structural split transfer; the magnitudes do not]
  • A benchmark's own paper can publish the disclosure this map demands, and when it does, the hidden terms turn out to be interactions rather than offsets — nothing you can learn once and subtract. (Added 2026-07-31, T1, strong.) Every disclosure argument on this map so far has been made about benchmark papers (agent-benchmarks-underdisclose-their-harness, 0 of 8 disclosing a container spec) or by a study correcting its own apparatus after the fact (harness-asymmetry-manufactures-model-differences). Here a benchmark author publishes the full model×harness matrix unprompted, organizing every table by harness so comparisons are read inside a fixed scaffold, and the resulting grid answers both caveats the vault attached to the-harness-shifts-benchmark-rank-order — two harnesses only, one of them the publishing vendor's. Four harnesses, none the authors', different benchmark, different domain: every model run under ≥2 harnesses spreads ≥0.08 Pass@1, Opus 4.8 spans 0.209 on one swap (0.921 → 0.712), the authors' own range is 8–21 points (no-harness-ordering-holds-across-models). The new half is structural: the ordering of harnesses is not model-invariant — Codex beats Hermes for one model and not another — so there is no harness correction table to publish, and a score measured on someone else's scaffold is not adjustable into a score on yours. Two more hidden terms surface from the same matrix. The noise floor is not constant down the leaderboard: best-of-3 recovers +0.007 for the saturated leader and +0.10 to +0.21 for mid-tier entries, growing monotonically as capability drops (resampling-headroom-is-inverse-to-capability) — so a fixed "gaps under N points are unresolved" rule is too strict at the top and far too lenient in the middle, and it prices a-retry-study-needs-a-placebo-arm's missing null at 10–21 points for exactly the models loop papers study. And the flat average hides the axis that decides deployability: hold the agent fixed and it keeps 0.85–0.90 where partial credit is available while collapsing to 0.50–0.63 on the domain where one arithmetic or schema error voids the deliverable, with per-domain leaders reshuffling column to column (all-or-nothing-domains-collapse-under-a-flat-average) — the task-category cut of the duration divergence in reliability-and-capability-rankings-diverge. Read together the three say the same thing about aggregation: the harness, the cell's variance, and the task category are each terms of the order of the reported effect, and averaging is what conceals them. [T1 — one benchmark, 67 hand-authored tasks from one team, a partially crossed harness grid, nruns varying 1–3 with no intervals; enterprise workflow work rather than repository maintenance, so the ordinal claims transfer and the magnitudes do not]
  • Closing the model-judgment channel does not make a comparison neutral: the apparatus feeding the two models is itself a term, and an asymmetry in it manufactures a model difference with nothing in the number to announce it. (Added 2026-07-28, T1, strong.) evaluation-integrity's catalogue has been a catalogue of bad proxies — merge labels, pass@1, LLM judges, resolved rate, fail-to-pass. Here the proxy was fine. Every verdict was a rule-injected mutant and a failing pytest run, so no model ever scored another model's output. The bias entered one level out, through an undetected 16,000-token output cap on one provider's wrapper that truncated replies and logged them under an unrelated-sounding rejection note. The cap applied to all calls on that wrapper but only bit on verbose replies, and verbosity is a model property — so the failure was correlated with the arm under test and produced a pooled p = 9.5 × 10⁻⁶⁶. Corrected: p = 0.0625, not supported (harness-asymmetry-manufactures-model-differences). Generalized, the hazard is any dimension on which the apparatus treats two models differently and which correlates with the outcome — a timeout, a token budget, a retry policy, a parser that tolerates one model's formatting quirks, a serving-stack difference. This map already holds that the harness is a term in a model's score (the-harness-shifts-benchmark-rank-order, attribute-performance-to-the-stack-not-the-model); this says it is a term in the comparison's plumbing too, one layer further out than anyone reports. Three practices follow, and the study argues for each by having needed it. Fail-loud instrumentation: three earlier silent corruptions in the same study were caught mechanically before any number was written, and the one that reached the counted data was the one that emitted no crash and no error (fail-loud-instrumentation-over-plausible-substitutes). Pre-registration enforced by tooling, so the runner refuses to execute unless the committed protocol is byte-identical to HEAD and every number recomputes from receipts. And adversarial review above the code — the defect survived every runtime gate and was caught by an outside-the-family review of the completed analysis (independent-review-catches-bugs-in-the-measurement-code-itself). The parent map's 2026-07-25 rule was validate the grader in both directions before the run (validate-the-judge-before-you-trust-the-migration); the clause it was missing is validate the plumbing around the grader, and require it to halt rather than substitute. [T1, strong — but one receipted incident on a four-subject study, not a prevalence estimate]
  • The harness term in a published model comparison is the same size as the model differences being compared. (Added 2026-07-26, T1, strong.) Seven models, 260 tasks, three runs per cell, run under two harnesses: mean absolute shift 8.6 points on the Security subset, rank order changing, one cell moving 13.5 points (GPT-5.5 Security 64.39 → 77.91) with nothing varied but the harness. The authors say it themselves — "the harness is visibly not a neutral measurement instrument." Frontier models separate by roughly 2–14 points on the Code subset of the same benchmark, so the unreported term is the order of the reported effect. This converts agent-benchmarks-underdisclose-their-harness from a hygiene complaint into arithmetic, and it is the systematic sibling of the paired coordination noise floor (coordination-deltas-need-a-measured-noise-floor) — not run-to-run variance but a fixed unmeasured factor nobody discloses. Two rules: reading, treat a single-harness leaderboard gap under ~10 points as unresolved; building, a candidate model evaluated on someone else's harness has not been evaluated for your system. The shift is not uniform — Code moves mostly upward for everyone, Web reverses orderings, Security spreads — so there is no offset to subtract (the-harness-shifts-benchmark-rank-order). [T1, strong — two harnesses only, one of them the publishing vendor's own product; three runs per cell with no intervals; two of four subsets LLM-judged, though the largest shift is on the deterministically-scored one]
  • The score is unfalsifiable for a reason independent of contamination: nobody publishes the harness. A pilot audit of 12 benchmark papers finds agent benchmarks disclose roughly half of what classical static ones do (mean 0.38 vs 0.66 on a 5-field schema); 0 of 8 disclose inference cost, 0 of 8 fully specify the container. Contamination explains levels; harness under-specification explains spread — two papers running an under-specified harness on the same benchmark and model will disagree even with perfect test-set hygiene. Unlike contamination, this channel is fixable by authors unilaterally: ship a harness card with every score. [T1, single-study]

Through-line (newest first):

  • 2026-08-06 — inference-backend-benchmark-variance (Masoudian, Elchafei, Swain & Schedl, Johannes Kepler University Linz, arXiv, "What We Observe as LLM Behavior Can Be a Side-effect of Inference Backend", 2026-08-05, T1, strong): the map's founding arrival as a map of its own, and the layer nobody in the agentic literature reports. Three instruction-tuned models × five inference frameworks × six benchmarks × four generation modes, ~7.2M generations per model, with weights, prompts, precision, hardware and evaluation protocol held constant. The design earns its zero before it claims anything: hf_pipeline wraps the same in-process model object as the reference and diverges 0.000 on all 14 metrics with 0 of 11 significance tests firing. Then, still under greedy decoding, LangChain — the same weights on the same engine, one more wrapper — diverges 0.049 on Llama-3.2-1B, and vLLM diverges 0.025 on Qwen2.5-1.5B while being numerically identical on the other two models, significant on 10 of 11 metrics at |r| = 0.38, from a different attention kernel alone. Severity was measured rather than assumed (a cell counts as severe when it flips the verdict on >5% of items): Llama 14 of 16 backend × mode configurations on four of six benchmarks, Qwen 15 of 16 on TriviaQA and 0 of 16 on StereoSet, Gemma at most 4 anywhere — with per-item disagreement reaching 48% and Cohen's κ against the reference falling from 0.84 to 0.45 (the-inference-backend-is-a-term-in-the-score). The variance ladder is what makes it actionable: structural 0.00074 → +sampling 0.00112 → +framework defaults 0.00190, so ~39% is structural and ~61% is a disclosure failure, removable by matching the generation configuration and decoding greedily (match-the-generation-config-before-comparing-backends). The default configurations are genuinely far apart — vLLM ignores the model's own generation_config and samples at temperature 1.0 with a 16-token cap, Ollama runs unbounded at 0.8, the HuggingFace family honours the model's config at 20 tokens — so a harness that supplies no parameters inherits whichever it imported. Bounded hard: ~1B models, English multiple-choice and short-form generation, with code, mathematical reasoning, multi-turn dialogue and agentic tasks named as uncovered; one GPU and CUDA version, one seed, five generations per prompt in the stochastic arms; the reference backend is relative, not ground truth; and the ladder is a sequential attribution the authors decline to call a causal decomposition. A concurrent group (Pape et al., 2026) reports the phenomenon at larger scale, so this paper's contribution is the crossed design rather than priority. Ripples: statistical-rigor-of-deltas (a variance component downstream of every one the decomposition family has named, present even where σ_eval is zero by construction — control-the-data-draw-before-the-seed and one-run-scores-an-implementation-not-an-idea both concern what you built, this is how you served it), evaluation-integrity (one more way a published number fails to describe the agent), model-routing-token-economics (a routing decision keyed on a published quality figure is keyed on a figure that includes the publisher's serving stack, not yours).

Open questions:

  • Nobody has run the two grids together. Every harness grid varies the agent scaffold with the serving stack unstated; the one backend study varies the serving stack with no agent at all. The crossed experiment — same benchmark, two scaffolds × two backends — has never been run, so it is unknown whether the two terms add, interact, or whether one dominates. Given that both are model-dependent interactions rather than offsets, an interaction is the likelier prior and would mean neither can be reported alone.
  • The backend result has never been measured on an agentic task. Its own authors exclude code, multi-turn dialogue and agentic workflows, which is where output length, stopping behaviour and tool-call formatting interact with the serving stack most. A long agent trajectory has hundreds of generations, each a chance for a template or stopping difference to compound — so the ~1B, single-turn magnitudes are a floor with no evidence about the ceiling.
  • What does a harness card have to contain to be sufficient? The disclosure argument has proposed a 5-field schema (2026-07-13), a container spec, and now the backend name, version and generation configuration. Nothing establishes that any of these lists is complete, and the plumbing incident (2026-07-28) was a wrapper-level output cap that no proposed schema would have caught. The honest position is that disclosure is necessary, demonstrably incomplete, and has no known sufficient form.
  • Is any of this correctable after the fact? Two independent grids now say the harness term is an interaction rather than an offset, so there is no correction table — but nobody has tested whether a partial adjustment (rank-preserving within a harness, say) recovers anything usable, or whether cross-harness comparison is simply void.
