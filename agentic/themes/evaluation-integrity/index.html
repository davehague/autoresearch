The boundary: this map asks whether a number describes the agent (is the benchmark clean, is the harness disclosed, does the judge hold, is the proxy valid); the child asks whether a difference between two numbers survives its own null (paired floors, placebo arms, majority-class baselines, seed-versus-draw-versus-implementation variance, denominators, distribution shape). What we believe now:

  • This map's proxies mostly rank wrong; here is one that is structurally blind, and no amount of strengthening it helps. (Added 2026-08-03, T1, strong.) Hold the task fixed, the model fixed and the generated patch fixed; add a source-level check that fails while the code the repair was meant to remove is still present, and 21.3 points of reported resolution disappear — 86 of 136 attempts (63.2%) pass the original suites, 57 (41.9%) also satisfy the deletion check, every one of four frontier models declining 17.6 to 23.5 points, and 33.7% of the attempts the original suites accept retaining a validated target (passing-tests-do-not-check-that-code-was-removed). The mechanism is one sentence and it is not a calibration failure: a behavioural suite asserts what the code does, and a guard clause preserves behaviour exactly, so the retained path is unreachable for the tested input and there is no test to write. That distinguishes this from everything else on the map. Coverage predicting across models and near zero within one (coverage-stops-predicting-when-the-code-is-buggy), fail-to-pass certifying tests that impose no constraint (fail-to-pass-does-not-constrain-the-fix), resolve-rate gains not carrying quality gains (resolve-rate-gains-do-not-carry-quality-gains) — those are proxies that move, just not with the target. This one cannot see the defect class at all, and the remedies the map currently prescribes do not reach it: adversarial mutant grading asks whether a suite distinguishes the patch from perturbations of the patch, which is a behavioural question a Guard-and-Go patch and its mutants agree on. The generalization worth adopting is a reading rule: the class of defect a gate can catch is fixed by the class of statement the gate can make, and nearly every executable contract in this vault makes statements of one class. The check that closes this gap is not a better test but a different oracle — a static assertion of absence — and 377 of the 500 SWE-bench Verified tasks require at least one deletion from a non-test file, so the affected slice is not a corner. [T1 — the 34 retrofit tasks are deletion-heavy by construction and not representative of Verified as a whole, each worth ~2.9 pp so the drop rests on 29 flipped attempts; the developer patch is a behavioural reference rather than the unique correct repair, and the authors state the retrofit identifies an evaluation gap without establishing that deletion is the only valid fix]
  • The instrument can be wrong in the direction nobody checks — and a benchmark cannot detect it from inside, because its reference answers and its evaluator are usually the same code. (Added 2026-07-31, T1, single-study.) This map's grader discipline is validate-the-judge-before-you-trust-the-migration: pass the original, fail a deliberate defect, and you have demonstrated discrimination. Here is a documented case where both directions were satisfied and the oracle was still wrong about the world. On one held-out case all three evaluated agents identified the same answer, consistent with the case's own inputs; the evaluator demanded a different one that contradicted those inputs. The cause was an off-by-one in the evaluator's domain model, and the reason nothing internal caught it is structural: the reference solver used for self-checking is derived from the same function as the evaluator, so solver and evaluator agreed with each other and the public sample passed (an-evaluator-sharing-its-reference-solver-cannot-be-self-checked). The transferable rule is small and cheap: a reference solution scoring 1 is evidence the task contract is coherent, not evidence the evaluator is correct — two claims benchmark papers routinely report as one, and where the two share code the only external signal is disagreement from something that does not share it. That is an-independent-checker-beats-the-same-model-checking-itself with the correlated component being code rather than a model, and the benchmark-construction sibling of independent-review-catches-bugs-in-the-measurement-code-itself. The method that surfaced it generalizes further and costs nothing, because you have already run the agents: read failures across agents rather than per agent, and treat a unanimous same-way failure as a likely specification or evaluator defect, then confirm by inspection (a-unanimous-agent-failure-flags-a-broken-task). Used during construction it caught a series of spec defects, each validated by correcting the spec and watching the agents recover, and it reported its own false positive (a unanimous failure that was a genuine shared blind spot). Its stated expiry is what makes it safe and it inverts this map's newest finding: the rule discriminates only while honest failure is rare, and benchmark-misalignment-concentrates-in-the-unresolved-tail puts defect density at 41.2% exactly in the unresolved tail where it stops working — so it is a construction-time instrument, not a frontier-audit one, and the tail still needs independent recomputation. Both entries also land on the pessimistic side of the ledger, where this map has only two other members: the agents were right and were marked wrong. [T1, single-study — one receipted incident and an unquantified series of defects from a single unaffiliated author's v0 benchmark, in electric power engineering; existence proof and mechanism, no prevalence]
  • A benchmark's own paper can publish the disclosure this map demands, and when it does, the hidden terms turn out to be interactions rather than offsets — nothing you can learn once and subtract. (Added 2026-07-31, T1, strong.) Every disclosure argument on this map so far has been made about benchmark papers (agent-benchmarks-underdisclose-their-harness, 0 of 8 disclosing a container spec) or by a study correcting its own apparatus after the fact (harness-asymmetry-manufactures-model-differences). Here a benchmark author publishes the full model×harness matrix unprompted, organizing every table by harness so comparisons are read inside a fixed scaffold, and the resulting grid answers both caveats the vault attached to the-harness-shifts-benchmark-rank-order — two harnesses only, one of them the publishing vendor's. Four harnesses, none the authors', different benchmark, different domain: every model run under ≥2 harnesses spreads ≥0.08 Pass@1, Opus 4.8 spans 0.209 on one swap (0.921 → 0.712), the authors' own range is 8–21 points (no-harness-ordering-holds-across-models). The new half is structural: the ordering of harnesses is not model-invariant — Codex beats Hermes for one model and not another — so there is no harness correction table to publish, and a score measured on someone else's scaffold is not adjustable into a score on yours. Two more hidden terms surface from the same matrix. The noise floor is not constant down the leaderboard: best-of-3 recovers +0.007 for the saturated leader and +0.10 to +0.21 for mid-tier entries, growing monotonically as capability drops (resampling-headroom-is-inverse-to-capability) — so a fixed "gaps under N points are unresolved" rule is too strict at the top and far too lenient in the middle, and it prices a-retry-study-needs-a-placebo-arm's missing null at 10–21 points for exactly the models loop papers study. And the flat average hides the axis that decides deployability: hold the agent fixed and it keeps 0.85–0.90 where partial credit is available while collapsing to 0.50–0.63 on the domain where one arithmetic or schema error voids the deliverable, with per-domain leaders reshuffling column to column (all-or-nothing-domains-collapse-under-a-flat-average) — the task-category cut of the duration divergence in reliability-and-capability-rankings-diverge. Read together the three say the same thing about aggregation: the harness, the cell's variance, and the task category are each terms of the order of the reported effect, and averaging is what conceals them. [T1 — one benchmark, 67 hand-authored tasks from one team, a partially crossed harness grid, nruns varying 1–3 with no intervals; enterprise workflow work rather than repository maintenance, so the ordinal claims transfer and the magnitudes do not]
  • The judge does not merely misgrade under pressure — it decouples from task completion when nothing is pressing on it at all, and it decouples exactly above the threshold where you would use it. (Added 2026-07-31, T1, strong.) This map's judge entries are all about optimization: llm-judges-have-exploitable-biases (optimize toward a judge, hack the judge), harness-self-evolution-is-capped-by-its-proxy-judge (a judge in the control loop becomes the ceiling), validate-the-judge-before-you-trust-the-migration (check discrimination first). This is the passive case and it is cheaper to see. Three scoring components run side by side on 1,206 (entry, task) pairs: the two deterministic ones agree at r = 0.85, the judge sits at r = 0.18 against structural grade and 0.13 against the test suite — and conditional on the tasks that actually got solved (grade ≥ 0.5, 81.6% of the population) the correlation goes to r = −0.04. The mechanism is that the judge is not emitting a quality score: 60.1% of verdicts ≥ 0.8, 22.5% ≤ 0.5, only 6.0% in the middle band and 15.4% exactly zero — pass / near-pass / hard-reject, compressing the range before any content of the judgment matters. The disagreement is asymmetric and legible (132 pairs at grade ≥ 0.8 with judge ≤ 0.4 against 97 the other way, the over-penalized cluster being long-form generative output judged on fluency), and even at grade = 1.0 mean judge is 0.70 (a-judge-decouples-above-the-completion-threshold). The constructive half is the authors' own and belongs in this map's ledger of instruments that fail in different directions: the judge is unusable as a ranking metric and is the only component sensitive to semantic degradations that pass every deterministic check. [T1 — and the caveat has teeth: the judge model is never named, nor its decoding settings, in a paper whose central argument is that a score without its apparatus is not meaningful]
  • The defect can be in the instance, not the metric — and it concentrates exactly where capability claims point. (Added 2026-07-31, T1, strong.) This map's catalogue is proxies that misgrade optimistically. Here the flaw sits upstream of the agent and the metric, in how the instance was built, and it grades pessimistically: pairing a merged pull request with its linked issue assumes the PR addresses exactly that issue and the issue fully specifies the PR, and a hand-audit of all 500 SWE-bench Verified instances finds 13.6% violating it across five patterns — gold patches that were themselves buggy or incomplete (44.1% of the misaligned), PRs bundling unrelated work (32.4%), issues whose real requirements were settled later in the discussion thread (26.5%). The distribution is the finding: misalignment falls monotonically with how many agents solve an instance, from 41.2% of the 34 instances no leaderboard agent ever resolved to 5.7% of those resolved by over a hundred (benchmark-misalignment-concentrates-in-the-unresolved-tail). Two-fifths of the residual everyone points at when arguing how far agents are from real maintenance work is a broken brief. And the ranking is not stable to fixing it — excluding the 68 defective instances moves 64.1% of 131 agents and 9 of the top 10 positions, with per-agent movement spread −0.24 to +4.49 pp, so the defect behaves like a per-agent bias rather than a shared offset (removing-defective-instances-reshuffles-the-leaderboard). Human curation helps only where a curator can see the problem in the task text (unspecified literals 15.9% → 3.0%, incomplete specs 14.0% → 4.3%) and leaves the cross-PR relationship defects flat at 6–8% across curated and uncurated sets alike. [T1, peer-reviewed at ASE '26 — prevalence from two annotators coding the corpus that generated the taxonomy; the leaderboard recomputation is explicitly not causal, and no same-configuration noise floor was measured against it]
  • The audit of a benchmark can be automated for flaws that leave their evidence in the transcript, and not for flaws that require knowing what the benchmark meant. (Added 2026-07-31, T1, strong for the unevenness.) Every defect above was found by a human reading transcripts, and a single evaluation run can produce 100 million to a billion tokens. Four scanners built on the Agentic Benchmark Checklist and frozen before a held-out set, validated against five human graders over 742 transcripts from five widely-used benchmarks, split cleanly by that criterion: guessing vulnerability is self-contained in the transcript and reaches sensitivity 0.93 at F1 0.74; tool failure requires deciding whether a broken command is a defect or an intended obstacle, and gets F1 0.27 at best with one scanner model showing no discrimination at all; ground-truth access and format ambiguity land between at F1 0.30–0.50 (benchmark-flaw-detection-is-uneven-by-criterion). So "we scanned it and it looks clean" is four claims of wildly different strength, and an automated audit should be priced as lowering a base rate, not clearing a class — the same high-precision / low-sensitivity profile this vault keeps finding in gates (a-deterministic-prefilter-makes-a-model-gate-affordable, verifier-catch-and-false-alarm-rates-are-measurable). Two cheap levers: the scanner model is a first-class variable (the two frontier models differ up to fourfold on the same criterion, and exploiting their disagreement beats either — a max rule buys sensitivity, an agreement rule buys specificity to 0.96–0.98), and the audit's cost is now known (≈75 human-graded or ≈120 scanner-graded transcripts to rule out a >5% violation rate; ≈1,000 screened to estimate a scanner's own sensitivity). The scanners' findings also deliver this map's first non-vendor replication of the retrieval channel — prompts quoting the gold patch including which files to change, and models reading upstream git history containing the human patch and implementing it verbatim, independently confirming benchmark-scores-inflate-when-agents-can-retrieve-the-fix. [T1, explicit proof of concept — scanners not elicited to their ceiling, human labels themselves subjective in places, four of eleven suitable criteria built, wide sensitivity intervals]
  • Closing the model-judgment channel does not make a comparison neutral: the apparatus feeding the two models is itself a term, and an asymmetry in it manufactures a model difference with nothing in the number to announce it. (Added 2026-07-28, T1, strong.) This map's catalogue has been a catalogue of bad proxies — merge labels, pass@1, LLM judges, resolved rate, fail-to-pass. Here the proxy was fine. Every verdict was a rule-injected mutant and a failing pytest run, so no model ever scored another model's output. The bias entered one level out, through an undetected 16,000-token output cap on one provider's wrapper that truncated replies and logged them under an unrelated-sounding rejection note. The cap applied to all calls on that wrapper but only bit on verbose replies, and verbosity is a model property — so the failure was correlated with the arm under test and produced a pooled p = 9.5 × 10⁻⁶⁶. Corrected: p = 0.0625, not supported (harness-asymmetry-manufactures-model-differences). Generalized, the hazard is any dimension on which the apparatus treats two models differently and which correlates with the outcome — a timeout, a token budget, a retry policy, a parser that tolerates one model's formatting quirks, a serving-stack difference. This map already holds that the harness is a term in a model's score (the-harness-shifts-benchmark-rank-order, attribute-performance-to-the-stack-not-the-model); this says it is a term in the comparison's plumbing too, one layer further out than anyone reports. Three practices follow, and the study argues for each by having needed it. Fail-loud instrumentation: three earlier silent corruptions in the same study were caught mechanically before any number was written, and the one that reached the counted data was the one that emitted no crash and no error (fail-loud-instrumentation-over-plausible-substitutes). Pre-registration enforced by tooling, so the runner refuses to execute unless the committed protocol is byte-identical to HEAD and every number recomputes from receipts. And adversarial review above the code — the defect survived every runtime gate and was caught by an outside-the-family review of the completed analysis (independent-review-catches-bugs-in-the-measurement-code-itself). The map's 2026-07-25 rule was validate the grader in both directions before the run (validate-the-judge-before-you-trust-the-migration); the clause it was missing is validate the plumbing around the grader, and require it to halt rather than substitute. [T1, strong — but one receipted incident on a four-subject study, not a prevalence estimate]
  • A proxy can be honest at one granularity and uninformative at the next, and the field reports only the granularity where it looks good. (Added 2026-07-28, T1, strong.) Same corpus (8,268 machine-written suites, 11 models, 318 Defects4J focal methods), same relationship, three views: coverage predicts real-bug detection at r = 0.861 across models, 0.190–0.481 pooled, and below 0.2 within a model. So it is a valid model selector and a near-useless suite ranker — and the literature it replicates reported the pooled view only (proxy-metrics-rank-models-not-suites). This joins the map's disclosure rules as a peer of reporting the harness (agent-benchmarks-underdisclose-their-harness), the paired noise floor (coordination-deltas-need-a-measured-noise-floor), the majority-class baseline (skewed-label-bases-inflate-classifier-headlines) and the attempt denominator (scoreable-runs-are-a-separate-denominator): a coefficient without the frame it was computed in cannot be checked. A second, sharper corollary about replication itself: both replicated originals identified test suite size as the dominant confound, and here it explains nothing (r = 0.031) — because their confound was an artifact of their sampling protocol (draw k tests from a project-wide pool), not a property of tests. Re-derive a study's confounds when you carry it into a new generation regime; do not inherit them. [T1, strong; Java/Defects4J, one prompt template, 13 points for the inter-model view]
  • The harness term in a published model comparison is the same size as the model differences being compared. (Added 2026-07-26, T1, strong.) Seven models, 260 tasks, three runs per cell, run under two harnesses: mean absolute shift 8.6 points on the Security subset, rank order changing, one cell moving 13.5 points (GPT-5.5 Security 64.39 → 77.91) with nothing varied but the harness. The authors say it themselves — "the harness is visibly not a neutral measurement instrument." Frontier models separate by roughly 2–14 points on the Code subset of the same benchmark, so the unreported term is the order of the reported effect. This converts agent-benchmarks-underdisclose-their-harness from a hygiene complaint into arithmetic, and it is the systematic sibling of the paired coordination noise floor (coordination-deltas-need-a-measured-noise-floor) — not run-to-run variance but a fixed unmeasured factor nobody discloses. Two rules: reading, treat a single-harness leaderboard gap under ~10 points as unresolved; building, a candidate model evaluated on someone else's harness has not been evaluated for your system. The shift is not uniform — Code moves mostly upward for everyone, Web reverses orderings, Security spreads — so there is no offset to subtract (the-harness-shifts-benchmark-rank-order). [T1, strong — two harnesses only, one of them the publishing vendor's own product; three runs per cell with no intervals; two of four subsets LLM-judged, though the largest shift is on the deterministically-scored one]
  • Contamination now has a lever upstream of the run — reverse-engineer tasks from private artifacts so the searchable prompt never existed — and nobody has measured whether it works. (Added 2026-07-26, T1, suggestive.) Every prior remedy on this map operates at run time and stops the agent reaching the answer. None touches the channel that survives a sealed container: the task text itself sitting in training data. Building every task from a real commit, PR or business scenario and rewriting it as a colloquial role-played request closes that path independent of release timing, which is why the same benchmark can ship environments, tests and reference solutions publicly. Adopt it — it is nearly free — but record it as a design argument, not a result: no leakage number, no counterfactual against a public-issue-derived set, no memorization probe, and the authors concede both live channels (the underlying commit may already be in training data; the public release will be scraped). By this map's own 2026-07-13 rule — prevalence is not inflation, measure the counterfactual — the validating experiment is cheap and undone (build-tasks-from-private-artifacts-not-public-issue-text). [T1, suggestive — the paper's central claim is untested by its own authors]
  • Build the grader before the run and validate it in both directions — it must pass the original and fail code you broke on purpose. (Added 2026-07-25, T2 practice.) Every other remedy in this map is retrospective: read transcripts, replay the reference patch, find the majority baseline, measure a floor. This is the same discipline moved upstream and stated as a prerequisite of doing the work — the protocol from two production migrations is to categorize the existing tests, rewrite the portable ones, then verify the judge in both directions before translating a line. The skipped direction is the second: a grader that passes the original is trivially satisfying, and only one that also fails a deliberate defect has demonstrated discrimination — the property that decides whether the loop it governs has positive value at all. It is also the control that would have caught both of this map's self-improvement failures (harness-self-evolution-is-capped-by-its-proxy-judge, harness-optimizers-fabricate-failures-to-fix). Unimplementable where no oracle exists, which is exactly the unlabeled setting those two describe (validate-the-judge-before-you-trust-the-migration). [T2, suggestive]
  • A new failure shape: a proxy that grades honestly and is read as a claim it never made — and the comparison that manufactures the difference is the un-matched one. (Added 2026-07-24.) Everything else in this catalogue is a proxy that misgrades the agent, always optimistically. Resolved rate is not broken. It measures functional repair, correctly, and is then reported as model progress — a claim about the code rather than the count. Hold the tasks fixed and the code does not improve: on instances two generations both resolve, the median paired difference is 0.00 for CodeQL and CodeScene in both model families and across all four models, nothing survives Holm correction per-rule or per-category, and the later models use slightly more CPU and peak memory (Claude +0.048 s, +4.524 MiB, r = 0.93; ratios ≤1.02). The methodological artefact is the transferable half: on the full resolved sets — each model scored on the instances it happened to solve, i.e. how every leaderboard comparison is built — CodeQL showed p = 0.039; match the instances and it vanishes, because the sets are different populations (57 of 71 shared Claude instances from Django; 31 of 62 later-model-only from SymPy). A difference attributed to model quality was task composition. The remedy is not a better instrument — it is match, then compare. And the paper does something rarer that this map should cite it for: because most paired differences are literally zero (66/71 and 52/56), it reports the smallest two-sided p-value its own test could have reached (~0.063 and ~0.125), stating that p = 1.000 "did not constitute evidence that the two models were equal." Null result and null instrument, separated and both published — the same discipline as skewed-label-bases-inflate-classifier-headlines and coordination-deltas-need-a-measured-noise-floor (resolve-rate-gains-do-not-carry-quality-gains). [T1, strong on the null and the matching artefact — pairs differ in tier as well as release date, so each comparison is a case study; SWE-bench Lite, Python bug repair only]
  • Some under-measurement is a budgeting failure, not an epistemic one. (Added 2026-07-20, T1 suggestive.) Practitioners who have made evaluation the mechanism that steers development (82% agree) report the signal is untrustworthy on four axes — invalid, unstable across identical runs, gamed within a quarter, and prohibitively expensive: the environment build is the work, "what you output is just a dataset and a score," and per-commit evaluation is priced out. The first three are this map's existing content confirmed by a new method; the fourth suggests part of the remedy is organizational (fund and credit the environment) rather than methodological, and explains why the disclosure gap persists — nobody is paid for the part that would close it.
  • Every cheap proxy for agent quality misgrades the agent, and they fail in the same direction — optimistic. Four independent T1 measurements, four different proxies: the repository's merge/reject label (only 35.7% of rejections are genuine agent failure; 15.4% of merges embed human repair), the outcome pass rate (agents with similar pass rates differ widely in process defects and controllability), the LLM judge (reproducibly gameable under optimization pressure), and the agent's own self-report (91.49% of visible misalignment resolutions required explicit user correction, and inaccurate self-reporting grows as a share of failures as models improve). [T1] Refinement (2026-07-12): the optimistic bias belongs to proxies under selection or optimization pressure. Plain instrument bugs misgrade in whichever direction the bug points — a broken grader buried 53 points of one model's CORE-Bench capability (42% → 95% after eval fixes + scaffold change). Either way the remedy is the same: audit the eval and read transcripts before believing the number. [T2]
  • The benchmark score is a proxy too, and it is contaminated at a magnitude that exceeds the model differences it is used to demonstrate. 63% of a frontier agent's successful SWE-bench Pro resolutions retrieved the fix rather than derived it — upstream web lookup in 57% of trajectories, git-history mining in 9%. Constraining the environment costs 14.1 points (Opus 4.8 Max) and 20.7 points (Composer 2.5). A leaderboard gap of a few points, measured permissively, carries no information. [T2] Replicated 2026-07-13 by an independent group in a second domain (deep-research agents, medical QA), with the map's first graded severity scale (metadata / question-context / explicit-answer leakage) — and a magnitude split that teaches: leakage is rampant (up to 60–78% of questions on some agent/benchmark pairs) while measured inflation is ~4 points, because saturated parametric baselines leave retrieval little headroom. Prevalence and inflation are different quantities; only the counterfactual (block the channel, re-measure) licenses an inflation claim. [T1]
  • The score is unfalsifiable for a second, independent reason: nobody publishes the harness. A pilot audit of 12 benchmark papers finds agent benchmarks disclose roughly half of what classical static ones do (mean 0.38 vs 0.66 on a 5-field schema); 0 of 8 disclose inference cost, 0 of 8 fully specify the container. Contamination explains levels; harness under-specification explains spread — two papers running an under-specified harness on the same benchmark and model will disagree even with perfect test-set hygiene. Unlike contamination, this channel is fixable by authors unilaterally: ship a harness card with every score. [T1, single-study]
  • Measurement integrity is an infrastructure problem, and its primitives are the containment primitives. Deterministic environment controls — strip .git and reinitialize as a single commit; deny egress by default behind a pinned registry allow-list — are what make a score mean something, and they are the same mechanisms runtime-action-governance uses to bound a production run. Report the harness with the number, or the number is unfalsifiable. [T2]
  • Replication does not certify a corpus, and treating it as if it does is this map's own blind spot. A systematic fault in how evaluation items were constructed is inherited by every replicate, so larger N, a converging mechanistic story, and even a controlled manipulation can all confirm an effect that does not exist — documented end-to-end in one case where a shared decoding parameter fabricated a 32-point judge gap that survived N=50→N=500 and a producer-swap experiment, then vanished to ceiling on correction. The structural remedy is to prefer oracle-bearing corpus designs: negatives produced by deterministic perturbation of a gold answer are checkable item-by-item for free, while LLM-generated negatives are not checkable at all by any aggregate statistic. Where the oracle-less design is unavoidable, read 15–20 raw items per condition and report length and degeneration rates before computing anything. [T1, single-study — demonstrated outside agentic coding (multilingual faithfulness judging); the argument transfers, the magnitudes do not.]
  • The trustworthy signal is the trajectory, not the endpoint. An aggregate score cannot reveal that 57% of runs went to the public web; only the transcripts can. Auditing claims against the evidence the run actually gathered is a measurement practice, not just a debugging one — which is why the localization work in observability and the defect ontology in ProcCtrlBench are the constructive half of this map. [T1] Emerging instrument (2026-07-15): "trajectory not endpoint" gets a candidate metric on the evidence side — reconstructability, asking per claimed decision whether the captured trace is sufficient to reconstruct the decision the claim depends on, plus a claim–evidence overclaim gap. Two evals can report identical surface numbers on traceable vs hollow evidence; on real public traces the replay precondition was unmet in every case. The construct fits and the direction (surface numbers outrun their evidence) is the map's own — but it is single-author, n=4, agent-safety evals not coding benchmarks, so the vault carries the instrument and direction, not the magnitudes, and it moves no status (measure-whether-evidence-reconstructs-the-claim). [T1, single-study]
  • The first criterion in this map that is grounded in a human action, rather than a model's opinion. The lesson is specific and load-bearing: replication defends against sampling noise and does nothing against a systematic fault in how the items were constructed, because every replicate inherits it. The constructive half is the taxonomy — a corpus built by deterministic perturbation of a gold answer carries a free item-level oracle (their positive control caught an injected 30%-rate fault at 100% accuracy with a string comparison, 0 API calls, 0 human reads); a corpus whose negatives are LLM-generated carries none, and a degenerate generation is surface-identical to a merely short one. The protocol that follows is cheap enough to adopt unconditionally: read 15–20 raw items per generation condition and report mean length plus verbatim-repeat and filler rates before computing any aggregate. Scope discipline, stated plainly: the domain is Turkish/English faithfulness judging on wiki40b, not agentic coding — the vault carries the oracle argument and the validation protocol, and explicitly does not import the 32-point magnitude, the 0.64/0.96 accuracies, or κ=0.041 into any agent-benchmark claim. Relevance here is real but structural: this map's sources increasingly rely on synthetic negatives and injected failure classes, which is exactly the oracle-less regime. Open questions:

  • STANDING ADVISORY (2026-07-20) — check AIDev's base rate before believing an accuracy-shaped claim computed on it. The corpus's merge label is ~92% positive (inferable only from a majority-class baseline row; never stated outright in the source that revealed it). This vault already cites AIDev-derived work (dev-vs-agentic-prs-merge-factors, predicting-pr-acceptance-review-effort). Odds-ratio and explanatory-power claims are unaffected; accuracy, F1, and "prediction is feasible" claims are not. No re-grading applied this run — flagged for David.
  • NEW 2026-07-14 — the noise floor has been measured exactly once, on one model and one benchmark, and the field needs it everywhere it argues. The protocol is cheap (pair two configuration-equivalent arms, measure the gap before the mechanism can act) and the result was ≲15 pp on τ²-bench/Haiku 4.5. The authors are emphatic that it does not transfer, and their own probes show it swinging from ≈0 pp to 20 pp across model/domain — which means the number is useless second-hand and the measurement is mandatory first-hand. The urgent instance: nobody has floored SWE-bench, where loop-engineering's two counterexamples (+8.3, +9.3–10.5 pts) and much of the harness literature's evidence live. One paired re-run would tell us whether an entire contested map is arguing over signal or variance.
  • NEW 2026-07-14 — can a self-improving system be bounded by its own selector, and is anyone measuring it? TTHE publishes a 20-point gap between what its judge commits (50%) and what was reachable (70%). That gap is only visible because the authors ran post-hoc oracles with gold, purely as a diagnostic. Every deployed self-evolving harness has this gap and no way to see it. Open: does the gap widen or narrow with more generations (correlated-blind-spot compounding says widen); and is there any label-free signal that detects judge miscalibration in-flight, or is a periodic gold-labeled audit the only option? Nobody has run an adversarial arm — a harness actively optimizing to fool its own judge — so the worst case is unmeasured, not absent. Partially answered 2026-07-16, and the answer is worse than the question: fabrication needs no adversary. A controlled micro-lab shows the optimizer inventing failures to fix under failure-presupposing instructions alone (15/60 vs 0/60), invisible to suppression-only acceptance by construction; warrant-aware acceptance (oracle-confirmed citations required per self-edit) eliminates it (harness-optimizers-fabricate-failures-to-fix). Still open: whether warrant-style acceptance is implementable where no oracle exists — which is the unlabeled setting's defining condition.
  • The map's sharpest evidence (benchmark contamination) is single-org T2 on competitors' models, self-audited. Partially closed 2026-07-13: an independent group ran the same block-the-channel counterfactual in medical QA and confirmed the direction — but the magnitude came out ~4 points, not 14–21, so the coding-domain decomposition (63%/57%/9%) still stands on one org's self-audit. The remaining ask is narrower: a second org repeating the constrained-harness experiment on an agentic-coding benchmark specifically.
  • The prevalence≠inflation split raises its own question: is the small medical-QA inflation a ceiling effect (parametric baselines saturate) or a domain effect (MCQ answers are guessable where patches aren't)? If ceiling, contamination inflation should grow as benchmarks get harder — which would make the freshest, hardest benchmarks the most inflated, an ugly selection effect nobody has tested.
  • Nobody has established what the constrained score is a good estimate of. A strict harness may under-credit legitimate documentation lookup — real engineers read the docs. The correct baseline for "derived the fix" is undefined, so the 73.0% is a different number, not obviously a truer one.
  • No cross-proxy study exists. If merge labels, pass rates, judges, self-reports, and benchmark scores all misgrade, do they misgrade the same agents in the same direction? An agent that games benchmarks may or may not be the agent whose PRs embed human repair. Until someone measures several proxies on one population, "triangulate across proxies" is a plausible heuristic, not a validated one.
  • The vault's standing fleet-quality gap lives here now: process-defect scores, control-preservation scores, and review-theme distributions are all instruments, and not one has been linked to downstream shipped-defect escape. Instruments without a criterion are a measurement proposal, not a measurement. Narrowed 2026-07-11: resolution rate (grade-the-reviewer-on-what-the-author-fixed) is the first criterion — its ground truth is a change a human chose to make to their own code, which is expensive to fake and exists whether or not anyone is evaluating. It still is not defect escape, and it has no false-negative side, but the gap is now "link the criterion to escape" rather than "find a criterion at all."
  • A benchmark number can now be wrong in two directions at once, and this map should say so. loop-engineering's 2026-07-11 counterexample (icat-agent, +8.3 pts on SWE-bench Pro) is scored on the benchmark this map knows is retrieval-contaminated at 63% — and the winning scaffold's distinguishing behaviour is exploring harder before patching, which is what a better retriever looks like. Nobody can currently tell a scaffolding win from a retrieval win on SWE-bench Pro. That is not a footnote about one paper; it means the contested question in loop engineering cannot be settled on the benchmark everyone is using to argue it.
  • Contamination is a moving target: constraining egress and history defeats today's retrieval channels. Task instances still leak through training data, and no one has quantified that channel for benchmarks built from public repository history.
