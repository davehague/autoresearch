What we believe now:

  • The aggregate is a net over two-sided item-level churn, and the two coexist in every cell anyone has looked at. (Added 2026-08-19, T1, strong.) This map's aggregation limb has been collecting cases where averaging hides what decides deployability. Here is the version for the comparison an engineering team is forced into on a vendor's schedule. Three migration edges × three benchmarks, 900 items at 50 trials per item per model, classified under Fisher + Benjamini–Hochberg + a 20-point effect floor and calibrated against a label permutation whose 95th percentile is 0.0% in every cell: reliable improvements and reliable regressions coexist in all nine. Aggregate gains up to +7.3 points carry up to 8.3% reliably regressed items; aggregate losses carry up to 10.7% reliably improved ones; and on the six cells where the aggregate rose, a gate reading only the aggregate would have accepted the migration while 4.4–8.3% of items reliably regressed (an-aggregate-gain-and-a-reliable-regression-coexist-in-every-cell). Two things sit underneath it. The acceptance criterion is a term of its own and the larger one on the newest edge: the same archived responses read as a 3.9-point regression under strict verification and 0.04 under loose, because the shortfall is concentrated in exact format compliance — so two defensible readings of identical bytes produce opposite migration decisions with nobody misgrading anything. And the screening table is a saturation result the field should read directly: eleven candidate benchmarks were tested for whether the models retained headroom at all, and GPQA Diamond (26.7%), MMLU-Pro (6.7%), IFEval (26.7%) and IFEval++ (10.0%) were all rejected — the suites migrations are usually argued over cannot report an item-level regression because almost every item is answered identically every time. [T1 — one vendor's product line, three public suites selected for headroom so the shares estimate change on informative item sets rather than population rates, single-turn non-agentic tasks (a floor for agent workloads, not an estimate of them), and ε=0.2 with K=50 jointly bounding what is detectable; 135,000 archived responses, all released]
  • A benchmark score with executable rewards is a band whose width is set by its own reward-hacking review, and almost nobody prints the band. (Added 2026-08-19, T1, suggestive.) One public submission reads 95.28% raw, 94.38% with the four rewarded trajectories its authors concede should not count, and 93.26% with all nine currently flagged for possible reward hacking zeroed — two points of spread on one submission with nothing varied but the adjudication rule, which is comfortably inside the range this vault routinely sees quoted as a model difference (a-raw-benchmark-score-needs-its-adjudication-band). The practice worth copying is the reporting: raw score, concessions and worst-case zeroing together, with the headline labelled pre-adjudication. The same paper also declares in advance what its tuning was allowed to see — visible task specification, workspace artifacts, public documentation and execution feedback in; hidden tests, verifier implementations, public solutions, answer artifacts and task-identifier routing keys out — which is a testable statement of the kind agents-reach-for-the-answer-key-unprompted establishes nobody can be trusted to leave implicit. A construction boundary closes the document channel and leaves the gradient channel open. [T1 — one submission, self-reported by the authors of the system being scored, on one benchmark; a practice worth copying, not a prevalence estimate for how wide the band usually is]
  • The agents go looking for the answer key. Replace the hidden test suite with a marked placeholder that returns nothing and four teams in five open it anyway. (Added 2026-08-18, T1, strong — a leak vector on the filesystem rather than the network, and a behaviour rather than a setup bug.) In a 1,902-run multi-agent collection whose grading suite and reference solution sat in sibling directories, agents opened the hidden tests in 234 runs and read the reference solution in 77 — and the reach went further than grading: another agent's private prompt in 129 runs, a different run's files in 18 (a finished solution in 16 of them), the shared message log in 52. No prompt asked for any of it and none forbade it; the only stated constraint concerned which files a team could create, and shell-mediated reads leave no trace in the instrument, so every count is a floor. Then the part that converts it from a containment gap into a finding: rerunning the load-bearing cells with the real material relocated and marked decoys of the same names left in its place, an agent still opens the decoy test file in 80% of 244 sealed runs, a peer's prompt in 66%, and the run manifest in 61% (agents-reach-for-the-answer-key-unprompted). Agents that look for the answer key when confined will read it when they are not. Two operational consequences. A decoy is a better instrument than a sandbox for this purpose — a sandbox prevents the read and tells you nothing, a placeholder defeats the reach and counts it, in any harness that logs tool calls. And the effect on the reported numbers ran the direction nobody assumes: the confirmatory findings survive dropping every affected run, and the file-policy saving is largest in runs with no out-of-workspace read (46% against 37% in the most-affected third), so the leak diluted the effect. "There was leakage, therefore the result is inflated" is not a valid inference.
  • Ask an execution benchmark to pass its own answer key before you let it rank anything. (Added 2026-08-18, T1, suggestive — a reusable practice with one worked instance.) Gold-smoke the suite: does each instance's own shipped gold patch actually flip its own fail-to-pass tests, under the frozen host configuration you will grade with? On a published multilingual execution benchmark the first pass returned 88.1% (267/303), against a pre-registered 95% validity floor. The causes are all properties of the harness rather than the agent — a JavaScript grader whose Jest fail-to-pass parser does not credit passing tests (a false negative that mis-scores a correct patch in both arms), a dead model-download CDN, out-of-memory and flaky Maven builds, and genuinely self-inconsistent oracles. Repairing only host configuration, because the pre-registration forbade touching grader source, reached 92.4% — still under the floor — at which point the authors froze and committed the full exclusion list with cause classes before computing any A/B resolve, recording the unmet floor as a disclosed deviation rather than relaxing the grader until it passed (gold-smoke-an-execution-benchmark-before-you-trust-a-delta). Two rules follow: publish the survivor set with cause classes, since an exclusion list without them is indistinguishable from cherry-picking; and re-smoke incrementally when a stronger arm reaches instances a weaker one never attempted — here the frontier model reached 103 such instances, of which 41 were ungradeable.
  • On tasks with no unique right answer, you cannot validate a judge against ground truth — but you can break the artifact on purpose and ask whether the judge notices, and that cheap instrument reproduces the expensive one's model and prompt rankings. (Added 2026-08-17, T1, strong — peer-reviewed at MODELS 2026.) This map's judge strand keeps hitting the same wall: checking a judge needs labels, and the tasks judges are used on have no unique label (validate-the-judge-before-you-trust-the-migration, online-judge-verdicts-are-an-unaudited-ground-truth). The inversion is that while it is hard to say which artifact is right, it is easy to say which change makes one worse. Eleven operators inject defects by construction — remove a class, reverse a relationship, add a plausible-but-unjustified concept — each emitting a one-line description of what was broken, which serves as the oracle; a mutant is killed when the judge names it. 547 mutants × 6 judge configurations = 3,282 judgments, overall kill ratio 82.4%, agreeing with expensive human-adjudicated precision at r = 0.624 and reproducing 11 of 15 pairwise orderings — including both decisions a practitioner acts on, which model and which prompt (mutate-the-artifact-to-test-the-judge). It fails in one legible direction: kill ratio measures sensitivity and cannot see restraint, so a verbose judge scores well by reporting everything, which is exactly the inversion observed. The per-operator breakdown is the real product — 62.3% to 97.8% across operators, with "add an unrelated element" at 95.8–97.8% inflating the aggregate unless reported separately, and low cells localizing a specific blind spot no aggregate human-agreement number would reveal. And the human instrument it is being validated against turns out to be the weak one: four MDE-trained annotators labelling 428 reported issues agreed on 65% of them, Krippendorff's α = 0.32, with adjudication deciding the ambiguity rather than removing it — while the judges themselves report only 31.6% to 63.7% valid issues on unmutated artifacts (the-human-reference-for-design-critique-is-itself-unreliable). A judge cannot be shown to exceed a reference whose own reliability is 0.32. [T1 — PlantUML domain class diagrams only; the manual reference rests on 60 judgments over ten entries; mutation assumes the base artifact is good enough that a change degrades it, and 10 of 79 hand-inspected difficult cases were borderline and retained; kill detection is embedding similarity at τ = 0.55 calibrated on one model's wording]
  • A graded corpus is ordered by what has been demonstrated, and that ordering is nearly uncorrelated with what it costs you to skip. (Added 2026-08-17, T3, suggestive — carried as an open question, not a finding.) An engineering monograph ranked 52 of its own reliability practices by consequence for a real decision and separately recorded whether each carried any strong evidence item: Spearman −0.004. The author reports it to defend an editorial choice; the number is the more interesting artifact, and it is a problem for every graded vault including this one. The mechanism is legible — the practices that matter most tend to be structural (separate the recovery identity from the production identity, validate write authority at the boundary, refuse to treat a self-report as completion), each testable against its own mechanism and none with a study estimating how often the omission causes loss, while well-evidenced material clusters where experiments are cheap to run (urgency-and-evidence-strength-are-nearly-uncorrelated). This map has never claimed its best-evidenced claims are its most consequential; on this evidence they are unrelated, and a primer ordered by tier would be ordered at random with respect to what happens if you skip it. The disclosure practice around the number is what makes it credible and is worth copying wholesale: three publisher indexes unreachable (HTTP 403 to automated clients, a dead credential, no API key) reported as not performed rather than as absence of results; a credential-free substitute census surfacing 50 publications absent from every other lane, queued rather than absorbed past the cutoff; a self-audit that reduced six of the ten practices whose sole support was a synthesis graded strong; and a grading instrument released deliberately uncalibrated — no external graders, no inter-rater agreement value claimed, a blinded packet and a κ script shipped so someone else can run the pass.   • The instruments the field uses to detect contamination are themselves calibrated on models nobody deploys, and go inert at frontier scale — and the pass@k drop they read has been measuring two separable things at once. (Added 2026-08-16, T1, strong.) This map's contamination evidence rests on counterfactuals — block the channel, re-measure — and that remains sound. What does not is the cheaper method: perturb the prompt and read the drop. Synonym fuzzing costs frontier code models at most 2.1 to 5.4 points, occasionally gaining them points, while collapsing models below 22B; the decoder-side likelihood probe separates seen from unseen corpora at AUC 100.0 up to 12B parameters and 25.0 to 75.0 from 70B to 405B (memorization-probes-saturate-at-scale). The probe also fails the prediction that would validate it — the largest drops do not land on the one benchmark contaminated for every model — so it entangles encoder fragility with memorization rather than measuring either. So a memorization or contamination figure obtained by perturbation or likelihood probing carries information only inside the scale band where the probe was validated; ported upward it reports nothing, and reports it as a small number. The replacement instrument is what makes this more than a null. Wrap the task in an invertible value transform so the algorithm is provably unchanged and retrieval cannot pass, and frontier pass@1 still falls 14 to 30 points — while the opcode distribution of the generated programs barely moves, and the loss attributes 9% to comprehension against 26% to generation. The models keep the algorithm and break on the encoding contract (representational-load-is-not-lost-capability). Two rules follow. Never attribute a surface-form effect from one number — this vault carries a shelf of studies varying prompt format, docstring wording, test placement and instruction surface, each reading a single score and naming a single cause. And measure what kind of output came back, not only whether it passed; opcode divergence is the cheap second axis for code, and the general form is an instrument that distinguishes a narrowed channel from a closed one. [T1 — dense architectures only (mixture-of-experts adaptation named as open), Python only, three benchmarks, five greedy completions per cell, and a decoder arm resting on four corpus points per row with seen labels inherited from another group. The authors also name training duration and composition as a largely uncontrolled variable that model size is standing in for, since two models of the same size can sit on opposite sides of a grokking-like transition.   • A metric that cannot decrease cannot report a decrease, and two independent teams have now caught the same loop degrading underneath one. (Added 2026-08-15, T1, strong — a replication, in a different domain, of the map's cleanest structural finding.) report-current-correctness-not-only-ever-correct established it on coding agents: ever-correct rose 0.820 → 0.853 across forced revisions while current correctness fell to 0.673, with 16.0% of trajectories producing a correct patch and losing it.   • A benchmark can accept "your task is broken" as a graded answer, when the acceptance criterion is machine-checkable. (Added 2026-08-15, T1, suggestive.) This map's defect literature is entirely retrospective and external — scan the finished benchmark (automated-benchmark-flaw-scanners), re-score without the defective instances (removing-defective-instances-reshuffles-the-leaderboard) — and the best in-run signal it held was statistical and weak (a-unanimous-agent-failure-flags-a-broken-task, which cannot separate a broken task from a hard one). A repository-scale verified-synthesis benchmark instead admits machine-checked negative evidence as a first-class submission: prove the specification unsatisfiable, prove the reference implementation wrong, or prove the specification set mutually inconsistent. It surfaced latent curation errors that manual review had missed (let-the-agent-prove-the-task-wrong) — note what that says about expert review of formal artifacts, since unsatisfiability is not something careful reading detects. The transferable rule is narrow and real: where your acceptance criterion is machine-checkable, make its negation submittable too; a proof that one supplied test contradicts another is an ordinary program. What it does not reach is this map's central worry — formal satisfiability is not semantic correctness, so an oracle that rewards the wrong behaviour (agents-build-to-the-oracle-you-expose) passes the audit untouched.   • Two confounds this map had no name for, both arriving with the control that removes them: an aggregate that is stable while its successes churn, and a compliance rate inflated by the rules the agent was going to follow anyway. (Added 2026-08-13, T1 both, strong.) The first is the sharpest paired-versus-unpaired demonstration the vault holds: 1,194 executions read two ways give 78.8% against 78.7% unpaired and 36.4% of demonstrated-competent blocks failing when paired on the same task/model/scaffold/repeat, on the same data, because gains in some blocks cancel losses in others and averaging discards the identity of the successful run (pair-the-runs-or-the-mean-hides-the-churn). The lesson generalizes past its subject: when an intervention is expected to change which runs succeed rather than how many, a flat mean is evidence of nothing until the pairing has been checked. The second names the instruction-layer version of the same disease. Every instruction-following number is a mixture of obedience and coincidence; re-running each task with the rule withheld and keeping only the rules the agent then violates drops all 12 frontier models by 3.6 to 7.4 points (mean 5.81) — and the discount is model-specific, varying roughly twofold, so it does not cancel in a comparison. Applying it exchanges three adjacent rank pairs while leaving the top build unchanged (an-obeyed-rule-may-just-be-the-default). Both papers also model the reporting this map keeps asking for: attrition separated from failure before any comparison (276 external invalids counted, timeouts and empty patches retained as agent outcomes), and intervals that resolve the metric contrast model by model while explicitly leaving every adjacent build rank unresolved.   • Two additions to the instrument thread, and they run in opposite directions: the strongest available answer to "how do you hold data out from an agent that can read and write," and a demonstration that judge agreement is a property of the condition rather than of the panel. (Added 2026-08-09, T1 both, strong / suggestive.) (a) Make the boundary a property of the sandbox, not an instruction. This map's standing problem is that an agent evaluation is a system the agent participates in — retrieving the fix, gaming the judge, leaking through search (benchmark-scores-inflate-when-agents-can-retrieve-the-fix, llm-judges-have-exploitable-biases, search-time-leakage-inflates-web-agent-scores) — and the usual answer is a better-stated rule. HarnessOpt-Bench states none: the held-out partition, the provider credentials and the budget meter are simply absent from the optimizer's sandbox, so there is no compliance step to fail and no injection that reaches the protected object (enforce-the-evaluation-boundary-in-the-environment-not-the-prompt). This is the runtime-governance posture arriving inside an eval harness (runtime-action-governance, contain-at-the-environment-layer-first), and its disclosure is graded by partition purpose — development reveals per-case outcomes and full traces because its job is diagnosis, validation reveals only an aggregate because its job is selection, test reveals nothing. It earns its keep empirically: most submitted candidates score below their best observed validation score, so a system reporting its search-time peak would publish an inflated number, and the authors claim only that the visible best is optimistic rather than attributing it to overfitting. Budget denominated in evaluation calls and case passes rather than compute is charge-every-search-method-the-same-budget implemented. Self-described as hack-resistant, not hackproof — repeated dev and val feedback can still reward strategies specific to a fixed evaluation, with per-run jitter in cases, tool behaviour and verifier implementation named as the unmade fix. (b) Report κ per condition, and treat a low-agreement cell as a measurement failure rather than a small effect. The same three-judge panel, same prompt, same benchmark, adjudicating two arms of one experiment: Fleiss κ = 0.51 on one agent's runs and −0.06 — below chance — on the other's, such that a lone judge could have misstated the second rate by more than twenty points while a pooled statistic looked acceptable (report-judge-agreement-per-condition-not-per-panel). The likely mechanism is nastier than bias because it is heteroscedastic by treatment: the arm whose transcripts are dominated by ambiguous behaviours is both the arm with the smaller effect and the arm with the noisier instrument. This extends validate-the-judge-before-you-trust-the-migration and verifier-diversity-is-not-verifier-independence from "validate the panel once" to "validate it per cell," and sits beside a-detectors-operating-point-belongs-to-its-deployment. [T1 — (a) is one benchmark's infrastructure over 111 runs, argued rather than ablated since no arm removes the boundary; (b) is two arms of one study, so an existence proof that per-condition agreement can diverge sharply within a single design, not a rate, and the transcript-distribution mechanism is this vault's reading rather than the source's finding]
  • A benchmark is only well-posed relative to the environment you run it in — and the reference solution is a free probe that tells you, before any agent runs, which tasks the environment will penalize and which it has made impossible. (Added 2026-08-08, T1, strong.) This map's audits ask whether a task is well-posed (fix-the-eval-before-trusting-the-score, a-unanimous-agent-failure-flags-a-broken-task, benchmark-defects-suppress-scores-not-only-inflate-them). None controls a variable that turns out to dominate once the environment stops being permissive. Replaying Terminal-Bench's own reference solutions under an enforced security policy partitions 89 tasks into 50 unaffected (the canonical solution still passes), 32 affected (a compliant solution exists but is not the canonical one), and 7 blocked by design (no compliant solution exists at all). The blocked seven are guaranteed failures for every agent alike and are worth a common 3.4–5.8 points of apparent degradation — pure environment, read as capability. The affected/unaffected split then predicts the rest: cost inflates 1.75× / 2.59× on affected tasks against 1.18× / 1.14× on unaffected ones, success falls 70.3% → 54.5% against 73.8% → 71.8% (noise), and 83.5% of all additional failures land on the affected 32 — with the two subsets showing near-identical control success rates, so this is an environment effect and not a hidden difficulty split (reference-solution-compatibility-predicts-the-policy-tax). The same audit exposed 5 over-specified verifiers demanding incidental detail the task never required, repaired additively, run identically at every level including control, originals retained — 2 recovered, 3 did not move, which is the evidence the repairs corrected checks rather than inflating scores. The transferable rule generalizes past security policy to any environment a benchmark was not designed under — a sandbox, an offline mirror, a pinned toolchain, a corporate proxy: without the partition, a reported score mixes agent capability, environmental tax, and tasks the environment foreclosed. [T1 — one benchmark, three trials per cell; the 32 author-written reference solutions and 5 verifier repairs are the authors' judgment, disclosed but unreplicated; bootstrap intervals quantify within-subset uncertainty and explicitly do not test the between-subset difference]
  • The instrument can be wrong by more than the models differ, in the direction this map barely audits for: a production benchmark was failing correct answers on 91% of its problems, and repairing it moved every frontier model 53 to 70 points. (Added 2026-08-06, T1, strong.) Almost everything on this map concerns numbers that are too generous — retrieval inflating a resolve rate, a judge gameable under pressure, a merge label crediting work a human finished. The pessimistic ledger has had two members, both existence proofs from single incidents (an-evaluator-sharing-its-reference-solver-cannot-be-self-checked, a-unanimous-agent-failure-flags-a-broken-task). This is the third and it is a prevalence result on an instrument in production use — a component of the Artificial Analysis Intelligence Index, part of a national AI security institute's evaluation suite, a standing evaluation at national laboratories, and a table row in current frontier model cards. A per-problem domain-expert audit of all 65 test problems finds 263 defects; 192 reject a correct, instruction-following solution (8 were too lenient and were tightened, so the corrections are not a difficulty reduction), touching 58 of 64 main problems. Corrected, twelve frontier snapshots move from 45–60% to 84–98% on subproblems and 9–27% to 69–92% on main problems (benchmark-defects-suppress-scores-not-only-inflate-them). Two structural properties did the amplifying and are worth recognizing in any benchmark: subproblems are cumulative, so an early defect contaminates everything downstream, and scoring is all-or-nothing, so one bad gold value forfeits the problem.   • The instrument can be wrong in the direction nobody checks — and a benchmark cannot detect it from inside, because its reference answers and its evaluator are usually the same code.   • The judge does not merely misgrade under pressure — it decouples from task completion when nothing is pressing on it at all, and it decouples exactly above the threshold where you would use it. Open questions:

  • STANDING ADVISORY (2026-07-20) — check AIDev's base rate before believing an accuracy-shaped claim computed on it. The corpus's merge label is ~92% positive (inferable only from a majority-class baseline row; never stated outright in the source that revealed it). This vault already cites AIDev-derived work (dev-vs-agentic-prs-merge-factors, predicting-pr-acceptance-review-effort). Odds-ratio and explanatory-power claims are unaffected; accuracy, F1, and "prediction is feasible" claims are not. No re-grading applied this run — flagged for David.
  • NEW 2026-07-14 — the noise floor has been measured exactly once, on one model and one benchmark, and the field needs it everywhere it argues. The protocol is cheap (pair two configuration-equivalent arms, measure the gap before the mechanism can act) and the result was ≲15 pp on τ²-bench/Haiku 4.5. The authors are emphatic that it does not transfer, and their own probes show it swinging from ≈0 pp to 20 pp across model/domain — which means the number is useless second-hand and the measurement is mandatory first-hand. The urgent instance: nobody has floored SWE-bench, where loop-engineering's two counterexamples (+8.3, +9.3–10.5 pts) and much of the harness literature's evidence live. One paired re-run would tell us whether an entire contested map is arguing over signal or variance.
  • NEW 2026-07-14 — can a self-improving system be bounded by its own selector, and is anyone measuring it? TTHE publishes a 20-point gap between what its judge commits (50%) and what was reachable (70%). That gap is only visible because the authors ran post-hoc oracles with gold, purely as a diagnostic. Every deployed self-evolving harness has this gap and no way to see it. Open: does the gap widen or narrow with more generations (correlated-blind-spot compounding says widen); and is there any label-free signal that detects judge miscalibration in-flight, or is a periodic gold-labeled audit the only option? Nobody has run an adversarial arm — a harness actively optimizing to fool its own judge — so the worst case is unmeasured, not absent. Partially answered 2026-07-16, and the answer is worse than the question: fabrication needs no adversary. A controlled micro-lab shows the optimizer inventing failures to fix under failure-presupposing instructions alone (15/60 vs 0/60), invisible to suppression-only acceptance by construction; warrant-aware acceptance (oracle-confirmed citations required per self-edit) eliminates it (harness-optimizers-fabricate-failures-to-fix). Still open: whether warrant-style acceptance is implementable where no oracle exists — which is the unlabeled setting's defining condition.
  • The map's sharpest evidence (benchmark contamination) is single-org T2 on competitors' models, self-audited. Partially closed 2026-07-13: an independent group ran the same block-the-channel counterfactual in medical QA and confirmed the direction — but the magnitude came out ~4 points, not 14–21, so the coding-domain decomposition (63%/57%/9%) still stands on one org's self-audit. The remaining ask is narrower: a second org repeating the constrained-harness experiment on an agentic-coding benchmark specifically.
  • The prevalence≠inflation split raises its own question: is the small medical-QA inflation a ceiling effect (parametric baselines saturate) or a domain effect (MCQ answers are guessable where patches aren't)? If ceiling, contamination inflation should grow as benchmarks get harder — which would make the freshest, hardest benchmarks the most inflated, an ugly selection effect nobody has tested.
  • Nobody has established what the constrained score is a good estimate of. A strict harness may under-credit legitimate documentation lookup — real engineers read the docs. The correct baseline for "derived the fix" is undefined, so the 73.0% is a different number, not obviously a truer one.
  • No cross-proxy study exists. If merge labels, pass rates, judges, self-reports, and benchmark scores all misgrade, do they misgrade the same agents in the same direction? An agent that games benchmarks may or may not be the agent whose PRs embed human repair. Until someone measures several proxies on one population, "triangulate across proxies" is a plausible heuristic, not a validated one.
  • The vault's standing fleet-quality gap lives here now: process-defect scores, control-preservation scores, and review-theme distributions are all instruments, and not one has been linked to downstream shipped-defect escape. Instruments without a criterion are a measurement proposal, not a measurement. Narrowed 2026-07-11: resolution rate (grade-the-reviewer-on-what-the-author-fixed) is the first criterion — its ground truth is a change a human chose to make to their own code, which is expensive to fake and exists whether or not anyone is evaluating. It still is not defect escape, and it has no false-negative side, but the gap is now "link the criterion to escape" rather than "find a criterion at all."
  • A benchmark number can now be wrong in two directions at once, and this map should say so. loop-engineering's 2026-07-11 counterexample (icat-agent, +8.3 pts on SWE-bench Pro) is scored on the benchmark this map knows is retrieval-contaminated at 63% — and the winning scaffold's distinguishing behaviour is exploring harder before patching, which is what a better retriever looks like. Nobody can currently tell a scaffolding win from a retrieval win on SWE-bench Pro. That is not a footnote about one paper; it means the contested question in loop engineering cannot be settled on the benchmark everyone is using to argue it.
  • Contamination is a moving target: constraining egress and history defeats today's retrieval channels. Task instances still leak through training data, and no one has quantified that channel for benchmarks built from public repository history.
