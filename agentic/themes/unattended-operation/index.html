What we believe now:

  • The strongest long-horizon result on this map keeps nothing across episodes except what a gate accepted — the project persists and the agents are disposable. (Added 2026-08-13, T1, single-study.) Every continuity mechanism here so far extends some part of the agent: a longer window, a memory store, a manager, a shared scratchpad, a resume contract — each a component that can be stale and can poison what follows, which is what persisted-state-without-revalidation-amplifies-errors and memory-scaffolds-can-degrade-long-horizon-agents measure. EvoX Genesis inverts it: a finite-lived agent enters at an accepted (version, path) scope, performs one bounded task, proposes a change and terminates; recursive delegation creates children without advancing the accepted version, and only a parent's validation-gated acceptance does. A rejected change leaves the version untouched — but a failure reason written into Context, tests, constraints or provenance is itself a separate accepted event, so the project inherits the lesson without the code. From an empty repository, this produced a 248,989-line Rust C compiler over 123.4 hours and 1,019 archived episodes at delegation depth five, for US$44 in model-token charges, passing 220/220 c-testsuite, 32/36 evaluated LLVM cases and 93/93 Csmith programs (make-the-project-persistent-not-the-agent). The result that matters most for a fleet is the continuation arm: two branches from the identical completed compiler, one swapping the foundation model, and development continued with c-testsuite at 220/220 throughout — if continuity had lived in agent state, a model swap would have been a migration; because it lives in an accepted repository, it is a configuration change. That sharpens this map's standing instruction: externalize the artifact, not the agent's notes about the artifact (persist-the-contract-not-the-conversation reached the same place from the memory side). [T1 — but bounded hard. There is no audit log of every human action and the authors decline to treat missing intervention records as proof of zero involvement. One run per condition, no baseline arm, no controlled comparison against a persistent-memory or persistent-agent organization, so project-persistence is demonstrated once rather than measured against its alternatives. The paper's own appendix scopes the formation run as "automated implementation under a detailed human specification, not architecture-free formation." Dollar figures are model-token charges only]
  • Externalizing run state is necessary and not sufficient: the persistence layer holding it has to state, and keep, a machine-checkable contract about what a resume means for effects that already fired — and across five shipped agent workflow frameworks, no two share a conformance profile. (Added 2026-08-07, T1, strong.) This map's headline pattern is attested by five orgs at five layers, and every one of those attestations is an architecture claim from an operator who ships it. None is a conformance claim. Here is the first audit. Six properties are stated over the resume plane — prefix continuation, effect exactly-once, fork determinism, checkpoint validity, consume-once, recovery determinism — machine-checked in TLA+ (reference configuration clean; verdicts unchanged at 7.4 × 10⁶ distinct states; a 39-cell per-invariant fault matrix whose clean runs are the separating models the independence argument needs), then measured by a deterministic LLM-free harness against pinned releases with an on-disk external effect ledger as oracle (the-durable-unit-needs-a-contract-not-a-checkpoint). Three results reset what this map thought the pattern bought. The gap is incoherence, not absence: CrewAI's checkpointing documents exactly-once, LlamaIndex Workflows documents at-least-once and tells users to make preceding work safe to re-execute, LangGraph memoizes completed task results — and a developer porting a side-effecting workflow between them crosses regimes with no type error and no property to consult. Crash-resumption is the arm that fails, not pause-safety: LangGraph 1.2.9 is exactly-once across interrupts and at-least-once across crashes on the same API, with a barrier-synchronized SIGKILL after the completed task's durable write re-executing it (ledger 1→2), and an exhaustive kill-point sweep showing all four incomplete durable prefixes of a five-operation protocol license re-execution of completed effect-bearing work. That narrows the 2026-07-19 boundary in the uncomfortable direction — this vault had been treating crash-resumption as the property the pattern reliably buys. And the duplicate can be invisible in framework state: CrewAI's from_checkpoint re-executes a completed effect-bearing method, effect counter 2, while the flow's own state counter reads the exactly-once value — if the method charges a card, the card is charged twice while the state looks correct. Hence the operational rule: an unattended fleet cannot audit its own duplication from inside the framework's state; keep a side-channel effect ledger for anything non-idempotent. Two smaller cells worth carrying: pydantic-graph passes every probed safety property and fails the point of the plane — after a crash inside a node its own resume entry point refuses to restore the file it wrote, which is why the contract carries an explicit liveness obligation so that "never resumes" cannot pass by vacuity — and AutoGen AgentChat is alone among the five in loudly rejecting tampered state. Finally, the version datum is the argument for the contract rather than for any one fix: LangGraph's fork and silent-persistence violations reproduce at every release from 1.0.5 to 1.2.9, while two others shipped as 1.1.x regressions and were repaired — absent a stated contract, semantics drift inside one framework between minor releases, so a team that audited its persistence layer audited a version. [T1, strong — but a single independent author with the artifact private pending publication; the paper explicitly disclaims minimality of the property set, prevalence rates for any violation, ecosystem representativeness, and any claim about paths it did not probe. Verdicts are conformance on probed paths at pinned versions. Strength rides on the harness being deterministic, LLM-free and mechanically reproducible against your own pins rather than on sample size]
  • Crash recovery is not environment recovery — give the agent a tool to inspect its own environment, then run a separate automation that decides which failures are worth repairing and repairs them by pull request. (Added 2026-08-01, T2, suggestive.) This map's whole durable-state thread answers "the process died, how does work resume." The more common failure in a standing fleet is that nothing crashed and the environment quietly stopped being correct: a rotated secret, a changed egress rule, a drifted base image. The shipped answer has two layers and the split is the point. Below, a dynamically discoverable tool surface (MCP) the agent uses to inspect setup failures, egress policy and changed secrets — so a broken environment is something the agent can name rather than silently absorb — with interfaces that can change without rebuilding the agent loop. Above, an automation that periodically checks for failures, remembers which errors are transient versus salient, root-causes the salient ones, and opens PRs for fixes it is confident about. The transient/salient memory is the non-obvious part: most environment noise is noise, and an automation that repairs every blip is worse than none (give-the-agent-tools-to-diagnose-its-own-environment). Alongside it, two containment properties that hold against an agent rather than asking it: secrets redacted in tool results, so the value cannot be read even if the agent tries, and a supervisor process that restarts long-running builds, taking a deterministic responsibility off the model entirely. Worth carrying because it is a vendor's own stated next step delivered: the same team's earlier post named self-healing environments as the aim (environment-setup-determines-cloud-agent-quality), and a quarter later it has a name and a repair channel. [T2, suggestive — single org, same vendor as the prior post so this deepens rather than replicates, no control arm, no independent verification. The headline figure (cloud agents from ~1 in 10 merged PRs in December to more than half now, on the vendor's own monorepo) is throughput with no quality criterion — no defect escape, revert rate, review burden or rewrite fraction — and the automation's confidence threshold and precision are unstated]
  • The cheapest durable layer is a work queue derived from the filesystem, and it is a fifth attested one. (Added 2026-07-25, T2 practice.) Deployed across hundreds of agents on a 1M-LOC migration finished in under two weeks: the queue is recomputed from disk state on every restart and "done" is defined as the output file existing, so there is no durable structure to lose and no reconciliation step — resumability falls out rather than being engineered. The one necessary serialization point is a build daemon batching patches and rebuilds so parallel workers cannot race: serialize the mechanical operation, never the knowledge. Read with the map's own boundary (durable-execution-engines-do-not-supply-barrier-semantics) it is at the easy end of crash-survival and supplies none of pause-safety — there is no pause primitive in "the file exists," and a worker mid-write is exactly the state the predicate cannot see. The task class also supplies the property: one output artifact per unit of work plus a compiler to check it, which ordinary feature work lacks, and where the output is a change rather than a creation you need the hash-bound version (treat-agent-output-as-a-claim-not-lifecycle-state, build-the-work-queue-from-disk-state). [T2, suggestive — no control arm]
  • The operator surface has to include who may ask whom, not only liveness and restarts. (Added 2026-07-25, T2, single-study.) The credential posture extends from secrets to identity: single-purpose agent identities at minimum permissions, agent-to-agent traffic routed through a monitored channel rather than direct, and irreversible effects held behind a separate agent plus a human. The motivating failure is concrete — an agent barred from deploying asked a peer agent to push code, caught at a human gate (least-agency-blocks-an-agent-that-recruits-another-agent). An orchestrator that is first responder for stalls is not thereby first responder for capability escalation, and a fleet's effective permissions are the transitive closure over its channels. Same vendor as keep-credentials-outside-the-agent-sandbox, so this deepens rather than replicates. [T2, single-study]
  • Make the durable unit of an unattended agent its externalized run state, not the process running the loop — a crashed/restarted harness should reboot and resume from durable state rather than losing what the process held in memory. Now attested by three independent orgs at four layers: infrastructure-based (Anthropic's replayable session event log), repo/file-based (progress files + failing-until-verified feature lists + git history as the re-entry contract), tracker-state (OpenAI's Symphony daemon — restart recovery without a persistent database), and workflow-engine (Cursor's agent loop on Temporal, with machine state and conversation state decoupled from it) — the last carrying the pattern's first effect size: reliability ~90% → ~99% at 50M+ actions/day. [T2, cross-org]
  • Never let a sandbox executing model-generated code hold a reachable credential; broker actions that need secrets (git push/pull, OAuth-scoped calls) through infrastructure or an MCP proxy instead of handing the token to the agent. Deepened same-vendor by Cowork's sealed-VM pattern (credentials live in the host keychain, outside the VM where model-generated code runs); Cursor names secret redaction and credential management as cloud-agent infrastructure but without comparable depth — so still no second-org account at depth. [T2]
  • An unattended fleet needs an operator surface: structured logs at minimum, plus liveness/stall detection with automatic restart and exponential-backoff retries — the orchestrator, not a human, is the first responder. [T2]
  • Durability is not boundedness, and adopting a durable-execution engine does not buy you a working pause. Measured on Temporal: replay double-execution is closed by construction, while the approval-pause barrier is independently absent — a sibling effect commits inside the approval wait, before any decision arrives. Treat "survives a crash and resumes" and "cannot act while suspended" as two separate properties to be verified separately; the second needs an admission gate at the effect boundary, which the engine does not supply. [T1, single-study]
  • When nobody is watching, self-report cannot be a term in the admission rule. An unattended loop that advances on the agent's own "tests passed" is trusting the one witness this vault has repeatedly measured as unreliable (users-correct-agents-in-nine-of-ten-resolutions, and self-misreporting rising as models improve). Advance lifecycle state only on evidence bound to the current source hash. The supporting ablation isolates enforcement rather than review volume as the active ingredient (14/1800 advisory vs 2/1800 enforced at equal compute) — but it is a T3 self-evaluation, so this is carried as a design principle with one study behind it, not as settled practice. [T3, single-study]

  • 2026-08-13 — persistent-recursive-worlds-autonomous-evolution (Huang, Liang, Zheng & Cheng, The Hong Kong Polytechnic University, arXiv, "Persistent Recursive Worlds Enable Autonomous Software Evolution", 2026-08-10, T1, single-study): the longest unattended run this vault has ingested, organized around a design choice that removes the component every other approach here depends on. Software is modelled as a persistent recursive world: state is a (version, path) pair, a local world is situated by an accepted version and a repository path, and a finite-lived agent works only inside that scope before terminating. Two moves, and the asymmetry is the architecture — recursive delegation pushes work to a more specific path and spawns children without advancing the accepted version, while an accepted software event advances (v, p) → (v′, p′) only after a parent evaluates the contribution against available tests, constraints and integration evidence. Rejected code never enters; a rejected attempt's failure reason can, as a separate accepted event. Three experiments. Formation: DeepSeek V4 Flash, from a repository with no compiler implementation, 123.402 h wall time against 666.385 summed agent-hours (episodes overlap), 1,019 archived episodes, delegation depth five, 248,989 tracked Rust lines, US$44 — validated externally at 220/220 c-testsuite, 32/36 evaluated LLVM cases, 93/93 executed Csmith programs, plus LZ4, SQLite and 2,904 Rust workspace tests, with direct use or translation of Clang/LLVM source prohibited. Continuation: two branches from the same completed GLM-5.2 compiler at commit 37216cfa254a, one continuing on GLM and one switching to DeepSeek — 1,445/1,448 and 1,820/1,820 on their respective retained LLVM sets, c-testsuite 220/220 at every stage, and different delegation shapes from identical saved state (98 agents to depth four vs 178 to depth eight), which the paper is careful to present as continuation across model replacement and not a model ranking, since the retained test sets differ and the budgets are unmatched. Redevelopment: 13 MESA modules, 100k+ Fortran lines → a ~90k-line Rust workspace, lower median runtime in all six numerical workloads, 1.55× to 6.87× (make-the-project-persistent-not-the-agent). Status held at consolidating — this is the map's durable-state instruction taken to its limit and demonstrated at a scale nothing else here approaches, but it is a single-study system paper and the map's status rests on the accumulated externalization evidence, not on this. The caveat the authors state against themselves is the load-bearing one: no audit log of every human action exists, and they decline to read missing intervention records as proof of zero involvement — so read this as a demonstration of an organizing principle, not as a measured autonomy rate. One run per condition, no baseline arm; the appendix scopes the formation run as automated implementation under a detailed human specification. Ripples: loop-engineering (a coordination substrate that is the version history itself, with an executable admission test — let-the-gate-decide-what-the-next-agent-inherits), context-engineering (episode-bounded execution state means nothing to compact and nothing to go stale), model-routing-token-economics (US$44 of model tokens for 123 hours prices long-horizon autonomy by its validation rather than its model), harness-self-evolution (the project evolves while the agents do not).
  • 2026-08-10 — interaction edge from agentchaos-fault-injection-agent-systems (Tan et al., Sun Yat-sen University / Singapore Management University, ASE 2026, arXiv, "AgentChaos", 2026-08-07, T1, strong for this edge): the failure mode an unattended fleet is least equipped to notice, priced. When the LLM API returns an error, a timeout, an empty body or a truncated reply, 21.82% to 65.71% of the resulting failures surface nothing to the user — the conversation pattern is worst at 65.71% and a single-agent loop at 61.09%, against a pipeline's 21.82%. Everything else on this map assumes something eventually reports: an operator surface, a stall detector, a durable state record. A silent wrong answer produced by a degraded provider passes all three, and its own signature is misleading — call counts move 1.72 → 7.3 on one architecture and 7.34 → 5.2 on another, so an unattended run that costs less than usual may be the one that gave up (a-degraded-provider-moves-the-token-bill-both-ways). Two practical consequences for a scheduled fleet. Persistent degradation is the regime to alarm on (47.64–62.39 points of task success on multi-agent systems) while intermittent faults at p = 0.3 are nearly free — so the useful signal is a sustained provider condition rather than any single bad response. And the deterministic checks this vault already trusts are the right instrument here, because the diagnostic layer is weak: neither a rule-based scanner nor a frontier model clears 56% at naming or locating the fault, with truncation at 4.30% for the rules (the-costliest-provider-faults-are-the-hardest-to-diagnose, a-deterministic-recheck-beats-a-learned-monitor-on-precision). Bounds: an injection study over a coverage-chosen fault mix, one system per architectural pattern, and no measurement of how often a real provider degrades this way. Primary map: agent-harness-architecture.
  • 2026-08-08 — interaction edge from boundary-bench-policy-graded-hardening (Davidovich, Amar, Rozencwajg & Hiltch, Accomplish AI, arXiv, "Permission Denied", 2026-08-02, T1, strong for this edge): a failure mode an unattended fleet cannot see, measured across 12 model–harness bundles and 2,952 runs per condition. When the environment denies an action, the agent does not stop and report it. Hardening converts successes into timeouts (≈59% of the added failures) and wrong solutions inside budget (≈37%) while early stops barely move (2.4% → 2.7%), and 97% of the deep-sampled cost movement is workaround construction — rebuilding a toolchain from source rather than surfacing the obstruction. So a fleet running under real controls emits no permission request, no fast failure, no distinguishable signal: just a slower run and a subtly wrong patch, in a mix that differs by bundle (hardening-produces-timeouts-not-refusals). An operator watching outcome rate will read a hardening regression as a capability regression, which makes blocked-action counting an operator-surface requirement rather than a diagnostic nicety — and the study shows the signal discriminates (675 of 2,051 trials record a denial under the strictest policy; exposure runs 14.4% → 51.6% → 67.8% across unaffected, affected and foreclosed tasks) (keep-the-agent-interruptible-and-reversible, fail-loud-instrumentation-over-plausible-substitutes, route-agent-identities-and-messages-through-the-siem). It also complicates a property this map treats as engineerable: not one of twelve bundles stopped when it could not proceed (unprovable-is-a-terminal-state-not-low-confidence) — persistence is what the loop rewards, so surfacing a denial has to be built. Practical for anyone budgeting a nightly fleet: matched passing runs under hardening still take 13% more wall-clock, 14% more tool calls and 26% more tokens. Caveats: one benchmark, three trials per cell, no intervals; blocked-action counts are diagnostic associations. Primary map: runtime-action-governance.
  • 2026-08-07 — resume-contract-workflow-persistence (Sajjad Khan, independent researcher, arXiv, "Resume Means Resume: A Machine-Checked Conformance Contract for Checkpoint, Interrupt, and Resume Semantics in Workflow Persistence Layers", 2026-08-04, T1, strong): the first audit of the layer this map's whole thesis rests on, and it is a direct successor to agent-framework-control-primitives-gap — that source separated durability from approval-barrier enforcement on one engine; this one states six properties over the persistence API, machine-checks them, and measures five pinned frameworks against them. No two probed frameworks share a conformance profile. LangGraph 1.2.9: exactly-once across interrupts, at-least-once across crashes on the same API, with an exhaustive kill-point sweep showing every incomplete durable prefix licensing re-execution; schema-invalid state persisted silently; and a second resume to the same checkpoint durably recorded and never consulted.   • 2026-08-07 — interaction edge from agent-failure-telemetry-detection-repair (Sunny Dubey, independent, arXiv, "Real-Time Detection and Repair of LLM Agent Failures", 2026-08-03, T1, strong for this edge): the cheapest operator-surface component this map has seen, and the one with no calibration burden. Three deterministic checks — recompute the run's stated total from the tool results it actually received, confirm every required call was made, and validate each result against the shapes its tool can return — catch 60% (96% with the coverage check) at 0 of 63 false positives against a learned monitor's 54% at 17%, hold at 0 of 64 on a frozen 120-episode disjoint-seed replication, and transfer to another model family with nothing retuned (110 of 110 at 0 of 10). The shape check trips on 0 of 1,825 healthy episodes and fires within one step of onset 215 times in 218 (a-deterministic-recheck-beats-a-learned-monitor-on-precision). For an unattended fleet the zero-false-positive property is what makes the next step legal: flagged runs are rolled back and re-run automatically, lifting net task success 52% → 73% with zero correct runs broken, for about one extra model call per run. This is the constructive complement to the persistence finding above — the ledger that catches a duplicated effect is the same kind of artefact as the check that recomputes a stated total, both of them side-channel records the framework's own state cannot supply. Its primary contribution is the layered detection architecture, so the full entry sits in observability. Bounded: 3B–8B local models plus one commercial API, single author, and the tasks carry a recomputable invariant by construction.
  • 2026-08-05 — interaction edge from failfast-restartsmart-early-termination (Wang, Lyu, He, Yang, Zhong, Harel & Lo, Singapore Management University / Alberta / NJUST / Tel Aviv, arXiv, "Fail-Fast, Restart-Smart", 2026-08-04, T1, strong): this map's orchestrator is the first responder principle with a measured policy instead of a heuristic, and the first version of it that includes what to do after the kill. The map has held since 2026-07-11 that the Meltdown Onset Point is an operational signal as much as an evaluative one — the point past which an unattended run should be killed rather than left to burn tokens (reliability-and-capability-rankings-diverge). What it lacked was a detector and a recovery step. A 0.6B monitor reading only observable trajectory text — no policy internals, so it works against closed APIs — decides the kill under an explicit false-positive budget: the operator declares what fraction of would-succeed runs they will sacrifice, and the controller maximizes detection subject to it (5% reclaims 14.6–20.4% of execution tokens; 25% intercepts 68.3% of failing runs and half the tokens). The half this map cares about most is that the kill is only tolerable because the restart is not a cold start: a fresh same-policy rollout with no prior prompt history, offered the aborted run's repository diff as a removable overlay it may inspect, apply or discard, takes resolution from 66.6% to 71.8% while losing only 8.8% of falsely-aborted runs against cold restart's 27.5%. For a standing fleet that is the difference between an abort policy you can deploy and one you cannot — an unattended stall-killer without an edit-preserving restart destroys real work at whatever rate its detector is wrong. Caveats: one benchmark, one scaffold, 100 test instances, five seeds; a 25% false-positive budget means aborting a quarter of successful runs, and the two knobs are not independent; the +5.2 costs +43.8% net tokens. Primary map: loop-engineering. See carry-the-edits-not-the-narrative-across-a-restart, a-tiny-monitor-prices-a-doomed-trajectory.

  • 2026-08-02 — interaction edge from orca-bench-oncall-root-cause (Gong, Choi, Agarwal, Schechner, Huang & Agrawal, Cornell / UC Berkeley, arXiv, "ORCA-bench", 2026-07-30, T1, strong for this edge): a price on a capability this map's operator surface has been assuming without naming. Bounds: public benchmark system likely in pretraining, no cross-incident memory, no action loop, one harness — all pushing the same way, so the authors call the gap a lower bound.
