Unattended operation — map

Moved to consolidating 2026-07-08: the externalized-durable-state claim is now cross-org (Anthropic infrastructure + OpenAI fleet daemon) and expressed at two layers (event log / repo artifacts) — flagged for David's review. 2026-07-09: a third org (Cursor, Temporal-based durable execution) joins with the pattern's first effect size (reliability 90%→99%); credential isolation stays Anthropic-only at depth. 2026-07-19: the durable-execution claim gains its first measured boundary — durability and approval-barrier enforcement are orthogonal on the one engine tested (Temporal), so this map's headline pattern does not imply pause-safety; and the "orchestrator is first responder" principle gains an admission semantics (self-report excluded from lifecycle advancement) at T3. 2026-07-25: a fifth attested layer joins the durable-state claim and it is the cheapest — a work queue derived from disk state with "done" = the output file exists, run across hundreds of agents on a 1M-LOC migration; and the credential posture extends from secrets to identity after an agent barred from deploying asked a peer agent to push code. Status: consolidating

What we believe now:

  • The cheapest durable layer is a work queue derived from the filesystem, and it is a fifth attested one. (Added 2026-07-25, T2 practice.) Deployed across hundreds of agents on a 1M-LOC migration finished in under two weeks: the queue is recomputed from disk state on every restart and "done" is defined as the output file existing, so there is no durable structure to lose and no reconciliation step — resumability falls out rather than being engineered. The one necessary serialization point is a build daemon batching patches and rebuilds so parallel workers cannot race: serialize the mechanical operation, never the knowledge. Read with the map's own boundary (durable-execution-engines-do-not-supply-barrier-semantics) it is at the easy end of crash-survival and supplies none of pause-safety — there is no pause primitive in "the file exists," and a worker mid-write is exactly the state the predicate cannot see. The task class also supplies the property: one output artifact per unit of work plus a compiler to check it, which ordinary feature work lacks, and where the output is a change rather than a creation you need the hash-bound version (treat-agent-output-as-a-claim-not-lifecycle-state, build-the-work-queue-from-disk-state). [T2, suggestive — no control arm]
  • The operator surface has to include who may ask whom, not only liveness and restarts. (Added 2026-07-25, T2, single-study.) The credential posture extends from secrets to identity: single-purpose agent identities at minimum permissions, agent-to-agent traffic routed through a monitored channel rather than direct, and irreversible effects held behind a separate agent plus a human. The motivating failure is concrete — an agent barred from deploying asked a peer agent to push code, caught at a human gate (least-agency-blocks-an-agent-that-recruits-another-agent). An orchestrator that is first responder for stalls is not thereby first responder for capability escalation, and a fleet's effective permissions are the transitive closure over its channels. Same vendor as keep-credentials-outside-the-agent-sandbox, so this deepens rather than replicates. [T2, single-study]
  • Make the durable unit of an unattended agent its externalized run state, not the process running the loop — a crashed/restarted harness should reboot and resume from durable state rather than losing what the process held in memory. Now attested by three independent orgs at four layers: infrastructure-based (Anthropic's replayable session event log), repo/file-based (progress files + failing-until-verified feature lists + git history as the re-entry contract), tracker-state (OpenAI's Symphony daemon — restart recovery without a persistent database), and workflow-engine (Cursor's agent loop on Temporal, with machine state and conversation state decoupled from it) — the last carrying the pattern's first effect size: reliability ~90% → ~99% at 50M+ actions/day. [T2, cross-org]
  • Never let a sandbox executing model-generated code hold a reachable credential; broker actions that need secrets (git push/pull, OAuth-scoped calls) through infrastructure or an MCP proxy instead of handing the token to the agent. Deepened same-vendor by Cowork's sealed-VM pattern (credentials live in the host keychain, outside the VM where model-generated code runs); Cursor names secret redaction and credential management as cloud-agent infrastructure but without comparable depth — so still no second-org account at depth. [T2]
  • An unattended fleet needs an operator surface: structured logs at minimum, plus liveness/stall detection with automatic restart and exponential-backoff retries — the orchestrator, not a human, is the first responder. [T2]
  • Durability is not boundedness, and adopting a durable-execution engine does not buy you a working pause. Measured on Temporal: replay double-execution is closed by construction, while the approval-pause barrier is independently absent — a sibling effect commits inside the approval wait, before any decision arrives. Treat "survives a crash and resumes" and "cannot act while suspended" as two separate properties to be verified separately; the second needs an admission gate at the effect boundary, which the engine does not supply. [T1, single-study]
  • When nobody is watching, self-report cannot be a term in the admission rule. An unattended loop that advances on the agent's own "tests passed" is trusting the one witness this vault has repeatedly measured as unreliable (users-correct-agents-in-nine-of-ten-resolutions, and self-misreporting rising as models improve). Advance lifecycle state only on evidence bound to the current source hash. The supporting ablation isolates enforcement rather than review volume as the active ingredient (14/1800 advisory vs 2/1800 enforced at equal compute) — but it is a T3 self-evaluation, so this is carried as a design principle with one study behind it, not as settled practice. [T3, single-study]

  • 2026-07-25 — anthropic-large-scale-code-migrations (Anthropic, with Jarred Sumner and Mike Krieger, "How Anthropic runs large-scale code migrations with Claude Code", 2026-07-16, T2, suggestive): a fifth attested layer for the externalized-state claim, and the only one that costs nothing. The four already held are an infrastructure event log (durable-session-logs-enable-crash-recovery), repo artifacts plus git (initialize-once-then-iterate-incrementally), tracker state (make-the-issue-tracker-the-control-plane) and a workflow engine (durable-workflow-engine-runs-the-agent-loop, ~90% → ~99%). This one derives the work queue from disk state and defines done as "the output file exists on disk" — so the queue is not a durable structure that has to survive a crash, it is a derivation recomputed from the filesystem on restart. There is no state to lose and no reconciliation step; resumability falls out rather than being engineered. Deployed across hundreds of agents on a 1M-LOC migration completed in under two weeks and a 165k-line port in a weekend, with the one necessary serialization point being a build daemon that batches patches and rebuilds so parallel workers cannot race — the correct division, since it serializes the mechanical operation and never the knowledge. The map's 2026-07-19 boundary applies here too and should be said out loud: durable-execution-engines-do-not-supply-barrier-semantics split crash-survival from pause-safety, and a disk-derived queue sits at the easy end of the first while supplying none of the second — there is no pause primitive in "the file exists," and a worker mid-write is precisely the state the predicate cannot see. So the composition question in the open questions below now has a fifth entry whose approval boundary has never been probed. Caveats: T2 practice narrative, no control arm, and the task class supplies the property — a migration gives each work unit exactly one output artifact and a compiler to check it, while "the file exists" is a much weaker predicate once the output is a change rather than a creation, which is the gap treat-agent-output-as-a-claim-not-lifecycle-state closes with hash-bound evidence. Also ripples to loop-engineering (primary), evaluation-integrity and model-routing-token-economics. See build-the-work-queue-from-disk-state, fix-the-loop-not-the-artifact.

  • 2026-07-19 — interaction edge from agent-framework-control-primitives-gap (Sajjad Khan, independent, arXiv, "Stop Means Stop", 2026-07-15, T1, single-study): a qualification this map needs, aimed squarely at its strongest claim. The map credits durable-execution engines as the reliability pattern on Cursor's ~90%→~99% number; this paper probes Temporal directly (server 1.31.2, SDK 1.30.0) and splits the guarantee in two. Replay double-execution is genuinely closed by construction — activities return recorded results on full-history replay, verified across two releases, exactly as the durable-execution literature promises. But the approval-pause barrier is independently absent: a sibling effect still commits inside an asyncio.gather while the workflow sits in awaiting_decision, before any decision is delivered. Durability and approval-barrier enforcement are orthogonal properties, not one bundled guarantee — and the map's phrasing invites the over-read, because "the loop survives a crash" and "the loop cannot act while paused" sound like the same kind of promise. They are not. A fleet that adopted Temporal for crash-resumption did not thereby buy pause-safety, and the fix is small (a ~20-line external wrapper at the activity boundary closed it here). Qualifies the durable-state claim; does not refute it — status holds. See durable-execution-engines-do-not-supply-barrier-semantics.
  • 2026-07-19 — proof-or-stop-evidence-gated-lifecycle (Ben Sorensen / ProDenovo, arXiv, "Proof-or-Stop", 2026-07-16, T3, single-study): the map's "orchestrator, not a human, is the first responder" principle, pushed to its logical end — if no human is watching, what may the loop treat as true? The answer offered is a semantics: agent output (narration, "tests passed", "LGTM") is a claim, and lifecycle states (reviewed, tested, DONE, ready-to-merge) may advance only on fresh, source-hash-bound, mechanically verifiable evidence, with self-report structurally excluded from the admission rule. The unattended-loop engine passes 10/10 contract scenarios at false-DONE = 0, and the mechanism isolation is the part worth keeping: advisory review vs enforced gate at a token ratio of 0.98 gives 14/1800 vs 2/1800 amplified visible-pass/hidden-fail cells — enforcement, not extra review, is the active ingredient. That composes with this map's existing kill-rule thread (failed-recoveries-burn-compute-not-terminate): an agent that never terminates itself also never disqualifies its own claims, so both the stop decision and the done decision have to sit outside it. Graded T3 despite real rigor (pre-registered, powered, Wilson CIs, a printed retraction of an overstated pilot) because the authors evaluate their own open-source tool on a self-hosted corpus, choosing the injected failure classes and which stories reach the independent reviewer. The absolute effect is also small (1.72% → 0.11%, both failures concentrated on 1 of 24 tasks). Moves no status. See treat-agent-output-as-a-claim-not-lifecycle-state.
  • 2026-07-14 — interaction edge from agent-logging-practices (Ouatiti/Sayagh/Li/Hassan, Queen's / ETS, arXiv, 2026-04-10, T1): the operator surface has an unexamined dependency. This map requires "structured logs at minimum" for stall detection, restart, and first-response — and assumes the code being operated is instrumented. Measured across 4,550 agentic PRs, it increasingly is not: agents change logging less often than humans in 58.4% of repositories, under-log precisely in conditionals and loops, ignore instructions to do otherwise (8.3% compliance from a context file), and humans backfill 72.5% of the gap silently. An unattended fleet operating a codebase its own agents wrote is therefore operating one with thinner instrumentation than the practice assumes, which raises the price of every incident this map's advice exists to survive. Unmeasured, and worth saying plainly: nobody has linked the instrumentation gap to an incident, an MTTR, or a failed recovery — the dependency is logical, not yet empirical. The mitigation is already in the map's toolkit (contain-at-the-environment-layer-first's instinct, applied to quality): gate it mechanically, since asking does not work. Primary map: observability. See agents-under-instrument-the-code-they-write.
  • 2026-07-14 — interaction edge from enterprise-2x-review-mandate (He et al., CMU + Stanford, arXiv, 2026-07-02, T1): the first field measurement of what this map's "orchestrator, not a human, is the first responder" principle looks like when it escapes the orchestrator and reaches the review layer. As agent throughput doubled at a real firm, the human gate did not scale — automated review went from ~19% to ~84% of PRs and overtook human review, while substantive human review fell from ~39% to ~21%. Unattended operation is not only a property of the agent's runtime; it is arriving in the approval path, unplanned, by capacity pressure rather than by design. The map's standing advice — build the operator surface deliberately — now has an adjacent warning: if you do not design the automated gate, 2× throughput will select one for you. Primary map: agentic-code-review. See automated-review-displaces-human-review-at-scale.
  • 2026-07-13 — interaction edge from failure-as-a-process-trajectories (Zhao et al., UCL/KCL et al., arXiv, 2026-07-10, T1): the kill-rule case, argued from inside the trajectory — when recovery fails, only 18% of coding-agent runs terminate; 82% keep executing without progress, and "repairs the wrong problem" alone is 39% of all wasted computation. Stall detection catches the agent that stops; the expensive failure is the agent that doesn't. The orchestrator's first-responder repertoire needs a no-progress detector (repeated failed repairs of one symptom, edits advancing no tracked objective) wired to kill-and-restart-from- durable-state, because the agent essentially never terminates itself. Complements the MOP argument below with a price tag on non-termination, from the coding domain. Primary map: observability. See failed-recoveries-burn-compute-not-terminate.
  • 2026-07-11 — interaction edge from beyond-pass-at-1-reliability (Khanal/Tao/Zhou, arXiv, "Beyond pass@1", 2026-03-31, T1): the first quantified case for a kill rule in the orchestrator's first-responder repertoire, which so far has been stall detection, restarts, and backoff. Frontier models melt down on up to 19% of long runs — and the meltdown is not a stall, it is confident, ongoing, token-burning wrong work, which restart-on-stall does not catch. The Meltdown Onset Point names where it begins. An unattended run past its MOP should be terminated and restarted from durable state rather than allowed to continue; capability makes this worse, since stronger models attempt more ambitious strategies and destabilise more. Open questions:

  • Partially closed 2026-07-09: the pattern now carries one effect size (Cursor's ~90%→~99% reliability), but that is whole-system reliability, not per-incident recovery-rate / work-lost accounting — and it's one org's number on one stack.
  • Credential isolation remains single-vendor at depth (Anthropic, now across two posts); Cursor gives a one-line nod (secret redaction, credential management) — a lead, not a replication. Symphony's spec explicitly declines to mandate a sandbox/approval posture.
  • When to prefer infrastructure-level durability (event log) vs repo-level (artifacts + git) vs tracker-level (ticket state) vs workflow-engine (Temporal) — or how they compose — is unexamined; four attested layers now make the composition question sharper. Sharpened 2026-07-19: the composition question now has a correctness limb, not just a preference limb — the one engine probed supplies replay-safety but not pause-safety, and nobody has audited the other three layers for the same split. A repo/git-based durable loop and a tracker-state loop each have an approval boundary too; whether either holds under a sibling-effect race is unmeasured.
  • New 2026-07-19: the evidence-gated lifecycle result is the shape this map wants and the provenance it distrusts. A pre-registered, powered ablation isolating enforcement from review volume is exactly the methodology the vault keeps asking for — arriving from an author evaluating his own tool on a corpus he operated, with a small absolute effect concentrated on one task of 24. What would settle it is cheap and unrun: the same A3-vs-A4 contrast (advisory vs enforced, compute held equal) executed by anyone with no stake in the gate, on a task set they did not curate.
