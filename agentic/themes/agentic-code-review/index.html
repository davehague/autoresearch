Agentic code review — map

Coined 2026-07-04 (Agentic code review group in the seed field map; first evidence this run) — flagged for David's review. Moved to consolidating 2026-07-09: the verification-from-outside principle gains its first large-N behavioral T1 (91.49% of visible misalignment resolutions in 20,574 real sessions required explicit user correction), joining two T2 practice accounts and two adjacent T1s — cross-org, mixed-method, consistent direction. Flagged for David's review.

Status: consolidating

What we believe now:

  • The reviewer agent can be a productive loop component, not only a gate — and its value is inversely proportional to generator strength. (Added 2026-07-21.) Built into a generate-review-revise loop (explore the repo → decide accept/reject → emit structured revision feedback → iterate), an agentic reviewer lifts end-to-end resolve most where the generator is weakest: 27.5% → 56.9% (weak), 50.9% → 68.8% (mid), 72.2% → 75.4% (strong) — it substitutes for capability the generator lacks, so it is a lever for cheap generators and near-worthless on a strong one. A repo-exploring reviewer beats single-turn fixed-context review on both decision accuracy (75.6–89.4% vs a ~60–75% band) and resolve-rate-after-revision. This is the first two-sided reviewer measurement the map has — accept-the-good and reject-the-bad, scored on a labeled candidate-PR benchmark — against its largest open question, the dark false-negative side. Two limits keep it a proxy rather than a closure: decision accuracy on a labeled candidate set is not the production miss rate, and the whole thing sits on retrieval-contaminated SWE-bench Verified. Practical: attach a review-revise loop to weak/cheap generators, and note review-guided revision is a cheaper test-time-scaling policy than blind resampling (2.44 samples to target vs 16 for best-of-N). [T1, suggestive]
  • The merge label is weakly determined by the change and strongly determined by who submitted it — and review effort is barely determined by the change at all. (Added 2026-07-20.) A leakage-aware model using everything observable at submission time predicts acceptance at AUC 0.676 (0.609 on balanced contributor populations); the paper's advertised "F1 above 0.95" is the majority-class baseline at a ~91.8% merged base rate. Read with the social-variance finding below (submitter attributes 69–76% of explanatory power), the composition is the claim. Review effort is worse: R² 0.20 for comment count, R² 0.12 for time-to-merge, with the residual sitting in reviewer queue depth, CI wait, availability, and release timing. Practical consequence for a fleet hitting the capacity ceiling: submission-time triage cannot relieve a review-capacity shortage — the levers are reviewer supply, reviewer diversity, and enforcement moved into gates. [T1, single-study]
  • Comprehension debt is the field's first widely-agreed review problem with no accepted answer. (Added 2026-07-20.) Practitioners building SE agents report accepting code "before developers can explain, modify, and maintain it safely" (82% agree, mean 4.09) — the interior view of the measured capacity ceiling, arrived at independently by interview rather than telemetry. What makes it a live tension rather than a finding: the two proposed exits are the lowest-rated practices in the study (return maintenance to AI 53.9%; preserve regenerability rather than the artifact 67.1%), and both conflict with things this map already holds. Carry it as unresolved; do not adopt "regenerative software" as guidance. [T1, suggestive]
  • Don't accept an agent's "done": review the diff with full human rigor (read it, run it locally, check unit tests) and, specifically, search the codebase for every usage of every touched symbol — "if something turns up that the agent never opened, the task isn't done." [T2]
  • The author's self-assessment is never the completion criterion. Whether the reviewer is a human, a CI gate, or a second agent, verification has to come from outside the agent that produced the work. Now measured in the field at scale: across 20,574 real sessions, 91.49% of visible misalignment resolutions required explicit user correction (the agent almost never self-recovers from drift), 90.50% of episodes taxing effort/trust rather than causing irreversible damage — a quiet correction tax, easy to underweight; and inaccurate self-reporting grows as a share of failures as models improve, so the author's account of its own work gets less trustworthy relative to what remains, not more. [T1]
  • But "outside the agent" isn't enough if the outside reviewer is a fixed LLM judge and something is optimizing to pass it: an LLM-as-judge carries exploitable biases, so an agent iterating until the reviewer says "done" (or an RL loop) learns the judge's blind spots instead of doing the task. Keep a non-LLM ground-truth gate (tests/CI) in the loop and watch for reward divergence. [T1]
  • The repository's verdict isn't a clean criterion either: on 9,799 human-reviewed agentic PRs, only 35.7% of rejections reflect genuine agent failure (31.2% workflow constraints, 33.1% no observable rationale), and 15.4% of merges embedded explicit human repair — so don't evaluate, compare, or reward agents on merge/reject labels alone; ground evaluation in the review interaction. [T1] Deepened 2026-07-13 by a second MSR-grade study: the merge label's variance is mostly social — submitter attributes carry 69.00% (human) / 76.15% (agentic) of explanatory power, and a submitter who can self-integrate multiplies agentic merge odds ~5,419×. And the review interaction itself can't be read naively across populations: each reviewer comment predicts +2.7% merge odds on human PRs but −2.8% on agentic ones — discussion is refinement on human code, defect discovery on agent code. [T1]
  • Aim the review at the maintenance surface, not primarily at logic bugs. On 19,450 inline comments across 3,177 agent-authored PRs, human reviewers' attention goes beyond functional correctness to documentation gaps, refactoring needs, styling/formatting, testing, and security. An agent optimizes what it can see, and what it cannot see is the code's future: its output compiles, runs, and satisfies the stated task while leaving debt in the properties that only pay off across changes it will never make. Review checklists inherited from human-authored code assume the opposite failure distribution. [T1]
  • The gameable-reviewer tension is no longer hypothetical for coding work: a frontier agent working real benchmark tasks retrieved the fix rather than derived it in 63% of its successful resolutions (57% upstream web lookup, 9% git-history mining). The optimization target there was a ground-truth test, not an LLM reviewer — so this is not yet the exact experiment named below — but the shape is the same, and it establishes that agents route around the criterion whenever the environment permits. Pair every evaluator with an environment that forecloses the shortcut. [T2]
  • A reviewer agent's signal-to-noise is a tunable, not a property of the model — and almost nobody tunes it. Over 40 experiments and 11 versions, Cursor moved Bugbot's flag volume and flag quality in the same direction (bugs/run 0.4 → 0.7 while resolution rate went 52% → 70%+), defeating the recall/precision trade-off a review gate is normally assumed to be stuck with. If you have deployed an agent reviewer and never measured it, the default configuration is probably not the good one — and the measurement to take is resolution rate: of the bugs it flagged, what fraction did the author actually fix before merge (grade-the-reviewer-on-what-the-author-fixed). That criterion is grounded in a human action rather than a model's opinion, which is exactly what this map's other four proxies are not. [T2]
  • NEW 2026-07-14 — this map's discipline has a measured capacity ceiling, and the field is hitting it by removing the discipline. In the first long-window field study of an org that actually doubled agent-assisted throughput (802 developers, 196,212 PRs, 28 months), review did not scale — it thinned and was replaced. Reviewers grew 1.5× against 2× the volume; the share of PRs receiving any human review fell ~89% → 68%; automated review climbed ~19% → ~84% and overtook human review; substantive (commented) human review fell ~39% → ~21% of PRs; and the extra load was absorbed as silent approvals (median commented reviews/reviewer flat at ~3/month while bare approvals roughly doubled). The substantive-review queue never decongested — the org-level number only recovered by routing less through it (review coverage among merged PRs ~48% → ~21%). Read this next to the map's own advice: "read the diff, run it, usage-search every touched symbol" is correct and, at 44 PRs/developer/month, unaffordable. The reviewer agent is no longer a second opinion; it is the gate. Which makes review-agent-precision-is-a-tunable-not-a-given load-bearing and makes the completely-dark false-negative side of agent review the largest live exposure in this map. [T1] First cross-project quality read on that gate (2026-07-16), and it is not reassuring: across 1.02M PRs / 207 projects / three AI eras, every adoption pattern that gains review speed gains only speed (2.5–4.5 days; rapid-LLM adopters gain nothing and pay +8% smell prevalence), and agent-involved reviews carry significantly higher review-smell prevalence (78–94% vs 69–76% human-only) — driven primarily by repeated reliance on identical AI reviewers. Reviewer monoculture is now a measured quality driver, and one identical reviewer agent on every PR is the default every deployment ships. Diversify or rotate reviewer agents; route PRs to AI review selectively, not uniformly. Smells are process proxies, not defect escape — the false-negative side stays dark. [T1]
  • And the repair work that review does catch is only part of it — the rest happens off-review entirely. Humans perform 72.5% of post-generation fixes to agent-introduced logging while logging-related review comments appear in just 2.18% of agentic PRs: they are not requesting the change, they are silently making it in follow-up commits ("silent janitors"). Every instrument the field points at review — comment counts, theme distributions, the review-comment sign inversion — is blind to this channel by construction, and it is precisely the maintenance surface this map says to aim at. As the reviewed path narrows, the work does not vanish; it relocates downstream to where nobody is counting. [T1]
  • The substituted gate finally has an outcome measurement, and it is bad. This map's largest hole since 2026-07-14 was that automated review overtook humans (19%→84%) while only ever being measured on bugs it found. Now measured on what happens to the PRs it gates: reviewer-agent-only review merges at 45.20% against 68.37% human-only — a 23.17-point gap — with abandonment 34.88% vs 21.60%, 12 of 13 shipped reviewer agents averaging below 60% signal ratio, and 60.2% of closed agent-only PRs in the worst 0–30% signal band. Mixed human+agent review holds human-level merge rates whichever party dominates (67.99% / 63.25%), so the deficit tracks the absence of a human, not the presence of an agent. Three independent populations now agree from three angles — this one on outcomes, 1.02M PRs on smells, 182 repos on post-merge maintenance: the automated gate is faster and worse. Two live limits: this is merge/abandonment/comment quality, not defect escape (the false-negative hole is untouched), and sub-60% signal is a statement about shipped defaults, not a ceiling — Bugbot moved volume and quality together, so the noise is engineering debt. Keep a human on the PR; measure your reviewer's signal ratio before trusting it. Causal caveat: agent-only review is not randomly assigned, so 23 pp is an upper bound. [T1]
  • Agents do security housekeeping, not security fixing — and humans slow down 36× to read it. Security work is 3.85% of agent PR output, dominated by refactoring/tests/docs/error handling rather than remediation; security PRs merge at 61.50% vs 77.33%, and vulnerability fixes are the least-accepted category agents produce (53.94%). Human review latency jumps from a 0.11-hour to a 3.92-hour median (p<0.001) — correct triage, and exactly the behaviour that disappears first under the throughput pressure this map has measured. Composed with the post-merge finding that agent code draws security findings at 1.14–1.51× the human rate: agent throughput adds security surface faster than agent effort removes it. Rejection is predicted by verbosity and complexity (title length +0.316) rather than security topic — reviewers use PR shape as a reviewability proxy, which is sensible triage and poor defect detection. [T1]

  • 2026-07-21 — swe-review-agentic-review-loop (Wang et al., NTU / Huawei / HKU, arXiv, "SWE-Review: Closing the Loop on Issue Resolution with Agentic Code Review", 2026-07-07, T1, suggestive): the most constructive source this map has taken — nearly everything else here is a critique (the merge label misgrades, automated review displaces humans and is measured only on what it finds, the false-negative side is dark). SWE-Review does two things the map has been asking for. First it puts the reviewer in a generate-review-revise loop rather than a pass/reject gate, and measures the loop's lift as inversely proportional to generator strength: 27.5%→56.9% (Qwen3-30B-A3B), 50.9%→68.8% (Qwen3-Coder-30B), 72.2%→75.4% (GLM-5) — the reviewer substitutes for missing generator capability, so it is a lever for the cheap-tier generators model-routing-token-economics cares about and near-worthless bolted onto a frontier one (the same agent-conditional shape SCATE found for iteration budget, learn-when-to-stop-not-just-which-model). Second it builds SWE-Review-Bench (1,384 candidate PRs over 500 SWE-bench Verified issues) so the reviewer can be scored in both directions — accept-good and reject-bad — where a repo-exploring agentic reviewer beats single-turn fixed-context review on decision accuracy (75.6–89.4% vs ~60–75%) and on resolve-rate-after-revision; a trained open-weight reviewer (SWE-Review-8B/-30B, SFT on 8,914 decision-correct trajectories) recovers much of a prompted frontier reviewer's lift (DA 67–76%, RRR +0.4 to +8.3). This is the closest the map has to a two-sided reviewer number against its dark false-negative side — but decision accuracy on a labeled candidate set is not the production miss rate, the strong reviewer is Claude Opus 4.6, and everything rests on retrieval-contaminated SWE-bench Verified (benchmark-scores-inflate-when-agents-can-retrieve-the-fix), so the resolve deltas inherit that contamination. Also a test-time-scaling datum: review-guided revision reaches a target in 2.44 samples vs 8.9 (reviewer-gated resampling) vs 16 (best-of-N) — a better policy than best-of-N, ripple to model-routing-token-economics and ci-cd-for-agents (the revise step is the enforcement's active ingredient). Single group, arXiv v1, paired deltas unfloored (coordination-deltas-need-a-measured-noise-floor). See review-revise-loop-lifts-resolve-most-on-weak-generators.
  • 2026-07-20 — how-practitioners-build-se-agents (Lyu et al., SMU / UCL / Tencent / Alberta, arXiv, "How Do Practitioners Build SE Agents?", 2026-07-12, T1, suggestive): the interior view of this map's capacity ceiling, plus a problem with no accepted answer. On 2026-07-14 this map recorded review coverage falling 89%→68% and substantive review 39%→21% under 2× agent throughput, absorbed as silent approvals (automated-review-displaces-human-review-at-scale) — measured from outside, from telemetry. Practitioners who were not being measured report the same thing from inside and name it comprehension debt: "code is accepted before developers can explain, modify, and maintain it safely" (82% agree, mean 4.09). "Previously, a week's commits might contain a few hundred lines. Now… it is 10K or 20K lines. There is really no way to read it. People have started to give up" (P15). "This review burden should have been borne by the person upstream. Now it is all pushed onto the person downstream" (P16). "I know there is a landmine in the AI-generated code. It may eventually explode, but I have no choice" (P20). Method triangulation on a claim this map leans on heavily. What is new is that the exits are not believed: the two proposed responses — return maintenance to AI (53.9%) and preserve regenerability rather than the artifact (67.1%, the "regenerative software" framing) — are the two lowest-rated practices in a study where most clear 75%, and both sit badly with what this vault knows (returning repair to the agent routes it through the least reliable witness, users-correct-agents-in-nine-of-ten-resolutions; regenerability assumes a spec complete enough to regenerate from, which emergent-specs-corrupt-the-artifact says it is not). Carried as a live tension, not guidance. Also here: 95% agree / 0% disagree (mean 4.46, the study's strongest consensus) that AI both unmasked existing work and created new work — reviewing agent output being the new and central job. See comprehension-debt-outpaces-review-capacity.
  • 2026-07-20 — predicting-pr-acceptance-review-effort (Pansuriya/Ghorbani/Singh/AlOmar, Stevens Institute, arXiv, "Predicting Acceptance and Review Effort in Human and Agent Pull Requests", 2026-07-13, T1, single-study): read this through AUC, not the abstract. A leakage-aware pipeline (submission-time features only; reviewer comments, CI results, later commits, review decisions and merge timestamps explicitly excluded) predicts PR acceptance at AUC 0.676, falling to 0.609 when contributor populations are balanced. The paper's headline "F1 above 0.95" is what the majority-class baseline scores (F1 0.957, AUC 0.500) at a ~91.8% merged base rate; the best model beats it by 0.001 F1. So: acceptance is weakly determined by anything observable about the change at submission. That composes with this map's strongest thread rather than repeating it — merge-outcomes-are-dominated-by-who-submitted found submitter attributes carry 69–76% of explanatory power and self-integration multiplies agentic merge odds ~5,419×; this attacks the same target from the artifact side and finds little there. Together: merge outcome is weakly determined by the change and strongly determined by who submitted it — one more reason not to reward or benchmark agents on merge rate. Consistent secondary signal: for acceptance, text and metadata (body length, title length) rank above raw diff-size features; for review effort the ranking flips to diff variables. The review-effort result is the actionable half and it is new here: R² = 0.20 for comment count and R² = 0.12 for time-to-merge, with the residual attributed to reviewer queue depth, CI wait, availability and release timing. Review latency is an organizational property, so — set against the capacity ceiling above and the backlogs practitioners describe — you cannot triage your way out of a review-capacity shortage; the levers are reviewer supply, reviewer diversity (faster-ai-review-is-not-better-review), and enforcement moved into gates (gate-agent-commits-on-the-same-ci-as-humans). Reporting caveats are severe: no PR count, no agent/human split, no repository count, no date window, no list of which agents — and the human-only/agent-only breakdowns promised by the RQs are never given as numbers. See pr-acceptance-resists-prediction-at-submission-time, review-effort-is-organizational-not-artifact-determined.
  • 2026-07-18 — code-review-agents-industry-claims (Chowdhury/Banik/Ferdous/Shamim, arXiv, "From Industry Claims to Empirical Reality: An Empirical Study of Code Review Agents in Pull Requests", 2026-04-03, T1, strong): the first population-scale outcome read on the automated gate — the measurement this map has been asking for since the capacity ceiling landed. 19,450 AIDev PRs narrowed to 3,109 in commented review state: CRA-only merges 45.20% (127/281) vs human-only 68.37% (804/1,176), abandonment 34.88% vs 21.60%, and mixed review at human levels either way (67.99% human-dominated / 63.25% CRA-dominated) — so the deficit is the missing human, not the present agent. Feedback quality, with signal ratio = (Tier 1 critical + Tier 2 architectural/performance) / total comments and κ=0.75 on the manual tiering: 12 of 13 agents average below 60%, and 60.2% of closed CRA-only PRs sit at 0–30% — the authors' mechanism being that noise-dominated review leaves the author nothing actionable, so the PR is abandoned rather than repaired. Named agents include github-advanced-security, Copilot, ellipsis-dev, codefactor-io, aikido-pr-checks, two semgrep variants, entelligence-ai-pr-reviews and cursor. Reads directly against end-of-code-review-supersede's position that agents can serve every review goal, and completes a trio with faster-ai-review-is-not-better-review and unreviewed-agent-code-accrues-more-maintenance. Still not defect escape. Main threat: CRA-only review is not randomly assigned — PRs no human chose to review may be lower-value on their own, and the authors do not control for it. See reviewer-agent-only-review-halves-the-merge-rate.
  • 2026-07-18 — security-agentic-pull-requests (Siddiq/Zhao/Lopes/Casey/Santos, Notre Dame et al., arXiv, "Security in the Age of AI Teammates: An Empirical Study of Agentic Pull Requests on GitHub", 2026-01-01, T1, strong): the contribution-side complement to the post-merge security-defect number. 33,596 agent PRs across 2,807 repos and five agents (Claude Code, Copilot, Cursor, Devin, Codex) yield 1,293 (3.85%) manually-confirmed security PRs, dominated by hardening actions — refactoring 957, testing 755, documentation 692, error handling 595 — over remediation.   • 2026-07-17 — end-of-code-review-supersede (Monperrus, KTH, arXiv, "The End of Code Review: Coding Agents Supersede Human Inspection", 2026-06-11, T3, position paper): a stance marker on the map's central tension, not evidence that moves it. The argument: every stated review goal (Bacchelli & Bird's four — defect detection, style/consistency, knowledge transfer, team awareness) is servable by agents at lower cost/higher throughput, so mandatory human review is no longer necessary, and the "agents write, humans must review" arrangement is a dead end (humans rubber-stamp what they can't verify; fixed human capacity becomes the bottleneck). Proposed replacement: agent-in-the-loop verification as default gate, humans reserved for high-stakes paths. The map's own T1 evidence cuts against the load-bearing step: automated review is already overtaking humans as substantive human review collapses (automated-review-displaces-human-review-at-scale) — the paper's world arriving — yet the reviewer agent's false-negative rate is unmeasured everywhere, and agent-involved review buys only speed at higher smell prevalence driven by exactly the single-reviewer-model default this paper endorses (faster-ai-review-is-not-better-review). So the paper is right that naive human-mandatory review doesn't scale, but ahead of the evidence in concluding the human is the removable part rather than the unmeasured false-negative rate being the unsolved part. Its "reserve humans for high-stakes, gate the rest" is compatible with enforce third-party approval and review-the-diff-and-search-all-usages. No empirical contribution (argument from premises); does not move the consolidating status. See agents-can-serve-every-stated-goal-of-code-review.
  • 2026-07-17 — interaction edge from cheap-code-costly-judgment (Davis et al., Purdue, arXiv, "Cheap Code, Costly Judgment", 2026-07-04, T3, single-study): the vault's first sustained first-person account of building the substitute gate the capacity-ceiling study measured being adopted. The engineer's answer to "what replaces human review at velocity" is not a reviewer bot but an accreted governance apparatus 2.75× the size of the product — an incorporation-gate family (sentinel first-commit early abort, pre-commit hook, merge-train batching, staged deploy gates) plus 577 project-specific static analyses and 13,000+ tests, i.e. the maintenance surface mechanized. A concrete data point on what the substitute gate actually costs to build. Primary map: runtime-action-governance. See governance-conversion-controls-discovered-from-agentic-failures.
  • 2026-07-16 — agentic-review-generations-quality (Zhong/Noei/Adams/Zou, Queen's University, arXiv, "From Human-Centric to Agentic Code Review: The Impact of Different Generations of Generative AI Technology on Review Quality", 2026-07-14, T1): the largest longitudinal read on AI's arrival in review — 1.02M reviewed PRs, 207 projects, May 2022 → Feb 2026, three eras, quality proxied by normalized decision latency and six review-smell anti-patterns. Three adoption practices: Gradual (46% of projects, +2.5 days efficiency), Rapid-LLM (22%, no gain, +8% smells with the "Review Buddies" anti-pattern up 26%), Rapid-Agent (32%, +4.5 days). Nowhere does speed buy quality, and agent-involved reviews rank fastest while carrying 78–94% smell prevalence vs 69–76% human-only — the dominant driver being repeated reliance on identical AI reviewers: the human clique anti-pattern, automated and scaled. Once AI joins, collaboration patterns displace author experience (17–22% delay reduction pre-LLM) as the top efficiency factor. Gives the 2026-07-14 capacity-ceiling finding its quality counterpart — the gate that replaced human review is faster, not better — and hands the map a new lever: reviewer diversity is a measurable input. Caveats: observational; smells ≠ defects; era boundaries calendar-based; detection validated on a 384-PR sample. See faster-ai-review-is-not-better-review.
  • 2026-07-16 — interaction edge from beyond-test-presence-agent-test-quality (Jhanglani et al., Stevens Institute, arXiv, 2026-07-13, T1): the maintenance surface extends into the test suite — agent-generated tests carry 8× the unrecognized assertion patterns (11.58% vs 1.46%), maintainability friction a correctness-focused review walks past, alongside a higher flakiness-candidate rate (0.41 vs 0.30) from un-stubbed I/O and non-determinism.   • 2026-07-15 — interaction edge from post-merge-fate-agentic-code (Xia & Miller, arXiv, "Do These Violent Delights Have Violent Ends?", 2026-07-10, T1): the cost of the capacity ceiling, measured over a year. Following agent code past merge (182 repos) finds it carries 49% more corrective maintenance (HR=1.49) — and the penalty is moderated by review: each +10pp of a project's no-review rate adds ~6% agentic maintenance burden. This is the downstream bill for the 2026-07-14 finding that human review coverage falls 89% → 68% under throughput pressure (automated-review-displaces-human-review-at-scale), and it lines up with humans-silently-repair-agent-code-outside-review (72.5% of agent-code repair happens off-review): the corrective maintenance this study counts is where the skipped review resurfaces. It converts the map's "review is a formality under load" worry into a lever — enforcing review buys down the corrective bill; letting coverage lapse pays it with interest — and it re-motivates enforced third-party approval (merge-outcomes-are-dominated-by-who-submitted). Correlational moderation; carried as a direction, not a dosage. Primary map: ci-cd-for-agents. See unreviewed-agent-code-accrues-more-maintenance.
  • 2026-07-14 — enterprise-2x-review-mandate (He/Agarwal/Denisov-Blanch/Azaletskiy/Koyejo/ Vasilescu, CMU + Stanford, arXiv, "AI Writes Faster Than Humans Can Review: A Longitudinal Study of an Enterprise 2x Mandate", 2026-07-02, T1): the field study this map has needed and did not want. 802 developers / 196,212 PRs / 364 repos / Jan 2024 – Apr 2026 at a firm whose CTO publicly committed to doubling merged PRs per engineer. Throughput hit 2.09× (21.2 → 44.3 PRs/dev/month; within-developer adoption-attributable 1.46–1.72× under DiD). Review: human coverage 89% → 68%, automated 19% → 84% (crossover months after the mandate), substantive human review 39% → 21%, per-reviewer load 2.0× absorbed as doubled silent approvals, AI-PR review-lead latency +23%, substantive-review p90 queue stuck at ~73 h (vs ~63 h pre-ramp) — it never decongests; the org-level recovery is a composition shift (review coverage among merged PRs 48% → 21%). Quality proxies held: merge rate flat, and AI PRs reverted slightly less (−0.067 post-mandate, p<0.001) — carried in ci-cd-for-agents with the authors' own caveat that merge/revert are "coarse, short-horizon proxies that miss defects, incidents, and maintainability." Caveats: single near-best-case firm, observational, non-randomized (C&S estimator attenuates the throughput effect to non-significant), the model-generation channel is not identifiable (a placebo release moved the outcome as much as the real ones), and the mandate's own metric invites gaming — which the authors concede they cannot rule out (evaluation-integrity). The review findings are the best-triangulated part and, because the firm began auto-approving late in the window, conservative. Open questions:

  • NEW TENSION 2026-07-14 — the map's advice is right and the field cannot afford it. Everything here says verify from outside the agent, thoroughly, per diff. The first field study of an org that doubled agent throughput says that under that load the human review layer contracts (coverage 89% → 68%, substantive review 39% → 21%, extra load taken as silent approvals) and automation becomes the gate. This is not a refutation — nothing in the mandate study says careful review stopped working — it is a collision between a correct discipline and a capacity constraint, and the vault should carry it as such. The unresolved question is whether the automated gate that replaced human review is good enough, and the honest answer is nobody knows, because the false-negative rate of every reviewer agent in production is unmeasured. The one org publishing a reviewer-agent curve (Cursor's resolution rate) measures only the bugs it found. At 84% automated coverage, that blind spot stopped being academic. 2026-07-16 supplies the first cross-project quality read, on process proxies: AI-involved review is faster in every adoption pattern that gains at all and better in none, with agent-involved reviews carrying higher smell prevalence driven by reviewer monoculture (faster-ai-review-is-not-better-review). Still not defect escape — but the direction says the substituted gate's quality question is now measured-and-worrying, not merely unmeasured.
  • NEW 2026-07-14 — how much agent-code maintenance never touches review at all? Measured once, on one quality attribute: 72.5% of logging repair is done by humans in silent follow-up commits, with review comments in 2.18% of PRs. If that generalizes to other non-functional properties (error handling, telemetry, migrations, docs), then every review-based measurement of agent code quality — including this map's theme taxonomy and merge-label studies — is systematically undercounting, and the "quality held steady" readings from merge/revert rates are measuring a channel the work has already left. The test is cheap: instrument post-merge commit authorship on agent PRs across several quality attributes, and see who is really doing the work. 2026-07-15 runs a version of it and confirms the direction: the corrective-maintenance channel is real (1.49× hazard over a year) and it scales with skipped review (~6% per +10pp no-review rate) — so the reviewed path narrowing is not free, it is deferred cost (unreviewed-agent-code-accrues-more-maintenance). Still measured on maintenance events, not yet decomposed to per-attribute authorship.
  • The consolidation is on direction (external verification is structurally required); the field-study numbers are one telemetry population, and silent-failure undercounting means the true correction burden is bounded below, not measured exactly.
  • No measured catch-rate for the usage-search discipline — it's a named, sensible practice, not yet a quantified one.
  • The false-negative side of agent review is completely dark. Resolution rate (2026-07-11) finally gives the field a cheap, human-grounded criterion for the bugs a reviewer does flag. Nothing — vendor or academic — counts the bugs it doesn't. A reviewer that flags one real bug per PR and misses nine scores identically to one that flags one and misses none. This is the same coverage hole runtime-action-governance carries, and it is now the largest unmeasured quantity in this map.
  • Does the recall/precision co-improvement generalize, or was Bugbot's v1 simply badly tuned and the gains are a one-time climb off a bad starting point? Cursor's is the only published curve.
  • Interaction-aware evaluation is now half-instrumented: the 12-theme taxonomy is a review-behavior signal set applicable at scale (0.78 macro F1), but no one has linked the theme distribution a fleet's PRs attract to downstream shipped-defect escape. An instrument without a criterion is a proposal. OpenAI's agent-to-agent review loop (openai-harness-engineering) still has no published catch-rate versus human review.
  • Do reviewers comment on documentation and style because that is where agent code is weakest, or because those are the easiest things to comment on? The theme study measures reviewer attention and cannot separate the two — an availability effect would invert the practical advice.
  • The T2 practice entries have no independent benchmark of agentic-review effectiveness yet (the closest measured neighbor is the observability finding on error localization).
  • Open tension, narrowed 2026-07-10: reward hacking against an evaluator is now documented on real coding tasks (Cursor, T2, 63% retrieved-not-derived), not only in rubric-based RL training (T1). The exact experiment is still unrun — an agent iterating against a fixed LLM code reviewer, with and without a paired ground-truth gate (tests/CI), measuring how much the gate suppresses gaming. What Cursor establishes is that the agent takes the shortcut whenever the environment leaves one open, which makes the reviewer-gaming hypothesis substantially more plausible and moves the burden of proof.
