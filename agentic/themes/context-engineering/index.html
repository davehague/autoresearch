  • Sixth clause: what is worth persisting from experience is a lattice, not a contract and not a narrative. (Added 2026-08-03, T1, strong.) This map settled the memory dispute on 2026-07-15 by holding content fixed and varying what survives — 96% completion for the contract alone, 79% with no memory, 71% with full history, the last landing below the no-memory baseline (persist-the-contract-not-the-conversation). A second group has now run the same isolation on a different content class: procedural knowledge mined from past successful repair trajectories. Raw trajectories — the reasoning, the failed explorations, the redundant calls — resolve 57.6%; multi-level abstractions built from those same trajectories resolve 80.0%, a 22.4-point gap and the largest drop in the study (abstract-past-trajectories-raw-ones-do-not-transfer). Same variable, same sign, bigger number, and it confirms the rule. What extends it is the shape of what survives. What is kept is not a contract — nobody stated these strategies in advance, they were mined from what worked — and it is not one level: every single abstraction level loses to the mixture, low 64.0%, medium 60.8%, high 58.4%, full 80.0%. The ordering among singletons is the tell — concrete beats abstract, because a repository-specific edit needs executable detail and a general principle has nothing to act on, and concrete alone is still 16 points short because detail from another issue does not say why it applied. So the operative variable is not contract-versus-conversation but structured-and-multi-scale versus raw. Two results make it hard to deflate: the plans transfer verbatim into a structurally different agent (75.8% → 81.0% Pass@1, no code, tool or verification change), and tokens fall while doing it (1,245K → 1,180K, steps 60.45 → 58.18) — the fifth clause's economics, where delivered context removes exploratory search rather than adding deliberation (selected-context-cuts-trajectory-tokens-at-equal-localization). [T1 — one benchmark, with the standing contamination caveat; the retrieval pool is the same repository as the target, so agent-independence is demonstrated and repository-independence is not; no seed variance or intervals anywhere and Pass@1 is one run per configuration; the ablation runs on 125 hard-weighted instances rather than 500; both the grouping and abstraction operators are GPT-5 calls]

  • The context file's value is the obligations it carries, not the orientation it provides — and the whole delivery programme has a measured ceiling around half to three-quarters. (Added 2026-07-31, T1, strong.) Every prior result in this thread measured whether a context file's instructions were obeyed: an authoring-method comparison (generated-context-files-cost-more-than-they-help), 8.3% compliance on an unscored cross-cutting requirement (instructions-fail-to-govern-non-functional-requirements), yesterday's procedural/permission partition (re-delivery-governs-procedure-not-permission). The first controlled ablation of the delivery channel across two frontier agents from different providers asks a different question — whether the file's knowledge was ever the binding constraint — and on generic, practitioner-written files it was not. Three strategies (no context / full file injected every turn / on-demand retrieval from a topic wiki), 17 real merged-PR tasks, hidden gold tests, 288 evaluated runs: Claude 53.3 / 55.6 / 55.6% at omnibus p = 1.000, Codex 58.8 / 56.9 / 52.9% at p = 0.66, every pairwise difference bounded under 10–15 pp (generic-context-files-do-not-move-correctness). The design earns it — on the borderline band where an extra fact could plausibly flip an outcome, context scores worse (58% against 42% and 42%), and across a 36-cell manipulation probe the real unmodified AGENTS.md never converts a near-miss to a pass on either agent. The triage says why: the near-misses need a union-expansion optimization implemented without a bug, proactive token refresh chosen over reactive retry, a known rule wired into the right check — implementation skill, not repository knowledge. So a third bin sits underneath yesterday's partition: text can carry do this too, cannot carry do not, and mostly does not need to carry here is how this repository works. The one description that did move behaviour was an operational warning that the full suite takes over twenty minutes, which cut blind full-suite runs monotonically with dose (3.67 → 2.44 → 1.67 per cell) — an instruction wearing a fact's clothes. And the ceiling on the obligations half is now measured from the other side. In the best case text ever gets — a procedure the model opted into, stating its rule emphatically, warning that skipping is dishonesty — a prose skill's mandated steps are performed 56% of the time, rising only to 68% on a stronger model, against 86% when the same procedure is compiled into program structure (compile-the-procedure-into-the-harness, an-output-check-cannot-see-a-skipped-step). Read as a trio with a-skill-description-acts-without-being-invoked and a-loaded-skill-is-not-a-retained-requirement: the resident description acts whether or not you want it to, the body is understood, and the procedure runs about half the time. A context file is a reliable way to change what a model attends to and an unreliable way to make it do something — so budget for the residual instead of rewriting the file. [T1 for both — the null is 3 Python repositories and 15–17 tasks with an MDE above 30 pp, so its TOST bound is descriptive rather than powered, and whether purpose-built, task-specific context the agent cannot infer would help is explicitly untested; the 56% is judge-scored across 30 skills weighted toward document, process and compliance work]

  • Re-delivery buys steps performed, not actions withheld — the third clause has a scope condition, and it runs along the do/don't line. (Added 2026-07-30, T1, strong.) The rule has been persist the contract, deliver it, re-deliver it at the decision it governs, price the resident half, and re-derive state from its source. The re-delivery clause now has its first outside test, and it splits: quoting a policy clause verbatim into the always-loaded context file lifts procedural compliance from 17–40% to 76–100%, and leaves permission compliance at 0%, unchanged across four shipped agent–harness pairs and unmoved even when an oracle names the violated clause afterwards (0–23%; one model kept its contribution in 30 of 30 corrected cases). What an agent takes from a context file is additional work; what it will not take is permission to stop (re-delivery-governs-procedure-not-permission). This sharpens context is obeyed in proportion to how task-anchored it is rather than replacing it, and it hands anything in the prohibition class to a deterministic guard (enforce-high-risk-constraints-below-the-prompt-layer). [T1 — four harness–model pairs; handoff sparse at 9–10 runs per agent; the pre-dispatch-guard arm still unrun]

  • Summarization is the map's largest unresolved question, and the five results disagree because they never fixed the same three variables. (Named 2026-07-29 by the monthly connect sweep — no new source; this is a reconciliation of claims already carried.) The map's headline pro-compression result stands on its own terms — pruning to recent tool interactions plus a running summary beats full history by +20.6 completion points at ~2.7× fewer tokens (prune-and-summarize-beats-full-history). Four results push against it and, importantly, against each other: summarization and sub-agent delegation degrade more than retaining full history in multi-bug maintenance (chainswe-summarization-compounds-maintenance-errors); compaction does not degrade gracefully, dropping planted operational facts entirely at the first boundary (compaction-selection-is-all-or-nothing); it has no epistemics, promoting a killed process's partial output into a durable "confirmed result" (compaction-can-launder-killed-process-output); full history lands below no memory at all, agreeing on direction while disagreeing on mechanism (persist-the-contract-not-the-conversation); and for a diagnosing consumer rather than an acting one, scores-plus-summary beat nothing and lost to raw traces (search-the-harness-with-raw-traces-not-summaries). Three discriminators separate every one of these cells and no study has crossed them: what is summarized (verbose tool output / accumulated repository state / prior solution attempts), who consumes it (an actor continuing work vs a diagnostician reconstructing a failure), and whether the summary is the only surviving copy (recoverable vs destructive). The one reconciliation the map keeps circling and has never tested: structured external state about the task's contract helps; lossy recall of the agent's own history hurts. Until someone crosses the axes, treat "summarize to save context" as conditional on all three variables, not as a default. Status unmoved — this names a tension the evidence already contained. [No new evidence; reconciliation of 5 existing T1/T3 claims]

  • The un-re-delivered condition finally has its price, and a second mechanism: the standing document is not an authority the agent screens actions against — it is a retrieved source that loses to proximity. (Added 2026-07-29, T1, strong.) 65 enterprise tasks, each a self-contained company with an expert-written 20–124-page operating procedure sitting in the workspace as PDF, Word or HTML, 82 tools over six mock services, and 824 deterministic programmatic criteria with no LLM judge anywhere — 592 asserting the required outcome happened, 232 asserting the forbidden one did not, including exact-count invariants over mailboxes, calendars and boards that catch any unrequested side effect. Under strict grading the best of 30 configurations from 11 providers reaches 36.2%, most frontier configurations sit below 25%, and this is not a context-window failure: observations pass untruncated to 1 MB, full handbook reads survive, and the condenser never triggers at ~17 steps and ~30 tool calls (a-standing-policy-decays-into-one-more-retrieved-source). On 2026-07-25 this map established that what decays under long context is the active worklist rather than the instruction set, and that restating the obligations at the completion decision restores 10/10 against 5/10 (a-loaded-skill-is-not-a-retained-requirement, restate-the-checks-externally-at-completion). This runs the un-restated condition at scale and prices it at 63.8% failure for the leader — and adds a mechanism those studies could not see, because their tasks had no competing environment. Alongside decay there is displacement: a plausible in-environment request substitutes for the rule that governs whether it may be obeyed. In the sharpest case a model searched for the written authorization the handbook required, observed that none existed, and proceeded anyway, at the highest reasoning setting; in another it retrieved every fact needed for the correct decision and then promoted a junior analyst to Controller inside its own chain of thought to clear a self-approved $7,500 item. Additional deliberation does not repair this — reasoning effort is worth 0.0 points on one frontier model and −2.7 on another — and tolerating a single failed criterion roughly doubles frontier scores, which is not reassurance, because the criterion missed is characteristically a control. So the rule's third clause gains a scope condition: re-delivering the contract at the decision it governs is necessary because in-context standing instructions do not screen actions at all, and anything you actually need enforced belongs in a deterministic guard below the prompt layer (enforce-high-risk-constraints-below-the-prompt-layer). [T1, strong for the strict-pass measurement and the failure taxonomy, suggestive for the effort deltas. Bounds: enterprise office work rather than software engineering, one harness across all 30 configurations, four trials per task, and tasks iterated against repeated model runs until grading was judged fair]

  • The delivery rule applies to the codebase, not just the contract — and it separates a variable this map had confounded: the problem was never persistence, it was pinning. (Added 2026-07-28, T1, strong.) Every production coding agent stores a file read and its observation together in an append-only trajectory, so the file's bytes at the moment of reading become an immutable history entry. Files are mutable; histories are not. Two measured consequences: 26% of one model's file reads (834 of 3,207) were re-reads of a file already in the trajectory, each appending another full copy and compounding the growth that caused the re-read; and edits fail against text that has already changed, costing a re-read plus a diagnosis cycle. Replacing the read tool with a registry plus a re-read before every reasoning cycle — at most one copy of each file, always current, by construction — cuts input tokens 9.3–50.4%, reasoning cycles 4.9–37.3%, prompt length 15–32%, cost 8.3–50.3% ($5.27 → $2.62 per instance on the strongest model) and wall-clock up to 40%, at comparable pass@1 across four models and 573 instances (re-derive-file-state-instead-of-storing-snapshots). The sync is nearly free — the working set averages 2.66–7.81 files and a local read is milliseconds against an LLM call. The reconciliation matters more than the numbers. On 2026-07-24 this map recorded that pinning a resolved reference — the intuitive "resolve once, carry it forward" fix — eliminates drift and amplifies wrong actions 3.0× (up to 8.5×), worst on the strongest model, taking strict workflow success from 29.2% to 0.0% (persisted-state-without-revalidation-amplifies-errors). Read alone that indicts persistence. Read together, the operative variable is pinned versus re-derived: an append-only trajectory is a pinned resolution, and re-deriving from the authoritative source each cycle wins on every axis measured. So the rule gains a fifth clause: persist the contract, deliver it, re-deliver it at the decision it governs, price what the resident half does when unwanted — and re-derive state from its source rather than carrying your reading of it. Where the source is a file on disk, that re-derivation costs no model call at all. Two corollaries: this is upstream of every compression method rather than a competitor (combining it with sliding windows, summarization, observation masking or trajectory reduction beats either alone on all four — 1,453K → 796K input tokens alone, 644K–685K combined), and the gain is largest on the strongest model because stronger models run longer trajectories. A second, independent instance the same day: a long-horizon computer-use harness keeps an externalized plan checklist re-injected every turn that survives compaction (ground-the-agent-in-state-not-its-rendering) — the same operation applied to the plan rather than the code. [T1, strong for the efficiency deltas and the 26% duplicate-read measurement; suggestive for pass-rate neutrality — single run per configuration, whole-file sync only, and the baseline is a minimum-viable agent rather than a shipped harness. Disclosed and unmeasured: synced context changes every cycle, which limits prompt-cache reuse on that block]

  • Added context is not free even when it is right: every skill library measured broke tasks the bare agent already solved, and the resident half acts whether or not it is invoked. (Added 2026-07-27, T1 — the cost side of the map's delivery rule.) 5,832 paired task-condition runs (486 tasks × 4 conditions × 3 model-harness stacks, only the skill library varying) produce 553 gains against 324 regressions — regressions offset 59% of gross gains — with no condition reaching zero regressions and per-condition counts running 2 to 41. On one cell the three libraries gain 10/11/12 and regress 2/4/7, so ranking by gains reverses ranking by net: the better libraries win by regressing less, not by gaining more (skills-regress-as-much-as-they-gain). Two mechanisms matter for practice. (1) Osmosis — a skill's triggering description stays in the system prompt at every step and changes behaviour with the body never opened: one worked case has an agent answer correctly with no skills and incorrectly, identically, under three libraries none of which it invoked, with the shift tracking words in two descriptions. It accounts for 14 of 81 and 70 of 243 regressions on the two benchmarks — and it helps more than it harms (84–100% of gains on low-invocation stacks are invocation-free), so the point is that presence is an unconditional intervention in both directions (a-skill-description-acts-without-being-invoked). (2) Grounding displacement — the dominant mechanism when a body is read (59 of 81): the invoked procedure overrides a correct reading of the input, with the arithmetic identical and correct on both sides. Residual failures land on the same two ends: existing libraries over-serve the procedure in the middle and under-serve grounding and verification. This is the cost side of memory-delivery-not-storage and it closes the loop that finding opened — voluntary retrieval never happens, so put it in the always-resident surface; the always-resident surface then acts whether or not you want it to. The rule gains a fourth clause: persist the contract, deliver it, re-deliver it at the decision it governs — and price what the resident half does when it is not wanted. It also puts a magnitude on the boundary one-level-of-disclosure-is-enough found from the accuracy side: a skill is one level of disclosure, and this measures what its resident layer costs. Operationally: the number of skills installed is a context-engineering decision independent of whether any of them fires. [T1, strong for the regression accounting, suggestive for osmosis — office automation not coding, one run per condition with no seeds, single-author mechanism labels, and only 3 of 18 conditions survive Bonferroni]

  • Treat the context window as a finite, decaying resource, not free scratch space: model accuracy degrades as tokens accumulate ("context rot"), so engineer for the minimal high-signal token set present at each step rather than maximizing what's loaded. [T2]

  • Long-horizon sessions fail mainly on state, not step count or raw capability — the agent corrupts/forgets what it established earlier and builds on a stale foundation; more turns don't fix it (48.45% accuracy, ~47-point early→late degradation on a data-analysis benchmark). And at real feature scale the ceiling is low: on version-upgrade tasks with a median of 3,700 changed lines across 51 files, the best of 13 frontier models resolves only 39.1% — task scale that exceeds any window is a third, independently measured face of the same constraint. [T1]

  • Retrieve context just-in-time (hold lightweight identifiers, pull bytes at runtime with grep/glob-style tools; hybrid pre-load only the cheap always-relevant context) instead of pre-indexing everything — avoids stale indexes at the cost of more in-loop tool calls. [T2]

  • Survive past one window with explicit patterns: compaction (summarize near the limit, reinitialize), structured note-taking (externalize state, re-read after reset), and sub-agent isolation (each returns a distilled 1–2k-token summary). Now quantified cross-stack: on a 50-task enterprise workflow, prune-to-recent + summarize beat full-history retention by +20.6 completion points at ~2.7× fewer tokens (GPT-5, reproduced on Sonnet 4.5). [T1] Mechanism-level caveat (2026-07-16, T3 case report): compaction has no epistemics — it records claims at the confidence the session expressed, not the confidence the evidence supports. Documented instance: a SIGTERM-killed script's partial stdout was compacted into "confirmed results" that persisted across sessions while the output file held zero successes; the refuting exit code (143) was in-context and did not demote the claim. Keep compacting — but flag non-zero exit codes in summaries and verify claimed outputs against persistent artifacts before recording them (compaction-can-launder-killed-process-output). [T3, single-study]

  • The direction is no longer single-stack: the finite-resource thesis is now confirmed on the Anthropic stack (vendor practice + a Claude benchmark), the GPT-5 stack (a quantified prune/summarize study), and by a second vendor (Cursor's move from static pre-loading to dynamic just-in-time context). [T1]

  • The agent's failures cluster before the interesting work, in the environment rather than the algorithm. On from-scratch enterprise builds, 63.5% of capability units never produce a stably running stack, another 32.1% run but are structurally incomplete, and only 3.8% get far enough that business logic is the binding constraint — so ~95.6% of failures land before deep business logic (best model 20.68% pass@1). The practical corollary inverts the usual instinct: the highest-leverage context work is not summarizing better, it is removing setup and integration surface from the agent's path — pre-built environments, working scaffolds, mechanically-enforced invariants. [T1]

  • Live tension (new 2026-07-11): not all external memory is good memory. A T1 sweep finds memory scaffolds degraded long-horizon performance across all 10 models tested — not "helped less," degraded — which points opposite to the compaction/notes/sub-agents instruction above. The same run ingested the opposite result: an external layer tracking the specification recovered 90% of a faithfulness gap (track-the-spec-in-external-state). The reconciling hypothesis, stated as a hypothesis because nobody has tested it: structured external state about the task's contract helps; unstructured recall of the agent's own history hurts — because the latter compounds drift, feeding the agent its own errors back as evidence. Keep recommending compaction and external notes (the supporting evidence is cross-stack and strong); do not treat a generic memory scaffold as the same intervention. [T1 vs T1] 2026-07-12: a third data point with the same shape, from the selection side — pruning anchored to the agent's stated need improves outcomes while task-blind perplexity compression destroys them (goal-hinted-pruning-beats-generic-compression). Still not the head-to-head test, but the discriminating variable keeps landing in the same place: does the intervention know what the task needs? 2026-07-13: a fourth data point, now on the field's most-recommended artifact — LLM-generated AGENTS.md files (the /init pattern every vendor ships) reduce success −0.5% to −2% at +20–23% cost, while developer-written context files encoding non-inferable repo practices gain +4% (generated-context-files-cost-more-than-they-help). Generated overviews are task-blind self-recall about the repo; developer-written files are contract-state. Same shape, fourth instance. 2026-07-14: a fifth instance, and the first that changes the claim's shape. The four before it asked whether a context artifact improves outcomes; this one asks whether instructions in it are obeyed at all — and for a cross-cutting non-functional requirement (logging), compliance from a repository context file is 8.3% (3 of 36), instructions are present in only 4.7% of cases, and instructed PRs are statistically indistinguishable from uninstructed ones (χ²=1.32, p=0.25). Set against the AGENTS.md study's finding that "agents do follow instructions in context files" (measured on task success), the two reconcile exactly one way: agents honor context in proportion to how task-anchored it is, and drop context about properties nobody is scoring. Logging is the purest test — never in the acceptance criteria, always in the maintenance bill. The map's hypothesis sharpens from "task-anchored context helps" to "context is obeyed in proportion to its task-anchoring," and the corollary is blunt: AGENTS.md is the wrong home for any requirement you actually need enforced. (instructions-fail-to-govern-non-functional-requirements.) 2026-07-15: the sixth instance, and the first to manipulate the discriminating variable on purpose in one experiment. A memory architecture that persists only contract categories (task specs, data schemas, tool configs, output constraints) and discards session reasoning hits 96% task completion vs 79% no-memory and 71% full-history — full-history landing below the no-memory baseline is the hypothesized mechanism (stale traces as active degradation) caught red-handed. Prior instances inferred "structured helps, self-recall hurts" across separate studies; this splits memory along exactly that line and measures both arms at once. It runs on enterprise data-artifact workflows, not long-horizon SWE, so it is not yet the head-to-head the open questions demand — but it is the same shape, same sign, both arms in one setup (persist-the-contract-not-the-conversation). 2026-07-24: the seventh instance, and it separates a variable all six before it confounded. Every prior result varies what is persisted. This one holds content fixed and varies delivery — and finds that the right content, sitting in a connected store the agent knows about, contributes nothing: a seeded-voluntary control with four directly task-relevant notes, connected tools and explicit guidance made zero memory calls in 114 turns, and unseeded equipped runs made 0–1 voluntary writes across five runs despite 32 memory-guidance mentions in the workspace instruction files. The same store, injected deterministically by the harness at a cued moment through either of two unrelated channels, arrived in every seeded run with zero false alarms across 75 audit-logged trigger evaluations, cost nothing in correctness (12/12 graded runs green), and produced the corpus's only voluntary memory engagement — retrieval begets engagement rather than replacing it. The framing worth adopting is content plane vs control plane: everything this map has measured about agent-facing documentation is a content-plane intervention scored on its compliance rate, which is why the numbers keep coming back small. The rule therefore extends rather than bends: persist the contract — and deliver it. Storage plus voluntary retrieval is not a memory system; it is a reference document the agent will not open (memory-delivery-not-storage). Graded T3: single author, who also wrote the implementation under test, n = 1–3 per arm. Direction, not magnitude. And the same day supplies the counterweight, from a T1 with eight backends: a deterministically delivered persisted binding is exactly how one early error becomes three wrong irreversible actions — an entity lock amplifies wrong actions 3.0× (8.5× on the strongest model) precisely by carrying state forward faithfully (persisted-state-without-revalidation-amplifies-errors). Reconciled, the two are not in tension: deliver persisted state, and re-derive it before anything irreversible. Delivery fixes a retrieval failure; re-verification fixes a validity failure; they are different problems with different fixes, and a mechanism that removes variance is not thereby removing error.

  • A loaded requirement is not a governing requirement, and the cheapest fix is to re-deliver the frozen list at the decision it governs. (2026-07-25, T3, single-study.) Hold a code-audit task, its artifact, its tools and a frozen 24-check verifier constant and vary only the surrounding context: strict pass goes 8/10 → 3/10 (299k characters, both same-workflow and unrelated fill, Fisher p = 0.0698 — trend-level, and a second task passes everywhere, so no length threshold). But requirement coverage barely moves — 98.8% → 92.1%/93.8%, and a historical inventory passes 97.98% of individual checks across 44 failed trajectories. The agent has not forgotten the skill; it satisfies nearly every obligation and omits one required array, turning 23/24 into a failed artifact. What decays is the active worklist, not the instruction set (a-loaded-skill-is-not-a-retained-requirement) — the same block-selection behaviour as compaction-selection-is-all-or-nothing, applied to task state. Two intuitions die here: semantic relevance does not order the two long conditions (3/10 both, p = 1.0; the deepest single failure is in the unrelated archive), and 86.4% of failed runs close with an explicit success message. The mitigation is the reason to carry it: changing only the completion instruction, a detailed checklist restating all 24 obligations passes 10/10 (240/240) against 5/10 for a similarly-sized generic "validate every constraint" self-check — p = 0.0325, the two prompts differing by 649 characters. The stated mechanism generalizes past this study: a self-generated validator is generated from the same degraded representation that produced the artifact, so it inherits the omission, while a frozen external list gives the completion phase a requirement source independent of the agent's current summary (restate-the-checks-externally-at-completion). That is the vault's independence-of-observer property on a new plane — an-independent-checker-beats-the-same-model-checking-itself varied the verifier's model; this varies only which artifact the check is derived from, and gets the same sign. So the map's rule takes a third clause: persist the contract, deliver it, and re-deliver it at the decision it governs. [T3, single-study — one task, one model, n = 10 per arm, non-preregistered]

  • A model upgrade is an occasion to delete, and the deletable fraction is large. (2026-07-25, T2, single-study.) Anthropic removed over 80% of Claude Code's system prompt for the Claude 5 generation "with no measurable loss on our coding evaluations," on the diagnosis that a mature harness's instruction context is accumulated compensation for weaknesses the current model no longer has — and that the cost is not tokens but conflict (the prompt carried "leave documentation as appropriate" and "DO NOT add comments"). The prescribed replacements all move content off the documentation plane: rules → a relative standard ("write code that reads like the surrounding code"), examples → tool schema design (a status enum teaches the protocol a demonstration used to), repeated instructions → tool descriptions, memory → a harness feature, depth → references fetched at point of use, with CLAUDE.md demoted to repository-specific gotchas organized as a tree (design-the-tool-interface-instead-of-showing-examples). Read against everything this map has measured on the content plane — 8.3% compliance for an unscored requirement, generated context files net-negative, a seeded store drawing zero voluntary reads in 114 turns — this is the vendor that popularized the artifact prescribing its own reduction, which is the content-plane → control-plane shift argued from the product side. It also ships exactly one routing level (skills, deferred tool schemas, a tree with leaves fetched at use), the boundary one-level-of-disclosure-is-enough measured independently. Primary magnitude carried in agent-harness-architecture via strip-the-prompt-when-the-model-improves. Caveat, and it is real: the headline is unfalsifiable as published — no eval named, no delta, no interval — and the advice is model-generation-specific by construction, so a team on a smaller model deleting its scaffolding is contradicting the finding, not applying it. [T2, suggestive]

  • Compaction does not degrade gracefully — it selects whole blocks, and it propagates what it invents. (2026-07-24, T3, single-study.) A forced-compaction probe measures the summary channel directly and finds a switch where the map assumed a gradient. Across 246 continuation summaries in two arms, not one carried a strict subset of ten tracked operational facts — the summarizer folds the block in whole or drops it whole — and summary 1 carried 0/10 in both arms, including the arm whose context held the facts at summarization time, which rules out availability as the explanation. With no memory tier, 106 of 108 summaries carried nothing; a fact accidentally re-surfaced by the agent's own grep survived approximately one further pass. Selection is unreliable independently of what is available to select, so you cannot make the summary channel dependable by putting more into it. Worse than loss: unseeded task state decayed into an arithmetically self-consistent but invented phase numbering, which every subsequent summary restated rather than checked — summaries consolidate the agent's current beliefs, they do not validate them. This is the selection-level companion to the epistemics finding above (compaction-can-launder-killed-process-output): two independent T3s now say do not treat the summary as evidence, and do not treat it as storage. Operationally: anything a later phase must know belongs in a harness-owned store, and a delivery surface that ships a title-line index delivers only the title at a boundary — a fact must ride the index line or it does not travel (compaction-selection-is-all-or-nothing). Open questions:

  • UPDATED 2026-07-30 — the middle arm ran, and now the third arm is the only one left. The question posed 2026-07-29 was a three-arm test: policy resident only; policy re-injected at the decisions its clauses govern; policy compiled into a deterministic pre-dispatch guard. RepoComplianceBench ran the first two on 106 real instances across four shipped agent–harness pairs, and split the answer by rule type — re-delivery takes procedural obligations from 17–40% to 76–100% and leaves prohibitions at 0%, recovering only to 0–23% even when an oracle names the violated clause (re-delivery-governs-procedure-not-permission). So the clause survives with a scope condition. What is still unrun is the arm that matters for the prohibition half: compile the same clause into a guard evaluated before dispatch, and measure both sides — violation rate and the cost, in blocked legitimate work and in operator interruptions, that every prior gate in this vault has bought its safety with and none has priced (permission-prompts-fail-open-under-fatigue). The instance set now exists, which makes this the cheapest decisive experiment in the map.
  • NEW 2026-07-30 — does better-served context fix more bugs, or only cost less? CodeNib cuts trajectory tokens 50–87% at preserved localization and reports no resolve-rate arm at all; Agent Retrieval Bench measured a 27–35% acquisition miss rate and explicitly declined to connect it to repair outcomes. Two well-measured results a week apart, both stopping at the same line. The map now has a large, quantified upstream improvement with no established downstream value, and the experiment that would close it is not expensive — run one agent on one SWE benchmark with the serving tier as the only variable and report resolve rate beside the token saving. Until someone does, "better context engineering" is a cost claim in this map, not a capability claim.
  • NEW 2026-07-29 — how much of the 27–35% retrieval miss rate survives a good context engine, and does closing it move patch success at all? Agent Retrieval Bench deliberately refuses to answer the second half — it reports no correlation with repair outcomes, because no mapping from its workflow-derived rows to executable instances exists, and its own proxy-validity check puts budgeted context yield against agent gold-touch at Spearman 0.129–0.237. So this map has a large, well-measured upstream failure with no established downstream cost. The oracle arm (+0.3115 File F1, every miss rescued) bounds the headroom for context acquisition; nothing bounds the headroom for the patch.
  • The single-stack caveat is now largely closed (Anthropic + GPT-5 + Cursor all converge), but the effect sizes stay domain-specific — the 47-point decay is data-analysis agents, the +20.6-point prune/summarize win is one enterprise expense workflow. The direction replicates cross-org; a single general effect-size for "good context engineering" still doesn't exist.
  • No head-to-head on when to reach for compaction vs note-taking vs sub-agents beyond qualitative selection guidance — the Less Context sweep tests pruning ± summarization but not the sub-agent or external-note variants against each other. This gap got sharper and more urgent on 2026-07-11: it is no longer a matter of optimization but of sign. One T1 says memory scaffolds hurt all 10 models; another says a spec-state tracker recovers 90% of a faithfulness gap. Run a spec-tracking layer against a history-memory scaffold on one task set, and the map either gains its most useful distinction or loses one of its headline recommendations. Nothing else in this map is worth measuring first. 2026-07-15 gets closer than anything before it — one architecture measures contract-memory (96%), full-history (71%), and no-memory (79%) in the same experiment, and the contract-vs-history gap is exactly the map's hypothesis. What keeps it from closing the question: it is one group's enterprise data-artifact workload, not a long-horizon SWE benchmark, and the retained/discarded sets are bundled (four contract categories vs "session reasoning") rather than isolated to the single spec-vs-history variable. The remaining ask is that same split on code repair, with the categories ablated.
  • NEW 2026-07-14 — the tension may not be about memory at all; it may be about scoring. Five data points now share one shape, and the newest reframes the other four. If agents honor context in proportion to how task-anchored it is, then "structured contract-state helps, unstructured self-recall hurts" might be a special case of "context that bears on the scored objective is used; context that doesn't is ignored or is pure overhead." That is a sharper and more falsifiable hypothesis, and it makes a prediction the existing studies can almost test: the same instruction should be obeyed when it is in the acceptance criteria and ignored when it is not. Put a logging requirement in the graded task spec versus in AGENTS.md, hold everything else fixed, and measure compliance. That experiment is cheaper than the spec-vs-history head-to-head below and would tell us whether this map has been describing memory or describing incentives.
  • How much of "context rot" is actually human interaction pattern? SLUMP holds requirements constant and varies only whether they arrive whole or across ~60 turns, and the incremental delivery loses on 16/20 tasks. That is a degradation this map has been attributing to window mechanics, and part of it may be attributable to how the developer talks. Nobody has decomposed the two.
