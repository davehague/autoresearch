Context engineering — map

Coined 2026-07-04 (Context engineering group in the seed field map; first evidence this run) — flagged for David's review.

Status: consolidating

What we believe now:

  • Treat the context window as a finite, decaying resource, not free scratch space: model accuracy degrades as tokens accumulate ("context rot"), so engineer for the minimal high-signal token set present at each step rather than maximizing what's loaded. [T2]

  • Long-horizon sessions fail mainly on state, not step count or raw capability — the agent corrupts/forgets what it established earlier and builds on a stale foundation; more turns don't fix it (48.45% accuracy, ~47-point early→late degradation on a data-analysis benchmark). And at real feature scale the ceiling is low: on version-upgrade tasks with a median of 3,700 changed lines across 51 files, the best of 13 frontier models resolves only 39.1% — task scale that exceeds any window is a third, independently measured face of the same constraint. [T1]

  • Retrieve context just-in-time (hold lightweight identifiers, pull bytes at runtime with grep/glob-style tools; hybrid pre-load only the cheap always-relevant context) instead of pre-indexing everything — avoids stale indexes at the cost of more in-loop tool calls. [T2]

  • Survive past one window with explicit patterns: compaction (summarize near the limit, reinitialize), structured note-taking (externalize state, re-read after reset), and sub-agent isolation (each returns a distilled 1–2k-token summary). Now quantified cross-stack: on a 50-task enterprise workflow, prune-to-recent + summarize beat full-history retention by +20.6 completion points at ~2.7× fewer tokens (GPT-5, reproduced on Sonnet 4.5). [T1] Mechanism-level caveat (2026-07-16, T3 case report): compaction has no epistemics — it records claims at the confidence the session expressed, not the confidence the evidence supports. Documented instance: a SIGTERM-killed script's partial stdout was compacted into "confirmed results" that persisted across sessions while the output file held zero successes; the refuting exit code (143) was in-context and did not demote the claim. Keep compacting — but flag non-zero exit codes in summaries and verify claimed outputs against persistent artifacts before recording them (compaction-can-launder-killed-process-output). [T3, single-study]

  • The direction is no longer single-stack: the finite-resource thesis is now confirmed on the Anthropic stack (vendor practice + a Claude benchmark), the GPT-5 stack (a quantified prune/summarize study), and by a second vendor (Cursor's move from static pre-loading to dynamic just-in-time context). [T1]

  • The agent's failures cluster before the interesting work, in the environment rather than the algorithm. On from-scratch enterprise builds, 63.5% of capability units never produce a stably running stack, another 32.1% run but are structurally incomplete, and only 3.8% get far enough that business logic is the binding constraint — so ~95.6% of failures land before deep business logic (best model 20.68% pass@1). The practical corollary inverts the usual instinct: the highest-leverage context work is not summarizing better, it is removing setup and integration surface from the agent's path — pre-built environments, working scaffolds, mechanically-enforced invariants. [T1]

  • Live tension (new 2026-07-11): not all external memory is good memory. A T1 sweep finds memory scaffolds degraded long-horizon performance across all 10 models tested — not "helped less," degraded — which points opposite to the compaction/notes/sub-agents instruction above. The same run ingested the opposite result: an external layer tracking the specification recovered 90% of a faithfulness gap (track-the-spec-in-external-state). The reconciling hypothesis, stated as a hypothesis because nobody has tested it: structured external state about the task's contract helps; unstructured recall of the agent's own history hurts — because the latter compounds drift, feeding the agent its own errors back as evidence. Keep recommending compaction and external notes (the supporting evidence is cross-stack and strong); do not treat a generic memory scaffold as the same intervention. [T1 vs T1] 2026-07-12: a third data point with the same shape, from the selection side — pruning anchored to the agent's stated need improves outcomes while task-blind perplexity compression destroys them (goal-hinted-pruning-beats-generic-compression). Still not the head-to-head test, but the discriminating variable keeps landing in the same place: does the intervention know what the task needs? 2026-07-13: a fourth data point, now on the field's most-recommended artifact — LLM-generated AGENTS.md files (the /init pattern every vendor ships) reduce success −0.5% to −2% at +20–23% cost, while developer-written context files encoding non-inferable repo practices gain +4% (generated-context-files-cost-more-than-they-help). Generated overviews are task-blind self-recall about the repo; developer-written files are contract-state. Same shape, fourth instance. 2026-07-14: a fifth instance, and the first that changes the claim's shape. The four before it asked whether a context artifact improves outcomes; this one asks whether instructions in it are obeyed at all — and for a cross-cutting non-functional requirement (logging), compliance from a repository context file is 8.3% (3 of 36), instructions are present in only 4.7% of cases, and instructed PRs are statistically indistinguishable from uninstructed ones (χ²=1.32, p=0.25). Set against the AGENTS.md study's finding that "agents do follow instructions in context files" (measured on task success), the two reconcile exactly one way: agents honor context in proportion to how task-anchored it is, and drop context about properties nobody is scoring. Logging is the purest test — never in the acceptance criteria, always in the maintenance bill. The map's hypothesis sharpens from "task-anchored context helps" to "context is obeyed in proportion to its task-anchoring," and the corollary is blunt: AGENTS.md is the wrong home for any requirement you actually need enforced. (instructions-fail-to-govern-non-functional-requirements.) 2026-07-15: the sixth instance, and the first to manipulate the discriminating variable on purpose in one experiment. A memory architecture that persists only contract categories (task specs, data schemas, tool configs, output constraints) and discards session reasoning hits 96% task completion vs 79% no-memory and 71% full-history — full-history landing below the no-memory baseline is the hypothesized mechanism (stale traces as active degradation) caught red-handed. Prior instances inferred "structured helps, self-recall hurts" across separate studies; this splits memory along exactly that line and measures both arms at once. It runs on enterprise data-artifact workflows, not long-horizon SWE, so it is not yet the head-to-head the open questions demand — but it is the same shape, same sign, both arms in one setup (persist-the-contract-not-the-conversation). 2026-07-24: the seventh instance, and it separates a variable all six before it confounded. Every prior result varies what is persisted. This one holds content fixed and varies delivery — and finds that the right content, sitting in a connected store the agent knows about, contributes nothing: a seeded-voluntary control with four directly task-relevant notes, connected tools and explicit guidance made zero memory calls in 114 turns, and unseeded equipped runs made 0–1 voluntary writes across five runs despite 32 memory-guidance mentions in the workspace instruction files. The same store, injected deterministically by the harness at a cued moment through either of two unrelated channels, arrived in every seeded run with zero false alarms across 75 audit-logged trigger evaluations, cost nothing in correctness (12/12 graded runs green), and produced the corpus's only voluntary memory engagement — retrieval begets engagement rather than replacing it. The framing worth adopting is content plane vs control plane: everything this map has measured about agent-facing documentation is a content-plane intervention scored on its compliance rate, which is why the numbers keep coming back small. The rule therefore extends rather than bends: persist the contract — and deliver it. Storage plus voluntary retrieval is not a memory system; it is a reference document the agent will not open (memory-delivery-not-storage). Graded T3: single author, who also wrote the implementation under test, n = 1–3 per arm. Direction, not magnitude. And the same day supplies the counterweight, from a T1 with eight backends: a deterministically delivered persisted binding is exactly how one early error becomes three wrong irreversible actions — an entity lock amplifies wrong actions 3.0× (8.5× on the strongest model) precisely by carrying state forward faithfully (persisted-state-without-revalidation-amplifies-errors). Reconciled, the two are not in tension: deliver persisted state, and re-derive it before anything irreversible. Delivery fixes a retrieval failure; re-verification fixes a validity failure; they are different problems with different fixes, and a mechanism that removes variance is not thereby removing error.

  • Compaction does not degrade gracefully — it selects whole blocks, and it propagates what it invents. (2026-07-24, T3, single-study.) A forced-compaction probe measures the summary channel directly and finds a switch where the map assumed a gradient. Across 246 continuation summaries in two arms, not one carried a strict subset of ten tracked operational facts — the summarizer folds the block in whole or drops it whole — and summary 1 carried 0/10 in both arms, including the arm whose context held the facts at summarization time, which rules out availability as the explanation. With no memory tier, 106 of 108 summaries carried nothing; a fact accidentally re-surfaced by the agent's own grep survived approximately one further pass. Selection is unreliable independently of what is available to select, so you cannot make the summary channel dependable by putting more into it. Worse than loss: unseeded task state decayed into an arithmetically self-consistent but invented phase numbering, which every subsequent summary restated rather than checked — summaries consolidate the agent's current beliefs, they do not validate them. This is the selection-level companion to the epistemics finding above (compaction-can-launder-killed-process-output): two independent T3s now say do not treat the summary as evidence, and do not treat it as storage. Operationally: anything a later phase must know belongs in a harness-owned store, and a delivery surface that ships a title-line index delivers only the title at a boundary — a fact must ride the index line or it does not travel (compaction-selection-is-all-or-nothing). [T3, single-study]

  • 2026-07-18 — the task-anchoring rule gets its first purpose-built experiment, and it is the constructive dual. The rule ("context is obeyed in proportion to how task-anchored it is") was inferred across studies from an 8.3% compliance figure on an ungraded requirement. Now the variable is manipulated inside one design: hold the request constant, vary only whether the agent can see the 222-test oracle, and agents go from honest partial delivery (162–177/222, structurally sound) to 221–222/222 on a dead artifact. Everything unscored — here, "make it a reusable library" — is treated as optional. The generalization: task-anchoring does not merely predict compliance, it reallocates effort away from whatever lacks it. Anything you need enforced belongs in the graded channel, not in prose context. [T1, suggestive]

  • The task-anchoring rule cuts both ways, and the obedient end is an attack surface. The same mechanism that makes agents ignore an unscored cross-cutting instruction (8.3% logging compliance) makes them execute setup documentation without any provenance check, because setup instructions are the immediate task. Editing only a README, requirements.txt, or Makefile suffices to redirect an agent into installing attacker-chosen packages — name-based attacks are caught nearly everywhere, source- and version-based attacks nearly nowhere (CVE pins: 270/270 runs installed across nine harness-model configurations). Treat the docs tree as untrusted input on the execution path, not only as an asset to curate for fidelity and cost; the exposure is ordinary rather than exotic (--extra-index-url in 5,500+ READMEs, 6,900+ requirements.txt). [T1, single-study]

  • Judge the scope before gathering, not after. Every other reduction technique in this map is reactive — prune, summarize, compact what was already pulled in. Estimating a task's required scope first, executing the minimum path, and expanding only on verification failure is a distinct and earlier lever, with a metric attached (redundancy ratio against an oracle minimum). Carried with its arms separated: −85% cost / −91% tokens at equal success in a deterministic simulator, but −18% tokens versus a read-everything agent on live gpt-4o over one library at case-study scale. The durable part is directional and holds in both arms — over-provisioned context costs reliability, not just tokens (the thorough agent lost 3/3 runs on the hardest tier where the scoped one held 93%). [T1, suggestive]

  • Retriever structure is a context lever, and it can be cost-negative. (Added 2026-07-21.) The map has held "retrieve just-in-time" as grep/glob-style tool calls or a lightweight table of contents. A within-harness ablation (Claude Opus 4.7, 91 instances, 3 seeds) shows the structure of the retriever matters: a structural codebase index — vector embeddings + a graph of definitions and call edges + BM25 lexical, built over live source — lifts localization acc@5 44.3% → 84.5% (p<0.0001) and resolve 41.9% → 50.4% (p=0.003) over index-off, and beats an agentic-grep baseline by +8.1 pp localization / +6.0 pp resolve (marginal, p≈0.08) at a lower dollar-per-solve ($2.30 vs $2.92) because it finds the site faster and wastes fewer turns. The payoff concentrates on multi-file changes, so the value is workload-dependent by the authors' own framing. It composes with the point-of-use-verification axis (verify-generated-context-against-live-source): a generated index over ground truth queried at retrieval time helps, where a generated artifact trusted blind (a lossy AGENTS.md, generated-context-files-cost-more-than-they-help) hurts — same machine-built context, opposite sign, set by whether it resolves to current source. [T1, suggestive]

  • Packaged retrieval structure buys context, not intelligence — its value is the gap between corpus size and the harness's own navigation ability. (Added 2026-07-22, the first controlled test of this map's founding instruction.) Three reading strategies over the same book-length text — raw navigation, a flat description-gated skill pack, a hierarchical one — across three harnesses × three model families. On a single document the pack lifts harnesses that navigate raw text poorly and adds nothing to one whose bare agent already greps for the entities a question names; at twenty documents that same agent can no longer find the right file and the pack pulls 1.7× ahead (En.QA 0.257 → 0.462), beating a hybrid BM25+dense+rerank retriever in nearly every cell. So the technique is not a universal accuracy lever — it is a scale lever, and it is redundant until the corpus outgrows native search. The economics agree: as the corpus grows the cost–accuracy frontier recedes down and to the right, so a larger corpus is strictly less efficient to read. This is the scale condition just-in-time-context-retrieval and structural-index-beats-grep-at-lower-cost both lacked, and the two agree in shape — retrieval structure pays where the search space is too big to read. [T1, suggestive; narrative prose, no transfer to code claimed]

  • One level of disclosure, and put the index where it is paid on activation, not always. Same study, chunk set and descriptions held identical so only the wiring varies: a second routing level — every chunk its own skill with an always-loaded description plus a meta-router — never helps and sometimes destroys accuracy (En.MC 0.9126 → 0.6398; Zh.QA 0.7479 → 0.3890). The mechanism is self-inflicted and is this map's own central claim biting the retrieval index: the always-loaded child descriptions saturate the router's context before it commits to a chunk, recreating exactly the pressure disclosure exists to relieve (context-is-a-finite-decaying-resource). The same information moved from load-on-activation to always-resident flips the result from best-in-table to worse-than-raw. The concrete rule: package a long document as one skill with a single in-skill index, and treat the instinct to add a routing layer when retrieval underperforms as usually backwards — the same economy behind agents-md-is-a-map-not-a-manual. [T1]

  • 2026-07-22 — progressive-disclosure-long-context (He/Zhao/Wang/Chen, UC Davis / Zhejiang University / HKU, arXiv, "Is Progressive Disclosure All You Need for Long-Context Agents?", 2026-07-20, T1, suggestive): the first controlled study of the Agent Skills progressive-disclosure pattern — adopted across the practitioner community on engineering intuition, argued about ever since, never measured against a raw-document baseline on a standardized benchmark. Its methodological contribution is separating two design choices the practitioner literature bundles: how deep the disclosure recurses and where the per-chunk index physically lives (parent body, paid on activation, versus child description fields, paid always). Findings: the single-document gain is harness-dependent and often zero; depth never pays and sometimes collapses accuracy; and at library scale flat disclosure becomes decisive, beating raw in all six En.QA cells across two harnesses and two models — the most robust effect in the study. The authors' slogan is worth keeping: progressive disclosure buys context, not intelligence. Two ripples. It is a fourth arrival at the harness-model pair thesis (agent-harness-architecture) and the first to manipulate the harness on purpose. And its cited neighbours sharpen this map's live tension about machine-authored context: SkillsBench finds curated packs lift performance while model-authored ones add nothing — the same sign as generated-context-files-cost-more-than-they-help, and consistent with the 2026-07-20 reconciliation (verify-generated-context-against-live-source), since here the LLM writes only the routing description while the chunk bodies are ground-truth text. Caveats, the first named by the authors: a pre-training confound on the multiple-choice subset (canonical novels, with the raw agent answering correctly in too few tool calls to have read anything), so the open-QA subsets are the clean test — fortunately where the effect is largest; gains task- and language-specific (absent or negative on Chinese, where base-model capability sets the ceiling); the scale axis sampled only at K ∈ {1,5,10,20} so the crossover is bracketed, not located; one chunking recipe; several cells within one standard error; and the domain is narrative prose, not code or technical manuals, with no transfer claimed. Environment (LoongDoc, on BenchFlow) released. See progressive-disclosure-buys-context-not-intelligence, one-level-of-disclosure-is-enough.

  • 2026-07-19 — setup-instruction-supply-chain-attacks (arXiv, "Setup Complete, Now You Are Compromised", 2026-07-16, T1, single-study): this map's live tension, turned adversarial — and the inversion is the point. The standing question since 2026-07-14 has been whether context files are obeyed (instructions-fail-to-govern-non-functional-requirements: 8.3% compliance on logging). This paper measures the opposite failure: for setup documentation the agent is too obedient, with no provenance check at all. Editing only a README, requirements.txt, or Makefile — no malicious code, no compromised registry — is sufficient to make an agent install attacker-chosen packages. Name-based attacks (typosquats) are caught nearly everywhere; source-based (registry redirection, hidden index) are missed nearly everywhere; version-based (CVE pins) are missed by all nine harness-model configurations, 270/270 runs. The reconciliation with the compliance finding is clean and worth stating, because it sharpens the map's rule rather than complicating it: agents comply with context in proportion to how task-anchored it is — a logging instruction is a cross-cutting requirement nobody scores, so it is ignored; a setup instruction is the immediate task, so it is executed without question. Obedience and neglect are the same mechanism read at two ends. The operational consequence is new: this map has treated the docs tree as an asset to curate for fidelity and cost; it is also an untrusted input on the execution path, and the surface is real at scale (--extra-index-url appears in 5,500+ READMEs and 6,900+ requirements.txt files; a CUDA-wheel index URL in 10,000+). Nothing here weakens just-in-time retrieval — it adds a provenance obligation to it. Primary map: agent-harness-architecture. See project-documentation-is-a-code-execution-attack-surface.
  • 2026-07-19 — execution-scope-estimation-e3 (arXiv, "Do AI Agents Know When a Task Is Simple?", 2026-07-14, T1, suggestive): the map's context-reduction cluster is entirely reactive — prune, summarize, evict, compact, all operating on context already gathered (goal-hinted-pruning-beats-generic-compression, prune-and-summarize-beats-full-history). Open questions:

  • The single-stack caveat is now largely closed (Anthropic + GPT-5 + Cursor all converge), but the effect sizes stay domain-specific — the 47-point decay is data-analysis agents, the +20.6-point prune/summarize win is one enterprise expense workflow. The direction replicates cross-org; a single general effect-size for "good context engineering" still doesn't exist.
  • No head-to-head on when to reach for compaction vs note-taking vs sub-agents beyond qualitative selection guidance — the Less Context sweep tests pruning ± summarization but not the sub-agent or external-note variants against each other. This gap got sharper and more urgent on 2026-07-11: it is no longer a matter of optimization but of sign. One T1 says memory scaffolds hurt all 10 models; another says a spec-state tracker recovers 90% of a faithfulness gap. Run a spec-tracking layer against a history-memory scaffold on one task set, and the map either gains its most useful distinction or loses one of its headline recommendations. Nothing else in this map is worth measuring first. 2026-07-15 gets closer than anything before it — one architecture measures contract-memory (96%), full-history (71%), and no-memory (79%) in the same experiment, and the contract-vs-history gap is exactly the map's hypothesis. What keeps it from closing the question: it is one group's enterprise data-artifact workload, not a long-horizon SWE benchmark, and the retained/discarded sets are bundled (four contract categories vs "session reasoning") rather than isolated to the single spec-vs-history variable. The remaining ask is that same split on code repair, with the categories ablated.
  • NEW 2026-07-14 — the tension may not be about memory at all; it may be about scoring. Five data points now share one shape, and the newest reframes the other four. If agents honor context in proportion to how task-anchored it is, then "structured contract-state helps, unstructured self-recall hurts" might be a special case of "context that bears on the scored objective is used; context that doesn't is ignored or is pure overhead." That is a sharper and more falsifiable hypothesis, and it makes a prediction the existing studies can almost test: the same instruction should be obeyed when it is in the acceptance criteria and ignored when it is not. Put a logging requirement in the graded task spec versus in AGENTS.md, hold everything else fixed, and measure compliance. That experiment is cheaper than the spec-vs-history head-to-head below and would tell us whether this map has been describing memory or describing incentives.
  • How much of "context rot" is actually human interaction pattern? SLUMP holds requirements constant and varies only whether they arrive whole or across ~60 turns, and the incremental delivery loses on 16/20 tasks. That is a degradation this map has been attributing to window mechanics, and part of it may be attributable to how the developer talks. Nobody has decomposed the two.
