Context engineering — map

Coined 2026-07-04 (Context engineering group in the seed field map; first evidence this run) — flagged for David's review.

Status: consolidating

What we believe now:

  • Treat the context window as a finite, decaying resource, not free scratch space: model accuracy degrades as tokens accumulate ("context rot"), so engineer for the minimal high-signal token set present at each step rather than maximizing what's loaded. [T2]

  • Long-horizon sessions fail mainly on state, not step count or raw capability — the agent corrupts/forgets what it established earlier and builds on a stale foundation; more turns don't fix it (48.45% accuracy, ~47-point early→late degradation on a data-analysis benchmark). And at real feature scale the ceiling is low: on version-upgrade tasks with a median of 3,700 changed lines across 51 files, the best of 13 frontier models resolves only 39.1% — task scale that exceeds any window is a third, independently measured face of the same constraint. [T1]

  • Retrieve context just-in-time (hold lightweight identifiers, pull bytes at runtime with grep/glob-style tools; hybrid pre-load only the cheap always-relevant context) instead of pre-indexing everything — avoids stale indexes at the cost of more in-loop tool calls. [T2]

  • Survive past one window with explicit patterns: compaction (summarize near the limit, reinitialize), structured note-taking (externalize state, re-read after reset), and sub-agent isolation (each returns a distilled 1–2k-token summary). Now quantified cross-stack: on a 50-task enterprise workflow, prune-to-recent + summarize beat full-history retention by +20.6 completion points at ~2.7× fewer tokens (GPT-5, reproduced on Sonnet 4.5). [T1] Mechanism-level caveat (2026-07-16, T3 case report): compaction has no epistemics — it records claims at the confidence the session expressed, not the confidence the evidence supports. Documented instance: a SIGTERM-killed script's partial stdout was compacted into "confirmed results" that persisted across sessions while the output file held zero successes; the refuting exit code (143) was in-context and did not demote the claim. Keep compacting — but flag non-zero exit codes in summaries and verify claimed outputs against persistent artifacts before recording them (compaction-can-launder-killed-process-output). [T3, single-study]

  • The direction is no longer single-stack: the finite-resource thesis is now confirmed on the Anthropic stack (vendor practice + a Claude benchmark), the GPT-5 stack (a quantified prune/summarize study), and by a second vendor (Cursor's move from static pre-loading to dynamic just-in-time context). [T1]

  • The agent's failures cluster before the interesting work, in the environment rather than the algorithm. On from-scratch enterprise builds, 63.5% of capability units never produce a stably running stack, another 32.1% run but are structurally incomplete, and only 3.8% get far enough that business logic is the binding constraint — so ~95.6% of failures land before deep business logic (best model 20.68% pass@1). The practical corollary inverts the usual instinct: the highest-leverage context work is not summarizing better, it is removing setup and integration surface from the agent's path — pre-built environments, working scaffolds, mechanically-enforced invariants. [T1]

  • Live tension (new 2026-07-11): not all external memory is good memory. A T1 sweep finds memory scaffolds degraded long-horizon performance across all 10 models tested — not "helped less," degraded — which points opposite to the compaction/notes/sub-agents instruction above. The same run ingested the opposite result: an external layer tracking the specification recovered 90% of a faithfulness gap (track-the-spec-in-external-state). The reconciling hypothesis, stated as a hypothesis because nobody has tested it: structured external state about the task's contract helps; unstructured recall of the agent's own history hurts — because the latter compounds drift, feeding the agent its own errors back as evidence. Keep recommending compaction and external notes (the supporting evidence is cross-stack and strong); do not treat a generic memory scaffold as the same intervention. [T1 vs T1] 2026-07-12: a third data point with the same shape, from the selection side — pruning anchored to the agent's stated need improves outcomes while task-blind perplexity compression destroys them (goal-hinted-pruning-beats-generic-compression). Still not the head-to-head test, but the discriminating variable keeps landing in the same place: does the intervention know what the task needs? 2026-07-13: a fourth data point, now on the field's most-recommended artifact — LLM-generated AGENTS.md files (the /init pattern every vendor ships) reduce success −0.5% to −2% at +20–23% cost, while developer-written context files encoding non-inferable repo practices gain +4% (generated-context-files-cost-more-than-they-help). Generated overviews are task-blind self-recall about the repo; developer-written files are contract-state. Same shape, fourth instance. 2026-07-14: a fifth instance, and the first that changes the claim's shape. The four before it asked whether a context artifact improves outcomes; this one asks whether instructions in it are obeyed at all — and for a cross-cutting non-functional requirement (logging), compliance from a repository context file is 8.3% (3 of 36), instructions are present in only 4.7% of cases, and instructed PRs are statistically indistinguishable from uninstructed ones (χ²=1.32, p=0.25). Set against the AGENTS.md study's finding that "agents do follow instructions in context files" (measured on task success), the two reconcile exactly one way: agents honor context in proportion to how task-anchored it is, and drop context about properties nobody is scoring. Logging is the purest test — never in the acceptance criteria, always in the maintenance bill. The map's hypothesis sharpens from "task-anchored context helps" to "context is obeyed in proportion to its task-anchoring," and the corollary is blunt: AGENTS.md is the wrong home for any requirement you actually need enforced. (instructions-fail-to-govern-non-functional-requirements.) 2026-07-15: the sixth instance, and the first to manipulate the discriminating variable on purpose in one experiment. A memory architecture that persists only contract categories (task specs, data schemas, tool configs, output constraints) and discards session reasoning hits 96% task completion vs 79% no-memory and 71% full-history — full-history landing below the no-memory baseline is the hypothesized mechanism (stale traces as active degradation) caught red-handed. Prior instances inferred "structured helps, self-recall hurts" across separate studies; this splits memory along exactly that line and measures both arms at once. It runs on enterprise data-artifact workflows, not long-horizon SWE, so it is not yet the head-to-head the open questions demand — but it is the same shape, same sign, both arms in one setup (persist-the-contract-not-the-conversation).

Through-line (newest first):

  • 2026-07-16 — compaction-epistemic-failure (Tamba, independent, arXiv, "Compaction as Epistemic Failure: How Agentic LLM Tools Fabricate Confirmed Results from Killed Processes", 2026-07-11, T3, single-study): a mechanism-level caveat on the map's headline compaction recommendation. A long-running script killed via SIGTERM (exit 143) before persisting results had its partial terminal output recorded by session compaction as confirmed results, which then persisted across sessions unverified — the actual output file contained zero successes (11 HTTP 400s); four structurally identical instances in 48 hours. The conflation: terminal-observed ≈ disk-persisted. This is the self-report unreliability the vault already carries (users-correct-agents-in-nine-of-ten-resolutions) being made durable at the summarization boundary — the inverse face of persist-the-contract-not-the-conversation (what you persist decides whether memory helps or harms). Mitigations are verification-shaped: flag non-zero exit codes in summaries; check claimed outputs against persistent artifacts; tier confidence (file-verified vs terminal-observed). Case report, not a rate — n=1 primary + 4 corroborating, one user's workflow, undocumented compaction internals; moves no status. Also ripples to observability (the post-compaction trajectory no longer contains the evidence an audit needs). See compaction-can-launder-killed-process-output.
  • 2026-07-15 — shared-selective-persistent-memory (Pedada/Dhavala/Patil, arXiv, "Shared Selective Persistent Memory for Agentic LLM Systems", 2026-07-10, T1): the closest thing yet to a designed test of the live tension — it splits memory along the exact line the map hypothesized. Persist only the contract (task specs, data schemas, tool configs, output constraints), discard session reasoning: 96% completion vs 79% no-memory vs 71% full-history. The authors' own line names the mechanism: "naive full-history persistence actively degrades completion by biasing the agent with stale traces, while selective memory outperforms both extremes." Full-history below no-memory is the drift-compounding the map has flagged since 2026-07-11, now measured in one comparison rather than inferred across studies. A zero-token data refresh is an orthogonal model-routing-token-economics win (97× per-invocation cost cut, 12/12 replications). Caveats: architecture-proposal-with-eval on enterprise data-artifact workflows (not code repair), model(s)/trial count under the 96/79/71 split unreported, four-category taxonomy is a design choice not an ablation; single group, arXiv v1. Same shape/sign as the existing four data points; does not close the SWE-domain head-to-head. See persist-the-contract-not-the-conversation.
  • 2026-07-14 — interaction edge from agent-logging-practices (Ouatiti/Sayagh/Li/Hassan, Queen's / ETS, arXiv, "Do AI Coding Agents Log Like Humans?", 2026-04-10, T1): the live tension's fifth data point, arriving on a new axis — compliance rather than performance. Logging instructions appear in 4.7% of agentic PRs that have any observable instruction channel (98.7% of all agentic PRs have none), and where they appear they are ignored: 8.3% add-compliance from repository instruction files (AGENTS.md, CLAUDE.md, copilot-instructions.md), 27.3% for strong issue-level instructions, ~67% overall non-compliance on constructive requests — and instructed PRs behave no differently from uninstructed ones (p=0.25). This does not contradict generated-context-files-cost-more-than-they-help (which found agents do follow context-file instructions on scored tasks); it bounds it. The reconciliation is the map's sharpest formulation yet: context is followed to the extent it is task-anchored, and a cross-cutting quality attribute nobody scores is the limiting case. The authors' remedy — deterministic CI guardrails, not prose — is runtime-action-governance's instruction arriving on the quality axis. Caveat: the guardrail recommendation is an inference from the compliance gap, not a tested intervention — there is no guardrail-vs-prompt arm in the study. Primary map: observability. See instructions-fail-to-govern-non-functional-requirements, agents-under-instrument-the-code-they-write.
  • 2026-07-13 — evaluating-agents-md (Gloaguen et al., ETH Zurich / LogicStar, arXiv, "Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?", 2026-02-12 (v2 2026-06-23), T1): pushes back on the most-shipped context artifact. Four agents × three settings on SWE-bench Lite (300 tasks) + AGENTbench (138 tasks, 12 niche repos with real developer-written context files): LLM-generated context files −0.5% to −2% success at +20–23% cost; developer-written +4%; generated files only help (+2.7%) when the repo's docs are deleted — they are a lossy README copy. Agents follow the instructions; overviews just don't shorten the path to relevant code. Kills the weak form ("run /init, commit, assume value") while sharpening agents-md-is-a-map-not-a-manual — OpenAI's ~100-line hand-maintained ToC sits on the winning, developer-written side of the split. Fourth data point for the live tension. See generated-context-files-cost-more-than-they-help.
  • 2026-07-12 — swe-pruner-context-pruning (Wang et al., SJTU et al., arXiv, "SWE-Pruner: Self-Adaptive Context Pruning for Coding Agents", 2026-01-23 (v4 2026-05-07), T1): the prune-side thread gains a third independent group and a mechanism — a 0.6B skimmer prunes tool outputs line-by-line against the agent's stated information need (a context_focus_question on file tools). SWE-bench Verified: −23.1% tokens/+1.4 pts (Sonnet 4.5), −38.3%/+1.2 pts (GLM-4.6); rounds −18.2–25.7%; cost −26.8%/−36.4%; up to 54.4% reduction on SWE-QA. The instructive contrast: generic perplexity-based compression (LLMLingua-2) scores near-zero AST correctness (0.29%) and loses 10 points of success where the goal-anchored skimmer holds 87.3% — a third data point shaped exactly like the live tension below: task-anchored context interventions help, task-blind ones hurt. See goal-hinted-pruning-beats-generic-compression.
  • 2026-07-11 — beyond-pass-at-1-reliability (Khanal/Tao/Zhou, arXiv, "Beyond pass@1", 2026-03-31, T1): pushes back — memory scaffolds degraded performance on longer horizons across all 10 models evaluated (23,392 episodes, 396 tasks). Read next to slump-emergent-specification (same run, where an external spec-state tracker recovered 90% of a faithfulness gap), the two suggest the distinction is what you externalize, not whether you do.   • 2026-07-11 — interaction edge from slump-emergent-specification (Yan/Chen/Zhang, Purdue, arXiv, "When the Specification Emerges", 2026-03-17, T1): a context-engineering intervention wearing a spec-tracking label. It also identifies a context cost nobody had priced: the way humans normally talk to agents — dribbling requirements across ~60 turns — is itself a degradation mechanism, worth 16/20 papers against handing the same spec over whole. Open questions:

  • The single-stack caveat is now largely closed (Anthropic + GPT-5 + Cursor all converge), but the effect sizes stay domain-specific — the 47-point decay is data-analysis agents, the +20.6-point prune/summarize win is one enterprise expense workflow. The direction replicates cross-org; a single general effect-size for "good context engineering" still doesn't exist.
  • No head-to-head on when to reach for compaction vs note-taking vs sub-agents beyond qualitative selection guidance — the Less Context sweep tests pruning ± summarization but not the sub-agent or external-note variants against each other. This gap got sharper and more urgent on 2026-07-11: it is no longer a matter of optimization but of sign. One T1 says memory scaffolds hurt all 10 models; another says a spec-state tracker recovers 90% of a faithfulness gap. Run a spec-tracking layer against a history-memory scaffold on one task set, and the map either gains its most useful distinction or loses one of its headline recommendations. Nothing else in this map is worth measuring first. 2026-07-15 gets closer than anything before it — one architecture measures contract-memory (96%), full-history (71%), and no-memory (79%) in the same experiment, and the contract-vs-history gap is exactly the map's hypothesis. What keeps it from closing the question: it is one group's enterprise data-artifact workload, not a long-horizon SWE benchmark, and the retained/discarded sets are bundled (four contract categories vs "session reasoning") rather than isolated to the single spec-vs-history variable. The remaining ask is that same split on code repair, with the categories ablated.
  • NEW 2026-07-14 — the tension may not be about memory at all; it may be about scoring. Five data points now share one shape, and the newest reframes the other four. If agents honor context in proportion to how task-anchored it is, then "structured contract-state helps, unstructured self-recall hurts" might be a special case of "context that bears on the scored objective is used; context that doesn't is ignored or is pure overhead." That is a sharper and more falsifiable hypothesis, and it makes a prediction the existing studies can almost test: the same instruction should be obeyed when it is in the acceptance criteria and ignored when it is not. Put a logging requirement in the graded task spec versus in AGENTS.md, hold everything else fixed, and measure compliance. That experiment is cheaper than the spec-vs-history head-to-head below and would tell us whether this map has been describing memory or describing incentives.
  • How much of "context rot" is actually human interaction pattern? SLUMP holds requirements constant and varies only whether they arrive whole or across ~60 turns, and the incremental delivery loses on 16/20 tasks. That is a degradation this map has been attributing to window mechanics, and part of it may be attributable to how the developer talks. Nobody has decomposed the two.
