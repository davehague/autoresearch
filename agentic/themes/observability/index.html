Logging, auditability & observability — map

Coined 2026-07-04 (Logging, auditability & observability group in the seed field map; first evidence this run) — flagged for David's review.

Status: consolidating

What we believe now:

  • Attribution beats symptom-side repair by 2–3× — and the attribution itself is right under four times in ten. (Added 2026-07-26, T1; general agentic and assistant traces, not coding.) The map's founding instruction finally closes into an action, and reports its own precision. The action: organizing debugging as Detect → Attribute → Recover → Rerun, with the rerun starting from the attributed checkpoint, repairs 13 of 73 failed runs against Reflexion's 6, AutoManual's 5 and CRITIC's 4 (overall 55.8% → 63.6%). Those three baselines all repair from the visible failure, which is on average ten steps downstream of the cause (decisive-errors-strike-early-and-surface-late) — so the gap is the operational value of first-wrong-step localization, priced (close-the-loop-from-attribution-to-rerun). The precision: strict agent-and-step accuracy is 28.8% on a 9B backbone and 38.0% on a 27B one. Naming the right agent alone reaches 56.0%; landing within one step reaches 44.0%. So the honest statement of this map's core practice is that a majority of attributions are wrong and it is still the best move available — which means an attribution is a hypothesis, and anything downstream that treats it as ground truth (a training signal, a regression label, an automated rollback) is consuming a minority-correct estimate, the same failure shape as harness-self-evolution-is-capped-by-its-proxy-judge (first-wrong-step-attribution-is-mostly-wrong). Two transferable implementation details: detection runs deterministic rule packs first and escalates to LLM judgment only for what they cannot decide (enforce-invariants-not-implementations), and attribution is an explicit cost ladder — heuristics, one whole-trace pass, binary search, per-step inspection, budgeted ensembles — rather than a single strategy (expose-a-cost-quality-dial-not-a-fixed-policy). [T1 — but GAIA and Who&When, not SWE; the +7.8 points bundles attribution with the rerun by the authors' own statement; the attribution advantage disappears on hosted backbones, so the machinery is compensation for a weak diagnostician]
  • The operator surface for a governed fleet is the security log, and it must carry the deciding signals, not just the decision. (Added 2026-07-25, T2 practice.) Every instrument in this map so far has been analytic — applied after the fact to trajectories collected for research. One vendor specifies the same signal as production telemetry: every automated approval, every tool call and every agent-to-agent message shipped to the SIEM together with the signals used and the human accountability record. That meets measure-whether-evidence-reconstructs-the-claim by construction rather than assessing it afterwards. Two structural requirements make it work: single-purpose agent identities at minimum permissions, so the actor of every logged action is unambiguous — which matters because the modal agent bug emits no signal at all, so attribution cannot come from an exception — and agent-to-agent traffic routed through a monitored channel rather than direct, which is the only reason one agent asking a peer to push code was a visible event (least-agency-blocks-an-agent-that-recruits-another-agent). The question of which system should hold agent telemetry gets a plain answer: the one already built to record who did what, on what basis, and whether it was authorized (route-agent-identities-and-messages-through-the-siem, treat-internal-agents-as-insider-threats). Unmeasured: detection rate, time-to-response, false-positive burden, and log volume at agent-authored throughput. [T2, suggestive]
  • Silence is the modal failure, so an outcome-keyed monitor is blind to the plurality of defects. (Added 2026-07-20.) Across 255 hand-labeled agent-reactive bugs the largest symptom class is Silent Errors at 108/255 (42.4%) — normal-looking run, fluent answer or modified workspace, no exception, warning, retry, or non-zero exit. And the two triggers most reliably silent are exactly the claims-versus-evidence mismatches this map proposes auditing: instruction non-compliance (81% silent) and statement fabrication (90% silent). Because a crash gets filed and a quiet wrong answer often goes unattributed, 42.4% is a lower bound on the silent share. [T1, suggestive]
  • Grade the trajectory, not just the outcome: locate the first wrong step that made the answer unreliable rather than only scoring the final answer, because a run can end "correct" while resting on a broken step (DRIFT lifts error-localization accuracy up to 30 points over baselines on a 1,000-instance benchmark). Now cross-org and cross-granularity: a production runtime framework reaches the same conclusion at the pipeline-stage level — completion collapses 100%→20% across serial stages, so a final-outcome score is meaningless and you must localize the failing stage. [T1]
  • The reliable audit signal is the gap between what the agent claimed and what its own trajectory gathered: track claims, bind each to supporting evidence in the log, flag unsupported or conflicting claims that reach the answer path — rather than judging each reasoning span for surface plausibility. [T1]
  • The field now has a shared process-defect vocabulary, not just localization methods: an ontology of 11 defect types in 4 categories over a unified trajectory representation, plus a control-preservation axis — agents with similar pass rates differ widely on both, so outcome benchmarks alone misgrade agents. [T1]
  • Trajectory observability is not only diagnostic — it can be an actuator. Represent the system's editable components explicitly, distill trajectories into an evidence corpus, and pair each proposed change with a prediction verified against outcome, and the same evidence used to localize failures drives a control loop that improves the system (a self-evolving harness: Terminal-Bench 2 69.7%→77.0% over ten iterations). [T1]
  • NEW LIMB 2026-07-14 — the agent degrades the observability of the system it builds. Every claim above concerns observing the agent. This one concerns the product: across 4,550 agentic vs 3,276 human PRs in 81 repos, agents change logging less often than humans in 58.4% of repositories, and their apparent higher log density is mostly a PR-size artifact (control for size and it collapses to 1.64 vs 1.59 logs per 1,000 LOC). The divergence is not uniform — agents match human practice in try/catch (the mechanical, pattern-matchable case) and diverge most in conditional branches (46.7% similar) and loops (41.5% similar), which is exactly where a human decides from context that a future maintainer will need to know what happened. Telling the agent to log does not fix it: instructions are present in 4.7% of cases and complied with 8.3% of the time from a repository context file (instructions-fail-to-govern-non-functional-requirements). Humans backfill 72.5% of the missing instrumentation, silently, off-review. The consequence lands on the rest of the vault: unattended-operation's operator surface and this map's own in-loop audit window both assume the code beneath the agent is instrumented. What the study does not show is downstream cost — no incidents, no MTTR, no debugging-time data. The gap is measured; that it hurts is inferred. [T1]
  • The window for in-loop trajectory auditing is now measured, and it is wide enough to act in. The error that decides a failed run lands at a median of 7 steps into trajectories averaging 27, but the first observable failure signal trails it by ~10 steps — and 57.9% of decisive errors are epistemic (the agent misused information already in its own trajectory; false premises alone are 30.7% of all failures). So first-wrong-step localization has ~10 steps of headroom, and the claims-vs-evidence audit substrate is the right one: the catching evidence was already in-context. The optimization target flips accordingly — 71% of successful runs also hit errors; recovery, not error avoidance, separates outcomes, so optimize the error→detection loop, not the error rate. [T1]

  • 2026-07-26 — agentdebugx-failure-attribution-recovery (Zhu et al., multi-institution, arXiv, "AgentDebugX", 2026-07-21, T1; general agentic and assistant traces, not coding — taken for method, not magnitudes): the first source to close this map's loop and the first to report how often its central instrument is correct. Built on the map's own premise, stated in the abstract: "the step where an error surfaces is often not the one that caused it," and existing tools "replay execution traces but provide little support for identifying the root cause or translating diagnosis into recovery." Recovery (GAIA, 165 tasks, 73 failures, one rerun each): attribute-then- rerun repairs 13/73 and lifts overall accuracy 55.8% → 63.6%, against Reflexion 6/73, AutoManual 5/73, CRITIC 4/73 — a 2–3× gap over three policies that repair from the symptom, with the largest gain on Level-2 multi-hop tasks (48.8 → 61.6) (close-the-loop-from-attribution-to-rerun). Attribution (Who&When, 184 traces): strict agent-and-step 28.8% vs 21.7% on qwen3.5-9b (agent 56.0 vs 47.8, exact step 28.8 vs 22.3, step ±1 44.0 vs 35.3) and 38.0% vs 36.4% on qwen3.6-27b. That second set is the number this map has been missing: the practice is validated and mostly wrong, so an attribution is a hypothesis rather than a fact (first-wrong-step-attribution-is-mostly-wrong). Method details worth stealing regardless of the domain: deterministic rule packs before LLM judgment at detection, and an attribution cost ladder ending in budgeted ensembles at 12.8K tokens against 8.1K for one whole-trace pass (1.6×) — with the authors declining to invoke the expensive path unconditionally because on hosted backbones "a single global reading is already stronger and adjudication does not improve it." Bounds: GAIA is not SWE; the +7.8 points "neither isolates attribution's effect alone nor is a blind single-shot score"; recovery execution is gated on human approval; and the opt-in Error Hub's scrubbing "strips event inputs and redacts known credential/PII patterns but not arbitrary content."

  • 2026-07-25 — interaction edge from agent-skills-long-context-failure (Yue Xue, independent, arXiv, "How Agent Skills Fail under Long Contexts", 2026-07-20, T3, single-study): a third number under the claims-versus-evidence audit, plus a usable coding scheme. 38 of 44 failed runs (86.4%) close with an explicit success, safe or completion message (audit-agent-claims-against-trajectory-evidence) — and the study's four-class taxonomy of the first visible divergence is directly reusable for trajectory triage: lost requirement (a mandatory item absent from the active task or the artifact), editing drift (the requirement is present and the edit violates it), failed checking (tool output or artifact contradicts completion and is not repaired), and non-agent failure (evaluator or runtime).   • 2026-07-24 — interaction edge from cue-anchored-working-memory-harness (Saha, independent, arXiv, "Delivery, Not Storage", 2026-07-23, T3, single-study): audit-agent-claims-against-trajectory-evidence in its purest available form, and two findings about the audit substrate.   • 2026-07-24 — interaction edge from binding-drift-multi-step-agents (Babu/Indukuri, arXiv, "Binding Drift", 2026-07-17, T1, suggestive): a failure class that is silent by construction, adding a mechanism to the map's 2026-07-20 field-scale finding that silence is the modal symptom (108/255, 42.4% — silent-errors-dominate-agent-bug-reports).   • 2026-07-22 — interaction edge from trim-codeslop-trajectory-minimization (Mathai et al., Columbia / Google / Google DeepMind, arXiv, "TRIM", 2026-07-20, T1, strong): the cleanest instance yet of this map's claim that trajectory evidence can drive a control loop, not merely diagnose (evolve-the-harness-from-trajectory-observability, audit-agent-claims-against-trajectory-evidence) — and the tidiest, because the signal consumed is the trajectory's structure rather than its content.   • 2026-07-20 — agent-reactive-bugs-model-harness-boundary (Chen et al., arXiv, "Understanding Agent-Reactive Bugs at the Model-Harness Boundary", 2026-07-17, T1, suggestive): the field-scale case for this map's founding instruction. Across 255 hand-labeled agent-reactive bugs the largest symptom class is Silent Errors — 108/255 (42.4%): the agent runs normally, produces a fluent answer or a modified workspace, and no exception, warning, retry, or non-zero exit fires. Crash 71 (27.8%), Error-in-Output 34 (13.3%), Retry Loop 33 (12.9%), Hang 9 (3.5%) make up the rest. It also promotes a vivid anecdote to a category: compaction laundering a killed process's partial output into a confirmed result (compaction-can-launder-killed-process-output) is one instance of statement fabrication, and there are 20 here from user-filed issues. Downstream consequence shared with ci-cd-for-agents: a silent error passes every gate that checks for exceptions or exit codes, and detection needs an oracle that frequently does not exist — the authors name absent test oracles as why these are hard to catch and hard to reproduce.   • 2026-07-07 — ramp-runtime-agent-assessment (Ouyang et al., arXiv, "Benchmarks are Not Enough: RAMP", 2026-05-26, T1): the runtime/production face of first-wrong-step localization — on serial production workflows completion decays 100%→20% down the chain and none of 15 models finish the pipeline, so RAMP builds staged recovery to localize which stage broke. A different org and granularity (pipeline stages vs reasoning spans) reaching the same "grade the trajectory, localize the break" conclusion — the cross-org convergence that moves this map from emerging to consolidating.   • 2026-07-04 — seeded from span-level-error-localization (Wang et al., arXiv, "Where Do Deep-Research Agents Go Wrong?", 2026-06-01, T1): TELBench (1,000 instances, 2,790 annotated trajectories) reframes agent evaluation around first-wrong-step localization, and DRIFT localizes by auditing claims against trajectory evidence (+ up to 30 points over baselines). See localize-first-wrong-step-not-final-answer, audit-agent-claims-against-trajectory-evidence.

Open questions:

  • NEW 2026-07-14 — the map has two halves now, and only one is measured. Observability of the agent is well-instrumented (spans, defect ontologies, audit windows, supervisor coverage). Observability of what the agent builds has exactly one source, and it shows the property degrading while nobody gates on it. The missing quantity is the one that would make it matter: does agent under-instrumentation cost anything downstream? No incident rate, no MTTR, no time-to-diagnose has been measured against agent-authored code. Until someone links the instrumentation gap to a debugging outcome, this limb is a measured behavior in search of a consequence — plausible, unpriced, and exactly the sort of thing the vault should refuse to over-claim.
  • NEW 2026-07-14 — the recursion nobody has closed. If agents write less logging, and the field's own trajectory-audit techniques (audit-agent-claims-against-trajectory-evidence, decisive-errors-strike-early-and-surface-late) depend on evidence being present in the run, then an increasingly agent-authored codebase is quietly eroding the substrate this map's methods run on. That is a testable prediction — first-wrong-step localization accuracy should be lower in agent-authored code than in human-authored code — and nobody has run it.
  • The three sources converge on the principle (localize the first break, not the final outcome) but span three domains and granularities — deep-research reasoning spans, production pipeline stages, harness components — so the mechanism replicates cross-org while no single localization metric is shared across them.
  • Still no clean account of the cost of always-on trajectory auditing / evidence-corpus distillation (extra model calls per run) versus sampling — now a live tension for the self-evolving-harness use, where the corpus quality is the new bottleneck.
