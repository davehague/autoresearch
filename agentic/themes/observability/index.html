Logging, auditability & observability — map

Coined 2026-07-04 (Logging, auditability & observability group in the seed field map; first evidence this run) — flagged for David's review.

Status: consolidating

What we believe now:

  • Grade the trajectory, not just the outcome: locate the first wrong step that made the answer unreliable rather than only scoring the final answer, because a run can end "correct" while resting on a broken step (DRIFT lifts error-localization accuracy up to 30 points over baselines on a 1,000-instance benchmark). Now cross-org and cross-granularity: a production runtime framework reaches the same conclusion at the pipeline-stage level — completion collapses 100%→20% across serial stages, so a final-outcome score is meaningless and you must localize the failing stage. [T1]
  • The reliable audit signal is the gap between what the agent claimed and what its own trajectory gathered: track claims, bind each to supporting evidence in the log, flag unsupported or conflicting claims that reach the answer path — rather than judging each reasoning span for surface plausibility. [T1]
  • The field now has a shared process-defect vocabulary, not just localization methods: an ontology of 11 defect types in 4 categories over a unified trajectory representation, plus a control-preservation axis — agents with similar pass rates differ widely on both, so outcome benchmarks alone misgrade agents. [T1]
  • Trajectory observability is not only diagnostic — it can be an actuator. Represent the system's editable components explicitly, distill trajectories into an evidence corpus, and pair each proposed change with a prediction verified against outcome, and the same evidence used to localize failures drives a control loop that improves the system (a self-evolving harness: Terminal-Bench 2 69.7%→77.0% over ten iterations). [T1]
  • NEW LIMB 2026-07-14 — the agent degrades the observability of the system it builds. Every claim above concerns observing the agent. This one concerns the product: across 4,550 agentic vs 3,276 human PRs in 81 repos, agents change logging less often than humans in 58.4% of repositories, and their apparent higher log density is mostly a PR-size artifact (control for size and it collapses to 1.64 vs 1.59 logs per 1,000 LOC). The divergence is not uniform — agents match human practice in try/catch (the mechanical, pattern-matchable case) and diverge most in conditional branches (46.7% similar) and loops (41.5% similar), which is exactly where a human decides from context that a future maintainer will need to know what happened. Telling the agent to log does not fix it: instructions are present in 4.7% of cases and complied with 8.3% of the time from a repository context file (instructions-fail-to-govern-non-functional-requirements). Humans backfill 72.5% of the missing instrumentation, silently, off-review. The consequence lands on the rest of the vault: unattended-operation's operator surface and this map's own in-loop audit window both assume the code beneath the agent is instrumented. What the study does not show is downstream cost — no incidents, no MTTR, no debugging-time data. The gap is measured; that it hurts is inferred. [T1]
  • The window for in-loop trajectory auditing is now measured, and it is wide enough to act in. The error that decides a failed run lands at a median of 7 steps into trajectories averaging 27, but the first observable failure signal trails it by ~10 steps — and 57.9% of decisive errors are epistemic (the agent misused information already in its own trajectory; false premises alone are 30.7% of all failures). So first-wrong-step localization has ~10 steps of headroom, and the claims-vs-evidence audit substrate is the right one: the catching evidence was already in-context. The optimization target flips accordingly — 71% of successful runs also hit errors; recovery, not error avoidance, separates outcomes, so optimize the error→detection loop, not the error rate. [T1]

  • 2026-07-16 — interaction edge from compaction-epistemic-failure (Tamba, independent, arXiv, "Compaction as Epistemic Failure", 2026-07-11, T3, single-study): the audit substrate degrading at the summarization boundary. The claims-vs-evidence audit (audit-agent-claims-against-trajectory-evidence) assumes the refuting evidence survives in the record; this case report documents compaction removing it — a killed process's exit code 143 was in-context, yet the summary promoted its partial stdout to "confirmed results" that persisted across sessions. Post-compaction, a first-wrong-step audit runs on laundered evidence. Rhymes with the map's replay-precondition finding (measure-whether-evidence-reconstructs-the-claim): the trace that remains cannot reconstruct the claim it carries. Mechanism only, no prevalence. Primary map: context-engineering. See compaction-can-launder-killed-process-output.
  • 2026-07-15 — interaction edge from reconstructability-metric-agent-evals (Solozobov, arXiv, "Agent-Safety Evaluations as Load-Bearing Evidence", 2026-07-14, T1, single-study): first-wrong-step localization has an evaluative twin. Where this map asks "where did the run first go wrong," reconstructability asks "does the captured trace license the decision the score claims" — a claim–evidence overclaim gap over 8 decision-property classes. The empirical finding is an observability indictment: on real public traces the replay precondition was unmet in every case — the evidence to reconstruct a claimed decision was routinely absent even where the headline number looked fine. It generalizes audit-agent-claims-against-trajectory-evidence from debugging one run to validating an eval's claims, and it prices what under-instrumented traces cost at the measurement layer. Caveats: single author, n=4, agent-safety not coding. Primary map: evaluation-integrity. See measure-whether-evidence-reconstructs-the-claim.
  • 2026-07-14 — agent-logging-practices (Ouatiti/Sayagh/Li/Hassan, Queen's University / ETS, arXiv, "Do AI Coding Agents Log Like Humans? An Empirical Study", 2026-04-10, T1): the map's first source about the observability of the product rather than the process — and it is a negative. 4,550 agentic vs 3,276 human PRs, 81 repos (AIDev; Python/Java/ JS-TS): agents change logging less often than humans in 58.4% of repositories (p=0.019); the higher density they show when they do log is largely a PR-size composition effect (1.64 vs 1.59 logs/1,000 LOC once size is controlled); and the placement gap concentrates in conditionals (46.7% similar) and loops (41.5% similar) while try/catch tracks human practice closely. Instructions don't fix it — 4.7% prevalence, 8.3% compliance from a repo context file, instructed vs uninstructed PRs statistically indistinguishable (χ²=1.32, p=0.25) — and humans quietly perform 72.5% of post-generation logging repair with review comments in only 2.18% of agentic PRs. The authors' conclusion is this vault's own: prose is not a control; use deterministic guardrails (observability linters, CI checks). Instrumentation is solid (96% precision / 94% recall on 380 diffs; LLM-jury κ=0.83; replication package released). Unmeasured, and the paper says so: the downstream cost — no incidents, no MTTR, no debugging-time data. Also feeds context-engineering (fifth data point in the live tension), runtime-action-governance (gate, don't ask), and agentic-code-review (the silent-janitor leak). See agents-under-instrument-the-code-they-write, humans-silently-repair-agent-code-outside-review.
  • 2026-07-14 — interaction edge from tthe-test-time-harness-evolution (Nie et al., HKBU / USTC / HKUST / TCL, arXiv, 2026-07-09, T1): a second, independent instance of this map's observability-as-actuator claim — and the first to run the control loop with no labels at all, scoring candidates purely on execution-derived proxies (execution health, round-trip consistency, public-test pass rate) distilled from the traces the agent produced on the test inputs. It also prices the limit of the idea: the trace-driven judge is "measurably miscalibrated," and the loop commits a 50% harness when a 64% one was in the pool it read. Trajectory evidence can drive the loop; it cannot, by itself, tell the loop which way is up. Primary map: agent-harness-architecture. See harness-self-evolution-is-capped-by-its-proxy-judge.
  • 2026-07-13 — failure-as-a-process-trajectories (Zhao et al., UCL/KCL et al., arXiv, "Failure as a Process: An Anatomy of CLI Coding Agent Trajectories", 2026-07-10, T1): the largest manual failure anatomy to date — 1,794 trajectories / 63k+ annotated steps, 7 frontier models × 3 scaffolds on 89 Terminal-Bench tasks, κ 0.78–0.94. Decisive error at median step 7 of ~27; observable signal lags ~10 steps; 57.9% epistemic (false premises 30.7% of all failures) vs 32.8% competence, 9.4% environment; 71% of successes also hit errors — recovery, not avoidance, is the separator. Quantifies exactly the gap localize-first-wrong-step-not-final-answer closes and vindicates audit-agent-claims-against-trajectory-evidence's substrate (the evidence was in-context). The zombie-execution numbers (82% of failed recoveries never terminate; wrong-problem repair = 39% of wasted computation) are carried in unattended-operation as the kill-rule case. See decisive-errors-strike-early-and-surface-late, failed-recoveries-burn-compute-not-terminate.
  • 2026-07-11 — interaction edge from beyond-pass-at-1-reliability (Khanal/Tao/Zhou, arXiv, "Beyond pass@1", 2026-03-31, T1): four instruments that grade an agent's run distribution rather than any single trajectory — Reliability Decay Curve, Variance Amplification Factor, Graceful Degradation Score, and Meltdown Onset Point, measured over 23,392 episodes / 396 tasks / 10 models. Open questions:

  • NEW 2026-07-14 — the map has two halves now, and only one is measured. Observability of the agent is well-instrumented (spans, defect ontologies, audit windows, supervisor coverage). Observability of what the agent builds has exactly one source, and it shows the property degrading while nobody gates on it. The missing quantity is the one that would make it matter: does agent under-instrumentation cost anything downstream? No incident rate, no MTTR, no time-to-diagnose has been measured against agent-authored code. Until someone links the instrumentation gap to a debugging outcome, this limb is a measured behavior in search of a consequence — plausible, unpriced, and exactly the sort of thing the vault should refuse to over-claim.
  • NEW 2026-07-14 — the recursion nobody has closed. If agents write less logging, and the field's own trajectory-audit techniques (audit-agent-claims-against-trajectory-evidence, decisive-errors-strike-early-and-surface-late) depend on evidence being present in the run, then an increasingly agent-authored codebase is quietly eroding the substrate this map's methods run on. That is a testable prediction — first-wrong-step localization accuracy should be lower in agent-authored code than in human-authored code — and nobody has run it.
  • The three sources converge on the principle (localize the first break, not the final outcome) but span three domains and granularities — deep-research reasoning spans, production pipeline stages, harness components — so the mechanism replicates cross-org while no single localization metric is shared across them.
  • Still no clean account of the cost of always-on trajectory auditing / evidence-corpus distillation (extra model calls per run) versus sampling — now a live tension for the self-evolving-harness use, where the corpus quality is the new bottleneck.
