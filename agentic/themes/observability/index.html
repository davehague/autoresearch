Logging, auditability & observability — map

Coined 2026-07-04 (Logging, auditability & observability group in the seed field map; first evidence this run) — flagged for David's review.

Status: consolidating (held 2026-08-18 — three arrivals, all inside this map's own argument. Sub-threads: none — one argument: audit and govern agents from trajectory-level evidence (claims vs. what was gathered, first-wrong-step attribution, fail-loud instrumentation) rather than outcome. The strongest split candidate is the static half of auditability — the configuration as a governed versioned object rather than the run as a trace — the counterpart of that argument, separable on a second source. What we believe now:

  • An instrument that reads its value from the same expression the system decided with cannot contradict that decision — and it will report perfect compliance in a world where compliance is universally broken. (Added 2026-08-19, T1, single-study.) Yesterday this map took a limit on its own substrate: read-derived-coverage-instruments-are-blind-by-construction showed that inferring what an agent knows from what it read cannot see a knowledge shortfall, because a deprived agent acts rather than abstains. That bounded one family of trajectory measures. This is the same failure in the event log, and it is worse because the log is the substrate everything else here is built on. A shipped collision-avoidance defect commanded both aircraft of a coordinated pair to climb, preserving exactly the vertical gap the advisory fired on, and reachable in ordinary geometry (two aircraft on final to different airports 1.4 NM and 300 ft apart). Across 147 recorded activations the telemetry showed correctly complementary outputs 100% of the time — and would have shown exactly that in a world where every single one was wrong — because the event stream logged the senses the resolver returned, which are opposite by construction, rather than the senses a later override actually applied (an-instrument-fed-from-the-same-source-as-the-expectation-cannot-contradict-it). The distinction this forces is provenance, not proxy choice: every signal this map argues for — claims against gathered evidence, first-wrong-step, process defects — can be chosen correctly and still produce this, because the question is not which quantity you record but where in the dataflow you read it. A record written at the point of decision reports intent; only one written at the point of effect can disagree with it, and disagreement is the whole value of a trace. For an agent fleet the generalization is uncomfortable, because agent telemetry is overwhelmingly decision-point: a tool-call record emitted by the planner reports the call chosen rather than the call the transport executed (the gap exit-codes-and-linters-miss-command-path-failures measures), and an approval event written when the policy engine returns permit is not evidence anyone judged (the shape of the-approval-artifact-never-recorded-that-anyone-judged). The companion control is worth as much as the finding: inverting the module's primary output left a pre-existing 3,824-test suite passing unchanged, so two independent instruments were blind to the same thing — which is what happens when they share an input. Practice: record a value downstream of every step that can modify it, and where the recording point and the deciding point are the same expression, treat the metric as uninformative about that invariant no matter how many activations it covers. [T1 — one deployed system, one defect, one author, no prevalence estimate; the 147/100% figure is a count from that system's own logs with no comparison instrument run alongside, and the defect was found by writing the oracle the paper's own survivor clustering predicted was missing, so it is selected by the analysis rather than sampled]
  • An instrument that infers what an agent knows from what it read cannot see the shortfall it was built for, because an agent deprived of a fact acts rather than abstains. (Added 2026-08-18, T1, strong — a limit on this map's substrate, stated by authors withdrawing one of their own prior results.) A missing fact yields a fabricated file or a guessed value, so the shortfall enters the tool stream as more activity: reads of a withheld file rise 5.5 → 10 → 13 as availability falls, and the score holds up or climbs precisely as the quantity it estimates collapses. Three concrete defects, each with its correction. The score credits files the agent wrote itself — under deletion a naive reading returned a perfect 1.000 in the condition where nothing was available, and disqualifying agent-authored paths takes the same cell to 0.000, an exclusion the authors note is not standard anywhere. Import neighbourhoods recover 40% of the authored coupling edges at 40% precision, and identifier resolution reaches perfect recall at 4% — a candidate generator, not a measure. And the measurement vanishes where the condition is most severe: under full withholding ~60% of trials make no edit, so the survivors are selected by the behaviour under study (read-derived-coverage-instruments-are-blind-by-construction). On SWE-bench Verified the score separates success from failure at AUC ≈ 0.49 — chance — where an earlier version scoring above 0.92 was leaking the outcome through a retirement term. The prescription that survives: check availability against what the agent produces, not against what it reads, and log an edit intent naming the facts and versions relied on before the write, which is gate-the-edit-on-evidence-observed-not-claimed turned into a log schema.
  • Failure attribution is two targets, not one, and they are not equally tractable — naming the responsible role is roughly twice as accurate as localizing the step that introduced the error. (Added 2026-08-18, T1, strong.) On 1,140 observed, non-injected failed trajectories across five domains, every one annotated by hand (22 graduate annotators, 30–40 minutes each, full coverage), with the role and the earliest decisive step scored independently and the role never inferred from the emitter of the predicted step: the best method reaches 51.1% role accuracy against 24.1% exact root-step accuracy, and the strongest prior method reaches 13.2% on the step (naming-the-responsible-role-is-a-different-target-from-localizing-the-step). Any harness reporting one blended "attribution accuracy" is averaging the two and flattering the number an operator needs. The regime is longer than anything this map's existing ceiling was measured on — mean 156.3 steps against 7.5–50.9 for comparable resources, with the root preceding the failure by a median of 48 recorded steps and more than 100 in 28.4% of cases — and the labelling rule makes late steps ineligible by construction, so a method cannot score by pointing at the symptom. What moves it: recall candidates from cheap segment summaries but decide on the original logged text, and trace each candidate back to the earlier handoff instruction addressed to its role (trace-the-candidate-error-back-to-the-handoff-that-instructed-it). What does not: dependency-guided search over decisions, tool outputs and messages scores 2.8% exact — below plain all-at-once prompting — and binary search 3.4%.
  • The record layer is populated where a vendor needs authorisation and empty where accountability would need it: an approval is stored as the submission of a review, the same event type as a comment. (Added 2026-08-18, T1, suggestive — documentation analysis, not repository data.) The artifact carries that a party with authority acted and never that anyone formed a judgement, and the platform does not even distinguish endorsing a change from remarking on it. The audit log carries fields for whether an actor is an agent, whether an actor is a bot, and an agent session identifier — and defines none of them. No standardised trailer exists for machine authorship; one provider repurposes the co-authorship trailer, documented elsewhere purely as a multiple-human mechanism, and that attribution is disableable. Attribution runs in opposite directions across providers: one records the agent as commit author with the assigning human as co-author, another posts agent output under the human's own account with only a label in the body (the-approval-artifact-never-recorded-that-anyone-judged). The thinness is not new — a decade of code-review research found ~15% of reviewer comments indicate a possible defect and 70% of changes committed within a day of review — but it has moved from a property of how people work to a documented property of what a product does. For this map that is the hole at the commit boundary underneath every trajectory result: an increasingly agent-authored repository whose provenance record is optional, inconsistent across vendors, and undefined in its own field documentation.
  • Every trace this map argues for is a record of a run against a system nobody wrote down: the tooling versions the prompt and traces the execution, and represents the configuration — agents, tools, skills, models, policies, workflows and their dependencies — nowhere. (Added 2026-08-14, T1, single-study.) This map's whole method is auditing from trajectory-level evidence, and every result in it silently assumes a statement of what the system was configured to be when the trajectory was produced. A capability audit across five platforms practitioners actually use — LangSmith, Langfuse, Helicone, Braintrust, PromptLayer — finds prompt versioning, tracing, observability, evaluation and lineage supported everywhere, and framework-independent configuration model, configuration graph, immutable baseline, configuration lifecycle, dependency model, governed revisions, state propagation and governance semantics marked "not provided as a first-class capability" in all five columns (govern-the-agents-configuration-as-a-versioned-object). Four design moves survive the paper they come from. Configuration–runtime separation — runtime observations may enrich governance information and may not modify governed configuration, with provenance mapping every runtime entity back to the revision that produced it and a replayable ordered event log. Immutable revisions with stable logical identity, so "the reviewer agent" and "the reviewer agent as it was on Tuesday" are both nameable — agent-specifications-are-versioned-engineering-artifacts taken past commit the markdown too into an addressing scheme. Four dimensions kept apart (quality, assurance, impact, eligibility) so absence of evidence is not read as poor quality and only impact propagates. And a measured reason to compute impact transitively: on a graph built to contain a two-level dependency, one-hop traversal found 6 of 9 affected items and fixed-point propagation found 9 of 9, with the three misses reached through an intermediate revision — deterministic across five repetitions, and scope-independent at 3 iterations for local, intermediate and global changes alike (one-hop-dependency-inspection-misses-transitive-config-impact). [T1 venue, read as a design with a conformance test — the 27 governance scenarios compare behaviour against expectations pre-specified by the same author from the same model, which the paper says plainly; the quantitative campaign runs on graphs of 11 and 13 items; inspection-scope reduction of 61.5–84.6% counts configuration elements, explicitly not human effort; single author, no users, no production deployment, and nothing measures whether a governed configuration produces better agent outcomes; three orchestration frameworks, none of them a file-based coding harness]
  • The layered architecture this map assembled from small-model studies has now been run on frontier coding agents, and it pays: judge with a rule, advise with a model, and the value comes from the interventions the rule suppresses. (Added 2026-08-10, T1, strong.) The map's answer to "who watches the agent" — deterministic checks first, a cheap behavioural signal for drift and looping, an LLM as escalation rather than default (a-deterministic-recheck-beats-a-learned-monitor-on-precision, name-the-failing-check-not-the-finding) — was assembled on 3B–8B locally-served models, with no frontier coding harness anywhere in it. LivePlan runs exactly that split on SWE-agent and wins every cell: +5.00 to +15.24 points (average +9.9) across three executors × two SWE-bench variants, for $0.08 per instance, with the monitor costing "a few milliseconds" because it contains no model at all — it pattern-matches two structural views of the live trajectory (a graph over visited locations, and the phase sequence) into ten named drifts, five of them blocking the pending action before execution (judge-with-a-rule-advise-with-a-model). Three things about it change practice. Advice beats re-planning: the re-planning baseline falls below the unmodified agent on two of three models at two to three times the cost, with 12–26 resolved→unresolved regressions against LivePlan's 2–7 — the correction wants to be as local as the error, which is localize-first-wrong-step-not-final-answer applied to the remedy. Triggering beats scheduling: firing the same advisor every five steps hits 97.7–99.6% of instances at 3.25–7.38 interventions each and scores 2.3–5.3 points lower at higher cost, so the detector's job is to suppress advice into healthy trajectories rather than to find opportunities (intervene-on-a-trigger-not-on-a-schedule). And drift is the normal state, not an exception: 86.16% and 78.33% of unmodified trajectories carry at least one, which is why an outcome-keyed monitor sees none of it. The window result gets its first confirmation from an intervention that actually recovered runs — across all 244 unresolved→resolved flips the first intervention landed within the first third of the trajectory, and 74.6% needed several (mean 3.70), so correction is early and repeated rather than a late rescue (the-correction-window-is-the-first-third-of-the-trajectory, decisive-errors-strike-early-and-surface-late). The ceiling is stated by the authors and is the honest limit on all of this machinery: "in nearly all LivePlan R→Us, the root cause is not incorrect advice or a failure to intervene on time, but rather the executor's inability to follow the correct guidance." [T1 — three executors, two advisors, two benchmarks, Python only, one harness; no confidence intervals anywhere and single runs per instance, with a deterministic-outcome-subset re-check (84/80/88% of instances) confirming direction rather than magnitude; θ_p = 7 and the cooldown were fitted to this harness's own step distribution; phase detection is rule-based over commands and stated reasoning, inheriting the annotation exposure of every trajectory instrument]
  • Diagnosis has the same ceiling one layer below the agent, at the provider response path. (Added 2026-08-10, T1, strong.) This map carries two attribution numbers — first-wrong-step over agent trajectories at 28.8–38.0% (first-wrong-step-attribution-is-mostly-wrong) and agentic root-cause analysis over a live stack at 25.3% (agents-cannot-enumerate-concurrent-root-causes). A third subject now lands in the same band: given the full trace of a run degraded by an injected API fault and no hint about what was injected, a rule-based signature scanner reaches 52.45% / 55.5% (fault type / step) and a frontier-model diagnoser 47.25% / 53.52% — neither clears 56% on any metric over 654 failed cases. That the ceiling recurs across three unrelated subjects argues it belongs to the class of task — reconstructing a cause from a trace that was not built to record it — rather than to any instrument. Two operational riders. Accuracy is inversely related to damage: truncation costs up to 52.63 points and the rules name it 4.30% of the time, while timeouts, nearly harmless when intermittent, are named at 91.04% — a truncated reply is a perfectly well-formed one that just stops, which is fail-loud-instrumentation-over-plausible-substitutes arriving on the provider's side of the wire. And the two methods are complementary rather than redundant, proven by the disagreement rather than the accuracy: Cohen's κ is 0.813–0.907 on crash faults and 0.098–0.372 on omission and value faults, with the model catching truncation at 34.41% where rules manage 4.30% and rules catching schema at 52.46% where the model manages 27.05% (the-costliest-provider-faults-are-the-hardest-to-diagnose). Run both. [T1 — one agent system and one benchmark for the diagnosis arm, chosen for having the longest traces; rule signatures derived from public API documentation rather than from the injector, so their coverage of a real provider's failure vocabulary is untested; accuracy computed only over failed cases, so false-alarm behaviour on healthy runs is unmeasured]
  • This map finally has a field distribution to calibrate against, and it says the unit almost every agent dashboard displays is the wrong one. (Added 2026-08-08, T1, strong.) One sampled week of production coding-agent telemetry — 13.5M sessions, 95.1M turns, 3.2M users, 760.5M LLM calls, 774.7M tool calls. Three properties change what an operator should be looking at. Load is agent-generated: each user message unfolds into an average of 6.6 autonomous LLM calls, an 87% / 13% agent-to-user split, so a view keyed on the user prompt is showing 13% of what the system did — the informative unit is the turn, and a turn is a whole trajectory. Everything is heavy-tailed: median session 3 turns / 15 calls / 4.2 minutes against a mean of 6.1 / 40.6 / 62.6 minutes (14.9× on duration, P90 above three hours), and median turn 3 calls / 160.2K prompt tokens against a P90 of ~16 and over 1M — so alerting or budgeting on the mean describes almost no real session, the same warning agent-improvement-distributions-can-be-bimodal raises about improvement deltas. Populations differ 50×: five clustered user archetypes spanning 23K to 1.1M tokens per turn with different tool mixes and idle profiles, so one SLO over that spread is tuned for nobody (agent-load-is-self-initiated-and-heavy-tailed). Two structural facts to hold when reading any trajectory: time and tokens are inverted (LLM execution is 85.4% of wall-clock and 48% of prompt tokens; tool calls 4.7% of time and 28% of tokens), so a latency profile and a token profile of the same session accuse different components; and execution is overwhelmingly serial (36.7% of turns strictly, median concurrency 1.15, 93% of tool batches a single invocation). [T1, and the caveat is load-bearing for this map specifically — this is telemetry, NOT trajectories: no prompt text, outputs, tool arguments, source code, correctness or failure labels were collected. It calibrates expectations; it audits nothing. One vendor, one product, one sampled week, post-hoc clusters, no intervals]
  • The field's reflex when an agent might be going wrong is to add an observer; measured head-to-head on the same episodes, a deterministic recomputation beats the learned observer on precision, on portability and on the failure class that matters most — and it carries neither of the two burdens the learned one cannot shed. (Added 2026-08-07, T1, strong.) This map's thesis — audit from trajectory-level evidence rather than outcomes (audit-agent-claims-against-trajectory-evidence, localize-first-wrong-step-not-final-answer) — has always had a cost problem, since the standard implementation puts a second model on every step. The cheap answer is a one-class monitor over observable step telemetry (a deterministic char-3-gram hash embedding, token-uncertainty aggregates, action metadata; a frozen reservoir with a closed-form ridge readout fitted on healthy runs only; per-channel CUSUM), costing ~200 µs per step with a 674 µs adapter — under a millisecond against one 7B forward pass. It works on the classes with no invariant to recompute: looping 0.48–1.00, goal drift 0.66–0.86, tool cascade 0.17–1.00 across nine real corpora, with content corruption the named weak spot (0.00–0.50) that a grounding channel lifts 0.27 → 0.58 with zero discordant losses and behavioural detection improving rather than trading. But it carries two burdens the paper measures rather than argues around: a per-deployment healthy null (calibrated on one model family and deployed on another it sits at chance, AUROC 0.527 against 0.885 recalibrated on itself) and a residual false-alarm rate (a-detectors-operating-point-belongs-to-its-deployment). Three deterministic checks carry neither — recompute the run's stated total from the tool results it actually received, confirm every required call was made, validate each result against the shapes its tool can return — and beat it: 60% (96% with coverage) at 0 of 63 false positives against 54% at 17%, holding at 0 of 64 on a frozen 120-episode disjoint-seed replication, transferring across model families with nothing retuned (110 of 110 at 0 of 10), and catching 26 of 26 provoked fabrications, a class a one-class monitor cannot be scored on at all. The shape check alone trips on 0 of 1,825 healthy episodes and fires within one step of onset 215 times in 218 (a-deterministic-recheck-beats-a-learned-monitor-on-precision). The honest architecture is therefore layered rather than either/or, and the layers are chosen by whether an invariant exists: a shape check at every tool return, deterministic recomputation at every asserted figure, a cheap behavioural monitor for drift and looping, and an LLM judge as escalation rather than default — justified not as a cheaper approximation but because judge and monitor fail on different classes (the measured judge perfect on goal drift at 21/21 and 0.18 on context corruption, where the monitor is 1.00). And the whole thing closes into repair: flagged runs rolled back and re-run lift net task success 52% → 73% at about one extra model call, with the surprise that naming the failing check while withholding the values (45%) beats supplying the finding in full (36%) (name-the-failing-check-not-the-finding). [T1, strong for the checks and the layering, and unusually well-bounded by its own author: 2,823 committed episodes over 25 datasets, three frameworks, three local models in two families and one commercial API — but 3B–8B locally-served models with no frontier model and no frontier coding harness; the simulator's telemetry is constructed and the author states no deployment claim rests on it; the checks were authored by inspecting serving-arm failures, with the frozen disjoint-seed arm as the held-out test costing the expected margin; and the tasks carry a recomputable total by construction, so how much of an arbitrary workload admits such an invariant is unmeasured. Single independent author; the paper explicitly declines to claim mid-episode detection, observable telemetry, per-step cheapness or label-free training as individually novel]
  • NEW LIMB 2026-08-02 — the agent as consumer of an observability stack: given the whole telemetry surface and the source, the best of five frontier agents names every root cause of a realistically- reported incident 25.3% of the time, and the binding constraint is enumeration, not detection. (Added 2026-08-02, T1.) This map has had two limbs — observing the agent, and (since 2026-07-14) the agent degrading the observability of what it builds. A third arrives with the first benchmark to put general-purpose coding agents against a live OpenTelemetry-instrumented microservice system: six days and ~50 GB of real metrics, logs and traces through Prometheus/Jaeger/OpenSearch, full source access, 1,079 tasks varying report specificity, time-to-detection and fault concurrency, expert-SRE ground truth, and a judge hand-re-scored at κ_w = 0.90. Best RCA accuracy is 25.3% on Medium and 10.0% on Hard; best partial-credit depth is 48.8%; hallucinated root causes run 7% to 40% across models on identical inputs, so the backend choice moves the false-alarm rate nearly six-fold. The failure has a shape rather than a rate: agents lock onto the loudest symptom and stop, so accuracy degrades with the number of concurrent causes (4.41 ground-truth causes on hard tasks vs 2.00 on easy; 19–50 points lost to reduced specificity) rather than with the difficulty of any one. The decisive observation is that in a six-fault scenario three models each named exactly one cause — all three different — and missed the rest: not a shared blind spot, five partial and non-overlapping pictures of one incident (agents-cannot-enumerate-concurrent-root-causes). That is this map's own thesis pointed at a new subject — the task is first-wrong-step localization, performed against a distributed system — and it lands in the same band as the vault's attribution result (first-wrong-step-attribution-is-mostly-wrong, 28.8–38.0%), which suggests the ceiling belongs to the class of task rather than to either instrument. [T1, strong for the headline and ablations; the authors state every simplification points the same way, so the gap is a lower bound — public system likely in pretraining, fixed codebase, no cross-incident memory, no action loop, one harness, one prompt template]
  • The evidence worth most to an incident investigation is the evidence agents look at least, and the instrument they prefer fails silently a third of the time. (Added 2026-08-02, T1.) Two measurements from the same runs. Ablating source-code access while leaving telemetry intact costs 9–16 accuracy points for every model and spikes hallucination for every model — with incident timing the one metric that survives (82.6% → 79.9%), since timestamps live in metric series rather than code. Yet those same agents spend 16–20% of commands reading source against 70–72% on telemetry, and 26–40% of telemetry calls error out or return empty, dominated by empty (source-code-access-lifts-root-cause-analysis-the-agents-underuse-it). An empty query result is a plausible substitute for "this service is healthy" — the exact pathology this map's fail-loud principle names (fail-loud-instrumentation-over-plausible-substitutes), arriving on the agent's inputs rather than its outputs. So the largest measured gap in agentic RCA is an allocation failure the harness can address (force a code-orientation pass before hypothesis formation; make empty results loud) rather than a capability the model lacks — the standing shape of move-task-difficulty-from-the-model-to-the-harness and compile-the-procedure-into-the-harness. Also worth carrying: retrieval discipline and diagnostic completeness come apart across models — GPT-5.5 is simultaneously most economical, highest-success and best at citing ground-truth signals while another model leads strict accuracy — so a composite RCA score averages two different competences. [T1, strong for the ablation and the command-mix; the re-allocation intervention itself is unrun, so the recoverable share is bounded below at 9–16 points and otherwise unknown]
  • Build the pipeline so a component that cannot do its job halts loudly instead of emitting a plausible substitute — the corruptions that reach your data are precisely the ones that produced no crash and no error. (Added 2026-07-28, T1.) This map's field-scale finding is that silence is the modal failure (silent-errors-dominate-agent-bug-reports, 108/255 = 42.4%). A pre-registered measurement study documents the same pathology in its own instrument, with an unusually complete account of which corruptions were caught and which was not — and the sorting principle is exactly the noise level. Three defects were caught mechanically before any number reached a results file: a sandbox crash that would have laundered into a false all-survived zero, a scoping bug that silently stopped generated tests from being collected, and scope-transcription errors. The one that reached the counted data was an output-token ceiling that truncated replies and recorded them under an unrelated-sounding rejection note — no crash, no error, only a plausible-looking wrong number — and it inverted the study's headline finding, surviving every runtime gate until an adversarial review of the completed analysis asked why those specific rounds were failing (fail-loud-instrumentation-over-plausible-substitutes). The repair is mechanical rather than procedural: one ceiling value read by both the request and a new check, every reply's token count compared against it, a reply at the ceiling raising a truncation error that is never retried, the round recorded honestly with its real billed cost and the raw truncated reply archived, and a truncation at a measurement-defining step failing the cell as missing data rather than being silently recovered. The proof it works is the recurrence: under the corrected instrument the identical mechanism fired three more times within days and was scored rather than laundered. This is the upstream half of the map's audit substrate — the claims-versus-evidence audit (audit-agent-claims-against-trajectory-evidence) needs the refuting evidence to survive in the record, and the vault has already documented compaction removing it (compaction-can-launder-killed-process-output, compaction-selection-is-all-or-nothing) — so: do not write the plausible substitute into the record in the first place. It is also the reason attribution is possible at all when the modal failure emits nothing to attribute from: the instrument, not the agent, supplies the signal. [T1, suggestive — one study's engineering account, not a controlled comparison of fail-loud against fail-soft pipelines]
  • Attribution beats symptom-side repair by 2–3× — and the attribution itself is right under four times in ten. (Added 2026-07-26, T1; general agentic and assistant traces, not coding.) The map's founding instruction finally closes into an action, and reports its own precision. The action: organizing debugging as Detect → Attribute → Recover → Rerun, with the rerun starting from the attributed checkpoint, repairs 13 of 73 failed runs against Reflexion's 6, AutoManual's 5 and CRITIC's 4 (overall 55.8% → 63.6%). Those three baselines all repair from the visible failure, which is on average ten steps downstream of the cause (decisive-errors-strike-early-and-surface-late) — so the gap is the operational value of first-wrong-step localization, priced (close-the-loop-from-attribution-to-rerun). The precision: strict agent-and-step accuracy is 28.8% on a 9B backbone and 38.0% on a 27B one. Naming the right agent alone reaches 56.0%; landing within one step reaches 44.0%. So the honest statement of this map's core practice is that a majority of attributions are wrong and it is still the best move available — which means an attribution is a hypothesis, and anything downstream that treats it as ground truth (a training signal, a regression label, an automated rollback) is consuming a minority-correct estimate, the same failure shape as harness-self-evolution-is-capped-by-its-proxy-judge (first-wrong-step-attribution-is-mostly-wrong). Two transferable implementation details: detection runs deterministic rule packs first and escalates to LLM judgment only for what they cannot decide (enforce-invariants-not-implementations), and attribution is an explicit cost ladder — heuristics, one whole-trace pass, binary search, per-step inspection, budgeted ensembles — rather than a single strategy (expose-a-cost-quality-dial-not-a-fixed-policy). [T1 — but GAIA and Who&When, not SWE; the +7.8 points bundles attribution with the rerun by the authors' own statement; the attribution advantage disappears on hosted backbones, so the machinery is compensation for a weak diagnostician]
  • The operator surface for a governed fleet is the security log, and it must carry the deciding signals, not just the decision. (Added 2026-07-25, T2 practice.) Every instrument in this map so far has been analytic — applied after the fact to trajectories collected for research. One vendor specifies the same signal as production telemetry: every automated approval, every tool call and every agent-to-agent message shipped to the SIEM together with the signals used and the human accountability record. That meets measure-whether-evidence-reconstructs-the-claim by construction rather than assessing it afterwards. Two structural requirements make it work: single-purpose agent identities at minimum permissions, so the actor of every logged action is unambiguous — which matters because the modal agent bug emits no signal at all, so attribution cannot come from an exception — and agent-to-agent traffic routed through a monitored channel rather than direct, which is the only reason one agent asking a peer to push code was a visible event (least-agency-blocks-an-agent-that-recruits-another-agent). The question of which system should hold agent telemetry gets a plain answer: the one already built to record who did what, on what basis, and whether it was authorized (route-agent-identities-and-messages-through-the-siem, treat-internal-agents-as-insider-threats). Unmeasured: detection rate, time-to-response, false-positive burden, and log volume at agent-authored throughput. [T2, suggestive]
  • Silence is the modal failure, so an outcome-keyed monitor is blind to the plurality of defects. (Added 2026-07-20.) Across 255 hand-labeled agent-reactive bugs the largest symptom class is Silent Errors at 108/255 (42.4%) — normal-looking run, fluent answer or modified workspace, no exception, warning, retry, or non-zero exit.
