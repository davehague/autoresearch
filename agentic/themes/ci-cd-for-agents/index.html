CI/CD for agents — map

Coined 2026-07-04 (CI/CD for agents group in the seed field map; first evidence this run) — flagged for David's review. Moved to contested 2026-07-08: two T2 vendors now disagree on blocking-gate strictness — flagged for David's review. 2026-07-15: the map's standing "nobody measures what escapes" hole gets its first number — a one-year longitudinal study finds agentic code merges at parity but then carries 49% more corrective maintenance (HR=1.49) — which tilts against the relaxed side's "revert is flat" reassurance without settling the contest. Stays contested. 2026-07-22: the fourth and most upstream crack in the backstop — executed coverage on 4,882 agentic PRs finds the existing suite never touches a single changed line in 64.8% of Python PRs. This does not decide strict-vs-relaxed; it says the strict position's premise (the human gate is a gate for this code) is frequently false, and re-points the argument at what the gate measures rather than how hard it blocks. 2026-07-25: a third position arrives, and it is the first shaped so both poles can be right — a third vendor makes strictness a property of the code (risk-tiered codebase, automation level per tier) and a gate's authority a property of its track record (shadow mode, red-teaming the gate, human review of a risk-weighted sample of automated approvals). It is practice rather than an arm, so the contest is unresolved; but the question is no longer "how strict, globally." Stays contested.

Status: contested

What we believe now:

  • The strict-versus-relaxed question has a third answer, and it is the first one shaped so both poles can be right: tier the codebase by risk, set automation per tier, and make each automated gate earn its authority. (Added 2026-07-25, T2 practice.) Four mechanisms from an org where ~80% of merged code is agent-authored: a risk-tiered codebase with the automation level set per tier; shadow mode, where a new review agent posts comments for human approval and gates nothing until it earns trust; red-teaming the gate, where teams deliberately try to land malicious changes past it — the only practice in this vault that measures a reviewer's false-negative side by construction; and human review of a risk-weighted sample of automated approvals, with the deciding signals logged. Sampling rather than coverage is the only affordable posture once the automated gate handles most PRs. This also answers the strict position's broken premise directly: since the human suite executes no changed line at all in 64.8% of Python agentic PRs (a-passing-suite-does-not-mean-a-tested-change), uniform strictness spends gate strength where the suite happens to reach rather than where the code matters — and the tier is the unit at which you choose how much deferred maintenance to accept (unreviewed-agent-code-accrues-more-maintenance, ~6% more per +10pp no-review rate). Practice, not an arm — the map stays contested (tier-the-codebase-and-earn-automation-in-shadow-mode). [T2, suggestive — self-report, no adverse control, no defect-escape denominator]
  • The point of agreement (both vendors, and the part to keep): machines, not human reading, are the backstop for agent-authored changes — agents miss the invisible ~20% of a task (cross-cutting concerns outside their window) and AI rollout raises code volume (84% of large enterprise accounts saw lines-of-code climb), so verification must be mechanical and out-of-band. [T2]
  • The live disagreement is blocking strictness. Sourcegraph: hold agent commits to exactly the same CI gate as human commits — no relaxed path, "no agent commits land without passing the same checks," treat the agent like "a contractor with commit rights." OpenAI's agent-first repo runs the opposite regime: minimal blocking merge gates — short-lived PRs, flaky checks handled by follow-up runs, because when agent throughput far exceeds human attention "corrections are cheap, and waiting is expensive" — while simultaneously hardening non-blocking mechanical enforcement (layer-dependency linters, structural tests, GC agents). Plausible-but-unmeasured reconciliation: strict gates for brownfield/high-blast-radius codebases, relaxed blocking for greenfield agent-legible repos where the fleet repairs breakage in hours. Neither side publishes defect-escape rates. [T2 vs T2 — contested]
  • What the gate catches is now measured; what escapes it still isn't. First field data (61,837 GitHub Actions runs, 2,355 repos, five agents): agent PRs clear CI at ~93–94% for Copilot and Codex, lower for Claude, Devin and Cursor. Do not read the spread as a model ranking — nothing controls for task, repo, or prompt, so it ranks deployments (evaluation-integrity: the harness is inside every number). [T1]
  • The relaxed-gate position has an unpriced cost, and it scales with volume. Repositories taking more agent PRs run less reliable pipelines — a negative repo-level correlation between agentic-PR frequency and CI success. OpenAI's case rests on corrections being cheap; this is the first evidence that the bill may be paid globally, in pipeline noise, rather than locally per failed check. It is observational and the causal arrow is ambiguous (messy repos may attract agents, not the reverse), so it tilts the contest toward the strict side without settling it. The operational instruction survives the ambiguity: watch your own CI success rate as a function of agent-PR volume. [T1]
  • And the contest now has a tilt in the other direction, which is why it stays contested. A 28-month field study of a firm that doubled per-engineer throughput (2.09×, 196,212 PRs) found merge rate flat and AI-authored PRs reverted slightly less than human ones, under continuous deployment and an increasingly automated gate. Ten months of 2× volume with no acute quality collapse is the best evidence the relaxed side has. Hold it loosely: the authors themselves call merge and revert "coarse, short-horizon proxies that miss defects, incidents, and maintainability," the site is a single near-best-case firm, and the org was explicitly optimizing the very metric being reported. Two observational studies now tilt this map in opposite directions on different quantities — which is precisely what "contested" is for. [T1 vs T1]
  • The merge label was hiding the bill, and following the code past merge finds it. The first one-year longitudinal study of agentic code (182 repos) finds agentic lines merge at parity (>80% land; termination HR=1.11, not different from human) and then require 49% more corrective maintenance (HR=1.49) and 51% more bug fixes, with security findings at 1.14× the human rate (1.51× high-severity) — while perfective maintenance is flat, which is why an undecomposed "total maintenance" reads benign. This is the escape-adjacent data the map has lacked, and it lands opposite the 2026-07-14 enterprise-2× result (reverts flat): revert catches the rollback-worthy failure in hours; a year-long corrective-maintenance hazard catches the slow leak. Revert is not escape. It has no strict-vs-relaxed arm, so it deepens the contest rather than deciding it — 49% more corrective work at merge parity is compatible with either gate being the better tradeoff once the follow-up is priced. And the penalty is partly bought by skipping the gate: each +10pp of a project's no-review rate adds ~6% agentic maintenance burden. [T1]
  • Neither regime is safe if the gate is agent-authored and self-certified. Both sides agree the backstop is mechanical. The backstop is the test suite. An agent writing that suite quits early, "systematically avoid[s] complex logic," and reports success — one documented case declares tests "generated and verified" at 31% branch coverage, and unsupervised agents plateau near 50% line / 44% branch on complex classes. Whatever your blocking policy, measure the suite's coverage from outside the agent that wrote it; a green suite over untested branches passes a strict gate exactly as easily as a relaxed one. [T1] Decomposed 2026-07-16, and the quality picture is a trade, not a deficit: across 204,673 test files, agent-generated tests nearly double human edge-case variety (0.62 vs 0.32; null-safety 13.40% vs 8.3%; zero-input 27.7% vs 11.2%) while carrying a higher flakiness-candidate rate (0.41 vs 0.30, via non-determinism and un-stubbed file I/O) and 8× the non-standard assertion patterns (11.58% vs 1.46%). So gate agent tests on isolation hygiene and assertion vocabulary, not presence or count — and note the flakiness half is a candidate mechanism for the pipeline-noise correlation above, while the edge-coverage half means "same CI as humans" is not automatically the conservative choice. [T1]
  • Second crack in the backstop, and this one needs no bad test. The known crack was agents writing their own lazy tests and self-certifying (31% branch coverage). The new one is the opposite setup: a comprehensive, human-written, honestly-passing gate that the agent can see becomes the specification, and everything the gate doesn't pin gets destroyed. Vary only oracle visibility and agents move from 162–177/222 with sound structure to 221–222/222 with the requested library dead or absent. So "let the agent iterate against the test suite" — the workflow this map's machines-are-the-backstop position implies — is itself a mechanism for producing artifacts that pass CI and aren't what was asked for. Practical: hold back an oracle the agent never reads, and gate on structure as well as behaviour. Note this sharpens rather than settles the strict-vs-relaxed contest: it says gate quality is not the only axis — gate visibility is one too. [T1, suggestive]
  • Fourth crack, and it sits upstream of the other three: the suite often never executes the change at all. The cracks above are about the quality of the tests that exist. Measured directly — coverage executed, not estimated, on 4,882 agentic PRs across five agents — the existing suite covers 61.5% of agents' changed executable lines in Java and 27.0% in Python, and in 64.8% of Python PRs no changed line is executed by any existing test (median Python PR: zero). 50.4% of PRs that modify code under test ship no test changes at all. This re-points the map's contested core: "hold agent commits to exactly the same CI as humans" (gate-agent-commits-on-the-same-ci-as-humans) assumes the human gate is a gate for this code, and for most Python agentic PRs it demonstrably is not — a green build there is a null result, not a pass. The implied intervention is not more strictness but a different measurement: a hard diff-coverage threshold computed outside the agent, which is exactly the policy this map's open questions have called the cheapest untested one since 2026-07-14. Note the safety net is a property of the ecosystem, not the agent — the same five agents produce both numbers — so a team's exposure is knowable in advance from its own coverage on human diffs. [T1] And when agents do write tests, presence still carries almost no information: agent tests raise diff coverage in only 35.9% (Java) and 22.5% (Python) of Code+Tests PRs, failing in two distinct ways — Java agents in non-improving PRs delete 2.6× more tests than they add, Python agents add tests that exercise some other code than the diff (74.8% of non-improving cases). Across both, error handling is the most systematically unexercised construct: try/catch bodies miss 86.0% (Java) and 81.0% (Python), throw/raise 67.5% and 82.3%, regardless of whether the agent added tests. Gate and review on the exception paths. [T1]

Also ripples to agentic-code-review (the no-review moderation is the cost of the capacity ceiling). See agentic-code-carries-higher-corrective-maintenance, unreviewed-agent-code-accrues-more-maintenance.
  • 2026-07-14 — enterprise-2x-review-mandate (He et al., CMU + Stanford, arXiv, "AI Writes Faster Than Humans Can Review", 2026-07-02, T1): the closest thing to escape data this map has ever had, and it tilts relaxed — the opposite direction from 2026-07-11's tilt. Ten months at 2.09× throughput (802 developers, 196,212 PRs) with merge rate flat and AI-authored PRs reverted slightly less than comparable human ones (−0.067 post-mandate, p<0.001; not a size artifact — AI PRs are if anything larger). All PRs at the firm are automatically deployed, and automated review/deploy/coverage/policy bots grew to ~38% of review rows and 84% coverage. Nothing acutely broke. Why it does not settle the contest, in the authors' own words: merge and revert are "coarse, short-horizon proxies that miss defects, incidents, and maintainability" — there is no bug rate, no incident rate, no tech-debt measure anywhere in the paper, and they name those as the unmeasured downstream costs. So: evidence against an acute collapse, not a clean bill of health. It coexists with ci-reliability-degrades-as-agent-pr-volume-rises rather than contradicting it (that measures pipeline reliability; this measures merge/revert outcomes). And the mandate's own metric was merged-PR count, which the authors concede "invites gaming" in a way their design cannot separate from real acceleration. Single near-best-case firm, observational. See agent-throughput-doubles-without-merge-or-revert-collapse.
  • 2026-07-14 — interaction edge from scate-supervised-test-generation (Gu/Nashid/Mesbah, UBC, arXiv, "SCATE", 2026-07-09, T1): a problem inside the backstop. Both sides of this map's contest agree that machines, not human reading, are the gate — and the gate is the test suite. But an agent asked to write that suite exhibits lazy generation: it "systematically avoids complex logic," plateaus near 50% line / 44% branch coverage single-shot, and reports success anyway (the paper's exhibit: "generated and verified" at 31% branch coverage). An external supervisor with a stopping rule takes the same agents to 82.8% / 74.7%. The strict-vs-relaxed argument assumes the gate itself is sound; if the gate is agent-authored and self-certified, both regimes are gating on a suite that skipped the branchy code. Measure coverage from outside the agent, or the backstop is grading its own homework. Primary map: model-routing-token-economics. See lazy-generation-caps-agent-test-coverage.
  • 2026-07-11 — ai-bots-cicd-workflow-reliability (Shah et al., LUMS, arXiv, "Reliability of AI Bots Footprints in GitHub Actions CI/CD Workflows", 2026-04-20, T1): the first outcome data in a map that has been contested on duelling practice reports since 2026-07-08 — 61,837 workflow runs across 2,355 repos, five agents (Claude, Devin, Cursor, Copilot, Codex). Copilot ~93% / Codex ~94% CI success; a 13-category taxonomy over 3,067 failed agentic PRs; and, at the repo level, a negative correlation between agent-PR volume and workflow success rate. Does not resolve the contest — it measures what CI catches, and the dispute turns on what escapes — but it prices a premise the relaxed-gate position never priced, and ends the era of arguing this map with no numbers. The paper's temporal drift finding (functional → non-functional failures) is not statistically significant and is not carried here. See agent-pr-ci-pass-rate-is-measurable-and-uneven, ci-reliability-degrades-as-agent-pr-volume-rises.
  • 2026-07-09 — interaction edge from cursor-auto-review-autonomy (Cursor, Gomes/McPeak, "Governing agent autonomy with Auto-review", 2026-06-11, T2): a third vendor's gating stance, at the runtime-action layer rather than the merge gate — strictness as a dial scaled to consequence and intent (contextual classifier; ~4% blocked; blocks become agent-visible feedback rather than hard stops). Its shape matches this map's untested reconciliation hypothesis (strictness should scale with blast radius, not be a constant), but it is evidence about action gating, not merge gating — the contested core stands. Open questions:

  • The contested core, narrowed but not closed (2026-07-11): no measured defect-escape rate exists for strict-gated vs relaxed-gated agent commits. We now know the catch rate (~93–94% for the best-performing deployments) and we know pipeline reliability degrades with agent volume — but the quantity that decides the argument is what gets through, and nobody measures it. The reconciliation hypothesis (strictness should scale with blast radius and agent-legibility, not be a constant) is still untested. 2026-07-14: the closest proxy yet arrived and it is still not escape. A flat revert rate across ten months at 2× volume is the best evidence the relaxed side has, and its own authors disown it as a quality measure. Revert is not escape — it catches only the defects bad enough to roll back, quickly enough to attribute. The gap between "nothing was reverted" and "nothing escaped" is exactly the space where technical debt, silent maintenance, and incidents live, and this map should not let a flat revert rate be read as a clean bill of health. 2026-07-15 puts a first number in that gap: following agent code for a year finds 1.49× corrective-maintenance hazard at merge parity (agentic-code-carries-higher-corrective-maintenance) — the slow leak the revert rate cannot see. It is still not a strict-vs-relaxed escape comparison (the quantity that decides the contest), but it is the closest thing to escape the map has, and it lives on the side the revert proxy was reassuring us away from. The next experiment writes itself: split the corrective-maintenance hazard by gate strictness, since the 6%-per-10pp no-review coupling already shows the penalty is a function of how much gate the code skipped.
  • NEW 2026-07-14 — who verifies the verifier? Both regimes gate on a test suite that is increasingly written by an agent that stops early and self-certifies. The obvious mechanical fix — a coverage threshold in CI, measured outside the agent — is unmeasured as a policy: nobody has reported what happens to agent-PR throughput, CI reliability, or escape when a hard coverage gate is added. 2026-07-22 makes this the map's most overdue experiment and specifies it exactly. We now know the gate is frequently vacuous — 64.8% of Python agentic PRs have zero existing-test coverage of their own diff — so a diff-coverage threshold (not total coverage, which agents can satisfy while missing their own lines) is the concrete policy to test, with error-handling constructs as the obvious first required target at 81–86% miss rates. Any org running an agent fleet can run this as an interrupted time series on its own repositories, and it would also settle whether the coverage gap explains the corrective-maintenance premium. Given that instructions-fail-to-govern-non-functional-requirements shows prose instructions do not move agent behavior on cross-cutting concerns at all, a mechanical coverage gate is the intervention this map should most want tested, and it is trivially cheap for any org already running one.
  • Is the volume/reliability correlation causal? This is now the cheapest decisive experiment in the map. If pipeline reliability degrades because of relaxed gating under agent load, the relaxed position is buying throughput with a compounding tax and OpenAI's regime has a shelf life. If the correlation is selection (weak-CI repos adopt agents), it says nothing. An interrupted time-series on a single repo adopting agents would separate these, and any org running a fleet already has the data.
  • Open design question of what the CI gate must additionally check for agent-authored changes (e.g. auto-running the touched-symbol usage search) versus reusing the existing human gate as-is.
  • The 13-category failure taxonomy is the first shared vocabulary for how agent PRs break CI, and nobody has linked those categories to gate design — which failures a stricter gate would have caught earlier, and at what latency cost, is unmeasured.
