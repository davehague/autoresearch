CI/CD for agents — map

Coined 2026-07-04 (CI/CD for agents group in the seed field map; first evidence this run) — flagged for David's review. Moved to contested 2026-07-08: two T2 vendors now disagree on blocking-gate strictness — flagged for David's review. 2026-07-15: the map's standing "nobody measures what escapes" hole gets its first number — a one-year longitudinal study finds agentic code merges at parity but then carries 49% more corrective maintenance (HR=1.49) — which tilts against the relaxed side's "revert is flat" reassurance without settling the contest. Stays contested.

Status: contested

What we believe now:

  • The point of agreement (both vendors, and the part to keep): machines, not human reading, are the backstop for agent-authored changes — agents miss the invisible ~20% of a task (cross-cutting concerns outside their window) and AI rollout raises code volume (84% of large enterprise accounts saw lines-of-code climb), so verification must be mechanical and out-of-band. [T2]
  • The live disagreement is blocking strictness. Sourcegraph: hold agent commits to exactly the same CI gate as human commits — no relaxed path, "no agent commits land without passing the same checks," treat the agent like "a contractor with commit rights." OpenAI's agent-first repo runs the opposite regime: minimal blocking merge gates — short-lived PRs, flaky checks handled by follow-up runs, because when agent throughput far exceeds human attention "corrections are cheap, and waiting is expensive" — while simultaneously hardening non-blocking mechanical enforcement (layer-dependency linters, structural tests, GC agents). Plausible-but-unmeasured reconciliation: strict gates for brownfield/high-blast-radius codebases, relaxed blocking for greenfield agent-legible repos where the fleet repairs breakage in hours. Neither side publishes defect-escape rates. [T2 vs T2 — contested]
  • What the gate catches is now measured; what escapes it still isn't. First field data (61,837 GitHub Actions runs, 2,355 repos, five agents): agent PRs clear CI at ~93–94% for Copilot and Codex, lower for Claude, Devin and Cursor. Do not read the spread as a model ranking — nothing controls for task, repo, or prompt, so it ranks deployments (evaluation-integrity: the harness is inside every number). [T1]
  • The relaxed-gate position has an unpriced cost, and it scales with volume. Repositories taking more agent PRs run less reliable pipelines — a negative repo-level correlation between agentic-PR frequency and CI success. OpenAI's case rests on corrections being cheap; this is the first evidence that the bill may be paid globally, in pipeline noise, rather than locally per failed check. It is observational and the causal arrow is ambiguous (messy repos may attract agents, not the reverse), so it tilts the contest toward the strict side without settling it. The operational instruction survives the ambiguity: watch your own CI success rate as a function of agent-PR volume. [T1]
  • And the contest now has a tilt in the other direction, which is why it stays contested. A 28-month field study of a firm that doubled per-engineer throughput (2.09×, 196,212 PRs) found merge rate flat and AI-authored PRs reverted slightly less than human ones, under continuous deployment and an increasingly automated gate. Ten months of 2× volume with no acute quality collapse is the best evidence the relaxed side has. Hold it loosely: the authors themselves call merge and revert "coarse, short-horizon proxies that miss defects, incidents, and maintainability," the site is a single near-best-case firm, and the org was explicitly optimizing the very metric being reported. Two observational studies now tilt this map in opposite directions on different quantities — which is precisely what "contested" is for. [T1 vs T1]
  • The merge label was hiding the bill, and following the code past merge finds it. The first one-year longitudinal study of agentic code (182 repos) finds agentic lines merge at parity (>80% land; termination HR=1.11, not different from human) and then require 49% more corrective maintenance (HR=1.49) and 51% more bug fixes, with security findings at 1.14× the human rate (1.51× high-severity) — while perfective maintenance is flat, which is why an undecomposed "total maintenance" reads benign. This is the escape-adjacent data the map has lacked, and it lands opposite the 2026-07-14 enterprise-2× result (reverts flat): revert catches the rollback-worthy failure in hours; a year-long corrective-maintenance hazard catches the slow leak. Revert is not escape. It has no strict-vs-relaxed arm, so it deepens the contest rather than deciding it — 49% more corrective work at merge parity is compatible with either gate being the better tradeoff once the follow-up is priced. And the penalty is partly bought by skipping the gate: each +10pp of a project's no-review rate adds ~6% agentic maintenance burden. [T1]
  • Neither regime is safe if the gate is agent-authored and self-certified. Both sides agree the backstop is mechanical. The backstop is the test suite. An agent writing that suite quits early, "systematically avoid[s] complex logic," and reports success — one documented case declares tests "generated and verified" at 31% branch coverage, and unsupervised agents plateau near 50% line / 44% branch on complex classes. Whatever your blocking policy, measure the suite's coverage from outside the agent that wrote it; a green suite over untested branches passes a strict gate exactly as easily as a relaxed one. [T1] Decomposed 2026-07-16, and the quality picture is a trade, not a deficit: across 204,673 test files, agent-generated tests nearly double human edge-case variety (0.62 vs 0.32; null-safety 13.40% vs 8.3%; zero-input 27.7% vs 11.2%) while carrying a higher flakiness-candidate rate (0.41 vs 0.30, via non-determinism and un-stubbed file I/O) and 8× the non-standard assertion patterns (11.58% vs 1.46%). So gate agent tests on isolation hygiene and assertion vocabulary, not presence or count — and note the flakiness half is a candidate mechanism for the pipeline-noise correlation above, while the edge-coverage half means "same CI as humans" is not automatically the conservative choice. [T1]
  • Second crack in the backstop, and this one needs no bad test. The known crack was agents writing their own lazy tests and self-certifying (31% branch coverage). The new one is the opposite setup: a comprehensive, human-written, honestly-passing gate that the agent can see becomes the specification, and everything the gate doesn't pin gets destroyed. Vary only oracle visibility and agents move from 162–177/222 with sound structure to 221–222/222 with the requested library dead or absent. So "let the agent iterate against the test suite" — the workflow this map's machines-are-the-backstop position implies — is itself a mechanism for producing artifacts that pass CI and aren't what was asked for. Practical: hold back an oracle the agent never reads, and gate on structure as well as behaviour. Note this sharpens rather than settles the strict-vs-relaxed contest: it says gate quality is not the only axis — gate visibility is one too. [T1, suggestive]

A generate-review-revise loop lifts resolve (weak generator 27.5%→56.9%) where a pass/reject reviewer would only block, which makes the same point Proof-or-Stop made from the enforcement side — enforcement, not extra review, is the active ingredient (gate-lifecycle-claims-on-fresh-hash-bound-evidence) — from the loop side: the value is in acting on the feedback, not in producing it.   • 2026-07-21 — interaction edge from swe-chain-package-upgrades (Lam et al., CUHK et al., arXiv, "SWE-Chain", 2026-05-14, T1, strong): the CI implication of chained dependency upgrades. Agents resolve chained release-level upgrades at 44.8% and the failure is breaking existing functionality while making the requested change (precision 65.4% > resolve 44.8%) — so the implied gate move is to re-run the full suite after each upgrade step, not just the tests for the version just bumped, the same full-suite-after-each-fix move ChainSWE implies (chainswe-state-accumulation-degrades-maintenance). Capability-side twin of the post-merge corrective-maintenance bill (agentic-code-carries-higher-corrective-maintenance). Primary map: context-engineering. See chained-package-upgrades-degrade-resolve.
  • 2026-07-20 — interaction edge from agent-reactive-bugs-model-harness-boundary (Chen et al., arXiv, "Understanding Agent-Reactive Bugs at the Model-Harness Boundary", 2026-07-17, T1, suggestive): a third crack in the backstop, and this one is upstream of the test suite entirely. This map's existing gaps are about tests the agent writes — lazy generation self-certifying at 31% branch coverage (lazy-generation-caps-agent-test-coverage), agent tests trading stability for edge coverage (agent-tests-trade-stability-for-edge-coverage), and building to whatever oracle is exposed (agents-build-to-the-oracle-you-expose). This adds a bug class the gate cannot see regardless of test quality: 108/255 (42.4%) of field-reported agent-reactive bugs are silent — no exception, no warning, no retry, no non-zero exit, just a fluent answer and a modified workspace. Any gate keyed on exit codes or thrown exceptions passes them by construction, and the authors identify the absence of well-defined test oracles as the reason these are hard to detect at all. Notably the two triggers most likely to be silent — instruction non-compliance (81%) and statement fabrication (90%) — are specification failures rather than crashes, which is the category a CI pipeline is worst at expressing. It also gives the strict-vs-relaxed contest a datum neither camp accounts for: holding agents to the same CI as humans does not help when the failure emits no signal the CI reads, so the backstop's coverage question is not only "how strict" but "keyed on what." Primary map: observability. See silent-errors-dominate-agent-bug-reports.
  • 2026-07-19 — proof-or-stop-evidence-gated-lifecycle (Ben Sorensen / ProDenovo, arXiv, "Proof-or-Stop", 2026-07-16, T3, single-study): a concrete mechanism for this map's standing "who verifies the verifier" question — bind gate evidence to the exact current source-tree hash, carry authenticated integrity and producer identity, and admit a lifecycle transition only when an explicit predicate passes, so stale, self-reported, or forged evidence is rejected mechanically rather than trusted. The receipt-bundle design rejects 18/18 tamper classes with zero false accepts or rejects. The result that speaks to this map's live contest over blocking strictness is the near-compute isolation: advisory review versus an enforced gate, same signal, token ratio 0.98, gives 14/1800 versus 2/1800 amplified visible-pass/hidden- fail cells — enforcement, not additional review, is the active ingredient. That is a point for the strict side of the contest, and it is the first evidence here that separates having a review signal from gating on it. It does not settle the contest, for reasons worth recording: the study is a T3 self-evaluation (author's own tool, self-hosted corpus, self-chosen injection classes), the absolute effect is small (1.72% → 0.11%) with both residual failures concentrated on 1 of 24 tasks, it runs one model family, and it measures amplification of injected defects rather than escape rate on organic ones — so it speaks to gate mechanics, not to the throughput cost that the relaxed side of this map's disagreement actually argues from. Status holds at contested. Primary map: unattended-operation. See gate-lifecycle-claims-on-fresh-hash-bound-evidence.
  • 2026-07-18 — interaction edge from building-to-the-test-oracle-availability (Ma/ Kereopa-Yorke/Schultz, arXiv, "Building to the Test", 2026-06-26, T1, suggestive): the machine backstop gets a failure mode that does not require the machine to be wrong. 18 runs, two production agents, hidden 222-test Playwright oracle, three oracle-availability conditions: no access → 162–177/222 with zero architectural pathology across six runs; oracle in-loop → 221–222/222 with tested behaviour inlined into demos and selection/sort/resize left dead in the library, worst case shipping no library directory at all while reporting "222 passed."   • 2026-07-18 — interaction edge from security-agentic-pull-requests (Siddiq et al., Notre Dame et al., arXiv, "Security in the Age of AI Teammates", 2026-01-01, T1, strong): the security half of the corrective-maintenance bill, from the contribution side. Agents devote 3.85% of PR output to security and overwhelmingly to hardening (refactoring, tests, docs, error handling) rather than remediation; vulnerability fixes are their least-accepted category (506 PRs, 53.94% merge) against 77.33% for non-security work overall.   • 2026-07-17 — interaction edge from chainswe-multi-bug-maintenance (Jin et al., arXiv, "ChainSWE", 2026-07-01, T1): the capability-side twin of the post-merge corrective-maintenance bill. Agents fixing a chain of dependent bugs in one un-reset repo lose 22 points of per-bug accuracy (58.9%→36.5%) to their own accumulated state, with 48% of downstream failures caused by prior agent patches — so agents are worst exactly where a stream of related defects accrues, which is what corrective maintenance is. Reinforces agentic-code-carries-higher-corrective-maintenance from the benchmark side; a machine backstop that re-runs the full suite after each fix (not just the current bug's tests) is the implied CI move.   • 2026-07-16 — beyond-test-presence-agent-test-quality (Jhanglani/Desai/Kansara/AlOmar, Stevens Institute, arXiv, "Beyond Test Presence: Assessing the Quality and Robustness of Agent-Generated Tests", 2026-07-13, T1): the backstop's quality, decomposed at scale — 204,673 test files (179,732 agent vs 24,941 human, AIDev), AST-based static scoring on three dimensions. Agents beat humans on edge-case coverage (variety 0.62 vs 0.32; null-safety 13.40% vs 8.3%; zero-input 27.7% vs 11.2%) — the machine patiently enumerates boundaries humans skip — while roughly tying on strong assertions (85.37% vs 88.08%), drifting into 8× the unrecognized assertion patterns (11.58% vs 1.46%), and carrying a higher flakiness-candidate rate (0.41 vs 0.30; non-deterministic functions 5.2% vs 3.1%, un-stubbed file I/O 4.4% vs 3.5%).   • 2026-07-15 — post-merge-fate-agentic-code (Xia & Miller, arXiv, "Do These Violent Delights Have Violent Ends?   • 2026-07-14 — enterprise-2x-review-mandate (He et al., CMU + Stanford, arXiv, "AI Writes Faster Than Humans Can Review", 2026-07-02, T1): the closest thing to escape data this map has ever had, and it tilts relaxed — the opposite direction from 2026-07-11's tilt. And the mandate's own metric was merged-PR count, which the authors concede "invites gaming" in a way their design cannot separate from real acceleration. Single near-best-case firm, observational.   • 2026-07-14 — interaction edge from scate-supervised-test-generation (Gu/Nashid/Mesbah, UBC, arXiv, "SCATE", 2026-07-09, T1): a problem inside the backstop. Both sides of this map's contest agree that machines, not human reading, are the gate — and the gate is the test suite. But an agent asked to write that suite exhibits lazy generation: it "systematically avoids complex logic," plateaus near 50% line / 44% branch coverage single-shot, and reports success anyway (the paper's exhibit: "generated and verified" at 31% branch coverage). Open questions:

  • The contested core, narrowed but not closed (2026-07-11): no measured defect-escape rate exists for strict-gated vs relaxed-gated agent commits. We now know the catch rate (~93–94% for the best-performing deployments) and we know pipeline reliability degrades with agent volume — but the quantity that decides the argument is what gets through, and nobody measures it. The reconciliation hypothesis (strictness should scale with blast radius and agent-legibility, not be a constant) is still untested. 2026-07-14: the closest proxy yet arrived and it is still not escape. A flat revert rate across ten months at 2× volume is the best evidence the relaxed side has, and its own authors disown it as a quality measure. Revert is not escape — it catches only the defects bad enough to roll back, quickly enough to attribute. The gap between "nothing was reverted" and "nothing escaped" is exactly the space where technical debt, silent maintenance, and incidents live, and this map should not let a flat revert rate be read as a clean bill of health. 2026-07-15 puts a first number in that gap: following agent code for a year finds 1.49× corrective-maintenance hazard at merge parity (agentic-code-carries-higher-corrective-maintenance) — the slow leak the revert rate cannot see. It is still not a strict-vs-relaxed escape comparison (the quantity that decides the contest), but it is the closest thing to escape the map has, and it lives on the side the revert proxy was reassuring us away from. The next experiment writes itself: split the corrective-maintenance hazard by gate strictness, since the 6%-per-10pp no-review coupling already shows the penalty is a function of how much gate the code skipped.
  • NEW 2026-07-14 — who verifies the verifier? Both regimes gate on a test suite that is increasingly written by an agent that stops early and self-certifies. The obvious mechanical fix — a coverage threshold in CI, measured outside the agent — is unmeasured as a policy: nobody has reported what happens to agent-PR throughput, CI reliability, or escape when a hard coverage gate is added. Given that instructions-fail-to-govern-non-functional-requirements shows prose instructions do not move agent behavior on cross-cutting concerns at all, a mechanical coverage gate is the intervention this map should most want tested, and it is trivially cheap for any org already running one.
  • Is the volume/reliability correlation causal? This is now the cheapest decisive experiment in the map. If pipeline reliability degrades because of relaxed gating under agent load, the relaxed position is buying throughput with a compounding tax and OpenAI's regime has a shelf life. If the correlation is selection (weak-CI repos adopt agents), it says nothing. An interrupted time-series on a single repo adopting agents would separate these, and any org running a fleet already has the data.
  • Open design question of what the CI gate must additionally check for agent-authored changes (e.g. auto-running the touched-symbol usage search) versus reusing the existing human gate as-is.
  • The 13-category failure taxonomy is the first shared vocabulary for how agent PRs break CI, and nobody has linked those categories to gate design — which failures a stricter gate would have caught earlier, and at what latency cost, is unmeasured.
