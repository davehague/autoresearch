What we believe now

A test result is not a measurement. It is a measurement that has been through six or more software steps, each involving a choice, and most of those choices are not written down anywhere a second laboratory could find them.

LevelWhat it isThe choice that produces it
zeromachine configurationfilter width, camera gain, electrode impedance, ambient control
Imachine output(acquisition) — voltages, light intensity, pixel values
IIraw dataconversion to readable numbers; quality control; filtering of erroneous data
IIIaveraged / relativewhat counts as a replicate; arithmetic, geometric or median mean; normalisation to which control
IVconcentration-response curvewhich regression model; are non-monotonic shapes allowed; how many points define the baseline
Vintegrated curve informationwhat benchmark response is set; how uncertainty is computed
VIhit definitionthe prediction model / data-interpretation procedure
IATAintegration across several NAMs(out of scope of the source)

"for some NAMs, a dozen or more processing steps can be required."

The vault's closed-loop-ready tier grades exactly one of those transitions — V → VI. Everything from level zero to level V is what this vault has been treating as "the readout", as though a plate reader emitted a point of departure. It emits level I.

And the layer is outcome-changing. The paper's central sentence: "The same raw data, processed in different ways, may result in different final outcomes that may affect the readiness status and regulatory acceptance of the NAM." Its supporting evidence is secondhand but specific — Kessel et al. 2023 gave five biostatistical procedures that change developmental-neurotoxicity test results; Lasch et al. 2020 found five mathematical models producing different outcomes from one mixture dataset.

The consequence for anyone who improves the software: "changing the pipelines of already established NAMs can have serious consequences. In the worst case, the NAM may need to be re-validated … If the output of a NAM changes (because of the use of an alternative data processing pipeline), then the apparent performance of the NAM could change." The analysis code is part of the method. Optimising it produces a different, unvalidated method with the same name and someone else's performance number attached. (changing-the-analysis-pipeline-changes-the-method.)

The imaging corroboration is independent and it is sharper. The European Commission's Joint Research Centre — the institution hosting EURL ECVAM, the EU's validation reference laboratory — reaches the same place from the high-content-imaging side and adds the reason the layer stays dark: "Manufacturers are reluctant to disclose details on the instrument settings and controls", with the stated consequence that "only few imaging-based in vitro methods would be used for regulatory toxicology." Commercial analysis software carries "the proprietary nature of the used algorithms with little insight of their precise makeup." And the working practice is worse than the documentation: "many researchers relying on the acquired images themselves to set the acquisition parameters for each experiment." (level-zero-the-instrument-nobody-specifies.)

Loop readiness

loop_readiness: computational-connective — the model layer, not an assay. But this map's finding is about the loop-readiness of everything else, so state it precisely:

  • Nothing in the vault demotes on this. For most closed-loop-ready maps the chain is short and the Test Guideline specifies it: absorbance → percent of control → compare to 50%. A normalisation and a threshold, both public. That is what a Test Guideline is for, and it is why adopted methods are in better shape here than research assays.

  • What changes is what the tier means. closed-loop-ready certifies the decision rule, not the pipeline that feeds it. The vault has occasionally been reading it as the latter, and should stop. (six-data-levels-sit-between-the-plate-and-the-call.)

  • A cycle the vault had drawn as a straight line. For multi-endpoint assays, level VI can invalidate level V — a cytotoxicity call flags a functional readout as meaningless, because "the preconditions for the measurement … have not been fulfilled." Omit that feedback edge in a re-implementation and you get confident false positives. This is the same architecture automation-tox21-qhts-platform uses at scale (multiplexing viability into the same well) and which the vault filed on 2026-07-13 as a counter-design against correlated blind spots. It is both: a blind-spot remedy and a pipeline feature.

  • A specific requirement for a loop, in plain engineering terms: version the pipeline, pin it, treat a pipeline change as a method change requiring re-qualification, and keep golden-file regression tests. All cheap. All exactly the kind of overhead an optimiser deletes first — the third time in five days the vault has recorded that shape (pin the seed, pin the reference set, now pin the pipeline).

  • The validation paradigm (composes-with, and a direct dependency): validation-paradigm-nam-confidence.   • Tox21 (confirms, with a named artefact): automation-tox21-qhts-platform runs tcpl, the ToxCast pipeline, which Blum et al. cite as the field's reference implementation and as the example of continuous hit calling — an output of "a hit at concentration X µM" rather than a categorical call. The vault's account of Tox21's ambiguous curves being "manually inspected … by masking or unmasking data points" is a level II/III operation in this map's taxonomy, which is a more precise statement of the problem than "humans still interpret."
  • DNT (confirms, and it is the worked example): developmental-neurotoxicity-dnt-ivb is where both sources' concrete evidence comes from — Kessel 2023's five outcome-changing biostatistical procedures were demonstrated on DNT battery data, and the JRC paper describes the Human Neurosphere Assay's Omnisphero + two-CNN scoring stack. The DNT map's blocker (no fixed data-interpretation procedure) sits at level VI; this map says the battery also has unresolved choices at levels II–V.

  • ⚠️ ADDED 2026-07-28 — there is a LEVEL ZERO, and it has no assurance either. This map's six levels run from the instrument's raw output (level I) to the hazard call (level VI). AEGIS (setty-2026-aegis-protocol-validation-runtime-monitoring) sits one step below level I — the protocol that produces the raw number in the first place — and demonstrates that this pre-instrument layer has exactly the properties this map documents one level up: outcome-changing, treated as an implementation detail, and largely unverified. Its motivating case is a protocol that reuses a pipette tip between a PCR template and its no-template control: valid code, clean execution, a plausible number rather than an error. That is this map's central complaint about the software layer, restated about the wet layer. The measured assurance available at level zero is worse than anything reported for the levels above it — checking the protocol scores adjusted F1 0.97, watching the robot physically execute it scores F1 0.71, and 0.47 at the smallest pipette volumes. This map's warning that "re-analysis by alternative pipelines … may lead to an altered overall output" has an exact analogue underneath it: re-execution by an unmonitored robot alters the data.
