Human Liver-Chip / MPS — hepatotoxicity (DILI) — method

Status: emerging (2026-07-06) — split axes, bias-flagged. evidence_tier: peer-reviewed-method (one sizeable blinded study) but regulatory_status: under-validation (FDA ISTAND pilot, not adopted), and the key validation is developer-run (funding_flag: industry / method-developer). The vault's first entry for the hepatotoxicity endpoint, previously a headline coverage gap.

What we believe now

The human Liver-Chip is a perfused microphysiological system (organ-on-chip) co-culturing primary human hepatocytes with non-parenchymal cells to reconstitute liver metabolism and microenvironment. In the largest single reported Organ-Chip evaluation to date (Ewart et al. 2022, PMID 36473994), it reached 87% sensitivity and 100% specificity for drug-induced liver injury (DILI) on a blinded 27-drug panel (870 chips, 3 donors). The eye-catching specificity is real but the panel is curated and the study was run by the platform's developer (Emulate) — a developer validation, not an independent ring trial. Kept emerging: promising, single-study, developer-led, regulatorily unadopted.

Through-line

  • 2026-07-06 — Ingested Ewart et al. 2022 (PMID 36473994). Coins this map (new endpoint: hepatotoxicity). 87%/100% on a blinded 27-drug DILI panel, but developer-run + single study + under-validation → emerging (deliberately not upgraded on a developer-run panel).
  • 2026-07-06 — Regulatory momentum (not acceptance): FDA accepted a liver MPS into the ISTAND pilot (Sept 2024); the April 2025 FDA Roadmap prioritises MPS/organ-chip data. Watch for an independent (ECVAM/ICCVAM/IQ-MPS) validation that would move the science axis.
  • 2026-07-10 — An adopted human-liver TG arrives — for a different question. Status holds at emerging. metabolism-cyp-induction-heparg (OECD TG 445A) is the first adopted OECD in-vitro method using a human hepatic model — the HepaRG™ line this map already named among the hepatic systems to watch. It does not validate, refute, or supersede the Liver-Chip: TG 445A reads a mechanistic metabolic perturbation (CYP induction) in a static monolayer, while this map reads apical liver injury (DILI) in a perfused multi-cell system. The pairing is the vault's cleanest demonstration that the axes are orthogonal, not correlated: the Liver-Chip has a real apical predictivity number (87% / 100%) and no adoption; TG 445A has no predictivity number and full adoption on both axes. Neither fact bears on the other.

Cross-intervention / connect (§6.5)

  • ⚠️ ADDED 2026-07-12 — this map's regulatory_status: none has been read wrongly, and the regulator says so. regulatory-acceptance-fda-nam-framework (FDA CDER draft guidance, March 2026) states that "for a NAM to be considered for review in drug development, the test does not necessarily need to be validated … A fit-for-purpose NAM, even if not validated, may adequately address specific toxicological concerns" inside a weight-of-evidence argument. The Liver-Chip is precisely the class that route exists to admit — and CDER's own worked example of "human biological relevance" for hepatotoxicity reads like a specification of this method: "the model should contain the relevant cell types (e.g., hepatocytes, stellate cells, Kupffer cells) and biological features (e.g., albumin production, metabolic competence)." This map is already in FDA's own ISTAND pipeline. The Status does not move and regulatory_status: none is not wrong — there is no Test Guideline, and the 87%/100% panel is still developer-run, which is exactly the weakness the vault flagged and exactly the weakness a case-by-case fit-for-purpose regime is least equipped to catch. What changes is the reading: none means "has no guideline", not "cannot be used regulatorily." The vault has been narrating the second while measuring the first.
  • ADDED 2026-07-12 — and the tension cuts both ways. The FDA route is the strongest available argument that this map's science should be usable now (the alternative is a validation queue that took metabolism-cyp-induction-heparg twelve years). It is also the regime in which a developer-run 87%/100% panel could start carrying regulatory weight it has not independently earned. The vault does not resolve this; it records that this map is the test case for the whole question.
