Imputed descriptors put the blind spot inside the feature matrix

What arrived

A free web service that will build you a toxicity prediction model without your writing any code, over ~50,000 curated chemicals, with the source published. For a vault whose central question is whether a machine could run a method end to end, the model layer becoming a button is not a small thing.

The good half: an access gate loosens

in-silico-qsar-read-across carries an access_gate set on 2026-08-14 with a precise justification: a model served only from a vendor's login-gated endpoint "cannot be version-pinned, re-run against a fixed reference set, or audited for which applicability-domain stratum a prediction came from." The gate is not about cost. It is about the ability to check.

ToxiVerse is the opposite arrangement — free service, published source. In principle an automated pipeline can pin a version and re-run it against a fixed reference set, which is precisely what the gated tools forbid.

In principle. Whether it actually can depends on whether the repository is release-tagged and whether the curated dataset is downloadable in bulk rather than only queryable. Neither is stated in the abstract or the inspected repository description. The gate is loosened, not lifted, and the map's access_gate text stays as it is — one open tool does not undo a class-level barrier.

The half that needs writing down

A (Q)SAR model is a function from descriptors to a prediction. Here, some of the descriptors are themselves predictions.

The Bioprofiler builds a chemical's profile from PubChem bioactivity data "with a machine learning-based data gap-filling procedure." For a well-studied chemical assayed hundreds of times, little is filled in. For a poorly-studied one, much of the profile is imputed by a model.

Then a second model is trained on those features.

The two models fail on the same chemicals for the same reason, and the reason is sparsity. Where the bioactivity record is thin, the imputer is guessing and the downstream model is learning from guesses. A cross-validation score computed on the combined pipeline will not separate the two error sources; it will report one number that looks like model quality.

Those are exactly the chemicals a (Q)SAR exists for. Nobody needs a prediction for a compound with four hundred assay results. The whole point is the data-poor chemical — the new one, the untested one, the one nobody has run — which is the regime where the feature vector is most imputed and the model is least entitled to confidence, and where nothing in the pipeline says so.

This is this vault's correlated-blind-spot rail, relocated from the bench into the feature matrix. The rail says two assays failing together for the same structural reason cast one vote, not two. Here it is not two assays — it is a model and its own inputs, which look like two independent things and are not.

Why the guard that should catch this cannot

The obvious answer is the applicability domain: the check that says whether a new chemical resembles the training set closely enough for the prediction to be trusted. Compute it, and refuse to predict outside it.

in-silico-qsar-read-across carries a domain_gate set on 2026-08-21 recording that this guard has a proven structural hole. On a 1,174-chemical skin-sensitisation set, 235 of 235 held-out chemicals passed the standard similarity-based domain check — including the ones inside the near-identical clusters the models called wrong. A similarity check cannot flag an activity cliff, because a cliff is defined as two similar chemicals with opposite outcomes.

A platform that auto-generates models for people who do not write code will auto-generate that hole at scale, and the abstract does not say whether it does anything about it. That is not a criticism of the authors' competence; it is what "no reported applicability-domain policy" means in practice when the audience is explicitly non-specialists.

The number that is missing

For a platform whose product is predictions, the abstract reports no accuracy, no cross-validation, no benchmark, and no comparison to an existing tool. That is normal for an applications note and it is still the first thing a reader needs. Combined with no stated licence and no curation provenance — curated by whom, against what, and how are conflicting assay results resolved — the honest grade is evidence_tier: in-silico-mechanistic, regulatory_status: none, and a note that the tool is inspectable, which is more than can be said for its commercial equivalents.
