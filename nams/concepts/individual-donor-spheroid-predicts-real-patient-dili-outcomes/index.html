The scientifically interesting design choice, independent of the accuracy numbers: every other liver method this vault holds (hepatotoxicity-liver-chip-mps, hepatotoxicity-cholestasis-battery, hepatotoxicity-steatosis-battery, hepatotoxicity-dili-in-vitro-pbk-integration) produces one answer per drug, built from one cell source or one averaged reference population. This platform seeds each spheroid with 50% serum from one individual donor, so the same drug can in principle return a different call for different people — a first attempt in this vault's hepatotoxicity column at modeling inter- individual variability directly in the assay rather than applying a population-level safety-factor multiplier after the fact, as population-variability-human-lcl-panel does for genotoxicity. The ribociclib case is the paper's strongest evidence for this idea: spheroids built from three actual patients' own donor material returned the same DILI call each patient actually experienced clinically. Read correctly, this is three data points, not a validation — but it is a mechanistically coherent demonstration of the platform doing the thing it claims to do (personalizing a hazard call), which few single-lab proof-of-concept papers in this vault manage even once.

The blocker is not the biology, it is the black box. The spheroid's inputs (dose-response viability curves, mechanistic markers) are fully instrument-readable — a robot could run the plates and generate the numbers today. What converts those numbers into a no-DILI/less-DILI/most-DILI call is a proprietary algorithm the paper cannot describe, "due to confidentiality." This is the same shape of blocker this vault has already graded once, on cardiotoxicity-hipsc-cm-proarrhythmia (a working classifier "available from the corresponding author upon reasonable request") — a rule that is not missing, only unpublished — and it earns the same tier for the same reason: automatable-open-loop, not closed-loop-ready, because nobody outside the company that built it can inspect, replicate, or audit what the loop would actually be running.

Connect check — the immune-cell gap this vault has flagged twice, partially addressed for the first time. hepatotoxicity-dili-in-vitro-pbk-integration carries an explicit correlated_blind_spot: its three components are "single-cell-type... with no immune component," so the battery fails together on immune-mediated (idiosyncratic) liver injury. This platform's spheroid includes THP-1-derived monocyte/macrophage cells alongside hepatocytes and stellate cells — a genuine architectural difference, not a claim the paper itself makes about closing that gap. Recorded as a partial mitigation to watch, not a resolved gap: THP-1 is an immortalized monocytic leukemia line, not primary human immune cells, and no idiosyncratic-DILI compound is tested in this paper to demonstrate the immune component actually catches anything the HepaRG-based batteries miss. Global-ripple: no other map's Status, evidence_tier, regulatory_status or loop_readiness moves — this is a new map's founding source, not a finding that touches an existing one.
