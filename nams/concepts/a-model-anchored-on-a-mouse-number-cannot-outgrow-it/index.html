A model trained to predict a mouse test is a faster mouse test

ExSERA (exsera-predicts-the-mouse-potency-within-fivefold) takes three non-animal assays as input and outputs a potency number. That reads like animal replacement. The target variable says something more careful: the number it outputs is the murine LLNA EC3 — what the mouse ear test would have measured.

Three consequences, and they are structural rather than a criticism of this particular model.

1. The accuracy ceiling is the mouse assay's own accuracy. The model is scored right when it agrees with the mouse and wrong when it disagrees — including in the cases where the mouse is wrong about people. Any mouse-versus-human discordance is baked into the target and cannot be learned out of it. The vault has the general version of this from a different direction: EFSA measuring the dog study's own reproducibility, and the-reference-answer-was-built-by-committee-because-no-animal-test-could-supply-it on what "ground truth" means when the reference is itself a judgement.

2. The training data cannot exist without the animal study. 154 substances with measured mouse EC3 values had to be produced by running the assay on 154 substances. Every future extension of the applicability domain needs more of them. A model of an animal test is not independent of the animal test; it is downstream of it, permanently.

3. And it is the same dependency the vault already grades as a hard loop blocker — routed to a different answer. This is the point worth keeping.

The schema problem this exposes

The vault's loop_readiness ladder is deterministic and applied in order. Rule 2: the method's own prediction model consumes an in-vivo study → bench-bound, with bench_bound_reason: animal-input. That rule is why immunotoxicity-myelotoxicity-cfu-gm is bench-bound despite being fully quantitative with a fixed decision rule — its scaling model takes a prior mouse maximum-tolerated dose as an input, so a loop cannot close around it without a mouse.

But rule 1 fires first: no physical assay (a pure model) → computational-connective. ExSERA is a pure model, so rule 1 catches it and rule 2 never runs. The animal dependency is real, identical in kind to CFU-GM's, and lands in a tier the vault explicitly scores "off the ladder."

The consequence is that a computational method can carry an animal dependency that the third axis does not show. For anyone using this vault to prioritise where loop infrastructure would pay off, that is a live misreading: computational-connective reads as "this is the model layer a loop would update," and for a mouse-anchored model it should read "this is a model layer that a loop would update using animal data it must keep generating." Logged in docs/open-gaps-log.md.

What keeps this an open question rather than a refutation

Anchoring on an animal endpoint is not automatically a defect, and the adopted tools do it too. OECD Guideline No. 497 Part III's regression defined approach — adopted, in force — trains on LLNA EC3 and on human weight-of-evidence potency values, and takes the more conservative of the two answers. SARA-ICE uses historical LLNA and human patch-test data as inputs. The guideline's own rule is that existing in-vivo data may be used while new in-vivo data must not be generated for these approaches, which is a coherent position: mine the animal studies that already exist, stop producing more.

Under that rule, ExSERA is legitimate. What it does not do, per its abstract, is anchor on human data as well. The adopted tool hedges its mouse target against human outcomes and takes the safer number; ExSERA reports only the mouse target. Whether the full text includes a human comparison is unknown — the paper is paywalled — which is why this is graded stance: open-question and not refutes.

The generalisable rule to carry. When a non-animal method reports impressive agreement, ask what it agreed with. Agreement with an animal assay measures substitutability, not correctness — and the ceiling of a model trained on an animal endpoint is the animal.
