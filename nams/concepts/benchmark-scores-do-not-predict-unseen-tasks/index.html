The benchmark says the agent works. It does not say the agent will work.

Every automation number this vault holds is a benchmark score — ProtoPilot's 88.24% instrument pass rate, Pipette's 37–72% task success, LabBench2's 1,912 tasks, AEGIS's F1 0.97 on plan checking, LabRobFail's 90.83%→71.02%. On 2026-08-02 the vault recorded that such benchmarks carry construction flaws that inflate scores.

This is a different and more basic problem, and it is measured rather than argued. Even a benchmark with no validity flaw at all, whose score is a perfectly honest measurement of performance on its own tests, may carry no information about performance on a task it does not contain.

The experiment

Train a model to predict "will this agent configuration pass this test?" from the configuration alone. Then check it two ways.

ROC-AUC is the probability the model ranks a randomly chosen success above a randomly chosen failure. 0.5 is a coin flip. The second row is a coin flip.

What the model had actually learned was which tests are hard — test identity was the strongest predictor. Strip that out and nothing remains.

Why this is the applicability-domain problem wearing different clothes

This vault already has a name for "the method works, inside a boundary, and outside it you cannot say": the applicability domain, carried in frontmatter as domain_gate. OECD Test Guideline 435 screens out much of pH 4.5–8.5. OECD Test Guideline 249 is bounded to a lipophilicity range. A closed-loop-ready tier has never meant "trust the rule on any chemical" — it means trust it inside the domain.

An agent benchmark is an assay, and it has an applicability domain that nobody was declaring. The 53 tests are its reference chemical set. Passing them qualifies the agent for those tests. This paper is the first source in the vault to measure how far outside that set the qualification carries, and the measured answer is: approximately nowhere.

For toxicology the consequence is direct and unpleasant. A regulator asked to accept an AI-driven method will ask what evidence supports it. The natural answer — "it scores well on a benchmark" — is exactly the answer this result undercuts, because a hazard-testing loop's whole purpose is to run chemicals nobody has run before. The benchmark covers the tasks you already did.

What this does not license

  1. It is not evidence that agents fail on new tasks. The five held-out tasks were completed on real hardware. What failed was the prediction — you cannot tell in advance which configuration will handle them.
  2. The dataset is messy and the authors say so. Historical, unbalanced design rather than a factorial experiment; model, prompt, framework and hardware versions changing mid-study; runs mixed across a simulator and three microscope models; non-independent repeats. That weakens the surrogate as much as it weakens anything else, so "benchmarks don't generalise" is partly confounded with "this training set was noisy."
  3. Vendor-authored and vendor-funded. Carl Zeiss employees, Carl Zeiss money, Carl Zeiss instruments. Counterweight: the headline argues against interest, and the winning configuration was the cheapest one.
  4. No toxicology, no endpoint, no guideline. X-ray microscopy of materials. The transfer is the vault's inference, labelled.
