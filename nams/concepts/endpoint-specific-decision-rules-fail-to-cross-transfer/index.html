A toxicity model's decision rule mostly does not survive a move to a neighboring endpoint

Thirteen toxicity endpoints, evaluated pairwise (156 ordered pairs) under scaffold-disjoint, leakage-controlled cross-validation — the harder test of generalization to genuinely new chemical structures, not near-duplicates of training compounds. Training a model on endpoint A and predicting endpoint B directly averages ROC-AUC 0.525, barely above a coin flip. Pooling all 13 endpoints' labeled data into one training set performs worse than training each endpoint separately (-0.0287 macro-average ROC-AUC) — more data, wrongly mixed, costs accuracy rather than buying it. More sophisticated transfer architectures (stacking, multitask learning, model-agnostic meta-learning, frozen-encoder feature augmentation) recover only small, inconsistent gains (+0.0070 to +0.0101 on average), and the authors report the gains track the specific strategy and target endpoint rather than how biologically related two endpoints are to each other.

Why this lands on in-silico-qsar-read-across. The map's whole standing thesis is a bounded scope: computational prediction works broadly as weight-of-evidence support, and works as a licensed replacement in exactly one narrow, validated domain (ICH M7 bacterial mutagenicity). This source is an independent, quantitative confirmation of why that scope stays narrow — a learned decision rule does not reliably travel even one small step sideways, to a different endpoint on the same chemicals. It is new evidence for the map's existing single argument, not a new strand: a direct measurement of the generalization failure the map has already been naming qualitatively.

Composes with automation-experiment-selection. That map's recurring finding is that nothing prices what a correct toxicology decision is worth, so an automated selector has no rule to optimize against. This source sharpens the same problem from the fitted-model side: even once you have enough labeled data to fit a rule for one endpoint, that rule does not reliably transfer to the next question a loop would ask — the portability problem survives having the data, it is not only a data-scarcity problem.
