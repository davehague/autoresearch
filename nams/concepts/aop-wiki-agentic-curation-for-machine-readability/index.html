The knowledge base underneath every AOP-based battery gets its own agentic-AI proposal — and this vault has been assuming it was static

What this adds

Every time this vault has used an Adverse Outcome Pathway to justify a testing battery's composition — the kidney and cholestasis batteries choosing Key Events from published pathways rather than from assay availability, quantitative-aop-probabilistic-modelling's attempt to put numbers on the arrows — it has treated the AOP-Wiki as a fixed reference to consult, not a system with its own curation bottleneck. This source names that bottleneck directly: a human-curator-only model cannot keep a knowledge base current against the literature's actual publication rate, and proposes agentic AI as the curation mechanism itself — software agents reading new papers and populating Key Events, Key Event Relationships and supporting evidence into the Wiki's structured fields.

This is a different application of "agentic AI in toxicology" than every other instance this vault holds. The self-driving-lab and experiment-selection literature uses agents to pick and run experiments. This paper uses an agent to keep the shared knowledge layer itself current and machine-readable — a curation problem, not an experimentation problem. Filed as a new data-layer object, data-layer-aop-wiki-knowledge-model, distinct from nam-data-processing-pipeline (the numeric instrument-to-hit-call chain): this is the causal-knowledge database an AOP-based battery design or a quantitative AOP model draws its structure from, not the numbers a single assay produces.

Why this is graded cautiously

No quantitative result was recoverable from the abstract-level material this run's tooling could read. The paper's title names a "content evaluation framework" as a companion contribution, but no metric, threshold, or score the framework produced against real AOP-Wiki entries was found. This is architecture/systems work, graded the same way this vault grades every self-driving-lab-infrastructure paper with no accuracy benchmark — real, potentially important, and not yet evidence that the agentic curation pipeline actually works at any measured rate. strength: single-study and evidence_tier: in-silico-mechanistic reflect that caution, not a judgment that the idea is weak.

Why this matters for the vault's central question

If a loop is ever built to run a NAM battery and update its own decision rule, the rule it updates has to be grounded in some structured account of the pathway it is testing. A knowledge base only a human curator can keep current is itself a bottleneck on how fast that loop's reasoning layer can grow — a slower-moving, less visible cousin of the "reality gap" UniLabOS names for physical lab hardware (unilabos-hardware-interoperability-kernel): both are proposals to make something machine-legible that used to require a human in the middle, one for physical instruments, one for causal knowledge.
