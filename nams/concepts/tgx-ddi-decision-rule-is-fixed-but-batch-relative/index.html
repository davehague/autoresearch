A fixed decision rule with two batch-relative legs — a new way to fail the loop test

The vault's ladder asks one decisive question to separate automatable-open-loop from closed-loop-ready: does a fixed, deterministic data-interpretation procedure exist? OECD TG 493 is fully quantitative and stuck one rung down purely because the guideline says no agreed interpretation method exists. By that test TGx-DDI passes cleanly. Its rule is written down, mechanical, and conservative:

Run three classifiers. Call the compound DDI-positive if any one of them is positive.

The three are nearest shrunken centroid probability analysis (supervised — compare the sample's 64-gene profile against trained DDI and non-DDI centroids), principal component analysis, and hierarchical cluster analysis.

But two of those three are unsupervised. PCA finds the axes of greatest variance in the analysed set. HCA groups samples by similarity to each other. Neither is a function of the test sample alone — both are functions of the sample and its neighbours in the batch. Change what else was analysed and, for a borderline compound, the projection and the cluster membership can change with it. Only the supervised leg is per-sample-independent.

Why this is fine in a lab and not fine in a loop. In normal use a technician runs the protocol's standard reference compounds every time; the batch composition is effectively a constant, so the batch-relative legs behave deterministically. The rule is reproducible — the ring trial's Kappa of 0.61–1.0 across four labs is the evidence.

A closed loop breaks that assumption by construction. The whole point of an autonomous lab is that the AI chooses the next set of compounds based on what it just learned. So the loop is continuously changing the thing two of its three classifier legs are conditioned on — and doing it on purpose, adaptively, in a direction correlated with the previous result. A compound tested in an early exploratory batch and the same compound tested later among its structural analogues are not guaranteed the same call.

What the vault takes from this. A new distinction the axis definition did not previously make:

  • Fixed — the procedure is written down and applied mechanically. TGx-DDI: yes.
  • Sample-independent — the call for compound X depends only on compound X's data and pre-trained parameters. TGx-DDI: partly, no.

closed-loop-ready was defined on the first property. This is the first source in the vault that separates them. It does not demote TGx-DDI — the rule is fixed, the reproducibility is measured, and the failure mode is hypothetical rather than demonstrated (strength: suggestive, stance: open-question). What it demands is that a loop running this assay pin its reference set, run it every batch, and treat the reference panel as part of the protocol rather than as overhead to be optimised away. That is a cheap, concrete engineering requirement, and it is the kind of thing an autonomous system would strip out first precisely because it looks redundant.

Related, from the other direction: ai-decision-rules-are-not-deterministic records that a model which retrains is not a fixed rule at all. This note records the milder cousin — a rule that is fixed but whose inputs include its own context.
