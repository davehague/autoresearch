The thing the loop would update is now a listed method

What changed

The vault grades one class of map computational-connective: not physical assays, but the model layer a closed loop would update — (Q)SAR and read-across, physiologically based kinetic modelling, the data-processing pipeline, the machine-learning literature's own quality record. Four maps, deliberately scored off the ladder rather than on it, because "could a robot run it" is the wrong question to ask a model.

EPA's 2026 list puts that layer on the same page as the wet assays. Under "Data Integration Tools, Predictive Models, and Assessment Frameworks," all marked NEW:

  • ToxCast — the high-throughput screening dataset that is the most common training data for machine-learning toxicity models (automation-tox21-qhts-platform)
  • GenRA Resource Hub — automated read-across predictions (in-silico-qsar-read-across)
  • SeqAPASS — cross-species susceptibility prediction from protein sequence
  • ChemExpo — exposure data; ECOTOX — an ecotoxicity knowledgebase; TEST — toxicity estimation software; cheminformatics modules; read-across frameworks and structural alerts
  • the developmental-neurotoxicity in-vitro battery — filed here rather than among test methods (developmental-neurotoxicity-dnt-ivb)

Three rows above them on the same page sit OECD Test Guidelines 444A, 467, 492B, 497 and 498 — adopted, ring-tested, internationally mutually accepted methods.

Why this is not a technicality

A database is not a method. ToxCast is a body of measurements. GenRA is a similarity engine. ECOTOX is a literature index. None of them produces a hazard call; each is an input to somebody's reasoning. Placing them in a statutory list of "alternative test methods and strategies" is a real widening of what the word "method" covers under US chemicals law — the strategies half of the title is doing heavy lifting.

The consequence for this vault's third axis is direct. loop_readiness: computational-connective was defined as "not a physical assay — this IS the model layer a loop would update." The vault scored it off the ladder on the reasoning that a model is not something a robot runs. That reasoning holds scientifically. Regulatorily, it just stopped holding: under TSCA, the model layer and the assay layer are now the same kind of listed object.

And the vault has now watched this happen from three directions in five days, which is the point at which it stops being an anecdote:

DateSourceThe model layer gains…
2026-07-26European Commission JRC + a 32-author ALTEX paper…six documented data-processing steps under every decision rule (nam-data-processing-pipeline)
2026-07-27US EPA's TSCA list…statutory standing beside adopted Test Guidelines
2026-07-27an Archives of Toxicology commentary…a documented way of learning the wrong thing from the assay layer (models-trained-on-hit-calls-learn-the-assay)

Read the three together and the shape is uncomfortable: the model half of the loop is being admitted to regulatory instruments on the same night the vault records that its training data can teach it the assay's artifacts, and one night after recording that the software between the instrument and the answer is largely undocumented. Acceptance is arriving faster than the accounting for it.

That is a statement about pace, not a claim that any listed model is wrong — and per ml-model-reporting-reproducibility's own domain gate, nothing here refutes a specific model.
