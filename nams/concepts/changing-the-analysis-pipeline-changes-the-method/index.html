The analysis code is part of the method, and optimising it breaks the method

The claim, verbatim

"changing the pipelines of already established NAMs can have serious consequences. In the worst case, the NAM may need to be re-validated, as the alteration of data processing may have changed the output. A typical measure of NAM performance is the comparison of NAM output with a gold standard or a ground truth … If the output of a NAM changes (because of the use of an alternative data processing pipeline), then the apparent performance of the NAM could change."

And the underlying observation the whole paper rests on: "The same raw data, processed in different ways, may result in different final outcomes."

Why an engineer should read this twice

Every performance number in this vault — "catches 85% of real allergens", "96% catch rate", "ROC-AUC 0.982", "specificity 86%" — is a number produced by a method plus a pipeline, benchmarked against a reference set. The number is not a property of the biology. It is a property of the whole computation.

So: swapping a better curve-fitting routine into an adopted assay does not give you the same assay with better software. It gives you a different assay whose published performance number no longer describes it, running under the same guideline name, with the same reference to a validation study that measured something else.

The specific problem for a closed loop

An autonomous system optimising a laboratory will, given the chance, optimise the analysis. That is the cheapest place to find improvement — no reagents, no plates, no wall-clock. It is also the one place where improvement is indistinguishable from invalidation, because there is no ground truth in the loop to check against; the ground truth lives in a validation report the loop never sees.

Three concrete failure shapes, none of which trip an alarm:

  • A better outlier rule. Excluding more noisy wells raises apparent reproducibility and shifts the benchmark concentration. Nothing in the data says this is wrong.
  • A better curve fit. Allowing non-monotonic shapes where the guideline assumed sigmoidal changes the point of departure for exactly the compounds where the shape matters most.
  • A cheaper feature. Dropping the multiplexed cytotoxicity check saves a channel and removes the feedback edge that invalidates functional readouts in dying wells — turning a known artefact into a confident hit.

The remedy is not clever and it is not new to software engineering: version the pipeline, pin it, and treat a pipeline change as a method change requiring re-qualification. The paper asks for exactly this, in the language of its own field — extend the ToxTemp reporting template to carry the processing pipeline, the way the OECD Omics Reporting Framework already does for transcriptomics and the (Q)SAR Result Reporting Format does for structural models. It notes the revision of OECD Guidance Document 34 — the document that defines what validation means — is considering data-processing documentation as a readiness criterion.

What is actually evidenced here, and what is not

Evidenced (secondhand): two published demonstrations that processing choices change answers — Kessel 2023 (five biostatistical procedures, on developmental-neurotoxicity NAM data) and Lasch 2020 (five mixture models, one dataset). Both are cited, neither is reproduced in this paper.

Not evidenced: how often it matters, how large the shift is, or whether any adopted OECD Test Guideline has ever produced a different classification under a different pipeline. strength: suggestive, stance: open-question. The worked case studies are "planned as a follow-up publication."
