A decision rule with adjustable constants is a different object from a decision rule

The vault grades a method's top loop-readiness rung on one conjunction: an instrument-readable readout, and a fixed data-interpretation procedure. The SENS-IS draft satisfies both on a plain reading — see sens-is-fixed-prediction-model-on-human-skin-tissue. This note is the asterisk, and it is drawn from the guideline's own text rather than from anyone's commentary.

Para. 32, immediately after stating the ≥7-gene rule:

"If different parameters (threshold value, gene identity or number of genes) should be chosen, they should be scientifically justified and validated with the proficiency substances."

Para. 31 says the same thing about the irritation gate. And para. 29 says the 1.25-fold cut-off "was selected using the EPISKIN™ - Large model and the PCR condition described in the SOP. In case alternative RHE are used the threshold level could be adjusted, justified, and validated with the proficiency substances."

Those three sentences give away the cut-off, the gene set, and the count. That is every free parameter the prediction model has. What remains constant is the form of the rule — count genes over a threshold, compare to a floor — not the rule.

Why an engineer should read this as a real distinction

There are two different objects here and the vault has been treating them as one.

A constant of the method. OECD Test Guideline 439 — the lab-grown human skin test for irritation — calls a chemical an irritant when tissue viability falls ≤ 50%. That number is the same in every laboratory on earth that runs the guideline. It is not derived, negotiated or re-fitted. Two labs that disagree about a chemical disagree about the measurement, and that is diagnosable.

A per-configuration fit. SENS-IS's 1.25 is a number derived against one tissue brand and one PCR protocol, and the guideline explicitly anticipates it being re-derived elsewhere. Two labs running SENS-IS on different tissue may be applying different rules to the same chemical, both correctly, both in conformance.

For a human toxicologist this is unremarkable — assay calibration is ordinary practice, and the proficiency-substance requirement is a real control. For a closed loop it is a different failure surface. An automated system that ingests a guideline as its decision rule must know whether the constants it copied are universal or local. If they are local, then transferring the loop to a second site, or switching tissue supplier mid-campaign, silently changes the classifier — and the change appears in no result table, because a result table records the verdict, not the constant that produced it. The loop would report a consistent methodology while running two different classifiers.

The pattern this belongs to

The vault has now met this shape from four directions and should stop treating each as a novelty:

  • Fixed but not sample-independent — a rule whose threshold depends on what else was on the plate.
  • Fixed but with a measured uninformative band — U-SENS's stimulation-index cut-off, where a 128–176% band around the adopted 150% reclassifies 35 of 191 chemicals.
  • Fixed but user-retunable — this note.
  • Fixed but preceded by an unruled setup choice — full-thickness-escalation-is-an-unruled-pre-analytical-choice, on the same assay.

All four are the same defect wearing different clothes: the arithmetic is deterministic and something upstream of it is not. A loop-readiness tier that only inspects the arithmetic will grade all four as top-rung, and will be wrong in the same way each time. The honest reading is that closed-loop-ready names a property of the published rule, and the vault has to carry the upstream conditions as modifiers rather than pretend they are absent.

This does not demote SENS-IS below the top rung, and saying why matters. The rule is fixed for any given configuration, the retuning is gated behind published proficiency substances rather than left to taste, and a machine can apply the rule perfectly once the configuration is pinned. What it does is make the configuration a first-class part of the loop's state — something that has to be recorded, versioned and checked on transfer, exactly like a model checkpoint.
