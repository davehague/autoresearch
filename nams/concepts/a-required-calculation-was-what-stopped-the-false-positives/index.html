Make it say what it expects before it says what it saw

An LLM agent judging real instrument data called signals that were not there, at rates up to 53%, and the rate got worse the more reasoning effort it was given (more-reasoning-effort-produced-more-hallucinated-signal).

One change fixed it. Require the model to calculate the expected signal first — commit to a quantitative prediction of what a real result would look like — and then judge the data against that.

ConditionFalse positive rate, all three models, all reasoning settings
Judge the data directly1.4% – 53.2%
Compute the expected signal, then judge0 – 3.7%

False negatives stayed near zero in both conditions. The constraint cost nothing in sensitivity.

Why this matters more here than in physics

Because the thing that worked is the thing this vault says is missing.

Twenty-three method maps in this vault sit at automatable-open-loop, blocked on "no agreed decision rule." The vault has consistently read that blocker as institutional: a committee has not written down how to convert the number into a call, so a regulator will not accept the output, so the loop cannot close. Paperwork, essentially — real, expensive, slow paperwork, but paperwork.

This paper reframes it. A stated numeric expectation the answer must be consistent with is not only what a regulator wants; it is what stops the model from making things up. The decision rule is load-bearing inside the loop, as error control, whether or not anyone outside is asking for it.

That changes the argument for writing one. The vault's standing position — from the GPT-5/Ginkgo campaign on 2026-07-26 — is that the loop closes where the objective is a number the instrument reports. This adds the mechanism: without a prior expectation to check against, a model asked "is this a hit?" will find hits. A screening loop over hundreds of thousands of wells runs that judgement more times than any human ever has.

The pattern this belongs to

It is the third instance of the same architecture in this vault, arriving from three unrelated fields:

  • The GPT-5/Ginkgo campaign (2026-07-26) — what made it safe was "a hand-written Pydantic type schema plus hand-written protocols", and one of the two failures was fixed by editing the schema rather than the model. → the-guardrail-was-a-schema-not-the-model
  • AEGIS (2026-07-28) — deterministic pre-flight rule checking caught what syntax checking could not.
  • This system — the agent has no hardware access at all; a deterministic verification program checks every request against safety constraints before the queue accepts it, and a required calculation constrains its data judgements.

In every case the thing carrying the safety property is not the model. It is a non-AI artifact — a schema, a rule database, a required calculation — that the model has to satisfy. For a hazard-testing loop that is the transferable design finding, and it is more actionable than any capability number in the automation column.

The brakes

  • One paper, one platform, one provider's models, not peer reviewed. The mechanism is not explained and the effect is not replicated.
  • This is one judgement task pulled out of a loop, not a measurement of an end-to-end system.
  • It does not make anything loop-ready. A required expected-signal calculation is available to the physicists here because the physics supplies the expectation. In regulatory toxicology the equivalent — how much should this reporter assay move if the chemical is a real hazard — is exactly the number nobody has published. The mechanism transfers; the input it needs does not exist yet. That is the same wall the cost-aware experiment-selection work hit on 2026-08-01, reached from the opposite side.
