That is a narrowing severe enough to reopen the claim, which is this vault's written test for contested. Two things the map must state in the same breath, because the headline invites a wrong reading. The extrapolated crossover for a realistic pool is ≈1e30 FLOPs, roughly 2,000× the largest training run in existence, so at every scale this vault's readers operate, filtering still wins and this paper's own curves are the evidence. The update is not "stop filtering" — it is that filtering is buying sample efficiency under a compute constraint, not removing a defect, which is a more useful belief because it predicts when it will stop paying. What we believe now:

  • "Selection dominates scale" is true, and it is true because compute is scarce — not because bad data is bad (new 2026-07-30, and this is the tension the map is now contested about). A deliberate scaling study fixes a Common Crawl pool, spends more compute than one epoch over it (up to 121.6 epochs), and finds a crossover in every configuration it can run: the unfiltered pool starts behind RefinedWeb (13% retained) and DCLM-Baseline (2.1% retained) and ends ahead of them. On a 670M-token pool at 1B parameters the unfiltered pool reaches loss 3.37 and beats every filter once given enough steps. Fitted scaling laws (R² > 0.99) put the crossover for a realistic pool at ≈1e30 FLOPs against ≈5e26 for current frontier runs — so the practitioner rule below is unchanged and this paper's curves are its strongest evidence yet. What changes is the reason: a filter is a compression technique whose value falls as compute rises, so it predicts its own expiry. Two consequences the map now carries. A filter comparison run to a fixed step count is an experimental condition, not a fact about the data, and no filtering paper in this vault reports where on the crossover curve its ablations sit — the same shape as the recipe-leakage mode on evaluation-contamination. And one crossover is reachable: at 330M parameters past ~11B tokens, adding word-shuffled documents (unigrams preserved, syntax destroyed) makes the model better than the clean pool alone, and at 1B a +800% dose roughly matches clean data. That is not tolerance of junk; no account of filtering-as-defect-removal predicts a gain. [T1]
  • Selection dominates scale at a third pipeline stage, and the corpus being selected from can be machine-generated (new 2026-07-27). The map's principle was replicated at pretraining (15T tokens) and at supervised fine-tuning (1,000 examples) by two groups that do not cite each other. The third object is reinforcement-learning prompts — what a GRPO run consumes — from a third group, and the ranking holds. Filtering a generated prompt set is worth +4.2 points on a four-benchmark reasoning average (53.0 → 57.2) while shrinking the set; the authors' own summary is the rule to carry — "it is better to have less high-quality synthetic data than more lower-quality synthetic data." Filtering also lifts the weaker generator (plain Self-Instruct with reasoning-generated targets goes 49.5 → 53.6), so this is a property of the curation step rather than of one pipeline. Two findings underneath it. Generated prompts beat human ones, for prompts: unfiltered synthetic (53.9 on AlpacaEval 2 / Arena-Hard) beats filtered human WildChat (50.7) with the same student, judges and recipe — the first head-to-head on the map's oldest live tension, though not at matched cost, and about prompts rather than annotations, so Molmo's argument about human-sourced labels is untouched. And the best filter is not the obvious one: when a model builds a problem and solves it in the same reasoning pass, checking a later majority vote against that generation-time answer beats using the majority vote alone (57.2 vs 55.1), because the construction-time label came out of a trace that knew the intended solution. Design rule: generate the label with the item and keep it as an independent reference — a pipeline that labels afterwards has discarded its cheapest verification signal. [T1]
  • Quality and diversity are the levers; quantity saturates — and this now holds at both ends of the pipeline (new 2026-07-25). At fine-tuning scale, with everything else matched, the three variables separate cleanly: response-quality filtering is worth +0.50 (2,000 filtered Stack Exchange examples 3.83 vs 2,000 unfiltered 3.33), prompt diversity is worth +0.34 (heterogeneous Stack Exchange 3.83 vs equally-well-answered but homogeneous wikiHow 3.49), and scaling the example count 16× from 2K to 32K moves nothing at all (flat at ~3.8). The filters that earn the half point are unglamorous and specific — answer score ≥10, length between 1200 and 4096 characters, drop first-person or cross-referencing answers, strip links and images. Practitioner consequence, and the most directly actionable claim on this map: given a fixed curation budget, spend it filtering what you have and broadening the prompt distribution, not collecting more of the same. Scope condition added 2026-07-30: this holds at every compute budget a reader of this vault can reach, and the bullet above now says why — a fixed curation budget is the compute constraint that makes selection pay. What is no longer safe is the unstated premise that the ranking is a property of the data. [T1]
  • Alignment is format selection, not knowledge acquisition — which is why the small-data result is possible at all (new 2026-07-25). The Superficial Alignment Hypothesis: capabilities and knowledge are learned almost entirely in pretraining, and alignment teaches only which subdistribution of response formats to use. Its corollary survives testing — LLaMa 65B on 1,000 curated examples (~750,000 tokens), no RLHF and no reward model, is equal-or-preferred to GPT-4 in 43% of 300 head-to-heads, to Bard in 58%, to RLHF-trained DaVinci003 in 65%, and beats Alpaca-65B — the same base model trained on 52× more distilled data. The sharpest demonstration is multi-turn: a model trained on zero dialogue examples can converse at all, and 30 hand-written chains take excellent responses from 45.2% to 76.1%. Those are the numbers of a capability being invoked, not installed. [T1]
  • Data curation is an engineering variable you can ablate — not a trade secret. The way to know a filtering or dedup choice helps is to train identical proxy models on each data variant and read the downstream benchmark. FineWeb releases the corpus (15T tokens from 96 Common Crawl dumps), the processing code (datatrove), and the ablation models — the method made legible, not just the artifact. It beats other open pretraining corpora on downstream evals. [T1]
  • The intuitive moves are non-monotonic — more filtering/dedup is not always better. Aggressive global (cross-dump) deduplication can hurt: it strips so much that quality drops, and per-dump dedup wins because surviving across dumps is itself a weak quality signal. A default ("dedup as hard as possible") inverted by controlled evidence — exactly the shape this vault's status-moves-both-ways rule exists to catch. [T1]
  • A cheap learned quality filter can beat a much larger unfiltered corpus. A small classifier trained on LLM-rated "educational value" yields FineWeb-Edu (1.3T tokens) whose models show large gains on knowledge/reasoning benchmarks (MMLU, ARC) vs the unfiltered 15T set. Selection can matter more than scale. [T1]

  • 2026-08-01 — this map's central claim replicated from the reinforcement-learning side, by a group with no interest in data curation, from small-model-rl-failure-modes (T1, primary map post-training-rl): alignment-is-format-selection-not-knowledge-acquisition holds that capabilities and knowledge are acquired in pretraining and that alignment merely selects which subdistribution of response formats to use — LIMA's evidence being 1,000 curated examples on a 65B base beating the same base on 52× more distilled data. If that is right, a post-training stage should return nothing when the base has nothing to select among, and the return should scale with how much the base already does. That is exactly what is measured here, three orders of magnitude down: across fifteen configurations at 70M–500M, PPO's reward gain is a negative monotonic function of the SFT prior's perplexity on the target corpus, inflecting near PPL_SFT ≈ 20, with a significant regression in the one cell (Pythia-410M on Wikitext-103, PPL 25.4) that sits above it while a smaller model with a better prior improves. Neither paper cites the other; they are the same claim about where capability lives, argued from data at 65B and from RL at 400M. Two things for this map. It supplies a decision rule with the same shape as this map's own, and one that is cheap enough to actually run: if the SFT checkpoint's perplexity on your target corpus is high, the budget belongs in SFT data, not in preference optimization. And it is a reminder that this map's contested axis — what filtering is worth, and at what compute budget (bitter-lesson-for-data-filtering) — has a downstream twin nobody has connected to it: the point where more data stops paying and the point where post-training starts paying may be the same point, measured from opposite directions.   • 2026-07-28 — a downstream symptom that would follow from this map's 2026-07-27 finding, on the best-known synthetic-data models, from gsm-symbolic-limitations-mathematical-reasoning (T1, primary map evaluation-contamination). What it does is turn this map's newest worry into something falsifiable: generate a synthetic corpus from benchmark-adjacent seeds, then score the resulting model on templated variants of that benchmark — the missing dose-response experiment, run on the pipeline this map actually recommends. Also worth noting for the selection thread: the corpus that produced these models is exactly the "select don't collect" recipe, so the risk here is a cost of the map's central claim rather than an argument against it.

  • 2026-07-24 — counterpart edge from min-k-prob-detecting-pretraining-data (T1, primary map evaluation-contamination): decontamination has a supply side and a demand side, and this map only has the supply side. Open questions:

  • Does the filtering crossover exist for fine-tuning data? (new 2026-07-30, and it is now the map's sharpest missing datum, displacing the source-diversity question below because it decides whether the downgrade reaches practitioner scale at all.) The crossover is demonstrated for pretraining — the regime two of this map's three sources are not in. LIMA scaled 2K → 32K instruction examples within one source under one filter and found nothing; it never ran the many-epoch, deliberately-low-quality arm, which is exactly the arm that crosses over at 330M parameters in pretraining. The experiment: fix a 7B base, fix the example count, sweep filter aggressiveness × epochs, and look for the crossing. Cheap, and it would settle whether "filter what you have" survives at the scale this vault's readers work at or is merely undefeated there.
  • What does filtering cost, now that it has an expiry date? (sharpened 2026-07-30.) The map already held that nobody prices filtering — K extra generations per candidate in the synthetic case. That question is now paired with a second: the crossover framing means the honest comparison is filter-then-train versus train-longer-on-everything at matched total compute, and no source on this map reports the compute spent on curation alongside the compute spent on training. Until one does, "selection dominates scale" is a comparison with one side's bill missing.
  • Two sources now disagree about where fine-tuning data should come from, and neither settles it (new 2026-07-19). LLaVA manufactures it with a teacher; Molmo collects it from humans and reaches the top of an 11-benchmark suite doing so. But no source compares the two at matched cost, which is the only form the question takes for a practitioner: given a fixed budget, is teacher synthesis or collection design the better spend? Molmo proves feasibility, not superiority — and its protocol needs a 712k-image annotation operation most readers cannot run.
  • Synthetic-data generation has a source; synthetic-data filtering does not. RESOLVED 2026-07-27 (cot-self-instruct-synthetic-prompt-curation): the ablation instrument has been pointed at a generated corpus and filtering it is worth more than generating more of it. What replaces the gap is narrower and harder. Filtering is not cheap and nobody has priced it — both filters cost K extra generations per candidate, or K responses scored by a 70B reward model, and no compute accounting appears anywhere. That is not a footnote: it is the missing half of this map's longest-standing question, since "teacher synthesis versus human collection at matched cost" cannot be answered while one side's cost is unreported. And nobody has measured what share of a teacher's errors the student inherits — the original 2026-07-18 form of this gap — which filtering by answer-consistency addresses for verifiable targets and leaves entirely open for everything else.
  • Curating by generation carries a contamination mode that curating by filtering does not (new 2026-07-27). A pipeline that generates training data from public seeds is a paraphrase generator aimed at the benchmark distribution, whether or not that is the intent — public-training-corpora-carry-undetected-benchmark-rephrasings found 12.8% of HumanEval inside a Self-Instruct-generated instruction set, invisible to n-gram overlap. The detector that catches this class needs the training corpus, which a corpus builder has and a model consumer does not. So the practical question this map should now be asking is the one nobody has published: what does a decontamination step cost inside a synthetic-data loop, and does running one change the downstream numbers? Every synthetic-data result in-vault, including tonight's, reports no such step.
  • "More data doesn't help" is not yet established in the form a practitioner needs (new 2026-07-25). LIMA's quantity ablation scales 2K→32K examples sampled from Stack Exchange under one filter, so what it demonstrates is that more of the same distribution saturates. The move a practitioner actually makes is adding a different distribution — and this map's own diversity result predicts that would help. Those two findings are in tension at the boundary and nobody has run the experiment that separates them: hold example count fixed and vary the number of distinct sources. That is cheap, and it is now this map's sharpest missing datum.
  • The data lever just got more load-bearing. peft-methods went contested 2026-07-18: low-rank adaptation underperforms on genuinely new domains (low-rank-capacity-binds-when-the-domain-is-new). When the cheap adaptation lever binds, data quality is the remaining lever a practitioner controls — which raises the value of every unanswered question on this map.
  • Ablations are validated at small proxy scale; whether the ranking of curation choices holds at large-model training is assumed, not shown in-vault.
  • "Educational value" is an LLM-labeled proxy with its own biases; what it systematically excludes (and whether that narrows the model) is unmeasured.
  • Multilingual, code, and math data curation (FineWeb-2 and code-corpus work) are separate and not yet ingested.
  • The practical decontamination workflow for the craft loop (dedup your training set against your eval set, prove it) — FineWeb shows the supply side at pretraining scale; the fine-tuning- loop tool-doc version is still open (evaluation-contamination).
