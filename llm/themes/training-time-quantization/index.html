Status: consolidating Status note (2026-10-31, new angle, flagged — object mismatch with this strand's usual QAT/healing scope): a candidate mechanism for pretraining instability names finite-precision training arithmetic itself, not a deployment quantization format, as a cause — adjacent to this strand rather than inside it. quantization-induced-loss-spikes (T1, arXiv 2610.38277, Columbia University/MBZUAI/University of Maryland/Vector Institute; code released) traces a delayed, terminal class of pretraining loss spike ("time-bomb" spikes) to AdamW's preconditioning breaking a zero-sum structure in the LM head's cross-entropy gradient, letting the mean output embedding drift; under BF16 this harmless-in-exact-arithmetic drift amplifies the quantization error between BF16 and FP32 logits until the model's predicted token flips. A controlled precision sweep (28M params, 5 seeds) confirms the causal chain directly: BF16-true fails first, mixed precision later, FP32 stays stable. Replacing AdamW with SGD-with-momentum on the LM head only keeps the quantization error bounded and stays stable across the full learning-rate grid tested (162M, 404M params) where AdamW diverges or time-bombs at the largest rates. Graded open-question rather than folded into this strand's QAT/healing claims: this paper's object is training-time numerical precision causing a training instability, not a model being trained to tolerate a deployment quantization grid — whether or how the two interact is this vault's own open question, not the source's claim. All causal evidence is at 28M-404M params, far below frontier pretraining scale. Status does not move. Cross-linked to distributed-training (mixed-precision training mechanics is that map's territory). adamw-lm-head-drift-causes-delayed-quantization-driven-loss-spikes

Status note (2026-10-27): a different 2-bit reasoning-recovery recipe lands with no comparison to OnQ (2026-10-22), but its own ablation happens to supply this vault's first controlled, same-method, same-bit-width size comparison on a decoder-only LLM for the "small models quantize worse" question post-training-quantization has carried since 2026-07-31. thinkbit-two-bit-quantization-preserves-reasoning (T1, arXiv 2610.34886, Microsoft Applied Sciences Group) tiers each layer's precision by sensitivity, searches codewords with Gumbel-softmax, recalibrates scales against a distillation loss, runs a short QAT stage on reasoning traces, and selects the final checkpoint by a paired significance test on held-out MATH problems rather than by loss. This vault's "small models quantize worse" thread previously rested on a ~150M CLIP encoder and a 2B vision-language model; this is the first decoder-only-LLM instance, in the same direction. Status note (2026-10-23): holds consolidating, and the strand's "train into the deployment format" claim extends to a structurally different format family — lattice vector quantization — for the first time, with the training-time cost that kept VQ-QAT small-scale shown to be an engineering problem rather than a fundamental one. squat-spherical-lattice-vq-qat (T1, arXiv 2610.31412) splits each weight block into a unit-norm direction (quantized on a spherical E8-derived lattice codebook) and a scalar magnitude (quantized separately, its own straight-through estimator), and makes the per-step nearest-neighbor codeword assignment — the cost that had kept VQ-QAT off this strand entirely — nearly free via a distributed exact-search scheme exchanging only integer indices across workers, cutting LLaMA-3.2-1B training time from 62.5 to 4.9 seconds/iteration (12.8x), close to plain BF16's 4.3 s/it. At 2.25 bits/weight and 10B training tokens, SQuAT matches or beats scalar INT-QAT on perplexity and most downstream metrics across LLaMA-3.2-1B/3B and Qwen3-4B (Qwen3-4B MMLU: 69.5 vs. INT-QAT's 67.8, both from a 54.2 post-training-quantization starting point). squat-spherical-vq-qat-scales-to-billion-parameter-llms. This is the first entry on this strand whose format is not scalar/integer or floating-point — it extends "train into the format" to vector quantization specifically, a format family this map's parent (post-training-quantization) already tracks at post-training scale (QuIP#, QTIP) but that had never been trained into from the start at this strand's scale. Status does not move: 1-4B parameters, up to 10B training tokens — an order of magnitude below the 60-120B scale this strand's healing and NVFP4-at-MoE-scale sources use — no absolute GPU-hour figure, no code/weight release confirmed in this read.

Status note (2026-10-21, cross-link): this strand's ultra-low-bit object gets its first direct interaction with speculative-decoding's decode-cost lever, and the two don't stack for free. bitmtp-low-bit-multi-token-prediction (T1, arXiv 2610.28500, NeurIPS 2026, code released) finds that a ~1.58-bit (BitNet-class) backbone and multi-token-prediction drafting, naively combined, fail to produce a decode speedup at comparable quality — the low-bit backbone's output distribution interacts with drafting's acceptance mechanics in a way that erases the expected gain. Status note (2026-10-08): holds consolidating, and the strand's on-policy-recovery claim gets a second, independent test in a QAT-from-scratch setting rather than post-hoc QAD — repeating cleanly at the higher of two tested bit-widths and nearly vanishing at the lower one, which is exactly the regime the strand's name promises most. onlineqat-on-policy-distillation-ultra-low-bit (T1, arXiv 2610.09346, Hong Kong Polytechnic University / Sun Yat-sen University) adds an on-policy reverse-KL recovery stage — sampled on the quantized student's own rollouts, scored against a frozen full-precision teacher — after block-wise QAT. Graded extends against on-policy-recovery-doubles-low-bit-reasoning-retention — same mechanism (train against self-visited states, not fixed text), different pipeline stage (QAT, not post-hoc QAD) — and it narrows rather than contradicts: the existing entry's headline doubling ran at 2.79/1.88 effective bits across four models; this paper is weakest at its own lowest bit-width, on one model. Status note (2026-09-30): holds consolidating, and the strand gets a result one level below every existing entry: native FP8 training wasn't just a precision-vs-quality tradeoff, it had a specific numerical bug that gets worse with scale. delta-matching-native-fp8-attention-training (T1, MIT/Song Han group, arXiv 2609.37852) traces naive FP8 attention training's failures to a stale backward-pass delta that violates the softmax gradient's zero-row-sum invariant, causing selective channel amplification that compounds with model size and training length: mild at 569M parameters, a 0.48-point validation-loss gap at 1.67B, and outright collapse at 5.29B (1.93 vs. a 1.33 reference). Delta-Matching restores the invariant with a closed-form correction, matching BF16/FP32 loss and downstream accuracy at every scale tested (RULER-4K 61.4% vs. 24.8% for the stale-delta baseline), with no architecture changes. delta-matching-fixes-native-fp8-attention-trainings-stale-delta. This is a new object for the strand — every existing entry here recovers or heals a checkpoint that was trained some other way first; this is about training natively in FP8 from the start — but the same shape of finding as the strand's core claim: training into the deployment format works, and the failure modes of doing it wrong get worse as you push further (more scale, more steps), not staying fixed. Status does not move: tested only to 5.29B parameters, no evidence at the 60-120B scale this strand's healing sources use; code/models announced but not yet released.

Status note (2026-09-28): holds consolidating, and the strand gets its first result on the specific failure mode that made "training into the format" worth doing in the first place — not just recovering accuracy, but recovering the ability to finish a long generation at all. on-policy-distillation-low-bit-reasoning (T1, arXiv 2609.26708) shows quantization-aware distillation (QAD) recovers short-form QA well below three bits (82% average BF16 retention across four models) but leaves reasoning badly broken (35% average MATH-500 retention), traced to quantization-amplified exposure bias: QAD trains on fixed corpus prefixes while the quantized model's own errors compound along the trajectories it actually generates at deployment. An on-policy distillation (OPD) stage — sample through the deployment-quantized path, get frozen full-precision teacher feedback plus verifier rewards on the student's own prefixes — raises MATH-500 retention to 70% and HumanEval to 91%, at 14-23x fewer GPU-hours than the QAD stage it follows, and beats continued teacher-forced QAD in all 16 matched-budget comparisons run. on-policy-recovery-doubles-low-bit-reasoning-retention. This is squarely this strand's territory — the object under study is what the model is trained against during/after the quantization step, extending the existing teacher-choice and curve-shape findings to a training method (on-policy rollouts) rather than a static corpus. It also narrows, without closing, the map's standing "nothing measured on a consumer card" gap: the four recovery targets (Qwen3-0.6B/1.7B/4B, Falcon3-1B) are consumer-card-sized for inference, though the recovery training itself ran on an unspecified 8-GPU setup, not confirmed single-card hardware. Status does not move: single preprint, no independent replication, GPU hardware for training unstated.

What we believe now:

  • A different 2-bit reasoning-recovery recipe (sensitivity-tiered codeword search, distillation- recalibrated scales, a short QAT stage on reasoning traces, checkpoint selection by a paired significance test rather than loss) shows the reasoning-retention gap from BF16 shrinking roughly 7x in points lost as model size goes from 1.7B to 14B, under the identical method and bit-width — this vault's first decoder-only-LLM data point for post-training-quantization's "small models quantize worse" question (new 2026-10-27). Qwen3-1.7B: MATH-500 73.0 vs. 91.2 BF16 (-18.2), beating EfficientQAT (30.0) and every published 2-bit GGUF. Qwen3-14B: 94.8 vs. 97.5 BF16 (-2.7), same recipe. [T1, strong; Microsoft Applied Sciences Group; two sizes in one family, not a scaling-law sweep; no code/weights release yet; no head-to-head against this strand's own OnQ recipe] thinkbit-2bit-reasoning-gap-shrinks-7x-from-1-7b-to-14b
  • "Train into the deployment format" now covers vector quantization, not just scalar/integer and floating-point grids — and the per-step cost that kept VQ-QAT small-scale was an engineering bottleneck, not a fundamental one (new 2026-10-23). Splitting each weight block into a direction (spherical E8-derived lattice codebook) and a magnitude (separate scalar quantizer), each with its own straight-through estimator, plus a distributed exact nearest-neighbor assignment scheme that exchanges only integer indices across workers, cuts training time 12.8x per iteration and scales VQ-QAT to 10B training tokens on 1-4B-parameter models for the first time. Matches or beats scalar INT-QAT at 2.25 bits/weight (Qwen3-4B MMLU 69.5 vs. 67.8, both from a 54.2 PTQ starting point). [T1, strong, extends to a new format family; 1-4B parameters only, an order of magnitude below this strand's 60-120B-scale sources; no absolute GPU-hour figure or code release confirmed] squat-spherical-vq-qat-scales-to-billion-parameter-llms
  • The W2A16 on-policy-recovery weakness looks fixable by loss design, not a hard bit-width ceiling: a candidate-wise Dynamic KL loss (weighting forward/reverse KL per-token by the teacher/student probability ratio) on the quantized student's own rollouts beats every tested baseline on every benchmark at every size, at 2-bit precision (new 2026-10-22). OnQ diagnoses two failure modes in fixed-response QAT recovery — trajectory divergence (training prefixes unlike the student's own generated prefixes, worse at length) and distributional misalignment (under/over-predicting next-token candidates, worse at high-entropy points) — and fixes both with on-policy distillation plus Dynamic KL. Across Qwen3-1.7B/4B/8B at 2- and 3-bit, OnQ wins the nine-benchmark average at every size; at 2-bit it beats every baseline on every benchmark at every size, improving the Qwen3-8B average by 10.26 points over the strongest baseline, with shorter responses and fewer truncation/repetition failures. [T1, strong; Qwen3 family only, no code/weight release stated, no isolation of Dynamic KL from on-policy distillation itself] onq-dynamic-kl-closes-2bit-reasoning-gap
  • An ultra-low-bit (~1.58-bit) backbone and multi-token-prediction drafting don't compose for free — bolting MTP onto a BitNet-class model doesn't produce a decode speedup at comparable quality without a co-designed hybrid decoder (new 2026-10-21). BitMTP trains a single model to do both ordinary autoregressive generation and block-causal multi-token drafting, exposing confidence-only, speculative-only, and hybrid decoding modes; hybrid dominates. Five-task mean 2.2x (BitNet b1.58-2B) and 2.1-2.4x (Bonsai 1.7B-4B) decode speedup on an H20 at comparable quality, up to 2.0x on an RTX 3090, 3.3x on MBPP+ on a Jetson Orin. First in-vault source crossing this strand and speculative-decoding at the mechanism level. [T1, strong; NeurIPS 2026, code released; backbones trained natively at ultra-low bit-width only, not post-training-quantized] bitmtp-hybrid-decoding-composes-ultra-low-bit-with-mtp
  • Native 4-bit (NVFP4) pretraining works at dense-8B and 30B-A3B-MoE scale to 1T tokens, but needs depth-wise precision placement, not just a better backward-pass estimator, to avoid diverging (new 2026-10-20). An unbiased gradient estimator (MS-EDEN) on backward-pass tensors is necessary but not sufficient: quantizing every layer diverges the 8B dense run past 300B tokens, and the final recipe keeps the last 15% of layers in BF16, reaching under 1.2%/0.81% relative training-loss gap to BF16 (8B dense/30B-A3B MoE) — the strongest published FP4 training result at this scale, by the authors' own claim. With the BF16 tail in place, the choice of backward-tensor de-biasing technique underneath makes only a small further difference. [T1, strong, extends to a harder format and MoE scale; no absolute pre-recipe baseline or compute-cost figure stated; no code/checkpoint release stated] nvfp4-pretraining-recipe-needs-a-bf16-tail-to-avoid-divergence
  • On-policy recovery's benefit on this strand's own showcase technique shrinks as bit-width falls, in a QAT-from-scratch setting as well as the post-hoc QAD setting that established it (new 2026-10-08). Adding a self-rollout reverse-KL recovery stage after block-wise QAT beats fixed-completion recovery by 2.90 points average at W3A16 (Qwen3-1.7B, 57.28 vs. 54.38) but only 0.44 points at W2A16 (32.52 vs. 32.08), trailing the baseline on three of six benchmarks at the lower bit-width. [T1, suggestive] online-distillation-on-student-rollouts-recovers-ultra-low-bit-qat-modestly
  • Native FP8 training's apparent precision-quality tradeoff was partly a numerical bug, and fixing it restores BF16-matching loss and accuracy at every scale tested (new 2026-09-30). A naive FP8 attention backward pass computes its delta term from stale, already-quantized values, breaking the softmax gradient's zero-row-sum invariant; the resulting channel-amplification error is mild at 569M parameters but collapses training at 5.29B (validation loss 1.93 vs. a 1.33 reference). Delta-Matching's closed-form correction restores the invariant exactly, matching the BF16/FP32 reference at every scale from 569M to 5.29B parameters with no architecture changes, and holding RULER-4K at 61.4% against the broken baseline's 24.8%. [T1, strong] delta-matching-fixes-native-fp8-attention-trainings-stale-delta
  • Quantization-aware distillation's short-form/reasoning gap is a training-distribution problem, and training the student on its own quantized rollouts (not just fixed corpus text) closes most of it at a fraction of the original recovery cost (new 2026-09-28). Below three bits, QAD alone leaves reasoning at 35% average BF16 retention (MATH-500) against 82% for short-form QA, because supervision on fixed prefixes never exposes the student to the states its own quantization errors put it in at deployment. A follow-on on-policy distillation stage — teacher feedback and verifier rewards scored on the student's own quantized-path generations — lifts MATH-500 retention to 70% and HumanEval to 91%, for 14-23x fewer GPU-hours than the QAD stage it builds on, across four models (Qwen3-0.6B/1.7B/4B, Falcon3-1B) at 2.79 and 1.88 effective bits. [T1, strong] on-policy-recovery-doubles-low-bit-reasoning-retention
  • Train into the deployment format rather than converting into it, and the advantage widens as bits fall. Below roughly three bits this stops being an advantage and becomes the difference between a model and rubble: on Llama 3.2 11B Vision at ~2.7 bits per weight, a rate-matched uniform integer grid under GPTQ scores 0.018 average across four visual-QA benchmarks, the same rate under a vector format scores 0.340, and the same format under quantization-aware training scores 0.661 — a 37× spread at one bit budget. Format and procedure do not decompose into separable levers here; the format decides whether there is enough representable structure for the procedure to train into. [T1, strong] below-three-bits-the-quantization-procedure-outweighs-the-format, training-into-the-deployment-format-beats-choosing-a-better-one, quantization-can-be-a-training-decision-not-a-post-hoc-one, the-four-bit-penalty-is-a-training-decision-you-can-decline
  • The teacher is a free variable, and in a multi-step compression pipeline the obvious choice is the worst one. Under compound compression — a structural step then a quantization step — the intermediate full-precision checkpoint was never independently trained: it is a distillation-recovered approximation carrying the compressed architecture's ceiling. Supervising the quantized student from it caps the student there. Supervise from the original uncompressed model instead — architectures need not match, since distillation only needs logits — and the 4-bit artifact matches or beats the bfloat16 checkpoint it was quantized from on 7 of 9 benchmarks (AA-LCR +7.4, AIME 2025 +5.6) at roughly 4× less weight memory, matching the uncompressed teacher on LiveCodeBench at half its parameter count. The quantization step is a second pass of teacher supervision, not lossy postprocessing. Held down hard: the decisive head-to-head against distilling from the recovered checkpoint was never run. [T1, single-study] the-quantization-step-is-a-second-training-opportunity, distil-from-the-original-not-from-the-recovered-checkpoint
  • Choose the recovery recipe on the shape of its curve, not on its peak. Two healing recipes reaching 54.9 and 54.6 are indistinguishable on a benchmark table and not remotely equivalent in a release process: a KL objective against a frozen teacher peaks in ~100 steps and stays within about two points of that peak for the next 1,100, while a cross-entropy objective takes ~700 steps to an equal peak and then loses nearly 19 points by step 1,200. One can be run to convergence and shipped; the other requires correctly-tuned early stopping against a held-out signal or the artifact that leaves the building is post-collapse. [T1, single-study] a-kl-objective-can-be-run-to-convergence-a-task-loss-cannot
  • Some tensors must not be trained while the rest of the model is quantized. Unfreezing layer norms and embedding projections during the quantization stage — especially at higher learning rates — produced checkpoints worse than the unhealed quantized model, across an eleven-configuration sweep and under both objectives tested. Freeze embeddings, norms and selected attention components. The failure is cliff-shaped rather than graded, which is exactly the regime in which a stopping rule is a liability. [T1, suggestive] freeze-quantization-sensitive-submodules-during-healing
  • The training run has its own budget, and it is the reason this strand is not free. Quantization-aware work costs a training pass the post-hoc path does not, and long-context healing is memory-bound: the naive distillation loss materializes a [B,L,V] log-softmax whose peak memory is prohibitive at 32k context with a ~200k vocabulary. Cached offline top-K teacher logits plus a fused chunked KL reduce that to linear in sequence length while staying bit-identical to the dense loss, which is what lets long-context healing fit the same hardware as short-context training. [T1, suggestive] the-quantization-run-has-its-own-memory-budget, caching-the-teachers-top-k-logits-removes-the-teacher-from-memory, the-kl-loss-not-the-model-caps-distillation-context-length
  • Where the strand shades into adaptation, initialization is the cheap version of the same idea. A quantization-aware initialization for a low-rank adapter extends usable fine-tuning below the 4-bit floor without a full training-time quantizer, and offline recovery can be bought without touching the serving kernel at all. These are the low-cost rungs of the same ladder and they belong to peft-methods as much as here. Open questions:

  • Does finite-precision training arithmetic (BF16-vs-FP32 logit drift in the LM head) interact with, predict, or stand entirely apart from this strand's deployment-quantization-tolerance findings? (new 2026-10-31.) quantization-induced-loss-spikes traces a delayed pretraining loss-spike class to AdamW breaking a zero-sum structure in the LM head gradient, amplified into a spike by BF16 quantization error — a training-stability mechanism, not a QAT recipe. Whether a model trained with this paper's SGD-M LM-head fix quantizes differently post-hoc, or whether this strand's existing QAT recipes already sidestep the mechanism by construction, is untested by either literature; nobody has run the controlled pairing (same base recipe, with and without the LM-head fix, then post-training quantized) that would say. adamw-lm-head-drift-causes-delayed-quantization-driven-loss-spikes
  • Is the W2A16 weakness in on-policy QAT recovery a quantization ceiling, a reverse-KL limitation, or a token-selection problem? (new 2026-10-09, cross-linked from distillation-small-models; narrowed 2026-10-22, not closed.) online-distillation-on-student-rollouts-recovers-ultra-low-bit-qat-modestly's plain reverse-KL recovery stage nearly vanishes at W2A16; dial-opd-logarithmic-mean-weighting-beats-reward-magnitude-token-selection shows, in a different (non-quantization) on-policy-distillation setting, that which tokens of a rollout carry the training signal matters as much as which divergence is used. onq-dynamic-kl-closes-2bit-reasoning-gap now shows a different loss design — candidate-wise Dynamic KL rather than plain reverse-KL — winning cleanly at 2-bit, which favors the token-selection/loss-design explanation over a hard quantization ceiling. Still open: neither paper runs the controlled ablation (same recipe, swap only the loss term) that would isolate which specific change (on-policy rollouts, Dynamic KL weighting, or their combination) is doing the work.
  • Does precision-masking of weight deltas affect how this strand's own results are read? (new 2026-10-02, cross-linked from distillation-small-models.) multi-teacher-on-policy-distillation-mechanisms finds that on a Qwen3-1.7B student, ~97% of parameters move from initialization in FP32 but only 7-11% differ after BF16 rounding — most of a training run's real signal is invisible at the precision it's typically evaluated in. This strand's own results (on-policy recovery, native-FP8 training, healing curves) are reported at BF16/FP8 without a parallel FP32 delta check; whether any of this strand's effect sizes would read differently measured in full precision is unchecked.
  • The comparison that decides this map's strongest claim has never been run. Quantization-aware healing is argued to beat quantization-aware distillation-from-the-recovered-checkpoint because the recovered checkpoint carries a ceiling. That is an argument about how the checkpoint was produced, and the head-to-head at matched configuration is one training run. Until somebody runs it, "the 4-bit artifact can beat its 16-bit source" is a demonstration attached to a motivation.
  • Does the teacher-choice result survive a non-proprietary compression operator? The only demonstration uses a proprietary tensor-network operator. The claim is operator-agnostic in principle — it needs only logit access — but layer pruning, SliceGPT and low-rank decomposition produce differently-damaged students, and nothing says the recovered-teacher ceiling is the same height in each.
  • Nothing in this strand has been measured on a consumer card, which is the axis this vault exists on. The healing runs are 8×H200; the sub-3-bit VLM pipeline's QAT compute is unreported. The two questions a practitioner has — can a quantization-aware run be done on one or two consumer GPUs for a model small enough to serve on them, and does the sub-3-bit gap over post-hoc quantization hold at 3B–8B — are both open and both cheap for somebody with the hardware. Narrowed 2026-09-28, not closed: on-policy-recovery-doubles-low-bit-reasoning-retention recovers reasoning on 0.6B–4B targets — models sized for a single consumer card at inference — but the recovery training itself ran on an unspecified 8-GPU setup, so the training-side half of this question is still open.
  • How does the curve-shape finding interact with the stopping rules the rest of the field uses? The claim that a KL objective can be run to convergence while a task loss cannot is one pipeline, one format, single-run. If it generalizes it deletes a whole class of operational risk; if it is an artifact of MXFP4 or of this data mixture, the field's early-stopping practice is correct and this map is over-reading a training curve.
  • Is there a bit-width below which training-time quantization also fails? The 37× spread at 2.7 bits is the strand's most dramatic number and it is one point on a curve. Nobody has published the equivalent sweep at 2 bits and 1.58 bits with the procedure and the format each held fixed in turn, which is the experiment that would say whether "train into it" has a floor of its own.
  • Does ThinkBit's size effect (2.7-point gap at 14B vs. 18.2-point gap at 1.7B, same recipe, same bit-width) hold at more than two sizes, and does it replicate under this strand's own OnQ recipe? (new 2026-10-27.) ThinkBit's comparison is incidental to its own paper and rests on two checkpoints in one family (Qwen3). post-training-quantization's "small models quantize worse" thread has asked for exactly this sweep (one model family, four-or-more sizes, one quantizer, one benchmark suite) since 2026-08-02 without a decoder-only-LLM data point; running OnQ's own recipe at the same two Qwen3 sizes would say whether the shrinking gap is a property of 2-bit quantization generally or of ThinkBit's specific codeword-search-plus-recalibration method. thinkbit-2bit-reasoning-gap-shrinks-7x-from-1-7b-to-14b, onq-dynamic-kl-closes-2bit-reasoning-gap
