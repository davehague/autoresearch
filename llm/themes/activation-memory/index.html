Activation memory (checkpointing, recomputation, activation offload) — map

Forked 2026-08-02 (auto run) from distributed-training, which reached the fork condition (18 dated bullets, 6 declared sub-threads) and had been carrying a strand that is not about distribution at all. Every other axis on the parent map answers "the model, its gradients or its optimizer state will not fit on one device — how do I spread them across several?" This one answers a question a practitioner with exactly one card still has: activations scale with batch size and sequence length rather than with parameter count, so no amount of sharding, tensor parallelism or optimizer offload touches them. The parent map's own cross-cutting note says it plainly — this is the memory technique PEFT cannot delete, because every other lever attacks a term proportional to trainable parameters. The vault's premise is one or two consumer cards, which makes this the strand its readers reach for first and the parent's five other strands the ones they never reach at all. Status: consolidating Status note (2026-08-02, at forking): consolidating, carried over from the parent rather than re-derived. Four independent sources across three evidence types converge: a 2016 T1 supplying the cost model and the exactness proof, a 2026 T1 supplying the measured interior optimum on real fine-tunes with watt-hours, and two unrelated maintainer teams' official documentation (torchtune, Axolotl) independently agreeing on the constraint that activation offload requires checkpointing. That last pair is the T2-practice half of this vault's own consensus test, and it is the reason this strand can stand alone. What keeps it below consensus is that the two halves of the evidence do not overlap: the theory is a 2016 CNN/RNN result on a Titan X with not a transformer in the paper, and the measurement is 21–32M-parameter vision backbones on 32×32 images with no decoder-only model, no 4-bit base and no long sequence. The transformer case at a realistic sequence length is argued from both ends and measured from neither.

Sub-threads: none — one lever (trade compute for activation memory) with one policy question (where on its continuum to sit) and one rider (offload, which is defined over the checkpointed set); the tooling findings characterize the same lever rather than a second one [reviewed 2026-08-02 @ 4 bullets]

What we believe now:

  • Activation memory is a continuum with a budgeted search on it, not the boolean every framework ships. The cost model is O(n/k) + O(k), minimized at k = sqrt(n) for one extra forward pass, extending to O(log n) memory for O(n log n) compute, and the original method searches a memory budget rather than flipping a switch. Measured: 48 GB → under 7 GB for a 1,000-layer ResNet, >4× below an already in-place-and-sharing-optimized plan for a 1,024-step LSTM, both at ~30% runtime. Liveness analysis alone is worth 2–3× and stays linear. Note where the gain was largest — the long-sequence case, not the deep one, which is the regime that binds once context-length-is-a-cheap-post-hoc-edit-not-a-pretraining-property makes long windows cheap to acquire. Caveats are heavy and structural: 2016, ResNet and LSTM, MXNet, a Titan X — not a transformer in the paper; the 30% figure does not transfer unexamined to a block whose attention op already recomputes its largest intermediate; memory counts feature maps only. [T1] See activation-memory-is-a-tunable-continuum-not-a-fixed-cost, rematerialization-trades-compute-for-the-activation-memory-nothing-else-shrinks.
  • This is the only exact memory lever in the vault, which is why it is the one to spend first. Every transformation in the original method "gives equivalent weight gradient for training and can always be safely applied" — it changes when a value is computed, never what it is. Set against the alternatives, that is a ranking rather than a footnote: sharded optimizer math is silently inexact by its own authors' statement and measured by nobody, and asynchronous pipelining is deliberately inexact. Practitioner ordering: turn on recomputation before anything that changes the arithmetic, and note that a results table mixing a checkpointed run with an unsharded one is comparable while one mixing ZeRO-3 with local training is not. [T1] See recomputation-is-the-one-memory-technique-that-is-exact.
  • The interior optimum is real and measured, and the boolean is not at it. A threshold-triggered cascading policy cuts peak memory 43–79% at 9–30% energy overhead, where checkpointing every layer buys comparable memory for 17–44% — with the threshold converging to τ = 0.5 independently on three backbones. It pays only where per-layer activation cost is roughly uniform, which decoder-only stacks are and hybrid vision stems are not. The same study lands the correction this strand's parent needed: "PEFT saves memory" is not a property of PEFT — BitFit peaks at 2.6× LoRA's memory on TinyViT at matched batch size, because trainable parameters in the earliest layers keep the entire activation stack alive. Placement is a memory decision, the same variable where-the-adapter-budget-goes-matters-more-than-how-much-there-is found worth accuracy points at fixed budget, and nothing in the tooling reports it. Scope is heavy: 21–32M-parameter vision backbones on 32×32 images, no decoder-only model, no 4-bit base, no long sequence. [T1, one study] See adaptive-checkpointing-beats-the-boolean-at-a-measured-price, peft-does-not-reliably-reduce-peak-memory.
  • The tooling exposes a different parameterization than the papers, and one constraint the papers never state. Two unrelated maintainer teams agree: activation offload is a rider on checkpointing, not an alternative to it — both frameworks require checkpointing before offload can be enabled, because offload operates on the tensors checkpointing decided to keep. So the obvious 2×2 experiment has three reachable cells, not four, and offload's apparent cheapness is partly an artifact of moving the already-reduced subset. On granularity, Axolotl ships selective_checkpointing.save: [attention] — an op list, not a block count, which is arguably the better parameterization since ops differ enormously in recompute cost per byte saved — but saving matmul ops is rejected in LoRA/QLoRA runs because of in-place mutations, so the most obviously worth-saving op class is unavailable in exactly this vault's regime. And PEFT does not only delete memory axes: layer_offloading streams frozen decoder layers, a lever on the model term that a full fine-tune cannot have — that finding moved to memory-hierarchy-offload on 2026-08-03, where the demotion axis now lives, since it streams parameters rather than activations and belongs with the tier it uses. Neither doc reports a single measured number. [T2 ×2, independent maintainer teams] See activation-offload-is-a-rider-on-checkpointing-not-an-alternative, checkpointing-granularity-ships-as-a-selective-op-list, frozen-weights-can-be-streamed-which-is-a-peft-only-memory-axis.

Through-line (newest first):

  • 2026-08-18 — nanbeige-looped-transformer-apple-silicon (T1, UW; primary map local-inference): the first architecture on this map whose selling point is parameter efficiency, and it pays for that entirely in this map's currency. A Looped Transformer feeds hidden states through all L physical layers and then re-feeds them through the same L again — 2L effective layer-executions from L layers of weights, the parameter-count version of the compute-for-memory trade this map is built on. The bill: prefill peak activation is dominated by materializing an O(prompt_len²) attention-score tensor per layer pass, and the loop performs that pass twice, so peak prefill memory doubles against a non-looped model of the same parameter count. On a dedicated accelerator that is noise; on Apple Silicon's unified memory, shared with the OS and with no CUDA-style page-out path to demote to, it is binding — naive prefill of Nanbeige4.2-3B in bf16 on a 32 GiB M2 Max cannot process an 8,192-token prompt at batch 1, so a model chosen because 3B fits on a laptop cannot read a prompt long enough for the agentic work it was trained for. The sizing rule this yields is concrete and this map did not have it: budget the activation term at the architecture's effective depth, not its physical depth, and check it at the context length you intend to use rather than the one in the model card. Nothing in that card warns you (weight-sharing-across-a-loop-doubles-prefill-activation-memory). The mitigation is chunked prefill, which bounds the score tensor independent of prompt length and buys 4,096 → 11,231 usable tokens for 22.8–40.9% throughput, bit-identical (chunked-prefill-converts-a-memory-ceiling-into-a-throughput-tax) — an instance of this map's own lever (trade compute for activation memory) applied at inference rather than in training, which is where every prior source here operated.

Open questions:

  • The standing experiment, inherited and still the cheapest useful run in the vault (carried from the parent, last revised 2026-07-29). Peak memory and step time for a 4-bit LoRA fine-tune at a realistic sequence length, with and without gradient checkpointing, with and without CPU activation offload, at more than one granularity. Three specifications the tool docs added: the grid is three cells, not four (offload is defined over the checkpointed set); granularity should be expressed as the tooling exposes it — selective_checkpointing.save, an op list — with the note that matmul saving is rejected under LoRA/QLoRA; and a fourth arm now exists that did not before, layer_offloading on/off, streaming the frozen 4-bit base. Everything needed is public and it is a few GPU-hours. It has been open since 2026-07-24 and is the reason this strand is consolidating rather than higher.
  • Does the transformer double-count the win? (new as a standalone question 2026-08-02.) Attention has recomputed its largest intermediate since FlashAttention, so some of recomputation's headline saving may already be banked by the kernel. The 2016 cost model and the ~30% runtime figure both predate that, and no source in this vault has measured checkpointing's marginal benefit on top of a FlashAttention-class kernel. If the answer is "most of it," the interior-optimum result changes shape — the curve to search is flatter than the theory says, and the boolean everyone ships costs less than this map has been implying.
  • Is the interior optimum a decoder-only result? The measured τ = 0.5 convergence comes from 21–32M vision backbones on 32×32 images, and the study itself says the policy pays only where per-layer activation cost is roughly uniform. Decoder-only stacks are uniform, which is the encouraging read — but nobody has run the threshold policy on one, at a sequence length where activation memory actually dominates, and the uniformity argument predicts the optimum should move with sequence length in a way a fixed τ cannot express.
  • Nobody reports adapter placement's memory cost alongside its accuracy (shared with peft-methods). Two sources have now measured the same variable on different axes — 10.7 accuracy points at fixed budget on one side, a 2.6× peak-memory inversion at matched batch size on the other — and neither cites the other. One adapter budget, several placements, accuracy and peak memory in the same table is what a practitioner choosing target_modules on one card actually needs, and it costs a handful of short runs.
