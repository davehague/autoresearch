What we believe now:

  • The checkpointing dial has an interior optimum, and "PEFT saves memory" is not a property of PEFT (new 2026-07-31, and the map's first measured numbers on either point). A threshold-triggered checkpointing policy cuts peak memory 43–79% at 9–30% energy overhead against 17–44% for checkpointing every layer, with the threshold converging to τ = 0.5 independently on three backbones — so the continuum this map has argued from theory since 2026-07-26 has a measured interior optimum, and the boolean every framework ships is not at it. It pays only where per-layer activation cost is roughly uniform, which decoder-only stacks are and hybrid vision stems are not. The second half is the correction: this map's organizing inference — PEFT deletes trainable-parameter-scaled terms and leaves activations standing — is right about terms and wrong about totals. BitFit peaks at 2.6× LoRA's memory on TinyViT at matched batch size, because trainable parameters in the earliest layers keep the entire activation stack alive. Placement is a memory decision, the same variable where-the-adapter-budget-goes-matters-more-than-how-much-there-is found worth 10.7 accuracy points at fixed budget, and nothing in the tooling reports it. Scope, and it is heavy: 21–32M-parameter vision backbones on 32×32 images, no decoder-only model, no 4-bit base, no long sequence. [T1, one study]
  • The tooling has now been read, and it corrects this map in three places (new 2026-07-29 — the vault's first official tool documentation sources, torchtune and Axolotl, two unrelated maintainer teams). Every other source in this map is a paper arguing one axis; a doc reports what shipped, which under this vault's own evidence model is the T2-practice half of the consensus test the vault has never been able to run. Three corrections, one of them against a complaint this map made. (1) Activation offloading is a rider on activation checkpointing, not an alternative to it. Both frameworks require checkpointing before offloading can be enabled, because offloading operates on the tensors checkpointing decided to keep. So the standing experiment's 2×2 grid has three reachable cells, not four, and the real question is not which activation lever but how far down the hierarchy the surviving activations go — VRAM, host RAM, or (Axolotl's activation_offloading: disk) storage. It also explains why ZeRO-Infinity's "under 2 GB/s" activation-offload figure looked suspiciously cheap: it is moving the already-reduced checkpointed subset, not the activation stack. (2) The granularity dial this map said nobody exposes is exposed, in a better shape than the paper's. The 2026-07-26 complaint was that "the framework flag everyone uses fixes k = number of blocks, a single point on a curve." Axolotl ships selective_checkpointing.save: [attention] — choose which operations are cheap enough to store rather than how many blocks to segment, which exploits the fact that ops differ enormously in recompute-cost per byte-saved where k treats them as uniform. The complaint retires; what replaces it is that nobody has published the curve in either parameterization. (3) The host side of offload is priced, and it is expensive. CPUOffloadOptimizer costs 4× the model size in system RAM and forces gradient_accumulation_steps=1 — so on a 32–64 GB desktop an 8B model's offloaded state alone is ~32 GB, and the technique that makes the model fit simultaneously removes the mechanism that made a batch-size-1 run tolerable. [T2, two independent tool docs]
  • PEFT does not only delete memory axes — it opens one (new 2026-07-29). This map's organizing inference is that the axes attacking trainable-parameter-scaled terms are the ones PEFT renders moot, leaving re-materialization standing. Axolotl's layer_offloading is the case that argument has no slot for: it streams frozen decoder-layer parameters between CPU and GPU one layer at a time, and is documented as "best suited for LoRA/QLoRA where most parameters are frozen." A full fine-tune has no frozen weights to stream. So shrinking the trainable set turns the resident base into a large, read-only, sequentially-accessed object — the friendliest possible pattern for a prefetcher — and creates a lever on the model term rather than the activation term. Whether it is affordable is exactly offload-efficiency-is-a-bandwidth-arithmetic-intensity-problem's question, unanswered by the doc; the vault's prediction is that naive streaming is bandwidth-bound at batch size 1 and the winning implementation will look like the MoE expert-offload literature (cache + prefetch one layer ahead), except easier, because a dense stack's access order is deterministic where a router's is not. [T2]
  • Not all of these axes are memory axes, and the map mis-filed one of them (new 2026-07-26). The organizing question has been which memory term do you attack?, and PipeDream shows that pipelining was never primarily an answer to it. Its motivation is bandwidth: data-parallel BSP all-reduces every parameter every step, which the paper measures at 70–90% of total training time for VGG16, AlexNet and S2VT, and stage-partitioning ships one layer's activations instead — up to 95% less traffic, up to 5× faster time-to-target-accuracy. It costs memory rather than saving it (one stashed weight version plus intermediate state per in-flight minibatch). So the pipeline axis has two branches with opposite trades: GPipe pays throughput (the bubble) to save memory and keeps the gradient exact; PipeDream pays gradient freshness to save bandwidth and never flushes. The driver also worsens over time — across five models, moving K80 → Titan X → V100 raises communication's share, and PipeDream's edge over BSP grew 2.99× → 5.12× on newer cards behind a slower network. Three unrelated literatures now agree the durable optimizations are the ones about movement: FlashAttention about HBM, this about Ethernet, ZeRO-Infinity about PCIe and NVMe. [T1]
  • The activation axis is a continuum with a knob, and it is the only lever here that is exact (new 2026-07-26). Split n layers into k segments, store only the boundaries, recompute each segment's interior in the backward pass: O(n/k) + O(k) memory, minimized at k = sqrt(n) for exactly one extra forward pass, and extending recursively to O(log n) memory for O(n log n) compute. Measured at 48 GB → under 7 GB for a 1,000-layer ResNet and >4× for a 1,024-step LSTM, both at ~30% runtime. Graph liveness analysis alone (in-place + sharing) is worth 2–3× and stays linear in depth, which is what makes the recompute step necessary rather than optional. Two things the field's boolean flag hides: the effect is largest in the long-sequence case, not the deep one; and every transformation here "gives equivalent weight gradient for training and can always be safely applied," making it the only memory technique in this map that needs no footnote in a results table. Practitioner ordering: turn on gradient checkpointing before anything that changes the math. [T1]
  • The right setting is a search over a budget, and nobody ships the search (new 2026-07-26). Three independent systems reach the same conclusion about their own dial. FSDP exposes a continuous sharding factor and documents measurably wrong settings in both directions. Gradient checkpointing's origin paper does a budgeted grid search over the memory budget rather than exposing a boolean. PipeDream profiles the model for 1,000 minibatches and runs an O(N^2 M^2) dynamic program over the stage partition, replication factor and in-flight count — and in all but one experiment the optimum was a mixture of data, model and pipeline parallelism, while in that one exception the search correctly returned pure data parallelism (Inception-v3, 5% communication overhead, 1.00× over BSP). Same model, different cluster, different answer: 25 Gbps says data-parallel, 10 Gbps says 7-1 pipeline. The transferable rule for a small-scale reader is not the DP but its premise — profile the specific model on the specific hardware; the optimum is a property of the deployment. [T1]
  • There are six distinct answers to one memory ceiling, and they are indexed by three different things (revised 2026-07-25; the count is unchanged by the 2026-07-26 ingest, which supplies a primary source for the recompute axis and a second, opposite-trade branch of the pipeline axis rather than a seventh answer). Five of them are indexed by parameters — shard the replicated state, split a layer's math, give each device unique experts, demote cold state down the memory hierarchy, or partition depth and recompute the rest. The sixth, sequence parallelism, is indexed by sequence length, and it is the only one that makes context a property of the cluster rather than of the model: split the input into blocks, one per host, and rotate the key/value blocks around a ring while each host computes blockwise attention on whatever it currently holds. Attention over a query block against a group of KV blocks is permutation-invariant, so the visiting order is free and the next transfer overlaps the current compute. Per-host activation memory becomes 6bch — a function of the block size, containing no s at all — so trainable context scales linearly with device count (7B: 32K → 256K on 8 A100s; 3B: 32K → 16M on TPUv4-1024, 512×) at essentially unchanged MFU. It composes with re-materialization rather than replacing it. The precondition is unusually crisp and is where it stops: c ≥ F/B, block size above the host's FLOPS-to-interconnect-bandwidth ratio, minimum per-host sequence 6c — 6.2K tokens on an A100 behind NVLink and 149.5K behind InfiniBand, a 24× swing from the wire alone. [T1]
  • The offload axis has a third tier and an efficiency formula, and the formula reorders the intuition (new 2026-07-25). NVMe is over 50× larger than GPU memory on a DGX-2-class node, and running the demotion argument down to it removes model scale as a constraint: 32 trillion parameters on 512 V100s at >25 petaFLOPS (40% of peak), and 1T fine-tuned on a single node with no model parallelism where 3D parallelism stops at 20B. Crucially, at 500B — where both still fit — offload and 3D parallelism are within a point of each other (46 vs 47 TFLOPS/GPU), so this is not a penalty you accept. What generalizes past the scale headline is the decision rule: efficiency = ait × bw / (ait × bw + peak_tp), which given each state class's arithmetic intensity yields three very different bandwidth thresholds — parameters/gradients ~70 GB/s, optimizer states up to ~1.5 TB/s (their update cannot overlap with compute), and activation checkpoints under 2 GB/s. Activations are the cheapest thing to demote and the optimizer is the most expensive, which is the inverse of the ZeRO-Offload intuition below — both are right, about different resources (compute-independence vs bandwidth demand). The enabling trick is worth stealing on its own: bandwidth-centric partitioning replaces a single owner's broadcast with an allgather across all data-parallel ranks, identical GPU-side volume but every PCIe link active at once, lifting CPU→GPU from ~12 GB/s to 48 and NVMe to 25, linear in node count. [T1]
  • There are four parameter-indexed answers requiring more GPUs, and one that does not. Sharding partitions replicated state along the data-parallel axis; tensor parallelism splits one layer's math along a model axis; expert parallelism gives each device unique experts; and offload demotes cold state down the memory hierarchy — fp32 optimizer states, fp32 parameters, and the Adam step itself run on the CPU, while fp16 params/grads and forward/backward stay on the GPU. That last one is the only answer available to someone who cannot add cards, and it is derived rather than chosen: partition mixed-precision Adam training as a data-flow graph under three constraints (orders-of-magnitude less CPU compute than GPU, minimum CPU↔GPU communication, maximal savings at that volume) and the cut is forced — 12 of the 16Ψ bytes/param go to CPU, a 4× GPU-memory reduction before any sharding, at a communication volume fixed at 2× the parameter count per step regardless of batch or sequence length. It works because of a property of the optimizer, not of CPUs: forward/backward costs O(params × batch × seq) while the Adam step costs O(params), so the optimizer is the one stage whose cost is independent of the batch — hence the one you can afford to run an order of magnitude slower. Result: 13B on a single GPU (10× PyTorch), 40 TFLOPS/GPU on one V100 for a 10B model vs 30 TFLOPS for the 1.2B largest non-offload model, near-linear to 128 GPUs, 70B+ on one DGX-2 composed with model parallelism. [T1]
  • There are two memory axes, not one, and sharding only addresses the first. Sharding (ZeRO/FSDP) partitions the replicated state — optimizer, gradients, parameters — along the data-parallel axis; it answers "the copy of the state on every GPU won't fit." Tensor (intra-layer) model parallelism answers a different question — "one layer's weights or activations won't fit on a single device" — by splitting each matmul along a model axis. Megatron shows the transformer block can be partitioned so a whole layer costs only two all-reduce collectives forward and two backward (MLP: column-split the first weight so the nonlinearity stays local, row-split the second, one all-reduce; attention: split across heads, one all-reduce on the output projection), reaching 8.3B params on 512 GPUs at 15.1 PetaFLOPs, 76% scaling efficiency. The two are orthogonal and compose (with pipeline parallelism) into 3D parallelism — but tensor parallelism's all-reduce is latency-bound, so it stays efficient only inside a high-bandwidth island (a node's NVLink); practice confines TP within a node and shards/pipelines across nodes. [T1]
  • The ceiling that makes this map necessary is memory, and it arrives early. Distributed data parallel replicates parameters, gradients, and optimizer states on every GPU, so training stops where one device's memory stops — the paper puts that near 1B parameters on a 40GB card and demonstrates DDP failing to wrap T5 above 2.28B. Below that line, sharding buys nothing and costs collectives. [T1]
  • Sharding is a dial, not a switch. FSDP decomposes the model into units, coalesces each unit's parameters into one FlatParameter, all-gathers it just before that unit computes and frees the peer shards immediately after, reduce-scattering gradients instead of all-reducing them. Peak parameter memory becomes O(Σψᵢ/F + max ψᵢ). The sharding factor F runs continuously — F=1 is plain DDP (cheapest communication, no savings), F=W is full sharding (lowest memory, most communication), and hybrid values in between are "a graduating trade-off." FSDP-unit granularity is a second knob in the same currency. [T1]
  • The dial has a knee, and the first two-thirds of it are free. ZeRO decomposes sharding into three cumulative switches with asymmetric communication prices: P_os (optimizer states, 4× memory reduction), P_os+g (+ gradients, 8×), P_os+g+p (+ parameters, N_d×, linear in data-parallel degree). Stages 1 and 2 move the same communication volume as plain data parallelism — they are close to strictly dominant. Stage 3 costs 1.5×. Concretely, a 7.5B model at N_d=64 goes 120 GB → 31.4 → 16.6 → 1.88 GB per device. This is the practitioner's answer to "how far do I turn FSDP's dial": turn on 1 and 2 unconditionally; turn on 3 when you must fit, and know you are paying bandwidth for it. [T1]
  • The waste being removed is 15/16ths of the state, and the arithmetic is simple enough to do yourself. Mixed-precision Adam costs 16Ψ bytes per parameter (2Ψ fp16 params + 2Ψ fp16 grads
    • 4Ψ fp32 params + 4Ψ momentum + 4Ψ variance), all of it replicated per GPU under plain DP. Every reduction factor above follows from that constant — which also means they change with the optimizer, since K=12 is Adam-specific. [T1]
  • Memory in a training job is two pools, not one, and they need different tools. Model states (params/grads/optimizer) are handled by partitioning; residual states (activations, temporary buffers, fragmentation) are handled by ZeRO-R — partitioned activation checkpointing, constant-size fusion buffers so all-reduce temporaries stop scaling with model size, and live defragmentation. The last one encodes a real operational lesson: OOM-from-fragmentation is a distinct failure from OOM-from-size, and they have different fixes. [T1]
  • Removing memory pressure buys throughput, not just capacity. ZeRO reports super-linear speedup from 64→400 GPUs — mechanistic, not anomalous: smaller per-device footprint permits a larger batch, which raises arithmetic intensity. This is why "it fits now" and "it's faster now" arrive together. [T1]
  • This is ZeRO stage 3, and the paper says so. FSDP is explicitly "motivated by the ZeroRedundancyOptimizer (ZeRO) technique from DeepSpeed"; the claimed difference is native co-design with PyTorch's tensor, dispatcher, and CUDA caching-allocator internals — not different sharding math. Treat FSDP and DeepSpeed ZeRO-3 as the same idea with different integration stories until a neutral comparison lands. [T1]
  • The dial has measurably wrong settings in both directions. T5-11B loses 7% per-GPU TFLOPS scaling 8→512 GPUs as communication outruns the available overlap. The CPU rate limiter that buys up to 5× on T5-11B costs 5% on DeepViT-8B and nothing on RegNet-9B, because throttling only helps when a CPU running ahead is actually causing allocator defragmentation. Tuning is workload-specific and the paper says to check num_alloc_retries before enabling it. [T1]
  • Sharded training is not guaranteed mathematically equivalent to local training — the paper's own words. Because the optimizer steps over flattened, evenly-chunked FlatParameters whose layout ignores individual parameter boundaries, anything needing a parameter's unsharded value (weight or gradient norm, hence norm-based clipping), its tensor structure (approximate second-order methods), or global state across parameters is computing over the wrong object. Fixing it is called an open research question. No quality delta is measured, which is exactly what makes it worth flagging: the failure is silent. [T1, unquantified]
  • What the engineering actually buys, in numbers: minGPT-175B at 173/186 TFLOPS per A100 (batch 1/2, ~55–60% of the 312 TFLOPS BF16 peak), linear TFLOPS scaling 128→512 GPUs, on 8–512 A100 80GB with 2Tb/s RoCE. The enabling mechanisms are deferred initialization (build on a meta device, replay init per unit — otherwise materializing the model OOMs before sharding can help), prefetched all-gathers on a separate CUDA stream to overlap communication with compute, and mixed-precision materialization of only the live unit. [T1]

  • 2026-08-01 — a numerical-precision edge, on a default this map has priced only for memory, from small-model-rl-failure-modes (T1, primary map post-training-rl): every recipe in this vault — torchtune, Axolotl, PEFT, and every memory calculation this map has made — assumes bfloat16 mixed precision, and this map has costed it in bytes per parameter and never in correctness. Here is a correctness failure with a clean mechanism. PPO's importance ratio ρ_t = exp(log π_θ − log π_SFT) is a difference of two nearly equal log-probabilities, then exponentiated; bfloat16's 7-bit mantissa loses most of the significant digits in the subtraction and the exponential amplifies the residue, producing ratios above 10⁶ and hardware exceptions within the first optimization steps below 200M parameters. The fix is float32 for every tensor in the loop — policy, reference model, value head, reward model — which is a memory cost this map is equipped to price and nobody has. Two things worth carrying. The failure is not about model size: what makes it bite at 70–500M is that a small policy departs further from its reference per step, so the real precondition is any ratio-based objective with a fast-moving policy, and nobody has instrumented ρ_t at 7B. And it is a reminder this map's own framing invites: reduced precision is a memory technique with a numerical bill, and unlike recomputation — which recomputation-is-the-one-memory-technique-that-is-exact establishes leaves the gradient unchanged — bf16 changes the arithmetic, so it can enter the experimental configuration silently. Also a useful calibration datum from the same source: fifteen complete (model, corpus) fine-tune-plus-PPO configurations in ~16 GPU-hours on two RTX A6000s, the cheapest full experimental grid in this vault. See small-scale-ppo-fails-three-ways-before-it-fails-at-learning.

  • 2026-07-28 — the parallelism question gets two answers inside one deployment, from distserve-disaggregating-prefill-decoding (T1, primary map local-inference): every source in this map argues one axis in isolation and asks which is best, and the-parallelism-configuration-is-searchable-not-a-dial says the combination is a search. This adds a shape none of them has — in serving, tensor and pipeline parallelism win in opposite regimes within the same request, and the argument is a derivation rather than a benchmark. Model a prefill instance as an M/D/1 queue and time-to-first-token is execution time plus queueing delay, D + RD²/(2(1−RD)). Two-way pipeline parallelism leaves D alone and halves the queueing term; two-way tensor parallelism divides D by an imperfect 1 < K < 2 and cuts queueing less. So tensor parallelism wins when arrivals are sparse or the latency target is tight, pipeline parallelism wins as the rate climbs, and a worse K moves the crossover earlier. Decode inverts the pair — at large batch it is bandwidth- bound, so tensor parallelism gives diminishing latency returns while pipeline parallelism scales throughput near-linearly. The ablation is the sharpest part: searching parallelism configurations without separating the two phases performs identically to not searching, so the coupling was the constraint, not the configuration. Also a fifth instance of this vault's interconnect threshold, for once permissive: a 1.13 GB KV transfer per request needs ~90 Gbps at 10 rps, which vanishes over 600 GB/s NVLink and does not over the same testbed's 25 Gbps cross-node link — which is why the placement algorithm used throughout constrains prefill and decode segments to share a node. Megatron's node-locality, Ring Attention's c ≥ F/B, Sarathi-Serve's cross-node TBT penalty and now this: four literatures, one ratio. See each-inference-phase-wants-a-different-parallelism.

The scheduling contribution, DualPipe, is the direct successor to this map's two pipeline sources: it splits each chunk into attention / all-to-all dispatch / MLP / all-to-all combine, splits the backward chunk further into backward-for-input and backward-for-weights, and feeds micro-batches from both ends of the pipeline, so the ~1:1 computation-to-communication ratio that cross-node expert parallelism otherwise imposes is hidden entirely. Read against pipeline-parallelism-splits-depth-and-pays-a-bubble and asynchronous-pipelining-buys-bandwidth-with-gradient-freshness, this is the third answer to the bubble and the only synchronous one that claims to hide rather than amortize it — so it costs no gradient freshness, which is the currency the asynchronous branch spends.   • 2026-07-27 — inference-side edge on two of this map's axes from sarathi-serve-chunked-prefill-stall-free-batching (T1, primary map local-inference): the pipeline-bubble analysis this map built for training reappears in serving, with a different cause and the same fix. GPipe's bubble is O((K−1)/(M+K−1)) and comes from filling and draining a fixed pipeline; in inference the stages are never idle for that reason, yet bubbles are worse, because micro-batch runtimes vary wildly with their prefill/decode mix. The worked case is stark: a single 4K-token prompt takes ~1150 ms where a batch-32 decode iteration takes ~200 ms, so interleaving them wastes ~950 ms of every GPU behind the long one. The fix is the same principle as M ≥ 4K arriving from the other side — make the micro-batches uniform in compute rather than uniform in count — and it is worth 3.6× serving capacity under strict latency targets. Second and sharper for this map: it is a fourth instance of the interconnect threshold this map keeps rediscovering. Megatron's tensor parallelism is node-local because its two all-reduces per layer are latency-bound; Ring Attention needs c ≥ F/B, so 6.2K tokens per host over NVLink and 149.5K over InfiniBand. Here, in inference, cross-node tensor parallelism costs >2× the median time-between-tokens of in-node TP with pipelining across, which is why pipelining is the cross-node option at all — and why removing its bubbles is what makes commodity-ethernet serving viable. Three literatures, one boundary: every distributed technique in this vault is decided by the ratio of compute to interconnect, and every one of them is ruled out below a datacenter fabric. See prefill-saturates-compute-far-below-a-full-prompt.
  • 2026-07-26 — ingest of pipedream-asynchronous-pipeline-parallelism (Harlap, Narayanan, Phanishayee et al., MSR/CMU/Stanford, arXiv 2018 v1, T1): closes the asynchronous pipelining gap this map has named since GPipe landed — the branch it knew only through a competitor's characterization. It arrives as a correction to the map's own filing, which is the more valuable half. GPipe made pipelining look like a memory technique; PipeDream is the origin of the idea and it is a communication technique that spends memory. The two are not variants: flush and stay exact (GPipe, bubble O((K−1)/(M+K−1))) versus never flush and go stale (PipeDream, 1F1B). Weight stashing keeps one weight version per in-flight minibatch so a stage's backward pass sees its own forward pass's weights — without it "the weight update is not a valid gradient of the loss function f for any weight vector" — but staleness still differs per stage, and the mechanism that would restore data-parallel equivalence (vertical sync) is measured as negligible and shipped off by default. That makes this the vault's sharpest instance of evaluation-contamination's infrastructure non-equivalence: not an unnoticed break but a documented, deliberate one. Open questions:

  • The standing experiment now has one measured instance in the wrong modality (new 2026-07-31). adaptive-checkpointing-peft-consumer-gpu runs the grid — five fine-tuning methods × four backbones × three checkpointing strategies under a 2 GB budget, with watt-hours — and reports the shape the map predicted (interior optimum at τ = 0.5, 43–79% memory for 9–30% energy). It answers none of the transformer-specific halves: no decoder-only model, no 4-bit base, no long sequence, and the double-counting question (attention already recomputes its largest intermediate since FlashAttention) is untouched because these are not attention-dominated workloads. So the ask survives with its parameters intact and gains two: is the interior optimum still interior when the sequence is long enough for activations to dominate, and does the uniformity precondition hold for a decoder-only stack — which the paper makes checkable rather than assumable, since it supplies the counterexample (a hybrid stem) that breaks the policy. Newly cheap and newly interesting: the same measurement on a VLM, where the vision tower is exactly the heterogeneous front-end that broke the adaptive algorithm here.
  • Placement has never been priced as a memory variable (new 2026-07-31). Two independent studies now say the same thing about where the trainable parameters go — 10.7 accuracy points at fixed budget (where-the-adapter-budget-goes-matters-more-than-how-much-there-is), and a 2.6× peak-memory inversion at matched batch size (peft-does-not-reliably-reduce-peak-memory) — and neither cites the other or measures the axis the other measured. Nobody has run one adapter budget, several placements, reporting accuracy and peak memory together, which is the table a practitioner choosing target_modules on one card actually needs and which costs a handful of short runs to produce.
  • The standing experiment is now half-equipped and still unrun (new 2026-07-26). Gradient checkpointing has a primary source, a cost model (O(n/k) + O(k), one extra forward pass at k = sqrt(n), ~30% runtime) and an exactness guarantee — but every number in it is a 2016 CNN or RNN on a Titan X, and the transformer case is genuinely different in two ways nobody has measured: attention already recomputes its largest intermediate since FlashAttention, so part of the win is double-counted, and the framework flag every practitioner uses is a single point (k = number of blocks) on a curve the paper searches. So the ask sharpens rather than closes: peak memory and step time for a 4-bit LoRA fine-tune at a realistic sequence length, with and without gradient checkpointing, with and without CPU activation offload, and at more than one segment granularity. Everything needed is public and it is a few GPU-hours. Revised 2026-07-29 by the tool docs, in three ways — the experiment is smaller, better specified, and no less necessary. (i) The grid is three cells, not four: offload is defined over the checkpointed set, so "offload without checkpointing" does not exist. (ii) "More than one segment granularity" should be re-specified in the shape the tooling actually exposes — selective_checkpointing.save, an op list, not a block count — and note that saving matmul ops is rejected in LoRA/QLoRA runs because of in-place mutations, so the most obviously worth-saving op class is unavailable in exactly this vault's regime, which likely narrows the reachable part of the curve considerably. (iii) A fourth arm is now worth adding that did not exist when the item was written: layer_offloading on/off, streaming the frozen 4-bit base. Neither doc reports a single number for any of this, which is precisely why the run is still the cheapest useful thing anyone could do here.
  • The memory-wall comparison has been asking about the wrong term for a PEFT reader (revised 2026-07-25). This map now holds six answers — shard it, split the layer, demote it down the memory hierarchy, route around it with sparsity, recompute it, and partition the sequence — and the first four all attack terms that scale with the number of trainable parameters, which is why the vault suspects offload is the axis PEFT deletes. Activations do not scale that way: the forward activations of a 70B model are the same size whether you update every weight or 0.01% of them. So the two activation-indexed axes — re-materialization and sequence parallelism — are the memory techniques here that PEFT cannot make redundant, and by elimination the ones most likely to bind in the LoRA-on-one-card regime this vault's premise assumes, especially once cheap context extension (context-length-is-a-cheap-post-hoc-edit-not-a-pretraining-property) makes long sequences easy to acquire and expensive to train through. Sequence parallelism, though, is ruled out for this audience by its own precondition (c ≥ F/B, overlap-requires-a-block-size-above-the-flops-to-bandwidth-ratio) — which leaves gradient checkpointing as the single activation lever available on one or two consumer cards, and makes the standing experiment more urgent rather than less. The cheapest useful experiment across this map and peft-methods: peak memory for a 4-bit LoRA fine-tune with and without gradient checkpointing at a realistic sequence length. Nobody in-vault has run it, and it would say whether the multi-axis comparison is even the right question for this audience. Newly adjacent (2026-07-25): ZeRO-Infinity prices activation offload to CPU at under 2 GB/s (offload-efficiency-is-a-bandwidth-arithmetic-intensity-problem), i.e. trivially affordable over PCIe — so the second half of that experiment is "and with activation offload," and it is equally unrun.
  • This map's one source has nothing to say about fine-tuning. Every experiment is generic full-parameter training — no frozen layers, no adapters, no fine-tuning-specific memory profile. How FSDP composes with LoRA on a quantized base (what actually gets sharded when 99.99% of parameters are frozen and 4-bit, and whether sharding is even the right lever there) is the single most decision-relevant untested combination for this vault's premise. Unsourced.
  • NVMe offload: RESOLVED 2026-07-25 (zero-infinity-nvme-memory-wall) — and what replaces it is narrower. The tier question is answered; the contention question is not. That paper's efficiency analysis holds bandwidth infinite for every state class but the one under study, so it prices each in isolation and says nothing about what happens when parameters, optimizer states and activations are all moving over the same PCIe link at once — which is the actual configuration. A neutral FSDP-vs-DeepSpeed comparison also remains unsourced, and this is now the fourth first-party DeepSpeed/FSDP account in-vault with a shared lineage across two of them, so nothing here is a disinterested head-to-head. If that is right it is a genuinely useful negative result for this vault's premise, and nobody has measured it. The optimality argument is also Adam-specific (derived from K=12 optimizer bytes) and does not transfer to a different optimizer.
