Agentic tool use (tool selection, retrieval orchestration, agent-corpus scaling) — map

Coined 2026-10-23 (auto run) — flagged for David's review. This vault's premise is using data and your own compute to make an open-weights model outperform a frontier model on a specific task. Every existing map that demonstrates this premise does so on a performance axis — reasoning accuracy (distillation-small-models), preference alignment (post-training-rl), format efficiency (the quantization maps). This map exists for a different axis: as agents are handed corpora of thousands of tools, picking the right one for a multi-step instruction becomes its own bottleneck — descriptions don't fit the context window, and a relevance-based retriever ranks tools without knowing which ones a given substep actually needs. That orchestration skill — decomposing an instruction and matching descriptions to substeps — has its own failure modes (candidate-cap sensitivity, retriever dependence, cross-domain transfer) that neither distillation-small-models nor post-training-rl's standing questions are built to hold.

Status: emerging Status note (2026-10-26): holds at emerging, and the map gets a third, genuinely different axis: not which tool to pick, but how fast the call you already decided on gets decoded. specmem-live-memory-for-agentic-tool-speculation (T1, arXiv 2610.31840, UIC/Salesforce Research) accelerates agentic tool calling via speculative decoding, drafting from a memory of the agent's own verified past tool calls — kept alive and written back online into bounded per-user stores with LRU eviction, rather than built once and frozen (the prior system, ToolSpec). A side-effect gate defers drafting on irreversible calls until verification confirms, rather than gating on retrieval confidence. On multi-session, multi-user streams across three open-weight models: a 27% gap in mean accepted tokens against a frozen store (+11% to +34% across benchmarks), up to 1.74x wall-clock speedup; local per-user scoping adds no acceptance gain but closes a measured cross-user leakage channel. This is orthogonal to sub-threads 1 and 2 (both about selection quality) and closer in kind to speculative-decoding's drafter-provenance question — cross-linked there as a new mechanism (live retrieval memory) alongside DLite's hidden-state-reading fix for the same agentic-workload gap, neither citing or testing the other. Names this map's third sub-thread. Status does not move: single demonstration, three unnamed open-weight models, no frontier/closed-API test. specmem-live-per-user-memory-sustains-tool-call-speculation.

Status note (2026-10-25): holds at emerging; sub-thread 2 gets a second, independent source — different benchmark, different group, different mechanism, same underlying bet — plus an unplanned contribution to this map's own cross-link with evaluation-contamination. our-own-jev-typed-decisions-in-house-judge (T1, arXiv 2610.29052, PayPal.AI) builds "typed decisions" — a pointer head reading a frozen backbone's output-token probabilities in one forward pass, no generation — and applies it at 1B/2B/35B scale (MiniCPM5-1B/2B, Qwen3.6-35B-A3B) via the public Eikos recipe and JevBench. The 35B model scores 79.3% on JevBench's hard tier, not significantly different (p=0.12) from a commercial reference at 73.0%. This does not replicate or extend per-option-scoring-beats-joint-for-tiny-decision-encoders's specific per-option-vs-joint scaling question (Jev never runs that ablation), but it is independent convergence on sub-thread 2's premise — non-generative, single-forward-pass closed-set scoring — reaching 1B-35B scale where the prior source's controlled test topped out at 32M, on a wholly separate benchmark/corpus/mechanism. The paper's own motivating finding (a frontier judge's stored labels agreeing with a fresh consensus only 26.9% of the time) and its own measurement-instability result (an 11.7-point swing on an unchanged benchmark from a corpus retrain) are graded primarily on evaluation-contamination — cross-linked here because Part II's scale is this map's territory. Status does not move: no replication of the founding claim (small model beats a much larger proprietary system's own agentic workflow) and no per-option-vs-joint comparison, so neither the consolidating bar nor sub-thread 2's open scaling question is met. jev-typed-decisions-reach-1b-to-35b-scale-on-a-separate-benchmark.

Sub-threads: (1) generative tool orchestration — decompose a multi-step instruction, retrieve candidates, plan and select via a trained generative model · (2) direct closed-set decision scoring — no decomposition, no generation, a small discriminative encoder scores already-enumerated options directly · (3) tool-call decode acceleration — not which tool to pick, but how fast the already-decided call is served, via speculative decoding against a maintained draft source [reviewed 2026-10-26 @ 4 bullets]

What we believe now:

  • Accelerating an agent's tool calls is a different axis from deciding which tool to use, and the lever is keeping the speculative-decoding draft memory alive rather than freezing it once built (new 2026-10-26). SpecMem drafts tool calls from a live, per-user, LRU-bounded memory of the agent's own verified past calls, gated on declared side-effect reversibility rather than retrieval confidence. Against a frozen store (the prior system, ToolSpec): 27% gap in mean accepted tokens (+11% to +34% across benchmarks), up to 1.74x wall-clock speedup. Local per-user scoping adds no acceptance gain but closes a measured cross-user leakage channel. Names this map's third sub-thread; cross-linked to speculative-decoding as a new drafter-provenance mechanism for agentic workloads (retrieval from a maintained external memory, vs. DLite's reading of the target's own hidden states), neither source testing or citing the other. [T1, strong; UIC/Salesforce Research; three unnamed open-weight models; no frontier/closed-API test; leakage channel measured as present but not severity-characterized] specmem-live-per-user-memory-sustains-tool-call-speculation
  • A non-generative, single-forward-pass readout scoring closed-set options gets independent convergence at 1B-35B scale, on a separate benchmark and corpus from sub-thread 2's founding source — though not a test of that source's specific per-option-vs-joint question (new 2026-10-25). "Typed decisions" (a pointer head over a frozen backbone's output-token probabilities) scores 79.3% on JevBench's hard tier at 35B (MiniCPM5-1B/2B, Qwen3.6-35B-A3B via the public Eikos recipe), statistically indistinguishable (p=0.12) from a commercial reference at 73.0%. Different mechanism and benchmark from per-option-scoring-beats-joint-for-tiny-decision-encoders (no per-option-vs-joint comparison here), so this doesn't close that source's 1B-scale open question — but it is a second, independent group finding non-generative single-pass scoring competitive at a scale three orders of magnitude past the prior controlled test. The paper's own disclosed contamination admission (the 35B "developed with those items in view," caught only by an 8-gram lexical check) and an 11.7-point retrain-to-retrain swing on an unchanged benchmark are graded primarily on evaluation-contamination. [T1, single-seed throughout for these results; PayPal.AI; no per-option-vs-joint ablation; contamination caveat is self-disclosed] jev-typed-decisions-reach-1b-to-35b-scale-on-a-separate-benchmark
  • A small open model, trained with SFT on a proprietary teacher's filtered decompositions then GRPO reinforcement learning, can learn to plan-and-select tools from a 10,000+-tool corpus well enough to beat every tested agentic workflow built directly on that same (402B) teacher — and the skill transfers to a different retriever and to out-of-domain tool benchmarks with no retraining (new 2026-10-23). On ToolBench's held-out G3 test (2,124 instructions), Qwen3-8B (SFT+RL) reaches 41.5% exact-match success against Llama-4-Maverick's best workflow (Search-R1-style) at 30.6% and ReAct at 28.4%. SFT alone already reaches 36.2%; RL alone from the base model reaches 35.7% — the two stages are roughly complementary. Swapping the test-time retriever (BM25 → COLT) with no retraining improves success at every model scale. Transfer to ToolBench G2, Gorilla, and CRAFT beats the best Maverick baseline; TaskBench is a disclosed exception where Maverick's workflow retains the lead (80.6 vs. 63.1-72.8), attributed to that workflow's Plan-stage domain knowledge. [T1, strong; supervision traces back to the proprietary teacher for gold-tool filtering and SFT traces, so this is a distillation-RL hybrid rather than a from-scratch result; 8×A100, Qwen3-1.7B/4B/8B only] small-model-tool-selection-beats-proprietary-402b-teacher
  • For closed-set decisions, a small discriminative encoder that scores each option separately against the query beats one that reads all options jointly — once it starts from a reranker initialization — and small (68M-150M) released joint encoders already beat a much larger (435M) generic zero-shot classifier on accuracy and latency, with no generation step at all (new 2026-10-24). Per-option scoring beats joint by 5.8 points chance-corrected skill at matched optimizer steps, 2.8 at matched compute (32M params); the advantage needs 5-13x more encoder passes and only appears with reranker init. Reordering options changes 12-23% of joint models' answers, 0% of per-option models'. Released 68M/150M joint encoders beat a 435M DeBERTa-v3 zero-shot classifier by 4.9/5.9 accuracy points (209 overlap-audited tasks), answering in 14ms median vs. 728ms. Open questions:

  • Does the core result replicate with a different proprietary teacher or a tool corpus built independently of this paper's own data pipeline? The only demonstration uses Llama-4-Maverick as teacher and a ToolBench-derived training/eval family throughout; whether the recipe transfers to a different teacher model or a tool corpus this paper's authors didn't curate is untested.
  • Why does the trained skill fail to transfer to TaskBench specifically? The paper attributes the one disclosed loss to the Maverick workflow's Plan-stage domain knowledge, but does not test whether additional domain-specific SFT data would close the gap for the trained small model, which would distinguish "this skill doesn't transfer to novel domains" from "this domain needed data the small model's training set didn't include."
  • Does the result hold at larger open-weights scale, or with full-parameter fine-tuning compared against the LoRA-free full fine-tuning used here? All training is full fine-tuning on 1.7B-8B models; whether the gap over the proprietary-teacher baseline widens, narrows, or holds at 30B+ scale is unmeasured.
  • Does the per-option-vs-joint encoder advantage hold at the 1B scale the released-model comparison separately reaches, in the same controlled setting? (new 2026-10-24.) The controlled comparison is 32M-parameter only; the 1B-scale evidence comes from a different, uncontrolled comparison (released models vs. a generic classifier), so the two results don't directly chain.
  • Is there a head-to-head between this map's two sub-threads on one benchmark? (new 2026-10-24.) No source has run generative plan-and-select and direct closed-set encoder scoring on the same tool corpus; whether they are complements (encoder pre-filters candidates, generative model plans) or substitutes is unknown.
