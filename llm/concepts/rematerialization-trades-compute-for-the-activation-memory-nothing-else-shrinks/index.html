Re-materialization attacks the memory term nothing else touches

Training memory has four tenants: parameters, gradients, optimizer states, and activations. This map's other sources fight over the first three. Re-materialization — keep only the activations at partition boundaries, recompute the intermediate ones during the backward pass — is the only in-vault technique that attacks the fourth, and it does so before any distribution at all: 3.9× more parameters on one unchanged accelerator for AmoebaNet, 2.7× for the Transformer, purely by throwing activations away and paying one extra forward pass to get them back.

The reason this matters more than its 2019 framing suggests is what it implies about PEFT. offloading-the-optimizer-demotes-memory-instead-of-distributing-it wins by relocating 12 of the 16Ψ bytes of mixed-precision Adam state; sharding-is-a-dial-between-memory-and-communication and ZeRO's three switches partition optimizer states, gradients, and parameters. All of those terms scale with the number of trainable parameters — which is why the vault has flagged that offload may be the axis PEFT renders moot, since LoRA on a 4-bit base has almost no optimizer state left to demote.

Activations do not work that way. The forward activations of a 70B model are the same size whether you are updating every weight or 0.01% of them, because they are a function of batch size, sequence length, and depth, not of which parameters carry gradients. So re-materialization is the one memory technique in this vault that PEFT does not make redundant — and by elimination, the one most likely to be the binding constraint in the LoRA-on-one-card regime this vault's premise is built around, especially once context-length-is-a-cheap-post-hoc-edit-not-a-pretraining-property makes long sequences cheap to acquire and expensive to train through.

That inference is the vault's, not the paper's, and nothing in-vault measures it. It names the cheapest useful experiment across peft-methods and distributed-training: peak memory for a 4-bit LoRA fine-tune with and without gradient checkpointing at a realistic sequence length, which would say whether the memory-wall comparison the index has carried since 2026-07-22 is even asking about the right term for a practitioner.

Bound: measured on 2018-era accelerators for a convnet and an encoder-decoder NMT model, as part of a pipeline-parallelism system rather than in isolation, and the compute cost of the extra forward pass is not separately priced against the memory saved.

Rebutted by: peft-does-not-reliably-reduce-peak-memory — qualifies the framing that activations are merely the term PEFT fails to shrink: where the trainable parameters sit decides how much of the activation stack stays alive, so PEFT can enlarge this term (BitFit at 2.6× LoRA's peak on TinyViT). Also adaptive-checkpointing-beats-the-boolean-at-a-measured-price — the budgeted search this claim describes now has one measured interior optimum, plus the precondition it needs (near-uniform per-layer activation cost). Adjacent rather than opposed: dense-token-rewards-decay-with-trajectory-depth notes that the sequence lengths where this lever starts to matter on one card (~3K–7K) are roughly where on-policy distillation's supervision signal starts to fade — so the memory ceiling and one training method's horizon ceiling arrive together, which is a coincidence worth knowing and not a claim about this mechanism.
