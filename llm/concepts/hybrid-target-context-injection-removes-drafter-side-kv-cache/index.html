The drafter-side KV cache was never necessary for parallel block drafting — direct target-KV reuse just needed a second signal to keep it from degrading across the block

This map already knows parallel/block drafters (P-Eagle, DFlash, and DSpark — the last two documented on this map via distributed-training's disaggregated-training entries) pay a memory and write-bandwidth cost for maintaining a separate drafter-side KV cache, built by projecting the target's hidden states at every input position. H-Spec's contribution is showing why the obvious fix (reuse the target's own KVs directly, skip the drafter cache entirely) has not simply replaced the incumbent approach: attention-only reuse degrades draft quality as the block progresses, because nothing updates the drafter's read of the target as drafting proceeds token by token within the block. The fix is architectural rather than a tuning knob — pair the direct-reuse attention path with a second, complementary path (Mamba modules seeded once from the target's last-position hidden state, updated via Mamba's own parallel scan across the block) rather than picking one source of target context over the other.

The result generalizes across three target models (Llama3.1-8B-Instruct, Qwen3-4B, Qwen3-8B) and wins on every reported axis against three existing parallel-drafter baselines, with the gains compounding into vLLM-served throughput and — notably for this map's KV-budget-adjacent concerns — a reduction in KV-cache utilization (4.3-24.6%) rather than a neutral or negative trade, since the whole point is removing a cache that competes for the same memory as the target's own KVs and weights on the device where memory is usually the binding constraint.

Graded extends: this narrows an architectural design space (how to give a parallel drafter target context without its own cache) that this map's DSpark/DFlash entries opened but did not resolve; it does not contest anything already recorded. Graded strong: multiple target models, an established multi-task evaluation surface (Spec-Bench plus HumanEval/BFCL, extended by the DeepSpec suite), and three named baselines rather than a single ablation.

Bounded: the architectural requirement that drafter and target K/V dimensions match limits applicability to cases where that alignment is chosen at drafter-design time, not a drop-in for an arbitrary existing drafter; the hybrid backbone is reported to draft more slowly at low concurrency or short input lengths, so the win is concurrency-dependent and the crossover point is not stated; all latency/throughput numbers are single-GPU (A100 80G) — no multi-GPU or consumer-hardware measurement; only Llama and Qwen families are tested.

Rebutted by: none.
