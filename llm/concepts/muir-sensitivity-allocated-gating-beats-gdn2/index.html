Gated DeltaNet-2's full-rank channel-wise gates spend parameters symmetrically on erasure and writes, but erasure turns out to need far less capacity than writes do -- and an unweighted readout lets slow-decaying state rows dominate, forcing the erase gate to do work a smarter readout could do instead; Muir fixes both and extrapolates 2,560x beyond its training context with no drift

TL;DR: Gangavarapu, Tabak and Schaefer (UT Austin/Google) extend the gated-delta-rule linear-attention lineage (Gated DeltaNet → Kimi Linear → Gated DeltaNet-2) by diagnosing two parameterization bottlenecks GDN-2's channel-wise, decoupled full-rank erase/write gates introduce. First: key activations and unit normalization concentrate energy onto a sparse subset of channels, so the erase gate -- which decides whether to overwrite a state value for an incoming key -- can be parameterized at much lower rank than GDN-2 uses without losing erasure fidelity, because most of what needs erasing lives in a small channel subspace. Second: state rows that decay slowly accumulate much larger norms over time than fast-decaying rows, so an unweighted readout lets the slow rows dominate every prediction, which forces the erase gate to over-suppress cross-key interference that a smarter, weighted readout could instead handle at read time. Muir responds by fusing all gates into a single sensitivity-allocated low-rank projection (reclaiming the parameters GDN-2 spent on a symmetric full-rank erase gate), adding a matched-filter readout gate that reweights state rows before they're read, and reinvesting the freed budget into a wider feed-forward network -- plus a new parallel-update training formulation, since standard chunkwise algorithms go numerically unstable at the large chunk sizes wide matrix units need to run efficiently.

What it says. Across 166M-1.34B parameters, Muir lowers perplexity by 1.8-2.0% versus GDN-2 and 2.5-3.6% versus a standard Transformer, with commonsense-accuracy gains up to 1.9 points and improved extractive recall over GDN-2; at 1.34B it outperforms both baselines on multi-hop and multi-needle recall. Trained at a 4K context length, it extrapolates 2,560x to 10M-token streams with no perplexity drift and maintains near-100% passkey retrieval accuracy out to 1M tokens, using the same static (non-growing) readout state throughout. Training throughput matches GDN-2 and reaches 2.7x faster than a standard Transformer at 32K sequence length; inference stays constant-memory by construction, since the fixed-size recurrent state never grows the way a KV cache does.

Caveats. No code release stated on this read. Evaluation tops out at 1.34B parameters, well below the scale at which this map's other recent linear-attention/recurrent-state evidence (hybrid-state-transfer-handles-three-interacting-cache-objects-at-a-model-switch, spare-compresses-linear-attention-recurrent-state-training-free) is measured, so whether the sensitivity-allocation argument holds at 7-70B is untested. The long-context extrapolation is measured on synthetic retrieval (passkey, multi-needle) rather than this vault's standing RULER-class benchmark on context-extension. No direct comparison against Kimi Linear or other channel-wise-decay variants is offered, only against GDN-2 and a Transformer. Muir is an architecture contribution (a new linear-attention design to train from scratch), distinct in kind from kv-cache-management's recent sources, which compress or transfer an already-trained linear-attention model's recurrent state rather than redesigning its gating -- the two are complementary and untested in combination (would a LoopVQ/HST/SPARE-style compression applied to a Muir-trained state behave the same as on a GDN-2 state?).
