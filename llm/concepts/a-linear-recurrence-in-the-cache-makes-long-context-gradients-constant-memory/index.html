A linear recurrence in the cache makes long-context gradients constant-memory

activation-memory collects ways to pay less for the tensors a backward pass needs to keep. Most of them recompute more (checkpointing) or move bytes somewhere slower (offload). This one is different in kind: it exploits a structural property of the thing being stored, and gets constant memory in the sequence length rather than a constant-factor reduction.

Under a fixed-size sparse-attention cache, the buffer at chunk n+1 is the buffer at chunk n with some slots overwritten. That is a linear recurrence, and it inverts:

keys = scatter(keys', index, delta_key),   delta_key = gather(keys, index)

So the autograd graph does not need (keys, values) per chunk. It needs (index, delta_key) and (index, delta_value), and can reconstruct the buffer on the backward pass from the delta plus the next chunk's buffer. Since autograd memory here is dominated by KV storage, it falls by the chunks-per-cell factor. The sequence can be arbitrarily long at fixed resources.

The implementation route is the part worth recording, because it is what makes the technique portable. PyTorch's autograd saved_tensors_hooks — built for checkpoint offloading — lets you substitute what gets stored in the graph. The mechanism is non-selective, though: the pack hook fires for every tensor autograd decides to keep, and there is no way to tag a tensor in the forward pass so it can be recognised later. Their solution is to build annotations alongside the forward code and identify a candidate x by testing gather(x, index) == delta_key. A missed match is not an error, only a little more memory. It is inelegant and it is honest, and the payoff is that the method is agnostic to the cache policy — the contrast the paper draws is with OOMB, which hides KV buffers from autograd using dedicated CUDA kernels that must be hardcoded per sparse-attention variant.

The bill: about 30% more per update step than exact attention at chunk 2048, and 11–14% more again at chunk 1024. Heavy-hitter policies add only 2–4% over a last-recent policy. In exchange, gradients for a 4B model fit on one A100 40 GB — the four devices in the experiments buy batch size through data parallelism, not context sharding.

Two bounds. One model, one scale, single seed, and the memory reduction is reported as a factor argument rather than measured peak-memory curves. And the technique is specific to sparse attention with a fixed-size cache — it is the fixed size that creates the recurrence. It does not apply to exact attention, where there is no eviction and therefore no delta.

The reason this matters beyond its own map: it removes the hardware argument for not co-adapting a model to its serving-time cache policy. See train-under-the-eviction-policy-you-will-serve-with.
