Selection dominates scale, at a third stage

data-curation has held one gap since 2026-07-18 and restated it more sharply on 2026-07-25: the vault has a source for synthetic-data generation (LLaVA manufacturing a multimodal corpus with a blind teacher) and none for synthetic-data filtering — the ablation instrument that data-curation-choices-are-ablatable-and-non-monotonic and finetuning-data-quality-and-diversity-beat-quantity both wield has never been pointed at a generated corpus. This closes it, and the result is the same shape as the two that came before.

The map's principle is that selection dominates scale. FineWeb established it at 15 trillion pretraining tokens; LIMA established it at a thousand instruction examples; neither group cites the other. The object curated here is a third kind: reinforcement-learning prompts, the input a GRPO run consumes. Same direction, same magnitude class.

Filtering the generated set is worth +4.2 points on a four-benchmark reasoning average (53.0 → 57.2) while removing examples. The authors' own summary is the one to carry: "it is better to have less high-quality synthetic data than more lower-quality synthetic data." Filtering helps the weaker generation method too — plain Self-Instruct with reasoning-generated targets goes 49.5 → 53.6 — so this is a property of the curation step, not an artifact of one generator.

Two further readings that neither the source nor the map had before.

Generated prompts beat human ones, for prompts. On open-ended instruction following, unfiltered synthetic prompts (53.9) beat filtered human WildChat prompts (50.7) with the same student, the same judges and the same training recipe. The map has carried since 2026-07-19 that LLaVA (manufacture with a teacher) and Molmo (collect from humans) take opposite sides and nobody compares them at matched cost. This is not a matched-cost comparison either — the human side is a pre-existing scrape rather than a commissioned collection, and generation's inference cost is unpriced — but it is the first head-to-head on one axis, and it inverts the default. Two scoping notes keep it honest: the object is prompts, not annotations, so Molmo's argument about human-sourced labels is untouched; and the comparison rests entirely on LLM judges.

Quantity is not flatly dead, and the reconciliation matters. LIMA found scaling instruction count 16× moved nothing. Here, going from 5k to 10k generated-and-filtered prompts is worth another 1.5 points (57.2 → 58.7). These are not in conflict once the operations are named: LIMA scaled within one source under one fixed filter — more of the same — while this scales generation and then filters, which broadens the distribution before selecting from it. That is the map's own diversity result appearing in a new guise, and it sharpens rather than answers the experiment the map has wanted since 2026-07-25 — hold example count fixed, vary the number of distinct sources. The reconciliation is this vault's reading, not either paper's.

Two things bound it. The paper's own filters are not cheap — each requires K extra generations per candidate, or K responses scored by a reward model — and no compute accounting appears anywhere, which is precisely the number that would settle synthesis-versus-collection at matched budget. And nothing in the pipeline is decontaminated: prompts are generated from public-benchmark-derived seeds by a model asked for items of similar complexity, then scored on public benchmarks, which public-training-corpora-carry-undetected-benchmark-rephrasings shows is a paraphrase generator by construction. The differences between arms survive that (every arm is generated the same way); the absolute numbers do not.
