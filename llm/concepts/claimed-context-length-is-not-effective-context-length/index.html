The advertised number measures the buffer, not the capability

Needle-in-a-haystack — hide a fact in filler, ask for it back — became the field's standard evidence for long context because it is trivial to build at any length. Hold seventeen models against a suite that keeps the synthetic controllability but adds three task families beyond retrieval, and almost every one of them falls apart long before its claimed length while continuing to ace the needle test.

The suite adds multi-hop tracing (a variable is bound to a value, then a chain of assignments is scattered through noise; return every name bound to that value — a minimal coreference proxy), aggregation (return the top-K most frequent words from a synthetic list, so the answer depends on the whole context rather than one span), and question answering padded with distracting paragraphs from the same dataset. It also hardens retrieval itself along three axes: needle type (words, 7-digit numbers, 32-digit UUIDs), hard distractors up to a haystack made entirely of decoy needles, and recall of all matches rather than one. Everything is synthetic, which is the design choice that matters — realistic long-context benchmarks let a model score from parametric knowledge instead of from reading.

Effective length is defined operationally: the longest evaluated length at which a model still beats an unextended Llama-2-7B's 85.6% at 4K. Against claimed lengths, the results are systematically worse and the shortfall is not small — Yi-34B claims 200K and holds 32K, Mixtral-8×22B claims 64K and holds 32K, DBRX claims 32K and holds 8K, and only the strongest closed model exceeds the longest length tested.

The error analysis is what makes this a capability finding rather than a leaderboard. Four failure shapes, none visible to a needle test. Distractor sensitivity: accuracy falls ~40 points when the haystack is made of decoy needles, and the errors are near misses — values retrieved from the vicinity of the target, i.e. the range is matched coarsely but the key is not located. Incomplete retrieval: going from one query to eight costs ~15 points, and asking for several values under one key produces duplicated answers. Copying: over 80% of one model's aggregation output at 128K is lifted verbatim from the single in-context example, a behaviour absent at short lengths; remove the example and it copies the start of the input instead, which the authors attribute to attention sinks. Falling back on parametric knowledge: in QA, enough distracting paragraphs drive performance toward the model's no-context baseline, i.e. it stops reading; in aggregation, a model asked for the most frequent words returns "the", "an", "a" without counting.

Two ablations name what actually buys effective length, and neither is the advertised window. Training context length helps but not monotonically — a model trained to 1M scores worse at 256K than the same model trained to 512K — while model size helps reliably: holding data and training length fixed, 34B beats 9B beats 6B on both absolute score and rate of degradation. The authors' own summary is that top performers share "larger model sizes and larger base frequencies in RoPE," and that a large training window "is not always necessary," since the top ranks contain both brute-force scaling and inference-time extrapolation.

For evaluation-contamination this is construct mismatch at unusual scale: a whole field's headline capability number, measured by an instrument that comes apart from the claim almost everywhere. For context-extension it means every window figure in the vault should be read as a buffer size until something measures what the model does inside it.
