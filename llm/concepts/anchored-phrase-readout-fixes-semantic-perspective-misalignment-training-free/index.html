Getting a usable embedding out of a VLM you already have loaded costs one forward pass and a prompt-format change — no fine-tuning, no architecture change, no reranking

This map's sub-thread on architecture/interface has mostly tracked how vision and text tokens are fused inside a model; this source is a different, deployment-facing question — how to get a directly usable representation back out of a frozen VLM for classification, retrieval, VQA-answer matching or grounding without any additional training. That question matters for this vault's premise specifically because it is a genuinely training-free technique: it works on whatever open-weights VLM checkpoint is already loaded, at the cost of one extra forward pass per query/candidate and a prompt-format change, with no fine-tuning run and no reranking pass required. The mechanism the paper isolates — anchor a readout phrase to the task's required semantic perspective via the answer-format text itself, then read that phrase's own contextualized multi-token state rather than the (arbitrary) last input token — beats every training-free baseline reported and, notably, beats every training-based MLLM embedding method in the same table too, meaning the failure it fixes (reading from the wrong internal position, not lacking task-relevant information) was costing more than the lack of fine-tuning was.

The representation-level probe is the part worth carrying independently of the benchmark numbers: it directly measures that changing only the answer-format anchor (task-oriented vs. content-oriented vs. none), while holding the input, instruction and extraction procedure fixed, moves the resulting embedding's cosine similarity to the correct topic representation from 0.960 to 0.981. That is evidence the anchor is doing what the mechanism claims — redirecting what the readout position encodes — rather than merely adding prompt tokens that happen to help.

Graded extends: this is a genuinely new training-free technique for this map's coverage of how to extract task-usable signal from a frozen VLM, not a contradiction of any standing claim. Graded strong: full 36-dataset MMEB evaluation across four task families, two backbone families at four sizes tested for generalization, two independent ablations each isolating one of the two mechanism components, plus a controlled representation-level analysis (not just downstream accuracy) supporting the causal story. Discounted for scope: all four tested backbones are Qwen-family (2.5-VL-3B/7B, 3.5-4B/9B) — no non-Qwen MLLM tested, so backbone-family generalization is unverified; task-specific prompts are hand-authored per MMEB task, leaving prompt-engineering sensitivity untested; and the method's one reported failure mode — weaker ablated variants outscoring the full method specifically on grounding (candidates that already carry strong localized visual cues) — is reported but not explained, which bounds how confidently "anchoring always helps" should be read.

Rebutted by: none — extends this map's coverage to a training-free representation-extraction technique rather than contesting an existing claim.
