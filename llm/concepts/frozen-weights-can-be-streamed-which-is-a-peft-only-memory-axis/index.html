The axis PEFT creates rather than deletes

distributed-training has organized itself around five answers to one memory ceiling — shard it, split the layer, shrink what you train, demote the optimizer to CPU, recompute the activations — and around one inference: the first four all attack terms that scale with trainable parameters, which PEFT has already shrunk, so rematerialization-trades-compute-for-the-activation-memory-nothing-else-shrinks is the one lever PEFT cannot delete.

layer_offloading is the case that argument has no slot for. It attacks the frozen parameters — the term PEFT creates. A full fine-tune has no frozen weights to stream; a QLoRA run is almost entirely frozen weights. So the relationship between PEFT and the memory hierarchy is not one of pure subtraction: shrinking the trainable set turns the resident base model into a large, read-only, sequentially-accessed object, and read-only sequentially-accessed objects are exactly what streaming is good at. You touch layer L's weights once in the forward pass and once in the backward pass, in a known order, which is the friendliest possible access pattern for a prefetcher.

Two implications worth carrying.

It is on a different term than everything else PEFT-adjacent. The 4-bit base already attacked the model term by shrinking each weight; this attacks it by not keeping all of them resident. They compose in principle — stream 4-bit layers — and nothing in-vault says whether that composition is affordable. Which raises the second point.

Affordability is exactly the question offload-efficiency-is-a-bandwidth-arithmetic-intensity-problem poses, and the docs do not answer it. Streaming weights over PCIe means the per-layer transfer must overlap with the per-layer compute, and a 4-bit LoRA forward pass at batch size 1 has very little compute per byte to hide behind — which is the same arithmetic-intensity trap that moe-sparsity-becomes-a-transfer-budget-when-weights-are-offloaded describes for expert offload, where the answer turned out to be an LRU cache plus speculative prefetch rather than naive streaming. The prediction this vault can make and should test: naive layer streaming will be bandwidth-bound at batch size 1, and the winning implementation will look like the MoE offload literature — cache the layers you will need, prefetch one step ahead — except that a dense stack's access order is deterministic, which makes it strictly easier than the MoE case where the router has to be guessed.

Also newly present in the consumer stack, and unpriced: activation_offloading: disk, motivated explicitly by long context in CPU-memory-constrained environments. This vault has treated storage as a training-memory tier as a datacenter technique via nvme-offload-removes-the-model-scale-ceiling; a single-GPU fine-tuning framework shipping it as a one-word config value moves it down-market. No bandwidth number accompanies it, from anyone.
