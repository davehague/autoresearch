Pay the packing once, offline, and the miss path becomes memcpy

Every expert-offloading system in this vault pays a miss in two currencies: the bytes across the bus, and the software work to turn those bytes into something a kernel will accept. moe-sparsity-becomes-a-transfer-budget-when-weights-are-offloaded measured the first and decomposed it — contiguous pinned buffers 0.661 → 1.168 tok/s, LRU cache → 1.567, speculative prefetch → 2.092 on a T4. This source attacks the second, and the design is almost embarrassingly simple: store the expert in the exact tensor layout the GPU kernel consumes, everywhere. Quantize and pack once, offline, into MARLIN-native packed qweights plus FP16 scales; hold that same object in the pinned host pool and in each GPU cache slot. A miss is then an async copy of the final representation. Nothing is dequantized, nothing is repacked, and — the consequence that matters for capacity planning — cache size no longer has to budget for a dequantization workspace, so slots cost exactly what an expert costs.

The second half is that a uniform packed representation makes grouping possible. Because every resident expert has identical layout, a layer's active set can be partitioned into cache-sized waves and each wave executed by one fused multi-expert kernel over the whole token matrix — two grouped GEMMs per wave, one fused gate/up and one down — with a global-ID-to-slot map and a sentinel for inactive experts. The alternative is a call per active expert.

The ablation isolating this is the note's load-bearing number and it is a clean one: matched 16-slot cache, identical W4 weights, sequential expert execution reaches 9.36 tok/s and grouped fused execution reaches 18.43 — 1.97×, with both paths producing the same 16 greedy tokens. So roughly half of what an offloaded W4 MoE runtime delivers is scheduling, not compression. That is a useful decomposition for anyone reading an end-to-end offloading number and trying to work out which idea in the paper is doing the work.

Two costs, both stated. Packing is not free at conversion time — 142.7 s against 4.71 s for a plain BF16 load — which is fine for a served checkpoint and annoying for iteration. And the representation is kernel-specific: MARLIN imposes dimension and grouping constraints and NVIDIA hardware, so "kernel-native" means native to one kernel. The idea generalizes; this instance does not port to llama.cpp or Metal without a new packing.

What this leaves on the table is the obvious composition nobody has built. This system uses plain LRU with no prefetching and pays 21.44 GiB of host-to-device traffic per 128-token request at 16 slots. expert-routing-is-predictable-one-layer-ahead and expert-prefetching-is-governed-by-the-worst-layer-not-the-average describe how to raise overlap past 99% by running the next layer's gate on this layer's hidden states with a per-token adaptive budget. Kernel-native packing plus adaptive prefetch would move the 16-slot operating point toward the resident one at the 16-slot footprint, and the two lines of work do not cite each other.
