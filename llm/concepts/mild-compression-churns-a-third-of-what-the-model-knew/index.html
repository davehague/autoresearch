Mild compression churns a third of what the model knew

post-training-quantization has held, since it was coined, that 4-bit weight representations retain the quality that matters. Every measurement this vault has taken supports that as stated: the entire FP16→INT3 sweep costs about 1.6 points on trustworthiness, INT4-GPTQ raises Llama-3.2-3B, perplexity moves negligibly. Nothing here refutes any of it.

What this refutes is the inference readers draw from it — that a 4-bit model is the same model, slightly noisier.

Measure the same regime as a knowledge-loss rate: of the questions the full-precision model answered correctly, how many does the compressed one get wrong. At 4-bit GPTQ, 30% WANDA and 5% layer dropping — the mild end, where aggregate metrics look untouched — it is 22% to 35%. The score holds because a comparable number of previously-wrong answers become right. The score is preserved. The answer set is substantially replaced.

Whether that matters depends entirely on what the model is for. For a benchmark average, or for a task where the specific facts are fungible, this map's existing advice stands unchanged and quantizing remains the right move. For anything that depends on which facts survive — a domain assistant expected to be reliable on a known question set, a retrieval-free knowledge lookup, an evaluation you plan to compare against a full-precision run item-by-item — a 22–35% churn at the recommended setting is a different proposition than "negligible loss," and no aggregate metric this vault currently records would show it.

The loss is unevenly distributed in the direction its companion finding predicts: under 5% ShortGPT, 19.1% on tail knowledge against 38–40% on middle and head. That is the same reversal compression-spares-the-tail-and-takes-the-head reports, arriving through a second instrument.

Three bounds, and the second is the one that limits how hard to push this. Three models at 8–9B, so nothing about scale. The popularity ordering does not replicate on Head-to-Tail, the paper's second knowledge benchmark, where mild and moderate compression give higher loss rates and a less consistent ordering — the authors report this without resolving it, so the churn magnitude is better supported than its distribution. And no code link is stated, so the protocol is not independently runnable.

The practitioner form: before and after a compression step, diff the answer sets, not the scores. It is a cheap check that this vault has never asked for, and it is the only one that would have caught this.
