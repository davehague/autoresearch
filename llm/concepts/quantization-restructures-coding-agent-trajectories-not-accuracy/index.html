Quantization's accuracy delta being flat is exactly the result that hides the interesting effect -- agentic coding behavior reorganizes under 4-bit weights even when the scoreboard doesn't move

TL;DR: This map's quantization-robustness evidence is overwhelmingly accuracy-delta-at-a-bit-width, and this source is the first in the vault to measure a quantized model acting as an agent rather than answering single-turn questions. Running four coding models (Qwen2.5-Coder-Instruct 7B/14B/32B, Devstral-Small-2507 24B) through an actual tool-use loop at BF16 vs. 4-bit AWQ/GPTQ, final accuracy differences are statistically insignificant for every model after Holm correction -- the standard quantization-robustness finding -- but the path to that accuracy is not stable at all: Qwen-7B's one-shot solves collapse from 17 to 0 (AWQ) / 3 (GPTQ) while its loop-based solves roughly double (10 to 25/20), and Devstral's failure-mode composition shifts significantly (the paper's only Holm-significant result), with Invalid-Return failures falling as Wrong-Answer and Timeout failures rise. Flat accuracy was concealing a real behavioral reorganization in both directions.

What it says. The effect is model-specific rather than a universal quantization signature: Qwen-32B's loop-dependence (71.3% tool-use rate, 0 one-shot/48 loop-based solves at BF16) is unchanged in kind by quantization, while Qwen-14B's roughly-balanced one-shot/loop split also holds. Only Qwen-7B shows the sharp one-shot-to-loop flip, and only Devstral shows the significant failure-mode shift -- so there is no single quantization-behavior rule across model families yet, only four data points that each move differently. This is a genuinely new axis for this map: every existing quantization-robustness finding here asks "how much accuracy is lost," and this source's contribution is the argument (not yet replicated) that accuracy alone can certify a quantized model as "fine" while its actual problem-solving process has been substantially altered -- relevant wherever an agent's tool-use pattern or retry behavior has downstream cost (more loop iterations = more tokens = more latency, even at unchanged final accuracy).

Caveats. One benchmark (OJBench), Python only, one quantization format family (W4A16 via AWQ/GPTQ, llmcompressor, 256 calibration samples), one agent scaffold (single python_executor tool, 5-call budget, 30s timeout), three seeds. All reported numbers are Easy+Medium only (Hard scored 0% everywhere), and absolute solve counts are modest (out of 115 problems x 3 seeds), which widens practical uncertainty around even large-looking shifts like Qwen-7B's one-shot collapse. No latency or memory measurement, so there is no connection yet to this vault's own throughput/VRAM accounting for 4-bit formats -- the contribution is behavioral, not a resource-cost number local-inference can use directly. Cross-linked to evaluation-contamination, which has established failure modes in how LLM-judged and benchmark-based evaluation can look stable while something underneath moves -- this is a quantization-specific instance of exactly that pattern, on agentic trajectories instead of judge verdicts.
