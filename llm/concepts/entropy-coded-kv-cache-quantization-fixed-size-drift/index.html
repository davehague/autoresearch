Fixed-width KV cache quantization was leaving bits on the table against its own preprocessing's output distribution — entropy coding claims them, and a bounded local reassignment keeps the result parallel-kernel-compatible

This map's "spending a fixed budget" strand already carries fixed-width KV cache quantization results and this run's own mixture-of-experts cross-reference to structured transforms improving rotation robustness. D-Quant's contribution sits one level below the quantization-format choice itself: given that this literature already rotates and normalizes KV values before quantizing (a step this map's other quantization sources also perform), the shape of the resulting distribution is approximately normal — concentrated near the center, sparse in the tails — which is exactly the shape entropy coding is designed to exploit and fixed-width coding is blind to. A b-bit fixed-width code spends the same bit budget on a common central value and a rare tail value; entropy coding doesn't.

The obstacle entropy coding usually runs into in this setting is the one this map's kernel-level sources keep surfacing: attention kernels need fixed-stride, parallel-dequantizable memory layouts, and naive entropy coding produces variable-length output. D-Quant's drift mechanism is the bridge: pose fitting entropy-coded assignments into a fixed-size container as minimizing reconstruction error plus a penalty on coded length, solved by bisecting a Lagrange multiplier; when the natural entropy-coded length would overflow the fixed container, reassign only the highest-coding-cost symbols to a nearby cheaper level. The reported touch rate is small (0.75% of keys, 5.00% of values, ≤1 level moved) — the compression gain from entropy coding is mostly preserved because the container-fitting correction is a minority operation, not a systematic re-coarsening.

Numbers: 2.26 bits/value against the strongest fixed-width baseline tested (OScaR) at 57-66% RULER accuracy at 128K context versus D-Quant's 71-75% (BF16 sits at 87-90%) — a real gap remains to full precision, but D-Quant roughly halves the accuracy loss the fixed-width baseline pays for the same compression class. The 3.5x throughput figure is a memory-bound, high-batch-size result specifically: the paper states D-Quant is slower than BF16 at small batch sizes because entropy decoding costs more compute than a fixed-width unpack, so the win is conditional on being memory-constrained enough to trade some per-token decode compute for more concurrent sequences fitting in HBM.

Graded extends: this is a coding-layer improvement layered on top of the rotation-preprocessing pipeline this map's other quantization sources already assume, not a contradiction of anything on the map. Graded strong: quantified across two models, six context lengths, two benchmark suites, with the mechanism's own approximation error (the drift touch rate) reported rather than asserted away. Discounted for scope: two models at 8B scale only — nothing at 70B+; the calibration-free probability model assumes near-normality after rotation, and the paper does not explore what happens when a model's KV statistics depart from that assumption; and it inherits, rather than tests, the Hadamard-rotation preprocessing step as a prerequisite.

Rebutted by: none — extends the map's quantization-format catalogue rather than contesting an existing claim.
