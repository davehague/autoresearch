Three cells, not four

distributed-training's cross-cutting note names the cheapest useful unrun experiment in this vault: peak memory and step time for a 4-bit LoRA fine-tune at a realistic sequence length, with and without gradient checkpointing, and with and without CPU activation offload. That phrasing assumes a 2×2 grid. Two official tool docs, from two unrelated teams, say the grid has three cells: offloading operates on the tensors checkpointing decided to keep, so offload=on, checkpointing=off is not a configuration anyone can run.

That is a small correction with three real consequences.

The experiment gets cheaper and better specified. Three configurations, not four, and the third one is "checkpointing plus offload" rather than "offload instead of checkpointing" — which is a different question than the vault was asking. The right framing is not which activation lever, it is how far down the hierarchy do the surviving activations go: kept in VRAM, or demoted to host RAM, or (in Axolotl) to disk.

It explains a number that had looked too good. nvme-offload-removes-the-model-scale-ceiling carries ZeRO-Infinity's pricing of CPU activation offload at under 2 GB/s, which the vault read as "trivially affordable over PCIe" and filed as slightly surprising. It is affordable because it is not moving the activation stack — it is moving the O(√n)-ish checkpointed subset that activation-memory-is-a-tunable-continuum-not-a-fixed-cost describes. Checkpointing does the heavy reduction; offloading relocates what is left. The two compose because the second is defined on the output of the first.

It sharpens the elimination argument. rematerialization-trades-compute-for-the-activation-memory-nothing-else-shrinks reasons that PEFT already shrinks every memory term that scales with trainable parameters, leaving activations as the binding constraint on one card, and so recomputation as the one technique PEFT cannot delete. The tooling agrees from the other direction: torchtune states that fusing the optimizer step into the backward pass shows "no meaningful impact when finetuning LoRA recipes," which is the same observation about the same term. For a LoRA or QLoRA run on one card, the levers that still move the needle are precision, checkpointing, and where the checkpoints live.

What neither doc supplies is magnitude. There is not one measured peak-memory figure, step time, model or GPU on either page — these are capability inventories. So this raises confidence about what is possible and what is mutually exclusive and adds nothing about how much anything costs. The backlog item stays open; it is now better posed.
