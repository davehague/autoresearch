A hybrid model's bounded recurrent-layer state is a timing oracle for streaming its attention layers' KV cache across the CPU-GPU boundary on unified-memory hardware

TL;DR: TideCache treats a hybrid LLM's two cache types — a small, fixed-size recurrent state and a large, context-growing attention KV cache — as one memory-management problem rather than studying either alone. A Transparent Cache Pool lets both share physical GPU memory behind fixed virtual addresses, so the split between them can be rebalanced without touching either component's layout. A Cache Streamer exploits the fact that the recurrent layers are cheap and always GPU-resident: their processing time is used as a predictable timing cue to prefetch the next global-attention layer's KV prefix from host memory into shared GPU slots just ahead of when it is needed, while freshly generated KV stays resident. A Request Scheduler then picks, per request, whether a layer runs resident or streamed. On GB300/GH200 superchips (CPU-GPU unified memory) via SGLang, this completes up to 2.04x as many agent turns in a fixed time budget, cuts P50 per-token latency 20-59%, and improves agent-workload P50 time-to-first-token 1.40-3.05x against SGLang + HiCache.

Why it matters here. This is the map's first source to manage a hybrid model's two structurally different cache types as a single, rebalanceable memory pool rather than compressing either one in isolation — every prior entry here (eviction, quantization, depth-axis caching, cross-layer/cross-model reuse) assumes one cache type and one GPU's worth of memory. It also lands the same week as frontierreplay-exact-prefix-caching-hybrid-lms (ingested 2026-11-21, primary map speculative-decoding/kv-cache-management territory via hybrid-model prefix caching): both exploit the identical structural fact — a hybrid model's recurrent state is small, bounded, and resides, while its attention KV is large and bursty — but in opposite directions. FrontierReplay avoids recomputing recurrent state across requests/branches by checkpointing it at structural boundaries; TideCache streams the attention layers' KV between host and GPU within a single request, using the recurrent layers' residency and timing as the prefetch signal. Neither refutes the other; together they say a hybrid model's two layer types are increasingly being engineered as two separate memory tiers with different reuse strategies, which this map had not previously had a vocabulary for. Also extends memory-hierarchy-offload's CPU-GPU demotion thread to a hardware class that map has not seen — a superchip with coherent CPU-GPU unified memory rather than a PCIe-attached host, which may relax that map's standing finding that optimizer-state offload needs up to 1.5 TB/s and is usually not worth it on commodity links. And it bears on speculative-decoding's "verification cost belongs to the backbone, not the draft" framing for hybrid models (recurrent state is path-dependent and expensive to replay per speculative-tree branch): TideCache's design implies the backbone's attention half, not its recurrent half, is the component worth moving off-GPU, consistent with that map's account of where the hybrid-model cost actually sits.

Caveats. No institutional affiliation stated on the abstract page; author list includes Song Han, whose lab has other systems work already in this vault (e.g. vr-sparsequant-fp4-24-sparsity), but this is not a stated affiliation. No code-release link listed. GB300/GH200 are datacenter-class CPU-GPU superchips — a standing gap against this vault's consumer-hardware premise — though the same unified-memory architecture, at smaller scale, underlies some prosumer devices (e.g. the DGX Spark/GB10 already in-vault on speculative-decoding), so the mechanism may be partially reachable there; untested. The comparison baseline is specifically SGLang + HiCache; no comparison against vLLM's own hybrid-serving or offload stack. No accuracy/quality evaluation reported (pure throughput/latency systems paper), and no combination with KV or weight quantization is tested.
