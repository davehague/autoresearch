Speculation's memory bill is paid by the prefix cache

prefix-reuse-attacks-prefill-and-needs-no-concurrency is one of the few serving levers on local-inference that pays at batch size 1: a reused prefix skips its prefill, which matters most in exactly the multi-turn, long-system-prompt, agent-loop workloads a single user runs. It only pays while the prefix is still resident, and residency is a memory question.

Bole supplies the first in-vault measurement of another technique evicting that reuse as a side effect. Tree speculation over a recurrent backbone allocates transient state per proposal node — up to 24.0 GB at batch 4 with 128 nodes on a 27B model. That memory comes out of the same pool the KV cache and its reusable prefixes live in. Cut it by 90% and, with the same drafter, the same tree and essentially the same acceptance (mean accepted tokens 6.38 vs 6.29), the prefix-cache hit rate goes from 58.3–69.7% to 90.8–92.6%, TTFT falls by up to 67.6% and TPOT by up to 49.9% on an agent trace.

The reading that transfers past hybrid-attention models: memory pressure is transitive, and speculation's memory bill is not usually counted. The map's currency test asks what each local lever spends — arithmetic, bandwidth, VRAM — and prices them against each other. Speculation has been filed as spending idle arithmetic, with speculation-and-quantization-compete-for-the-same-headroom as the one known contention. This adds a second, and it is a contention with the lever most likely to be running alongside it on a single-user machine. A drafter, its own weights, and a tree of candidate states all sit in the memory that would otherwise hold a reusable prefix — and the loss shows up as prefill you have to redo, which no speculation benchmark measures because they benchmark decode.

Two honest bounds. The measured effect is on a recurrent backbone, where transient state per candidate is unusually large; over a plain KV cache the candidate tokens' own cache entries are far smaller, so the magnitude will not transfer even if the direction does. And the workload is a multi-turn agent trace on a serving engine, not a single-user chat — the hit-rate difference is partly a load effect (the baseline's hit rate falls from 69.7% to 58.3% as pressure rises, which is itself the mechanism showing up).

The cheap unrun check for this vault's reader: run any speculative decoder on a local engine with prefix caching enabled, over a multi-turn conversation, and report the hit rate with and without speculation. Nobody has, and it is a configuration a person with one card actually uses.
