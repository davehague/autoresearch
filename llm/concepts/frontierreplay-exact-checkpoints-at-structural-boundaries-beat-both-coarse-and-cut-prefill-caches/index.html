Exact prefix caching for hybrid models no longer has to choose between wasting reusable prefixes and cutting the prefill pass to save them

TL;DR: Hybrid language models mix self-attention with recurrent layers whose state updates happen in place, which makes ordinary prefix caching awkward: saving state only at a coarse grid of positions throws away most reusable prefixes, while saving it everywhere a prefix might later be reused means cutting the prefill forward pass at each mid-prompt checkpoint — and those extra scheduler steps can cost more than the reuse they enable. FrontierReplay exploits the observation that, across multi-turn chat, agent loops, document QA, and tree search, prefix reuse almost always resumes at predictable structural boundaries (a turn's end, a known branch point) rather than at arbitrary positions. It materializes exact checkpoints only at those boundaries while letting the prefill pass run uncut, logging a short window of recurrent-layer inputs around each boundary and using a cross-layer, state-only replay kernel to reconstruct the exact state from that log — 6-37x cheaper per token than full recomputation, with no host synchronization required. A frontier-aware retention policy prioritizes active anchors and promising branches, lending unused checkpoint slots to the ordinary attention KV cache instead of leaving them idle. The result beats existing exact caches on time-to-first-token, SLO capacity, and goodput, and — unlike most compression trade-offs on this map — also beats approximate (lossy) replay on goodput while keeping exact accuracy rather than trading one for the other.

Why it matters here. This lands on kv-cache-management's recurrent-state-compression cluster (RAM-Net, SPARE, HST, and the training-free per-frame streaming cache for hybrid VLMs), but attacks a different failure mode than any of those: not how much recurrent state to retain under a budget, but how to reuse an exact copy of state across requests without the prefill-cutting tax every prior exact cache pays. It also supplies transformer-architecture's hybrid-model lineage (Gated DeltaNet → Kimi Linear → GDN-2 → Muir) with a serving-time cache-reuse mechanism none of those sources address — they optimize the recurrent layer's own compute or parameterization, not cross-request cache reuse. That exact caching here beats approximate replay on both speed and accuracy, where most of this map's other compression levers trade one for the other, is itself worth flagging as a reversal of the map's usual pattern.

Caveats. Two-author paper with no stated institutional affiliation or code/weight release; the headline ranges are reported across unspecified "diverse" architectures, scales, and workloads rather than one controlled, fully-itemized sweep. All reported metrics (SLO capacity, goodput) read as datacenter multi-tenant serving figures; no single-user, consumer-hardware latency number is given. No test of composition with this map's existing token-axis eviction or quantization methods on the attention side of the same hybrid model.
