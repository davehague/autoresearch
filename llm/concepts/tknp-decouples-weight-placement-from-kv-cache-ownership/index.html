Splitting "who holds the weights" from "who holds the KV cache" in distributed LLM decode serving beats both data parallelism and decode context parallelism, by moving only current-token activations across nodes instead of whole-model replicas or partial attention results

TL;DR: Shrestha, Settlemyer and Reddy target a specific bottleneck in distributed LLM decode serving: data parallelism replicates the full model per node, capping per-node KV capacity; tensor parallelism's attention-splitting stops once you run out of KV heads and gets collective-communication-expensive across nodes; decode context parallelism (DCP) grows KV capacity by sharding the sequence, but then must merge partial attention results across nodes every decode step. Their method, Decode Token Parallelism (TKNP), keeps one model copy total, split into layer blocks across nodes; the currently-active node runs the batch's projections and MLP with intra-node tensor parallelism, while each node computes attention only for the requests whose KV cache it locally owns — so only current-token activations cross the network, never partial attention results or full-model weights. Implemented in vLLM and evaluated on Llama 3.1 405B and Nemotron-4 340B across up to 64 H100 GPUs, TKNP improves completion throughput up to 1.7x over DCP and up to 2.06x over data parallelism at matched GPU count on long-context, high-concurrency workloads.

What it says. This gives kv-cache-management's "where the budget comes from" sub-thread (the strand that enlarges the serving-time KV budget via collectives and tokens/s/GPU rather than compressing cache contents) a fourth distributed topology, and the first in-vault comparison to specifically beat DCP — the map's own existing budget-enlarging method — rather than only compressing-the-contents approaches. It bears directly on local-inference's standing complaint that every KV-cache serving measurement in the vault is datacenter hardware: this result is again measured at 340-405B parameters on up to 64 H100s, so the magnitude does not transfer down, though the underlying principle — decouple cache ownership from active compute, move only activations — is architecturally scale-agnostic in a way this paper does not test at smaller scale. Cross-linked to distributed-training and pipeline-parallelism as a serving-time instance of splitting work across the same tensor/data/layer axes those maps track for training, not serving.

Caveats. Three-author team, no stated institutional affiliation found on this read; implemented in vLLM but no repository link found for this specific implementation. All evidence is datacenter-scale (340-405B models, up to 64 H100s) — no consumer-hardware or single-node numbers. The DCP and data-parallelism baselines are the authors' own vLLM implementations; no third-party replication exists yet, and tensor parallelism's own ceiling is named in the paper's framing but not separately benchmarked against TKNP in the results described here.
