A model-support release is also a VRAM-gate measurement: most new open-weight families still don't fit a consumer card, even once the runtime supports them

llama.cpp's v0.5.0 release (2026-09-23) adds support for six new open-weight model families (HRM-Text/DFM Mimir 1B, MiMo-V2.6, HunyuanOCR, Nemotron MTP/Nemotron-H, Qwen4Exp, Muse Glimmer), Metal MoE and SSM_CONV fusion optimizations for Apple Silicon, CUDA conv2d acceleration via implicit GEMM for multimodal projectors, and a new llama_adapter_lora_init_from_file_ptr() C API for loading LoRA adapters from a file pointer. ggml, the vendored tensor library, bumps to v0.25.0 the same day.

The fact worth carrying into this map: runtime support for a model family is necessary but not sufficient for local deployment. Per third-party tracking at release time, only two of the six newly-supported families produce a quantized GGUF that fits a 24GB consumer card — MiMo-V2.6-Distill-Qwen-9B (9.53GB) and Muse Glimmer 30B (16.76GB) — while the other four either exceed that budget or ship without a practical consumer-reachable quantization. This is the map's currency-test framing (what does a result actually cost on one card) applied to a model-support release rather than a method paper, and it names something papers rarely do: the gap between "llama.cpp can run this architecture" and "this specific checkpoint fits in 24GB."

The Metal MoE and SSM_CONV fusion work is directly relevant to this map's standing complaint that nearly every serving measurement in the vault is datacenter hardware — this is Apple-silicon-specific backend work — but the release notes report no benchmark numbers for it, so it is recorded as an open question (does the fusion work actually move tokens/s on a Mac) rather than a confirmed finding.

Caveats: this is a dependency/tooling release note, not a benchmarked study — "this code shipped" is not "this code was measured to help." The 2-of-6 VRAM-fit figure is a third-party snapshot at release time, not from the official release notes, and will shift as the community publishes further quantizations.
