A cache quantizer built for dense/GQA attention treats MLA's two cached tensors as one object; splitting the quantization by role (value-bearing latent vs. score-setting positional key) recovers accuracy a shared transform loses

TL;DR: RoLaQ (rolaq-jointly-calibrated-rotation-fixes-2bit-mla-kv-cache, already on this map) established that MLA's shared-latent cache needs its own jointly-calibrated rotation and quantization range rather than a dense-cache quantizer applied unchanged. RAQ-MLA (University of Chinese Academy of Sciences / Tencent) takes a different cut at the same object: rather than one calibrated transform for the whole cache, it splits MLA's two cached tensors — the shared latent (both score and value) and the decoupled positional key (score only) — and fits each its own transform based on the error it contributes to the attention output. Neither paper cites or compares against the other, so this map now holds two independently-motivated, non-head-to-headed answers to "how should an MLA cache be quantized," both beating generic dense/GQA-cache quantizers (KVarN, QuaRot, OSCAR) adapted to MLA.

What it says.

The setup. MLA (DeepSeek-V2/V3's attention design) caches a single compressed low-rank latent per token plus a narrow RoPE-carrying positional key, rather than per-head dense keys and values. This map's existing MLA-specific entry, RoLaQ, treats the shared latent as the object needing a jointly-calibrated rotation plus quantization range. RAQ-MLA instead observes that the latent and the positional key play different roles in the attention computation — the latent supplies both the matching signal and the value read-out, while the positional key, carrying relative-position information, mostly determines the attention score — so an error in the latent corrupts both halves of attention at once while an error in the positional key corrupts only the score half.

The method. RAQ-MLA fits a separate, invertible transform to each tensor, with the fitting objective being each transform's contribution to the resulting attention-output error (not raw per-tensor reconstruction error) — a role-aware split rather than a joint whole-cache calibration. The method is training-free.

The result. Across four MLA models and reasoning/math/code benchmarks, the full cache holds at ~2.5 bits/element with average benchmark deltas near zero against BF16 — beating three cache-quantization baselines adapted from dense/GQA attention (KVarN, QuaRot, OSCAR), none of which reach as low a bit count at comparable accuracy. The one clear gap is RULER long-context retrieval at a (higher) 2.66 bits/element, where RAQ-MLA trails BF16 by about 3.3 points — the retrieval task this map's own eviction-family entries have repeatedly found to be the hardest workload for any compression method to pass cleanly.

Caveats. CC BY-NC-ND 4.0 license — no commercial use, no redistributed derivatives — unusual for a technique paper rather than a model release; no code or weights release stated. All four test models are MLA-lineage (DeepSeek/Moonlight/GLM derivatives); no non-MLA cache is tested, so the role-split argument is not shown to generalize to GQA. No comparison against RoLaQ exists in either direction — whether role-splitting or joint rotation-calibration is the better MLA-cache strategy, or whether they compose, is unanswered.
