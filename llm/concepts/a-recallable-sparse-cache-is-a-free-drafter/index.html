Two techniques on the same cache, and only one of them has to be right

The KV cache is normally the object of a destructive decision: evict, merge, or quantize, and live with the consequence. This source uses it as the object of a reversible one, and that difference is the whole finding.

Draft by running the target model over a sparse view of its own cache — per layer and per head, keep sink tokens, a recent window, and the top-K_mid historical positions by S_{l,h}^{(i)} = Σ_{q=T−W+1}^{T} a_{l,h}^{(q→i)}, the attention those positions received from the last W=16 queries. Then verify all k drafted tokens in one parallel pass over the complete cache. Two properties follow, and they are the reason this belongs on a KV-cache map rather than only on a serving one.

The importance signal is free. The scores are not computed; they are recycled from the attention weights the previous verification pass already materialized. No extra forward pass, no separate scoring model, no calibration.

And nothing is destroyed, so the index is a hypothesis rather than a commitment. The original dense KV tensors stay resident. The sparse index is rebuilt after every verification step, so a token that looked unimportant at step t and matters at step t+1 is simply back. Contrast the static-compression drafters this replaces — MagicDec built on StreamingLLM or SnapKV — which permanently discard context and therefore accumulate irreversible fidelity loss over a long generation. That is exactly the failure mode what-eviction-deletes-is-two-sums-not-a-set-of-tokens attacks from the other side: ResKV keeps a compact reconstruction of what it threw away; this keeps everything and throws away nothing, spending memory instead of quality.

The result: 72.9% acceptance, 11.26 accepted tokens per step, 2.79× on LongBench v2 where a downloaded trained drafter reads 1.95% and 0.89× (a-downloaded-drafter-is-a-bet-on-its-training-distribution). Speculating over an approximate cache while verifying over the exact one is the same structural trick this vault has seen before: guessing which weights or which context you need is free to be wrong — the MoE expert-prefetch lesson from 2026-07-26 — because the guess is checked by something exact. Here the exact check is the lossless verification rule, so the output distribution is preserved by construction.

The condition worth stating precisely: this trades memory for the option to be wrong. It requires the dense cache to be resident, so it is not a memory-saving technique at all — it is a latency technique that presupposes you already paid for the cache. Every other method on this map exists because you could not. That makes it complementary to eviction and quantization rather than competing with them, and nobody has run it on top of either, which is the obvious next experiment and the one that decides whether it survives on a card where the cache is the binding constraint.

Bounded: one A40 at 48 GB, batch size 1, contexts capped at 64K, generations capped at 128 tokens — short for long-context reasoning, which is the workload that would amortize speculation best. No quantized base anywhere. And the verifier deliberately uses dense non-FlashAttention kernels in order to materialize the per-head statistics, so C_v is inflated for every arm in the comparison; the authors say so and call fused kernels future work. Sparse-index maintenance costs a real 41.1 ms per decoding iteration at 60K, which is the number to watch if anyone fuses the rest.
