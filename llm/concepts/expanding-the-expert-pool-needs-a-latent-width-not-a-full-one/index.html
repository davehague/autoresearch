Fine-grained experts have a width problem, and the answer is a latent space

mixture-of-experts has carried since DeepSeekMoE that fine-grained experts are the direction the architecture is heading, and AlphaQ's 2026-07-25 finding sharpened it — fine-grained MoEs have far more exploitable variance than vanilla ones, so allocation techniques pay most where the field is going. Kimi K3 is the largest published instance of that direction: 896 routed experts, 16 live per token, against Mixtral's 8-of-8 and DeepSeekMoE's much smaller pool.

The structural finding is that you cannot get there by scaling the vanilla design. In a conventional MoE each selected expert receives the full d-dimensional token representation, so communication volume and expert-weight traffic grow with the routing multiplicity — 16 active experts is 16 full-width dispatches. LatentMoE splits the widths instead: shared experts keep the full 7,168 path for transformations every token needs, while routed experts operate in a compact latent space of 3,584 (0.5×). This is a different lever from the one this map has been tracking. Sparsity buys FLOPs; latent width buys bandwidth, which — per this map's own 2026-07-24 edge result and 2026-07-26 offload result — is the currency that actually binds.

Two failure modes this map records as having "standard fixes" both come back at this scale, which is the honest half of the finding.

Activation explosion. The routed path composes a down-projection, a gated multi-branch expert FFN and an up-projection into nearly four consecutive matmuls; at 2.8T that structure produces exploding internal activations. Two fixes: an RMSNorm between expert aggregation and the up-projection, and SiTU-GLU, which applies softcap(x, β) = β·tanh(x/β) to both the gate and the up branch (β₁=4, β₂=25, bounding |f(x)| ≤ 100). The motivation is precision, not just stability: SwiGLU is unbounded in both multiplicative factors, so coincident large coordinates make outliers, and outliers "increase overflow risk in low-precision arithmetic" — which connects this directly to the map's MXFP4 decision (quantization-can-be-a-training-decision-not-a-post-hoc-one) and to the activation-outlier story post-training-quantization has carried since SmoothQuant.

Load balancing. This map's settled answer is auxiliary balance losses, upgraded by Switch's router z-loss. K3 uses auxiliary-loss-free routing (a per-expert bias added to the router score for Top-k selection, omitted from the mixture weights so it steers dispatch without touching gradients) and reports that the standard fixed-step bias update b ← b + γ·sign(ē − ē_j) "remains challenging" at 896 experts per layer, because slow adaptation leaves experts poorly trained. Quantile Balancing replaces the step rule with a closed-form target: route with Top-(k+1) so the (k+1)-th entry gives each token's cutoff, then set each expert's bias to the (1−k/n)-quantile of its margins. At scale the exact quantile is not computable across ranks, so each expert's quantile is read from a histogram of its margins — additive counts, one all-reduce, a few hundred bins per expert, and the pooled estimate is exact up to the bin width regardless of how tokens are sharded.

Graded suggestive, not strong, and the reason is important: the 2.5× scaling-efficiency figure is an aggregate over architecture, data and training-recipe changes, fitted at 1e20–1e21 FLOPs and read off far above that. There is no ablation isolating LatentMoE, SiTU-GLU or Quantile Balancing individually, and no independent replication of any of them. What is strong here is the existence proof that 896-expert routing trains stably at all; what is weak is any claim about how much each piece contributed.
