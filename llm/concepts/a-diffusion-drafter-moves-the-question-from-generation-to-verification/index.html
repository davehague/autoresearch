A diffusion drafter moves the question from generation to verification

The speculative-length literature has one shape: estimate how many of the next γ tokens the target will accept, and draft that many. speculation-length-has-a-closed-form-inversion-point is this vault's version of it — γ has an optimum because each additional draft token costs another drafter forward pass and buys a decreasing probability of surviving verification.

That cost model is a property of autoregressive drafters, and it quietly stopped holding. A diffusion drafter generates a candidate block in parallel, so the marginal cost of the twentieth draft token is approximately the cost of the fifth. The paper states the consequence directly: this shifts "the key question from how many tokens to generate to how many generated tokens are worth verifying." The tokens already exist; what you are choosing is how much of them to pay the target to check.

Recast as expected-speedup optimization, the rule becomes marginal — extend only while "the added segment provides a higher acceptance-gain-to-verification-cost ratio than the current sequence" — applied iteratively against the drafter's own confidence scores. It is training-free and plug-and-play, with a proof of monotone convergence to the optimal length, and it is lossless: the target still verifies, so the output distribution is preserved, keeping the property speculation-trades-arithmetic-for-latency-without-moving-the-distribution makes load-bearing for every stacking argument on this map.

Two structural notes for speculative-decoding.

First, this is the drafting-side counterpart to the map's recent verification-side findings, and it points the same way. verification-cost-is-a-property-of-the-backbones-memory-structure and the-verification-budget-has-an-interior-optimum both concluded that checking, not drafting, is where the cost and the tunable optimum live. A drafter whose generation cost approaches zero is the cleanest possible demonstration: when drafting is free, all of the optimization is about verification, and the method that falls out is entirely a verification-budget rule.

Second, the temperature numbers are a small independent datum on a question this map opened nine days ago. a-drafters-acceptance-rate-depends-on-the-temperature-you-decode-at found block drafters emitting independent marginals degrade monotonically with the target's sampling entropy, recoverable by +5.6–5.8% at T=0.7 and +9.3–12.1% at T=1.5. Here both endpoints appear on the same rows and the fall is much gentler: accepted length 5.11 → 4.94 on MATH-500 and 3.43 → 3.29 on MT-Bench from T=0 to T=1, roughly 3–4%. Weak evidence that these diffusion drafters carry more within-block dependence than a naive independent-marginal block head — different targets, different drafters, no shared baseline, so it is a lead rather than a result.

Graded strong: six targets from 4B to a 30B-A3B MoE, three independent diffusion-speculation base methods, four benchmarks across three task families, greedy and sampling both reported, a convergence proof, no per-model fitting. Discounted on scope rather than rigour — one hardware platform (A100) at one context length (1K), which is neither the bandwidth-bound single-stream decode where local-inference's currency test says speculation pays most, nor the long-context regime where the verification optima move. The 8.49× headline is a best cell; the band to plan against is 2.1×–3.5×.

The method's own precondition is the thing to watch: it rests on draft confidence correlating with target acceptance, which the authors say "gradually deteriorates" with speculative depth and requires model-specific maximum lengths. The failure is bounded rather than silent — a miscalibrated criterion wastes verification, it does not corrupt output — which is the same asymmetry moe-sparsity-becomes-a-transfer-budget-when-weights-are-offloaded found for expert prefetch: guessing which work to do is free to be wrong; guessing what to output is not.
