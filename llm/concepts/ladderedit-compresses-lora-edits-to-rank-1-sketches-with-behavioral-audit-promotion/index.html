A new sub-area for this map: LoRA as the storage unit for lifelong model editing, where strand 2's "bill" question (what adaptation costs on one card) becomes "what does keeping thousands of small adaptations cost, and how much of each is actually load-bearing"

This map's strand 2 ("the bill — what adaptation costs on one card": peak memory, energy, checkpointing/offload riders, a quantization run's own budget) has so far priced training-time and serving-one-adapter costs. LadderEdit introduces a cost this map has not carried before: the persistent storage cost of accumulating many small LoRA-style updates over time, in the specific setting of lifelong model editing (sequential factual-knowledge corrections, not task adaptation). The storage unit is still a LoRA adapter — so the object is squarely this map's — but the question (how much of each individual edit's adapter is behaviorally load-bearing, measured per-edit via a spectral predictor plus a behavioral audit, rather than a single rank/learning-rate choice applied uniformly across a training run) is structurally different from anything on strand 1 (the LoRA-vs-full-fine-tuning contest) or the rest of strand 2.

Why graded open-question rather than extends. No prior entry on this map addresses lifelong editing, so there is no existing claim to extend or confirm. The closest adjacent finding is this map's own freeze-decoder-heal-encoder-svd-kv-cache-peft (2026-10-10 — SVD-based KV-cache healing, cross-linked to kv-cache-management), which is a different kind of post-hoc compression entirely (healing a compressed KV cache via LoRA-style fine-tuning, not compressing stored LoRA adapters themselves). Whether LadderEdit's rank-allocation-by-behavioral-audit idea composes with, or is orthogonal to, this map's rank/initialization contest in strand 1 (which has mostly argued about ranks chosen before training, not ranks allocated after acquisition based on a passed/failed behavioral check) is an open question this vault should flag for a future model-editing synthesis if this sub-area grows.

The coverage-before-fidelity principle is the transferable idea. Independent of the lifelong-editing setting, LadderEdit's central empirical claim — most of a LoRA update's behavioral effect survives a rank-1 truncation, and only a genuine minority of updates need their full rank — is a measurement this map's rank-allocation thread (AdaLoRA and similar adaptive-rank methods are already baselines here) has not reported in this form: not "what rank does training converge to," but "what rank does a completed update actually need to keep working," checked against an explicit behavioral contract rather than a spectral-energy threshold alone (the paper's own compression-regularized population — 4-7% of edits where a cheaper sketch passes where the exact update fails — is evidence the full-rank update is not itself a behavioral ceiling).

Caveats carried from the source. LadderEdit is not constant-memory — persistent storage still grows linearly with edit count (every edit retains at least a rank-1 sketch), the opposite failure mode from GRACE/WISE/MEMOIR, which bound memory but lose generalization at scale per this paper's own WikiBigEdit results. The behavioral audit is explicitly described by the authors as "soft-coverage," not a correctness guarantee — a sketch can pass on probed prompts while misbehaving on unprobed ones. Evaluated on three 7-8B backbones only; no test beyond 8B scale or with a non-LoRA edit-writer. Yale / WashU / Mount Sinai / ASU; EMNLP 2026 Main Conference; code released per the source.
