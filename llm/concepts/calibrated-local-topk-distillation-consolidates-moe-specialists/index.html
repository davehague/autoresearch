Merging several separately-optimized domain specialists back into one MoE base model is itself an on-policy-distillation problem, and the fix for one teacher's loss scale drowning out another's is the same kind of lever this map has already seen matter more than the choice of divergence

TL;DR: This map's multi-teacher on-policy-distillation strand has so far been about routing during training a student toward whichever teacher helps most at a given moment (mid-rollout switching, farthest-KL selection). This source poses an adjacent but distinct problem: consolidating several already-fully-trained domain specialists — each separately post-trained on math, code, instruction-following, or agentic data — back into one shared dynamically-routed MoE base, without one domain's gradient signal swamping another's. Calibrated Multi-teacher On-policy Distillation (C-MOPD) assigns each prompt to exactly one frozen domain teacher via a task router, computes the distillation loss on the student's own on-policy generated prefixes against that teacher's local top-K token support (both distributions renormalized over the support, loss = reverse KL), and divides each token's loss by that specific teacher's own loss standard deviation within the microbatch before clipping — a calibration step the paper's own ablation shows is load-bearing: removing it costs nearly as much measured performance as removing the top-K-support restriction entirely. On an in-house 20B-total/2B-active MoE (Turing-20B-A2B), the consolidated model retains 90-114% of each domain specialist's own gain (exceeding the standalone Code and Agent specialists on their own scores), and beats both its own SFT baseline and Qwen3-8B on a four-benchmark reasoning mean at an 8K response-token cap — though that comparison flips on at least one benchmark once both models are given a 32K cap, and GPQA Diamond specifically regresses versus the SFT baseline.

What it says.

Problem framing. Where this map's existing multi-teacher sources ask "which teacher should train this token," C-MOPD asks "how do several already-specialized teachers get folded back into one generalist without each domain's distillation signal fighting the others' at the loss-scale level." A task router sends each training prompt to one frozen domain specialist; supervision is computed on the student's own sampled rollouts (on-policy, in this map's established sense), not teacher-generated text.

Local top-K support with calibration. At each response position, the assigned teacher's top-K logits (K=16 for the main results) define a local support; both teacher and student distributions are renormalized over that support before the reverse-KL loss is computed — trading completeness (no direct constraint on probability mass outside the support) for a cheaper, more stable local match. Because different domain teachers' losses live on different scales, each token's loss is divided by that teacher's own token-loss standard deviation within the current microbatch (floored at 0.1, detached, then clipped at 5) before fixed domain weights (0.3 for IF, 1.0 for Math/Code/Agent) are applied.

Results. Four-domain macro integration score 0.9988; per-domain specialist-gain retention Math 94.07%, Code 100.93%, IF 90.16%, Agent 114.35% (the consolidated model modestly exceeds its own Code and Agent specialists on their own domain score). Calibration ablation at K=32: full method 0.9962 vs. no-clipping 0.9834 vs. no-calibration 0.9724 vs. sampled-token (rather than top-K-support) distillation 0.9208 — no-calibration alone costs nearly as much as abandoning the top-K-support mechanism, which is the paper's clearest evidence that loss-scale calibration, not just which tokens are supervised, is doing real work. Reasoning-mode four-benchmark mean at an 8K cap: 85.92 (C-MOPD) vs. 80.33 (Qwen3-8B) vs. 74.21 (own SFT). GPQA Diamond regresses 5.05 points versus SFT (40.40 -> 35.35) even as the aggregate mean improves.

Caveats. The "beats SFT and Qwen3-8B" claim is an aggregate across four benchmarks, not a sweep — GPQA Diamond moves the wrong direction, and the comparison against Qwen3-8B is response-budget-dependent (at least one benchmark, MATH-500, favors Qwen3-8B once both models get a 32K token cap instead of 8K). The calibration ablation runs at K=32, not the K=16 used for the headline consolidated-model numbers, so the two sets of results are not from an identical configuration. Everything is measured on one in-house model (Turing-20B-A2B, XPeng Inc. Foundation Model Team); no code or weight release is stated, and no independent replication exists. No comparison is made to this map's existing single-domain OPD sources on consolidation specifically — the "several specialists back into one base" problem has no other in-vault instance to compare against yet.
