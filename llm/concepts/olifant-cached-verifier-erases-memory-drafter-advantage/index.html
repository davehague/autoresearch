A within-paper demonstration that a drafter's measured advantage is only as real as the verifier cost it was measured against — here the verifier's own cost changes, not the drafter's, and the conclusion is identical

TL;DR: This map's standing lesson from dcd-decoupled-contrastive-decoding — that accepted length and wall-clock speed can disagree once a drafter's own cost changes — gets a mirror-image demonstration: hold the drafter fixed and change the verifier's cost (KV caching) instead, and the same disagreement appears. Without a KV cache, Olifant's near-free CPU lookup (0.16-0.25ms) clearly beats a 254ms/token neural drafter, because the expensive, uncached verifier pass dominates total cost regardless of which drafter proposes tokens. With a KV cache, the verifier itself drops to 16.3-16.9 tok/s, and suddenly every drafter's own cost matters: the neural drafter's fixed per-token overhead no longer gets amortized against an expensive verifier call, and it becomes a net energy loss relative to cached plain decoding. Olifant survives this transition only where domain match keeps its acceptance rate high enough to clear its own (much smaller, but non-zero) overhead.

What it says. The paper's own energy-optimal-vs-speed-optimal draft length split (k=3 energy-optimal, k=3-5 speed-optimal, because verifier power rises with draft length under caching) is a joules-per-token framing this map rarely carries explicitly — most entries report tokens/sec or accepted length. This is a candidate addition to the map's open "what does speculation cost on the machine this vault is about" question, on an energy axis distinct from HyFlash's drafter-memory-budget framing and AdaSpark's end-to-end llama.cpp throughput framing — a third axis (energy per token, not memory or raw throughput) on the same standing question, untested against either. The non-neural drafter itself is also this map's first instance of a classical (non-gradient-trained) ML method as a drafter, distinct from every prior drafter-provenance entry (downloaded small model, self-speculative pass, trained MTP head, sparse-cache view, resident distilled expert, pretrained-and-adapted backbone) — an eighth provenance option, not run head-to-head against any of the other seven on one backbone.

Caveats. Single-author, no peer venue stated, code and models released. One hardware platform (Mac Studio M1 Max) and one verifier (Mistral-7B-v0.1) — no server-GPU evidence, and no comparison against this map's own dedicated neural drafters (DFlash/DSpark/EAGLE-class), only a single TinyLlama-1.1B data point. Greedy, batch-size-1 only — this map's standing concurrency complaint applies here too, and whether a memory-based drafter's near-zero marginal cost survives batching (where a neural drafter's cost amortizes across a batch while a lookup-table's does not obviously grow) is untested in either direction. Domain-matched vs. domain-unmatched comparisons are confounded with the EurLex corpus's own cross-document redundancy, which the author partially but not fully separates from the method's general applicability.
