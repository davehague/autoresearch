The same method, the same budget, and a forty-five-point spread depending on when you compress

This source evaluates every method under two construction settings, and reporting both is the most useful thing it does.

Query-aware: the downstream question is appended to the context before the cache is compressed, so token-importance scores are computed with the question visible. This is the standard reporting setting in the KV-compression literature.

Query-agnostic: the cache is built from the reusable context alone, and the query arrives afterwards.

On RULER at 32K with LLaMA-3.1-8B and 10% of the KV budget retained, AdaKV reads 72.20 query-aware and 26.92 query-agnostic. Same method, same model, same budget, same benchmark — a 45-point gap produced entirely by when the compression happened.

The second setting is the one that describes deployment, and the paper says so plainly: it "better matches practical serving because the cache is compressed before the next user query is known." That is not a marginal claim in this vault. local-inference holds prefix caching as a core serving lever (kv-reuse-must-be-exact-prefix-to-stay-lossless, prefix-reuse-attacks-prefill-and-needs-no-concurrency), and the entire point of a reusable prefix is that it is built once, before the queries that will hit it. A compression scheme that needs the query in hand is not compressing a prefix cache; it is compressing a single-turn context that will be discarded.

Three consequences.

A published KV-compression number is a claim about a protocol, and the protocol is usually the flattering one. This is the same shape as the recipe-leakage mode evaluation-contamination flagged on 2026-07-25 and generalized on 2026-07-30 — a preparation choice that moves the number by more than the method does, reported inconsistently or not at all. Here it moves the number by 45 points. Two honest papers can report "AdaKV at 10% retained" and differ by more than the entire span of methods they are comparing.

Method rankings are not stable across the two settings, and the differences are wider in the honest one. The residual-reconstruction improvement measured here is +4.54 query-agnostic against +2.22 query-aware — roughly double. Which makes sense: with the query visible, a token-scoring rule can find the few tokens that matter and a cheap method looks nearly as good as a careful one. Without it, the method has to preserve general recoverability, and how it does that starts to matter. So the setting that resembles deployment is also the one with more discriminative power, and it is the one the field under-reports.

And it puts a number on the gap between "long context works" and "long context is cheap." At 10% retained and 32K, the best query-agnostic result here is 32.74 against a full cache's 88.57. That is a considerably harsher picture of KV compression than the query-aware column suggests, and it is the column a serving stack lives in.

The operating rule this map should carry: a KV-compression result absent its construction setting is uninformative, and the default assumption for a deployment decision should be the query-agnostic number — or the absence of one.
