The cache-free layer ratio is a design variable, not an inherited constant

local-inference usually reads results that were produced for a datacenter and then asks whether they survive the trip to one card. This one was produced the other way round. The author fixed the target first — "one user, one token at a time, 4-bit weights, ordinary CPU" — and derived the layer composition from it.

The argument is three lines long and does not depend on the architecture that comes out of it. At batch size one there is no batching to amortise weight loading over, so throughput is bytes-read-per-token. Memory bandwidth binds before compute, so an architecture doing more arithmetic over fewer bytes runs faster. And the key–value cache is a per-token tax linear in context, tolerable under batched high-bandwidth GPU serving and dominant at batch one on a CPU. Only the third is a design lever, and pulling it means making most layers carry a constant-size state.

Daedalus keeps full attention in 6 of 18 blocks. The other 12 are depthwise short convolutions at kernel length 3, so their recurrent state is exactly two timesteps wide regardless of context. Cache bytes per context token: 6,144 for the hybrid, 12,288 for the parameter-matched 24-layer all-attention twin — exactly twice, despite the twin's narrower per-layer cache, because it has four times as many attention layers.

What makes this a finding rather than a design note is the shape of the measurement. The advantage is 1.20× at empty context, 1.45× at 512, 1.76× at 2048, and reproduces against an external 135M peer written by a different author at 1.06× / 1.49× / 2.08×. A model that were merely leaner would show a constant ratio. A model whose advantage is the cache it does not keep shows near-unity at depth zero and divergence after — which is what both comparisons show, and the author retires two earlier figures from the project's own history for failing this test (1.29× as unreproducible, 1.15–1.17× as the depth-zero floor quoted as a result).

The experiment is also unusually well-guarded. Both arms were trained on identical data and schedule, parameter-matched within 0.5%, the metric and a 0.5% margin floor were pre-registered, peers were re-scored on the same harness rather than quoted from their papers (the author notes published means run 0.5–1.5 points high, so quoting would have manufactured a point of advantage), and throughput arms alternate within a single pass so background load perturbs both equally. One confound runs against the hybrid: the reference runtime's attention graph is far better optimised than its convolution path.

Two things this is not. It is not a quality win — the hybrid clears the pre-registered bits-per-byte floor by 0.81% but the five-task mean is a tie the author declines to spin (44.68 vs 44.82, about 0.24σ), and the 2T-token peer in the same table stays 3.9 points ahead, conceded before training began. And it is a single author, single seed, English-only result on a CPU described only as "ordinary" with 8 threads, so the absolute throughputs are not reproducible even though the within-pass ratios are the reported quantity.

The transferable claim is the ratio, not the operator. The author's own framing: the contribution is not a new operator but the observation that in the batch-size-one CPU regime the ratio of cache-free to attention layers is the dominant deployable design variable, and that a depthwise convolution was chosen over a selective-scan state-space layer specifically because it maps onto existing CPU kernels without new operators — i.e. because it exports to a stock runtime.
