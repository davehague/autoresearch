A discrete code trained end-to-end for the task doesn't have a continuous distribution to drift away from as the compression ratio tightens -- which is likely why this is the first entry on the map where compression ratio and accuracy don't trade off together

TL;DR: Every lever this map already tracks compresses an already-materialized, continuous key/value representation after the fact — decide what to keep (eviction), at what fidelity (rotation-based quantization, anchor-plus-residual), or in what axis (depth partitioning). Transformer-FSQ instead changes what the key/value projections produce in the first place: a finite scalar quantization bottleneck makes the cache discrete by construction, with no per-token metadata (no scale, no zero-point) to carry alongside the codes. Converting a pretrained model costs a cheap adaptation pass (0.25 tokens/parameter, not a from-scratch retrain). Tested against five baseline families on 0.6B-8B models, it is the most accurate method on RULER at every compression ratio tried, from 12x up to 97.5x — holding accuracy further out on the ratio axis than anything else measured here. A fused Triton kernel decoding directly from integer codes is faster than native uncompressed attention at high compression (1.54x at 97.5x), not merely smaller — the first entry on this map where the throughput number is a genuine win rather than a tax paid for memory savings.

What it says. The mechanism explanation the paper's framing implies — a discrete code trained end-to-end for the task has no continuous target to drift away from as the ratio tightens, where methods approximating a continuous distribution necessarily degrade as the approximation coarsens — is a candidate general answer to this map's "why does everything else fail beyond moderate ratios" problem, worth testing against the map's other training-based instrument (RAM-Net, which migrates pretrained transformers into a different recurrent representation rather than requantizing the existing one). It also sharpens the map's live "does the factor decomposition predict which compositions interfere" open question: if FSQ's codes are discrete and metadata-free, composing it with a token-eviction policy (decide which tokens' codes to keep) is structurally cleaner than composing continuous-quantization methods with eviction, since there is no scale/zero-point interaction to worry about — untested here.

Caveats. The adaptation step, while cheap, is a training-based cost this map's training-free levers (SPARE, RAM-Net's training-free variants, data-free rotation) don't carry — a different cost profile, not a strictly better one. No code release stated at ingest time. RULER measures long-context retrieval specifically; whether the accuracy advantage holds on reasoning-heavy or generation-heavy tasks, where this map's own eviction-family evidence shows compression damage concentrates differently than on retrieval (the "salience is not trust" finding), is untested. Baselines are compared using their own authors' kernels "where available," so the throughput comparison is not uniformly matched across every baseline family.
