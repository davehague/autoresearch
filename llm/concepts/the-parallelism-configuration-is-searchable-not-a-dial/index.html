Measure the model, then choose the axis

Every parallelism source in this vault argues for its own axis. PipeDream argues for none of them. It profiles the model — 1,000 minibatches on a single machine, recording per layer the forward+backward compute T_l, the activation/gradient size a_l, and the parameter size w_l — and then runs a dynamic program that jointly picks the stage partition, the per-stage data-parallel replication factor, and the number of in-flight minibatches, minimizing the slowest stage. O(N^2 M^2) total, seconds of work.

The result is the interesting part. In all but one experiment the optimum was a mixture — neither pure data parallelism nor pure model parallelism. And in that one exception the search declined to pipeline: Inception-v3 on 8 machines of the faster-network cluster has only 5% communication overhead, so the optimizer returned plain data parallelism, and the system measured exactly BSP. The same model on the slower-network cluster got a 7-1 pipeline worth 1.45×. Same model, same code, different answer — because the answer is a property of the deployment, not the architecture.

This is the vault's third instance of one pattern, and the pattern is worth naming. FSDP found that the sharding factor is sharding-is-a-dial-between-memory-and-communication with measurably wrong settings in both directions. Gradient checkpointing's original paper searches a memory budget rather than exposing a boolean (activation-memory-is-a-tunable-continuum-not-a-fixed-cost). PipeDream searches the parallelism configuration. Three independent systems, three memory/communication trade-offs, and each one concludes that the right setting is a search over a budget rather than a default. What almost no tool ships is the search.

For a one- or two-card practitioner the dynamic program is overkill, but the transferable rule is not: profile the specific model on the specific hardware before choosing a strategy, because the optimum flips between a 25 Gbps and a 10 Gbps link for an unchanged model, and it flips again with the worker count.

Bound: 2018, convolutional and recurrent models up to 16 GPUs; the cost model assumes communication time is bytes divided by link bandwidth, which ignores contention and topology. Nothing here is a transformer, and the DP's objective is throughput per step, so it optimizes hardware efficiency and leaves statistical efficiency to the weight-stashing argument (asynchronous-pipelining-buys-bandwidth-with-gradient-freshness).
