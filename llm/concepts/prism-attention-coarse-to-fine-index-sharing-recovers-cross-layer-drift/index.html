The bandwidth budget this map named has its own internal tax, and it was being paid in accuracy rather than bytes

sparse-attention-buys-bandwidth-and-spends-memory established that this map's eviction, quantization and depth-partitioning methods all spend the memory budget, while token-level sparse attention spends the bandwidth budget instead — deciding which of the full, resident cache to actually read each step. That framing left an unstated assumption: that deciding which tokens to read is itself free, or close to it. It is not. Recomputing the top-k relevant-token index at every layer is expensive enough that production sparse-attention methods share one layer's computed index across several neighboring layers rather than recomputing it everywhere — and this paper is the first in-vault source to measure what that sharing costs: attention patterns drift from layer to layer, a shared index increasingly mismatches what a downstream layer actually needs, and the mismatch gets worse as context grows.

The fix exploits structure in the drift, not just its existence. The authors show the drift is not uniform churn — the core high-attention tokens stay stable across nearby layers, and almost all the change concentrates at the edges of the previously selected region. Prism Attention turns the shared anchor-layer index into a wide coarse proposal (e.g. top-512 instead of top-128) and does a cheap, layer-specific refinement within that wider region, rather than either recomputing the full index per layer (expensive) or reusing it unchanged (the accuracy-losing status quo). This is a third point on the bandwidth-budget axis, distinct from anything else this map holds: it does not change what gets stored or how much gets read, only how cheaply and accurately the which-to-read decision gets made.

Where this sits against the map's existing bandwidth entry. sparse-attention-buys-bandwidth-and-spends-memory's BinaryPC never materializes attention scores at all — it selects via hash codes, so it has no per-layer index-staleness problem to begin with, at the cost of adding 1.56% to the cache's own footprint. Prism Attention takes the opposite trade: it keeps the standard top-k selection mechanism (and its design rule from that entry — "a cache method's throughput is decided by whether its selection rule needs the attention matrix" — applies to Prism as written, since refinement still operates on attention-derived scores) but fixes the specific cost of sharing that selection across layers. The two are not measured against each other and solve adjacent but different sub-problems within the same budget.

Caveats. Datacenter-only (NVIDIA H800s) and 4-8B models in the detailed tables — nothing on consumer hardware, which is this map's and the vault's standing complaint. The accuracy edge over the next-best published baseline (IndexCache) is consistently small (1-2 points), and both methods share the same offline calibration pipeline for their sparse-budget hyperparameters, which narrows but does not eliminate a tuning-advantage concern. No code release noted at ingest time.
