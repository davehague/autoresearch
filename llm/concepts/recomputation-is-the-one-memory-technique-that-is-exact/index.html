The counterexample to infrastructure non-equivalence

evaluation-contamination carries infrastructure non-equivalence as the third of four ways a benchmark number misleads, and every instance so far has run one direction. Sharded optimizer math is not guaranteed equivalent to local training, and nothing in the output says so (sharded-optimizer-math-is-not-locally-equivalent). Asynchronous pipelining is worse and knows it: without weight stashing the update "is not a valid gradient of the loss function for any weight vector," and the mechanism that would restore data-parallel equivalence ships disabled (asynchronous-pipelining-buys-bandwidth-with-gradient-freshness).

Recomputation is the counterexample, and it is the only one the vault has. The paper states it in the experimental setup rather than the abstract, which is telling: "all the memory optimizations proposed in this paper give equivalent weight gradient for training and can always be safely applied." The reason is structural — the technique discards a stored value and reproduces it by rerunning the same deterministic operation. It changes when a number is computed, never what it is.

That gives a clean ordering for a practitioner who is out of memory, and it is the ordering nobody writes down:

  1. Turn on gradient checkpointing first. It costs about 30% of a step and changes nothing about the result you will report.
  2. Then reach for the levers that change the math — sharded optimizer states, asynchronous pipelines, reduced-precision accumulation — and record which ones you used, because they belong in the experimental configuration.

For an audience comparing small fine-tunes against each other, the distinction is not academic. A result table that silently mixes a checkpointed run with an unsharded one is comparable; one that mixes a ZeRO-3 run with a local one is not, and neither run will tell you.

Caveat on scope. The exactness claim is about the transformation, and it is a claim about the computation graph, not about floating-point bit-identity — the paper says "equivalent weight gradient," not bit-exact, and reordering operations can change rounding. It is also 2016 and pre-dates the transformer, so it is stated for the general graph rather than verified for attention. Nothing here rescues perplexity-does-not-rank-quantization-formats or any other failure mode; this narrows exactly one of the four, for exactly one technique.
