The wire decides, and on commodity interconnect the answer is no

Ring Attention's overlap is free when the compute for one blockwise attention step outlasts the transfer of the next key/value block. Blockwise self-attention costs 4dc² FLOPs; the KV blocks move 4cd bytes. Requiring 4dc²/F ≥ 4cd/B reduces to a single inequality:

c ≥ F/B — block size at least the host's FLOPS-to-bandwidth ratio — and since six blocks are resident, minimum per-host sequence length s = 6c.

This is the most practically useful thing in the source, because it is a precondition you can evaluate on paper before running anything, and because the answer varies enormously across hardware that looks similar:

HostFLOPSInterconnectMin per-host sequence
A100 + NVLink312 TF300 GB/s6.2K
A100 + InfiniBand312 TF12.5 GB/s149.5K
TPU v4275 TF268 GB/s6.2K

The same accelerator differs by 24× based purely on the wire. That is the general shape of the finding: F/B rises when accelerators get faster and interconnect does not, so this technique gets harder to satisfy over time on any given fabric — the same directional warning kernel-performance-expires-with-the-gpu-generation makes about kernels, arriving here as a property of a distributed algorithm.

For this vault's premise the conclusion is unwelcome and worth stating plainly: sequence parallelism is a datacenter technique. Consumer hardware has the worst possible ratio — high single-device FLOPS behind PCIe — so two 4090s over PCIe would need a per-host block far larger than anything they could hold, which is a contradiction rather than a tuning problem. Ring Attention extends context-length-scales-linearly-with-device-count to 16M tokens on a TPU pod and offers a practitioner with two GPUs nothing at all.

That is a different failure mode from the one this vault usually tracks. Most techniques here degrade gracefully off their measured hardware; this one has a hard threshold, and below it the communication stops overlapping entirely rather than partially.

Bound: the derivation deliberately excludes the query/key/value projections from the compute side, which the authors note makes the condition stricter than reality — so the table is conservative, by an unquantified margin. Bandwidths are nominal unidirectional peak, not measured achieved. Nothing in the paper tests a configuration that violates the condition, so the cost of doing so is predicted rather than observed.
