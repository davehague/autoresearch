Two answers to the same question, and only one of them is cheap information

Filtering a generated corpus pays (filtering-a-generated-corpus-outperforms-generating-more-of-it). This is about which filter, and the winning one is not the obvious one.

The standard move for verifiable tasks is self-consistency: sample K solutions to a generated problem, take the majority answer as the label, and reject the example if agreement falls below a threshold — low agreement means the problem is either mislabeled or too hard to be useful training signal. It works, worth +2.1 points here over no filtering.

The better move exploits an asymmetry the generation step created. Because the generator is asked to solve its own new problem in the same pass that constructs it, there are two independent answers available: the one produced while reasoning about how to build the problem, and the majority vote produced later by a model given only the finished problem. Answer-Consistency rejects the example when those two disagree. That is worth +4.2 over no filtering and +2.1 over self-consistency alone (57.2 vs 55.1) on the same prompt pool.

The stated reason is the interesting part: the generation-time answer "has access to more information" — it emerged from a trace that decided what the problem should be, chose the quantities, and knew the intended solution path. The inference-time majority is a cold solve. So the filter is not two samples of the same estimator; it is a construction-time label checked against a solve-time label, and agreement between two differently-informed processes is a stronger signal than agreement among K draws from one.

This generalizes into a design rule worth carrying on data-curation: generate the label and the item together, and keep the label as an independent reference. A pipeline that emits only problems and labels them afterwards has thrown away the cheapest verification signal it will ever have. The same shape appears in speech-sourced-captions-replace-the-teacher-vlm — where PixMo-Docs derives Q&A from the code that generated a chart rather than from the rendered image — and in both cases the move is to find a channel where ground truth already exists rather than to re-derive it.

For open-ended tasks where no answer exists, the paper falls back to a reward-model filter that scores an instruction by the lowest-rated of K responses to it: a prompt that admits any bad response is a bad prompt. That reaches 56.2 on the reasoning tasks too — below Answer-Consistency, which is the honest ordering: a verifiable reference beats a learned preference proxy when you can get one.

Graded suggestive. The comparison is clean (one prompt pool, one training recipe, filters varied) but it is a single setup — one generator, one 4B student from the same family, four small benchmarks with no confidence intervals — and the mechanism claimed for why the generation-time answer is better is an argument, not something the paper isolates with an ablation. Neither filter is free: both cost K additional generations per candidate, and no compute accounting appears anywhere.
