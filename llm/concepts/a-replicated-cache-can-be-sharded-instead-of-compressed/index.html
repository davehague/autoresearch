A replicated cache can be sharded instead of compressed

kv-cache-management was coined around one question — given a fixed budget, what do you keep and in what form? Every answer so far spends quality to fit: eviction (kv-eviction-is-a-quality-spending-lever-and-its-own-numbers-say-so), rotation to 3.5 bits (a-data-free-rotation-puts-the-kv-cache-at-three-and-a-half-bits), anchors plus residuals, depth partitioning (the-kv-cache-can-be-compressed-along-depth-not-tokens), learned restoration. This is the first arrival that declines the premise: the budget was an artifact of how the model was sharded.

The diagnosis is specific. Tensor parallelism splits the KV cache by attention head, which works only up to num_key_value_heads; past that the cache duplicates on every rank. Multi-head latent attention is the degenerate case — one shared latent "head," so the cache is replicated in full on every GPU no matter the TP size. Decode Context Parallelism shards along sequence position instead: AllGather the queries, run attention on each rank's local KV slice, then AllGather and ReduceScatter the partials, merged by online-softmax reweighting. That last step is why there is no quality term — partial softmax results carry their running max and denominator, so the merge is arithmetically identical to full-cache attention.

Measured on 8×B200 with Kimi K2.6 in NVFP4: baseline TP hits 100% KV memory at concurrency 64 and plateaus at 1,863 tok/s/GPU; DCP reaches 6,091 tok/s/GPU at concurrency 512 on 82% KV memory. 3.27× per GPU, exact.

The map should carry both framings with the boundary between them stated: compression is the answer when the memory is genuinely absent — one card, one machine; sharding is the answer when it is present but replicated. Almost every compression result this vault holds was measured in the first regime and none of them says so, which means the compression literature's baselines are systematically the harder case. That is not a criticism of those results; it is a scope condition on transferring them to a multi-GPU box.

Two things this does not settle. Throughput is measured at high concurrency, exactly where the two extra collectives per decode step per layer amortize across many sequences; per-token latency at low concurrency under DCP is unmeasured, and the vault's currency test predicts that is where the bill lands — the mirror image of cache-compression-charges-throughput-and-pays-only-under-pressure. And the post is silent on interaction with prefix caching and chunked prefill, which is where re-partitioning a cache is most likely to have consequences; kv-reuse-must-be-exact-prefix-to-stay-lossless is the constraint that would have to be checked.

Bounds. T2 — a primary engineering post from the team shipping the runtime, with the mechanism stated at the level of the collectives, working flags and explicit divisibility constraints, which is as good as this tier gets. But one hardware configuration, one model, one chart, no latency axis, no accuracy check (structurally unnecessary, still unreported), and prefill/decode disaggregation named as future work.
