The encoder is the repeated cost, not the cache

vision-language-models has had no local serving numbers at all — the map has said since Qwen2.5-VL that nothing tells us what llama.cpp does with a vision tower — and this map's serving layers were all derived from text-only workloads. Here is the first measurement, and it inverts the priority order every text result would predict.

A multi-turn conversation about one 1024×1024 image on Qwen3-VL-8B, on an M4 Max:

TurnLatency
1 (cold)21.7 s
21.15 s (19×)
3+0.78 s (28×)

21.7 seconds for the first turn is the number to remember, and it is the encoder rather than the language model — which is why local vision-language use feels broken in a way local chat does not.

The ablation is the finding: vision embeddings alone are worth 7.8×; the KV cache alone is worth 1.2×. In a text conversation, prefix reuse is the lever (prefix-reuse-attacks-prefill-and-needs-no-concurrency). With an image in the context, it is a rounding error next to caching the encoder output. The reason is structural rather than incidental: text prefix reuse saves a prefill that was already cheap per token, while an image's encoder pass is a fixed, large, non-incremental cost the model pays again on every single turn.

The enabling trick is small and worth naming, because the naive version fails silently. Identity is established by SHA-256 over decoded pixel values, not over the reference — so the same picture arriving as a URL on turn one, a base64 blob on turn two and a file path on turn three still hits the cache. That is kv-reuse-must-be-exact-prefix-to-stay-lossless's exact-match requirement relocated to a place where the obvious key does not detect identity that plainly exists.

This adds a clause to the map's regime rule. The rule was many users → batch continuously; one user, single-shot → speculate; one user, multi-turn → cache the prefix. Now: one user, multi-turn, about an image → cache the embeddings, and it is worth an order of magnitude more than caching the text prefix.

It also composes cleanly in the map's own idiom, which is not something the vault can say often. The map's newest structural lesson is to ask what currency each lever spends — the reason speculation and quantization failed to add (speculation-and-quantization-compete-for-the-same-headroom) is that both spend idle arithmetic. This lever spends memory (156 MB per cached 1024×1024 image) to buy repeated encoder compute, a currency nothing else in the local stack is competing for, which is why it adds cleanly. And the win is entirely conditional on repetition: the 28× is turn three of a conversation about one picture, the cold-start 21.7 s is unimproved, and one-shot image queries get nothing.

Graded suggestive: the ablation is one model at one resolution on one image, so the 7.8×/1.2× split is a single measurement rather than a curve; the author is the tool's own vendor; there is no quality evaluation anywhere in the source; and the machine is a 128 GB M4 Max, where a 156 MB embedding cache is free in a way it would not be on a 16 GB laptop — which is precisely where the video numbers (12.1 GB for 64 frames) would bind first.
