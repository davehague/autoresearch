Guessing right is worth less than not needing to guess

This vault's prior finding on offloaded mixture-of-experts inference is expert-routing-is-predictable-one-layer-ahead: run layer L+1's gating function on layer L's hidden states and you know which experts to prefetch with recall around 0.8–0.9, and the rule that generalized from it was that guessing which weights you need is free to be wrong, unlike speculative decoding, which guesses tokens and must verify.

This source takes the opposite move and it works better in the one place it applies. Rather than predicting the target's natural expert routes and prefetching them, AcceptMoE restricts which experts the verification pass is allowed to use, and orders that restriction by what is already resident: selected non-resident experts are ranked by commitment-weighted demand and the lowest-demand prefix is pruned, subject to a rerouting budget and a minimum set size. Eligibility becomes a function of the LRU cache's current contents. There is no learned expert predictor, no prefetch schedule and no auxiliary model inference — the machinery runs inside the serving engine after the verification block is fixed, from router logits it already has.

The isolated ablation is the evidence: enabling residency-aware pruning alone cuts host-to-device expert traffic 38.6–48.6%, raises the expert-cache hit rate 6.9–8.2 points, and improves throughput 4.6–15.1%, for 0.27 points of mean accuracy across 12 model–task pairs. The full method takes traffic down 73.6–77.1% against standard speculative decoding and the fetch-stall share of wall time from 65–78% to 27–35%, for 2.06× throughput.

The two approaches are not in conflict and the boundary is legible. Prefetching answers "what will I need next, so I can start the transfer early" — a latency-hiding play that needs lead time and tolerates being wrong. Residency conditioning answers "of the things I could use, which are free" — a demand-shaping play that needs no lead time and cannot be wrong, because it reads the cache rather than the future. Prefetching is right for the autoregressive decode step, where the route is what it is. Residency conditioning is available only where the consumer has slack about which weights it uses, and speculative verification is exactly that case: the eligible expert set is a choice, not a fact.

The price is stated plainly by the authors and belongs in this vault's ledger. Masking the target's router logits changes the model distribution, so this is not a distribution-preserving speculative decoder — it sits with lossy-verification-silently-replaces-the-target-distribution rather than with speculation-trades-arithmetic-for-latency-without-moving-the-distribution. Worse in kind: lossy verification alters the acceptance rule, which a different rule could restore, whereas this alters the target's own forward pass, which nothing downstream can correct. The measured cost is small (0.27 points mean, per-pair range −1.83 to +1.22) and it is not zero.

Scope: batch size one, three MoE targets at 30 B and 120 B, one offloading configuration, no composition with the resident-draft-expert approach that attacks the same bottleneck from the drafter side.
