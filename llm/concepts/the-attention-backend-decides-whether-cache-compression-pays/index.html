The kernel decides whether the compression pays

The efficiency table in this source is presented as an implementation note and is the most transferable thing in the paper. The same method, the same model, the same workload, measured under two attention implementations, gives two opposite answers.

Under eager SDPA, the compressed cache is 9.8% faster end to end and peak memory is flat — a modest win with no downside. Under FlashAttention-2, peak memory falls 29.7% (29.54 GB to 20.78) and throughput falls 59%, to 218 tok/s, which is below the uncompressed eager baseline at 379. Two of the four cells are strictly worse than doing nothing.

The mechanism is stated plainly: the implementation reconstructs low-bit windows before attention and falls back to SDPA at routing events in order to expose attention probabilities, which is exactly what a fused flash kernel refuses to materialize. So a technique that needs attention scores as a signal is structurally at odds with the kernel family that exists to avoid writing them down — and the harder the kernel is optimized, the more the fallback costs. That is the same tension attention-is-memory-bound-not-compute-bound set up in the other direction, and it means the compression literature and the kernel literature are quietly optimizing against each other.

For local-inference this is the second measurement in two days of the rule stated on 2026-08-06: a runtime comparison absent its runtime configuration is uninformative. There the term was a process memory allocator worth 2.3× on a CPU backend (the-cpu-inference-bottleneck-was-the-memory-allocator); here it is the attention backend, worth 2.5× in the other direction. In both cases the unreported configuration term is larger than every method term in the comparison.

Applied to kv-cache-management the consequence is uncomfortable and specific. Not one source on that map reports its attention backend. The eviction, residual-reconstruction, depth-partitioning and cross-model-transfer entries all report quality against a retention ratio and, where they report speed at all, report it once. If the sign of the throughput result depends on a kernel choice, then the map's efficiency claims are conditional in a way none of them says.

The practitioner form is narrow and usable: if you are compressing a KV cache to save memory, expect to give up the fused kernel, and measure both. The memory saving is real and only shows up in the configuration that costs throughput; the throughput saving is real and only shows up in the configuration that saves no memory.
