The repair term has a closed form if you pick the saliency function for one

The vault's compression-repair notes are almost all trained repairs — an-adapter-can-repair-what-eviction-deleted, a-per-language-rank-two-adapter-repairs-a-quantized-model, quantizing-only-the-residual-shrinks-qlora-error, and the whole quantization-aware-healing line. Each is a small optimization run bolted onto a deployed artifact. This one is not: the adapter values are solved for.

The trick is a design choice upstream of the math. Pick a saliency function that is invertible and additive, and the optimal low-rank correction to the compression-induced error falls out analytically. LQ-LoRA initializes adapters from the SVD of the quantization error and then trains; LoSparse does the same for pruning error; RoSA adds a sparse adapter alongside. All of them need iteration. SLiM computes the answer.

Two structural properties make it more interesting than the numbers alone. The framework is agnostic to the mask selector — Wanda, or the same thesis's OPTIMA and PATCH, or whatever replaces them — and compatible with standard quantization kernels, so it composes with the field's moving parts instead of replacing them. That is the opposite of the usual joint-compression paper, which ships one fused pipeline you adopt whole.

The claim worth flagging carefully is "outperforms uncompressed dense models at equal parameter budgets by up to 0.6%." That is a compressed large model beating a dense small one at matched parameter count — the same comparison post-training-quantization settled years ago in the 4-bit case and a different question from whether compression is free. It belongs in the note because it is the thesis's headline, not because it is news.

The premise-relevant number is the RTX 3060: 3.78× layer-wise speedup on a 12 GB consumer card, which is a rarer measurement in this literature than the A100 figure beside it. But it is layer-wise, not end-to-end generation throughput, and that gap is exactly what a-memory-saving-and-a-decode-speedup-are-different-quantities measures on a different substrate: a compressed layer that runs 3.78× faster in isolation can still leave decode slower once dequantization, cache format and dispatch are in the loop. Sparsity acceleration also presumes hardware that exploits N:M structure; on a CPU or an Apple-silicon runtime, 2:4 buys memory and no compute at all.

The author's own future-work section names the hole. The pipeline is sequential — quantize, then prune, then correct — and a joint "quantized sparse-plus-low-rank" formulation with tighter error bounds is unsolved, as is verifying that the Robust-PCA incoherence assumptions the theory would borrow actually hold for pretrained weight matrices. So the closed form is optimal for the last step given the first two, not for the composition.
