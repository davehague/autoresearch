The evicted tokens were never the point; their two sums were

Write attention with the normalization opened up: o = N_S(q)/Z_S(q) where Z_T(q) = Σ_{p∈T} e^{a_p} and N_T(q) = Σ_{p∈T} e^{a_p} v_p. Split the full set S into the retained main cache M and the evicted complement E. Then Z_S = Z_M + Z_E and N_S = N_M + N_E, and hard eviction is precisely the operation that drops (N_E, Z_E) and renormalizes over M alone.

That reframing does the work. The literature this vault holds — H2O, SnapKV, TOVA, AdaKV, and the counter-causal-surprise scheme ingested 2026-07-31 — treats the problem as which tokens to keep, and improves by scoring tokens better. But the quantity lost is not a set of tokens; it is two sums, and sums can be approximated cheaply even when their terms cannot be stored. Partition E into r groups (Lloyd iterations on key-space distance, run independently per layer and per KV head after prefill) and store for each group only a mean key k̄_j, a mean value v̄_j and a population count c_j. Since nearby keys induce similar logits, Σ_{p∈C_j} e^{a_p} ≈ c_j e^{ā_j} — the count is what carries the aggregate mass, and it costs one scalar.

The implementation detail that turns out to be load-bearing is that residual entries enter the same softmax as exact tokens, via the logit ā_j = ⟨q,k̄_j⟩/√d + log c_j + log g(q), rather than acting as a post-hoc correction to the output. Ablating that — separate normalizations for the main and residual branches — costs 3.00 points on RepoBench-P. Hard eviction is recovered exactly when the residual budget is zero, so the method is a strict generalization of the family it improves on.

Two failure modes it navigates between, and both are already in this vault. Eviction deletes aggregate mass that diffuse attention needs — the 2026-07-31 ingest measured that bill directly, at up to 13.3 AIME points at 25% retention. Merging (CaM, KVMerger, KeepKV) preserves more of the mass but folds evicted states into retained slots, perturbing keys and values that should stay exact; measured here, SnapKV+CaM lifts NrtvQA 19.43 → 20.27 while dropping HotpotQA 36.48 → 34.98, i.e. it is unstable in the direction the theory predicts. Keeping the residual separate from the exact cache is what avoids both.

The gains land exactly where the mechanism says they should: distributed-evidence tasks — Variable Tracking, FWE, multi-key retrieval, RepoBench-P, LCC, Passage Retrieval, TREC — where useful signal is scattered across many individually low-scoring positions. On single-needle retrieval, where one token carries everything, there is nothing aggregate to restore, and the dynamic gate exists precisely to withhold residual mass when main-cache attention is already sharp (p_max^M(q) > τ = 0.25).

Read the size of the win honestly. It is a relative improvement over a compressed baseline, not a recovery of the full cache: at 10% retained on 32K RULER, 26.92 → 32.74 is a real +5.82 and still 56 points below the uncompressed 88.57. Compression at that ratio remains expensive; this makes it less expensive.

Bounded: two 7–8B grouped-query-attention backbones, one A100-40GB, one seed, no code link. Residual entries are constructed once after prefill and never refreshed, which matches reusable prefix-cache serving and not generation-heavy workloads — the authors say so. And nothing here is quantized, so how residual entries interact with 2-bit KV quantization, the other lever on the same budget, is untested in both directions.

Rebutted by: accuracy-is-an-asymmetric-diagnostic-for-a-compressed-cache — every number above is a task score, and on reasoning workloads a preserved task score does not establish that the derivation supporting it survived; the eviction family this improves on loses a valid chain in 48–65% of matched-correct cases where 2-bit KV quantization loses 4.2%. The mechanism here is unusually well placed to answer the objection rather than fall to it — restoring aggregate softmax mass is closer to preserving trace coverage than selecting salient tokens is — but nobody has run the evidence check on it.
