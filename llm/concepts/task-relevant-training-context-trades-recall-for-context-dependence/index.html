You can fine-tune a model into needing its context

The pretraining half of this result (the-pretraining-context-window-has-an-interior-optimum) is about a decision almost nobody reading this vault gets to make. This half is about one they make constantly: what goes in the context of a fine-tuning example.

The design isolates the variable properly. The document budget is fixed at eight; only the fraction that is target-domain varies, k ∈ {0, 4, 8}, with the rest drawn from other domains. So token count, sequence length, training steps and adapter configuration are all constant, and the only thing changing is how relevant the context is. Going from zero to eight relevant documents improves accuracy when supporting context is available at test time — and significantly reduces accuracy without context, and significantly increases how badly the model is misled by conflicting context. The supporting-minus-conflicting gap opens from 22.1 points to over 42.

The name the authors give it is right: context addiction. The model has learned that the answer is in the context, so it stops carrying the answer itself, and it stops arguing with the context when the context is wrong.

Three consequences for how this vault reads fine-tuning results.

The first is a warning about how retrieval-augmented fine-tuning gets evaluated. A recipe that trains with retrieved documents and evaluates with retrieved documents will report improvement, correctly, while having made the model worse in both of the conditions production actually produces — retrieval returning nothing, and retrieval returning something wrong. That is a construct mismatch of the kind evaluation-contamination catalogues, arriving from the training side rather than the benchmark side, and it is invisible to the evaluation the recipe would naturally run.

The second is about peft-methods. The mechanism here is a shift in gradient pressure from feed-forward modules toward attention, and the causal check is direct: FFN-only tuning improves no-context robustness; attention-only tuning strengthens supporting-context performance and increases context reliance. That makes adapter placement a lever on a behavioral property, not only on quality — which is a second literature reaching that conclusion after placement-transfers-to-decoder-only-but-shrinks-by-an-order-of-magnitude and where-the-adapter-budget-goes-matters-more-than-how-much-there-is found placement dominating capacity. A practitioner who wants a domain expert that still works when retrieval fails now has a knob: put the budget in the feed-forward modules.

The third is an interaction with data-curation. That map's contested claim is about which examples to select. This says the context assembled around a selected example is a training decision with its own sign, and one that no curation pipeline in this vault currently treats as a variable. task-knowledge-has-a-third-place-to-live is the closest existing statement and it is about where knowledge can sit; this is about what determines where it does.

Bounds. This is LoRA, not full fine-tuning, so it measures how a low-rank update rebalances the carriers rather than how training does — plausibly a conservative estimate, since a full update has more capacity to internalize, but untested. Four domains from one benchmark family, evaluated by exact match against multiple-choice answers. The conflicting-context condition is synthetic (documents constructed to support a wrong answer), which is a harsher adversary than most retrieval failures. And the gap numbers are read from a figure rather than a table.
