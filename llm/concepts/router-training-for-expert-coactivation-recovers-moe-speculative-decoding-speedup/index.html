A training-time router objective, not an inference-time gating bias, is the second mechanism this map has for the expert-union problem

This map's standing open question — "why does speculation fight sparse routing, and is the fix portable?" — has so far collected inference-time answers: the-expert-union-is-a-decision-variable-not-a-cost-to-schedule-around-class methods (see mixture-of-experts) bias the target model's gating logits during verification to pull borderline experts toward ones already in flight, breaking the exactness guarantee to do it. Apple's result is a different kind of answer: shape the router during pretraining so that adjacent tokens naturally prefer overlapping experts, via a consistency loss between consecutive tokens' router logits plus shared experts, a global (not per-microbatch) load-balancing loss, and an inference-time autoregressive expert-carryover rule that only reorders which of a token's already-acceptable experts get picked. Because the overlap is trained in rather than imposed at verification time, this method does not need to touch the target's routing logits at inference — it should preserve exactness in a way the gating-bias methods on mixture-of-experts explicitly do not, though this source does not test exactness/distribution-preservation directly, so that inference is not yet a measured claim.

The boundary condition is sharp: this fix requires retraining the MoE from scratch with these losses. It answers "is the fix portable" in one sense (the training recipe is architecture-general, four techniques, tested at multiple expert counts and top-k) and not in another (it cannot be applied to an already-trained checkpoint the way the inference-time gating-bias methods can). A reader with a downloaded MoE checkpoint gets nothing from this result directly; a reader training their own MoE gets a recipe that, if it replicates, avoids paying the expert-union tax at all rather than mitigating it after the fact.

Graded extends: adds a second mechanism to the map's standing expert-union thread rather than contradicting the inference-time results, which remain the only option for pretrained checkpoints. Graded suggestive: single-lab (Apple), models capped at ~1B total parameters — two orders of magnitude below the 30B-235B-class MoEs this map's consumer-hardware entries actually run — no code or checkpoints released, and the paper's own ablations show three of the four techniques cost quality in isolation, recovering only when combined, which is a fragile-sounding recipe until independently replicated.

Bounded hard: H100-only (no consumer-card, no llama.cpp, no offload measurement — the exact deployment shape mixture-of-experts's S2MoE and EdgeXpert entries measured); throughput number is one QA task, with the paper's own figures showing smaller gains on harder tasks; no exactness/distribution check; no comparison against the inference-time gating-bias alternative on the same model.

Rebutted by: none.
