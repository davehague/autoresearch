Sparsifying attention's hidden (feature) dimension, not just which tokens it attends to, computes a third of the usual dot product and improves loss rather than trading it off

TL;DR: Borbely, Salzmann and Verscheure attack an axis this map's and kv-cache-management's large sparse-attention cluster had not touched: almost every existing method reduces which tokens a query attends to, keeping the per-pair dot product over the full head dimension intact. HiSA instead keeps the query and key projections unchanged and drops part of the dot product's feature axis, using the structure RoPE already provides — each 2D frequency pair rotates by an angle proportional to relative token distance, so high-frequency pairs complete many rotations within a few tokens while low-frequency pairs barely rotate even over a long context. HiSA's rule is static and parameter-free: keep a frequency pair's contribution to the score only when the RoPE-induced rotation angle between a given query and key is below a fixed budget (90° by default), determined purely by their relative distance and the model's RoPE base, with no learned selection and no runtime search. Training SmolLM-architecture decoders (135M and 360M parameters) from scratch on OpenWebText with this rule computing only 29.3-34.2% of the usual dot product, the resulting models reach lower validation loss than dense attention at every position in a 4K context window, and the advantage survives extending the trained models to a 16K context window at an even smaller computed fraction (20.2%). A block-tiled approximation built for FlashAttention-3 (needed because the exact per-pair cutoff doesn't align with GPU tile boundaries) keeps about half the loss gain while matching dense FlashAttention-3's training throughput at 4K context, and trains at 94% of dense speed after the 16K extension. At decode time the KV cache shrinks by a third relative to dense attention at matched context, and decoding throughput rises up to 42% at 16K context and batch 128 — part of that gain traced to the kernel's smaller query tiles rather than the sparsity itself, which the authors isolate and report honestly. A separate interpretability analysis finds densely-trained attention already learns to suppress the exact score components HiSA statically drops, suggesting the rule approximates something the dense model discovers on its own rather than removing information the model needed.

Why it matters here. transformer-architecture and kv-cache-management both carry extensive token-dimension sparse-attention evidence (Prism-Attention, RecSA, BF1, BinaryPC, FlashPrefill-v2, and more), none of which questions the feature-dimension computation itself. This is the first source on either map to do so, and the first to show a sparsity lever that improves rather than trades off quality — most of this vault's compression levers (quantization, eviction, pruning) report a quality cost at some compression level; this one, trained from scratch, does not. The KV-cache-size and decode-throughput results also land directly on kv-cache-management's "spending a fixed budget" sub-thread as a new, orthogonal axis: because it operates on the feature dimension of each kept key/value rather than deciding which tokens to keep, it should in principle compose multiplicatively with the map's token-axis eviction methods, though that composition is untested by this source or any other in the vault.

Caveats. Trained from scratch at 135M-360M parameters only — no evidence yet at billion-parameter scale, on a released frontier model, or with grouped-query attention, where head-dimension sparsity interacting with head grouping is untested. The exact (non-block) rule trains 1.7x slower than dense attention and is a research instrument rather than a deployable path; the deployable Flash-HiSA variant keeps roughly half the loss gain. The 90° angle budget and RoPE base are hyperparameters selected by ablation on these small models; transfer to a different RoPE base or much longer context is untested. No direct composition experiment against this vault's existing token-sparsity or KV-eviction methods on the same model.
