A failure mode nobody had isolated: fine-grained expert partitioning plus single-source initialization collapses upcycled MoE accuracy to near-random, and the fix needs two components acting together, not either alone

This map's accumulated routing/upcycling evidence has so far been organized around training-time or inference-time levers on an already-functioning MoE — top-k's gradient boundary (elastic-expert-routing-smooths-the-topk-gradient-boundary, 2026-10-09), the router as a cross-lingual alignment target (router-outputs-as-cross-lingual-alignment-target, 2026-10-04), consumer-GPU expert-parallel communication (comoe-host-centric-routing-closes-most-of-the-consumer-gpu-moe-communication-gap, pcie-native-communication-recovers-moe-expert-parallel-loss-on-consumer-gpus). DivMoE is different in kind: it is a construction-time finding about how to get from a pretrained dense model to a working fine-grained MoE at all, and it documents a failure mode (near-random accuracy from the combination of fine-grained partitioning and single-source initialization) that no prior upcycling paper in this literature isolated — every existing remedy (NVIDIA Upcycling's dense-equivalent init, Drop-Upcycling's random re-init) independently fixes part of the problem while leaving the other part broken (homogeneous initial routing scores, or lost pretrained knowledge, respectively).

Why this matters for the vault's premise. Sparse upcycling from a pretrained dense model is the cheap path to an MoE — training one from scratch is the alternative this map's entire routing/granularity thread presupposes is too expensive for most readers. DivMoE's ablation (Table 5) shows the naive combination of two individually-desirable design choices (fine-grained experts, which help quality elsewhere in the MoE literature; single-source upcycling, which is the cheap default) actively destroys the thing upcycling is supposed to preserve. This is a cautionary result as much as a fix: a reader upcycling a fine-grained MoE from one dense checkpoint without domain-specialized initialization and a structural diversity constraint risks landing at from-scratch-random accuracy while believing they saved the training cost of doing so.

The structural-vs-gradient-based routing distinction is itself notable. DivMoE's diversity constraint (hard: at most one expert per domain group, guaranteed by construction) is explicitly contrasted with the field's standard soft remedies for routing collapse — auxiliary load-balancing losses and router z-loss — which only shape routing through gradient pressure and provide no guarantee on which selections are reachable. This is a different kind of lever than anything currently on this map's routing-stability thread, and the paper's own ablation (Table 6) rules out the natural objection that forcing cross-domain co-activation would hurt domain-specific tasks — it improves all four tested domain benchmarks instead.

Closes a gap this map named at the founding upcycling ingest. The map's 2026-07-22 open-questions note on dense-checkpoints-can-be-upcycled-into-moe (Komatsuzaki/Puigcerver, Google Brain, T5-XL encoder-decoder) flagged specifically that "transfer to a fine-grained + shared-expert modern base is assumed rather than shown" — the founding upcycling evidence predates every decoder-only MoE this map tracks. DivMoE is the first source on this map to test fine-grained upcycling on modern decoder-only bases (Qwen3-1.7B/4B-Base, Llama3.2-1B) and is also the first upcycling source in-vault from a group outside the Google-Brain lineage that note separately flagged as covering "most of the map" — an independent fifth group, not a fourth Google paper. It does not touch that same note's other open cell (fine-tuning-scale extra compute, 1-5% rather than 20-100%, on an instruction-tuned checkpoint): DivMoE's Stage 2 continual pretraining runs 500B tokens on a base (non-instruction-tuned) checkpoint, which is still pretraining-scale compute, just a different base-model era.

Caveats carried from the source. Public-corpus-only training pipeline (Dolmino-Mix for CPT, Tülu-3-SFT- Mixture for the controlled SFT comparison); no test against a proprietary or much larger data mix. Base-model coverage is Qwen3-1.7B-Base and Llama3.2-1B for the main comparison, plus one larger Qwen3-4B→12B run for the open-source-MoE comparison — no test at Mixtral/DeepSeek-V2 scale (tens of billions of parameters). The n=4 domain taxonomy (math/code/science/commonsense) and m=2 shards/domain are the tested configuration; sensitivity to a different domain split or larger n is not reported. NeurIPS 2026 (NUS/SJTU), code not yet confirmed released in the source as read.
