A third case of a speculative-decoding method winning on wall-clock while losing on accepted length — and this time by solving parallelism's rollback problem rather than drafting cost

This map's parallel-drafting thread already has DSpark (parallel block drafting fixed with a Markov logit-bias head plus a confidence head that schedules verification by per-position survival probability) as the strongest named sequential-style parallel drafter, and a standing complaint that true parallel speculative decoding — overlapping next-round drafting with current-round verification, rather than just drafting several tokens per round — pays a rollback tax when the accepted-length guess is wrong. DPara answers that complaint structurally rather than by getting better at guessing: its backbone precomputes draft representations for every possible acceptance boundary simultaneously (a tree-structured attention mask gives causal sharing along the spine and bidirectional attention within isolated per- boundary branches), so there is nothing to guess and nothing to roll back. Zero fallback events at any batch size, against SSD's reported 57-96% fallback rate at batch 16 — a fallback event forces serial re-execution, so this is not a marginal efficiency gain but the removal of a failure mode this sub-thread has lived with.

The result is a second, independent instance of this map's 2026-08-14 lesson that accepted length is retired as a cross-study metric (train-the-drafter-on-accepted-length-not-likelihood): DPara's accepted length (4.41-4.43) is lower than DSpark's (5.36) — the paper's own honest accounting, "when the backbone starts, neither the accepted length nor the new bonus is known, and fresh target features for draft tokens carried over from the previous round are unavailable" — yet DPara wins on wall-clock because it collapses the draft-stage critical path (1.3ms vs. DSpark's 4.4ms) and removes rollback entirely. Comparing two drafters by accepted length alone would rank this backwards.

The resource-constrained variant (cheap A10 GPU drafting, expensive H800 GPU verifying, retaining 98% of the speedup at ~90% lower drafting-GPU cost) is the first entry on this map to put a number on heterogeneous-hardware drafting specifically for a parallel architecture, complementing rather than duplicating this map's existing single-GPU-colocated cost accounting.

Graded extends: adds a fourth architecture to the map's parallel/draft-model-free family without contradicting DSpark, ECHO, or the ordering DCD established for accepted length as a metric — it reinforces that ordering from a different mechanism (rollback elimination rather than draft-cost elimination). Graded strong: quantified across 7 benchmarks, 2 target models, multiple batch sizes, with an ablation isolating the multi-anchor finetune's contribution (30.7% average accepted-length loss when reverting to an unfinetuned DSpark checkpoint with the same frozen AR head).

Bounded hard: every primary number is on datacenter GPUs (GB200 training, H800 main inference) — the A10 result is a heterogeneous pairing with an H800, not a standalone consumer-GPU deployment, so this map's standing "what does speculation cost on the machine this vault is about" open question is still unanswered by this source; only Qwen3 target models tested; sampling (temperature 1.0) narrows the advantage over DSpark relative to greedy, continuing this map's pattern of every reported number needing its sampling regime stated to be comparable (open question below).

Rebutted by: none.
