Value caches, unlike key caches, survive cross-layer merging almost intact once the layers are aligned first — a new lever for this map's budget sub-thread that provably preserves the model's function

Every entry this map has carried so far on "spending a fixed budget" works within a layer: evict tokens, quantize the cache, anchor-plus-residual encode it, partition by depth. VFold is the first source here to spend the budget across layers, and it motivates that move with a clean asymmetry the paper measures directly: on GSM8K 8-shot CoT with Llama-3.1-8B-Instruct, naively averaging adjacent layers' key caches collapses accuracy from 80.7% to 2.7%, but averaging their value caches only drops it to 79.5%. Keys carry positional/rotary structure that breaks under blind averaging; values apparently do not.

The method does not stop at "average the values" — naive averaging (VFold-Naive) still loses badly on the harder RULER benchmark, and the gap grows with how many layers get grouped together (at 4-layer groups it collapses to 17-57 on RULER across models). The fix is an offline-computed CCA alignment map plus a per-head Hungarian permutation, folded directly into W_Q/W_K/W_V/W_O so the model's forward computation is unchanged — a provable guarantee (checked numerically: condition number mean 6.4, bf16 output distance averaging 0.28%), not an approximation bound like most of this map's other compression levers. Only the runtime value-cache merge introduces real error, and alignment keeps that error small enough that the method retains >=98.3% of full-cache performance at a 25% total KV reduction, beating or matching MiniCache, MiniCache-V and CommonKV in 5 of 6 model/benchmark cells (CommonKV edges it only on Mistral-24B/LongBench).

Composes with this map's precision axis. 4-bit KIVI quantization + VFold reaches 4.27x total compression (up from KIVI alone's 3.2x) while staying within 0.3 points of VFold alone on every model/benchmark — a direct, positive test of whether cache-compression levers stack, which this map has flagged as uncertain elsewhere. ThinK key-pruning + VFold is "roughly additive" in quality loss, one exception aside.

Caveats carried from the source. Three models only, all GQA — no MHA/MQA tested. The GSM8K asymmetry analysis (the motivating 79.5%-vs-2.7% number) uses a single model. CommonKV is prefill-only and needed adaptation for QK-Norm on Qwen3-8B; it still beats VFold on some larger-group-size cells, so VFold's edge narrows (without collapsing) as more layers get grouped. Calibration uses 128 Wikitext-2 samples; transfer to held-out GSM8K is good (~0.85 vs ~0.9 cosine) but not tested against a larger domain shift. Code released.
