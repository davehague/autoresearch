What's shared across layers, not what's learned per layer, is the new lever

Every method this map has absorbed factorizes ΔW per layer — LoRA's BA, DoRA's magnitude/ direction split, AdaLoRA's per-matrix budget allocation. Even the-rank-a-lora-needs-is-set-by-the-part-of-the-update-the-task-activates, this map's newest theory entry, treats the per-layer factorization as given and asks how much rank each layer's factor needs. FrameFT changes the object that gets shared: instead of a per-layer trainable factor pair, it builds one Fusion Frame — an algorithmically-generated, overcomplete basis — used across every adapted layer, and represents each layer's update as a sparse coefficient vector against that shared basis. What's trained per layer is which and how many basis elements the layer's update activates, not a private low-rank pair.

Why the memory shape changes. LoRA-family cost is O(dr) per layer, repeated at every adapted layer — rank r is a per-layer decision that pays every time. A shared frame means the basis itself is not a per-layer cost; what's counted per layer is a sparse coefficient count, and the paper's claim is this comes in below LoRA's O(dr) at matched or better quality, via dual sparsity — sparse coefficients and sparse basis-element usage — which is a different lever than truncating a rank.

Formal convergence results for the sparse-coefficient fitting procedure put this in the small company of PEFT methods this map has graded with a proof behind the optimization claim, not just an empirical sweep — joining the-rank-a-lora-needs-is-set-by-the-part-of-the-update-the-task-activates as the map's second theory-backed entry, though that one is pure representation theory with zero experiments and FrameFT is evaluated empirically.

Discounted to suggestive despite T1 tier because this digest is graded from an abstract-level read: no baseline PEFT methods are named, no parameter-count deltas at matched accuracy are pulled, and it is not yet clear whether the frame is fixed at initialization or grown during training. Flagged for a follow-up pass on the full PDF before this map treats FrameFT's memory claim as strong.

What it would change if the numbers hold. This map's cost thread — sub-thread (2), "the bill" — has so far measured LoRA-family memory in terms of rank and target-module count. A method whose per-layer cost is decoupled from a per-layer rank choice would be a genuinely different point on that cost curve, not an incremental improvement on it.
