The third rung, and the first one a model consumer can climb

evaluation-contamination holds two contamination tools and has recorded since 2026-07-27 that they do not compose. n-gram-decontamination-is-blind-to-paraphrase shows the reliable rephrasing detector needs the training corpus, which only a corpus builder has, while contamination-detection-is-a-prior-not-a-verdict gives everyone else a model-only screen at AUC 0.72. The gap between them is where every reader of this vault stands.

Perturbed evaluation needs neither. Annotate each benchmark question into a symbolic template — proper nouns, entities and numeric values become variables with sampling domains and correctness conditions (x = range(5,100), x + y + z == total, divisibility so answers stay whole) — then generate fresh datasets from it. Fifty draws of 100 questions each means a model can be scored fifty times on the same reasoning problems with different surface content.

Two things fall out. The first is that a single score is not a property of a model: one 9B model spans more than 12 points and another about 15 across draws that differ only in names and values. Two papers can honestly report very different numbers for the same model on the same task. Every "beats frontier on task X" claim this vault's premise depends on is one draw, and no source in the vault reports a spread.

The second is the contamination signal. The original benchmark items are just one more sample from the template family, so their score should sit near the centre of the distribution. For 21 of 25 models it sits on the right, frequently beyond a standard deviation — which is exactly what memorized items would produce, and is where a leakage prior lives. The gap is family-shaped rather than universal: the largest drops are 6–9 points across the Mistral, Gemma and Mathstral families, the smallest are under a point for GPT-4o and o1-mini, which is the same "contamination is unevenly distributed" shape benchmark-scores-can-be-memorization found by building a parallel benchmark from scratch. This is the cheaper version of that experiment: templating an existing test set instead of authoring a new one.

Two limits on resolution, and being exact about them is the useful part. The signal is population-level, not per-item — it says a reported number is inflated relative to equivalent questions, never which items leaked — and it requires a benchmark you can re-template, which took an annotation pipeline plus manual review of ten samples per template here.

And the harder limit: it cannot separate leakage from brittleness. The same models that lose points to a changed number also lose points to an inert added clause (an-irrelevant-clause-collapses-arithmetic-accuracy), for reasons that have nothing to do with having seen the test set. Perturbation measures both superimposed. That is a caution against reading a drop as a contamination verdict — the same over-reading this map already flags for a 0.72-AUC screen — and it is also a finding about the map itself: two of the four named failure modes produce the same observable, which the "clearing one says nothing about the others" framing did not anticipate.

The names-versus-numbers split is the closest thing to a discriminator. Variance is lowest and the original score sits nearest the centre when only proper nouns change; both the drop and the spread grow when values change. A memorizing model should be indifferent to a name change; so should a reasoning one. Neither is.

See also: eight-bit-is-not-a-free-precision-step — the same argument on the other side of the ledger. There, avoidable variance hides an effect that is real: a quantization sweep runs identical prompts through identical models at different bit-widths, which is a matched design, and scoring it with unpaired statistics threw away enough power to make an 8-bit penalty invisible in all three tested models. Unreported distribution in one direction inflates a score; in the other it conceals a regression.

Rebutted by: greedy-decoding-is-nondeterministic-under-batching — this note's design treats greedy decoding as the deterministic control that isolates template variance; measured, a frozen model re-scored twice through a 64-way-batched server flips 8% of verdicts, so part of the "one draw" is the serving stack rather than the item set.
