The serving stack has three independent layers, and this is the one that admits and returns

local-inference has listed continuous batching as absent from its runtime half since the speculative-decoding ingest. This is its origin, and the useful thing is that it is neither a kernel result nor a memory result — it is a scheduling result, which makes it the third distinct layer of the serving stack the map now holds.

The observation is specific to generation and the paper is careful about why. Training does not have this problem: teacher forcing processes a whole sequence in one iteration. Inference runs the model once per output token, for an unpredictable number of tokens, so requests in a batch finish at different times. Under request-level scheduling that costs twice — the engine keeps computing for requests that already finished, and finished requests cannot be returned until the slowest completes. Meanwhile new arrivals queue behind the entire batch. Rescheduling after every iteration means completion is detected immediately and a new arrival waits at most one iteration.

The evaluation design is what makes the claim trustworthy. Running the engine with the scheduler disabled puts Orca "similar or slightly worse" than FasterTransformer — the authors' own disclosure that they have no kernel advantage. All 36.9× is scheduling.

Two structural facts the map should carry. First, the relationship to paged-kv-cache-unlocks-throughput is precursor plus tension, not duplication: Orca reserves max_tokens KV slots in advance for each admitted request to avoid deadlock, and that over-reservation is precisely the internal fragmentation PagedAttention was written to eliminate. Continuous batching created the memory problem that paging then solved. Second, and practically: the 36.9× is measured against FasterTransformer, while vLLM's 2–4× is measured against Orca. Those numbers do not compose, and anyone quoting a stacked multiple is chaining baselines that do not chain.

The consequence for this vault's premise is a real limitation rather than a caveat. Orca's entire win is the multi-tenant regime — its one clear loss is max_bs=1, its one weak case is low load, and together those describe exactly the single-user local deployment this map is named for. Read beside speculation-trades-arithmetic-for-latency-without-moving-the-distribution, which wins specifically at batch size 1, the map now holds two serving levers that are anti-correlated in their operating regimes: continuous batching pays when you have many concurrent users, speculation pays when you have one. Neither paper states this, because each measured only its own regime.

Bound: the trace is synthetic — no public generative request trace existed, so arrivals are Poisson, lengths uniform, and the model is prevented from emitting EOS, making request duration a sampled constant rather than content-dependent. The homogeneous-trace experiment shows the win shrinking as that distribution narrows. One baseline, configured by the authors, from a commercial vendor whose product this is. The 36.9× is a single point read off a latency–throughput curve at one chosen latency target. All results are 2022 A100 datacenter configurations at 13B–341B with no quantization anywhere.
