An optimizer's own floating-point denominator floor, not the loss landscape, can be the thing that stops training progress under a power-law-skewed measurement spectrum -- a mechanism this map has not yet connected to this strand's deployment-quantization-tolerance findings, and that has not itself been tested on an actual LLM

TL;DR: This map's one existing training-arithmetic-precision finding (the AdamW/zero-sum LM-head gradient drift that produces delayed BF16-amplified pretraining loss spikes, adamw-lm-head-drift-causes-delayed-quantization-driven-loss-spikes) is about a specific mechanism in a specific layer of a real, if small, decoder-only pretraining run. This source is a different and more abstract instance of the same broad family -- "an optimizer's finite-precision arithmetic, not the optimization landscape, sets where training stalls" -- demonstrated on a synthetic low-rank matrix-sensing toy problem rather than any language model. Graded as an open question rather than folded into this strand's belief, for the same reason the LM-head drift finding was: the object here is a general optimizer-precision mechanism, not a model being trained against a deployment quantization grid, and whether (or how) the two interact with each other or with real pretraining is untested by either paper.

What it says. The paper's mechanism: in a problem with a power-law-skewed measurement spectrum, the curvature (smallest relevant Hessian eigenvalue) that matters for convergence in the rarest directions shrinks with problem size. Normalized optimizers like Adam divide by a running second-moment estimate plus a small denominator constant (epsilon); once true curvature falls below what that denominator can resolve, the optimizer's own arithmetic -- not the landscape, which is provably benign here -- becomes the bottleneck. This gives a closed-form, falsifiable prediction for where that stall happens as a function of problem size and the optimizer's epsilon, tested successfully against a held-out grid the author pre-registered before running. It also distinguishes this specific "denominator-precision" wall from two other named failure modes at the same abstraction level (a Hessian-conditioning wall for un-normalized optimizers like SGD, and a "sign-quantization" wall for sign-based optimizers like SignSGD/Lion) -- a taxonomy this map does not currently have, since its training-time-quantization strand has so far been organized around deployment-grid tolerance (QAT, healing, teacher choice) rather than optimizer-internal arithmetic failure modes.

Why this stays an open question rather than a belief update. Three gaps separate this from anything actionable for this strand: (1) the problem is synthetic (matrix sensing with an artificial power-law spectrum), not a language model or any realistic pretraining objective -- there is no evidence the relevant curvature-vs-size scaling this paper derives resembles anything in an LLM's loss landscape; (2) "precision" here means the optimizer's internal floating-point denominator floor, a different object from either the BF16-vs-FP32 logit drift this strand's existing loss-spike finding names or any post-hoc deployment quantization format this strand's QAT/healing claims are about; (3) the author is a single individual at a non-academic, unaffiliated lab with no stated peer review or independent replication, and the paper's own large-vocabulary extrapolation (V=32,000, D=1,024 -- roughly LLM-embedding-table scale) is explicitly analytical and untested. The genuinely interesting, untested pairing: does a real pretraining run's LM-head or embedding-table curvature ever fall into the regime this paper's formula would flag, and if so, does that predict anything about the AdamW drift mechanism the strand's existing loss-spike note already names -- both papers independently implicate AdamW's denominator/normalization behavior as a precision-related failure source, from completely different directions (one empirical-on-a-small-LLM, one synthetic-and-theoretical), and neither cites or tests against the other.

Caveats. Single-author, no university affiliation or peer-review venue stated, held at single-study strength despite the quantified calibration. The detection-lag constant is fit on only four configurations before being tested against the held-out grid; the full epsilon sweep is run for Adam only, at one fixed learning rate. The formula's own trend with D holds on an aggregate metric in 3 of 4 rows but not on a separate "rarest-direction" metric in 2 of 4 rows -- an inconsistency the author reports without resolving. The formula is explicitly out of its stated domain of validity at rank D=2. The paper's own pre-registration ledger discloses that three of its pre-specified success criteria failed as registered and one was censored. No public code repository is confirmed from the text read.
