Quantizing AdamW's optimizer states to 4 bits is not one problem but two — minimizing raw state error is not the same as minimizing the error in the update it produces — and a second independent group now attacks the same full-FT memory ceiling with a different compression mechanism than this map's existing entry

This map already carries taco-compresses-optimizer-state-not-trainable-parameters (TACO), which attacks AdamW's optimizer-state memory footprint by replacing the per-parameter moment tracking with a ternary, column-wise-one-sparse signal — a sparsification approach reaching 174x compression on OPT-13B, tested with one downstream-accuracy number and no comparison against LoRA/QLoRA. This paper attacks the identical memory target with a different mechanism — 4-bit quantization of the moments rather than sparsification — and contributes something TACO did not: a validation-loss comparison against the 32-bit reference optimizer across a model-size sweep (130M to 2.7B), which exposes a failure mode TACO's single-scale test could not — TorchAO's existing 4-bit baseline actually diverges at 2.7B parameters, where both of this paper's redesigned schemes remain stable.

The core diagnostic is genuinely new to this vault: a quantizer can minimize |v_hat - v| in raw second-moment space while still producing a large error in the preconditioner 1/(sqrt(v)+eps) that AdamW's update actually depends on, because that function's curvature is steepest exactly where v is small. The two fixes — rounding directly in preconditioner space (ZIP-SR) versus calibrating out a zero-excluding codebook's systematic floor bias (ZE-EDEN) — are shown by a component-attribution ablation (GPT 834M) to each do real, separable work: swapping only the codebook without the preconditioner-aware rounding makes things worse than the TorchAO baseline (0.0312 vs 0.0246), so the gain is not simply "any 4-bit redesign helps."

The open comparison this vault should now carry: nobody has run 4-bit quantization (this paper) against ternary sparsification (TACO) of the optimizer state at matched memory budget on the same model. The two papers report different metrics (validation-loss gap vs single downstream score) on different model families, so even a qualitative ranking is unavailable from what's in-vault. Cross-link to distributed-training, where TACO is already cross-linked as this map's "seventh lever... compress the optimizer state's information content, not its location" — this paper is a second, independent instance of that lever via a different mechanism, and the same cross-link applies here.

Caveats carried from the source. The theoretical motivation compares one-step bias on a toy scalar quadratic — it does not establish end-to-end convergence guarantees for either scheme. The targeted LM-head stochastic-rounding fix patches a late-cooldown instability the authors observed but do not fully explain (the directional first-moment bias's cause, and its link to LR decay, are explicitly unresolved). Several component-attribution numbers are single-seed. No sub-4-bit or non-AdamW-optimizer test — both flagged as future work by the authors. Code released.
