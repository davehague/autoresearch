The output-encoding choice for a small fine-tuned parser swings silent-error rate by close to 2x — independent of adapter rank or any other LoRA hyperparameter

TL;DR: This is direct evidence on peft-methods's practical strand of LoRA-fine-tuning small models for real tasks, from a design axis entirely outside the adapter itself. Ahmed et al. LoRA fine-tune two sub-billion-parameter models on six lossless encodings of the same structured target (a food-ordering parse tree) and find that making the training target shorter never, by itself, improves accuracy — contradicting the common assumption that a more compact target is easier for a small model to learn. What does help is writing the target in plain words rather than a compact symbolic/bracketed notation: this is the most accurate encoding on both tested model families, cutting silent errors (a parse that is well-formed and plausible but simply wrong, which nothing downstream flags) by 2.3x on Qwen3.5-0.8B and 1.8x on LFM2.5-350M relative to the field's usual compact encodings. Most of that gain traces to how the encoding expresses negation specifically.

What it says. Across 300 runs (5 training-pool sizes x 5 seeds) on the PIZZA ordering benchmark, the result replicates across two independent sub-billion-parameter model families on the identical task — an unusually clean replication for this vault's small-model evidence. Both models also incidentally learn to refuse off-menu requests and to handle mid-utterance self-corrections, but the learned refusal behavior has a measured cost: 2.1-10.1% of genuine, mostly polite, real orders get wrongly refused.

A scope tension worth carrying, not a rebuttal. peca-conciseness-adaptation-reasoning-models (ingested the same run) treats shortening generated output as a straightforward win for small models. This source's finding — that shortening the training target's encoding alone never helps accuracy — does not contradict PECA directly (PECA shortens generated chain-of-thought at inference time; this source varies how a fixed-length training target is textually expressed), so this is scored extends rather than pushes-back: no specific existing vault claim is named or contradicted. It is still worth flagging as an open scope question for peft-methods: whether "shorter is better" holds, fails, or depends on which length (generated output vs. training-target encoding) is being shortened.

Caveats. Single task domain (food ordering, PIZZA benchmark) — generalization to other structured-output tasks (code generation, API-call JSON, other semantic parsing) is untested. Only two model families, both sub-billion-parameter. No affiliation stated for the authors; code and models released (github.com/UmarGit/coffee-llm).
