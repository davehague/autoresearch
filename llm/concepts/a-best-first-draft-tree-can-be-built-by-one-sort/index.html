A best-first draft tree can be built by one sort

Two good ideas in the diffusion-drafting literature refuse to compose. Causal correction heads fix the missing intra-block dependency of a block-parallel drafter by propagating realized tokens along a draft chain. Draft trees broaden candidate coverage and pick the top-B prefixes with a max-heap. Combine them and correction becomes path-dependent, so every heap pop must be followed by a correction-head call before the next pop can happen — the correction cannot be batched, and tree construction becomes the dominant latency term.

The resolution is a two-line lemma. Score a depth-d prefix as s_β(u₁:d) = Σ log q̃ᵢ(uᵢ) + βd. Extending a prefix adds a non-positive log-probability and, for β ≤ 0, a non-positive bonus, so no child can outscore its parent. The globally highest-scoring B nodes are therefore prefix-closed and exactly the set the sequential heap would have popped. Build a fixed-width supertree by batching all branches at each depth, score everything, then apply a single top-B. The heap is not approximated away; it is deferred, and the equivalence is exact. It fails for positive β, which the paper states.

The ablation is what makes this a finding rather than an engineering note, because it holds acceptance fixed and moves only cost. Running the exact sequential alternative on the same drafter accepts the same number of tokens — 12.840 against 12.967 on GSM8K, 7.369 against 7.343 on MT-Bench — at roughly 2.2× the round time, and therefore delivers 4.38× where the batched version delivers 9.77×. Nothing about draft quality changed. What was removed was serialization.

That is the cleanest available statement of the claim accepted-length-can-be-anti-correlated-with-speedup made from the other direction. There, a drafter accepting 40% fewer tokens won on wall-clock because its proposal path was an order of magnitude cheaper. Here acceptance is held equal and only the schedule moves. Together they fix the map's reporting standard: a drafting comparison quoted in accepted tokens is not a comparison of speed, and the gap between the two is a scheduling property that a τ column cannot show.

The corollary the method exploits is worth stating separately, because it inverts a habit. Since the correction head is lightweight and batched, widening a layer is nearly free — 0.87 ms at width 1, 1.29 ms at width 16 — so the cheap move is to build a supertree wider than the tree you intend to verify and prune afterwards, which buys a further +6.5% τ / +7.1% speedup over fixed-width construction. Generate broadly where generation is cheap; spend the budget at the point where it is expensive, which is verification.

Bounds. One model family (Qwen3-4B and 8B), one GPU (RTX 6000 Ada), batch size one throughout, ≤2048 generated tokens. Baselines are re-measured locally, which is correct method and makes the absolute multipliers non-portable. No quality evaluation, because verification is unchanged and the speedup is lossless by construction — true, and it means nothing here bears on output quality. The supertree is built wider than it is verified, which is free on a resident dense model and is exactly the move speculation-multiplies-the-expert-union-not-just-the-tokens and offloaded-moe-verification-is-not-one-forward-pass say becomes expensive on an offloaded or MoE backbone; no measurement here covers either.
