Prefill and decode no longer have to share one active-parameter number

Every MoE-decoupling finding this map has held treats "active parameters" as one number that applies uniformly across the forward pass — Mixtral, DeepSeekMoE and the sparse-upcycling literature all report a single active-param figure regardless of whether the tokens being processed are prompt (prefill) or generated (decode). A Causal Encoder-Decoder splits that number in two by construction: the decoder's global KV is projected from the encoder's final hidden states rather than computed independently, so prefill (which runs the encoder) and decode (which runs the decoder, reading the encoder's projection) activate different fractions of the 552B-parameter backbone — 8B and 16B respectively, on a model whose report frames this split as "particularly cost-effective for input-heavy agentic scenarios," where prompts vastly outweigh generated tokens. The architecture's other headline effect is a FLOPs curve that stays nearly flat with context length: extending context 256-fold from 4K to 1M tokens raises single-token decode FLOPs by only ~1/4, where a standard transformer's per-token decode cost against a growing KV cache would scale with sequence length directly.

Graded extends, suggestive: this is a single vendor's report of its own generational improvement, with no independent replication, no ablation isolating the CED split from CSA2/FP4-caching/SWA-Bounded- Replay (all four ship together, so how much of the FLOPs-flatness or the parameter-efficiency gain is attributable to CED specifically is not separated in the sections read here), and no arXiv posting. The "matches DeepSeek-V4-Pro-Base at 1/3 total, 1/4 activated parameters" comparison is against DeepSeek's own prior model on DeepSeek's own held-out evaluation set. Nothing here is a throughput or latency number — the FLOPs claim is a compute-accounting argument, not a measured wall-clock speedup, and mixture-of-experts's standing complaint that inference cost on bandwidth-bound hardware tracks total parameters rather than active ones is untouched by this source: at 552B total parameters this model is far outside any consumer-card residency budget regardless of how few parameters activate per token.
