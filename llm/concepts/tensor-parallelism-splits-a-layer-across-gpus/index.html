Tensor parallelism splits one layer across GPUs — and it's a different axis from sharding

Sharding (ZeRO/FSDP) answers "the replicated optimizer state won't fit" by partitioning state along the data-parallel axis. Tensor parallelism answers a different memory question — "one layer's weights/activations won't fit on a single device" — by partitioning the math along a model axis. They are orthogonal, not substitutes: sharding-is-a-dial-between-memory-and-communication shards what DDP replicates; Megatron splits what neither can hold.

The engineering that makes it cheap is choosing the partition so the two GEMMs in a sub-layer compose without a sync between them. In the MLP, split the first weight column-wise so the GeLU applies independently per shard (a row-split would break the nonlinearity), and the second weight row-wise, closing with one all-reduce. In attention, split across heads so each device's softmax is local, then a row-parallel output projection closes with one all-reduce. A layer thus costs two all-reduces forward, two backward — and nothing else crosses devices. It composes with pipeline and data parallelism into 3D parallelism.

The load-bearing limit: those all-reduces are latency-bound, so tensor parallelism stays efficient only inside a high-bandwidth island (a node's NVLink). This is why practice confines TP within a node and uses pipeline/data parallelism across nodes — and why the 76% efficiency is a DGX-SuperPOD number that does not transfer to commodity interconnect. Absolute V100 TFLOPs are a hardware-generation artifact (kernel-performance-expires-with-the-gpu-generation); the durable content is the communication structure (4 collectives/layer). Nothing here touches fine-tuning — this is full-parameter pretraining, and TP-over-a-frozen-4-bit-base is undefined (peft-methods).
