At batch size one the bottleneck is dispatch count

local-inference opened an item on 2026-08-07 it could not close: an unreported-configuration list, two entries long, after finding that a process memory allocator was worth 2.3× on a CPU backend (the-cpu-inference-bottleneck-was-the-memory-allocator) and that the attention backend flipped the sign of a KV-compression result (the-attention-backend-decides-whether-cache-compression-pays). This is the third entry, from a substrate the vault has never held — the browser — and it names a term nobody in this map counts: how many times the runtime asks the GPU to do something.

The measurement is 24–36 μs per dispatch on Vulkan and 32–71 μs on Metal, across four GPU vendors, two WebGPU implementations and two browsers. The load-bearing detail is that the cost is identical for float32 and float16, which rules out arithmetic and memory traffic and leaves command encoding and submission. It is a property of the API surface.

The causal arm is unusually clean for this literature. Fuse operators to take the dispatch count from 876 to 564 on a 0.5B model while holding the computation fixed and the shaders essentially unchanged; throughput rises 53% and time-to-first-token falls from 71.4 to 41.6 ms. Nothing about the kernels got better, so the 312 removed API calls are the whole effect.

This is the general shape of attention-is-memory-bound-not-compute-bound pushed one level further out. At batch size 1 there is no batch to amortize anything against — not weight loads, and not fixed per-operation overhead either — so the orchestration layer is the workload. That is also why the three entries on the unreported-configuration list keep arriving from single-user decode measurements rather than from serving benchmarks.

The browser detail that makes this structural rather than a bug: per-operation validation is a security requirement in WebGPU, and the author says removing it must be weighed against the browser security model. So this is not overhead awaiting a release; it is the price of the sandbox, and browser inference is therefore worse at batch 1 than the same model on the same GPU through a native runtime by an amount this vault had never quantified.

Held at suggestive on magnitude for one reason the paper states and does not resolve: the causal experiment is a 0.5B model on an RTX 5090, a configuration where per-token weight traffic is small and fixed per-operation cost therefore dominates by construction. Parameter count raises memory traffic while leaving dispatch count roughly flat, so the dispatch share must fall with scale — and the sweep that would say by how much (the same fusion experiment at 0.5B, 3B and 8B) was never run. Also single platform for the causal arm, single author, and no existing browser engine was benchmarked.
