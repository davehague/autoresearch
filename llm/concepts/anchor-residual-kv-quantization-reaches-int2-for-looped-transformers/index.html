Anchor-plus-residual KV compression gets a new target architecture — looped transformers, where the "neighbor" being compressed against is another pass over the same position, not another position

This map's sub-thread on spending a fixed KV budget already names anchor-plus-residual as one of its standing strategies for eviction/quantization/rotation. This paper applies the idea to a target this map has not carried before: looped transformers, which re-apply the same shared weight block across multiple passes to add depth without adding parameters. The anchor here is categorically different from this map's prior anchor-plus-residual entries — it is the same position's KV state from a later loop, not a different position's KV state from elsewhere in the sequence — because looped models' per-loop KV states for a given token turn out to be highly correlated with each other, a redundancy specific to weight-sharing-across-depth architectures rather than to sequence structure.

The components compose cleanly and additively on the smaller model tested (Ouro-1.4B): residual encoding alone recovers more than rotation alone at INT2 (60.60 vs 55.40 against a 27.80 direct-quantization floor), and combining them recovers further (71.60), with mixed precision pushing a specific configuration above the BF16 ceiling at matched effective bits (76.00 vs 75.00). But the one result that would say whether this holds as loop count and model size grow — Huginn-3.5B at 32 loops — does not clear its own BF16 baseline under the full method, which this map should read as a live open question rather than noise: the correlation structure the whole method exploits (per-loop KV similarity) may itself weaken as loop count increases, and nothing in the paper's own comparison isolates whether the Huginn shortfall comes from loop count, model scale, or the specific anchoring-block grouping used there (loops are grouped into blocks of four for anchoring, rather than anchored against one global final loop).

Cross-link check against post-training-quantization. The rotation component (OptR-H) and the loop-wise mixed-precision-by-depth idea echo that map's rotation and per-layer-budget findings, but this paper applies both to KV activations, not weights, and runs no weight-quantization arm — no direct interaction to record beyond the shared rotation technique being reused across both activation- and weight-quantization work in this vault.

Caveats carried from the source. The 80.7% storage reduction is theoretical, not measured; mixed precision adds ~19% storage over uniform INT2 and the least-squares scale coefficients add ~0.1 bits per KV element, both partially offsetting the headline figure. Throughput measured on one GPU (RTX 5090), 128 generated tokens, two models total, greedy decoding with one response per problem. No code/data release stated in the portions of the paper read; a project page URL is given.
