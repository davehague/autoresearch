Apple Silicon encode throughput tracks GPU core count

Five Macs spanning 2022 to 2025, 10 to 80 GPU cores, and 16 to 512 GB of unified memory, all running the same 1.0B encoder over their own files. Divide throughput by GPU cores and the answer barely moves: 1,048, 1,348, 1,341, 1,189, 922 tokens per second per core. A 1.46× spread against an 8× spread in width.

That is a simpler sizing rule than anything local-inference currently offers, and it is worth stating carefully because the map's other Apple Silicon result points the same way from a different angle: the-same-four-bit-weights-run-faster-on-mlx-than-on-llama-cpp found the runtime, not the hardware, deciding a 4-bit inference comparison on the same chip. Here the runtime is held fixed and the hardware is varied, and the hardware turns out to be almost purely a core count. The M2's 922 is the outlier at the bottom (an older core), and the M3 Ultra's 1,048 at the top hints at a scaling ceiling above ~20 cores that the paper does not analyse.

The scope condition is the whole caveat, and it is large. This is a batched encoder, which is why accelerator utilization sits at 97.7–99.7%. Autoregressive decode is the opposite regime — attention-is-memory-bound-not-compute-bound — where the binding term is memory bandwidth per token and adding compute units buys much less. So the rule is: core count predicts throughput where the workload is compute-bound and batched; it does not transfer to token generation. For anyone sizing a Mac for local embedding, indexing or vision-encoding work, that is directly usable. For sizing one to run a chat model, it is not.

The other half of the finding is what does not scale. Throughput on the M2 is 9× below the M3 Ultra; the p99 for re-encoding after a single file edit is 13,261 ms against 2,916 ms, and image queries reach 1.2 seconds. Nothing here fails — the M2 indexes the largest corpus in the paper, 3.8M chunks from 2.39M files — but the tail latencies leave the range where the tool feels responsive. That is the same shape as moe-inference-cost-tracks-total-not-active-params-on-edge: the small machine does not refuse the workload, it stops being pleasant to use, and only the p99 shows it. It is the reason a "runs on a laptop" claim should always be read at the tail.
