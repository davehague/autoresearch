One user, multi-turn: cache the prefix

This vault wrote on 2026-07-25 that the serving stack had resolved into three layers — placement (paged-kv-cache-unlocks-throughput), admission (scheduling-at-iteration-granularity-unblocks-generative-serving) and serial depth (speculation-trades-arithmetic-for-latency-without-moving-the-distribution). RadixAttention is the fourth: reuse. Every engine discards a request's KV cache when the request ends, though the next request usually shares a prefix — a system prompt, a few-shot block, an image, a chat history. Keep them all in a radix tree with LRU eviction on leaves first, reference-count nodes so a running request's pages cannot be evicted, and schedule the queue longest-shared-prefix first (provably the optimal order, since it is a depth-first traversal; measured at 96% of optimal).

The four layers do not merely coexist — they stack in a dependency order, which is a structural claim no single paper here makes. RadixAttention needs a non-contiguous one-page-per-token layout, which is PagedAttention. It needs reference counting against a running batch, which exists because of continuous batching. Its policy of holding no preallocated cache pool — evict the whole cache when enough requests are waiting, in favour of a bigger batch — is an admission decision that presumes iteration-level scheduling. Each layer builds the substrate the next one needs.

The regime is what breaks the vault's existing rule. That rule read "many users → batch continuously; one user → speculate," derived from continuous batching's weak case being low load and speculative decoding being measured at batch size 1. Prefix reuse belongs to neither camp: its benefit tracks prefix overlap, not concurrency, and the most reliable source of prefix overlap is one user having a conversation — every chat turn resends the whole history, every agent step resends the same system prompt and tool schema. The production evidence is the strongest form of it: one worker per model on Chatbot Arena for a month, 74.1% hit rate on Vicuna-33B, 1.7× faster first token, attributed to common system messages, reused example images and multi-turn histories. So the rule gains a third clause — one user, multi-turn → cache the prefix — and this is the only one of the four layers that pays at batch size 1 without changing the arithmetic.

It also has a clean null result, stated by the authors: multi-turn chat with long outputs shows almost no speedup, "because there is not much sharing between different chat sessions and the decoding time dominates." Reuse cuts prefill. It does nothing for decode — which is exactly the half that quantization-speeds-decode-and-can-slow-prefill says quantization does speed up, so the two levers are complements rather than substitutes.

Bound: the headline is against vLLM v0.2.5, and the paper's own footnote concedes RadixAttention was subsequently integrated into vLLM — so 6.4× measures the value of the technique, not a current gap between projects. All hardware is datacenter (A10G, A100); no CPU, Apple-silicon or llama.cpp measurement exists, which on this map is the standing complaint. Ten of eleven workloads have structural prefix sharing by construction. Cache-aware scheduling can starve requests, which the authors acknowledge and do not quantify.
