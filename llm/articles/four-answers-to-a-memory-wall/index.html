Four answers to one memory wall: the state of distributed training

Synthesized 2026-07-22 from distributed-training (status: consolidating since 2026-07-20; this article is the map's first, written when ZeRO-Offload completed the set of axes). Every source below is a systems paper about full-parameter training. If you are fine-tuning with adapters on one card, read the last section first — it is the one that says which of this applies to you. Check the map's through-line before trusting this in 2027.

The claim

Training stops where one device's memory stops, and it stops early. Plain distributed data parallel replicates parameters, gradients, and optimizer states on every GPU, which puts the ceiling near 1B parameters on a 40GB card — the FSDP paper demonstrates DDP failing to wrap T5 above 2.28B. [T1]

The arithmetic underneath is worth memorizing, because every technique below is a rearrangement of it. Mixed-precision Adam costs 16Ψ bytes per parameter: 2Ψ fp16 params + 2Ψ fp16 grads + 4Ψ fp32 params + 4Ψ momentum + 4Ψ variance. Twelve of those sixteen bytes are fp32 optimizer state that the forward pass never touches, replicated on every GPU. [T1]

As of 2026-07 the vault holds four distinct ways to get past that wall, and they are not variants of each other — they cut along different axes:

What to do

  • Turn on ZeRO stages 1 and 2 unconditionally. ZeRO decomposes sharding into three cumulative switches with asymmetric prices: optimizer states (4× memory reduction), + gradients (8×), + parameters (N_d×, linear in data-parallel degree). Stages 1 and 2 move the same communication volume as plain data parallelism — they are close to strictly dominant. Stage 3 costs 1.5×. A 7.5B model at 64-way data parallelism goes 120 GB → 31.4 → 16.6 → 1.88 GB per device. So: 1 and 2 always; 3 when you must fit, knowing you are paying bandwidth for it. [T1]
  • Treat sharding as a dial, not a switch. FSDP's sharding factor runs continuously — F=1 is plain DDP (cheapest communication, no savings), F=W is full sharding (lowest memory, most communication), and hybrid values are a graduating trade. FSDP-unit granularity is a second knob in the same currency. [T1]
  • Expect wrong settings in both directions, and measure. T5-11B loses 7% per-GPU TFLOPS scaling from 8 to 512 GPUs as communication outruns the available overlap. FSDP's CPU rate limiter is worth up to 5× on T5-11B, costs 5% on DeepViT-8B, and does nothing on RegNet-9B — because throttling only helps when a CPU running ahead is actually causing allocator defragmentation. The paper's own advice: check num_alloc_retries before enabling it. There is no transferable configuration here. [T1]
  • Reach for tensor parallelism only when a single layer won't fit — and keep it inside one node. Megatron partitions the block so a whole layer costs two all-reduces forward and two backward (MLP: column-split the first weight so the nonlinearity stays local, row-split the second; attention: split across heads so each softmax is local). That bought 8.3B parameters on 512 GPUs at 76% scaling efficiency. But those all-reduces are latency-bound, so it stays efficient only inside a high-bandwidth island — practice confines TP within a node and shards or pipelines across nodes. [T1]
  • If you cannot add GPUs, demote instead of distribute. ZeRO-Offload runs the fp32 optimizer state and the Adam step on the CPU, keeping fp16 params/grads and forward/backward on the GPU — the 12Ψ/4Ψ split, a 4× GPU-memory cut before any sharding. That trains 13B parameters on one GPU (10× what PyTorch fits on the same card) at 40 TFLOPS/GPU on a single V100 for a 10B model, against 30 TFLOPS for the 1.2B largest model that fits without it. It scales near-linearly to 128 GPUs and reaches 70B+ on one DGX-2 combined with model parallelism. [T1]
  • Understand why offload works, because that tells you when it won't. Forward/backward costs O(params × batch × seq); the Adam step costs O(params). The optimizer is the one stage whose cost is independent of the batch — which is exactly why you can afford to run it on a device an order of magnitude slower, and why communication stays fixed at 2× the parameter count per step regardless of batch or sequence length. The corollary: the larger your batch, the better this trade looks. It also assumes ample CPU DRAM and PCIe bandwidth, and the optimality argument is Adam-specific — derived from K=12 optimizer bytes, not transferable to another optimizer. [T1]
  • Enable delayed parameter update after warm-up, not from step 1. ZeRO-Offload's one-step DPU overlaps the CPU optimizer step with GPU compute for up to 1.5× end-to-end, at the cost of the model at step i+1 being updated from step i−1's parameters. The reported no-accuracy-cost result is conditional: introduce it after a few dozen iterations, because early training is where gradients move fast enough for staleness to destabilize. [T1]
  • Budget for two memory pools, not one. Model states (params/grads/optimizer) are handled by partitioning; residual states (activations, temporaries, fragmentation) need different tools — partitioned activation checkpointing, constant-size fusion buffers so all-reduce temporaries stop scaling with model size, and live defragmentation. The operational lesson worth keeping: OOM-from-fragmentation is a distinct failure from OOM-from-size, and they have different fixes. [T1]
  • Expect "it fits now" and "it's faster now" to arrive together. ZeRO reports super-linear speedup from 64 to 400 GPUs. That is mechanistic rather than anomalous: a smaller per-device footprint permits a larger batch, which raises arithmetic intensity. [T1]

What the numbers don't say

  • Sharded training is not guaranteed mathematically equivalent to local training — the FSDP paper's own words. The optimizer steps over flattened, evenly-chunked FlatParameters whose layout ignores individual parameter boundaries, so anything needing a parameter's unsharded value (weight or gradient norm, hence norm-based clipping), its tensor structure (approximate second-order methods), or global state across parameters is computing over the wrong object. Fixing it is called an open research question. No quality delta is measured — which is what makes it worth flagging, because the failure is silent. [T1, unquantified]
  • Everything here is a vendor grading its own homework. Microsoft's "10× faster than SOTA" is measured against baselines Microsoft configured; Meta's FSDP numbers are Meta's. And FSDP says outright that it is ZeRO-3 — so what replicates across the two is the engineering (sharding works, at scale, in two production stacks), not two independent derivations. Megatron's 76% efficiency is NVIDIA-on-NVLink and does not transfer to commodity interconnect, where the per-block all-reduce dominates. No third party has audited any of it. [T1, first-party]
  • Absolute throughput figures expire with the GPU generation. ZeRO's 38 TFlops/GPU and ZeRO-Offload's 40/30 are V100-era. The ratios survive because they follow from byte accounting; the TFLOPs do not — the same expiry the kernel work in transformer-architecture measured directly. [T1]
  • Nobody has priced the practitioner-scale question: what actually fits on N cards. The in-vault numbers are 175B on 128–512 A100s. This vault's premise runs on far less.

The gap that matters most here

None of these four sources is about fine-tuning. Every experiment is generic full-parameter training — no frozen layers, no adapters, no fine-tuning memory profile. That leaves the most decision-relevant question in this map unanswered, and it cuts both ways:

  • What does FSDP even shard when 99.99% of parameters are frozen and 4-bit? The other route past this wall is peft-methods — shrink what must be trained rather than distribute it — and QLoRA's 65B on one 48GB GPU reaches a similar destination by a completely different road. Nobody in-vault has compared or combined them. [unsourced]
  • Offload may be the axis PEFT deletes. ZeRO-Offload's entire win is relocating 12Ψ bytes of fp32 optimizer state. Under LoRA on a 4-bit base there is barely any optimizer state to relocate. If that reasoning holds, offload is precisely the technique parameter-efficient fine-tuning renders moot — which would be a genuinely useful negative result, obtainable from one experiment, and nobody has run it. [unsourced]

The honest summary as of 2026-07: the memory arithmetic is settled and replicated, the four axes are individually well-measured, no source measures any combination of them, and the combination this vault's premise actually needs — adapters, on a quantized base, across whichever of these levers still applies — is undocumented in all four.
