The budget

Attention needs every previous key and value. Keeping them is the KV cache, and it grows linearly with context and batch while the weights do not — so past a certain length the cache, not the model, is what you cannot fit. Paged allocation (vLLM, T1) fixed the fragmentation half of that a few years ago and exact-prefix reuse (RadixAttention, T1) fixed the redundancy half. What is left is the part neither can fix: at 256K on an 8B model the cache is tens of gigabytes, and something has to give.

The literature's answer has been to pick a byte budget and decide what to keep inside it. Five families do this: evict tokens, quantize states, reconstruct what you dropped, partition by depth, or allocate per head. This article is organized around the two findings that cut across all five — check whether the budget is real before you spend it, and at a fixed budget, coverage beats fidelity — plus the measurement rule that the map is contested over.

First: is the budget real?

Before compressing anything, check whether you are storing one cache or N copies of it. Tensor parallelism partitions the KV cache by attention head, which works cleanly only up to num_key_value_heads. Past that the cache duplicates on every rank, and multi-head latent attention — one shared latent vector across all query heads — replicates in full at any TP size (vLLM's decode context parallelism, T2).

The fix shards the cache along sequence position instead: AllGather the queries, attend on each rank's local slice, then AllGather and ReduceScatter the partial outputs, merged by online-softmax reweighting. That merge carries each rank's running max and denominator, so the result is arithmetically the full-cache attention — not an approximation, and there is no quality term to trade. Measured on 8×B200 serving Kimi K2.6 in NVFP4: baseline tensor parallelism saturates KV memory at concurrency 64 and plateaus at 1,863 tok/s/GPU; sharded, it reaches 6,091 tok/s/GPU at concurrency 512 while still at 82% KV memory. Flags today: --decode-context-parallel-size N, with TP % DCP == 0 for latent attention and (TP // num_key_value_heads) % DCP == 0 for grouped-query. [T2, one configuration]

The reason this belongs at the top rather than in a serving footnote is that it reframes everything under it. Compression is the right answer when the memory is genuinely absent — one card, one machine. Sharding is the right answer when it is present but replicated. Every compression number in this article was measured in the first regime, and none of the papers says so, which means their baselines are systematically the harder case.

Added 2026-11-11: a third approach to the same replication problem skips sharding either the cache or the compute and instead decouples where weights live from who owns the KV cache. Decode Token Parallelism (TKNP) lets decode-stage tokens draw on weights replicated across a wider device group than the group that owns their slice of cache, rather than requiring the two groups to match. On up to 64 H100s serving 340-405B models, this beats decode context parallelism by up to 1.7x and data parallelism by up to 2.06x (TKNP, T1, implemented in vLLM). Datacenter-only evidence, same as decode context parallelism above — this article's consumer-hardware gap on the sharding question specifically is untouched by either.

Two things this does not settle, and they matter for anyone reading it as a general win. Throughput is measured at high concurrency, exactly where two extra collectives per decode step per layer amortize; per-token latency at low concurrency is unmeasured. And the post is silent on interaction with prefix caching and chunked prefill, which is where re-partitioning a cache is most likely to break something.

There is also a bill attached, payable by the architecture. Grouped-query attention buys roughly MHA quality at 5.4× decode speed (GQA, T1) by cutting KV heads — and the head count is the same number that caps how far the cache can shard. A KV-head reduction is a single-device win that becomes a multi-device constraint, and latent attention, the most aggressive version of the idea, is the worst case.

The same accounting question — is this a plain per-token KV cache, or a persistent state that needs different bookkeeping — turns out to bind on more than memory sizing. A hybrid linear-attention/full- attention MoE forces prefill and decode topologies to be tuned independently because GDN state is fixed-size per request while full-attention KV grows per token (vLLM's Qwen3.8 disaggregation post, T2) — this article's capacity-planning framing, confirmed once more. Added 2026-09-23: the same distinction decides correctness, not just capacity, on a different map. DeepSeek-V4's online-compressed attention state is prefix-dependent, so two speculative-decoding tree branches diverging from a shared prefix would each compress it differently — sharing one compressed state across the tree silently produces inconsistent verification. The fix is branch-local state during the speculative pass, refreshed only along the accepted path afterward (Tree-Structured Speculative Decoding on DeepSeek-V4, T1). Read together with this article's own recurrent-state entries (ReplaySSM, the GDN/full-attention split), the lesson generalizes past this article's memory-budget frame: treating a compressed or recurrent state as if it were a plain KV cache is a correctness bug waiting for the right consumer, not just a capacity- planning shortcut.

The first consumer-hardware number

Every method below was measured on a datacenter card until 2026-10-14. A training-free runtime scheduler — query-aware block selection, a cost-based dynamic budget, and a cost-aware fetch-or-recompute fallback, layered on top of an existing offloading scheduler (FlexGen) rather than a new storage format — cuts latency 31-63% and lifts throughput 1.4-2.7x on a single 8 GB RTX 3070 Ti, holding needle accuracy well above StreamingLLM and H2O at every keep ratio (SparPR, T1). It is evaluated on a constructed needle task with one dated model (OPT-6.7B) rather than against any imperative below, so it answers "does a consumer card see a gain at all" without yet answering "which of this article's compression methods wins on one." The question this article has asked since 2026-08-14 is no longer unanswerable in principle — it is unanswered for the specific methods above.

Serving practice is starting to move independently of that question. vLLM v0.31.0 makes an NVFP4-compressed KV cache the default attention path for DeepSeek-V4.1 on SM100/Blackwell — the first instance on this map of a compression lever shipping as a default rather than an opt-in choice a deployer makes. No accuracy or throughput number backs the switch itself, and it is hardware- and model-specific, so read it as evidence someone now judges the trade safe-by-default, not evidence of why. [T2]

Sparse-cache serving under load gets a concrete fix for two named limitations: one fixed budget regardless of demand, and no support for speculative decoding. Add a required/optional residency split (protect each request's working set; keep extra history resident only while memory is spare) plus speculative decoding run over the sparse hierarchy itself — sharing missing-row retrieval across a verification block, a window-bounded ring for draft KV — while leaving the target model's own token selection and the verifier's acceptance rule untouched (DHiSparse, T1). Against the authors' own optimized port of plain HiSparse, one configuration reaches 1.45x its throughput with lower time-to-first-token at every measured load; on a second backbone, adaptive serving with speculative decoding delivers 1.85x the output of resident serving with the same drafter. One hardware platform (8×B300), two architecturally-sparse backbones, closed-loop synthetic workloads — and once concurrency slots fill, the speculative gain stops adding further output and just lengthens the queue, so the benefit is concurrency-regime-dependent rather than universal.

Added 2026-11-18: llama.cpp's own maintainers name, for the first time in this article's reading of them, one of the project's internal trade-offs this article has otherwise only had to infer. A dedicated op (ggml_flash_attn_ext_rows) is added specifically to restore the prefill performance of llama.cpp's unified multi-sequence KV cache, confirming that cache was paying a real prefill-speed penalty relative to a non-unified cache, while keeping the unified cache's memory-sharing benefit (llama.cpp v0.9.0, T2, official ggml-org release notes). No before/after throughput figure is given — a maintainer self-report of the trade-off's existence, not its size — but it is this map's most-cited local-inference substrate confirming, in its own words, a cost this article's consumer-hardware-gap complaint has had to read between the lines for.

An agent can edit its own cache directly, and a shared index gets a stability fix

Every lever above acts on a KV cache built from a roughly fixed, externally-given token trajectory. Agentic workloads break that premise — the trajectory grows unboundedly across tool calls and turns, and the standard fix (context engineering: trim or summarize what the model sees) changes the prefix, which invalidates the cache built on it and forces a costly re-prefill. "Cache engineering" separates what the model is shown from what it attends to: an agent can drop cache entries from future attention and reposition the survivors' RoPE position IDs directly, leaving the visible trajectory untouched and never re-prefilling. A tool-response rolling-drop policy improves average benchmark score 1.7 points and cuts average cost 27.7% against threshold-triggered summarization; with the accompanying AKV serving engine, up to 1.2x output throughput and 1.5x P95 latency; recursive self-improvement of the cache policy cuts cost a further 7.1% against an expert-designed one (Cache Engineering for Agents, T1, THU NICS, code released). The sharper methodological finding travels past agents to this article's whole cross-request reuse thread: identical final token sequences can carry different cache states, depending on the history of drop/reposition operations used to reach them — so prefix matching alone is not a sufficient key for correct cache reuse in any system that allows this kind of editing, agentic or not.

Added 2026-11-15: agentic serving gets its first eviction policy built around session structure rather than request-level LRU. Serving an 816B-parameter MoE on TPU v7, protecting an idle agent conversation's KV cache instead of evicting it under plain LRU brings prefill recomputation within 1-5% of an ideal cache, against roughly 1.2x extra recomputed tokens under plain LRU. The same system pairs this with a host-DRAM L2 hierarchical cache (+77% agent-traffic throughput) and an fp8 sequence-on-lane KV layout (halving KV bytes/token/layer/device), plus a whole-step "megakernel" that nearly halves time-per-output- token versus a multi-kernel baseline (Muse Spark, T2, joint Meta/Google/PyTorch/SGLang). Enterprise TPU hardware only — this article's consumer-hardware gap is untouched — and none of the policy's three levers (layout, cache tier, eviction policy) has been ablated against the others. Added 2026-11-16: a fused TPU inference kernel for MoE serving lands on the same hardware generation from a different layer of the stack — kernel fusion and load-balancing rather than cache eviction policy — and neither source cites the other, so whether the two compose or compete for the same on-chip/host memory budget is untested (Fuse-All MoE, T1; primary map mixture-of-experts).

A narrower, adjacent fix lands on the bandwidth side of the budget rather than the memory side. Production sparse-attention systems share one layer's computed top-k token index across several neighboring layers to avoid recomputing it everywhere — cheap, but attention patterns drift layer-to-layer, so the shared index increasingly mismatches what a downstream layer actually needs as context grows. The drift is not uniform churn: core high-attention tokens stay stable nearby, and almost all the change concentrates at the edges of the previously selected region. Treating the shared index as a wide coarse proposal and doing a cheap, layer-specific refinement within it beats four published baselines (Quest, LessIsMore, SeerAttention-R, IndexCache) on average accuracy while delivering a 3.4x end-to-end decoding speedup over FlashAttention at 128K context (Prism Attention, T1, NeurIPS 2026). Datacenter-only (H800s), 4-8B models, and the margin over the next-best baseline is a consistently small 1-2 points. (A third 2026-10-23 arrival, RIFT, fixes an analogous staleness problem one layer over — a drafter's own KV cache degrading as speculative-decoding generation proceeds — but that is this map's cross-link from speculative-decoding, which carries the full entry.)

A new kind of question: can a cache cross models?

Everything above assumes one model reads its own cache. A different question — can a frozen reader model consume a different, frozen sender model's cache in place of its own, for a multi-agent handoff with no retraining — gets its first answer, and the answer separates two properties this literature had conflated. Across eight substitution methods (direct copy, learned projection, distillation-style alignment), all eight match an uninformative-cache baseline: a frozen reader's attention is "competitive" over whatever cache it is given, and a cache it didn't produce loses that competition regardless of how numerically close it is to the one the reader would have produced — the failure is a cliff, not a slope. What does work is additive rather than substitutive: keep the reader's own cache intact and attend over the sender's cache as a second, separate context, adapting only the reader's query projections. That beats the reader's own no-sharing baseline and keeps improving as up to eight senders' caches are pooled, where pooling the same caches without per-sender structure does not (fidelity-consumability decoupling, T1). Nothing here touches any imperative above — both models stay frozen, no cost (memory, latency) is reported for carrying a reader's own cache plus N senders' caches at once, and the result is a characterization on one probe setup, not a benchmark. It is this article's first evidence that "what to keep, in what form" and "whose cache is it" are separate questions, with the second one entirely unaddressed by anything else here.

Added 2026-11-07: the cross-model question gets harder once the sender is a hybrid linear-attention model, because "the cache" stops being one object. A mid-conversation model switch in a hybrid family has to transfer three interacting state types at once — the full-attention cache, a fixed-size recurrent state, and a short convolution history — not the single object every cross-model source above handles. The fidelity/consumability split recurs inside this harder problem for a reason the single-object case never confronted: the recurrent state is path-dependent (its value at any step depends on the whole history that produced it, not just the instantaneous content), so a numerically closer reconstruction of it can still continue worse, and perturbing the convolution history changes recurrent-state updates even after the convolution window itself is gone. The fix calibrates adapters against the frozen target model's own continuation output rather than a fidelity proxy, retaining 89.88%/94.11% mean task performance (Qwen3.5 4B→27B / 9B→27B) at roughly 21.7x/21.9x handoff speedup over re-prefill (HST, T1, South China University of Technology). One model family, no code release stated, and mean retention across five benchmarks with no per-task breakdown — but it is this article's clearest statement yet that "numerically accurate" and "usable" are different claims about any reconstructed cache object, not a peculiarity of the single cross-model mapper this section was built around.

Added 2026-11-10: the cross-model question gets a third instance, purpose-built for one specific handoff rather than a general sender/receiver pair — a large model handles compute-bound prefill and a smaller same-family model handles memory-bandwidth-bound decoding, with a lightweight trained module (learned layer mixing, separate key/value mappings) translating the large model's prompt-time cache into the small model's format while both base models stay frozen. Across 30 settings (six model pairs, five datasets), this beats fine-tuned small-model baselines at matched trainable-parameter budgets everywhere, closing up to 80% of the quality gap to running the large model for both phases, at a measured 3.0x request speedup for an 8B/1B Llama pairing on one A40 GPU (BridgeKV, T1, Georgia Tech/Cisco). Unlike the fidelity-consumability and HST results above, this is not a general-purpose handoff — it is trained for one specific prefill/decode role split — but it is the first cross-model result on this map with a measured (not simulated) speedup on real hardware rather than a characterization alone.

What is settled: eight imperatives

1. At a fixed byte budget, approximate every token rather than keep a few exactly. Store a small set of exact anchors per KV head, express every other token as a projection onto its nearest anchor plus a 2-bit Hadamard-rotated residual for the positions whose error most moves the attention output (AnchorKV, T1). At 20× compression that retains 99.3% of full-cache RULER-32K on Llama-3.1-70B, and at 10× it beats every byte-matched eviction baseline — the same quality for half the memory. The decisive number is not the average: on needle-in-a-haystack at 5× it reads 0.94 against an uncompressed 0.99 while AdaKV reads 0.18. Eviction fails hard, because a deleted needle is unrecoverable; approximation fails soft, because an under-valued position is stored coarsely and is still there. The trade: decode latency is 1.3× higher at 32K, reaching parity near 64K. [T1]

2. Spend bits before you spend tokens. On reasoning workloads 2-bit KV quantization matches the uncompressed model exactly on AIME (67.4 vs 67.4) where the best eviction method reaches 50.0, and degrades a matched-correct reasoning chain in 4.2% of cases against eviction's 47.9–64.8% (answer–evidence gap, T1). Read with the fact that 3.5 bits is reachable with no calibration data at all (TurboQuant, T1; 2-bit per-channel grouping is older still — KIVI, T1) and that a measured eviction study on an RTX 4090 bought a 4% speedup at higher peak memory (counter-causal surprise, T1), the ordering follows. Honest limit: the comparison is not byte-matched, and composing the two families is still the run nobody has done.

Two refinements, added 2026-10-09, sharpen what "spend bits" means rather than how many to spend. First: a fixed data-blind rotation (Hadamard) is not the floor. Fitting separate closed-form transforms for keys and values from each model's own calibration-time statistics — with the value-side transform folded into the weights for zero online cost — beats plain Hadamard by a wide margin at 2-bit (WikiText-2 perplexity 10.51 vs. 258.29, where 258.29 is a broken model) (WUSH-KV, T1). Second: the keys-over-values allocation this article has argued by measurement now has a proof behind it. At fixed total cache memory, K8/V4 precision beats K4/V8 (NLL 3.2139 vs. 3.2966, prediction agreement 95.80% vs. 85.06%) via a provable population-loss bound, not just an observed ordering (behavioral capacity certificates, T1). Neither result changes the practitioner rule; both remove a hedge this article was carrying.

Two more additions, 2026-10-14 and 2026-10-17, spend bits along axes this imperative had not separated yet. Splitting a fixed memory budget across both the layer axis and the token axis, rather than picking one, beats three published single-axis/hybrid baselines (OTT, PM-KVQ, KVmix) at every matched budget on five models, closing 48-52% of the remaining FP16 gap on the two largest (MultiAlloc, T1) — datacenter-only (one A100) so far, but the first evidence that this imperative's "spend bits" and imperative 4's "spend heads" questions are really one two-axis allocation problem rather than two separate ones. And the rotation-plus-quantization recipe this imperative already recommends turns out to need rework for multi-head latent attention's shared-latent cache (DeepSeek-V2/V3): because the same compressed vector is read twice — once for attention matching, once for value readout — a fixed rotation applied blind leaves damage a jointly calibrated rotation and quantization range, refined inside the model's own frozen projection subspaces, recovers. On DeepSeek-V2- Lite via SGLang this reaches the highest average accuracy among compared 2-bit methods across three MLA models and six benchmarks, delivering 3.96x the BF16 cache's token capacity and 2.51x decode throughput at 256K input, same memory budget (RoLaQ, T1). Scoped hard to MLA — none of this imperative's other evidence (Hadamard, WUSH-KV, BCC) transfers to or from a shared-latent cache without a separate check, and "highest average" across six benchmarks is silent on a per-benchmark floor.

Two more additions, both 2026-10-27, sharpen the MLA sub-question without yet closing it. RoLaQ applies one jointly-calibrated rotation across MLA's shared latent; splitting the latent and the positional key into separately-transformed quantization targets instead holds ~2.5 bits/element at near-zero accuracy change on four MLA models, beating KVarN/QuaRot/OSCAR (RaQ, T1, UCAS/Tencent) — no head-to-head against RoLaQ, so whether role-splitting or joint calibration is the better way to spend an MLA cache's bits is still open. Separately, a learned shared latent across adjacent layers (rather than MLA's fixed, architecturally-shared one) turns out to have no dominant outlier channel, beating xKV/CommonKV at high cross-layer compression ratios (97-98% retained at 16-20x against xKV's 54-84% at the same ratio) (BellowsKV, T1, Rice University, code released) — a second instance of "shared latent avoids the outlier problem token-wise quantization has," on the opposite side of the architectural-vs-learned-sharing line from imperative 1's residual approach.

Added 2026-11-04: rotation itself, this imperative's recurring tool since WUSH-KV, turns out not to be a uniform good. Applying a fixed rotation before quantizing helps spiky 32-channel sub-vectors and hurts already-flat ones; selecting rotated-vs-unrotated per piece via a calibrated attention-error signal beats treating rotation as a global on/off switch — at 2.5 bits/value, KIVI's 12-model KL divergence drops from 18.7 to 12.4x10⁻³, beating RotateKV on 9 of 12 models (FlagRot, T1, HKUST/Meta/Sun Yat-sen/Wuhan, code released). This narrows rather than replaces the imperative's standing advice: rotate, but decide at the sub-vector level rather than applying one transform to the whole cache.

Added 2026-11-09: native FP4 Tensor Cores (NVFP4/MXFP4) get their first accuracy fix built for the format rather than borrowed from the INT-quantization literature this imperative otherwise draws on. Three previously unnamed error sources — query quantization error, probability-scale underflow on long contexts, and key outliers under per-token scaling — are each fixed with a targeted technique rather than a global codebook change, paired with a systems fix (transposed softmax, fused probability quantization) that removes the lookup-overhead penalty accuracy-oriented vector-codebook methods pay. The result stays within 0.5-1 points of BF16 KV accuracy across dense and MoE models, under both GQA and MLA, and — new ground for this article — tracks BF16 KV inside RL training rollouts, not just at inference. On NVIDIA B300 serving Qwen3-4B and Qwen3-30B-A3B, 2.4-3.0x higher peak throughput than BF16 KV (BitDecoding-FP4, T1, code released). The three-way error decomposition is itself useful beyond FP4: it gives this imperative's bit-allocation literature, which has only ever reported one quality-at-a-ratio number per method, a vocabulary for diagnosing which computation stage is actually bleeding accuracy. All numbers are Blackwell-class datacenter hardware; this article's standing consumer-hardware gap is untouched.

Added 2026-11-17: a codebook-free alternative removes a tax every prior codebook-based vector quantizer on this map has paid. A beam-searched trellis code carries no explicit codebook, so there is no hardware codebook-size limit, and "MX-Hash" functions map a trellis index directly into a microscaling (MX) format reconstruction value — so decoding never leaves low precision, removing the dequantize-to-float tax every codebook-based KV quantizer here pays at attention time. At roughly 1.25 effective bits/element on Llama3/Qwen3, it beats evaluated baselines on both WikiText perplexity and GSM8K accuracy — a reasoning- sensitive benchmark, this imperative's standing complaint about retention/perplexity-only reporting — and posts the highest LongBench average among NVFP4-tested methods (MiSTiQ, T1). Still an instance of "nothing here composes with anything": untested against eviction, residual reconstruction, or depth-axis partitioning. No affiliation stated, no code release confirmed, no throughput/wall-clock number, and MX-format compute is an emerging hardware dependency, not available on consumer cards.

3. Do not delete irreversibly when you can demote cheaply. About 6.18% of long-inactive cache windows re-enter the important set later in decoding, against an oracle's 0.98% — the fraction a one-shot decision gets wrong by construction. Partition the budget three ways instead: full precision for the top band, an INT2 tier attention can still read for the middle, deletion only for the bottom, re-ranked every 8 tokens with promotion back out of the quantized tier (QEvict, T1). The attention-mass accounting moves from 33.3% exact / 64.8% gone to 19.7% exact / 42.6% quantized / 35.7% gone, and it beats the best pure-eviction baseline at every budget on Llama-3.1-8B (RULER-32K at 20% retained: 87.6 vs 86.4), with the margin widest at the tightest budgets. Note what this is and is not: the two levers act on disjoint window sets, so it shows a budget can be partitioned between precision and deletion, not that quantizing an evicted cache is safe. [T1]

4. Read the head budget off the frozen weights before you spend a calibration run. Form a head's query-key matching operator M_h = W_K^{h⊤}W_Q^h, normalize its singular values, take the exponentiated Shannon entropy: a concentrated spectrum marks a retrieval head that needs the full cache, a diffuse one marks a streaming head servable from a 128-token sink plus a 256-token recent window (Autonomy of Heads, T1). At 50% head sparsity that retains 96.5% of full-attention LongBench across four models and halves KV memory at 256K (34.362 → 17.206 GB). It beats gates trained on data at the identical budget, and the controls are brutal — random head selection reads 30.89, inverting the criterion reads 23.31. By Sylvester's determinant theorem the whole diagnosis is about 4.6×10⁷ operations, i.e. seconds on the checkpoint, once. [T1]

Per-head allocation gets a second instance (added 2026-09-23), one level more granular than which heads get the full cache: how each retained head spends its bits. Every prior low-rank-plus-quantization method picks one rank/bit-width split and applies it to every head; formalizing the split as a resource-allocation problem — balance rank-truncation loss against quantization loss within a head, then redistribute a fixed total budget across heads — beats six baselines (KIVI, KVQuant, GEAR, TurboQuant, SVDq, KQ-SVD) at extreme compression, nearly doubling LongBench F1 over integer-only methods at 1 bit per dimension on three 7-8B models, with the attention primitive itself 1.79–1.89× faster than FP16-SDPA at rank 16 (KV-COBRA, T1). The two results compose cleanly in principle — decide which heads keep the full cache first, then decide how the retained heads' budget is split between rank and bits — though nobody has run that combination yet. Caveat: compression here only reaches pre-RoPE keys, no end-to-end decode-loop latency is reported (only the primitive-op speedup), and the per-head split is calibrated once from 32 samples and assumed stationary thereafter.

Added 2026-11-20, cross-link: a different, orthogonal axis joins this imperative's budget-splitting logic — not which heads or how a head's bits split between rank and quantization, but how much of each kept token's own feature dimension needs storing at all. Dropping RoPE frequency pairs from the attention dot product by a static distance-based rule, rather than dropping tokens, shrinks the KV cache by a third at matched context and raises decode throughput up to 42% at 16K context/batch 128 — on top of reaching lower validation loss than dense attention when trained from scratch (HiSA, T1, EPFL, code released; primary map transformer-architecture). Because it operates on the feature axis of each kept key/value rather than deciding which tokens or heads survive, it should in principle compose multiplicatively with imperative 1, 3, and 4's token- and head-axis levers — untested by this source or any other here, and evaluated only at 135M-360M parameters trained from scratch, with no composition test against any eviction method on this map.

5. Report the attention backend with every efficiency number, or the number means nothing. The same method, model and workload under two attention implementations: eager SDPA gives +9.8% throughput at flat peak memory; FlashAttention-2 gives −59% throughput and −29.7% peak memory (29.54 → 20.78 GB). The compressed FA2 configuration is slower than the uncompressed eager baseline. This is structural, not an implementation slip — a policy that scores tokens by attention needs the probabilities materialized, and the fused kernel family exists to avoid writing them down. The memory saving and the speed saving live in different configurations, and no source on this map states its backend. [T1]

6. Score compression query-agnostically, or not at all. Appending the downstream question to the context before compressing versus compressing the reusable prefix before the query is known: same method, model, budget and benchmark, 72.20 against 26.92 on 32K RULER at 10% retained (ResKV, T1). The second setting is the one that describes deployment — a prefix cache is built once, before the queries that hit it — and it is also more discriminative, with method differences roughly double. A KV-compression result absent its construction protocol is uninformative. [T1]

7. Storage rate and read rate are different budgets — decouple them. Every imperative above assumes a fixed-rate code: what gets stored is what gets read, every time. Store each key/value scalar as a progressive code up to depth W and let each query fetch only the prefix depth R < W it actually needs — key-channel depth chosen by the query, value-token depth chosen by the resulting attention — and the unread refinement bits stay available for a later, different query with no re-encoding (ReadKV, T1, Amazon/UC Berkeley). This is provable, not just measured: on two finite-dimensional attention families, query-dependent reading strictly beats every query-independent reader at the same read budget (certified separation factor >155/k on the key stage). Empirically, across six base models, reading ~4 bits on average from an 8-bit stored cache raises C4 perplexity by at most 0.66% while using about a quarter of the logical reads of an always-16-bit cache, and a restricted single-layer hardware benchmark shows 39% lower latency and 62-65% fewer DRAM read bytes than a tested fused quantized codec at a 2-bit mean read budget. Caveat: the worst-case theorems hold on explicit families built for the proof, not arbitrary attention distributions, and the hardware number is a single restricted single-GPU, batch-one setup kept separate from the quality experiments. [T1]

8. Fix the geometry a selector leaves behind — it costs nothing and composes with whatever selector you already have. Token-axis eviction (imperatives 1 and 3's family) has always been scored on which tokens survive. Whichever tokens survive still carry their original RoPE positions — the gaps where evicted tokens used to be — which distorts relative-offset attention independent of whether the selection itself was any good. Reassigning compact, order-preserving RoPE coordinates to survivors, via inverse- then-re-rotation of each kept key's cached phase — no reselection, no re-prefill, no added memory — improves accuracy in 32 of 36 comparisons spanning 2 models, 6 selectors (attention-score, recency, and lexical/ BM25 among them) and 3 long-memory tasks. The sharpest number: Llama-3.1-8B-Instruct with BM25 selection on LongMemEval-S rises from 23.6% to 35.4% accuracy for roughly 1-3% request-time overhead (RoPERelay, T1). This is a free layer on top of imperative 1 or 3, not a competing method — 4 of 36 comparisons did not improve, and which combinations those were is not specified in the source read for this article. [T1]

9. A trained, end-to-end gate beats a training-free rule at the same job, and this is now true at two different points on the generation timeline. AbridgeKV (2026-10-18) re-encodes a finished reasoning block's cache into learned pause tokens after generation. Added 2026-10-25: TokenGate places a zero-initialized, MoE-routing-inspired gate at a chosen layer and trains it end-to-end through ordinary next-token cross-entropy to decide, before prefill, which tokens ever get a KV entry at all — deciding earlier on the same timeline, by a mechanism with the same shape. Against full-context prefill: 1.4-11.3x faster time-to-first-token, 1.5-3.4x lower peak memory, at no measured accuracy degradation across five benchmarks (RepoBench-P, 2WikiMultihopQA, MultiNews, BioDEX, NIAH). Against the strongest training-free token-pruning baseline tested (FastKV, SlimInfer, DASH, GemFilter, FlexFilter, MInference): up to 6.4x faster, 2x lower memory — a trained mechanism beating every training-free one in its own class, the same shape of win AbridgeKV delivered against eviction baselines. Adaptation is cheap (~1.8 A100-hours, comparable to a LoRA SFT run) and ports unchanged to both a standard transformer and a hybrid-attention model (TokenGate, T1, Stanford/UC Berkeley, code released). The two levers act on disjoint spans of the timeline — before prefill vs. after a block finishes — so they read as complementary rather than competing, though nobody has tested running both on one model. [T1, strong; per-task accuracy only in plots in the source read; no head-to-head against AbridgeKV or imperatives 1-8]

Added 2026-10-28: the trained-mechanism idea extends from a keep/evict policy to the codec itself. Every prior compression method here fits its transform offline (PCA, a fixed rotation, a reconstruction-error bit rule) and leaves the entropy model as an afterthought; training the transform, quantizer and entropy model jointly, end-to-end, against the frozen model stores 56-60x fewer bytes than bf16 at <=1.8 points of loss on three long-context benchmarks (Qwen3.5-2B, a hybrid model), 72% fewer bytes than the prior best offline codec (KVTC) at equal RULER-4K score (DCKV, T1, MIL Team/DAIMLD). The ablation that matters: training the correction network and the entropy model together saves more bytes at equal score than either saves independently — joint training is the lever, not just better components, which is the same shape of finding TokenGate and AbridgeKV already established for trained policies. No throughput measured (the full cache is restored before decoding, so the byte saving does not yet convert to a latency number), and no code release stated.

Why the map is contested

Everything above is scored on accuracy, and accuracy is an asymmetric diagnostic for a compressed cache. Under a controlled fixed-trace replay protocol — an uncompressed model writes the reasoning trace once, then every method replays the same text through its own compressed cache — eleven methods on Qwen3-8B separate on two axes that were assumed to move together. Spearman ρ between accuracy rank and reasoning-quality rank: AIME26 −0.95, GPQA-Diamond −0.20, MedCalc +0.31, RULER +0.61 (answer–evidence gap, T1).

The operating rule is the asymmetry itself: a collapse proves damage; a preserved score proves nothing. A compressed cache can keep the answer and lose the reason for it, and on matched-correct cases the chain becomes invalid for SnapKV 64.8% of the time, AdaKV 63.2%, TOVA 50.6% — against KIVI-2bit's 4.2%. More budget fixes the answer first: accuracy recovers across 512→8,192 retained tokens while chain consistency stays degraded at all of them.

Two riders. Coverage beats precision — the gap tracks losing access to parts of the trace, not reducing KV memory, which is why the quantization control is barely affected and why imperatives 1 and 3 point the way they do. And salience is not trust: sink/window policies over-preserve early claims (StreamingLLM fidelity 94.0 → 28.9 under wrong-chain span replacement) while attention-scored policies over-preserve late conclusion-shaped tokens, so each family has a position-shaped vulnerability rather than a uniform loss.

A third pushback, added 2026-08-31, attacks the ranking rule underneath most of the methods above rather than the metric that scores them. Attention magnitude is near-optimal for reproducing full attention — top-k closes all but a median 2.1–4.7% of the gap to an oracle subset — but that is a claim about reconstructing a distribution, and it has never been checked against a token's actual causal contribution to the answer. Measured directly, the two rankings are essentially uncorrelated: Spearman ρ = −0.004 (TwinKV, T1). The two results do not contradict each other — a signal can be near-optimal at one objective and uninformative at another — but together they say the field checked the easier of the two questions. TwinKV's own fix does not propose a better importance score; it scores redundancy instead — an orphan key with no duplicate elsewhere in the context is protected regardless of its attention score, a redundant donor key is safe to swap even if attention ranked it high — and runs as a training-free, attention-free repair pass composed on top of whatever eviction policy is already deciding the budget. Results are honest rather than uniform: strongest on Llama-3.2-1B/RULER, policy-dependent on Qwen3-4B, no benefit on few-shot classification, where eviction was never the bottleneck to begin with.

A second, narrower pushback runs alongside it and the boundary between them is legible. On single-needle retrieval an oracle and plain BM25 both hold 100 at 8k, 16k and 32k while recency falls to ~64 and reader-attention to ~78 (CoMem, T1) — so nearly every method here selects using an attention-derived signal, and on that diagnostic a lexical retriever from 2009 ties an oracle. Read the two together: when the evidence is one identifiable span, selection binds; when it is diffuse across many low-scoring positions, there is nothing to select and aggregate fidelity is what is missing.

Added 2026-11-20: a fourth instrument finally names a mechanism for the accuracy/trace-fidelity rank inversion this section opened with, rather than just measuring it again. On a known hybrid sparse-attention baseline (RocketKV, already cross-linked to local-inference), per-step key-selection error stays roughly constant in magnitude across decoding steps, but its effect on the output distribution rises 8x (total-variation distance) and the flip rate from 1.4% to 65% as the model's own next-token uncertainty rises — the same error costs far more when the model is already unsure. The fix widens the retained-token budget on uncertain decoding steps and tightens it on confident ones, reading the prior step's own output distribution with no extra forward pass, combined with a cosine-similarity penalty against recently cached keys to suppress redundant reasoning tokens. Across three reasoning benchmarks and two 7-8B models this beats RocketKV, RaaS, R-KV and SkipKV at every tested budget (e.g. +46%/+65% over RocketKV on MATH500), shipped as fused vLLM CUDA kernels that preserve vLLM's paged layout and CUDA-graph capture: 1.27x/1.43x latency speedup and 38%/45% higher throughput over Full-KV (RoCoKV, T1, Georgia Tech/Amazon/Google/Intel). This reframes the whole section's asymmetry as a measurable, exploitable quantity rather than an observed pattern — budget no longer has to be allocated by position or attention score alone, it can be allocated by how much the model's own confidence is wobbling. One A40, one model family (DeepSeek-R1-Distill); code released only on acceptance.

Results that change the shape of the problem

Eviction deletes a pair of sums, not a set of tokens. Write attention with the normalization opened up — o = N_S(q)/Z_S(q) — and hard eviction drops (N_E, Z_E) for the evicted set and renormalizes over what remains. The loss is algebraic, and sums are approximable even when their terms are not storable: keep a mean key, a mean value and a population count per group of evicted tokens, entering the same softmax (ResKV, T1). Improves all 32 displayed LongBench configurations and 63 of 64 RULER configurations at identical retained budget, largest at the tightest budgets, and recovers hard eviction exactly at zero residual budget — so it strictly generalizes the family it beats.

The cache has a second axis, and it is cheaper than the one everyone compresses. The cache is tokens × layers, and every method above operates on tokens. Cache one intermediate residual tensor per token at a mid-depth split instead, retrieve a bounded set of chunks, recompute only the upper layers (CoMem, T1): on Qwen3-8B at layer 12 of 36 the stored tensor is 1/18 the bytes of full bf16 KV, and at fixed retrieval breadth the model-side read is independent of stored context length. At 128k: 18.26 GB against 89.36 GB, 7.83× prefill, decode roughly a wash. The flagship configuration needs 4,000 self-distillation steps on 8 GPUs.

A third axis exists, and unlike the other two it can prove it changes nothing. Every method above compresses within a layer or restructures what a layer stores. Adjacent layers' value caches, it turns out, tolerate being merged across layers almost for free — naive cross-layer averaging holds 79.5% of full-cache accuracy for values against 2.7% for keys (GSM8K, Llama-3.1-8B-Instruct) — once the layers are aligned first. Fit a CCA-based linear map plus a per-head Hungarian permutation between adjacent layers offline, fold it into W_Q/W_K/W_V/W_O, and the model provably computes the same function; only the runtime merge of the aligned value caches introduces real error. At 25% total KV reduction this retains ≥98.3% of full-cache performance across three 8B–24B models on RULER-16K and LongBench, beats MiniCache/CommonKV in five of six settings, and composes with both key-pruning and 4-bit cache quantization for higher combined compression at little extra cost (VFold, T1). The alignment step is load-bearing, not cosmetic: skip it and the method collapses on the harder benchmark (RULER) even though naive averaging looked almost fine on the easier one (GSM8K) — the same shape of trap imperative 6 names for query-agnostic scoring. Three models only, all GQA, and the margin over CommonKV narrows (without collapsing) as more layers get grouped — but this is the first lever on this map with a correctness argument instead of a damage bound.

Added 2026-11-18: an exact, architecture-specific lever joins the third axis's correctness-argument family from a different angle — not a function-preserving transform applied to a model, but an identity the model already has. Gemma 4 31B's global-attention layers compute keys as a scaled copy of a normalized value projection, so storing one 640-value row per KV head/token instead of 1,024 loses nothing — read by an unchanged paged-attention kernel through two overlapping strided views, with only 2 of 432 final answers differing from a stock vLLM engine (attributed to run-to-run noise, not approximation). Decode KV memory per request falls 1.34-1.40x at 32K-64K tokens, decode tokens/step rise 1.24-1.38x on a two-A100 disaggregated setup, eager-mode throughput up 1.11-1.30x against a 4-9% per-step eager-mode overhead (Gemma-4 exact KV identity, T1). This is the first lever on this map that removes cache redundancy for free rather than trading accuracy for bytes at all — closer in kind to GQA's architectural shrink than to any compression imperative above — but it is architecture-specific (Gemma-4's global-attention identity) rather than general, sole-authored with no code release, and explicitly does not yet compose with an 8-bit KV cache at the engine's default settings, a second named non-composition on this map alongside the draft/target KV-quantization gap below.

A fourth axis replaces per-entry storage outright, with a weaker guarantee than the third. Rather than compressing or merging what a transformer already stores, migrate the model into linear attention's fixed-size recurrent state instead — soft (not hard) address assignment driving recurrent slot updates, with a weight-migration path for already-pretrained checkpoints and a local approximation guarantee for a restricted construction. Nine pretrained transformers (five families, 0.3B-7B), 500M migration tokens, recover an average 87.1% (79.2-95.0% range) of each teacher's accuracy gain over random guessing on six commonsense/knowledge tasks (RAM-Net, T1, Chinese University of Hong Kong). Architecturally more drastic than VFold's merge, and weaker in both proof (a local approximation for a restricted construction, not a function-preserving guarantee) and result: long-context recovery is substantially weaker than the six-task average, and gets worse for the strongest teacher tested (Mistral-7B LCC code-completion drops 70.0 → 33.4) — exactly the large-model, long-context regime where eliminating per-entry storage would matter most economically.

Added 2026-11-07: once a model has been migrated into this fixed-size recurrent state, the state itself turns out to still scale quadratically with representation dimension — a cost RAM-Net's own evidence implied but never priced. Compressing it training-free, via fixed low-dimensional subspaces, heterogeneous rank allocation (spend more of the budget where the state actually varies), and lightweight write compensation, buys 2.55x decode speedup, 7.49x lower recurrent-kernel DRAM traffic, and 3.31x lower peak memory, beating structured pruning on associative-retrieval accuracy at matched memory (SPARE, T1, University of Virginia). Together with HST above, this axis now holds three independent instruments on "what to do with a linear-attention model's recurrent state" (weight migration into it, cross-model transfer of it, training-free compression of it), and none has been tested against either of the others — composing RAM-Net's migration with SPARE's compression, in particular, is untested and would answer whether the fourth axis's weaker long-context recovery survives being compressed further.

Added 2026-11-12: a fourth instrument finds a reason SPARE's low-rank compression works at all. Across four hybrid linear-attention models (Mamba-2, GDN, KDA), queries/keys/values concentrate in a stable, input-independent low-dimensional subspace — a "linear attention sink," collapsing each recurrent state to effectively low rank — and adaptive storage via local SVD plus async CPU consolidation cuts peak recurrent- state memory up to 2.6x (1.9x average) and speeds decoding up to 1.58x (1.25x average) against Mamba-SSM/FLA on the same four models (SinkState, T1). The name collides with, but the mechanism differs from, transformer-architecture's positional attention-sink finding — flagged, not resolved. Whether this subspace-concentration account composes with or supersedes RAM-Net's heterogeneous rank allocation (which spends budget where the state varies, without naming why it concentrates) is untested.

Added 2026-11-21 and 2026-11-22: two more instruments join the recurrent-state cluster, attacking it from opposite directions. For hybrid attention/recurrent models, exact prefix caching has always had to choose between wasting a reusable prefix (coarse checkpoints) or cutting the prefill pass to save it (fine-grained exact caches). FrontierReplay observes that prefix reuse across multi-turn chat, agent loops, document QA and tree search almost always resumes at predictable structural boundaries (turn ends, branch points) rather than arbitrary positions, and materializes exact recurrent-state checkpoints only there — logging a short window of recurrent-layer inputs and reconstructing exact state via a cross-layer, state-only replay kernel, 6-37x cheaper per token than full recomputation, no host sync required. Versus existing exact caches: median TTFT down 16-89% (up to 8.9x), 80%-SLO capacity up to 1.73x, goodput up to 4.26x; versus approximate (lossy) replay, up to 1.54x higher goodput while avoiding up to a 17% accuracy drop approximate replay suffers on long contexts — exact caching beating approximate on both speed and accuracy at once is a reversal of this article's usual trade-off pattern (FrontierReplay, T1). One day later, TideCache attacks the opposite side of the same hybrid-model structural fact: rather than avoiding recomputation, it manages a hybrid model's two cache types — the large, context-growing attention KV cache and the small, bounded, resident recurrent state — as one rebalanceable memory pool on CPU-GPU superchips, using the recurrent layers' own residency and processing time to prefetch the next attention layer's KV prefix from host memory before it's needed. In SGLang on GB300/GH200: up to 2.04x as many agent turns completed in a time budget, P50 per-token latency down 20-59%, agent-workload P50 TTFT up 1.40-3.05x versus SGLang + HiCache (TideCache, T1). Neither refutes the other — one avoids recomputing recurrent state, the other streams attention KV off-GPU — but nobody has tested whether they compose, and both report only datacenter CPU-GPU superchip numbers, with no accuracy evaluation from TideCache and no consumer-hardware measurement from either.

A fifth axis doesn't compress anything — it taxes a specific architecture choice, and the field has now confirmed the tax twice in two days without either source noticing the other. Looped (recurrent-depth) transformers reuse one block of layers N times per forward pass to buy effective depth without adding parameters — a genuinely new architecture object for this map, not a compression method at all. Naively, each of the N recurrences produces its own KV cache, so the parameter saving is partly repaid in cache bytes: a stochastic-depth pretraining stage plus a post-training stage that broadcasts the final recurrence's cache into the first and trains the model to accept it collapses that cost at matched validation perplexity, with up to 31.4% better cache hit rate, 23.6% higher throughput and an 83.6% drop in simulated-low-memory p90 time-to-first-token (BeNice!, T1, 2026-10-24). One day later, a second, independently designed looped model — Accordion, which loops a fixed prefix window of layers a variable number of times rather than repeating a single block uniformly, reaching 3.6T pretraining tokens and a released multi-checkpoint line — states in its own architecture section that its KV storage scales 1.25-1.5x with loop depth, and proposes no fix at all (Accordion, T1, 2026-10-23, no cross-citation with BeNice). Read together: the cache-multiplication problem is not a quirk of one looping scheme, it recurs across at least two independently-designed ones, and the fix that exists for it has not yet reached even the next paper in the family, let alone practice. Neither source's KV-cost figure is a measured end-to-end latency/memory number on the architecture itself — BeNice's are the only measured serving numbers on this axis; Accordion's is analytical.

Added 2026-11-04: the tax gets a fix built for compression rather than architectural broadcast. BeNice avoids the multiplied cache by training the model to accept one shared cache across recurrences; LoopVQ instead compresses the per-loop caches a looped model already produces, exploiting strong redundancy across loop steps with loop-axis vector quantization plus loop-aware codebook fine-tuning — a new axis this article had not separated from the token/layer/head axes above, and explicitly orthogonal to channel-axis methods (TaSQ), so the two compose rather than compete. At 0.5 bits/element it beats standard KV-VQ baselines built for non-looped models; combined with TaSQ at 0.25 bits it retains most of BF16 accuracy; on SGLang, roughly 2x decode latency at 32K context converts to 4.3-6.1x peak throughput over BF16 (LoopVQ, T1, Seoul National University, code released). Untested against BeNice's broadcast-and-adapt fix on the same architecture — the two attack the tax from opposite ends (shrink what gets stored vs. avoid storing it N times at all) and nobody has run them together or against each other.

A sixth axis inverts the article's working assumption that compressing the cache costs something. Every lever above trades cache bytes against quality, at best for free. Reconstructing deep-layer K/V as a learnable channel-wise combination of a stride-aligned shallow-layer and middle-layer source pair — rather than sharing cache contents unchanged across adjacent or anchor layers, the way CLA/MLKV and YOCO/FusedKV do — cuts the cache ~1/3 while raising downstream accuracy at every tested size, dense and MoE, 0.5B to 16B-A3B, with the gain growing as the model gets bigger (+0.75 at 0.5B dense, +3.61 at 16B-A3B MoE; +7.00 MMLU-Pro points on the 16B MoE model specifically) (DepthGraft, T1, Shanghai Jiao Tong University/Xiaohongshu, code released). The claimed mechanism is that the reuse edge is also a gradient path — deep layers get a non-local route back to shallow/middle KV projections that adjacent-layer and global-anchor sharing don't provide, fighting Pre-LN's depth-wise information dilution — which is a different kind of claim than anything else on this map: not "this compression costs less than it looks," but "this cache-sharing choice is also a better architecture." The catch is in how it was tested: these are models pretrained from scratch with the sharing topology built in, on a primarily proprietary corpus, not a retrofit onto an existing checkpoint — so unlike every other axis in this article, it answers a pretraining-time design question, not a thing a reader can apply to a model they already have. Whether the regularization effect survives being grafted onto an already-pretrained model is untested, and bears directly on this map's and transformer-architecture's shared open question about when an architectural lever needs to be trained in from the start versus retrofitted after the fact (that map's own post-hoc looping result broke past 0.8B parameters under retrofit; whether DepthGraft's gain would survive the same test is unknown). Efficiency gains realized in serving (TTFT -26.8 to -28.8% at 128K, TPOT overhead under 1%) fall well short of the architecture's theoretical ceiling, for lack of specialized kernels — the same unoptimized-serving-stack gap imperative 5 names for attention backends generally.

A seventh axis doesn't compress an existing representation at all — it changes what the key/value projections produce, so there is nothing continuous left to compress. Every axis above operates on an already-materialized, continuous key/value tensor: decide what to keep (eviction), at what fidelity (rotation, quantization, anchor-plus-residual), or along which structural axis (depth, loop, cross-layer). Replacing the key and value projections with a finite scalar quantization bottleneck instead makes the cache discrete by construction — a packed vector of integer codes per token, with no per-token scale or zero-point to carry alongside it, unlike every quantizer above. Converting a pretrained model costs a cheap adaptation pass (0.25 tokens per original parameter), not a retrain. Across five baseline families and models from 0.6B to 8B, it is the most accurate method tested on RULER long-context retrieval at every compression ratio tried, from 12x to 97.5x — the first entry on this article that holds accuracy further out on the ratio axis than anything else measured here. A fused Triton decode kernel reading directly from the integer codes is faster than native uncompressed attention at high compression (1.01x at 32x, 1.54x at 97.5x) (Transformer-FSQ, T1, University of Edinburgh). The likely mechanism: a discrete code trained end-to-end for the task has no continuous target to drift away from as the ratio tightens, where every method approximating a continuous distribution necessarily degrades as the approximation coarsens — a candidate general answer to why every axis above eventually fails past a moderate ratio, untested against this article's other training-based instrument (RAM-Net) and not yet composed with any eviction policy, though its metadata-free codes should compose more cleanly with token-axis eviction than a continuous quantizer's scale-and-zero-point bookkeeping would. No code release stated; the RULER evaluation is long-context retrieval specifically, and whether the same advantage holds on the reasoning-heavy workloads where this article's own evidence check (above) shows compression damage concentrates differently is untested.

An eighth axis doesn't trade bytes for either tokens, bits, layers or architecture — it learns a small, decodable summary and reconstructs everything else on demand, at the largest compression ratio this article has ever carried. A memory encoder-decoder caches only a small subset of the model's own final-layer hidden states as compact "memory representations," then dynamically decodes those representations back into full per-layer KV caches only when attention actually needs them — paired with a memory sparse- attention mechanism whose retrieval index is computed once and shared across every layer, rather than recomputed per layer, for linear-time complexity. Adapting Qwen3.5-4B at 1M-token context: 1313x reduction in memory-state cache size, 6.9x faster prefill, 3.5x higher throughput, and +5.77% on an aggregate "memory performance" metric versus standard Transformer KV caching, with zero-shot transfer to downstream representation tasks competitive with specialized models (MemOnce, T1). This article's existing compression ceiling — across eviction, quantization, exact replay, and streaming — sits roughly an order of magnitude below 1313x, which makes independent replication unusually load-bearing before treating this number as comparable to anything above: no affiliation is stated, every headline number comes from one adapted model rather than from-scratch pretraining despite a broader claim across "model sizes, context lengths, and training paradigms," there is no head-to-head against any compressor in this article, no consumer-hardware measurement, and the aggregate memory-performance metric's own composition is undescribed.

Where the overflow tier lives

Everything above assumes the cache lives somewhere on or near the GPU — on-device, in host DRAM, or reconstructed from a learned summary. A 2026-11-23 arrival asks a different question: once a workload genuinely exceeds what DRAM can hold, does the overflow tier have to be DRAM at all? Agentic multi-turn sessions resend long prefixes on almost every turn — the median turn in a replayed real-agent benchmark is 142K input tokens, and over 96% of that is a prefix the server has already seen, making KV hit rate a direct throughput lever (+1% hit rate on prompt tokens is worth roughly +10% throughput). Host DRAM, the usual overflow tier beyond GPU memory, fills fast at real agentic write rates (2.3-4.6 TB/hour on one tested workload), so a 1.8 TB DRAM pool — list price roughly $76,000 — retains only 23-47 minutes of history. UMBP, the KV-cache pool inside AMD's open-source MoRI RDMA library (already used to move KV between vLLM prefill and decode nodes, co-designed with Moonshot AI for Kimi's agentic serving), is extended to place the overflow pool directly on NVMe instead, via a new UMBPStoreConnector. On 16 AMD Instinct MI355X GPUs running Kimi-K3 against a real-agent-session benchmark, an NVMe pool matched a same-sized DRAM pool's throughput within about 1%, with near-identical KV hit rates, across repeated runs on two different machine pairs; a second, longer-prompt workload showed the same roughly-1% parity. Because NVMe capacity per dollar is far higher than DRAM (roughly $42/GB server DDR5 versus roughly $666/TB enterprise SSD), a full day of retention costs about $59,000 on NVMe versus about $3.5 million on DRAM at the measured write rate — DRAM is cheaper only below about 24 minutes of retention. At larger NVMe pool sizes, throughput scales further: a 4.6 TB NVMe pool reached 5.1x a 1.0 TB DRAM pool's throughput at matched session count (93% vs. 52% hit rate) (Skip the DRAM Tier, T2, vLLM official engineering blog, AMD + Embedded LLM). UMBPStoreConnector has landed in vLLM main.

This is a different kind of lever from everything else in this article: it changes where the overflow tier physically lives, not how much of it is kept, and it is one of the only results on this map measured directly against the vault's recurring agentic-serving concern (prefix-reuse hit rate) rather than a single-shot benchmark. The caveats are symmetric with that strength: it is a vendor engineering post with a direct interest in favorable AMD hardware results, not independently reviewed, and every number is datacenter multi-GPU, multi-node, RDMA-connected — nothing here says whether NVMe-as-overflow-tier still beats DRAM once there is only one GPU and no RDMA fabric to amortize the latency gap over, which is exactly the gap this article's own standing consumer-hardware question has never closed. A same-day arrival on a different map adds a structurally different lever to the same budget without touching where it lives: Near- Far Attention scores near and far cached pages differently rather than uniformly, skipping whole regions at prefill for under 1% overhead, reaching up to 5.49x operator / 2.97x whole-model decoding speedup versus FlashInfer on Qwen3-8B at 512K context (Near-Far Attention, T1; primary map transformer-architecture). Because NFA decides which cached tokens get attended to rather than how much gets stored or where it lives, it should in principle compose with every lever in this article — untested by this source or any other here.

A new substrate question, twice: diffusion language models and multimodal context

Every method above assumes an autoregressive cache: write once, read forward, done. Two 2026-10/11 arrivals ask what happens when that assumption breaks, in two different directions.

A diffusion language model's cache is bidirectional and gets reused across denoising steps rather than written once — so KIVI and KVQuant's founding assumption (a cached prefix state is exact once written) already fails before any quantization error is even added; the cache has drifted from a full recomputation on its own. The first dLLM-specific fix — trajectory-aware calibration plus sensitivity-selected mixed-precision keys — beats both AR-adapted baselines on LLaDA at every tested cell and on Dream's prefix-cache configuration, but loses to plain KVQuant on Dream's dual-cache configuration (dLLM-KVQ, T1, Shanghai Jiao Tong University et al., no code stated) — partial, not uniform, evidence that this map's quantization imperatives need a substrate-specific variant rather than transferring unchanged, and the first time "which model reads the cache" has mattered as much as "what is stored in it." Cross-linked to diffusion-decoding.

Multimodal context breaks a different assumption: that a pruned token is gone for good. Deferring the tokens a multimodal pruner would otherwise discard into spare decode-time and post-response compute, instead of dropping them outright, recovers 77.7%/60.4% of hard-pruning's quality loss on two image-dialogue benchmarks (Qwen3-VL-8B/Qwen3.5-9B) at up to 24.1%/17.9% TTFT reduction and under 0.5% TPOT cost — though the recovery narrows sharply on video (TTFT win ~13%, TPOT overhead +14.9-19.9%, 42-69% of dialogues still needing post-response completion to recover at all) (Raincheck, T1, Zhejiang University/Alibaba Group/CMU et al.). Read against this article's own "coverage beats precision" rider: deferral is a third way to preserve coverage, alongside AnchorKV's approximate-everything and the redundancy-aware repair pass, specifically for the multimodal case where what gets pruned is a whole token's modality-specific content rather than a scalar's precision. No consumer-hardware measurement (one H20 GPU via SGLang). Cross-linked to vlm-on-device.

What nobody has run

  • Whether the redundancy repair composes with the coverage-over-precision methods above, not just with eviction. TwinKV's repair pass is tested against baseline eviction policies. Whether an orphan/donor redundancy signal has anything to add on top of AnchorKV-style approximate-everything compression — where the failure mode is already "coarse but present" rather than "deleted" — is untested, and might be the faster route to closing the causal-contribution gap than a better ranking rule would be.
  • The composition this map was coined to want. Quantizing the states a token-eviction policy has already selected — where eviction has concentrated attention onto fewer retained states and a coarse quantizer's error is least tolerable. QEvict partitions rather than composes, so the interference never gets a chance to appear.
  • The evidence check on anything but eviction. The replay protocol is released and the run is a day's work. Anchor-residual compression and learned restoration (RestoreKV, T1 — eight learned restore tokens over a LoRA-adapted pass, KVzip 38.2 → 73.2 at a 5% budget, but 42.0 vs 73.2 when trained on one evictor and run on another) both preserve coverage by construction and should land near the quantization end. If they do, the practitioner ordering stops being "prefer bits" and becomes prefer coverage, in whatever currency buys it.
  • Margins, not rankings. Every quality number here is an argmax-scored aggregate. Margin shrinkage (T1) shows aggregates survive compression while the decision margin behind them contracts, and supplies a paired instrument that would answer this in GPU-minutes. Until somebody runs it, "99.3% of full-cache RULER at 20×" is a claim about rankings and is silent about the size of the gap.
  • A curve instead of a table. Every result is reported at a handful of retention ratios against a full-cache reference. Nobody plots quality against cache bytes across methods on one axis — the single figure a practitioner choosing a budget needs, and one every paper here has the data to draw.
  • Whether the cross-layer axis stacks with the ranking-rule fix, not just with bits and tokens. VFold composes with key-pruning and 4-bit cache quantization, but nobody has tried it against the redundancy-aware or causal-contribution-aware selection fixes above — all three operate on disjoint structure (which layers share a cache, which bits a token gets, which tokens survive at all), and a practitioner stacking all three has no evidence either way. Also unweighed: whether a weight-space compensation patch, computed once per context to correct for what any compression already lost (PatchKV, T1), can repair VFold's alignment error the same way it improves every other compressed cache tested — the mechanism (a closed-form ridge-regression patch merged into the weights) is agnostic to what caused the loss, so in principle nothing rules it out.
  • Whether SparPR's gain holds against this article's own methods, not just against StreamingLLM/H2O. The first consumer-GPU number on this map is real and is also the easiest item on this list to close — it needs the same 8 GB card and a second afternoon running imperatives 1-8 through the identical scheduler, not a new experiment design.
  • Whether query-adaptive reading (imperative 7) composes with the free geometry fix (imperative 8). Both are selector/storage-agnostic layers that claim to cost nothing extra; nobody has run them on the same cache, and if they stack, this article's practical ordering gets a third free layer on top of "quantize before you evict."
  • Per-benchmark floors for every "highest average accuracy" claim, starting with RoLaQ. This article's own evidence check (above) already proved average accuracy and reasoning-chain validity can point in opposite directions; the MLA-specific quantization imperative is reported only as an average across six benchmarks, with no worst-case number, which is exactly the gap that check exists to catch.
  • Latency and memory cost of carrying more than one model's cache at once. The cross-model question (above) reports only whether attending over a pooled set of senders' caches helps accuracy — not what it costs to hold a reader's own cache plus up to eight senders' simultaneously, which is the number that decides whether the additive design is deployable at all outside a research harness.
  • Whether TokenGate and AbridgeKV actually compose on one model, since they act on disjoint spans of the generation timeline by design (before prefill vs. after a block finishes) but nobody has run both at once to confirm the composition is as free as the design suggests it should be. And whether BeNice's broadcast-and-adapt fix for the recurrence tax (fifth axis) is even mechanically compatible with Accordion's prefix-window looping — the two papers loop differently enough that "broadcast the final recurrence's cache into the first" may not translate without modification.
  • Whether RaQ's role-split MLA quantization or RoLaQ's jointly-calibrated rotation is the better way to spend an MLA cache's bits. Both report strong numbers against older MLA baselines; neither has been run against the other.
  • Whether DepthGraft's cross-layer-sharing-as-regularizer gain survives a post-hoc retrofit onto an already-pretrained checkpoint, as opposed to being trained in from scratch — the same from-scratch-vs- retrofit boundary transformer-architecture's looping thread just drew, on a different architectural lever, untested in either paper.
  • Whether dLLM-KVQ's partial win generalizes past LLaDA/Dream to other diffusion-LM families, and whether the autoregressive-cache assumption breaks the same way for other non-autoregressive architectures (e.g. this article's own linear-attention/recurrent-state entries) that this map has not yet checked against the same "does a cached prefix stay exact" test.
  • Whether LoopVQ's loop-axis compression and BeNice's broadcast-and-adapt fix for the looping tax (fifth axis) compose or substitute — shrinking what gets stored per loop step vs. not storing it N times at all are not obviously exclusive, and nobody has tried either on top of the other.
  • Whether Transformer-FSQ's discrete bottleneck is a general answer to "why does compression fail beyond moderate ratios," or specific to its own setup — the candidate mechanism (no continuous target to drift from) would predict RAM-Net's training-based state migration should also hold accuracy further out than SPARE's training-free compression of the same recurrent state, and nobody has run that comparison, or FSQ against RAM-Net directly.
  • Whether BitDecoding-FP4's three-error-source decomposition transfers to consumer FP4-capable hardware, and whether it composes with any eviction, anchor-residual, or rotation-based method this article already recommends — both arrivals this run report only Blackwell-class (B300) or unspecified non-consumer numbers, so the article's consumer-hardware gap is, once again, untouched by its newest entries.
  • Whether Muse Spark's session-aware eviction policy, host-DRAM L2 cache tier, and fp8 KV layout are additive or interacting when ablated against each other — all three are reported together, as one system, on one TPU v7 serving stack, with no component-by-component breakdown.
  • Whether Muse Spark's session-aware eviction policy and Fuse-All MoE's on-chip kernel fusion compose or compete for the same TPU on-chip/host memory budget — both report on TPU v7-generation serving infrastructure, attack different layers of the inference stack, and neither cites the other.
  • Whether SinkState's linear-attention-sink account of why recurrent-state compression works composes with or supersedes SPARE's heterogeneous rank allocation — SPARE spends budget where the state varies without naming a mechanism; SinkState names a mechanism (subspace concentration) without testing SPARE's allocation scheme against it.
  • Whether TKNP's weight-placement/cache-ownership decoupling composes with decode context parallelism's sequence-sharding, or whether a deployer has to pick one — both attack the same tensor-parallel replication problem from different angles and neither has been run against the other.
  • Whether UMBP's NVMe-pool parity holds on a single consumer card with no RDMA fabric or disaggregated prefill/decode split, and whether it composes with any compression lever above to shrink the pool further at the same cost ratio — every number reported is multi-GPU, multi-node, RDMA-connected.
  • Whether FrontierReplay's exact-checkpoint replay and TideCache's CPU-GPU cache streaming compose on one hybrid model, since they attack the same structural fact (recurrent layers' predictable timing/ boundaries) from opposite directions — avoiding recomputation versus streaming attention KV off-GPU — and neither has been tested against or alongside the other.
  • Whether MemOnce's 1313x compression ratio holds up against this article's other strong compressors (RoCoKV, FrontierReplay, AnchorKV) on the same model and workload, and whether it survives from-scratch pretraining rather than the one adapted model (Qwen3.5-4B) it was measured on — the cheapest version of this test is a single afternoon running both methods on one model.
  • Whether RoCoKV's uncertainty-tied budget generalizes past reasoning-specific models, and whether its rank-inversion mechanism (growing output-distribution sensitivity to constant-magnitude selection error) explains the inversion this article's evidence check found on non-reasoning benchmarks (GPQA-Diamond, MedCalc, RULER) as well as it does on AIME26.
  • Whether Gemma-4's exact key=value identity generalizes to any other architecture, or is a one-off property of that model's specific global-attention design — and whether it can be made to compose with an 8-bit KV cache rather than being disabled by it at the engine's default settings.

If you are choosing today

On one card, at batch 1, with memory binding: quantize the cache before you evict from it, prefer a method that stores every token coarsely over one that stores a few exactly, and read the head split off the weights for free before spending anything else. If you are evicting at all, apply the RoPE geometry fix (imperative 8) on top of whatever selector you use — it is free, selector-agnostic, and the only lever on this map with no reported downside at this article's writing. Measure on your own workload with your own attention backend, because the sign of the speedup depends on it — a fused compressed path costs 0.5% of prompt throughput against llama.cpp where an unfused one costs 44% (RotaryQuant, T1). On an 8 GB card specifically, a training-free runtime scheduler is now the one method on this map actually measured there (SparPR) — worth trying before any of the compression methods above, which still have no consumer-hardware number of their own. And if you are on more than one GPU, check whether you have a memory problem at all before you accept a quality trade to solve it.
