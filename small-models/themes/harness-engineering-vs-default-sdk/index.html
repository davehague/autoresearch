Per-workflow harness engineering vs a default SDK

Does building your own harness per workflow (Pi-style thin scaffolds, DSPy-style optimized programs) beat taking a lab/vendor SDK's defaults? This is the second half of the user's question, alongside model choice.

Through-line

  • 2026-08-17 (run 21) — Stays contested. Two arrivals, and the first one says a four-run-old conclusion on this map was measured on the wrong statistic. "Quality-neutral" was averaging over the thing the harness actually moves. Run 12 closed the shipped-harness half with an error bar — 0.079 normalized gain against per-task noise floors of ±0.035 to ±0.066 (optimizer-model-outweighs-harness-when-an-llm-builds-the-harness) — after three comparisons found quality flat while cost moved 2–3.7× (harness-swap-moves-cost-not-quality-on-real-engineering-tasks). Comparing Claude Code against native and open-source harnesses across seven models on 36 long-horizon R&D tasks reproduces that null exactly and then splits it: best@3 varies by at most 0.035 for any model, while avg@3 moves up to +0.055 (Kimi-K2.7-Code) with native harnesses improving stability (harness-choice-moves-average-performance-not-peak). The accurate statement is narrower than either prior version: shipped-harness choice does not move the ceiling and does move the repeatability. A harness that removes half a model's bad runs raises the average and never touches the best score — invisible to every best-of-n and single-run comparison, which is most of what this vault holds. Run 10's dichotomy gains a middle term (comparing shipped harnesses buys cost and stability; designing one buys quality), and any comparison we run must report avg@k, not best@k, or it will reproduce the null. Why that upgrade matters more than its size: the same study finds the open-versus-frontier separation is 0.237 on avg@3 against 0.122 on best@3 (the-open-frontier-gap-is-mostly-a-consistency-gap). Consistency is where the gap lives; consistency is what the harness moves. Two levers this map had been treating as unrelated turn out to be aimed at the same target. The second arrival kills a component we would have built, and names a failure mode this map cannot currently see. The token-efficiency case for semantic retrieval in a coding agent is, in the author's words, "asserted almost everywhere and measured almost nowhere." Measured at equal task success across three Claude models on Python and TypeScript repositories, LSP costs +6% to +118% more tokens-to-success than grep on symbol-named localization, saves nothing on reference completeness, and failed 75% of the multi-file renames grep solved (semantic-retrieval-costs-more-tokens-than-grep-at-equal-success). The mechanism generalizes past retrieval: an LSP round-trip is a genuinely external, genuinely more accurate referent, and it still loses because it is priced per question and an agent asks many questions. Same accounting that makes early pruning beat late pruning — a term multiplied by turn count beats a term paid once. And the failure mode: offered both tools, agents used the semantic one 0–6% of the time on localization, ~50% on reference tasks (agents-decline-the-expensive-tool-when-cheap-one-is-available). A declined tool costs setup and returns behaviour identical to the arm without it, so it appears in no quality comparison and no token comparison — only in an invocation count, which this literature almost never reports. Run 7's Reflexion silently never firing on the smallest model was the same failure in a different subsystem. Two instances, one rule: a harness ablation without invocation counts is uninterpretable, because a null is ambiguous between the component does nothing and the component never ran. It also supplies a partial alternative explanation for four runs of flat shipped-harness results — some of that flatness may be features that shipped and were never used. Discounts: the harness/stability finding is one model in one comparison at n=3 with no intervals, on one benchmark family's scale, with harness arms unpinned for version and effort; the retrieval study is explicitly preliminary, single-author, two languages, one closed model family, no repeat count, and its 6–118% range has a lower end inside every noise floor bracketed here.

  • 2026-08-16 (run 20) — Stays contested. Two arrivals, and the first closes this map's oldest standing complaint while the second opens a hole in an assumption every parallelism argument here rests on. The complaint is closed: a designed harness has finally been run on models we could host. Eight consecutive runs have ended with some version of every base and every optimiser in this literature is a closed frontier model — DarwinX on GPT-5.5 / GPT-5.6 Sol / Opus 4.8, HarnessOpt-Bench's five closed optimisers, AI4AI's two small frontier targets. AutoDesign runs a meta-harness optimizer — a coding agent that reads rollout trajectories and rewrites the harness recursively — and attaches the learned harness to seven code-agent-model configurations, five of them open weight. Every cell improves; average 54.99 → 67.39. Seed 2.1 Pro +17.82, DeepSeek V4 Pro +19.56, GLM 5.2 +14.01, Kimi K2.7 +12.92, LongCat 2.0 +11.87, against Codex (GPT-5.5) +5.59 and Claude Code + Claude 4.8 +5.01 (a-designed-harness-lifts-five-open-weight-targets-11-to-20-points). The harness's own content is this map's design rule yet again — provenance links back to source locations, rule-based validators for missing assets and broken links, a VLM critic on the rendered artifact, localized diagnostics driving targeted revision. External referents throughout, arrived at by a third independent automated route. The headroom law gets its tightest control. Uplift falls as base score rises across all seven cells, one task, one harness, spanning the open/closed line (harness-uplift-and-base-score-are-inversely-related-across-seven-agents). Run 17 measured this at r=0.75 on two models; run 19 replicated it across a fifty-point uplift range; this is the first time it has been tested at fixed task and fixed scaffold across a base-score range this wide, and it lands on the right side of SKILLER's qualification — a scaffold asks the model to do less, so headroom is addressable. The corollary is now hard to argue with and it cuts against the pairing: the stronger the checkpoint we pick, the less the harness buys. Run 19's Apache 27B is exactly where that bites. And a price, which almost nothing here has. ~$0.27 per completed poster on the weakest target; under $3 for a full autonomous loop of 253 tool calls and 11 editing turns over 40 minutes. Second dollar figure in this family after SKILLER's $8.95. Still unpriced, as with DarwinX: the optimization loop that produced the harness. Discounts are real — one task family, a frozen evaluator the optimizer optimizes against with no held-out arm, no repeats or intervals (so the two frontier gains sit inside every noise floor bracketed here), and human rescue required on premature convergence. The second arrival varies topology rather than scaffold, and it is the first parallelism result on this map with tokens on both arms. Anthropic ran 45 coordinated agents against independent parallel agents over the same 15 OSS projects: 266 vulnerabilities on 27M tokens against 21 on 6.5M, with only 12 findings in common — roughly 3× more per token, and the overlap explains the mechanism, since independent agents re-search ground coordinated ones partition (a-coordinated-swarm-found-three-times-more-per-token-than-parallel-agents). Same lever as early context pruning seen from the other end: the saving is in not re-reading. What it takes away is larger than what it gives. Conformity: agents in identical situations make near-identical choices — 18 of 30 naming a branch mvp-game-loop, over half building a ray tracer or a self-hosting compiler, and a job queue producing 2.4M requests against 117 accepted jobs from synchronized polling (identical-agents-make-identical-choices-and-that-is-the-failure-mode). Every scaling argument in this literature assumes N agents explore N paths; they explore closer to one. Run 7's token-matched result — repeated sampling beating every self-inspection method, penalty largest on the smallest models — still stands, but its payoff is diversity, and diversity is now a measured quantity rather than an assumption. The open question is ours and nobody has measured it: if a smaller or more heavily tuned model has a narrower behavioural distribution, the run-many-cheap-agents pattern is weakest exactly where we want it strongest. Cheap to answer without any multi-agent machinery — sample k completions from our candidate at deployment precision, count distinct strategies rather than distinct token sequences, do the same for the frontier model, and that ratio is the parallelism discount. One pushback on this map's central habit, from the same source: on an unchanged 12-hour setup, Sonnet 4.6 and Opus 4.6 opened 876 and 980 pull requests and merged ~12% while Sonnet 5 held a high merge fraction with real code sharing. Coordination competence is a model residual the orchestration cannot supply — consistent with the headroom law, and a caution against assuming a swarm architecture validated on frontier models transfers to an open 27B. Vendor post, one closed model family, unvalidated finding counts, and arms that differ in both topology and budget.

  • 2026-08-15 (run 19) — Stays contested, and for the first time the reason is not that the evidence is thin but that the two halves of the map both got stronger in the same run. The designed half finally has a protocol. DarwinX runs a population search over harnesses with the base model frozen, admitting a variant only if it extends coverage without regressing, with fitness drawn from each benchmark's own verifier and no human picking winners. It reports +7.7 on Terminal-Bench 2.1 — 75.5% to 83.2% — at avg@55, and 84.7% on a stronger base, against Claude Code on Fable 5 at 83.8% (evolved-harness-clears-the-harness-noise-floor-at-avg-55). Fifty-five trials per cell on the benchmark family where this map's noise floor was measured. Run 12 closed the shipped-harness half at 0.079 normalized gain against ±0.035–0.066 (harness-effect-on-quality-is-modest) and run 14 added a 9.4% trial error rate over 445 trials (vendor-benchmark-score-reproduced-in-an-independent-public-harness); a designed-harness effect stated at avg@55 is the first entry on this map that those three measurements cannot absorb. Run 10's dichotomy — comparing shipped harnesses buys cost; designing a harness buys quality — now has a measurement on each side rather than an asymmetry of protocols. The number to distrust is the biggest one. WebArena-Infinity moves 43.5% → 93.0%, in-domain against the search's own fitness verifier, which is the shape of proxy-fitting; the paper's own TerminalWorld ablation shows the best proxy-fitting variant generalizing worst (four specialists solving 24–27 of 41 held-out, merged reaching 28). The held-out arms are what carry: 68.3% on TerminalWorld and 84.2% on SWE-bench Verified from a Terminal-Bench-evolved harness with no in-domain evolution. That transfer is the finding with the most consequence, and it cuts against this map's own title — if a scaffold evolved on terminal work transfers to SWE work unchanged, harness gains are less per-workflow than the framing assumes, and the engineering cost amortizes across workflows rather than repeating per workflow. An automated search rediscovered the map's central rule. All seven skills DarwinX kept fall in one family — derive acceptance contracts, verify graded artifacts, ground outputs in real execution (an-automated-search-converged-on-external-verification-unprompted). Runs 7–12 reached internal referents are cheap and small; external referents are expensive and large (internal-referents-are-cheap-and-small-not-worthless) by argument. Run 17's eight independent frontier builders reached the compatible half by selection — deterministic code and format enforcement in ~100% of harnesses, verification passes in 12% (eight-builders-chose-deterministic-code-over-verification-loops). The apparent contradiction resolves the rule rather than straining it: AI4AI's targets answered multiple choice, where verification could only be the model grading itself; DarwinX's tasks have filesystems and graders, so verification has something to read. The task decides which side of the rule applies, not taste. The headroom law replicates, then breaks, and the break is the more useful half. DarwinX confirms it across a fifty-point range — 7.7 points of uplift on a 75.5% base, 49.5 on a 43.5% base (the-headroom-law-replicates-across-a-fifty-point-uplift-range). SKILLER contradicts it cleanly: Qwen3.5-9B gains 4.3–20.4 points, Qwen3.5-4B gains 1.8–13.3, with the 4B holding more headroom on all five benchmarks (skill-gains-favour-the-9b-over-the-4b-against-the-headroom-law). Restated so it predicts: headroom is addressable only where the intervention supplies something the model can execute. Scaffolding and deterministic offloading ask the model to do less and pay out where the failures are; a prompt-resident skill library asks it to do more and needs a competence floor first. That sorts all four of this vault's size datapoints, and it qualifies the free exercise queued in run 17 — measuring our candidate model's failure rate as-shipped estimates the scaffold uplift, and overestimates what a skill library will buy on a weak model. Nothing here moves the status. Both halves are single preprints, every base and every optimiser in both is a closed frontier model — the eighth run running in which the one experiment this map needs, a designed harness on an open checkpoint we could host, goes unrun — and DarwinX reports no cost at all for a loop that evaluated 62 variants and confirms at avg@55.

  • 2026-08-14 (run 18) — Stays contested. One arrival, and it contributes no evidence at all — it contributes two instruments this map has been listing as missing, plus a structural change to who ships the thing being compared. Harness-pinning shipped as a product feature. DeepSeek released dsh under MIT, a plugin architecture on the Cordis kernel where models, tools, skills, sessions, sandboxes, storage, loops, scheduling and UI are all swappable. It ships four runtime modes, one of which — Minimal — is labelled for benchmarking (a-harness-that-ships-a-benchmarking-mode-and-a-full-context-log). Every comparison on this map is discounted for an unpinned scaffold, and run 14 showed what pinning buys: one person reproduced a vendor's unreleased-harness Terminal-Bench score to the first decimal by stating model, provider, harness version, effort, skill state, a four-way token split, ±1.79 SE over 445 trials and a 9.4% trial error rate (vendor-benchmark-score-reproduced-in-an-independent-public-harness). That was one careful practitioner's discipline; a named, stripped runtime labelled for benchmarking moves it into a default. It does not make the harness good — it makes results through it comparable, which is the scarcer property. The append-only context log is the missing input to this map's cost arithmetic. The standing action item since run 14 is cost per completed task decomposed into cache-read, cache-write, prompt and output (cache-reads-dominate-an-agentic-token-bill). Computing it requires knowing what entered context and in what order, because order decides whether a segment bills as a hit or a fresh read — run 16's mechanism, where context admitted early is re-read every turn and therefore is the cache-read mass, while reordering invalidates caches (where-you-prune-matters-more-than-how-you-score). A log of every injection in order closes that gap, and it did so in the same week the price of the column it measures rose 6–12× (the-price-increase-landed-6x-to-12x-on-the-cheapest-token-category). Pin the version: this is a developer preview with promised breaking changes, which undercuts the first instrument exactly where it matters. What this map should not conclude is that a new shipped harness is a quality event. Three shipped-harness comparisons across two model families found quality flat while cost moved 2–3.7× (harness-swap-moves-cost-not-quality-on-real-engineering-tasks, harness-cost-spread-replicates-on-an-open-model); HarnessOpt-Bench put the harness contrast at 0.079 against noise floors of ±0.035–0.066 (optimizer-model-outweighs-harness-when-an-llm-builds-the-harness); and run 17 says uplift tracks the target's headroom at r=0.75, not the scaffold's sophistication (harness-uplift-tracks-headroom-not-model-size). By the standing rule — comparing shipped harnesses buys cost, designing a harness buys quality, removing model calls buys both — this is a cost datapoint waiting to be taken, and nobody has taken it: no benchmark, no token count, no comparison published. The incentive is worth naming rather than assuming away: a free vendor-authored harness landed days after the same vendor repriced cache-hit input up to 12×, and it defaults users toward that API. MIT and swappable model plugins make it reversible, which is more than most default SDKs offer.

  • 2026-08-13 (run 17) — Stays contested. Three arrivals, and the first is this map's oldest rule being recovered by machines that were not told it. The design rule, discovered rather than argued. AI4AI published a census of what eight frontier builder models actually put in the harnesses they wrote when optimising against a validation set: format enforcement 100%, greedy decoding 98%, benchmark routing 95%, forced chain-of-thought 79%, deterministic solvers 54%, few-shot 21% — and verification passes 12%, the rarest technique on the list (eight-builders-chose-deterministic-code-over-verification-loops). The authors state the gains come from offloading unstable reasoning into deterministic code, routing and format enforcement, not from more reasoning or broader sampling. That is build the scaffold, don't buy the loops (self-inspection-harnesses-lose-to-repeated-sampling-at-equal-cost) and removing model calls buys both (designed-harness-lifts-score-and-cuts-tokens-together), converged on independently by eight optimisers with no stake in the argument. Every technique above the 50% line removes or constrains a model call; the one that adds a call closing against the model is chosen one time in eight. Limits: prevalence is not effect size, and multiple-choice Theory-of-Mind makes format enforcement and deterministic solvers unusually available. Who designs still beats what they design in, and by more than we thought. Run 12's HarnessOpt-Bench put the optimiser model at 0.142 against 0.079 for the harness contrast — 1.8× (optimizer-model-outweighs-harness-when-an-llm-builds-the-harness). AI4AI is the second independent measurement: Opus-4.7 across four reasoning-effort tiers spans 0.711 → 0.856 (0.145, ρ=0.77) while the platform is worth +0.013 — roughly 11:1, before builder identity is varied (builder-capability-outweighs-the-platform-eleven-to-one). A second allocation finding rides with it: builders ran a median of 5 validation evaluations and validation count correlates with harness quality at r=0.17, so the spend that matters is effort per builder turn, not turns of the search loop — the same shape as iterated routing losing to one decision (multi-turn-routing-adds-nothing-over-one-decision). Reasoning effort was already the fifth pin (reasoning-effort-moves-one-model-15-points); it now needs pinning one level up, on the model that designed the deployment. The hole is unchanged and now conspicuous: every builder tested in both studies is a closed frontier model. The size story resolves into a headroom law. Run 9 left three measurements saying harness effects peak at 1.5B–7B against one saying mid-tier, with nobody plotting the curve (harness-benefit-peaks-at-middle-tier-models). AI4AI finds no peak — just headroom: weaker target +0.262, stronger target +0.110, headroom predicting uplift at r=0.75, with 96% of the stronger target's uplift coming from the one benchmark where it still had room (harness-uplift-tracks-headroom-not-model-size). Both prior observations fall on one line once the axis is residual rather than tier. Two consequences: the stronger the open checkpoint we pick, the less the harness buys — a trade we have never been treating as one — and headroom is measurable before any model experiment, by running our candidate on our tasks as shipped and recording where it fails. A ceiling effect on a bounded benchmark is an unexcluded alternative explanation. One cost item lands here too. SpeedRunner finds program-shaped skills are the only representation whose cost falls with experience — BabyAI output tokens to ~1/8 of ReAct, while ASI's cost grew on every benchmark and prompt optimization stayed flat (programmatic-skills-are-the-only-representation-whose-cost-falls) — with a code interpreter for reading trajectories without loading them into context as the named mechanism, which is Prime Agent's zero-token tool interface again. It also refines run 16's newest corollary. Internal referents are adequate for subtractive decisions and inadequate for generative ones would predict SpeedRunner failing: it is a generative internal loop with no replay and no validation. It wins because the artifact it generates is a program that must execute against a real environment — the loop is internal, the referent is not. Restated: an internal loop is safe exactly when its output is checkable by something that is not a model. Discount for toy environments (6–25 atomic actions), every method under 30% on the hardest one, and cost reported in output tokens — the unit run 14 retired.

  • 2026-08-12 (run 16) — Stays contested. Two arrivals, and between them they turn yesterday's scope correction into a shipped architecture and add a corollary to this map's oldest rule. Yesterday's correction is already infrastructure. Run 15 restored cross-model escalation — run a small model by default, escalate its failures to a stronger one — on the grounds that a heterogeneous pool gives the router an external referent (routing-across-models-is-learnable-routing-a-model-across-itself-is-not). Four days after that paper, NVIDIA shipped NeMo Switchyard, an open-source cross-model router, with two named production figures: LangChain cut 74% of cost by escalating 7% of calls to a frontier model, giving up 6% accuracy, and Ramp matched performance at 58% lower cost and 33% lower runtime (cross-model-escalation-routes-7-percent-of-calls-and-cuts-74-percent-of-cost). The number to steal is 7%. Every cost argument on this vault has asked which model to run; this asks what fraction of calls need the expensive one, and it reframes our threshold test accordingly — not "does the small model match" but "which 7% doesn't it, and can we spot them cheaply." Vendor blog, customer anecdotes, no task definitions or intervals; treat the direction as corroborated by switching-to-cheaper-models-is-the-largest-named-coding-cost-lever and the magnitudes as unchecked. A subtractive loop is the exception to the internal-referent penalty. This map's rule, as corrected in run 12, is that internal referents are cheap and small, external referents are expensive and large (internal-referents-are-cheap-and-small-not-worthless). Context pruning is as internal as a referent gets — the model scores its own accumulated notes for deletion — and yet lightweight heuristics cut up to 73% of tokens with little quality loss, with sophisticated marginal-value estimators failing to earn their cost over them (context-pruning-cuts-73-percent-of-tokens-with-cheap-heuristics). The corollary that reconciles it: internal referents are adequate for subtractive decisions and inadequate for generative ones. Self-critique fails because the model must judge whether its own answer is good; pruning succeeds because it need only guess which of its own notes it will not need again, where approximately right suffices and the downside is bounded. Consistent with designed-harness-lifts-score-and-cuts-tokens-together too — pruning removes model calls rather than arranging more of them, which is the intervention shape that moves cost and quality together. What does not transfer without care: a research agent accumulates retrieved evidence, most of it genuinely redundant; our workflows accumulate task state and tool results, where dropping the wrong item breaks the run. The vault's best long-horizon result handles that by moving state out of context and auditing it against the environment (external-task-state-lifts-long-horizon-agents), not by scoring it for deletion. Externalize what must persist, then prune what merely accumulated — in that order, because the externalization is what makes the pruning safe.

  • 2026-08-10 (run 15) — Stays contested, and the run's job is to correct this map's own headline from yesterday, which was overgeneralised. Run 14 read Wei et al. — five learned routing policies failing to reliably beat one well-chosen fixed setting — and promoted it to selecting among ready-made configurations buys cost; designing a configuration buys quality, stated without the word harness in it. LLMRouter runs a larger field (16+ routers) over a broader benchmark (xRouteBench, 4,767 instances, five tracks) and finds learned routing beating the strongest fixed-model baseline by ~14.6% relative on quality, because "always selecting the largest model incurs the highest cost yet delivers only mediocre performance" (routing-across-models-is-learnable-routing-a-model-across-itself-is-not). The reconciliation is a scope correction and it is ours rather than either paper's. Wei et al. route over observation modes of one agent — every alternative is the same model, so the router must predict its own failures, which is precisely why label availability and routing opportunity correlated at r = 0.95 (routing-supervision-is-scarcest-where-routing-would-help-most). LLMRouter routes over a heterogeneous model pool, where a strong model's successes label a weak model's failures from outside the weak model. So the learnability bound is real and belongs to the self-routing case: routing across models is learnable and buys quality; routing a model across its own configurations is not. That is this map's external-referent rule doing the work again, and this run it catches an error instead of confirming a habit. The deployment run 14 appeared to rule out — run a small model by default and escalate its failures — is back on the table when the escalation target is a different, stronger model, which is the arrangement we would actually ship. The same paper supplies a negative that lands squarely on this map's oldest rule. Multi-turn routing gives no consistent gain over a single decision, with Router-R1 at 22.30% against 45.46% for the best single-turn method (multi-turn-routing-adds-nothing-over-one-decision) — a second round of routing closes against the router's own prior decision with nothing new between rounds, the exact shape of self-critique and reflect-and-retry losing to plain repeated sampling (self-inspection-harnesses-lose-to-repeated-sampling-at-equal-cost). Worth carrying as a check rather than a finding: before adding a second pass to anything, name what it reads that the first pass did not. If the answer is "its own output," expect the reflection result. And a sixth variable for the pin-or-the-number-has-no-sign list, swinging harder than the grader or the effort dial: router rankings fully invert with the quality/cost weight — RouterDC first on generic tasks under quality-only scoring, tenth of eleven under maximum cost sensitivity, with MLPRouter running the opposite way on vision (router-rankings-fully-invert-with-the-cost-weight). Every "best router" claim, including this paper's own 14.6%, is a claim at an operating point that usually goes unstated. Since this vault's unit is cost per completed task under a price we control, our weight is not the literature's default and published orderings should be assumed not to transfer. One import from elsewhere, and it is the run's best evidence that this map's habits generalise. The Horizon Gap survey compiles 1,547 papers (2024–2026) and reports one pattern recurring across all six lifecycle categories: "outcome-only signals grow uninformative as horizon grows," with the field uniformly responding by manufacturing denser step-level signals (outcome-only-supervision-decays-with-horizon-across-1547-papers). This vault reached that by accumulation — curation, distillation objective, RL objective, rubric aggregation, deployment precision, skill-library drift, seed regimes, a chart axis — and the standing worry was that we were selecting for a pattern we had decided to see. A field-wide convergence compiled by people not arguing our case answers that worry without adding a datapoint. It also names the boundary: the defect scales with horizon, so it is worst on the long-running work we care about and mild on the bounded benchmarks where parity is usually claimed. Caveats across the run: LLMRouter's group publishes both the benchmark and the library scored on it, 14.6% is relative against an unnamed fixed baseline with no intervals, two of five tracks are irrelevant to us, and nothing in it is a small-model result. The survey is a survey — no new measurement, single annotator, 26.8% disclosed bleed.

  • 2026-08-09 (run 14) — Stays contested, and the run's surprise is a failed prediction of this map's own. A vendor score measured in a scaffold nobody can download — DeepSeek's 82.7% on Terminal-Bench 2.1, run in "DeepSeek Harness minimal mode" — was reproduced at 82.7% ±1.79 over 445 trials in a public harness (vendor-benchmark-score-reproduced-in-an-independent-public-harness). This map has been carried as "no model verdict is interpretable without its harness named," which invited the stronger inference that a private-scaffold number is worthless. It survived to the first decimal. The correct update is narrow: bounded benchmark, max effort, skills off — the configuration giving a harness the least room to act — so this is evidence for run 12's noise floor rather than against entanglement. Two shipped harnesses agreeing is what a 0.079 effect against ±0.035–0.066 noise looks like when you run it twice. Two things arrive alongside and both are more useful than the agreement. First, routing joins the ledger and lands where everything else did. Wei et al. varied observation mode rather than scaffold across six modes × eight site-model cells on VisualWebArena and WebArena: five learned routing policies, none reliably beating a single well-chosen fixed mode, while a cost-based rule cut spend 9.5–30.6% across all eight cells at maintained success (routing-cuts-cost-without-beating-a-fixed-choice). Third independent route, third time the same sentence, and now it can be stated without the word harness: selecting among ready-made configurations buys cost; designing a configuration buys quality. It is also the independent corroboration Databricks' 30%+ routing claim lacked, at a near-identical magnitude with the quality half measured rather than asserted. Second, and this one should change a plan we had not examined. The paper's mechanism is that routing supervision is produced at the agent's own success rate, with label availability and routing opportunity correlating at r = 0.95 — so the weaker the model, the thinner the signal for routing around it (routing-supervision-is-scarcest-where-routing-would-help-most). The obvious deployment for a small model (run it by default, detect its failures, escalate) has its detector trained by the model whose failures it must detect. Fifth instance of this map's most durable rule, with the paper's own control attached: cost routing worked because a token count is an external referent that does not require the agent to have succeeded. Sixth instance arrives the same run from SkillZip's ReZip, which revises skill macros against execution evidence and validates compression by structural reachability rather than judgment (skill-revision-grounded-in-execution-evidence) — and it suggests a gradient inside the "external" bucket we have been treating as uniform: structural check < re-execution < environment audit, ascending in cost and presumably in power, unmeasured. Noise-floor bookkeeping, because it is now the map's most quoted number: 12–14% of web-agent outcomes flip run to run at identical settings, alongside HarnessOpt-Bench's ±0.035–0.066 and a 9.4% trial error rate in the Terminal-Bench reproduction. Three independent measurements, three task families. Most single-run comparisons in this vault's own literature sit inside that band. Caveats: the routing paper is one preprint on web agents and observation-mode routing is not model routing; its authors note the learnability bound weakens as agents get stronger, so the pessimism should not be carried to a mid-size arm untested; and the Terminal-Bench reproducer discloses authorship of the harness being validated.

  • 2026-08-08 (run 13) — Stays contested.   • 2026-08-07 (run 12) — Stays contested. This map's founding claim gets its first measurement one level up, and there the ordering reverses. HarnessOpt-Bench runs five frontier models as optimizers — each given an evaluation-guided budget to rewrite the prompts, tools, control flow, memory and orchestration around a cheap target model — through their own native coding harnesses and through a shared third-party one, on four tasks, 111 scored runs. Changing the optimizer model moves normalized gain by 0.142 on average; changing the harness it works through moves it by 0.079 — the model contrast is ~1.8× larger, with an optimizer spread of +0.228 (claude-opus-5) to −0.174 (gpt-5.6-terra) (optimizer-model-outweighs-harness-when-an-llm-builds-the-harness). This does not contradict harness-dominates-model-in-performance-variance — that claim is about a fixed scaffold around a fixed model at inference, this one about who builds the scaffold — but the two compose into a spending rule: if we automate harness search, the budget goes on the optimizer, and the framework it drives is close to a free variable. Native harnesses showed no consistent advantage; Claude's strongest rows are through opencode, not claude-code. The second number is the more important one, because it is the first published noise floor in this column. Per-task resolution bands are ±0.045 (OfficeQA), ±0.066 (BrowseComp-Plus), ±0.054 (Terminal-Bench), ±0.035 (GAIA) — so the harness contrast of 0.079 sits inside or barely above three of four, while the model contrast clears all four. What is not flat is the optimization itself, which buys up to 0.63 on OfficeQA. The run-10 dichotomy survives this intact and sharpens: design buys quality, choosing which shipped harness to design in does not. Note whose configuration this is — the target models being optimized are cheap production models (deepseek-v4-flash, gpt-5.4-mini, grok-build), so this is the first measurement of how well the process of wrapping a cheap model works, and it works unevenly. Second item, and it is a genuine counterexample to the rule this map has been leaning on hardest. Run 9's formulation was binary: a loop earns its cost when it closes against something outside the model, and is worthless when it closes against the model. EnvACE builds the second kind deliberately — the agent role-plays its own environment's responses instead of executing against a real one — and it is not worthless, beating GRPO by 5.5% on τ²-Bench and topping environment-scaling baselines on three of four benchmarks (internal-referents-are-cheap-and-small-not-worthless). The strong form of the rule is wrong. The weak form is the useful one and it holds by an order of magnitude: external task state audited against the real environment bought 5.5–28.9 points (external-task-state-lifts-long-horizon-agents); simulating the environment inside the model buys 0.2–3.8, with one outright loss (BFCL-v4 46.04 against EnvScaler's 47.07). Restated so it predicts magnitudes rather than sorting methods: internal referents are cheap and small; external referents are expensive and large. One structural caveat keeps it from being a clean refutation — EnvACE's joint optimization is still driven by task-success reward, so the rehearsal is internal but the gradient is not. A thin external anchor spread over internally-generated rollouts still pulls; nothing here shows a model bootstrapping from nothing. Third, a measurement-hygiene finding this map should adopt as a standing requirement. HarnessOpt-Bench's per-task table swings hard — gpt-5.6-sol buys 0.49 on GAIA and 0.03 on BrowseComp-Plus — and the authors state gains "vary substantially across tasks and seed regimes" (harness-optimization-gains-swing-with-task-and-seed-regime). That is the harness instance of the pattern the vault has now traced through curation, the distillation objective, the RL objective, deployment precision and skill-library drift: the defect is invisible unless the report is split, here by task and seed rather than by condition. Any harness we tune on our own workflows needs per-task, multi-seed reporting before we believe it, because the run that overfits its seed and the run that generalizes produce the same single number. The benchmark's harness — fixed budget, trusted execution environment enforcing evaluation boundaries, every candidate version preserved for audit — is a cheap template to copy. Limits on all of it: both papers are unreplicated preprints from single groups, "normalized gain" is HarnessOpt-Bench's own construct, 111 runs across five models and four-plus harnesses is thin per cell, every optimizer tested is a closed frontier model, and neither paper prices anything.
