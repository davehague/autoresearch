Open vs frontier — is the capability gap closing?

Whether open-weight models are close enough to frontier proprietary models that the remaining gap is about economics and robustness rather than raw capability.

Through-line

  • 2026-08-20 (run 24) — Stays contested. One arrival, on the checkpoint this vault has been accumulating reasons to choose, and it is the cleanest natural experiment this map has had. The candidate base traded recall for agency, within one family, in twelve weeks. Same vendor, same 27B, same license class, measured by the same aggregator on the same methodology. Intelligence Index 37.70 → 52.02 (+14.32), Agentic Index 27.51 → 50.88 (+23.37), Terminal-Bench 2.1 60.67% → 79.78%, τ-banking 16.70% → 48.04%, GPQA 84.24% → 90.51%, HLE 23.08% → 33.92%, GDPval normalized 0.320 → 0.523, hosted input price $0.60 → $0.425. And Omniscience accuracy 19.6% → 15.58%, down 4.02 points (the-candidate-checkpoint-traded-recall-for-agentic-capability). Every reasoning and agentic axis rose; the one that fell is parametric factual recall. A practitioner thread reported the regression from a private trivia set at every quantization and sampling setting before the benchmark was consulted, and the strongest corroborating comment reproduces it on a different task family with a mechanism: the model is markedly more eager to reach for search and fetch tools, and the regression appears only with those tools disabled. That is a good trade for this vault and worth saying plainly. Every workload in the decision — repository-scale coding, terminal work, tool-calling, node-graph procedures — sits on the side that gained by double digits. What got worse is what this vault has argued should be retrieved rather than memorised, and run 24's coherence-debt evidence says the substitution is safe: context and parametric memory substitute for one another, and a supplied fact works as reliably at 128,000 characters' distance as beside the edit (harness-token-spend-differs-12-8x-at-identical-test-outcomes). A model that reaches for a tool instead of recalling is playing the channel the harness controls. What the table does not license is any claim about why: reallocation, data mix, post-training recipe and a more abstention-prone alignment pass all predict this exact shape. The measurement warning is the more portable half. The Omniscience Index rose 10 points — −20.02 → −9.98 — while its accuracy component fell 4, because the hallucination rate fell 49.27% → 30.29% (abstention-not-knowledge-moved-the-omniscience-index). The model got more cautious, not more knowledgeable. Both readings describe the same two rows and they support opposite sentences. This map reads composites constantly and mostly as capability — run 22 took the frontier band off the Intelligence Index, run 15 recorded a single open model's accuracy swinging 27 points across API endpoints (api-endpoint-changes-an-open-models-accuracy-by-27-points), run 12 found the grader is a variable that has to be pinned. Add the general form: any index that nets a capability against a failure mode reports progress for a model that merely stopped guessing. Before quoting a netted score, read which component moved. There is a second-order use for it. A falling hallucination rate is the closest public proxy we have for the property run 24 measured directly on the harness side — whether an agent says it is blocked instead of fabricating, which ranges from 100% to 0% by model (a-missing-fact-produces-wrong-work-not-a-stopped-agent) — and nobody is reading it that way. Discounts: one anonymous practitioner's private trivia set with no protocol and self-reported vibes as the confirming instrument, by its own author scoped to airgapped weights-only retrieval; benchmark rows with no intervals or repeats from an aggregator whose endpoint-variance problem this map has already recorded at 27 points; and two checkpoints are not a trend.

GLM 5.2, open weights, was statistically tied with Claude Opus 4.8 on quality, at $1.28 per task against $1.94 (open-weight-model-ties-frontier-on-private-uncontaminated-codebase). The authors' summary is "open models are here for coding." Three things make this the strongest gap measurement the map holds, and one thing keeps it from moving status. It is uncontaminated — private tasks, which is the objection the authors themselves raise against SWE-bench and which no other source here escapes. It is objectively graded. And it is priced per task, the unit that appears on a bill, rather than per token. Against that: the post publishes no pass-rate table, no task count and no interval behind "statistically tied," so the tie's strength is unverifiable; and Databricks commercially serves open models, so the incentive points at this conclusion — though it points away from the frontier vendors who supply most of this map's contrary evidence, which is not nothing. Also unchanged: this is one harness-controlled study and says nothing about open-model-live-use-robustness-is-disputed-and-tracks-the-harness, which is a claim about variance across scaffolds, not about a mean. Read alongside run 9's three-way confound warning, the design here is notable for pinning two of the three legs — one harness family, one task set — while leaving precision unstated, which is now the standing gap in every comparison this map collects.

  • 2026-08-04 (run 9) — Stays contested; no new gap measurement, but the theme's own methodological rule gets an instrument, and a note on how much of any gap here is now unmeasured. Since run 7 this map has held that no model verdict is interpretable without naming its harness, because every live-use verdict turned out to be a joint measurement. Scale AI's taxonomy operationalises that: 41 failure modes, each assigned to an edge between model, harness, environment and evaluation rather than to a blamed component, κ=0.76 against human labels (agent-failures-belong-to-edges-not-components). Edge attribution is the honest output for this map's founding dispute — identical DeepSeek V4 Flash weights at full precision, opposite verdicts, the split tracking the scaffold. It settles nothing (no census of which edge failures land on, and κ measures rater agreement rather than correctness, so a taxonomy can be reliably wrong), but if we ever run our own comparison the failure-coding scheme has to be fixed before the experiment, not after. One thing to carry into every future comparison on this map: run 9's serving evidence establishes that quantization silently costs long-tail factual recall while leaving reasoning benchmarks flat (quantization-erases-long-tail-knowledge-invisibly). Practically nobody runs a frontier-class open checkpoint at full precision, and the local-use verdicts this theme collects are overwhelmingly from quantized weights — so a third confound now sits alongside model and harness in every open-vs-frontier anecdote here: which quantization, and on which capability. The theme's entanglement problem is not two-way, it is three-way.

  • 2026-08-03 (run 8) — Stays contested, and the theme's most testable residual-gap hypothesis gets a concrete coding-task instance. Alibaba's open-weight Qwen3.8-Max (2.4T MoE, ~95B active; open weights shipping, plus an open 27B running in ~17 GB VRAM) reaches the frontier band on a bounded terminal benchmark — Terminal-Bench 2.1 86.6, ahead of Opus 4.8 and Fable 5 at 84.6, just behind GPT-5.6 Sol at 88.8 — while trailing 12–15 points on the harder, open-ended SWE benchmarks: SWE-bench Pro 67.7 vs Fable 5's 80.0, FrontierSWE 73.5 vs 88.8 (open-weight-model-ties-frontier-on-verifiable-trails-on-hard-swe). That is exactly the shape the sub-thread predicted — parity where the task is verifiable/bounded, a persistent gap where it resembles the multi-step engineering our workflows are. It reinforces the contest rather than resolving it: the trajectory toward parity is real on one axis and visibly incomplete on the other. Two discounts, both familiar to this theme. The numbers are vendor-reported with no independent replication and the weights aren't out yet, so nothing is verified; and every score is a model-plus-harness measurement in Qwen's own scaffold, so per this theme's entanglement rule none of these gaps is a pure model gap. The open 27B is the object most relevant to us, and its scores weren't published — the thing to chase next.

  • 2026-08-02 (run 7) — Moved emerging → contested. Run 6 said a fourth converging datapoint with real measurement would justify consolidating; what arrived instead is the first evidence running the other way, and it lands exactly on the counter-claim this theme had flagged as untouched — robustness in messy live use. Practitioners running DeepSeek V4 Flash 0731 locally at full precision reached opposite verdicts on whether it can follow rules at all, in a 198-comment dispute that never resolved (open-model-live-use-robustness-is-disputed-and-tracks-the-harness). That is the axis a blended intelligence index cannot see, and it is contested in the same week the index put this model mid-pack at 50 (open-weight-model-mid-pack-on-intelligence-index) — so it qualifies the forecast in open-frontier-gap-closing-fast-risk-is-regulatory rather than refuting it. Two things sharpen the contest rather than muddying it. (a) A specific, testable shape for the residual gap surfaced in that thread: open weights have largely closed on verifiable tasks and still trail on non-verifiable ones, because non-verifiable work needs reward models the open labs cannot afford to build. (b) The dispute itself sorted by harness, not by model — same weights, same precision, opposite verdicts, the difference being OpenCode vs Pi vs a bare chat window, plus an unowned chat template. So "is open robust in live use" may not be answerable at the model level at all. Arriving alongside, and cutting the other way: on production-fidelity oncall root-cause analysis, the best of five frontier agents managed 25.3% on realistic inputs and 10.0% on hard ones, with the weakest hallucinating a root cause in 40% of reports (frontier-agents-top-out-at-25-percent-on-realistic-oncall-rca). No open-weight arm, so it does not measure the gap — but it lowers what the gap is a gap to, and it is the strongest-method reminder yet that "frontier plus a default SDK" is a weak incumbent on messy multi-source work. Third datapoint, smaller: a 2.8T open-weight model now serves from a single node of rentable commodity hardware at 952 tok/s (accelerator-memory-capacity-swings-self-hosting-economics) — practical reach, independent of leaderboard position. Net: the capability trajectory still points toward parity; what is now genuinely contested is whether measured parity survives contact with a real workload, and by how much of that is the harness.

  • 2026-08-01 (run 6) — Stays emerging; a second practitioner voice sharpens the direction without adding measurement. Lambert forecasts open weights reaching the current frontier tier (GPT-5.5 / Opus 4.8 / GLM-5.2) in ~6 months, with DeepSeek leading the open field (open-frontier-gap-closing-fast-risk-is-regulatory) — consistent with the theme's economic-not-capability read, and echoed the same night by the DeepSeek V4 Flash datapoint already here (open-weight-model-mid-pack-on-intelligence-index).   • 2026-08-01 — Opened. Two early signals point the same way: a practitioner's read that the race is "economic staying power and fast-following, not a widening capability gap" (open-frontier-gap-is-economic-not-capability), and an open-weight model landing on the same blended intelligence axis as frontier (open-weight-model-mid-pack-on-intelligence-index). Both thin — one opinion, one datapoint — hence emerging. The live counter-claim to watch: closed models stay "more robust in messy live use."

Sub-threads: what actually bounds open is now the theme's centre of gravity, and it has three live candidates rather than two: robustness in messy live use (contested as of run 7, and possibly a harness property rather than a model one), a regulatory cap above a capability line, and the newest and most testable — non-verifiable tasks, where the constraint is reward-model quality and therefore compute, not weights. That third candidate is the one worth splitting off first, because it predicts where to look for the gap instead of merely asserting one. A second thread is now unavoidable: this theme's measurements and harness-engineering-vs-default-sdk's are entangled — every live-use verdict here turned out to be a joint measurement of model and scaffold, which means "is the gap closing" cannot be answered without fixing a harness first. Run 9 makes that thread three-way rather than two-way: precision joins model and harness as an uncontrolled variable in every local-use verdict this map collects, since a quantized checkpoint loses long-tail recall while its reasoning scores stay flat. Any future comparison here has to pin all three. Run 10 puts the non-verifiable-tasks candidate under real strain: on uncontaminated, objectively-graded, multi-language production engineering work — the most open-ended task this map has ever measured — an open model tied the best frontier model on quality and beat it on cost per task. The candidate is not dead (one study, no table, self-published), but the next thing to look for is no longer "where is the gap on hard tasks" so much as which reported gaps survive removing benchmark contamination. That reframing is cheap to test and would explain the run 8 / run 10 disagreement without either being wrong. Run 11 tests it and gets a mixed answer — two decontaminated, externally-graded studies disagree (tie on pull requests, seven points on enterprise workflows) — so the reframing survives as a method but stops being an explanation. What replaces it is a sharper predicate for what actually bounds open, and it should now lead the thread: long-running vs long-context. Where a harness can carry state, structure and verification, open weights close or win; where the material has to sit inside the model, they trail, and the best harness anyone has built does not fix it. That is testable by holding the harness fixed and varying only how much material the task forces into context — cheap, and directly answerable on our own workflows. It also subsumes the entanglement thread rather than competing with it: the gap appears precisely where the scaffold has nothing to contribute. Run 12 leaves that predicate untouched and disqualifies the instrument most often used to argue against it. Leaderboard aggregates cannot express a long-running/long-context split by construction, and this one moved 3–4 points on a grader change while the open-vs-frontier separation it reported was under a point — so no aggregate reading, in either direction, should be treated as evidence on this map again without its grading version stated. The entanglement list grows to four: model, harness, precision, grader. Practically that retires the cheapest kind of update this map receives (a leaderboard moved) and leaves only the expensive kind (a task-split measurement with all four pinned), which is the right trade but means this map should expect to move less often. Run 15 splits the leading predicate and grows the entanglement list to five. Long-running was two things — task horizon and system memory — and separating them turns the queued workflow-sorting exercise into a three-column sort where only one column (resident context) is a model property we would have to buy or train for; the other two have working answers on this vault's ledger already, which is the cheapest route to shrinking this map's question rather than answering it. The fifth entanglement is the endpoint, and it is different in kind from the other four: harness, precision, grader and effort change how weights are run or scored, while a serverless endpoint changes which weights you are served — 100% to 73% of reference on one open checkpoint, undisclosed and unhashable. So the standing rule extends from "name the harness, precision, grader and effort" to "and name the endpoint and the date, or the model is not identified." Alongside that, the run's contamination finding gives this map its bluntest self-assessment: on the benchmark family most often used to argue about coding, filtering leakage costs top systems 66% of their score — several times any separation this map reports — which means the honest position on published gaps is not that they are wrong but that they are unresolved, and only our own uncontaminated task-split measurement will change that.
