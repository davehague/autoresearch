The note outranks the code

Give a coding agent a written standard that contradicts the working code in front of it, and it follows the standard. In The Working Set of a Coding Agent (arXiv 2608.16630), that happened in 39 out of 39 trials across two harnesses — including the cases where the standard prescribed the worse implementation. The code was right there. The agent read it. It went with the note.

That result is easy to file as a curiosity about convention files. Three studies from the last few weeks say it is something more general, and that it has a price tag on both sides of it.

Memory systems that lose to having no memory

MemTrapBench (arXiv 2608.20202) asks a question the memory-benchmark literature had mostly skipped. Existing benchmarks check whether a system stores and retrieves the right thing. This one holds retrieval correct — every planted memory is accurately recorded and genuinely relevant — and grades what happens to the answer.

The results are lopsided enough to be worth stating flatly. Five memory frameworks (FullText, LightMem, MemOS, SimpleMem, EverMemOS) were run on two models. All ten combinations scored below having no memory at all. Gemini-3-Flash-Preview manages 85.16% with no history and 71.17% with the best framework. Qwen3-30B-A3B-Instruct-2507 manages 81.83% with none and 70.13% with the best.

The paper's worked example is clinical. The conversation history establishes that epinephrine is unsafe for one specific child with a rare channelopathy. The query then asks about a different, previously healthy child in anaphylactic shock. Without the history, the model answers intramuscular epinephrine, which is correct. With it, it does not.

The important control is the one that rules out the boring explanation. A "no-trap" arm keeps the task and the relevant history and removes only the designed trap. It scores 94.39% against 92.29% with no memory at all — clean history helps, slightly. Trap-inducing history scores 31.05%. So the problem is not that context is bad, or that there is too much of it. It is that a stored memory carries the conditions it was true under, and none of these systems carries those conditions along with it.

Nor is truncation a fix. At 25% of the history the score is already 36.03%; at the full history it is 31.05%. Almost all of the damage arrives the moment memory is introduced.

Two caveats belong in the same breath as those numbers. The instances are deliberately constructed traps, so the absolute scores forecast nothing about production traffic — what survives is the ordering and the control. And the grading is done by a language model, with a second judge as a reliability check but no human agreement study.

Domain knowledge that helps one model and hurts another

SWE-bench Science (arXiv 2608.19799) benchmarks coding agents on 119 real defects in 98 production scientific repositories across 20 domains. Buried under its headline result is a paired ablation: on the 91 tasks where explicit scientific guidance can be stripped cleanly, run each agent with and without it.

Two configurations were tested, at opposite ends of the score range:

without guidancewith guidance
GPT-5.6-sol in Codex36.26%31.87%
DeepSeek-V4-flash in Claude Code16.48%23.08%

The stronger agent got worse. The weaker one got better. And the token accounting inverts along with it — guidance cut GPT-5.6-sol's mean input from 3.86M to 3.70M tokens, while it raised DeepSeek-V4-flash's from 4.84M to 7.40M, a 53% increase for those 6.6 points.

It is not a shifted margin, either. GPT-5.6-sol solved 8 tasks only with the guidance and 12 only without it. Something in the supplied text pulled it off tasks it had been solving.

The authors name the mechanism on both sides, and are careful about what they claim. Well-grounded information supplies constraints that local code symptoms do not — limiting cases, coordinate consistency, authoritative interfaces. Poorly aligned information "can also induce anchoring, scope spillover, or premature reliance on a supplied explanation." They also state plainly that the paired differences "do not establish statistical significance or a causal effect." Two configurations, 91 tasks, one run each. Treat the direction as interesting and the magnitude as unestablished.

What the three have in common

Three different artifacts — a convention file, a retrieved memory, a paragraph of domain guidance. Three different task families — repository edits, question answering, scientific software repair. One shared failure: the agent treats supplied prose as authoritative and still-in-scope, over the code and the environment actually in front of it.

That reframes something. Written guidance for agents is normally costed as an asset with a build price — you spend tokens or hours writing the skill file, and you get accuracy back. These results say the artifact also carries a liability, and the liability grows with how out-of-date or out-of-scope the text is, not with how much of it there is.

Demystifying Agent Skills (arXiv 2608.14036) suggests why the effect is so strong. Across 8,135 trial records, it attributes 65.7% of skill effects to "procedural anchoring" — the skill stabilizes execution into a groove — against 4.5% for actually injecting knowledge the model lacked. If most of what a written procedure does is establish a groove, then a stale groove gets followed exactly as reliably as a fresh one. Nothing in the mechanism distinguishes them.

What to do about it

The cheap instrument is the obvious one, and almost nobody runs it: ship the artifact and the no-artifact arm together, and keep the artifact only where the paired arm loses. Every one of these studies found the no-artifact arm winning somewhere, and none of the systems being evaluated would have noticed.

Memory subsystems deserve their own note, because the cost evidence points the same way as the accuracy evidence. Total Recall at What Cost? (arXiv 2608.11879) benchmarked the serving cost of agentic memory systems and found break-even against no memory at all ranging from the first turn to never, depending on the system's internal behaviour rather than on conversation length. Put that beside MemTrapBench and adding memory is currently the one agent component where the available evidence argues against it by default — it can cost money that never pays back and lower the answer quality that motivated it.

Finally, if you are choosing between a strong model and a cheaper one, the guidance result cuts in a direction worth planning around. On this evidence the same context file is a liability for the strong model and an asset for the weak one. That is two opposite decisions from one artifact, and today nobody measures which side of it they are on.
