Coordinating 45 agents found 12.7× the vulnerabilities on 4.2× the tokens — the first parallelism result on this map with tokens attached to both arms

Every harness result this map holds varies the scaffold. This one varies the topology, and it is the first with a token count on each side.

Anthropic ran 45 coordinated agents and a set of independent parallel agents over the same 15 open-source projects. The coordinated swarm found 266 vulnerabilities on 27M tokens; the independent arm found 21 on 6.5M tokens. Per token that is roughly 3× more findings, and the mechanism is visible in the overlap: only 12 findings appear in both sets, and about half the swarm's results sat outside core directories. Independent agents re-search the same ground; coordinated ones partition it.

That is the same lever as context-pruning-cuts-73-percent-of-tokens-with-cheap-heuristics seen from the other end — the saving comes from not re-reading what has already been read — and it generalizes the cost mechanism run 16 established for a single agent's context to a fleet's search space.

The finding that changes a design we would otherwise build is the failure half. Conformity: given identical situations, agents make near-identical choices. Eighteen of thirty agents named a git branch mvp-game-loop; over half built either a ray tracer or a self-hosting compiler; in a job-queue simulation, synchronized high-frequency polling produced 2.4 million job requests and 117 accepted jobs. Every scaling argument in this vault's harness literature assumes N agents explore N paths. They explore closer to one.

This is a direct threat to the cheapest small-model deployment pattern on the board. Run 7 established that repeated sampling beats every self-inspection method at equal token cost, with the penalty largest on the smallest models (self-inspection-harnesses-lose-to-repeated-sampling-at-equal-cost). That comparison still holds — but sampling's payoff is diversity, and diversity is now a measured quantity rather than an assumption. If a smaller model has a narrower behavioural distribution, the run-many-cheap-agents strategy is weakest exactly where we would want it strongest. Nothing here measures that: every agent in every experiment is a closed frontier Claude model.

A third result pushes back on this map's central habit. On the same 12-hour game-development setup with no scaffold change, Sonnet 4.6 and Opus 4.6 opened 876 and 980 pull requests and merged ~12%, while Sonnet 5 held a high merge fraction with substantial code sharing. Coordination competence is a model property the orchestration cannot supply — consistent with the headroom law rather than against it (harness-uplift-tracks-headroom-not-model-size), and a caution against assuming a swarm architecture validated on frontier models transfers to an open 27B.

Discounts are heavy. Vendor research post; one model family; counts rather than validated vulnerabilities, with no false-positive rate — and triage cost is what decides whether 3×-per-token survives contact with a security team. The two arms also differ in both topology and token budget, so coordination and spend are not fully separated.
