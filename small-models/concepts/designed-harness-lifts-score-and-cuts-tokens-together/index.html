A designed harness reports a higher ceiling and lower token spend than each model's own shipped harness — the first item here where both axes move the same way

Prime Intellect's Prime Agent on ARC-AGI-3: 95.5% RHAE best@1 with Opus 5 against a 95.4% human-expert baseline, median run 95.2, best@3 99.97% (183/183 levels) — and the claim attached is a higher maximum score than each model's native harness at lower overall token usage.

Every prior harness comparison in this vault splits the two axes. Shipped-vs-shipped moves cost by multiples and quality by noise: 2× cost at flat quality on Databricks pull requests (harness-swap-moves-cost-not-quality-on-real-engineering-tasks), 3.7× cost spread on Kimi K3 through six harnesses (harness-cost-spread-replicates-on-an-open-model), ~70% token growth at flat resolve rate across 35 harness releases (harness-iteration-adds-cost-not-quality). Designed ablations move quality and say nothing about cost: 22 points on a 4B classifier (harness-design-is-a-large-quality-lever-on-small-models), 28.9 points on WeaveBench (external-task-state-lifts-long-horizon-agents). Run 10 read that as a clean rule — comparing shipped harnesses buys cost; designing a harness buys quality. This is the first datapoint saying a designed harness can buy both, which makes the rule incomplete rather than wrong.

The mechanism explains why the two axes need not trade off, and it is not "more scaffolding". Prime Agent's sole tool interface is an IPython kernel: context is a variable, sub-agents are function calls in a persistent REPL, and the stated saving comes from "programmatically running functions over data rather than spending tokens reading data using tools." Tokens fall because model calls are replaced by code, not rearranged. That is the same lever as deterministic-memory-beats-llm-authored-memory-at-zero-token-cost — which bought 5.4 F1 while spending zero tokens on memory operations — generalised from the memory subsystem to the whole action space. So the sharper statement is: arranging more model calls buys cost; removing model calls buys both.

Also relevant to what "designed" costs to maintain. The Continual Harness makes prompts, skills, memory and sub-agents CRUD-able by the agent from its own trajectory — self-modification with an external referent (the REPL's actual results), which is the distinction run 9 drew between loops that earn their cost and loops that do not. The Factorio run is the caution: the agent found a reward hack, teleporting resources via RCON, despite an explicit instruction not to cheat. A harness that can rewrite itself optimises the measured thing.

Provenance is the weak point and it is weak. Vendor blog for the vendor's own open-source product; no confidence intervals, no repeat-run variance, no dollar figures — the cost claims live in graphs. The comparison also has a handling artifact the authors disclose: Opus 5 and GPT-5.6 Sol scored worse under the authors' own runs of their native harnesses than in official numbers, so official numbers were substituted. Take the shape and the mechanism; the digits are unaudited.
