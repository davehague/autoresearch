Harness uplift tracked residual again — 7.7 points where the base scored 75.5%, 49.5 where it scored 43.5%

Run 17 replaced "harness effects are largest on small models" with headroom: uplift tracks how much the target was already failing, at Pearson r=0.75 across two targets (harness-uplift-tracks-headroom-not-model-size). The discount attached to it was real — two target models, both closed small frontier models, on Theory-of-Mind multiple choice, with a ceiling effect an unexcluded alternative explanation.

DarwinX reproduces the pattern on agentic benchmarks with frozen closed bases. Terminal-Bench 2.1: base 75.5% → 83.2%, uplift +7.7. TerminalWorld held-out: base 61.0% → 68.3%, uplift +7.3. WebArena-Infinity: base 43.5% → 93.0%, uplift +49.5. Three points, and the uplift ordering follows the residual ordering exactly, with a fifty-point spread in gain across a thirty-point spread in starting score.

Two reasons this is confirmation rather than replication. It is three points from one system on three benchmarks that differ in more than difficulty — the WebArena number is in-domain against the search's own fitness verifier, which inflates it by an unknown amount, and the Terminal-Bench base is already near the top of a bounded benchmark, so the ceiling-effect objection from run 17 applies here too. Nobody has yet varied base capability while holding task and protocol fixed, which is the experiment that would settle it.

What survives regardless is the corollary, now supported on the task classes we actually care about rather than on multiple choice: the harness lever and the model lever are substitutes, not complements. Every argument in this vault for pairing a strong scaffold with a small open model has implicitly assumed a stronger base and a better harness would compound. On this evidence they trade. Picking a stronger open checkpoint to close the model gap spends the harness gain doing it.

And the free action run 17 named is unchanged and now better supported: run our candidate small model on our own tasks as shipped, record the failure rate, and treat that rate as the predicted harness uplift. It needs no training run, no cluster and no procurement, and it queues alongside run 15's horizon/context/persistence sort (long-horizon-long-context-and-long-term-memory-are-three-independent-properties) and the procedure-versus-novel-artifact sort.
