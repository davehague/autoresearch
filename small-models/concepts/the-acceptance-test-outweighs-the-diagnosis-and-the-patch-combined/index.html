Ablate the filter and you lose 11.4 points; ablate the intelligence that writes the fix and you lose 4.2

AutoSaddler has three components. Ablating each, from a full-system 62.0 on GAIA2 pass@1:

RemovedScoreCost
In-depth diagnosis (deep debugging → shallow reflection)57.8−4.2
Structured intervention (targeted patch → unconstrained edit)56.9−5.1
Generalization-aware selection (validated accept → trajectory-specific repair)50.6−11.4

The acceptance test is worth more than the diagnosis and the patch structure combined (11.4 against 9.3). The generator is the replaceable part.

This is the vault's most-supported design rule arriving with a price tag on it. Run 12's corrected form: a loop earns its cost when it closes against something outside the model. Here the "outside" is a held-out task split, and ablating it costs half the method's total gain. Run 19's automated harness search converged on external verification without being asked to (an-automated-search-converged-on-external-verification-unprompted); this is the same finding measured by removal rather than by observation.

The practical consequence is a reordering of what to build first. A harness-improvement loop for our own workflow does not need a frontier model writing the patches — it needs a held-out task set large enough to reject bad ones. That is a data-collection job, not a modelling job, and it is exactly the dependency run 13 identified as unnamed in the build order: a corpus of tasks where our model fails.

And the companion paper says nobody has built one with enough power yet. the-validation-gate-cannot-resolve-the-effects-it-is-gating reports dev splits of 10–14 tasks against ±6–12 points of run-to-run variance, with 18 rejected candidates whose intervals contained zero. Two papers in the same week: one prices the gate at 11.4 points, the other shows the gate is under-powered. The cheapest thing this vault could commission is not a new harness — it is a properly powered acceptance test for one.

Discounts: one benchmark for the ablation (GAIA2), one optimizer model, pass@1 with no intervals; the three components are not independent, so "removing X" may degrade the others; and the ablated variant is not a null — 50.6 is still −2.4 from the ReAct base of 53.0, which means an unfiltered loop actively hurt.
