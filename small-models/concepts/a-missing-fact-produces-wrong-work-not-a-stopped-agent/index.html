When an agent lacks a fact it does not stop — it fabricates, and whether it says so ranges from every trial to none depending on the model

Withhold every fact a task depends on and record what each configuration does. Six or eight trials apiece:

Opus, Claude Code88100%
Fable, Claude Code8675%
Sonnet, Claude Code8225%
Haiku, Claude Code8112.5%

GLM-5.2, opencode600%
pooled461737%

Codex CLI and opencode never report it and instead produce a confident wrong migration every time. Haiku is the only configuration that fabricates the missing file outright, in 3 of 8. Within a model the rate is stable — a separate 96-trial check confirms it — so this is a model property, not noise. The harness changes the symptom: holding Sonnet and the task fixed, Claude Code produces mostly all-or-nothing failures, Aider partial migrations at 39–70% passing, OpenHands a split between 60–67% and 96–98%. Coverage decides whether the agent fails; policy decides how the failure looks.

Two consequences, and the second is the one that should change what we build.

The abstention rate is not a small-model property, it is an idiosyncratic one. The two configurations at 0% are GPT-5 in Codex CLI and GLM-5.2 in opencode — one frontier, one open-weight, and GLM-5.2 is exactly the class of model this vault plans to deploy. The pairing has always ended with an open model running inside a harness we control on work nobody watches turn by turn. This says the default behaviour on a missing fact is to act anyway and say nothing, and that the one configuration in the table resembling ours never abstains.

Read-derived instruments cannot measure the thing they were built for. Because a missing fact is filled by fabrication, an instrument watching file reads looks for a hole that has already been closed. The authors report the collapse directly: on SWE-bench, where the models likely already know the repositories, what an agent reads no longer predicts success. Run 20's AutoResearchEval found no agent checks what it produced against what it found (no-agent-checks-what-it-produced-against-what-it-found); this adds that no agent will tell you it could not find it, and that our natural telemetry is blind to both.

The design instruction the authors draw is the right one for our harness work: keep the facts an edit depends on available at write time, and check availability against what the agent produced rather than what it read.
