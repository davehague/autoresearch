The open 35B could author a valid environment 3.3% of the time where four API models managed 66.7–90.0% — and fine-tuning on the pipeline's own traces took it to 83.3%

On held-out briefs, oracle-pass rate for constructing a valid executable environment:

  • Qwen3.5-35B-A3B, zero-shot: 3.3%
  • Claude Opus, GPT-5, DeepSeek-V4-Pro, GLM-5, zero-shot: 66.7–90.0%
  • Qwen3.5-35B-A3B after SFT on 29,823 construction traces: 83.3% (p = 1.2×10⁻¹⁰)

This is the third independent observation of the same asymmetry: the open model can run the loop but cannot design it. Run 26 found most harness uplift sitting one level above the harness, in the meta-agent that proposes candidates (most-of-the-harness-uplift-lives-one-level-above-the-harness). Run 27 priced that layer as 2.4–3.3 hours of frontier inference per search, irreducible with evaluation budget (a-harness-search-costs-117-dollars-and-22-hours). Here the design step is measured directly on a different task — writing the environment rather than the scaffold — and the gap is an order of magnitude.

The good news is the second number, and it is genuine. The design capability transfers by plain SFT on traces the pipeline emits for free as a by-product of running. That is the first result in this vault showing the frontier-inference line item in a self-hosted build loop is removable rather than permanent — bootstrap with API calls, keep the traces, train the open model to take over.

Discounts: oracle-pass on held-out briefs is the authors' own grader; 3.3% → 83.3% is measured on a construction task whose distribution is defined by the same pipeline that generated the training traces, so this is closer to in-distribution imitation than to acquired design ability; no repeats or seeds; and the API baselines are zero-shot while the open model is fine-tuned, which is the comparator-quality problem this vault flags repeatedly (parity-claims-keep-using-zeroshot-comparators) — running in the vault's favour this time, which does not make it sound.
