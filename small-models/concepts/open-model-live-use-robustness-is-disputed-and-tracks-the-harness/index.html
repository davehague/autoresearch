Practitioners running the same open frontier-class weights reached opposite verdicts on instruction-following — and the split sorted by harness, not by model

A practitioner running DeepSeek V4 Flash 0731 natively at full precision reported that it ignores rules, prompts and skills across first- and second-person phrasings and across English and Chinese, concluding the model is "not actually frontier level and not just benchmaxxed." A 198-comment thread did not converge. A commenter running the same weights from the same Hugging Face repo through their own vLLM script and existing agentic loops reported "internal measurements for our workloads in the last 24 hours were clearly improved" and long-horizon phased tasks performing great — with harnesses "built entirely around opencode." Others reported the model failing long-horizon work under OpenCode but succeeding under Pi, or bluntly: "to test the model on llamaserver chat is useless."

Two things follow, and only one is about DeepSeek.

First, this is the first evidence to run against the theme's accumulation, and it lands on the counter-claim the theme had named as untouched — robustness in messy live use. The same week a blended index placed this model mid-pack at 50 (open-weight-model-mid-pack-on-intelligence-index), people running it in anger could not agree whether it works, which is precisely the axis an intelligence index cannot see. A separate commenter argues the remaining gap is concentrated in non-verifiable tasks — claiming even GPT-4o still beats all open weights on long-form multi-chapter fiction, because non-verifiable work needs reward models the open labs cannot afford to build. That is a specific, testable shape for the gap, and it is compatible with open weights having closed on verifiable code.

Second, and more useful: the dispute is not resolvable at the model level. Same weights, same precision, opposite verdicts, and the reported difference is the scaffold — plus an unowned chat template (DeepSeek shipped no official Jinja; Bartowski's and Unsloth's GGUFs carry materially different ones) and a prompting style that has to be relearned per model (firm positive instructions, no hedging, few negative constraints). This is harness-design-is-a-large-quality-lever-on-small-models reappearing in the wild at frontier scale, with harness variance large enough to flip a model's reputation. Note the direction: the people getting good results built a harness around the model; the people getting bad results ran defaults, a third-party template, or a chat box.

Grade: single-study, and weak even for that — forum anecdote on both sides, no task counts, no measurement, and the obvious control (does it reproduce on the official API endpoint?) was asked repeatedly and never run. The OP's post-hoc architectural explanation — sparse attention storing system prompts as compressed summaries, only two of 43 layers fully dense — is uncited forum reverse-engineering and should be carried as a hypothesis, not a finding. What earns the ingest is not any single claim but the natural experiment: a clean instance of identical weights producing contradictory verdicts under different scaffolds.
