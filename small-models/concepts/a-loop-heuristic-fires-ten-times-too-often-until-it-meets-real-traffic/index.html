One exemption list, measured against 381 real sessions, cut a loop detector's firings by about 90% with no loss of genuine catches

The obvious way to detect a stuck agent is to count identical tool results and warn after N. Measured over 381 real sessions, exempting mutating tools from that count fires ~90% less while keeping every genuine catch — because writing six files returns six identical "success" strings, which is productive rather than stuck.

The tuned design needs three detectors, each covering what the others cannot:

  • No-progress — identical results N times (default 6), skipping a ~55-name cross-harness union of mutating tools.
  • Action loop / ping-pong — the same tool-plus-arguments signature repeating while results differ every time, because screenshots, timestamps and harness message IDs make results unique and blind the first detector. Compared against the previous two turns, catching A→A→A and A→B→A→B, default 4. Deliberately does not exempt mutating tools: reissuing the same write with the same arguments is a loop.
  • Consecutive errors — with escalating warnings, classifying harness-generated envelopes (StatusCode: non 2xx, MCP errors, script failures) as failures for every tool class.

The same tuning logic appears in the failure classifier: output starting Traceback/Error:/fatal: marks a failed tool unless the tool is one of ~30 read/query tools, since a read returning a log that begins with Error: is a successful read of error-shaped content. And in what it refuses to do: it never matches user permission rejections, because scolding a model into retrying after a human said no is harmful.

The transferable claim is a budgeting one. Every heuristic anyone would write into a custom harness has this shape — cheap to specify, wrong by an order of magnitude until it meets production traffic, and fixable by an exemption list that can only be discovered from logs. Run 17 found that eight builders given a free hand chose deterministic code over verification loops (eight-builders-chose-deterministic-code-over-verification-loops); this says what the deterministic code costs to get right. Budget for the traffic, not the heuristic.
