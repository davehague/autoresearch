Routing labels are generated at the agent's own success rate — the weaker the model, the less signal exists to route around it (r = 0.95)

The paper's structural result, and the reason its five routing policies failed: routing supervision is produced at the agent's success rate. You only learn that mode A beats mode B on a task by observing A succeed there. Label availability and routing opportunity correlate at 0.95 across the eight experimental cells — supervision is scarcest exactly where the upside is largest.

This pushes back directly on an architecture this vault has been drifting toward without examining. The obvious way to deploy a small model is to run it by default, detect the cases it will fail, and escalate those. This says the detector's training signal is manufactured by the very model whose weakness it is meant to detect, at that model's competence — so the worse our small model, the thinner the supervision for routing around it. It is the same shape as self-inspection-harnesses-lose-to-repeated-sampling-at-equal-cost and self-judgement-penalty-is-largest-on-the-smallest-models: a loop closing against the model inherits the model's limits, and the penalty scales with how much you needed the loop.

So this is a fifth instance of the vault's most durable rule — a loop earns its cost when it closes against something outside the model — and the paper contains its own control for it. Cost routing worked (9.5–30.6% saved) precisely because a token count is an external referent that does not require the agent to have succeeded first. Same experiment, two policies, one grounded outside the model and one not, and only the grounded one paid.

One caveat that keeps this honest and is the authors' own: the bound weakens as agents get stronger, since stronger agents generate more labels. This is a constraint on routing around a weak model, not a permanent property of routing — which is the case that matters to us, but also means the pessimism should not be carried forward to a mid-size arm without re-testing.
