A Claude-built legal harness gets successfully ported to a self-hosted DeepSeek-V4.1-Flash on secondhand 2018 V100s, with the practitioner explicitly naming the capability gap rather than claiming parity

A solo practitioner's fifth self-hosting update reports porting a legal document harness — built for and validated against Claude between February and July 2026 — onto a self-hosted DeepSeek-V4.1-Flash-1017 setup, after judging it "the first model that is remotely similar to Opus 4.5/4.6." Claimed results: 8x V100s (2018-era datacenter GPUs bought secondhand) running DeepSeek-V4.1-Flash at near-NVFP4 quality, 500K-524K context, 100+ tok/s decode solo and ~160 tok/s with two concurrent chats; separately, two DGX Sparks running 3-4 concurrent DeepSeek agent sessions at 1M context. The author credits frontier models themselves (Opus 5.5, Fable 5.2) with doing the optimization and requantization work needed to get this running, and their own prompting skill with porting the harness. Self-assessment, quoted directly: "It's not as good as frontier, but it all works, right now... Actual productivity gains, actual frontier tasks being replaced."

This is a concrete, if anecdotal, instance of this theme's central question, and it is unusual among this theme's recent entries for naming the gap explicitly rather than implying parity. It also functions as a harness-engineering data point: the harness itself — not the model underneath it — survived the swap from Claude to DeepSeek, which several of this vault's other entries (model-harness interference, Harness-Zero, HAD) treat as the genuinely hard part. No total hardware cost or cost-per-task figure is given, which is the number this theme's other entries (the $10,000-buys-how-many-tokens comparison, GPU-hours cost curves) would need to make this commensurable with an API alternative.
