A clean corpus can still produce a flat distillation run, because the teacher that supervises must match the teacher that wrote the traces

On-policy distillation carries an unstated precondition: teacher consistency — the model supplying token-level supervision should also have generated the demonstrations used to train the SFT reference. Assembling a corpus the practical way violates it constantly, since SFT data has mixed or unknown provenance and you may prefer different models for generating data and for supervising. In those cross-teacher settings, Lightning OPD 2.0 reports, even a stronger OPD teacher can yield little improvement over the SFT reference.

The diagnosis is that raw teacher–reference disagreement mixes genuine context-specific teacher evidence with a recurring component tied to differences in wording, formatting and reasoning cadence — style, not substance — so the update budget partly goes to imitating another model's prose rhythm. Cross-fitted style residualization estimates that component at rollout level and subtracts it before building the token-level update. Starting from Klear-Reasoner-8B-SFT, the method reaches 82.4% on AIME 2024 and 63.0% on LiveCodeBench v5.

This extends the vault's data-pipeline constraint into a failure mode it had not catalogued. The existing worry was corpus corruption — syntactic and semantic damage with threshold effects and a capability curse (finetuning-is-fragile-to-data-quality). This is a clean-corpus failure: nothing is wrong with the data, and the run still goes flat because of a provenance mismatch between the traces and the supervisor. It also sits beside the run 5 curation instrument (reasoning-data-quality-readable-from-first-tokens) without overlapping it — a prefix-loss filter grades whether a trace is worth training on and says nothing about whether the teacher supervising it is stylistically compatible. Both belong to the same operational gap: nothing here is caught by a loss curve.

Belongs to training-your-own-feasibility; bears on finetuned-slm-narrow-task-parity via distillation-does-not-universally-close-the-gap, to which this adds a fourth named precondition.

Grade: single-study — one paper, one starting checkpoint, math and code benchmarks only, code not yet released. The reported 82.4 / 63.0 arrive without baseline figures beside them, so "consistently outperforms Lightning OPD" is a direction with an unstated magnitude. The method also adds real machinery to the training loop (cross-fitted estimation over rollouts), not a config flag. The cheap, robust takeaway is the negative claim: if we distil from a teacher that did not write our SFT traces, a null result is the expected outcome and does not mean the student cannot learn the task.
