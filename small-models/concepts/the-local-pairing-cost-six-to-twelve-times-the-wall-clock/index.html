The open model in a custom harness took 5.7–12.3× the wall clock of the frontier model in its default SDK, and produced the worse artefact both times

Same task, same day, same operator: Claude Code + Opus 5 finished in 21 minutes with the only usable port. qwen3.8:27b took 1h 40m in the author's own thin harness and 4h 18m in a heavy one — 5.7× and 12.3× the reference — and both outputs were graded bad.

Every cost argument this vault holds for the pairing is denominated in dollars per token. This is the first item here to price the latency side on open-ended work at full context, on hardware (RTX 6000 Pro 96 GB) well above what a typical self-hoster has. The mechanism is not mysterious: ~70% of a local agentic run is prompt processing (an-agentic-run-is-seventy-percent-prompt-processing), and agentic harnesses re-read constantly.

The consequence for the vault's central comparison is that the pairing's cost advantage has a second axis nobody has been costing. A workflow where a human waits on the result, or where throughput per day is the constraint, is priced in hours here, not cents — and run 24's 12.8× refetch multiplier lands on that axis too.

Discounts: n=1 per arm, eyeball-graded, one-shot prompt, on a task the author calls "brutal for a local LLM" and "not representative of anything"; the frontier arm confounds model and harness completely (Claude Code was never pointed at the open model); FP8 KV cache is an uncontrolled condition; and no dollar figure is computed for either side, so this is a wall-clock observation and not a cost comparison.
