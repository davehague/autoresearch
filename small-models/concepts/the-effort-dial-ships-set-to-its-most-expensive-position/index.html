Reasoning effort is not just an unreported variable — on this vault's candidate checkpoint it ships defaulted to xhigh, worth 6× the tokens on a trivial prompt

Run 13 added reasoning effort to the pin-list because ARC Prize moved one open checkpoint 46.0 / 56.0 / 61.4 on ARC-AGI-2 across three effort settings with weights, harness, precision and grader all fixed — 15.4 points from one parameter (reasoning-effort-moves-one-model-15-points). That framed effort as a variable experimenters forget to report.

A hands-on with Qwen 3.8 27B — the Apache-2.0 checkpoint run 19 named as our candidate base — shows it is also a variable the vendor pre-sets, and pre-sets to the most expensive rung. The model defaults to xhigh. Asked to "draw an svg of a circle," it deliberated for minutes about gradients, animation and extra geometry. On the author's standard pelican-on-a-bicycle prompt:

  • reasoning on: 21 minutes, 22,276 reasoning tokens, 3,223 output tokens
  • reasoning off: 137 seconds, 3,715 tokens total

Roughly 6× the tokens and 9× the wall clock, on one prompt, from a setting nobody chose.

Three consequences.

Any as-shipped cost figure for this model is an xhigh figure. This vault's unit is cost per completed task, decomposed four ways (cache-reads-dominate-an-agentic-token-bill). A per-task number computed from a default run is not slightly high — the reasoning column swamps it. Same defect as pricing from a headline per-token rate, one layer up.

The effort sweep queued since run 13 changes purpose. It was framed as our cheapest available cost/quality curve, obtainable with no training run and no procurement. Its more valuable output is now the setting we would actually deploy, because the shipped default is demonstrably wrong for short tasks and the vendor picked it for benchmark scores rather than for a bill.

And it is this vault's central design rule firing in an unexpected subsystem. Extended deliberation with no external referent is self-inspection under another name; the SVG-of-a-circle case is what it looks like when the loop fires on a task with no headroom to find (self-inspection-harnesses-lose-to-repeated-sampling-at-equal-cost). It also inverts the headroom law's practical advice — uplift may track residual, but spend does not, so effort should be gated on task difficulty rather than set globally.

It counts because the default is a published property of a checkpoint this vault has already named as its candidate, and because the arithmetic it breaks is arithmetic we were about to do.
