The vault's long-running/long-context predicate was two predicates — a 1,547-paper census separates task horizon, model context and system memory

The Horizon Gap survey disambiguates three properties the literature routinely conflates and shows they are logically independent:

  • Long-horizon — a task property: how many sequential decisions or actions completion requires.
  • Long-context — a model property: how many tokens one forward pass can attend to.
  • Long-term memory — a system property: whether information persists across steps or sessions.

A system can have an enormous context and no persistence; a long-horizon task can be run inside a short window through aggressive summarization.

Run 11 coined this vault's sharpest predicate for where open weights trail frontier: long-running work, where a harness supplies state and structure, versus long-context work, where the material has to sit inside the model (open-weights-in-the-best-harness-still-trail-frontier-in-a-stock-sdk). That cut survives, and this extends it by splitting the first term. What we called long-running bundles task horizon (how many steps) with system memory (what persists), and those are separately buildable: horizon is addressed by decomposition and external task state (external-task-state-lifts-long-horizon-agents), persistence by a memory subsystem — where deterministic machinery already beat model-authored memory outright at zero LLM tokens (deterministic-memory-beats-llm-authored-memory-at-zero-token-cost).

The consequence is for the sorting exercise this vault has queued as its cheapest open item. Sorting our workflows by how much material each forces into context was to be a two-pile sort; it should be a three-column sort — steps required, tokens that must be resident, state that must survive a session — because only the middle column is a model property we would have to buy or train for. The other two are things we build, and both have working answers on this vault's ledger already. If our workflows sort mostly into columns one and three, the open-vs-frontier question may not need a training run to answer.
