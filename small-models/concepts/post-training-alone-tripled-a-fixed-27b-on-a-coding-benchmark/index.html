Post-training alone moved a 27B by 3.2× on one coding benchmark with the architecture unchanged — the same claim as GLM-5.3, at a size we could reproduce

Run 18 recorded Z.ai's claim that GLM-5.3 went Terminal-Bench 3.0 4.6 → 28.3 and DeepSWE 46.2 → 66.9 on an unchanged 743B base, all from scaled post-training (post-training-alone-moved-an-open-model-six-fold-on-a-terminal-benchmark). The note attached was that this is the lever we have at a scale we do not.

Qwen3.8-27B is the same claim two orders of magnitude smaller. At identical parameter count to Qwen3.6-27B, the vendor's own before/after table reads DeepSWE 1.1 13.3 → 42.2 (3.2×), QwenSWEBench 49.3 → 79.0, Terminal-Bench 2.1 63.4 → 73.0, OSWorld-Verified 63.9 → 84.3, Agents' Last Exam 10.6 → 20.4 and BabyVision 28.9 → 85.6. A release-day community diff of the two model configs reported zero architectural changes, a thread that reached 921 points on r/LocalLLaMA. The model card independently describes the 27B as built on the Qwen3.5 architectural foundation — three minor versions on one shape.

Why this matters more than the GLM instance. 27B on a single node is inside our premise; 743B is not. The training map's standing question is whether our cluster can move a checkpoint enough to matter, and the two ends of the compute range recorded in run 18 were ~4,000 B200-hours for a 1B from scratch and one A100-hour for a LoRA on a 1.5B (a-tuned-1-5b-runs-real-work-on-a-laptop-cpu-for-one-a100-hour). This sits between them and says the answer is post-training, not pretraining — which is also the community's read, and the economically obvious one: pretraining compute dwarfs post-training, so a lab amortizes one base across several releases.

What stops this being an argument for building. The hard part is the part nobody describes. Z.ai's account of what it actually did was "more environments, more diverse tasks, and more compute spent training on them." Qwen's card says nothing at all — no training compute, no data description, no ablation separating SFT from RL from environment scaling. Every recorded gain is a result of post-training at frontier-lab scale with frontier-lab environment engineering, and this vault has already established that environment construction is the unpriced dependency in every version of the build order it holds. Run 13's CalibForge is the only thing on the ledger that prices any of it, and it prices task generation, not environment construction (training-tasks-must-be-calibrated-to-the-solver-not-just-validated).

Two smaller riders. The config diff establishes that the shape is unchanged, not that the pretraining run was — a re-pretrain on the same architecture would produce an identical diff, and nothing here excludes it. And the numbers are vendor-reported at unstated effort, harness and precision, so the magnitudes carry much less than the direction.
