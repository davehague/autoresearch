One A100-hour to train, 941 MB to ship, no GPU to serve — the cheapest end-to-end datapoint this vault holds

The training side: LoRA rank/alpha/dropout 32 / 64 / 0.05 on all linear modules of Qwen2.5-Coder-1.5B-Instruct, LR 2e-4 cosine with 3% warmup, 2 epochs, batch 16 × 2 grad-accum, seq 512, bf16, seed 42, over 125,770 pairs, on one A100 80GB for about an hour. The serving side: merged to bf16, converted f16 GGUF, quantized Q4_K_M to 941 MB, running at 31.9 tok/s on a 4-thread laptop i5 with 1.6 GB resident, 0.59s median warm latency and ~2s cold start. And it does real work — 0.620 on an execution-graded shell-command benchmark (the-eighth-parity-claim-and-its-margin-is-inside-the-noise).

This confirms finetuning-is-cheap-enough-to-be-routine and undercuts its own framing at the same time: an hour is cheaper than "routine" implied. Every dependency the vault has added to the build order since run 12 — calibrated task corpora, teacher access, provenance filtering, OOD eval batteries — is a dependency of the hard version. The easy version is one GPU-hour over permissively-licensed public data.

Two reasons it matters more than its grade suggests.

It is serving-economics-own-vs-api's sub-thread (a) at its physical limit. The vault's economics have always split into small compiled models (overwhelming) and frontier-class open weights at scale (marginal, volume-gated, headcount-dominated — self-hosting-savings-erased-below-engineer-scale-thresholds). Here there is no serving cost to model at all: the marginal cost of an inference is electricity on hardware already on a desk. Set against a DeepSeek API that just raised cache-hit input up to 12× (the-price-increase-landed-6x-to-12x-on-the-cheapest-token-category) and a GPU market up 87% (the-hardware-side-of-buy-vs-build-took-an-87-percent-price-increase), this is the one configuration where buy-vs-build is not a close question — and it is close to unaffected by either price move.

It anchors the low end of a compute range this vault now has both ends of. One A100-hour for a LoRA on an existing base; ~4,000 B200-hours for a 1B trained from scratch (a-1b-on-license-clean-data-ties-a-4b-in-general-and-beats-it-in-domain); an unpublished figure for post-training a 743B. Our build order starts from an open checkpoint, so we sit at the cheap end of that range, not the middle.

The honest ceiling: single-turn, 64-token outputs, English-only, no tool loops, no multi-step state. This is not agentic work, and run 10 showed compression takes instruction-following and tool use first (compression-degrades-agentic-skills-more-than-reasoning) — the capabilities that would matter if the same recipe were pointed at our workflows. The safety note is the author's own and it is the right one: a denylist over a Turing-complete shell is not containment.
