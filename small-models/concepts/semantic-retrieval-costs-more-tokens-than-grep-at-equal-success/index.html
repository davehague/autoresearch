The precise tool lost to the noisy one: LSP cost 6–118% more tokens-to-success than grep, and failed 75% of the multi-file edits grep solved

The efficiency argument for putting a Language Server in a coding agent is that typed, precise results save context against grep's noise. The paper's own framing of the evidence base is the finding worth quoting: the claim is "asserted almost everywhere and measured almost nowhere" — no public source isolates the LSP-versus-lexical token delta at equal task success.

Measured with a five-arm ablation on Python and TypeScript repositories across Claude Opus 4.8, Sonnet 4.6 and Haiku 4.5:

  • Symbol-named localization: LSP costs +6% to +118% in tokens-to-success.
  • Reference completeness: LSP is more precise and saves nothing.
  • Multi-file rename edits: grep succeeded; LSP failed 75%.

The mechanism transfers past retrieval, which is why this belongs on the map rather than in a tooling note. An LSP round-trip is an external referent and genuinely more accurate — so it is not an instance of the vault's self-inspection failure (self-inspection-harnesses-lose-to-repeated-sampling-at-equal-cost). It loses on pricing structure: grep returns noise the model discards inside one already-cached read, while LSP returns clean answers billed per symbol, and an agent asks many questions. The cheap noisy tool wins because the precise one is priced per question. That is the same accounting that makes early context pruning dominate late pruning — a term multiplied by turn count beats a term paid once (where-you-prune-matters-more-than-how-you-score) — and the same reason removing reading entirely beat arranging more calls (designed-harness-lifts-score-and-cuts-tokens-together).

The metric is the other half of the contribution and it is the reusable part: tokens-to-success, not tokens. A component that halves retrieved tokens and doubles the turn count has saved nothing, and only a success-normalised denominator catches it. That is the same correction run 10 forced on cost-per-token and run 14 refined into the four-way cache/prompt/output split (cache-reads-dominate-an-agentic-token-bill), arriving one level down at the individual component.

For us the instruction is direct, because semantic retrieval is exactly what we would put in a scaffold on exactly this reasoning: measure it on our repositories before adding it, in tokens-to-success.

It counts because it is the first measurement of a claim the field had been passing along unmeasured, and because the metric it introduces is the one this vault already argues for.
