Retrieving the right skill neither guarantees success nor is required for it — which bounds the measurement rule this map adopted two runs ago

The paper's third finding is that exact ground-truth skill invocation is neither sufficient nor necessary for downstream success. A skill can be retrieved, used, and make no difference; a task can succeed without the skill anyone would nominate as correct.

Run 21 adopted a rule from the opposite direction. Offered both a semantic tool and grep, agents used the expensive one 0–6% of the time on localization (agents-decline-the-expensive-tool-when-cheap-one-is-available), and the conclusion drawn was that a harness ablation without invocation counts is uninterpretable — a null result is ambiguous between the component does nothing and the component never ran. Run 7's Reflexion silently never firing on the smallest model was the same failure in a different subsystem.

Both are correct, and each bounds the other. Run 21 establishes that invocation counts are necessary to interpret a null. This paper establishes they are insufficient to attribute a positive. The rule that survives both is narrower than either: report invocations, and do not infer causation from them. That is a real tightening, because the natural next step after run 21 — instrument the harness, count what fires, credit what correlates — is exactly the inference this result forbids.

The mechanism reading makes the non-sufficiency unsurprising and the non-necessity interesting. If 65.7% of skill benefit is procedural anchoring rather than knowledge injection (skills-anchor-procedure-they-do-not-inject-knowledge), then anchoring on any coherent procedure may be most of the effect, and which specific skill was retrieved matters less than that something structured was. That would explain both halves at once — the "wrong" skill still anchors, and the "right" one adds little beyond anchoring. It would also mean the retrieval collapse (skill-retrieval-precision-collapses-from-30-to-3-percent-as-a-library-grows) is less damaging than it looks, since precision would not be the operative quantity. Those two readings pull in opposite directions on the same build decision and the paper does not adjudicate between them.

What is open, and it is ours to close: if invocation does not attribute, what does? This vault's instrumentation debt has been accumulating for twelve runs and is entirely about grading signals we generate. The honest position is that we currently have no validated way to attribute a harness component's contribution short of ablating it and measuring end-to-end with repeats — which is expensive, and which nothing in this literature routinely does.
