The same accumulated experience is worth 14.6 points in one harness and 2.3 in another

Same frozen GLM-5.1. Same initial skill library. Same task descriptions and the same instruction about how to record and reuse experience. Terminal-Bench 2.0 run as repeated sweeps, each harness folding its own runs' experience back into its own skill library. Improvement from iteration 0 to each harness's best observed result:

HarnessGain
PILOT+14.6
OpenCode+7.9
Pi+2.3

Nothing about the model changed and nothing about the available experience changed. The harness is the whole variable, and it spans 6.3×.

This is the second independent measurement of the same cell. Run 30's Recuris ablation, from a 58.1 base on τ²-Retail, put a skill library alone at +2.0 against externalised working memory at +23.9 (the-task-state-board-is-worth-twentyfour-points-and-the-skill-library-is-worth-two). Pi's +2.3 here is that +2.0 measured in a different lab, on a different benchmark, on a different model, by a different mechanism. A skill library bolted onto a thin harness does approximately nothing, and we now have two sources saying so. Run 23's retrieval-precision collapse from 30% to 3% as a library grows (skill-retrieval-precision-collapses-from-30-to-3-percent-as-a-library-grows) is the mechanism; run 25's null result where every memory framework scored below no memory at all (every-memory-framework-scored-below-no-memory-at-all) is the same finding at its floor.

The operational consequence is a build-order one and it is specific: if we install a skill library without also installing the machinery that decides when to write to it and when to read from it, we should forecast +2, not +15. PILOT's machinery is a separate supervisor process watching a shared stream — a second concurrent model instance, which is a real cost the paper reports only in output tokens. Run 30 already found that model-controlled skill invocation was worth +7.5 where the library alone was worth +2.0, so the write/read policy is where most of the value sits, not the store.

The efficiency side moves with it: skills grow 62→83 (GLM-5.1) and 50→81 (Kimi-K2.6) while mean output tokens per evaluated task fall 28.5K → 16.3K, and successful evaluations per million output tokens rise 110.3% and 134.0%. That is the rare case of the cheaper configuration also being the better one, which run 30 also recorded (101k agent tokens per success against 147k) and which inverts run 21's semantic-retrieval-costs-more result (semantic-retrieval-costs-more-tokens-than-grep-at-equal-success).

Discounts: each harness's gain is measured to its own best iteration, which are different iteration counts, so this compares three maxima rather than three endpoints — see the-self-improvement-headline-is-a-maximum-over-fourteen-sweeps. The comparison harnesses were not designed for an iterated-experience protocol and are being scored on it. Token efficiency is measured on the harness that also gained the most, so the two effects are not separated. One backbone for the three-way comparison.
