Who writes the harness outweighs what they write it in, by roughly eleven to one — second independent measurement

Run 12's HarnessOpt-Bench found the variable this vault had not been tracking: changing the optimiser model moved normalized gain 0.142 against 0.079 for the harness contrast — 1.8× (optimizer-model-outweighs-harness-when-an-llm-builds-the-harness). AI4AI measures the same thing on a different task family with a different design and finds it more lopsided. Opus-4.7 across four reasoning-effort tiers produced harnesses scoring 0.711 / 0.793 / 0.807 / 0.856 — a 0.145 span from one dial on one builder, monotonic, Spearman ρ=0.77. The platform the builder ran on (Cursor, Claude Code, GPT Codex) was worth +0.013 on matched comparisons, and native-platform advantage only appears at high effort at all.

So the ratio here is roughly 11:1 for builder effort over platform, before builder identity is varied across the eight models tested. Two independent studies, two task families, same ordering: the framework is close to free and the designer is the budget line.

A second allocation finding sits beside it and is new. Builders ran a median of 5 validation evaluations, and validation count correlates with final harness quality at r=0.17 — essentially uncorrelated. So the spend that matters is reasoning effort on the builder, not iterations of the search loop. That is the same shape as run 15's finding that iterated routing loses badly to a single decision (multi-turn-routing-adds-nothing-over-one-decision), and as the reflection results generally: more turns of a loop closing against the model buy little, while a better model per turn buys a lot.

Run 13 made reasoning effort the fifth entry on the pin-list after ARC Prize moved one open checkpoint 15.4 points across three effort settings (reasoning-effort-moves-one-model-15-points). This shows the same dial mattering one level up — not the effort the deployed model runs at, but the effort the model that designed the deployment ran at. Any automated harness-search budget we set has to name both.

The hole is unchanged and now conspicuous, because this is the second study in a row that could have closed it: every builder tested is a closed frontier model. Whether an open model can drive the design loop is unmeasured, and it is the difference between a workflow we can run on our own infrastructure and one that rents a frontier session per workflow.
