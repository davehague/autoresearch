The dependency this vault called unpriceable costs 28,811 synthesis tokens per verified environment

Run 19 named environment construction as the largest unpriced dependency in the build order, and made it the strongest structural argument for building that this vault holds: an environment is workflow-specific, non-transferable, and not purchasable from a model vendor at any price (rl-environments-and-infrastructure-are-what-does-not-distil). Three independent disclosures had named the object and none had costed it — Z.ai's account of a six-fold move was "more environments, more diverse tasks, and more compute" (post-training-alone-moved-an-open-model-six-fold-on-a-terminal-benchmark), and Qwen's card for a 27B tripling said nothing at all (post-training-alone-tripled-a-fixed-27b-on-a-coding-benchmark).

Envs-FORGE publishes the number, in a comparison table about something else. Four synthesis policies each export exactly 100 gold-verified terminal environments, and the budget to do it is 2.27M–2.88M tokens — 22,723 to 28,811 tokens per accepted environment. Envs-FORGE itself sits at the top of that range: 291 attempts to get 100 accepted, but the lowest tokens-per-attempt of any method at 9,901. It fails often and cheaply.

At any current frontier API rate the whole corpus is tens of dollars rather than thousands — our arithmetic, on a synthesizer model the abstract page does not name, so an order of magnitude and not a quote. That places it beside the only two other dollar figures this literature has produced: $8.95 for a full skill-generation phase (a-skill-library-for-a-compact-model-costs-nine-dollars-to-build) and ~$0.27 per completed poster for an optimized harness (a-designed-harness-lifts-five-open-weight-targets-11-to-20-points). Three independent measurements now agree about a class of work this vault has spent eight runs deferring as expensive, and they agree in the same direction: the front end of the build order is cheap.

What the number does not cover, and this matters more than the number does. It is synthesis only — not the RL run the environments feed, not the Docker infrastructure that executes them, not the gold-verification step that rejects half the output, and not the seed corpus the procedure starts from. The export size is fixed at 100 by construction, so nothing here says what a corpus large enough to move a production workflow costs; the paper's own stated next step is that scaling the seed pool is untested. Read it as an upper bound on the cheapest link, not a price for the dependency.

The action it unlocks is unchanged in shape and now cheaper than the procurement inquiry run 19 recommended: synthesize twenty environments against one of our own workflows and read the acceptance rate. Acceptance, not token count, is the number that transfers — 100 accepted from 203 attempts is a property of terminal tasks with executable verifiers, and our workflows may verify much worse.
