A tighter-confidence-interval update finds a quarter of real API endpoints still score below their own model's reference implementation, for reasons unrelated to model capability

Artificial Analysis's Endpoint Accuracy Index v1.1 triples AA-LCR-25's repeat count (10→25), narrowing the composite index's 95% confidence interval from ±5.5 to ±4.3 points, and expands coverage to six open-weight models. Of 103 endpoints now scored across three evals (BFCL-500 tool calling, HLE-250 scientific reasoning, AA-LCR-25 long-context recall) against a self-hosted reference, 24 score below reference with the interval now tight enough to call the shortfall real rather than noise. Named cases: a GLM-5.3 endpoint with a 16,384-token output cap scoring 7.6% on HLE-250 against a 63.6% reference; two GLM-5.3 Flash endpoints with ~32K output caps scoring 22.3%/28.5% against 55.4%; two gpt-oss-120b endpoints scoring 21.3%/22.3% on BFCL-500 against 37.1%; a Kimi K3 endpoint reusing tool-call IDs across turns, scoring 42.1% against 55.2%. DeepSeek V4.1 Flash 1017 is the clean exception — all 22 of its endpoints stayed in line (97.5-101.4). Causes cluster into output-token caps, reduced reasoning effort, tool-call formatting errors, and timeouts/truncation — not FP4 serving itself, which was generally not the culprit.

This sharpens a finding already cited elsewhere in this vault (as a 27-point endpoint swing) rather than introducing a new one, but it matters specifically for this theme's cost comparisons: any self-hosted-vs-API cost analysis that assumes a hosted endpoint delivers the reference model's accuracy is wrong roughly a quarter of the time, for reasons a token-price comparison alone never surfaces (output caps, timeouts, formatting bugs — not the model's own weights or quantization). DeepSeek V4.1 Flash 1017's 22/22 clean result is worth tracking against this vault's other entries naming that same checkpoint.
