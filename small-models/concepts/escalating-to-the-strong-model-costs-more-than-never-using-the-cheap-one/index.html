$1.61 for 69.2, or $0.72 for 79.2 — the cheap-first plan is a surcharge, not a discount

SWE-bench Verified, all 500 instances, Claude Haiku 4.5 escalating to Claude Opus 4.7 mid-run:

ConfigurationPass rateCost
Haiku 4.5 alone60.7$0.40
Opus 4.7 alone79.2$0.72
Haiku → Opus, full trajectory69.2$1.61

The escalation path costs 2.2× what never escalating costs and scores 10 points lower. On the GPT pair the quality story is the same: Luna 58.7, Sol 83.7, raw handoff 67.5 — 36% of the gap recovered. The authors name the penalty the handoff tax.

This retires a plan this vault has been leaning on without ever pricing. Every argument here that ended "run the open model and escalate when it struggles" assumed escalation was cheap and roughly recovered the frontier number. It recovers 36–47%, and it does so at a price above the frontier-only run, because the receiver pays full prompt processing on the sender's entire history — run 28's finding that prompt processing is ~70% of agentic wall clock (an-agentic-run-is-seventy-percent-prompt-processing) appearing as an invoice line rather than a latency complaint.

It also reframes run 13's cross-model escalation result, which routed 7% of calls and cut 74% of cost (cross-model-escalation-routes-7-percent-of-calls-and-cuts-74-percent-of-cost). That measured escalation between requests, where the cheap model's work is discarded on failure. This measures escalation within a trajectory, where it is carried. The two are different products and only the first one saves money.

Discounts: two model pairs, both same-family, both closed — no open-weight model is tested, and cross-family handoffs would add tokenizer and tool-schema mismatch on top; one benchmark carries the primary analysis; single episodes per task with the authors explicitly declining to estimate run-to-run variance; and the dollar figures are API list prices at a moment when run 22 showed those move 2–12× in a month in both directions (open-model-api-prices-are-not-a-stable-planning-input).
