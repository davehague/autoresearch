Machine learning for qubit calibration, control and code design

Status: emerging

Sub-threads: none — opened 2026-11-04 with 4 bullets; too early to split [reviewed 2026-11-04 @ 4 bullets]

Scope

Does machine learning (reinforcement learning, language-model agents, vision-language models) measurably improve how a quantum processor is tuned, controlled while running, or designed? Covers calibration and bring-up, control-parameter drift tracking during error correction, and automated discovery of error-correcting codes. Decoding has its own theme, neural-decoders-for-quantum-error-correction. The standard here is hardware data and independent baselines, not benchmark scores.

Through-line

  • 2026-11-06 — a third learned-search method for code discovery, and a first device-design surrogate. LiftDiff, a guided discrete-diffusion model, generates lifted-product codes beating the Gross code across a range of error rates, including a [247,19,14] code with the best kd²/n among its own baselines (peled-liftdiff-guided-discrete-diffusion-for-quantum-code-construction) — a third distinct learned-search approach after RL and GFlowNet, same simulation-only, single-group pattern. Separately, an FNO surrogate trained on a Thomas-Fermi simulator predicts quantum-dot charge-density fields at 0.6% error with a 17,000x GPU speed-up, and drives an inverse co-design loop to shape double-dot geometries (rychetsky-fno-based-inverse-co-design-of-semiconducting-quantum-dot-devices) — a new device-design facet, but against a simulator, not a fabricated chip. Held at emerging: all three code-discovery methods and this surrogate remain single-group and untested on hardware.
  • 2026-11-05 — a second learned-search approach to code discovery, still simulation-only. GFlowQEC, a generative flow network, finds more than twice as many new top-scoring 180-qubit lifted-product codes per paid evaluation call as tuned parallel tempering (batista-gflowqec-generative-flow-networks-that-learn-to-sample-quantum-ldpc-codes), echoing the RL-based code discovery already here. The lead reverses at larger search budgets, excludes training cost, and covers one code size with no decoder in the score — held at emerging.
  • 2026-11-04 — a stack-wide review frames this theme but adds no hardware evidence. The 28-author survey of AI for quantum computing lists device control, system characterization and code discovery among the places AI is already applied (alexeev-artificial-intelligence-for-quantum-computing), which matches the RL-control and calibration-agent results here. It surveys reported results without reproducing them, so the status stays emerging. Compilation and algorithm discovery have their own theme, ai-for-quantum-circuit-compilation-and-algorithm-discovery.
  • 2026-11-04 — opened at emerging. The best-evidenced item is Google's reinforcement-learning control of a running Willow surface code: 3.5x better logical stability against injected drift (2.4x from RL alone), and about 20% extra suppression over the standard calibration stack and expert tuning in fine-tuning experiments (google-reinforcement-learning-control-of-quantum-error-correction). It is real hardware but one lab, a 299-author preprint with unverified journal status, and a drift model that was largely injected. Scalability (speed independent of size to distance 15) is simulation only.
  • 2026-11-04 — language-model agents are at the characterization stage. An LLM-orchestrated system characterised 108 of 112 qubits in 4.7 hours, 4 to 5x faster than an estimated manual campaign, but its scope was mostly single-qubit characterization with no gate fidelities and shorter T2 Ramsey times than experts (xu-vibe-calibration-llm-agent-autonomous-bring-up-of-a-112-qubit-processor). NVIDIA's Ising Calibration 1.5 is a vendor benchmark score on an in-house test with no shown device run (nvidia-ising-calibration-1-5-and-qcaleval-automated-calibration). Held at emerging because the hardware demonstrations are single-group preprints and the vendor claim is unvalidated.
  • 2026-11-04 — code discovery by RL is still simulation. A noise-aware RL agent finds codes and encoders up to 20 qubits and distance 5; no RL-discovered code beating known ones or running on hardware was found (olle-rl-discovery-of-qec-codes-and-encoders-with-a-noise-aware-agent).

Open questions

  • Whether RL control gains hold against natural drift over hours or days, and appear in an independent lab.
  • Whether LLM-agent calibration reaches two-qubit gate calibration and reports fidelities, not just characterization.
  • A peer-reviewed version of the RL-control result (journal status unverified).
  • Independent validation of vendor calibration models on real devices.
  • Whether any of the three learned-search code-discovery methods (RL, GFlowNet or diffusion) finds a code that beats the best known construction, and whether the comparison still holds when training/search cost is counted in full.
  • Whether the FNO quantum-dot design surrogate transfers from its Thomas-Fermi training simulator to a fabricated and measured device.
