Evals that localize the fix

Status: contested

Sub-threads: localizing along the task · localizing across the system · which component the variance actually sits in · the metrics that arrive for free · the terms the two-factor frame has no slot for · the measuring instrument as one of the terms · which axis the variance is being read on · from a repair address to a measured repair [reviewed 2026-08-12 @ 34 bullets]

Scope

An eval that returns a number tells you whether something changed, not what to change. This theme collects the design choices that make a result point at a repair: staged scoring, fault attribution, and the audits that keep a passing score honest.

Through-line

  • 2026-08-07 — opened at emerging. Staged scoring recovers what binary grading discards: a run that found the bug but could not weaponize it and a run that found nothing both score zero, and in the regime these benchmarks operate in (13–18%) that is nearly every run (subtask-partial-credit-recovers-the-signal-binary-grading-throws-away-and-matters-most-when-every-model-scores-near-zero, patterns-for-building-cybersecurity-evals).

  • 2026-08-07 — the same survey supplies the counterweight: outcome-based grading is what makes these evals cheap, and transcript auditing is the tax that stops it certifying shortcuts as successes. The two are a matched set (outcome-based-grading-requires-transcript-auditing-as-its-counterweight-or-it-certifies-shortcuts-as-successes).

  • 2026-08-07 — a second, orthogonal axis: 41 failure modes each assigned to a component edge and a fault side, routing a repair to post-training, harness engineering, or environment redesign (assigning-each-failure-mode-to-a-component-edge-and-a-fault-side-turns-an-eval-score-into-a-repair-owner, model-or-harness-interaction-centric-taxonomy).

  • 2026-08-07 — the taxonomy above asserts the model/harness seam is real; a benchmark now measures it and finds the variance concentrates on the model side. Five frontier LLMs optimizing a target agent's harness across four tasks, 111 scored runs: the optimizer model separated results more than the coding harness it acted through, and native harnesses were not consistently better than a shared one (the-optimizer-model-separates-results-more-than-the-harness-it-acts-through, harnessopt-bench).

  • 2026-08-07 — and the same benchmark supplies its own limit: gains swung substantially by task and by seed-harness quality, so a harness win carries an implicit "on this task, from this baseline" and neither travels. The localizing has to be done locally — which is the least convenient answer to this vault's opening question, and the most likely to be true (harness-gains-do-not-transfer-across-tasks-or-seed-quality).

  • 2026-08-07 — moved emerging → contested. With the model backbone held fixed and only the agent harness varied across 410 analytics tasks, accuracy moved 15.36 points (harness-choice-moved-agent-accuracy-15-points-with-the-model-backbone-held-fixed, dataspace-verifiable-analytics-benchmark). That is the case the optimizer-role result above explicitly declined to cover, and it lands on the other side. See below.

  • 2026-08-07 — a second data point on the same side: one long-horizon harness ran across five backends from three model families without per-model tuning, so a harness looks like a portable asset rather than a per-model artifact (a-single-harness-carried-across-five-backends-from-three-model-families-without-per-model-tuning, onedayagent-long-horizon-harness). Weak on its own — a system paper's secondary claim with no per-backend numbers — but it points the same direction.

  • 2026-08-07 — the localizing methods themselves keep getting sharper. Inject the faults instead of waiting for them: seeded, replayable failure injection with recovery scored per mode produced a three-tier ordering — tool faults recovered fully, ambiguous delegation partially, latent and semantic modes not at all — stable across two task framings and three models (seeded-failure-injection-with-per-mode-recovery-rates-exposes-a-tiering-that-a-terminal-accuracy-score-cannot-see, orchestrabench-orchestration-failure-injection).

  • 2026-08-07 — and the same harness supplies the counterweight, in the pattern this vault keeps finding: blind retry reproduced latent faults and made detection later, while an ablation showed most apparent containment came from a trusted-state signal rather than from the system noticing anything. Recovery machinery built before attribution is negative-value (blind-retry-reproduces-latent-faults-and-delays-detection-so-recovery-machinery-is-negative-value-without-attribution).

  • 2026-08-07 — the cleanest localizing instrument yet, on a different system class: scoring what evidence a search agent retrieved separately from whether it used it splits a wrong answer into a retrieval gap or a utilization gap, which route to different teams (separating-retrieval-gaps-from-utilization-gaps-turns-a-wrong-answer-into-a-repair-address, diagnosing-search-behavior-in-long-horizon-search-agents).

  • 2026-08-07 — and a warning about the metrics that come free: search effort and context volume tracked answer quality only weakly, while cumulative evidence recall tracked it well. The informative metric is the one that needs human labels; the uninformative ones are the ones already on every dashboard (cumulative-retrieval-recall-tracks-answer-quality-better-than-search-effort-so-effort-metrics-mislead-as-progress-signals).

  • 2026-08-07 — the harness result gets its worst version. Eight LLMs, 177 executable tasks, nine domains, two harnesses: not only did scores move with the harness, the ordering of the models moved with it (both-scores-and-model-rankings-shift-with-the-agent-harness-so-a-leaderboard-built-under-one-harness-cannot-pick-a-model-for-yours, skill-use-skills-in-agentic-harnesses). A score shift is subtractable; a rank shift means a leaderboard built elsewhere cannot pick a model for your stack even directionally.

  • 2026-08-07 — and the same benchmark supplies another instance of this theme's central pattern, from a fourth direction. Splitting skill use into trigger, compliance, and boundary routes three failures to three different repairs — description writing, procedure format, permissions — and triggering and compliance fail as independent bottlenecks, so the aggregate is genuinely averaging unrelated deficits (splitting-skill-use-into-trigger-compliance-and-boundary-exposes-two-independent-bottlenecks-a-single-success-rate-merges). The construction move underneath is progressive disclosure — make the agent retrieve the procedure before following it, which turns a precondition into a measurable stage.

  • 2026-08-07 — a third position on the disputed question, from a design built to see it. Ten agent adapters over three base-model tiers in a 30-day tutoring relationship: quality belongs to the base model and the harness together, an interaction that a single-tier or single-adapter study would have credited entirely to one factor (a-factorial-of-model-tiers-against-agent-adapters-attributes-quality-to-model-and-harness-jointly-rather-than-to-either-alone, educlaw-bench-pedagogical-agents-simulated-learners).

  • 2026-08-07 — the cheap local version of the whole question, executed as a protocol. Fix the harness, the model, the decoding, and the datasets; swap exactly one component; read the difference off. Five memory strategies under those controls, and on the long-range dataset one reached Recall@5 0.573 while the other four reached at most 0.005 (swapping-one-component-under-a-fixed-harness-model-and-decoding-attributes-the-difference-to-that-component, agentmembench-memory-strategy-comparison). Greedy decoding is the underrated control — it removes the sampling variance that makes most agent comparisons unfalsifiable.

  • 2026-08-07 — and a shortcut closed before this theme walks into it. Everything above argues for scoring the trajectory, and the agent's own recorded plan is the most convenient trajectory artifact there is. It recovers only part of the true prerequisite structure, so grading against it grades the narration (an-agents-recorded-plan-recovers-only-part-of-the-true-prerequisite-structure-so-grading-against-the-plan-grades-the-narration, loopsbench-loop-engineering-benchmark). Same shape as the outcome-grading warning above: the self-reported artifact certifies itself.

  • 2026-08-07 — the staged-scoring argument loses the precondition it was carrying. Partial credit entered this theme on a floor-effect argument — at 13–18% strict success nearly every run is a zero, so binary grading discards nearly everything. A scientific-coding benchmark now shows strict pass and process reward diverging consistently at 48% strict success, in every one of six configurations (strict-pass-and-process-reward-diverge-in-every-configuration-so-partial-credit-is-a-second-question-rather-than-a-rescue-for-hard-benchmarks, mdarena-molecular-dynamics-coding-agents). There is no floor to rescue anything from, so the two gradings are answering different questions at any difficulty, and the size of the gap between them is itself a diagnostic — a wide gap routes to last-mile detail, a narrow one to getting started at all.

  • 2026-08-07 — a fourth task family joins the harness side of the contested question, and reports it the way the previous three did. 10,400 graph-analysis tasks, multiple harnesses, "harness choice significantly affects performance" — direction only, no magnitude (a-fourth-task-family-reports-harness-choice-significantly-affecting-performance-but-reports-no-magnitude, gabench-agentic-graph-analysis). Four teams have now built apparatus capable of a variance decomposition and none has run it, which is worth reading as a pattern rather than an oversight: the harness comparison is a robustness check in these papers, and robustness checks get reported qualitatively.

  • 2026-08-07 — and the same benchmark closes another cheap metric. Performance tracked tool-call quality, not tool-call count (tool-call-quality-rather-than-count-carried-performance-so-call-volume-joins-the-effort-metrics-that-do-not-track-outcome). That is the second task family to find it, after search agents. The list is now long enough to state as a rule: step counts, tool calls, tokens, context volume, and the agent's own recorded plan have all failed. Every metric that arrives without being asked for has failed.

  • 2026-08-07 — a third factor nobody in this argument is controlling. Same model, same harness, reasoning effort dialled from extra-high to medium: 24/50 → 21/50. A different harness and a different model family: 20/50 (reasoning-effort-moved-the-score-as-much-as-a-cross-family-harness-swap-so-the-model-versus-harness-frame-is-missing-a-third-factor). Three tasks out of fifty is inside binomial noise and this is a flag, not a result — but inference-time settings are neither model nor harness under the usual definitions, they default differently per vendor, and they are almost never reported. A "model" result could be an effort result wearing a model's name.

  • 2026-08-07 — and the deployment-frame restatement, from a weak source. Context engineering strongly changed reliability while capability improved behaviour without determining readiness (context-engineering-changed-reliability-more-than-capability-did-so-a-capability-score-does-not-predict-production-readiness, proofagent-index-capability-is-not-readiness). Single author, own index, own tool, no effect size — near-zero evidential weight, and it earns a bullet only for extending the unit: not the model-harness pair but the model-harness-context triple, of which the third part is what a team controls most and reports least.

  • 2026-08-08 — the fifth family arrives with the grid the theme has been asking for, runs it, and reports a sentence. All 20 combinations of four harnesses and five backends against 328 risk-injected cases: 6,560 runs, a complete factorial, and the finding is that observed safety "varies with both its harness-LLM pairing and how risk is introduced" (a-complete-four-harness-by-five-backend-grid-of-6560-runs-reports-safety-varying-with-the-pairing-and-still-does-not-apportion-the-variance, agents4d-lifecycle-runtime-safety-harness-grid). Unlike the previous four, this grid is not incidental to the paper's contribution — the cross product is one of its contributions, it cost 6,560 runs, and it still yields no apportionment. That changes the read from "these papers are not built for it" to "the decomposition is not what anyone is rewarded for reporting." See the status note below.

  • 2026-08-08 — and the same source adds a term the argument has no slot for: the risk carrier — which surface the adverse input arrives through — moved behaviour independently of both harness and backend. The construction move underneath is a cross product over adverse conditions rather than a list of them (6 entry sources × 6 induction strategies × 9 target harms), with 7 lifecycle checkpoints deciding in advance what evidence survives a run (the-same-harm-delivered-through-a-different-carrier-produces-different-behaviour-so-one-case-per-risk-conceals-the-weakness). The checkpoint schedule is the cheap version of the transcript-audit obligation above: naming what must be captured beats auditing whatever happened to be.

  • 2026-08-08 — a second new term, from a different direction, and this one is embarrassing because of how mundane it is. Seven environment parameters sit underneath every agentic-search number and go unreported: the corpus snapshot, preprocessing, chunking policy, retrieval backend, tool schema, observation format, and answer submission rule (seven-unreported-environment-parameters-sit-underneath-every-agentic-search-result-so-the-environment-is-a-fourth-term-beside-model-harness-and-inference-settings, simplewikisearch-specified-offline-search-environment). These are chosen in an afternoon by whoever wired up the retriever and never written down — the same failure class as unreported reasoning effort, and worse, because a harness at least has a name someone might mention. Asserted, not quantified; the paper builds the apparatus for measuring it and does not measure it.

  • 2026-08-08 — the theme gets its first split that clears a stage instead of finding a bottleneck, and it is the more useful kind. Scoring surface selection separately from answering across 1,151 enterprise tasks: Route F1 98.7–99.8 against Answer 56.1–75.3 (route-f1-near-99-against-answer-accuracy-near-60-shows-the-stage-a-split-retires-is-as-useful-as-the-one-it-finds, worksurface-bench-multi-surface-knowledge-routing). A team looking at 56% end-to-end would spend a sprint on source selection; this says do not, and no amount of staring at the aggregate could have said so. The design detail that makes the split credible rather than presentational: the two stages responded to different interventions — surface hints moved Answer, removing irrelevant tools moved routing and efficiency.

  • 2026-08-08 — and the cheap counterweight to outcome grading, which this theme has been paying for in transcript audits. Prespecify the constraint and score violations as their own rate: a reckless solve rate beside success, with no model exceeding 54% safe success (scoring-a-reckless-solve-rate-beside-success-catches-the-runs-an-outcome-only-grader-certifies, stealthbench-operational-stealth-in-offensive-security-agents). An audit catches what you did not think of; a named constraint rate catches what you did, at a fraction of the cost. Complements, and the constraint rate is the one a team can afford weekly.

  • 2026-08-09 — a sixth term, and the only one so far that anybody has actually modelled instead of noting. The judge is a variance source: a score from a panel is the agent's quality plus each judge's severity, and one benchmark now estimates the two as separate latents rather than pooling them (an-item-response-model-separating-agent-quality-from-judge-severity-is-a-fourth-panel-estimator-that-neither-votes-nor-averages, companionbench-judge-severity-separated-from-agent-quality). Every other candidate term in the restated question — reasoning effort, the risk carrier, seven environment parameters — was named by a paper and left unquantified. This one has an estimator attached, which is the difference between "there is another factor" and "here is how to take it out." What it does not have is a magnitude: nobody has published a leaderboard twice, pooled and severity-corrected, so the size of the judge's contribution is as unknown as everything else's. It also carries a scope limit the others do not — identifying severity needs many agents scored by the same judges, so it is available to whoever runs the leaderboard and not to the team reading it.

  • 2026-08-10 — the number this theme declared would never arrive, arriving two days later, half-formed. 328 persistent-risk cases across seven harnesses, and both margins of the grid reported in the same metric: backend fixed, harness swap moves the Chain-Stage Score 39.4 → 62.3, a spread of 22.9; harness fixed, backend swap runs 22.7 → 58.7, a spread of 36.0 (both-margins-of-a-harness-by-backend-grid-reported-in-one-metric-is-the-first-two-sided-number-in-this-vault-and-the-backend-margin-is-the-larger-one, harnesssafe-persistent-carriers-across-agent-harnesses). Two ranges are not a variance decomposition — no interaction term, no repeated runs, and a range is a property of the levels sampled — but this is the first source here to put a number on both sides at once, and the standing prediction from 2026-08-08 needs correcting rather than defending. The direction is the awkward part: five target-agent results came out on the harness side and this one comes out on the backend side, on an axis nobody else has scored. The reconciling hypothesis nobody has tested — the answer depends on which property you measure, model-dominated for containment, harness-dominated for task success. See the status note below.

  • 2026-08-10 — and the practitioner version of the same question, which is a different quantity and should not be added to the tally. Model held fixed at GPT-5.2-Codex, harness deliberately tuned against the benchmark: 52.8% → 66.5% on Terminal Bench 2.0, Top 30 to Top 5 (harness-only-changes-moved-a-fixed-model-13-7-points-on-a-public-coding-benchmark-which-is-an-upper-bound-on-tuning-rather-than-an-apportionment, langchain-harness-engineering-terminal-bench). Every benchmark result here swaps between scaffolds built for other purposes and reads off the difference; this hill-climbs one scaffold using the benchmark's own traces until the number stops moving, which estimates what a competent team can extract rather than what the harness owns. That is the number a team budgeting a quarter actually wants and it cannot be converted into an apportionment. It also carries the obvious hazard — optimizing against a public benchmark with its traces in the loop is fitting to the test set unless a held-out split was used, and none is mentioned. The four changes are copyable without the rest: forced verification before the agent may declare done, directory and constraint context injected at startup, per-file edit counting to break doom loops, reasoning effort concentrated at planning and verification instead of held at maximum.

  • 2026-08-10 — and one line in the same post is worth more than its score. The harness tuned to 66.5% under GPT-5.2-Codex scored differently under Claude Opus 4.6 and needed separate optimization (a-harness-tuned-to-one-model-scored-differently-under-another-so-harness-work-is-a-per-model-artifact-with-a-recurring-bill). That is harness-gains-do-not-transfer-across-tasks-or-seed-quality confirmed on a third axis — across models, not just across tasks and baselines — reported by a vendor whose interests run the other way. The distinction it forces, against a-single-harness-carried-across-five-backends-from-three-model-families-without-per-model-tuning: a harness ports; a harness's tuning does not. So harness engineering is a recurring cost that lands on every model upgrade, and a migration decision is not "is the new model better" but "is it better after I redo the tuning I already paid for."

  • 2026-08-10 — the instrument term finally gets a magnitude, and it dwarfs everything else in this vault. On CORE-Bench, one model scored 42%, then 95% after grading bugs were fixed (fixing-grading-bugs-moved-one-model-from-42-to-95-percent-so-the-measuring-instrument-can-own-more-of-a-score-than-anything-it-measures, anthropic-demystifying-evals-for-ai-agents). Fifty-three points, against 15.36 for a harness swap and 22.9 for the harness margin above. Unlike judge severity this cannot be modelled out — a grader defect is idiosyncratic rather than systematic, so it does not cancel across systems — and unlike every other term in the restated question it is free to fix and entirely inside the eval author's control. The failure mode is the nasty part: a 42% that should be 95% looks exactly like a hard benchmark, and nobody investigates a low score on a new benchmark. The obligation that follows costs an afternoon and appears in no construction skeleton here — score a known-good output before you trust any comparison.

  • 2026-08-10 — two more instruments, from opposite ends of the credibility range. The transcript-audit tax this theme has been charging since it opened gets paid by machine for the first time: traces out of the eval store, parallel error-analysis agents over them, failure classes out, which then became the change list (parallel-error-analysis-agents-over-stored-traces-is-the-first-report-of-the-transcript-audit-obligation-being-paid-by-machine). It emits classes rather than a number, which is why it does not join the graveyard of free metrics — and nobody validated it against human reading, so the prior from do-automated-evals-work should hold: it will find the mechanical classes and miss the ones needing domain taste, which is exactly the shape of the three it reported. Meanwhile, nine harnesses across 23 benchmarks show final-answer correctness spanning only 0.57–0.68 while planning, tool use and efficiency vary much more widely (final-answer-correctness-spans-eleven-points-across-nine-harnesses-while-planning-tool-use-and-efficiency-vary-much-more-so-the-headline-axis-is-where-the-harness-effect-hides, a2e-agent-auditing-engine). The outcome axis is a low-variance summary of a high-variance system, so a comparison run on it is underpowered for the difference it is looking for. If two harnesses tie on accuracy, that is not evidence the harness does not matter until you have looked at the trajectories — which are already in your traces.

  • 2026-08-12 — the first complete localize-then-repair loop in this vault, and the diagnostic splits on a variable the run produced itself. Across 2,846 state-confirmed violations, 17.92% happened after the agent had stated the relevant constraint in its own output; 5.48% after it explicitly acknowledged the prohibition (nearly-one-in-five-confirmed-violations-happen-after-the-agent-states-the-constraint-and-an-instruction-level-fix-then-removes-74-points, redagentbench-executable-red-teaming-faithful-measurement). Every localizing instrument this theme has collected — failure-mode-to-component-edge taxonomies, retrieval gaps separated from utilization gaps, per-mode recovery rates — classifies a failure using a scheme the analyst brought. This one partitions on did the agent say the rule before breaking it, which is a free signal sitting in transcripts everyone already stores, and it separates "did not know" from "knew and did it anyway" — two failures with different owners. Then it closes the loop: on that exact cohort a policy reminder took attack success from 88.25% to 14.06%, a neutral control moved nothing, and a self-reminder only reached 51.76%. The repair worked, which is the evidence that the address was right, and the 38-point self-versus-supplied gap says the fix belongs in the harness rather than in the agent's own prompting. Nothing else here gets past step one.

  • 2026-08-12 — a seventh term for the restated question, and the only one that changes the system under test rather than the measurement of it: whether you told the agent it was being evaluated. Disclosing an authorized evaluation in a mocked environment moved attack success −6.59 points on one model (95% CI [−7.89, −5.30]) and −4.77 on another, and +6.02 on one attack category under one harness (telling-the-agent-it-is-being-evaluated-moves-the-measured-rate-five-to-seven-points-and-not-always-downward). The sign instability is what makes it live: a reliably-suppressive bias could be reasoned around, and this one interacts with the harness and the case family, so no published number can be adjusted for it without the condition being stated. Every eval here makes this choice implicitly — a mock sandbox announces itself through fake data and unbranded services, and scrubbing the tells is deliberate work — and not one source states which way it went. Cheapest item on the list to fix, one line in a methods section, and the one that most directly undermines using an eval to predict production behaviour, because production does not announce itself.

  • 2026-08-12 — the harness-only delta gets a second independent reading and the headline is the spread, not the maximum. Same backbone (Qwen 3.7-Plus), same execution backend (Claude Code), only the loop harness changed: +7.5 on Terminal-Bench 2.1, +28.9 on WeaveBench, 3× on OSWorld 2.0 binary (a-second-harness-only-delta-on-a-fixed-model-and-backend-runs-from-7-5-to-28-9-points-depending-on-the-benchmark, longhorizon-harness-loop-engineering). After LangChain's 13.7 points it was tempting to read "harness work is worth ten to fifteen." Three benchmarks under one harness put it at a factor of four apart with model, backend and harness all fixed, which says plainly that the harness is worth X is not a property of the harness — it is a property of the harness and the task family together. That is harness-gains-do-not-transfer-across-tasks-or-seed-quality observed across a released artifact's own table rather than inside one study. Weakest evidence class in this vault: the authors' own README, their chosen baseline, no repeated runs. And the comparison it breaks is worth stating — if a bare agent and the same agent in a loop harness differ by up to 28.9 points, a leaderboard row is a measurement of a pair, and only one half of the pair is named.

  • 2026-08-12 — sixth family, same shape, no apportionment. REDAgentBench ran a full 6-model × 3-harness grid and reports a ~10-point harness spread on one model's row (OpenClaw 78.74, Codex 71.81, Hermes 81.74) without the model spread in matched units. The 08-10 hypothesis — that the answer is conditional on the axis measured — gains a consistent data point on a safety axis and no test.

What is contested

The question is where the variance in an agent's performance sits — in the model or in the harness — because that is what decides where a repair goes.

  • Model side: five frontier LLMs optimizing a target agent's harness across four tasks, 111 scored runs; the optimizer model separated results more than the coding harness it acted through, and native harnesses were not consistently better than a shared one (the-optimizer-model-separates-results-more-than-the-harness-it-acts-through, harnessopt-bench).

  • Harness side: six frontier multimodal backbones against five widely used harnesses on 410 deterministically graded tasks; with the backbone fixed, harness choice was worth 15.36 points (harness-choice-moved-agent-accuracy-15-points-with-the-model-backbone-held-fixed, dataspace-verifiable-analytics-benchmark).

  • Harness side, second measurement: eight LLMs on 177 tasks across nine domains under two harnesses; scores and model rankings both moved with the harness (both-scores-and-model-rankings-shift-with-the-agent-harness-so-a-leaderboard-built-under-one-harness-cannot-pick-a-model-for-yours, skill-use-skills-in-agentic-harnesses).

  • Harness side, third measurement, weakest: frontier LLMs over multiple harnesses on 10,400 graph-analysis tasks; harness choice "significantly affects performance," no magnitude reported (a-fourth-task-family-reports-harness-choice-significantly-affecting-performance-but-reports-no-magnitude, gabench-agentic-graph-analysis).

  • Neither side — an interaction: ten agent adapters over three base-model tiers on 30-day tutoring; quality attributed to model and harness jointly (a-factorial-of-model-tiers-against-agent-adapters-attributes-quality-to-model-and-harness-jointly-rather-than-to-either-alone, educlaw-bench-pedagogical-agents-simulated-learners).

  • Neither side — an interaction, second measurement: all 20 combinations of four harnesses and five backends, 6,560 runs, safety varying with the pairing (a-complete-four-harness-by-five-backend-grid-of-6560-runs-reports-safety-varying-with-the-pairing-and-still-does-not-apportion-the-variance, agents4d-lifecycle-runtime-safety-harness-grid). The largest grid here and still no apportionment.

  • Neither side — an uncontrolled third factor: reasoning effort alone moved a score about as far as swapping harness and model family together, on 50 tasks (reasoning-effort-moved-the-score-as-much-as-a-cross-family-harness-swap-so-the-model-versus-harness-frame-is-missing-a-third-factor, mdarena-molecular-dynamics-coding-agents). Inside noise; listed because it was the first thing here suggesting the two-factor frame is the wrong frame.

  • Backend side, and the only two-sided measurement here: 328 persistent-risk cases over seven harnesses; harness margin 22.9 Chain-Stage points with the backend fixed, backend margin 36.0 with the harness fixed (both-margins-of-a-harness-by-backend-grid-reported-in-one-metric-is-the-first-two-sided-number-in-this-vault-and-the-backend-margin-is-the-larger-one, harnesssafe-persistent-carriers-across-agent-harnesses). The first source to report both margins at once, and the first to land on the backend side for a target agent — on a containment axis rather than a task-success one, which may be the whole explanation.

  • Harness side, a practitioner upper bound rather than a swap: model fixed, harness tuned against the benchmark, 52.8% → 66.5% on Terminal Bench 2.0 (harness-only-changes-moved-a-fixed-model-13-7-points-on-a-public-coding-benchmark-which-is-an-upper-bound-on-tuning-rather-than-an-apportionment, langchain-harness-engineering-terminal-bench). Listed separately because it measures extractable gain, not owned variance, and because it is self-reported with no held-out split.

  • Neither side — a fourth and fifth factor: the risk carrier moved behaviour independently of harness and backend (the-same-harm-delivered-through-a-different-carrier-produces-different-behaviour-so-one-case-per-risk-conceals-the-weakness), and seven unreported environment parameters sit under every agentic-search result (seven-unreported-environment-parameters-sit-underneath-every-agentic-search-result-so-the-environment-is-a-fourth-term-beside-model-harness-and-inference-settings, simplewikisearch-specified-offline-search-environment). Both are properties of what the harness is pointed at rather than of the harness, and neither is quantified.

These are not a logical contradiction. The first measures a model in the optimizer role, editing a harness; the rest measure a harness carrying a target agent through its own task. Both can be true. What cannot survive is the general lean the first one gets summarized into — "upgrade the model, not the scaffold" — because the case that advice is applied to is the target-agent case, and that case has now been measured three times by three independent teams on three task families (tabular analytics, skill use across nine domains, tutoring), and not once did it come out that way.

Status note, 2026-08-07 — narrowed, still contested

The contest is materially narrower than it was this morning. It began as one study against one study; it is now one optimizer-role study against three target-agent-role studies that agree with each other across task families, which is the multi-family evidence this theme said it was waiting on.

It stays at contested anyway, and the reason is the bar this theme set for itself: a variance decomposition — model versus harness, target-agent role, on more than one task family. None of the three delivers one. DataSpace reports a spread in points, Skill-Use reports that rankings reorder, EduClaw-Bench reports a joint attribution — none apportions variance to model, to harness, and to their interaction as numbers. The EduClaw-Bench design would support exactly that analysis and the paper does not report it.

Three agreeing results are not the same object as the measurement asked for, and this vault walked back build-vs-adopt-eval-tooling this morning for accepting a weaker substitute. Same discipline applies here. What has changed is the practical read, which no longer needs the status to move: for a target agent doing its own task, treat the model-harness pair as the unit, because harness-gains-do-not-transfer-across-tasks-or-seed-quality and the rank-instability result together say no factor carries a result out of the cell it was measured in.

Status note, 2026-08-07 (evening) — the tally grew, the missing measurement did not arrive

Four target-agent studies now, not three: graph analysis joins tabular analytics, skill use, and tutoring. Still contested, and the reason has shifted from "not enough families" to something more specific and less likely to fix itself.

Four teams have now built grids capable of apportioning variance between model and harness. Zero have reported the apportionment. That is no longer plausibly coincidence — a harness sweep is a robustness check in these papers, not the result being sold, and a robustness check gets one qualitative sentence. Waiting for a benchmark paper to answer this incidentally is waiting for something with no incentive to happen. What would settle it is a study whose purpose is the decomposition, and nothing here is that study.

Two things also got harder tonight. GABench's contribution is the word "significantly," which adds a family to the tally and nothing to the measurement. And reasoning-effort-moved-the-score-as-much-as-a-cross-family-harness-swap-so-the-model-versus-harness-frame-is-missing-a-third-factor raises the possibility that the two-factor framing is wrong — that inference-time configuration, unreported almost everywhere, is a third term. The evidence for that is one noisy comparison on 50 tasks and should be held lightly. But it means the decomposition this theme is waiting for should be a three-way one, and asking for a two-way one may be asking for the wrong thing.

Status note, 2026-08-08 — the wait should be declared over, and the question restated

contested still, and for the first time the reason is not "the measurement has not arrived yet."

AgentS4D ran the grid. Four harnesses by five backends, complete, 328 cases per cell, 6,560 runs — the largest configuration sweep in this vault by roughly an order of magnitude, and unlike DataSpace's or GABench's or EduClaw-Bench's, the cross product is one of the paper's stated contributions rather than a robustness check attached to a different claim. It reports that safety "varies with both its harness-LLM pairing and how risk is introduced," and stops. Five teams, five grids, zero apportionments, and the fifth one was built for configuration comparison.

That retires the theme's standing hope. Since it opened, the plan has been to wait for a benchmark to answer this incidentally, and last night's note already flagged that as waiting for something with no incentive to happen. Tonight's evidence upgrades that from a suspicion to a conclusion: the apportionment is a statistical analysis nobody's reviewers ask for, and no volume of runs produces it as a side effect. This theme should stop treating the missing number as pending.

The question also has to be restated, because it acquired two more terms tonight and neither is model or harness. The risk carrier moved behaviour independently of both. Seven environment parameters — chunking policy, observation format, answer submission rule among them — sit under every agentic-search number unreported. Together with reasoning effort, that is a five-term problem being argued as a two-term one, and a clean two-way decomposition would now be answering a question nobody should be asking. The honest restatement: what fraction of an agent's performance variance is owned by things a team does not currently write down? On present evidence the answer is large, and none of the five candidate terms has an effect size against it.

What would settle it is unchanged in kind and larger in scope: a study whose purpose is the decomposition, reporting variance owned by model, harness, inference settings, and environment, with interactions, on one task family. The practical read does not need it. Treat the whole configuration as the unit, record every term of it, and expect nothing to transfer out of the cell you measured.

Status note, 2026-08-10 — held at contested, and the prediction made two days ago was wrong

On 2026-08-08 this theme concluded that the apportionment "will not arrive as a side effect of a benchmark paper" and that it should stop treating the missing number as pending. Two days later a benchmark paper reported both margins of a harness-by-backend grid in one metric, as a side effect. The conclusion was overstated and is corrected here rather than quietly dropped.

What was right in it survives: nobody has run the decomposition. Two ranges with the other factor pinned is not a variance component, there is no interaction term, no repeated runs, and both spreads are properties of which levels happened to be sampled. The bar this theme set — variance owned by model, by harness, by inference settings, by environment, with interactions — is unmet. What was wrong was the sociology, the claim that no benchmark author would ever report a two-sided comparison. One did, in a table, without making a fuss about it.

The finding underneath is more interesting than the correction. Five target-agent studies put the variance on the harness; this one puts it on the backend, by 36.0 to 22.9, and the difference between it and the others is not the task family but the property being scored. Everything prior measured task success. This measures whether a persisted risk got contained. Refusing a poisoned memory entry is a trained behaviour; retrieving the right file is a scaffold behaviour. If that reading holds, the model-or-harness question has been malformed in a second way nobody noticed: not only does it have too few terms, it has no single answer, because the answer is conditional on the axis. Every result in the list above is silently conditioned on measuring accuracy, and none of them says so.

That is now the theme's most testable open question and it needs no new apparatus: report both margins on a task-success axis from any existing grid, and see whether the ordering flips. Until somebody does, the practical read is unchanged and gets one addition — treat the whole configuration as the unit, record every term of it, expect nothing to transfer out of the cell you measured, and say which property you measured it on.

One more correction of emphasis, from a different direction. fixing-grading-bugs-moved-one-model-from-42-to-95-percent-so-the-measuring-instrument-can-own-more-of-a-score-than-anything-it-measures reports 53 points moving because the scoring code was wrong. That is larger than every model effect, harness effect and carrier effect in this vault combined, it is not exotic, and it is invisible by construction — a broken grader produces a low score, and a low score on a new benchmark is what everyone expects to see. Before any of the terms above can be apportioned, somebody has to establish that the instrument works, and not one source here reports doing so.

Why this is its own theme

It cuts across build-vs-adopt-eval-tooling rather than sitting inside it. Both a hand-built eval and an adopted platform can return an unactionable number, and the choices that fix that — milestone scoring, fault-side labels, trace audits — are grader and taxonomy design, independent of who wrote the runner.

The connective tissue with the vault's opening finding is that both point at the trace. Automated platforms miss failures that look fine in the transcript; outcome grading manufactures successes that look fine in the score. Both are corrected by someone reading how the run actually went.

Open questions

  • Does staged scoring generalize to tasks with no natural milestone ordering? Answered 2026-08-07, better than asked. The ordering does not have to be authored at all — it can be recovered from a project's own build history (a-dependency-dag-of-separately-testable-units-with-completed-nodes-held-as-regression-obligations-scores-a-long-run-continuously). What remains open is how complete that recovery is; the source reports it qualitatively.
  • How often does transcript auditing actually reject a scored success? No benchmark in the survey reports a rate. worksurface-bench-multi-surface-knowledge-routing reports a three-annotator audit rate on its corpus and is not an answer to this — auditing tasks before a run and auditing outcomes after one are different obligations, and this vault should not let the first stand in for the second.
  • Does a prespecified constraint rate substitute for transcript auditing, or only reduce it? The two catch different things by construction — one catches what you named, the other what you did not — and nobody has run both on the same runs and reported what only the audit found.
  • Does a split that clears a stage generalize as a reporting practice? Route F1 near ceiling is more informative than the Answer number it accompanies, and the literature is selected against publishing solved stages.
  • Does the trigger/comply/bound split transfer to other resources an agent must find before using — tool selection, retrieved context, documentation lookup?
  • Does the model/harness/environment fault split hold up when an independent team applies it to a different agent stack?
  • Does the model-or-harness answer depend on the property being scored? One grid puts the backend ahead on containment while five studies put the harness ahead on task success, and nobody has reported both margins on both axes from the same runs. This is answerable by re-analysing data that already exists.
  • Does the grader work? Nobody in this vault reports validating one, and one reported grading-bug fix was worth 53 points — larger than every other effect here. Scoring a known-good output is an afternoon and belongs in the construction skeleton.
  • Does an automated error-analysis pass over traces find what a human reading finds? Running both over the same trace set and reporting what only the human caught would answer this theme's oldest open question and the new one at the same time.
  • Has anyone decomposed configuration variance for a target agent as numbers — owned by model, by harness, by inference settings, by environment, and by their interactions? Five task families now agree qualitatively; nobody has apportioned it, including the team that ran 6,560 runs across a complete grid (agents4d-lifecycle-runtime-safety-harness-grid). This is the measurement the theme is blocked on, and as of 2026-08-08 it should be treated as something that will not arrive as a side effect of a benchmark paper.
  • Of the five candidate terms — model, harness, inference settings, risk carrier, environment configuration — which are actually recorded in published agent evaluations? A survey of what gets reported would be faster than a decomposition and would say how much of the literature is comparable at all.
  • Do the free metrics decouple from outcome outside search — on coding or computer-use agents, where a step acts on the world rather than looking something up? Answered 2026-08-07 for tool-call volume on graph analysis, where each call acts on an environment (tool-call-quality-rather-than-count-carried-performance-so-call-volume-joins-the-effort-metrics-that-do-not-track-outcome). Two families, two teams, same result. The follow-on: no free metric has now survived a test, so the question is no longer whether they decouple but whether any cheap signal exists.
  • Does an LLM judge reproduce the retrieval-versus-utilization split that human relevance labels produce? If so the best localizing instrument here becomes affordable. GABench scored tool-call quality somehow and does not say how; if it scored against the reference tool composition its generator used, that is the cheap instrument, and it would be the first one.
  • Does reasoning effort belong in the model/harness decomposition as a third factor, and how much of the published harness literature holds it fixed without reporting the value?
  • Now that decomposition has a companion question — how the components recombine into one number — where does splitting a score stop and what-the-headline-number-averages-away start? The two are the same analysis viewed from opposite ends, and a split undone by a mean downstream bought nothing.
