Evaluating over a horizon

Status: emerging

Sub-threads: the run can lose ground · the order of the run is a variable [reviewed 2026-08-07 @ 4 bullets]

Scope

Evals that score a sustained run rather than a point. The claim collected here is that a terminal number on a long-horizon task is an average over a trajectory with structure — order effects, regressions, decay — and that the structure is where the information is. Distinct from evals-that-localize-the-fix, which asks which component a failure belongs to; this asks when in the run it happened, and whether an earlier success is still a success.

Through-line

  • 2026-08-07 — opened at emerging. Structure each task as a dependency DAG over separately testable units, release tests along the ready frontier, and retain completed nodes as standing regression obligations. 112 tasks, 8 languages, 5,300+ units with executable tests, prerequisite edges recovered from real build history rather than authored (a-dependency-dag-of-separately-testable-units-with-completed-nodes-held-as-regression-obligations-scores-a-long-run-continuously, loopsbench-loop-engineering-benchmark). The finding that only this design can produce: regression events stayed visible across every loop implementation evaluated. Best configuration resolves 25.00%.
  • 2026-08-07 — the same mechanism from a different task family, and this is the reason the theme exists rather than living as a bullet elsewhere. For an agent with persistent memory, tasks are not independent and the order of accumulated experience moves the score, so one run sequence measures a path rather than an agent (the-order-of-accumulated-experience-changes-a-lifelong-agents-score-so-one-run-sequence-measures-a-path-rather-than-an-agent, path-bench-path-dependent-evaluation).
  • 2026-08-07 — and the decomposition that follows from it: report transfer and forgetting separately, because the agent that gains most from helpful history is not the one that keeps the gain (strong-forward-transfer-does-not-imply-retention-so-transfer-and-forgetting-need-separate-metrics). Two teams, two task families, one design principle — a long run needs previously-passed checks to stay live, or the scoring is monotone by construction and cannot represent damage.
  • 2026-08-07 — the third arrival extends the horizon from a run to a relationship, and pays for it. An agent tutor in a continuous 30-day relationship with a simulated learner across 55 scenarios, and almost no model-plus-adapter combination sustained good tutoring across the full 30 days (educlaw-bench-pedagogical-agents-simulated-learners, where-ground-truth-is-contested-the-construction-move-is-a-simulated-counterpart-fit-to-real-data-plus-a-cross-family-judge-panel-on-the-soft-axes). Whatever a single-session eval certifies, it is not durability.

Why this is its own theme

It does not fit the existing four. evals-that-localize-the-fix is about routing a failure to a component; the phenomena here — a passed test later broken, a gain later eroded, a history that helps or interferes — are about position in time, and they are invisible to any scoring that runs to completion and then grades. design-for-verifiability is adjacent and genuinely overlaps at the DAG bullet, since restructuring work into checkable units is that theme's move; what it does not cover is keeping those checks live afterwards. And this is not a cost question, though it is an expensive one.

Three sources arriving on the same day is a weak reason to coin a theme and is not the reason. The reason is that all three independently converge on a single design decision — previously-passed checks must stay live — reached from long-horizon coding, from lifelong memory, and from sustained tutoring, none of which cite each other's problem framing. A fourth source already in the vault sits squarely here too: verifying-and-repairing-the-deliverable-inside-the-harness-raises-the-floor-and-hides-the-variance-from-the-eval is a long-horizon harness absorbing failures before the eval can see them, which is the same seam viewed from the harness side.

Held at emerging and not higher. All three sources are first-of-kind benchmarks from single teams with no replication, and no one has reported what any of this machinery costs against what it catches.

Open questions

  • What fraction of long-horizon failures are regressions of earlier work rather than failures to progress? Every source here shows regressions exist; none reports the share.
  • Is path dependence larger than sampling variance? If re-running the same history twice moves the score as much as reordering it, the finding is real and not worth the second run.
  • How short can a horizon be and still show these effects? The three sources use 112-node DAGs, constructed history sequences, and 30 simulated days — all expensive. Nobody has looked for the cheapest run length that surfaces a regression.
  • Does this collapse into design-for-verifiability once someone builds an artifact designed for continuous re-checking, or does keeping checks live stay a separate discipline from making them possible?
