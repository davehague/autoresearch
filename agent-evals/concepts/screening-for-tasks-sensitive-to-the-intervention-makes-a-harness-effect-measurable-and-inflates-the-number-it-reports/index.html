Screening for tasks sensitive to the intervention makes a harness effect measurable and inflates the number it reports

Grounded in evo-bench-harness-evolving-capability; belongs to evals-that-localize-the-fix.

Evo-Bench names the problem directly — existing evaluations "fail to isolate harness improvements from base model strength" — and answers it with a construction step: "it leverages auxiliary-task evolution to identify tasks genuinely sensitive to framework improvements, followed by sensitivity-aware stratified splitting to ensure robust cross-suite generalization." Top models reach "massive absolute gains reaching 16.6 points."

A third way to isolate a harness effect, and the first that acts on the item set rather than on the design. This theme's isolation methods so far are controls: hold the model fixed and vary the harness, hold the harness fixed and vary the backend, run the full grid (a-complete-four-harness-by-five-backend-grid-of-6560-runs-reports-safety-varying-with-the-pairing-and-still-does-not-apportion-the-variance). Those all fight dilution by adding arms. This fights it by removing items — drop the tasks where the harness provably cannot matter, so the remaining signal is not averaged into invisibility by tasks that were going to score the same either way. It is the same statistical instinct as the discrimination-based item selection in discrimination-selected-items-beat-random-subsets-of-the-same-size-which-settles-half-of-the-comparison-between-the-two-cheap-subsetting-rules, pointed at an intervention instead of at a cost.

And it has a hazard the paper does not flag loudly enough: the screen inflates the effect it then reports. Tasks are kept because they responded to harness improvement in an auxiliary pass. Reporting 16.6 points from that set is reporting a conditional quantity — what harness evolution is worth on tasks pre-selected to be harness-sensitive — which is a legitimate measurement of the capability and a bad estimate of what harness work is worth on a workload you did not screen. Anyone carrying this number across to their own system will be disappointed, and the vault should quote it with the condition attached.

The two uses are worth keeping separate. For measuring whether a model can improve a harness, screening is correct and the alternative is a diluted null. For deciding whether to spend on harness engineering, the screen is exactly backwards, and the relevant question is the one harness-gains-track-recoverable-execution-defect-mass-so-where-there-is-no-defect-there-is-no-gain poses: how much recoverable defect mass does my workload carry.

Bounds. One benchmark, three domains, nine models, no per-domain magnitudes beyond the top figure, no repeated runs or intervals. "Closely approaching state-of-the-art human-engineered baselines" is a comparison whose baseline is not sized. The stratified split is aimed at cross-suite generalization within the screened population, which does not address the selection effect described above.
