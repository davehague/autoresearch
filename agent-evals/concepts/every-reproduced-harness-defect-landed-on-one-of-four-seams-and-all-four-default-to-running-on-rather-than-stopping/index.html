Every reproduced harness defect landed on one of four seams and all four default to running on rather than stopping, so the failure class this vault keeps diagnosing after the fact has named locations to check before it

Grounded in harness-architectural-convergence-three-coding-agents; belongs to evals-that-localize-the-fix.

Defects reproduced or located across two harnesses each fell on one of four recurring seams, with the loss column recorded:

S4 is the finding, and it is this vault's recurring disease stated as a design property rather than an incident. Four separate mechanisms, two languages, two codebases, and in every one the wrong path is the quiet one. That is the same shape as a-failing-sandbox-was-handing-its-error-to-the-agent-as-command-output-so-infrastructure-failures-entered-the-log-as-capability-failures, a-multibyte-read-boundary-silently-ended-tool-output-for-the-rest-of-a-session and batch-and-non-batch-prediction-paths-in-one-runner-scored-the-same-input-differently — but those were each diagnosed after someone noticed an anomaly. This is the first source here to give the class named locations you can go check before anything looks odd.

Three of the five specimens are marked irreversible, which changes what the seam list is for. A recoverable defect costs you a rerun. An irreversible one destroys the evidence: pi's destructive compaction permanently replaces the conversation history, so the trace you would use to diagnose the run is gone, and the run is scored anyway. An eval reading that log cannot tell it happened.

The rules are short enough to adopt tonight.

  • S2: one mandatory canonicalisation point per trust boundary; downstream accepts only the canonical form. Any check that compares an un-canonicalised value fails open when the two sides disagree about shape.
  • S3: errors carry a typed kind; regex is a last-resort fallback that must fail toward the safe side. The author's worked version: when unsure, "do not compact" — because compacting a non-overflow is unrecoverable and declining to compact a real overflow is not. That is a general rule for eval harnesses, where the asymmetric loss is almost always "destroyed the record" versus "wasted a run."
  • S1: where paired sync/async is hand-written, diff the guard clauses and test both halves against the same failure. Hand-written paired async is two copies of one intent the compiler never checks for agreement.
  • S4: make the unrecognised shape stop. deepagents' graph.py is cited as the counterexample that raises, so it is a choice within one codebase rather than a language constraint.

And it locates one seam inside a system this vault has already priced. deepagents' //secrets gap makes the human-approval interrupt fail open. Every judge-gate and human-in-the-loop cost estimate here has assumed the approval step runs when it is supposed to.

Single study, and the author is explicit that this is weaker evidence than the convergence claim: illustrative case reports rather than an independent test, four seams induced from a small analyst-directed sample, some language-specific (S1's drift cannot arise in pi's single-threaded model), and S4 a cross-cutting property rather than a fourth bin. Two of the specimens were re-derived in a sandbox and one was filed upstream as issue #5640; the rest were located by source reading. The taxonomy suggests rather than establishes that these fault lines track the problem shape — but every specimen is at a file:line re-checkable at a pinned commit, which is more than most defect claims in this vault carry.
