Injecting a fault as an overlay on the same execution structure, rather than as a separate mode, is what keeps the baseline and faulty arms positionally comparable

Grounded in llmmas-otel-tracing-and-fault-injection; belongs to evals-that-localize-the-fix.

The design rule is stated directly: "fault injection is not treated as a separate logging mode… but as an overlay on the same execution structure." A faulted run emits the same span tree, the same segment ordering and the same agent-step addressing as its baseline; the only difference is that the affected spans carry llmmas.fault.injected=true and llmmas.fault.type.

The alternative fails in a way that is easy to miss until the analysis. A separate fault-injection mode — a wrapper, a debug harness, a mocked provider — changes call ordering, adds or removes spans, or reshapes the phase boundaries. The two runs are then not misaligned by the fault; they are misaligned by the instrumentation, and there is no way afterwards to tell which. Every difference the analyst attributes to the injected fault includes an unknown contribution from the measurement apparatus, which is this vault's most persistent finding restated: the instrument becomes one of the terms.

It is the same precondition that arrived tonight from the scoring side, and the coincidence is instructive. scoring-only-the-items-every-arm-resolved-turned-a-three-point-loss-into-a-gain shows a comparison reversing because the two arms did not resolve the same items. Here the requirement is that the two arms occupy the same structural positions. Both are the general rule the vault has been circling since the interchange-format results: a paired comparison is undefined until both arms are represented identically — identically in items, identically in structure, identically in error handling. Three independent arrivals, three different layers, one rule.

And it upgrades the failure-injection method this vault already holds. seeded-failure-injection-with-per-mode-recovery-rates-exposes-a-tiering-that-a-terminal-accuracy-score-cannot-see scored recovery per injected mode and produced a three-tier ordering. That work compared outcomes across arms. Overlay injection makes it possible to compare trajectories — to see where the run diverged, not only that it did — which is the difference between knowing that latent faults are unrecoverable and knowing at which span the recovery attempt went wrong.

What it costs. Almost nothing at implementation time and a lot at retrofit time. Injection points here are three named boundaries — A2A messages, tool calls, LLM calls — each already a span. Adding two attributes to an existing span is trivial; rebuilding an injection harness that grew as a separate mode is not. Worth deciding before the second fault type gets added.

The tool's validation is a demo plus one system with no attribution-accuracy measurement, so the claim rests on the design argument rather than on demonstrated diagnostic value.
