ERPBench runs a human-approval-gated harness autonomously against a live ERP scored on database ground truth

Grounded in erpbench-enterprise-computer-use-agents; belongs to design-for-verifiability.

ERPBench scores screenshot-only computer-use agents against ground-truth values read directly from a live, reproducible ERP system's own database, rather than from a screenshot match or the agent's report of what it did. Alongside the benchmark, the same paper ships a production-grade harness that gates every agent action behind human approval before it executes — positioned for safe deployment, and run autonomously for the benchmark itself.

Why this extends the theme. This is checking-the-end-state-rather-than-the-path-is-the-verifiability-argument-arriving-from-the-eval-side-instead-of-the-product-side taken one layer further than most instances collected here: checking end state against a database rather than a screen is precisely what exposes erpbench-agents-saved-records-in-85-percent-of-runs-and-wrote-correct-values-in-3-percent — a screenshot-level end-state check would have missed the 85/3 gap entirely, because the screen after a bad save looks the same as the screen after a good one. The approval gate is the same architectural move as the long-horizon "Auditor" role in a-second-harness-only-delta-on-a-fixed-model-and-backend-runs-from-7-5-to-28-9-points-depending-on-the-benchmark, applied to a domain where the cost of an unreviewed wrong action is a corrupted persistent business record rather than a failed task.

What is new rather than repeated. Every ground-truth-from-execution source this theme already holds (DataSpace's tolerance rules, WorkSurface-Bench's per-surface oracle) grounds truth in something computable from the task's own domain — a query, a document span. ERPBench grounds truth in the state of a running production-shaped system that the agent is actively mutating, which makes the ground truth a moving target the harness has to snapshot and diff against, not a static reference authored in advance.

Why single-study. One system, one paper's own harness design; no comparison against an otherwise-identical benchmark without the approval gate to show what the gate itself buys versus the database-ground-truth scoring alone.

What would move this. A reported count of how often the approval gate blocked an action that would have produced one of the 3%-correct records — that would separate what the gate caught from what the ground-truth check merely revealed after the fact.
