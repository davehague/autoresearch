An eval vendor shipping its workflows as agent skills moves the adopt product from a library to a procedure

Grounded in promptfoo-0-121-14-to-0-122-0; belongs to build-vs-adopt-eval-tooling.

promptfoo 0.121.16 published all four of its skills to the Claude Code marketplace. That is the second instance in three months of eval expertise being distributed as agent skills rather than as code: the earlier one was a practitioner packaging six procedures — error analysis, synthetic data, judge-prompt authoring, judge validation, retrieval/generation separation, review-interface construction — with the explicit caveat that skills grounded in your stack and your data would outperform them.

The difference is who is doing it. The first was a consultant distributing a floor. This is a vendor distributing its own product's workflows, which is a different commercial act.

The adopt product is drifting from "a library you import" to "a procedure your agent runs," and the two have different properties.

The theme's boundary has been about layers; this is about form. The standing read here is that the generic layer knows procedures and not criteria — how to run error analysis but not what counts as an error. Skills are the natural packaging for exactly that generic-procedure layer, and the fact that both a practitioner and a vendor independently reached for it is evidence the layer is real and separable.

But it changes what adoption means. Adopting a library is a dependency decision with lock-in and an upgrade treadmill. Adopting a skill is closer to reading someone's runbook and keeping the parts you like — near-zero lock-in, and near-zero of the maintenance benefit that was the adopt column's main argument. A skill you have edited is a thing you now maintain, which puts it back on the build side of this theme's ledger. So the distribution shift does not move the boundary; it makes the two sides easier to mix, one procedure at a time, which is a better state than choosing wholesale.

The commercial read, stated plainly and speculatively. A vendor publishing its workflows as editable prose is either confident that the value is in the runner and the hosted pieces rather than the know-how, or is buying distribution in a channel where agents choose tools. Both are consistent with this theme's opening finding that the analytical content is commoditizing and what is sold is schema, integrations and operations.

Bounds. A changelog line — the contents of the four skills are not examined here, nobody has used them, and nothing is measured. Two instances is a pattern only in the weakest sense, and one of them is a marketing action that costs a vendor almost nothing. The comparison table above is reasoning about the form, not an observation about these skills. No evidence about whether skill-packaged eval procedures actually work as well as the library path.
