The residual between observed and predicted difficulty audits a whole corpus for broken items without reading any of them

Grounded in predicting-task-difficulty-without-rollouts; belongs to design-for-verifiability.

Residual analysis — observed IRT difficulty minus difficulty predicted from the task description — surfaced items whose two estimates disagree. A large positive residual on SWE-bench django-14725 traced to critical information missing from the task description: an item no correct solution could satisfy, which every model therefore fails.

It is the fourth way to check the instrument, and the only one that runs over the whole corpus at once. The three already here each read something: scoring a known-good output tests one output against the grader; the 25% holdout with precision, recall and kappa tests the judge against a person on labelled items; letting-the-agent-prove-the-specification-unsatisfiable-or-the-reference-wrong-is-grader-validation-that-runs-during-curation tests each item against an agent's argument that it is broken. This one reads nothing. Fit difficulty from outcomes you already have, predict it from the text, and rank items by disagreement. What comes out is a shortlist for human inspection over a corpus of any size.

The failure it catches is the one that is invisible by construction. An item with information missing from its description looks exactly like a hard item: every model fails it, the score is low, and a low score on a hard benchmark is what everyone expects to see. That is the same invisibility as the CORE-Bench grading bugs in fixing-grading-bugs-moved-one-model-from-42-to-95-percent-so-the-measuring-instrument-can-own-more-of-a-score-than-anything-it-measures — 53 points hiding behind a plausible number — and it is the reason this theme's standing instruction is to validate before comparing. The residual is a detector aimed precisely at it, and it aims from a direction the other three cannot: a specification no correct implementation satisfies is self-consistent and passes agreement checks, but it cannot be unusually hard for its description and stay unnoticed.

A team with its own eval set can run it today. The requirement is a response matrix over the team's own items — several model versions scored on the same suite, which any team iterating for a few months already has — plus a difficulty prediction from the item text. The prediction does not have to be good for the audit to work: a weak predictor (predicting-item-difficulty-from-the-description-alone-reaches-spearman-0-399-and-degrades-out-of-distribution) still ranks items by how surprising their difficulty is, and the audit only needs the extreme tail.

Bounds. Demonstrated on two named examples with no count of how many broken items it surfaced across 17 benchmarks — which is the number that would tell a reader whether to bother, and it is unreported. False positives are unbounded: a genuinely hard item with a short description looks the same as a broken one, so the residual produces candidates and a person still confirms. The negative-residual half of the analysis is a contamination argument and belongs to the separate epistemics vault; only the positive-residual, infeasible-item half is taken here.
