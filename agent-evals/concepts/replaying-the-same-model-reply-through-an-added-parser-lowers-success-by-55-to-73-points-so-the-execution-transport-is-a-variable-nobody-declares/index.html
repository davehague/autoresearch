Replaying the same model reply through an added parser lowers success by 55 to 73 points so the execution transport is a variable nobody declares

Grounded in quotebench-execution-transport-and-matched-scores; belongs to evals-that-localize-the-fix.

QuoteBench holds the model reply fixed and varies only the path it travels to the shell. "Across eight same-window configurations, replaying the same reply through the added parser lowers success by 55.4 to 73.2 percentage points." The control that isolates it: escaping at the interpolation point reproduces each replayed reply's raw-path outcome exactly, so the parser is provably the only difference and any score recovered under disclosure comes from the model generating differently, not from the transport being repaired.

This is a ninth unwritten variable, and it differs from the other eight in where it lives. Carrier, environment parameters, reasoning effort, judge severity, evaluation disclosure, network egress, instruction surface and trial count are all things a methods section omits — a setting someone chose and did not write down. The execution transport is code the harness author wrote without deciding they were making a choice: the layer that serializes, wraps, templates and reparses model output before it takes effect. Most harnesses have one. Almost none document it, and on this evidence it is worth more than everything else in the harness combined.

The magnitude has no peer in this vault. Harness effects catalogued here run 7.5 to 15.4 points; the largest single factors recorded are 53 points from fixing grading bugs and a 36.0-point backend margin. 55.4 to 73.2 points from one parser is larger than all of them, and it is measured on identical model output rather than across configurations that differ in many ways at once.

It generalises past Bash, which is what makes it a practice claim rather than a curiosity. Anything where model output is serialized, escaped, templated or reparsed before it takes effect has this boundary: tool-call arguments, SQL, structured-output schemas, file writes, and every MCP or RPC transport between an agent and the thing it acts on. The consequence for a team is not "audit your escaping" — it is that a benchmark score obtained through one transport does not predict behaviour through another, so a leaderboard result cannot be imported into a system whose plumbing differs.

Limits. 56 one-shot tasks, so this measures single-turn command generation and not an agent that sees the failure and retries — plausibly the harsher case, since a real loop gets feedback. The parser is described as "deliberately unescaped," a constructed fault rather than a survey of transports in the wild, so 55–73 points prices this fault and not the typical one. Single study, one model window, no repeated runs.
