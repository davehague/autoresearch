Anything a machine-readable spec already declares should be looked up, not inferred by a model

Grounded in who-belongs-in-the-eval-set-regression-curation; belongs to what-the-headline-number-averages-away and what-an-eval-costs-to-run.

The capability classifier is hybrid on purpose. Capabilities that the agent's specification declares — the example given is auth mode — are resolved by deterministic lookup from the spec. Capabilities that are only inferable from a query's intent — response formatting, branching logic — go to LLM self-consistency sampling, producing a per-capability verdict with a confidence score.

The rule is: never pay a model to infer something a file already states. It sounds obvious and it is routinely violated, because once an LLM is in the pipeline it is easier to hand it everything than to split the input. The split caps the inference bill at the genuinely ambiguous fraction, and — more importantly — it makes the deterministic part exactly right rather than probably right. A confidence score on a fact that is written down in a config file is a strictly worse artifact than reading the config file.

This is the same move as harvesting a check from something already written down, applied one level up. This vault has recorded that pattern for graders: a policy document, a schema, an API contract already encodes constraints, and turning them into assertions is cheaper and more reliable than asking a judge to notice violations. Here it applies to eval-set metadata rather than to graders — the classification of what an item tests, not the scoring of whether it passed. Both rest on the same observation: the expensive, unreliable instrument should only be pointed at the residue.

The practical procedure. Before writing the prompt, enumerate what you are asking the model for and cross off every field with an authoritative source — a manifest, a schema, a type signature, a route table, a permissions config. What remains is the actual inference problem, and it is usually a lot smaller than the original prompt. The two-way split also gives you a free consistency check: on fields where both a spec and an inference exist, disagreement locates either a stale spec or a miscalibrated classifier, and both are worth knowing.

Why this is filed under the aggregation theme rather than cost. The interesting part is not the money saved. It is that a hybrid classifier produces verdicts of two different epistemic kinds — one exact, one probabilistic with a confidence score — and the downstream consolidator consumes them side by side. This vault has already recorded that averaging signals of unequal reliability inflates confidence above the weakest input. A pipeline mixing looked-up facts with sampled inferences has that problem structurally, and this design at least keeps the confidence score attached rather than flattening both into one label. Whether the consolidator's rules actually treat them differently is not described, and that is the open question.

Bounds. One platform, no measurements — no cost saving quantified, no accuracy comparison between the deterministic and inferred paths, no report of how often they disagree where both are available. The self-consistency sampling budget is unstated. Which capabilities fall on which side is illustrated with two examples each and not enumerated.
