With the model backbone held fixed, swapping the agent harness moved accuracy by 15.36 points on a 410-task benchmark

Grounded in dataspace-verifiable-analytics-benchmark; belongs to evals-that-localize-the-fix and build-vs-adopt-eval-tooling.

Six frontier multimodal models were run against five widely used agent harnesses on 410 analytics tasks, graded deterministically. Best overall accuracy was 66.34%. Holding the backbone fixed and varying only the harness produced a 15.36-point spread.

Why this pushes back. the-optimizer-model-separates-results-more-than-the-harness-it-acts-through found that when an LLM improves an agent harness, the optimizer model drives more variance than the harness it works inside — and that note named its own open question: whether the same model-dominates-harness pattern holds for a target agent doing its actual task. This is a measurement of that case and it points the other way. Same model, five production harnesses, fifteen points.

The two are not a direct contradiction. One measures models in the optimizer role editing a harness; this measures harnesses carrying a target agent through its task. That distinction is real and both results can stand. What cannot stand is the general reading — "the model matters more than the scaffold, so upgrade the model" — because the case that reading gets applied to is the second one, and in the second one the scaffold was worth 15 points.

The decision it changes. It puts a number on the harness column of the build-versus-adopt ledger and it is not small. If harness choice is worth 15 points on a fixed backbone, then adopting one is a first-order accuracy decision rather than a convenience decision, and a harness comparison belongs in the evaluation rather than downstream of it.

Why single-study. One benchmark, one construction team, one task family, and five specific harnesses. It establishes that harness choice can be worth 15 points on a demanding multimodal analytics task; it does not establish a general magnitude, and a task with less tool orchestration in it would likely show less spread.

What would move this. A harness-versus-model variance decomposition on a second task family. Two measurements of the target-agent case, agreeing, would settle a question that currently has one result on each side.

2026-08-19 — the second measurement arrived and it disagrees. swapping-among-three-agent-frameworks-moved-the-score-by-1-79-points-so-harness-choice-is-a-small-capability-variable-on-rubric-graded-work ran the same experimental shape — target agent, harness varied — on 97 rubric-graded professional workflows across three frameworks, and got 1.79 points. An order of magnitude apart, and the "what would move this" condition above is now met in the negative. The caveat written into this atom on day one turns out to be the reconciliation: "a task with less tool orchestration in it would likely show less spread." DataSpace is 7,439 heterogeneous artifacts and a table to return; StartupBench is a long professional document graded on domain compliance. The 15.36-point figure stands as a measurement and falls as a general magnitude, and the number to quote alongside it is now the axis and the task family. Separately, the-same-model-was-4-3-times-less-safe-under-a-different-harness-so-a-safety-number-names-a-configuration-rather-than-a-model found a 4.3x harness spread on the safety axis using two of StartupBench's three frameworks — so the harness is a small capability variable and a large behavioural one, and this atom is about the axis where it matters least.
