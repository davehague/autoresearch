An RL-trained coding-agent verifier closed its 0% failure recall to 64% but stayed 21 points behind its own success recall

Grounded in swe-critix-training-a-coding-agent-trajectory-verifier-on-a-rule-based-unit-test-reward; belongs to the-judge-as-a-maintained-dependency.

SWE-Critix trains a 30B verifier to read a full coding-agent trajectory and predict whether the task succeeded, using SFT on teacher-written rationales followed by RL with a rule-based reward: +1 if the verdict matches the trajectory's own unit-test outcome, −1 otherwise — ground truth that costs nothing beyond the test the agent was already run against.

The untrained 30B model is not a weak judge, it is a non-judge: 0.00 negative recall paired with 0.85 positive recall is the "always say pass" strategy scored as if it were discrimination. SFT buys almost the entire failure-detection capability this model will ever have (0.00 → 0.62) but pays for it on the success side (0.85 → 0.67) — a trade this vault has not previously seen stated as a stage-by-stage number. RL recovers the success side in full without giving back the SFT-era gain on failures, but the two recalls do not converge: at the end of the pipeline the verifier is still 21 points worse at catching a real failure than at confirming a real success.

This is the same asymmetry this vault keeps finding in prompted judges, now reproduced inside a trained one. two-judge-backbones-produce-opposite-conservative-and-permissive-failure-profiles-so-a-mixed-panel-averages-to-a-rate-matching-neither and the loud-vs-quiet-failure literature both locate the hard half of judging at the same place — telling a plausible-looking failure from a real success — and training the judge with a free, rule-based reward signal instead of prompting one closes most, not all, of that gap. That the asymmetry survives a change in how the judge is built, from prompt engineering to RL on ground truth the environment already supplies, is evidence the gap is a property of the discrimination task itself rather than of any one construction method.

It also changes what "cheap ground truth" buys. Every other judge-training cost in this theme is priced in human-labelled items — roughly 900 rationale-annotated items for a production judge, ~300/week to monitor it, a practitioner's hundred labels plus weekly maintenance. This judge's training signal needed zero human labels, only trajectories the agent was already run against for an unrelated purpose (did the patch pass the test). That is a build-cost case this theme has not filed before: the labelling bill can be zero when the property being judged already has a deterministic check attached to it, and the open question is how often that condition actually holds — it holds for code because a unit test exists; it does not hold for most of what this vault's other judges are built to score.

Bounds. Single study, single domain (SWE-bench-style coding trajectories), and the paper reports no comparison against a prompted LLM judge or a scalar-reward critic on the same trajectories — so it is unknown whether 0.78 overall accuracy or 0.64 negative recall beats, matches, or loses to simply prompting a frontier model to read the same trajectory. Generalization across the three held-out subsets is also uneven: R2E-Gym reaches only 0.62 negative-recall-adjacent accuracy after RL against 0.78–0.82 for the other two subsets, which the authors attribute to under-representation in training rather than to anything about the subset itself — unconfirmed. No dollar cost or inference latency is reported, only training compute (15 NPU-hours for SFT against 533 for RL), which is not yet convertible into the per-item or per-week currency this theme's other cost figures use.
