An evolved harness cut estimated API cost per task by 17 to 53 percent while raising the score, so the harness lever moves cost and quality the same direction

Grounded in starharness-evolving-harnesses-stratified-search; belongs to what-an-eval-costs-to-run.

Alongside gains of 20.4 to 35.0 percentage points, StarHarness reports estimated API cost per task falling 17% on ITBench SRE, 53% on EnterpriseOps-Gym ITSM, 29% on AutomationBench Finance. Trace analysis attributes both to the same causes: interface repairs, environment conventions, and operational knowledge that compresses search, producing fewer false-positive diagnoses and shorter trajectories.

Nearly every cost result in this theme is a trade, and this one is not. Cutting items, cutting labels, cutting context, swapping to a cheaper judge — each buys money by spending some quantity of validity or coverage, and the theme's real content is the exchange rate. Harness quality is different in kind: a harness that stops the agent flailing produces both a better answer and a shorter trajectory, because the wasted tokens were the failure. The two numbers are not independent measurements, they are two readings of one improvement.

Which makes it the cheapest lever on this ledger by a wide margin, and it should be checked first. The theme already holds a practitioner ordering that puts retrieval and context first, the harness second, post-training last (a-practitioner-ordering-puts-retrieval-and-context-first-the-harness-second-and-post-training-last). That ordering was argued on effectiveness. This adds the budget argument: the second item on the list pays for itself. A team told to cut eval spend 30% reaches for fewer items or a smaller judge; the same 30% was available here from fixing tool interfaces, with the score going up.

Two caveats, both about the number's provenance. It is estimated API cost per task, not a bill — the paper does not say whether the estimate uses list pricing, whether cache-read and cache-creation tokens are counted separately, or how it treats subagent calls. This vault has now recorded three distinct ways a token figure can be quietly wrong: cache-write tokens billed inside the full-rate input line, delegation invisible to a root-only counter (aggregating-cost-across-root-and-descendant-sessions-is-what-makes-delegation-visible-in-a-budget), and provider billing diverging from model-facing context. An unqualified "estimated cost per task" does not tell you which of those it survived.

And it is the cost of running the agent, not the cost of the search that produced the harness. The evolution loop itself ran candidate harnesses repeatedly across an evolution pool of roughly half the reproducible tasks — a real bill, unreported here, and one that tonight's videoharness-rsi-context-construction-as-a-search-space does report at a much smaller scale.
