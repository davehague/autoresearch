DeepEval's merged fix for the empty-turn-extraction ambiguity rewrites the reported reason text so a reader can tell the two empties apart, but explicitly leaves the score at 1.0 for both — the perfect score still flows into the conversation average unchanged

Grounded in deepeval-3629-and-3634-turn-metric-empty-extraction-scores-1-0; belongs to what-the-headline-number-averages-away.

PR #3634's own description states the choice plainly: "Scores. Empty verdicts still score 1," with a configurable empty-score policy named as a possible future follow-up rather than something this fix does. What changed is diagnostic text — the three contextual metrics now report "The evaluation model returned no verdicts for the N retrieval context(s)... so [it] could not be evaluated" when context genuinely existed, instead of a message that reads as if there were none; faithfulness's reason now flags that extraction may have failed rather than asserting flatly that there was nothing to verify. The dead return 0 branch the issue reporter found is left in place, unreached, exactly as before.

This is a case where a headline number — the per-window score that gets averaged into a conversation-level metric — is deliberately preserved at its most favorable value across two materially different underlying states, by the people who maintain the metric, with the stated reason being a reluctance to change a default rather than an argument that 1.0 is correct for both. Anyone reading only the number, which is what feeds any aggregate, cannot recover the distinction the fix added; it is legible only to someone who reads the per-window reason string for every window, which is exactly the kind of per-item audit an aggregate exists to make unnecessary.

Bounds. Reflects the authors' stated intent in the PR description at the time of this ingest; whether a future release changes the default empty-score policy is unknown.
