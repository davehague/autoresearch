Harness-only changes moved a fixed model 13.7 points on a public coding benchmark, which is an upper bound on tuning rather than an apportionment

Grounded in langchain-harness-engineering-terminal-bench; belongs to evals-that-localize-the-fix.

Terminal Bench 2.0, model held fixed at GPT-5.2-Codex: 52.8% → 66.5%, Top 30 to Top 5. Four changes, reported as a bundle with no per-change attribution — a forced build-and-verify loop, startup injection of directory map and environment constraints, per-file loop detection, and a reasoning budget concentrated at planning and verification rather than held at maximum.

Why this extends, and why it is a different quantity from every other number here. Every benchmark result in this theme swaps between harnesses that were built for other reasons and reads off the difference. This is a harness optimized against the benchmark being reported, using that benchmark's own traces as the feedback signal, iterated until the number stopped moving. Those measure different things:

  • A swap between two off-the-shelf harnesses estimates how much the harness happens to matter across the scaffolds that exist.
  • Deliberate tuning estimates how much a competent team can extract by trying.

The second is larger by construction and it is the number a team actually wants when deciding where to spend a quarter. It is also not an apportionment, and it never can be — you cannot infer a variance component from a hill-climb.

The hazard, stated plainly. Optimizing against a public benchmark with that benchmark's traces in the loop is fitting to the test set unless a held-out split was used, and none is mentioned. Some unknown share of the 13.7 points is transfer to the benchmark rather than improvement of the agent. That is the same failure this vault flagged in an-agents-recorded-plan-recovers-only-part-of-the-true-prerequisite-structure-so-grading-against-the-plan-grades-the-narration — a signal used both to steer and to score — and it is exactly what harness-gains-do-not-transfer-across-tasks-or-seed-quality predicts will not travel.

The decision it changes. Harness work has a defensible budget now, for the first time from someone who ran it as an engineering project rather than a study: a team with trace tooling and a benchmark got double digits out of a fixed model. And the four changes are cheap and generic enough to copy without the rest — a forced verification pass before the agent may claim done, directory and constraint context injected at startup, a per-file edit counter that interrupts doom loops. None of those is domain-specific, which makes this the most directly actionable entry in the theme.

Why single-study. The weakest source class in this vault: a vendor reporting a favourable benchmark result about its own framework. Self-reported, self-optimized, no ablation, no repeated runs, no variance, no held-out split mentioned, no cost or calendar disclosed. What survives the discount is structural — the model was fixed, which is checkable against the leaderboard, and the direction is unambiguous. The magnitude should be read as generous.

What would move this. An ablation attributing points to the four changes, which would turn one bundled number into four transferable ones. Or the same optimization run against a held-out task set, which is what separates a better agent from a better-fitted one.
