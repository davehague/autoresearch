A runner put the reason a score is abnormal into the score schema, so grader failures separate from model failures with a groupby instead of a transcript read

Grounded in inspect-ai-changelog-score-reason-and-in-flight-scoring; belongs to evals-that-localize-the-fix.

The entry: a new machine-readable Score.reason field "records why a score has an abnormal value (e.g. invalid_response_format, grader_failed), is preserved across score edits, and appears as score_<name>_reason dataframe columns."

This vault has recorded, in one month, five distinct cases of a grader turning a valid model response into a zero — a trailing comma on a single-choice answer, a stray quote on a tool call, a four-option schema on a five-option benchmark, batch and non-batch paths scoring the same input differently, six assertion types scoring wrong in another runner. Every one was found because a person noticed something odd and went digging. The common structure is that an instrument failure and a model failure produce the same value, so no aggregate can distinguish them and no automated check exists.

Score.reason is the schema-level answer. It does not prevent the defect; it makes the defect's rate a computable quantity. "What fraction of my zeros came from the grader rather than the model" becomes a groupby over a dataframe column, per scorer, per run, comparable across runs. And because it survives score edits, a re-scored log keeps the record of why the original was abnormal.

Two limits worth stating. It is populated by the scorers that were updated — pattern(), answer(), perplexity(), target_perplexity() — so a custom scorer emits nothing unless its author sets it, and the coverage of the field is therefore unknown per suite. And a reason is an assertion by the same code that produced the score: a grader that mis-parses without noticing still reports no reason. It catches the failures the instrument can see itself, which is a strict subset, and this vault's evidence is that the worst ones were invisible to the instrument.

Still the most directly useful thing a runner has shipped for evals-that-localize-the-fix: a per-run number for how much of your failure mass is your own tooling.
