CHASE searches for validity-preserving protocol counterfactuals that destroy a harness's illegitimate gain

Grounded in chase-counterfactual-harness-search-and-evolution; belongs to design-for-verifiability and build-vs-adopt-eval-tooling.

Automatic harness evolution repeatedly edits a harness (prompts, memory, retrieval, tools, control code) against a fixed released benchmark. Task holdout varies the semantic tasks but leaves the benchmark's protocol fixed, so a "bad genius" Proposer can learn a benchmark-wide shortcut rather than a real improvement. CHASE adds a Challenger role: after each Proposer update, it searches for an executable protocol transformation that preserves task semantics (checked by a validity firewall) but destroys as much of the reported gain as possible. Transformations that pass both checks enter a finite archive the harness must keep working under. On OfficeQA, harnesses evolved this way retain strong gains on the released benchmark while losing much less of that gain when the protocol is validly perturbed.

Why this extends the theme. design-for-verifiability already holds letting-the-agent-prove-the-specification-unsatisfiable-or-the-reference-wrong-is-grader-validation-that-runs-during-curation — Vero's move of having the system under test attack the ground truth during curation. CHASE is the harness-evolution-search version of the same idea, but inverted: instead of the agent under test attacking the spec, a second search process attacks the harness's own reported gain, treating "does this gain survive a valid protocol edit" as the check. It is also the first source in build-vs-adopt-eval-tooling's dense harness-evolution sub-thread (DarwinX, ModularRSI, HarnessBandit, Ecdysis, and others) to build shortcut-detection into the evolution loop itself rather than reporting the evolved harness's benchmark score and stopping.

What it does not settle. No compute-matched baseline against harness evolution without the Challenger, so the cost of the extra search relative to what it buys is unpriced. No number for how much of a typical published harness-evolution gain this procedure would have caught — only that CHASE's own gains survive it better than an unstated alternative.

Why single-study. One method, evaluated on a synthetic benchmark and one real one (OfficeQA); no replication, no comparison against a compute-matched Proposer-only ablation.

What would move this. Running the Challenger against one of this vault's other harness-evolution sources' released artifacts (Beagle/DarwinX, HarnessDev) and reporting how much of their gain evaporates — that would price the shortcut problem across the sub-thread rather than inside one paper's own method.
