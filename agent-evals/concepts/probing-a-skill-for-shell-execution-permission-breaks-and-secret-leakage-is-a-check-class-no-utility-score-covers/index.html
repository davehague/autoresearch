Probing a skill for shell execution permission breaks and secret leakage is a check class no utility score covers

Grounded in skilltester-paired-utility-and-security-probes; belongs to design-for-verifiability.

SkillTester runs "a separate security probe suite" in three categories — abnormal behaviour control (unfiltered eval or shell execution), permission boundary (unauthorised file or network access), sensitive data protection (leakage of live API keys or sensitive context) — averaged unweighted into a score and mapped to Pass (100), Caution (80–99), Risky (<80).

These are properties of what the run did, not of whether it succeeded, and that makes them a genuinely separate axis rather than a competing metric. A skill can complete the task perfectly and shell out to something it should not have, read a file outside its boundary, or put an API key into a context that gets logged. No utility score expresses any of that, because utility is scored on the outcome and these are facts about the trajectory. They are also deterministic to check — a permission boundary violation is a matter of record — which puts them in the class this vault most trusts: cheap, reproducible, no grader to calibrate.

The night's other finding makes the case for keeping this as a third axis instead of merging it. Structural scanning and LLM review of the same skills correlate at Spearman 0.14 and neither predicts lift (structural-scanning-and-llm-review-of-the-same-skill-correlate-at-spearman-0-14-so-the-two-gates-are-not-substitutes). Adding an axis that predicts neither is not redundancy, it is coverage — skill admission is a multi-axis decision that most catalogues currently report as one label. The three-level Pass/Caution/Risky output reintroduces the single label at the last step, which is where the design gives back some of what it earned.

The cited audit is why this matters more than a checklist item. Of 3,984 public skills, 1,467 carried at least one flaw of any severity and 534 at least one critical issue — roughly 37% and 13%. At that base rate, "we scanned it" is a much weaker claim than a catalogue owner reading the word "scanned" would assume, and an unfiltered eval in an installed skill is a straightforwardly exploitable path rather than a code-quality nit.

The standing caveat on any probe suite applies and the label format obscures it. A probe suite finds what its probes cover, which makes the security score a lower bound on risk — and Pass (100) reads as an upper bound on it. This vault has repeatedly found sensible-looking deterministic gates that do not detect what they claim: a shipped similarity gate caught zero of fifty-six meaning-breaking edits (a-shipped-similarity-gate-caught-zero-of-fifty-six-meaning-breaking-edits-and-never-exceeded-0-700-balanced-accuracy-across-ninety-cells). Nothing here reports a detection rate against known-bad skills, so the probes' own sensitivity is unmeasured, and a Pass label carries whatever authority the reader grants it.
