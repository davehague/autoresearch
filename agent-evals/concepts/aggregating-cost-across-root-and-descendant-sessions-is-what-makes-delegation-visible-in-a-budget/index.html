Aggregating cost across root and descendant sessions is what makes delegation visible in a budget

Grounded in prime-agent-self-improving-rlm-harness; belongs to what-an-eval-costs-to-run.

"Accounting aggregates the root and descendant sessions, so delegation remains visible in test-time cost." The Factorio run is what that buys: 23.4 million output tokens across root and descendants, 633 depth-one subagents in 149 dispatch waves, seven concurrent at peak, over seven days. Without descendant aggregation the root session's own token count would have been the reported number, and it would have been wrong by whatever fraction 633 subagents consumed.

This is the accounting hole under every multi-agent result in this vault. per-run-token-and-cost-accounting-is-now-a-runner-default-with-judge-spend-separable-from-system-spend recorded a runner splitting judge spend from system spend, which is the same move on a different axis. Panels, juries and orchestrators all spawn work that a naive per-run counter does not see: a-jury-burning-7-6-times-the-tokens-billed-at-0-16-times-the-cost-because-of-the-rate-class is exactly a case where the token count and the bill diverge, and a cost figure that misses descendants diverges from both.

The second half is a unit result, and it is the more actionable one. On PMPP-Hard the comparison ran under a strict wall-clock budget, and the paper flags what that hid: "What the wall-clock budgets do not reveal is the substantial improvement in token usage by models that use Prime Agent. This means that the same performance as Codex or Kimi-Code is achieved by Prime Agent at substantially reduced cost, and, token-for-token, Prime Agent has an advantage." A comparison run under a fixed budget can only see differences in the axis the budget is denominated in. Equalise wall-clock and a token saving becomes invisible; equalise tokens and a latency saving becomes invisible. This theme has been arguing for cost-normalised comparison since a-6-8-point-quality-lead-at-2-2-times-the-cost-is-the-first-cost-normalized-comparison-in-this-vault; the refinement is that which cost you normalise on determines what the experiment can report at all.

The practical instruction. If you fix a budget to make two configurations comparable, record the other budgets too — wall-clock, tokens, dollars, calls — because the one you fixed is the only one your headline can no longer speak about.

Bounds. A design description plus one seven-day run; no per-subagent breakdown, no comparison of aggregated against root-only accounting, and no dollar figure. The PMPP token claim is asserted without a table.
