Final-answer correctness spans eleven points across nine harnesses while planning, tool use and efficiency vary much more, so the headline axis is where the harness effect hides

Grounded in a2e-agent-auditing-engine; belongs to what-the-headline-number-averages-away.

Nine agent harnesses — LangGraph, CrewAI, Google ADK, AutoGen AgentChat, Smolagents, Agno, LlamaIndex, Claude Agent SDK, OpenAI Agents SDK — across 23 benchmarks under a shared task protocol. Correctness spans 0.57 to 0.68. The paper's own summary of the same table: planning, tool use and efficiency "vary much more widely."

Why this extends. Every prior bullet in this theme is about combining components within an axis — items into a mean, groups into a minimum, judges into a panel score. This is a level up: the choice of which axis to report at all. An evaluation that prints final-answer correctness and nothing else sees an 11-point band where the underlying differences are larger, and it will conclude the harnesses are close together. They are not close together; they are close together on the one dimension that got printed.

That reframes the multidimensional-metrics argument, which is usually sold as diagnostic richness — more numbers, better repair addresses. The stronger version is evidential: the outcome axis is a low-variance summary of a high-variance system, so a comparison run on it needs more samples to detect a difference that a process axis would show immediately. Reporting only correctness is not just less informative, it is statistically underpowered for the comparison people run it to make.

The decision it changes. If you are comparing two harnesses and the accuracy difference looks like noise, do not conclude the harness does not matter — check whether the trajectories differ before you accept the null. Concretely: planning completeness, tool-use behaviour, and resource consumption are all computable from traces you already have.

Where it sits against the harness results. harness-choice-moved-agent-accuracy-15-points-with-the-model-backbone-held-fixed found 15.36 points of accuracy movement on a single task family, which is wider than this 11-point band across nine harnesses on 23 families. Not a contradiction — a spread over many benchmarks averages the family-specific effects down — but it does say the harness's effect on the outcome axis is task-dependent in a way its effect on the process axes may not be. Nobody has checked that.

Why single-study. One paper, and the per-cell numbers rest on five sampled tasks per harness–benchmark pair with no repeats reported. The band could move on resampling. The claim survives thin sampling better than a point estimate would — a qualitative comparison between the ranges of two axes is more robust than either range — but it has not been tested, and the "vary much more widely" characterization is the authors' rather than a reported statistic.

What would move this. A per-axis variance report on the same grid, or any second team publishing correctness alongside process metrics across more than two harnesses. Also worth having: whether the process axes rank the harnesses in the same order that correctness does, because if they do the cheap axis is a sufficient proxy and this whole argument is about efficiency rather than validity.
