Eleven substrates under one harness produced no dominant substrate so the adopt decision becomes a router you have to build

Grounded in harness-the-memory-substrate-evaluation; belongs to build-vs-adopt-eval-tooling.

Eleven memory substrates — flat indices, text records, structural and hierarchical stores, refinement memories, adapter tuning, full context, episode-clustered re-prefill — evaluated under one harness across three backbones and four suites on 26 metrics. "No single substrate consistently dominates." The winners change by regime: M5 Dual-Level Graph tops both QA suites (LoCoMo LLM-Judge 0.683, LongMemEval-S 0.667); M7 Distilled Strategies tops ALFWorld at 32.1%; M2 Sparse Vector tops BigCodeBench-Hard at 19.6% Pass@1 against M5's 16.2% "at roughly 1/6 the latency"; M8 Skill Bundles tops MAB Conflict Resolution at long inputs (0.51 at 262K).

This theme's adopt column has so far been full of things you pick once. A runner, a task corpus, a reference environment, an approval policy, a trace schema. The decision is a comparison, you make it, you live with the lock-in. A memory substrate looks like the same kind of object and is not: the right answer changes with task regime, retrieval depth and history length, all three of which vary inside a single deployed system. "A substrate optimal for short sessions can thus become a liability over a long-running agent's lifetime."

So the thing to adopt is a router, and nobody ships one. The paper says so directly: "The path forward is not a better single substrate but a multi-substrate or multi-agent memory system composed by role — refinement substrates curate abstractions, structural and text substrates hold facts, activation and flat substrates preserve raw experience — with the harness routing each query to the substrate whose representation aligns with the load-bearing region of its prompt." That is a proposal, not a result. A shopping decision has turned into a build item, which is the opposite of how this theme's items usually move and the first time an "adopt" candidate has dissolved on measurement rather than on price.

The measured routing signal is at least concrete. Three axes decide it: task regime (recall over a stored corpus versus concise procedural cues), retrieval depth (whether the answer lives in retrieved text or in the task context), and history length (refinement substrates scale gracefully; structural and full-context substrates hit deployment limits). All three are observable from a team's own traffic without running any of these benchmarks.

Note what the design of the study buys, separately from the finding. Eleven substrates under one harness with identical instrumentation is the controlled comparison this theme keeps saying does not exist — every other comparison here is across papers with different runners, prompts and budgets. The methodological point stands even where the specific rankings do not: if you want to choose between adoptable components, the comparison has to happen inside one harness, and someone has to build that harness.

Bounds. Single study; code "will be made available upon acceptance," so the comparison is currently unauditable. The evaluation "omits production-grade systems" — MemGPT, Mem0, Zep — because of "substantially different auxiliary-LLM budgets," which excludes precisely the systems a team would actually be deciding whether to adopt, and makes this a comparison of research reimplementations. "Implementation deviations from reference papers" mean a losing substrate may be a losing reimplementation. Three cells are excluded rather than measured (M7 trajectory-only, M9 incompatible with Gemma's MoE routing, M10 overflowing context on agent-centric tasks), so "no substrate dominates" is asserted over a ragged grid where some substrates never met some tasks. No routing system is built or evaluated, so the recommendation is untested.
