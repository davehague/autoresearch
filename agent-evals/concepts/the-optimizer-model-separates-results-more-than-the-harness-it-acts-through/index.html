When an LLM improves an agent harness, the choice of optimizer model drives more variance than the harness that optimizer works inside

Grounded in harnessopt-bench; belongs to evals-that-localize-the-fix.

Five frontier LLMs were given a target agent's seed harness, graded eval feedback, and a fixed evaluation budget, and asked to improve the harness. Each ran both inside a shared coding harness and inside its own native harness, across four downstream tasks — 111 scored runs. Candidates were scored by normalized gain over the seed on a held-out test partition kept inaccessible throughout the search.

Optimizer models separated more than the coding harnesses they acted through. A second result cuts the same direction: native harnesses were not consistently superior to the shared one.

Why this confirms. assigning-each-failure-mode-to-a-component-edge-and-a-fault-side-turns-an-eval-score-into-a-repair-owner argues the model/harness distinction is a real seam that repairs should be routed along. This is the empirical counterpart — when you vary model and harness independently and measure, the variance does concentrate on one side of that seam. The taxonomy paper asserts the seam is meaningful; this one measures it and finds it is, at least for the optimizer role.

The decision it changes. If the model doing the optimizing matters more than the scaffold it optimizes inside, then upgrading that model is the higher-return move — and the common instinct runs the other way, toward tuning the scaffold. The native-harness result cuts specifically against the assumption that a vendor's own harness is the right place to run its own model.

Why single-study. First-of-kind benchmark, no independent replication, and 111 runs spread across 5 models × 2 harness conditions × 4 tasks is thin per cell. The native-harness finding is the weakest of the set: it is a negative result over a small number of comparisons, which is where noise is most likely to be mistaken for signal. Read it as "no evidence native harnesses help," not "evidence they don't."

What would move this. Replication with more runs per cell, and an extension beyond the optimizer role — this measured models optimizing harnesses, and whether the same model-dominates-harness pattern holds for the target agent doing its actual task is a separate and more consequential question.

Rebutted in part, 2026-08-07. That separate question now has a measurement pointing the other way. On 410 analytics tasks with the model backbone held fixed, swapping between five widely used agent harnesses moved accuracy by 15.36 points (harness-choice-moved-agent-accuracy-15-points-with-the-model-backbone-held-fixed, dataspace-verifiable-analytics-benchmark). The two results are compatible as stated — one is about models in the optimizer role, the other about harnesses carrying a target agent through its task — so this note stands within its own scope. What does not stand is the generalization in "the decision it changes" above: upgrading the model rather than the scaffold is not supportable as general guidance while the ordinary case has been measured once and came out the other way.
