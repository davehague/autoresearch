The proposer cost $7.79 and candidate evaluation cost the rest, so automated harness search is priced by the development set rather than by the frontier model

Grounded in videoharness-rsi-context-construction-as-a-search-space; belongs to what-an-eval-costs-to-run.

The whole search: 15 candidates across five generations, three proposals per generation, from Claude Opus 4.6. Proposer API charges totalled about $7.79. Candidate evaluation — running each of those 15 harnesses end to end over a 350-question development set — took 2.28 hours of wall time and is where the actual spend sits.

This inverts the intuition that governs whether teams try this at all. "Have a frontier model design my harness" sounds like the expensive part, and it is under eight dollars for a complete five-generation search. The expensive part is that every candidate has to be run, and each run is a full evaluation pass. So the cost of automated harness search scales with development-set size times candidate count, and the model doing the proposing is a rounding error.

Which folds harness search into a problem this theme already has methods for. If the bill is the dev set, then every item-selection result here applies directly: sampling validation tasks by outcome variance cut a harness search from $117 to $30 and landed within one task of full-set search (sampling-validation-tasks-by-outcome-variance-cut-a-harness-search-from-117-to-30-dollars-and-landed-within-one-task-of-full-set-search). That was measured on a harness search, and this explains why it worked so well — it was cutting the only term that mattered. The corollary for a team is concrete: before starting a harness search, spend the effort on shrinking the dev set, not on choosing a cheaper proposer.

The tension with tonight's other harness-search result is worth flagging. StarHarness stratifies its evolution pool by baseline failure mode rather than by outcome variance, deliberately keeping tasks that fail reliably (stratifying-the-evolution-pool-by-baseline-failure-mode-makes-the-eval-set-a-function-of-where-the-system-already-fails). Variance sampling is the cheap answer; mode stratification is the coverage answer; nobody has priced them against each other on the same search. That is a small, well-defined experiment and it is unrun.

Scale honesty. $7.79 and 2.28 hours describe a search over one narrow space — context-construction programs at fixed capacity — with 15 candidates and a 350-question dev set on an 8B model. An enterprise agent search over four to twelve accepted changes on multi-step SRE tasks is not in this price range, and StarHarness does not report its search cost at all. What transfers is the ratio, not the figure: the proposer is cheap, the evaluation is not.
