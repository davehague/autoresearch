Logical tokens — uncached input plus cache-creation plus cache-read plus output — is a cost figure that survives a pricing change, and is not a bill

Grounded in pufibara-modelica-agent-workflow-benchmark; belongs to what-an-eval-costs-to-run.

The Modelica benchmark defines its cost metric explicitly: logical tokens sum uncached input, cache-creation input, cache-read input and output tokens across all LLM calls, and the paper says outright that this reflects total model-facing context rather than provider billing. On that metric Pufibara ran 76.4%–82.5% below Claude Code.

Naming the four components is the contribution, not the totalling. This vault has now collected three distinct ways a token figure goes quietly wrong, and all three are failures to enumerate: cache-write tokens billed inside the full-rate input line, so a cached suite's cost was computed wrong; delegation invisible to a counter that only watched the root session (aggregating-cost-across-root-and-descendant-sessions-is-what-makes-delegation-visible-in-a-budget); rate classes on the token line that a single number cannot represent. A cost figure is only checkable if the reader can see which buckets went into it. "Estimated API cost per task", which is what tonight's starharness-evolving-harnesses-stratified-search reports, is not checkable against any of those three failures.

But the metric answers a different question than a bill, and conflating them will mislead. Counting a cache-read token at full weight is deliberate — it measures how much context the model had to process — and it is exactly wrong for budgeting, where a cache read costs roughly a tenth of a fresh input token. Two harnesses with identical logical-token totals can differ severalfold in money if one of them caches a large stable prefix. The direction of the error is knowable: logical tokens penalise caching, so a caching-heavy harness looks worse on this metric than on the invoice. Which means Pufibara's 76–82% advantage is a lower bound on its context advantage and an unknown quantity in dollars.

The practical recommendation is to print both, and it costs nothing. Every provider returns the four counts per call. A results table that shows logical tokens and billed cost side by side lets a reader separate "this harness is more efficient at using the model" from "this harness is cheaper under current pricing" — two claims with different shelf lives, since the second expires the next time a provider changes its cache multiplier and the first does not.

Single study, one benchmark, and the metric is the authors' own definition rather than a standard. It is nonetheless the most precisely specified cost figure in this vault, which says more about the field than about the paper.
