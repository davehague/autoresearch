Tracing each error's resolution status and terminal impact separates an error from the cause of the failure

Grounded in trajdebug-error-lifecycle-critical-failure-attribution; belongs to evals-that-localize-the-fix.

"Failed trajectories often contain multiple local errors with different downstream effects, only some of which remain responsible for the final failure." TrajDebug "supports critical attribution by tracing each error's resolution status and terminal impact."

Every error taxonomy in this theme classifies errors by kind, and none asks whether the error survived. Component edge and fault side, retrieval versus utilization, per-mode recovery rates, the three process stages of Solution Framing / Execution / Feedback Control — all of them sort failures into categories the analyst brought. Two questions go unasked: did the agent subsequently fix this itself, and did it still matter at the end. On a long trajectory those are the whole problem. An agent that errs at step 12 and recovers at step 14 has produced a labelled error that is not a repair address, and a taxonomy that counts it inflates a category nobody should work on.

It is a free upgrade to any existing failure taxonomy. The two dimensions require no new instrument and no new labels: for each error already identified, ask whether the run recovered from it and whether the final outcome still depended on it. Applied to the failure profiles this vault already holds — the 41-mode taxonomy, the per-family DARC profiles, the machine-generated failure classes — it would separate the modes worth engineering against from the ones the system already absorbs. That distinction has never been drawn here, and it is the difference between a taxonomy of what goes wrong and a taxonomy of what costs you runs.

It also explains why the cheapest attribution heuristic fails. Earliest-error detection blames the first thing that looks wrong, which is right only if errors are never recovered from and never harmless. Both assumptions are violated, and the measured consequence is critical-errors-sit-mid-run-or-late-and-attribution-accuracy-collapses-past-61-steps.

Bounds. One paper, 486 annotated trajectories from two technical benchmarks, no reported inter-annotator agreement on the annotation of which error was responsible — a judgment plausibly harder to reproduce than a pass/fail label. Whether "the responsible error" is even well-defined when faults interact is left open. The instrument that implements the distinction reaches only 34.11% accuracy (the-best-automated-critical-error-attribution-reaches-34-percent-accuracy-so-a-machine-audit-is-triage-rather-than-measurement), so the concept transfers better than the tool.
