Inspect AI's ChatMessage text setter silently reordered content before media, so multimodal eval baselines could shift on rerun

Grounded in inspect-ai-changelog-unreleased-chatmessage-text-reordering-baseline-shift; belongs to design-for-verifiability.

Setting .text on a ChatMessage whose content was a list used to strip every existing text element and append the new one at the end of the list, regardless of where the original text sat relative to images or other media. prompt_template(), chain_of_thought(), and multiple_choice() all set .text, so a multimodal eval whose author wrote text before media had that order silently reversed for as long as the bug existed on main. The fix (PR #4773) replaces the first existing text element in place instead.

Why this confirms the theme. Every prior entry in this changelog's disclosed-defect series concerned something downstream of the model's action — a scorer, a cache key, an approval gate. This is the first to concern what the model was actually shown before it acted at all, and the changelog states the consequence outright: affected baselines "may shift on rerun." The theme's standing argument — that a harness's own internals can silently change what an eval measures — extends cleanly from post-hoc scoring to pre-hoc prompt construction.

What it does not settle. No affected-version range, and no estimate of how many published results actually used one of the three named solvers with text written before media in the source eval — the two conditions the bug requires to fire. Whether any specific published multimodal benchmark result predates this fix and should be treated as suspect is not addressed.

Why single-study. One maintained runner, one disclosed defect, no independent measurement of how much a given model's score actually moved.
