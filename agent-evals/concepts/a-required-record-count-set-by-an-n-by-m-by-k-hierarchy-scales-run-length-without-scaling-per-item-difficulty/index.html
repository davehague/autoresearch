A required record count set by an n-by-m-by-k hierarchy scales run length without scaling per-item difficulty

Grounded in wandr-refetching-judges-and-hierarchical-completeness; belongs to evaluating-over-a-horizon.

Tasks are specified as qualification key hierarchies: "a hierarchy with n companies, m employees per company, and k sources per employee requires n x m x k records," with targets "ranging from dozens to thousands of records." Reported result: "performance degrades as target volume and hierarchy depth increase."

Every long-horizon corpus in this vault confounds harder with longer. This one separates them by construction. A task that takes 300 steps in the corpora recorded here takes 300 steps because it is a difficult task; length and difficulty arrive together and cannot be varied independently, which is why this theme's oldest open question — how long does a horizon have to be before horizon effects appear — has been answered only by tertile-splitting an existing corpus after the fact. Here the required count is a stated parameter of the task. Ask for 60 records or 600 of the same kind, at the same per-record difficulty, and the run gets longer without getting harder item by item.

That makes it the first dial in this vault suitable for a controlled horizon experiment. The prior handle on this question grouped 82 tasks into tertiles by observed trace length and found a recovery intervention's advantage growing with the tertile — informative, but observational, with difficulty and length varying together. A knob that sets required volume directly allows the experiment the observational version approximates: hold the task family fixed, sweep the count, watch what degrades. WANDR does not run that sweep as a controlled study, but it reports the trend, and the corpus is constructed so someone could.

Two of the three named bottlenecks are horizon-shaped rather than capability-shaped. "Incomplete discovery, missing enrichment, and incomplete evidence construction" describe a run that stopped short at each level, not one that got things wrong. Combined with the multiplicative structure of hierarchical completeness, that suggests the degradation with depth is partly an accumulation failure — the agent does not lose the ability to verify a source at depth three, it runs out of run before it gets there. This is the same distinction longest-satisfied-prefix-rather-than-fraction-of-criteria-refuses-to-credit-out-of-order-progress draws between how far a run got and how well it did, arriving from the breadth axis instead of the sequence axis.

Bounds. Single preprint. The trend is reported, not isolated: target volume and hierarchy depth move together across the task set, and the systems evaluated were commercial products with their own internal effort budgets, so "degrades with volume" may partly be those budgets binding rather than the agents failing.
