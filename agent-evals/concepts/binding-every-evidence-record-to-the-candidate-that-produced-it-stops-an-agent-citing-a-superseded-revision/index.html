Binding every evidence record to the candidate revision that produced it stops an agent citing a superseded revision's simulation as support for the current one

Grounded in pufibara-modelica-agent-workflow-benchmark; belongs to evaluating-over-a-horizon.

Pufibara records each simulation result as an evidence record carrying invariant identifier, candidate identity, scenario, observables inspected, resulting trajectories, and the agent's adjudication. When the model changes, prior evidence stays in the history as auditable record but stops counting toward the new candidate's readiness — the agent has to collect candidate-specific evidence again.

The failure being prevented is specific, and it is a horizon failure rather than a reasoning failure. Early in a long run the agent simulates candidate A and sees the response settle correctly. It then revises to candidate B for an unrelated reason. Nothing in a flat transcript marks the earlier trajectory as stale, so the agent — reading its own context — concludes the current model is validated. The reasoning is locally sound; the premise expired. This is the same class as the vault's "history as a hazard rather than a resource" thread, made mechanical: the record is not deleted, it is scoped.

The design point is that staleness must be represented, not remembered. Every alternative relies on the agent noticing — a summariser that mentions the revision, a system prompt that says to re-verify, a context window short enough that the old trajectory falls out. None of those survive a long run, and the last one fails in the other direction. Attaching candidate identity to the evidence makes the invalidation automatic and makes it inspectable afterwards, which is what turns it from a prompt into a harness property.

It generalises past Modelica cleanly, and the vault should say where. Any eval where the agent iterates on an artifact and gathers evidence about it has this shape: test output bound to a commit, benchmark numbers bound to a config hash, a retrieval result bound to an index version, a scan result bound to a build. In each case the cheap implementation is a single identity field on the evidence and a rule that evidence from a different identity cannot discharge a readiness claim. The vault has recorded an agent rewriting a task's invariants into a coherent solution to a different problem, and an agent diagnosing a critical problem in 82.5% of trajectories and then reporting the unrevised conclusion. Evidence binding does not fix either, but it removes the version of them that is caused by the scaffolding rather than by the model.

Unmeasured. No ablation isolates its contribution to Pufibara's 202-versus-185 result, and no counter reports how often stale evidence was actually rejected — the number that would tell a reader whether this is a real hazard or a tidy invariant. That counter is a single increment in the code that already exists.
