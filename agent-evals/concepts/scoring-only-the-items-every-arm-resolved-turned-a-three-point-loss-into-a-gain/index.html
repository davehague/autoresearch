Scoring only the items every arm resolved turned a 3-point loss into a 0.66-point gain, so unpaired scoring systematically penalises the more expensive method

Grounded in recursive-agentic-reasoning-paired-scoring; belongs to design-for-verifiability.

On one model-benchmark cell (Qwen3.6-plus × HLE), BRANCH scored 11.20% against a 14.20% single-pass baseline — a 3-point regression. The BRANCH run had lost 172 items to timeouts against the baseline's 131. Recomputed over the intersection of items every operator resolved, BRANCH was +0.66. The published conclusion for that cell flips on a scoring choice, and the artefact is about 3.6 points.

Paired scoring, operationally, is one line: intersect the resolved-item sets before computing accuracy. Score all arms on "precisely the set of items that all operators resolved." Items lost to infrastructure — timeouts, empty returns, pipeline errors — leave every arm, rather than counting as wrong in whichever arm happened to hit them.

The bias has a direction, which is what makes it dangerous rather than noisy. A method that spends more compute per item times out more often. Unpaired scoring converts that into lower accuracy. So the penalty falls hardest on exactly the interventions a test-time-compute study exists to evaluate, and every such comparison in the literature that did not pair is biased against its own treatment arm. This is not a random-error problem an interval would catch; a confidence interval around a systematically depressed estimate is a precise wrong answer.

It is the same defect this vault has now seen from four directions, and the first time it has been shown to reverse a sign. A failing sandbox handed its error to the agent as ordinary command output (a-failing-sandbox-was-handing-its-error-to-the-agent-as-command-output-so-infrastructure-failures-entered-the-log-as-capability-failures). A runner's batch path trimmed schema-constrained outputs so the same input scored 1 and 0 (batch-and-non-batch-prediction-paths-in-one-runner-scored-the-same-input-differently). A multibyte read boundary silently ended tool output and the agent was graded as not knowing what to do. In each case infrastructure failure entered the record as capability failure. Those were all diagnosed after someone noticed something odd. Paired scoring is the first control that neutralises the whole class without needing to notice, because it never lets an unresolved item score.

And it composes with, rather than replaces, the fix upstream. The same paper's shared primitive already retries finalisation for budget-exhausted outputs, and 172 items still timed out. So the order is: fix what you can in the harness, then pair, then report how many items each arm lost — because the count of dropped items is itself a comparison between arms, and pairing hides it from the accuracy number on purpose. A team adopting this should print both.

Single study, one cell demonstrated in detail, and the paper runs no significance tests. The mechanism is arithmetic rather than empirical, though — the demonstration is an existence proof, not an estimate.
