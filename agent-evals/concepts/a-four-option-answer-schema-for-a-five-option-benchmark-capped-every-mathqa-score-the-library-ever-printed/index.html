A four-option answer schema for a five-option benchmark capped every MathQA score the library ever printed

Grounded in deepeval-4-2-0-benchmark-scoring-defects; belongs to build-vs-adopt-eval-tooling.

MathQA/AQuA-RAT questions "always have five options a–e" and option e is frequently "none of these." The schema constraining the answer declared answer: Literal["a", "b", "c", "d"], and the confinement instruction for non-schema models likewise said "Output 'a', 'b', 'c', or 'd'." The consequence, in the contributor's words: "A schema-constrained (native) model can therefore never emit e, and ... every MathQA item whose gold answer is e (~1/5 of the dataset) is scored 0, even for a perfect model."

This is not noise, drift, or a judge disagreeing. It is an arithmetic ceiling. A published accuracy from this path was capped roughly twenty points below 100% for every model, identically. Which is the worst version for a reader: rankings were probably preserved, so the leaderboard looked sane, while levels were wrong by a fixed offset nobody could see. A team using the number to decide whether a model is good enough to ship was reading a systematically deflated figure; a team using it to pick between two models was fine. Nothing in the output distinguishes the two situations.

Third runner, same fortnight, same defect class. five-scoring-path-defects-in-ten-days-all-sit-in-the-string-handling-between-model-text-and-a-structured-value came from Inspect AI. a-mature-oss-assertion-library-shipped-five-silent-wrong-score-defects-in-one-release-window came from promptfoo. This is DeepEval, and the two siblings in the same release are the same seam: DROP packed answer spans with a comma delimiter, so ["1,000"] round-trips to ['1', '000'] and a perfect "1,000" scores 0 — "every number ≥ 1,000 written with a thousands separator, spans like \"New York, New York\", can never be matched." Every eval runner this vault tracks by changelog has now disclosed silent wrong-scoring defects, and every one sits between free model text and a comparable value.

What that does to the adopt column. The vault's standing read has been that the maintained runner discloses what a hand-rolled one would not, and that this is the adopt side's most durable argument. It survives, with a sharper edge: three for three means the base rate of scoring defects in eval infrastructure is not low, it is unobserved everywhere it is not disclosed. A hand-rolled scorer written by one team, read by nobody, and never audited is the condition all three of these libraries were in until somebody read the code.

All three were found by reading, not by running. "While auditing the benchmark answer-scoring paths, I found three silent bugs." No test failed, no user complained, no metric moved. The regression tests that now cover them were written after the fact and "fail on the current code" — meaning the defects were invisible to the suite the project already had.

Bounds. One PR body plus one release note. No statement of how long the defects shipped, no list of affected published results, no maintainer postmortem, and the severity labels are the contributor's own.
