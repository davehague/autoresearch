A 21-point harness gain cost 2.1 times the prompt tokens and 3.5 times the wall clock, and the comparison was budget-matched on the context window only

The mechanism explains the ratio and does not excuse it. The control stops when the conversation stops fitting; the treatment compresses and keeps going. So the treatment's extra spend is definitionally the spend the control declined to make, and the "harness comparison" is partly a comparison between running longer and not.

That makes the two arms matched on exactly one budget — the per-call context window — and unmatched on turns, tokens and time. Under a token cap rather than a window cap the result is not predictable from this table: the treatment resolved 1.67× the tasks for 2.13× the prompt tokens, so per token it is less efficient than the control, and a study run at a fixed token budget could plausibly reverse the sign.

Which is the recurring finding in what-an-eval-costs-to-run arriving on the harness axis: the choice of budget unit determines what a comparison can see. Window-capped and token-capped versions of this same experiment are different experiments, and only one of them was run.

The wall-clock number deserves separate note. 1.3 to 4.6 hours for the same 169 tasks is a 3.5× change in how long a nightly eval takes, on a suite small enough to run nightly. That is a real adoption cost that no accuracy table shows.
