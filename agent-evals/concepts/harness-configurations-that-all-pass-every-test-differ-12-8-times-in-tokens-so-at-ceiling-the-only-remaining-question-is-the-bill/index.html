Harness configurations that all pass every test differ 12.8 times in tokens so at ceiling the only remaining question is the bill

Grounded in working-set-of-a-coding-agent-coherence-debt; belongs to what-an-eval-costs-to-run.

"Harnesses pay unequal prices for it: configurations that all pass every test differ more than tenfold in tokens consumed because they rebuild the same content at different rates." Precisely: tokens consumed over a run differ by 12.8x while the amount held in front of the model at any moment differs by only 1.8x, and "the expensive configurations recover nothing extra when facts are withheld."

Every harness figure in this vault is a score delta; this one holds the score fixed and reads the other axis. 15 points (harness-choice-moved-agent-accuracy-15-points-with-the-model-backbone-held-fixed), 13.7, 12.4, 11, 7.5 — all of them answer "how much better did it get". This answers "what did the same result cost", and the answer is an order of magnitude. At ceiling there is no quality question left to ask, so the comparison collapses onto price, and price turns out to be where the configurations actually differ.

The 12.8x against 1.8x split identifies what is being paid for. Context held at any moment barely varies; total tokens vary enormously. So the spread is not window size, it is refetch rate — configurations rebuilding the same content over and over. That is a diagnosable, fixable property of a harness rather than a design trade, and it is invisible to any comparison that reports only outcome and peak context.

It sharpens the cost theme's normalisation rule into its limit case. a-6-8-point-quality-lead-at-2-2-times-the-cost-is-the-first-cost-normalized-comparison-in-this-vault introduced quality-per-dollar as the axis. Here the quality lead is exactly zero and the cost ratio is 12.8, which is the configuration a quality-only comparison declares a tie and a cost-normalised one declares a rout. Any harness comparison run on tasks where everything saturates is measuring nothing unless it reports spend.

"Spending more recovers nothing when facts are withheld" is the other half, and it is the useful half for eval design. The expensive configurations are not buying insurance against the hard case; when the required facts are genuinely absent, the extra tokens return nothing. So token spend is not a proxy for thoroughness, and a harness that reads more is not a harness that is more likely to succeed — which is the same conclusion cumulative-retrieval-recall-tracks-answer-quality-better-than-search-effort-so-effort-metrics-mislead-as-progress-signals reached about effort metrics, arriving from the cost side rather than the diagnostic side.

Bounds. One paper, one set of workloads, five harnesses, seven models — the 12.8x is the observed spread among the configurations tested here, not a general figure, and the paper reports it at fixed outcome on tasks these configurations all saturate. No dollar conversion and no wall-clock. It says nothing about which configuration is right when the task is not saturated, where the expensive ones might well be buying the score. And "tokens consumed" pools input and output, which price differently.
