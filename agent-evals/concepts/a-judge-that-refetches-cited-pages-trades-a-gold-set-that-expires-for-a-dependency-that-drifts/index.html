A judge that refetches cited pages trades a gold set that expires for a dependency that drifts

Grounded in wandr-refetching-judges-and-hierarchical-completeness; belongs to the-judge-as-a-maintained-dependency.

WANDR "replaces static gold answer sets with task-specific judges that refetch cited pages and verify each record against its evidence, allowing evaluation of current and changing facts."

Every other verified corpus in this vault buys crispness by freezing something. A repository state, a hidden ground truth, a hand-specified reference, an executable test. That is the right trade when the answer does not move, and it has a known expiry when it does — the vault already holds the claim that evaluation scores are perishable. This construction refuses the trade: there is no answer set to go stale because the check is performed against the live page at grading time, and the record the agent returned has to survive contact with what that page says now.

What it buys instead is a grader with an external runtime dependency, which is why this note is filed under judge operations rather than judge design. A refetching judge fails in every way a network call fails: pages edited, moved, paywalled, rate-limited, geo-fenced, or simply slow. Each of those reads as an unverifiable record, and an unverifiable record reads as the agent being wrong. Two evaluations of the same system a month apart can therefore disagree for reasons entirely outside both the system and the judge, and no line in the score says so. This is a maintenance liability in the same family as the weekly-label drift band recorded here, with one difference that makes it harder: a-judge-drift-alarm-set-at-two-standard-deviations-of-human-disagreement-has-never-fired-in-production monitors a judge whose inputs are stable and whose behaviour might move; here the behaviour is stable and the inputs move.

The missing number is the one this design most needs and the paper does not report: re-run stability. Grade the same set of returned records twice, a week apart, and publish how many verdicts flip. Without it, a reader cannot tell whether the 0.363 soft F1 has a re-grade noise floor of one point or ten — and this vault has spent a fortnight arguing that a delta without its noise floor is not a result. A companion figure would help nearly as much: the fraction of records that failed verification because the fetch failed rather than because the claim was wrong. That single split separates a measurement problem from a capability one.

It also inherits the endpoint condition arriving here on the same day. A record whose verification happens after the run, against a resource that can change between the run and the check, is by construction an outcome that was not settled when scoring began — see outcome-finality-and-cross-unit-separation-are-independent-conditions-that-an-endpoint-does-not-establish. The refetching judge is the clearest live example of the condition the endpoint paper describes in the abstract.
