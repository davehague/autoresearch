A full-completion indicator at 99.9 of 100 is what turns a rubric into a contract, and the 0.1 of slack exists because a stochastic judge sits inside the grader

Grounded in frontierchallenge-scientific-workflow-completion; belongs to design-for-verifiability.

Each of 97 scientific-workflow tasks carries a task-specific Grader checking required files, numerical results, formats, figures, code execution and cross-artifact consistency, returning a native score in [0, 100]. Where a rubric criterion is semantic it is delegated to a Judge (GPT-5.6 Sol), run three times per criterion, with the Judge remaining part of that task's Grader rather than a separate downstream stage. The full-completion indicator is then f = 1[s ≥ 99.9].

Two design decisions here are worth more than the benchmark they came in.

First: the Judge is inside the Grader. Most eval architectures in this vault run deterministic checks and then, separately, an LLM judge, and report them as two things. Folding the Judge into the task's own Grader means there is exactly one score per task and exactly one pass criterion, and it makes the semantic criteria subject to the same contract as the file checks. That is what allows the strict threshold to exist at all — you cannot threshold a bundle whose semantic and deterministic parts are reported separately.

Second: the 0.1 of slack is an honest disclosure of where the noise lives. The threshold is 99.9 rather than 100 "only [to absorb] minor numerical variation introduced when the three Judge scores are averaged; it does not relax any rubric requirement." Read that backwards: a fully compliant submission can score 99.94, because a stochastic instrument is inside the measurement. The tolerance is not a softening of the standard, it is the size of the judge's jitter, stated in the units of the metric. This vault has been asking every judge-using system for a noise figure. This one publishes it as a threshold offset, which is a more useful form than an interval, because it is directly actionable: it is the number below which you must not set your pass bar.

Three judge passes per criterion is the cheapest version of a control this vault keeps recommending. Not a panel of different judges, not a moderator, not a stopping rule — the same judge three times, averaged. It buys the variance reduction that makes a strict threshold survivable, and its cost is exactly 3×. Against three-samples-of-one-model-gained-13-points-so-most-of-the-panel-effect-is-sampling-not-diversity, which found most of a panel's gain was resampling rather than vendor diversity, this is the design that result implies: if resampling is where the gain is, resample and skip the panel.

And the whole construction is what "design for verifiability" looks like as a shipped artifact rather than an aspiration. Each task is a self-contained package of five aligned elements — task description, fixed inputs, declared execution environment, an output contract listing required deliverables, and an executable evaluation procedure — with agent-visible instructions and inputs kept separate from evaluator-side references and scoring components. Tasks with purely subjective outputs, or lacking materials for reproducible scoring, were excluded before the pool was formed. The theme's founding claim is that you restructure the artifact so it can be checked at all; this is a 300-task corpus built on that premise, and the separation of agent-visible from evaluator-side material is the concrete mechanism that makes rerunning it under fixed conditions possible.

The limit is the same one the theme has been stuck on. This does not compare a contract-structured task against its un-structured self, so it does not measure what the restructuring bought. It demonstrates that the structure is buildable at scale and that it produces a metric which disagrees sharply with the mean (an-average-rubric-score-of-87-9-and-a-pass-rate-of-20-6-percent-came-from-the-same-graders) — an existence proof and a divergence, not an effect size.

Single study. The Judge is one model, so its jitter is characterised but its bias is not — three passes of a systematically wrong judge average to a systematically wrong score, and no human agreement rate for the Judge is reported anywhere. The 99.9 threshold makes the metric maximally sensitive to that: a criterion the Judge misreads costs a task its pass outright.
