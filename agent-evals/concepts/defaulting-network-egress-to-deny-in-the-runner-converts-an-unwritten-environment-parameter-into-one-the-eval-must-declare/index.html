Defaulting network egress to deny in the runner converts an unwritten environment parameter into one the eval must declare

Grounded in inspect-ai-changelog-0-3-255; belongs to build-vs-adopt-eval-tooling.

Inspect AI 0.3.255: an agent under evaluation can no longer reach the web through provider web search, code execution or remote MCP unless the eval grants it, and can no longer make the runner fetch a URL or read a host file by embedding it in image or document content.

Why this extends. seven-unreported-environment-parameters-sit-underneath-every-agentic-search-result-so-the-environment-is-a-fourth-term-beside-model-harness-and-inference-settings named a class of variable that moves scores and never gets written down — chunking policy, observation format, answer submission rule. Network reachability belongs to that class and is worse than the examples, because the others are at least chosen. Egress is whatever the runner happened to permit, which means it varies with the machine, the network, and the provider's feature set, and no one has ever put it in a methods section.

The mechanism is the transferable part, and it is the cheapest thing this theme has recorded: flip the default to deny, and the parameter has to appear in the config. Every other proposal here for making hidden variables visible is a reporting norm, which requires everyone to cooperate. This requires nobody to cooperate — an eval that needs the web now says so in a file, and one that does not is silently reproducible. Any harness could apply the same move to any implicit capability.

The comparability consequence is bigger than the security one. An agent with live web access is being scored partly on what the web contained that day. Two runs a month apart are not the same measurement; the same eval inside a corporate network and on a CI box are not the same measurement. This vault has read thirty-plus sources and not one states whether its agents had egress during the run. On this evidence some of them did, and there is no way to tell which.

The decision it changes. For anyone running an agent eval: find out whether your agent can reach the network mid-run, and write the answer down either way. If the eval needs the web, pin what it reaches. This is a question with an answer that takes minutes to get and it is currently unanswered across the entire literature here.

Why single-study. A vendor changelog — strong evidence about what shipped, no evidence that it works, that anyone uses it, or that egress changes any published number. And this is the third Inspect release ingested in five days, so it should count for less rather than more: what these establish together is one fact about where the bar for a hand-rolled harness sits, not three independent arrivals.

What would move this. Anybody running the same eval with and without egress and reporting the difference. That is a one-line config change and a rerun, and it would convert a plausible confound into a measured one.
