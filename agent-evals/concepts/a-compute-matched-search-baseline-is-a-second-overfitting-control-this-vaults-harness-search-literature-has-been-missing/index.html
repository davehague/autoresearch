A compute-matched search baseline is a second overfitting control this vault's harness-search literature has been missing

Grounded in rethinking-harness-evolution-matched-budget-baselines; belongs to design-for-verifiability.

The paper's stated case for its own protocol: harness evolution is itself an iterative search procedure consuming feedback and inference budget, so a fair evaluation has to compare it against simple task-level search baselines — parallel sampling, sequential refinement — under matched feedback and inference budgets, in addition to checking on held-out tasks.

splitting-the-task-pool-into-proposer-visible-search-and-proposer-hidden-selection-is-the-overfitting-control-a-searched-harness-needs named the first control this literature was missing: a harness produced by search is a fitted object and needs a validation split. This names a second, orthogonal one — even with a clean held-out split, a reported gain says nothing about whether evolving a harness specifically was the active ingredient, as opposed to spending the same budget on any iterative search at all. A held-out split answers "did this generalize"; a matched-budget baseline answers "was this worth doing compared to the cheaper thing." A result can pass the first check and fail the second, which is exactly what this paper's own held-out numbers show once set beside its search-baseline numbers.

The admissibility rule this adds to the theme's running list: a harness-search result is not fully readable from a held-out score alone — it needs a same-budget non-harness-search baseline run on the same tasks. Nothing in this vault's other harness-evolution sources reports one, so the same open question now applies to StarHarness, HarnessLens and VideoHarness's numbers: would parallel sampling at the same rollout budget have matched them.

Single study, one benchmark, one budget point (K=5); the paper does not test whether the missing-baseline gap it found on Terminal-Bench general coding holds at the larger search budgets or more plumbing-heavy task families the other harness-search sources here used.
