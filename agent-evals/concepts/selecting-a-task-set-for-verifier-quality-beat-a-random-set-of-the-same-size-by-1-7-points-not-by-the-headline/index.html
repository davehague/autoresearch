Selecting a task set for verifier quality beat a random set of the same size by 1.7 points, not by the headline

Grounded in river-verifier-quality-over-environment-quantity; belongs to what-an-eval-costs-to-run.

The abstract's claim is that fewer than 30% of a 14,399-environment pool, filtered for verifier quality, "improves RL gains by 106% and 30% on average" on two benchmarks. The controlled version — same 3,500 environments, selected by rubric versus sampled at random from the same pool — is much smaller:

+1.7 average points, and on one of four benchmarks random sampling is ahead. The large percentages compare against the unfiltered pool, which is a different and much easier baseline.

Why this belongs in the cost theme with a caution attached. This theme's item-selection sub-thread is built on results where a principled subset beat a random subset of matched size — discrimination-selected-items-beat-random-subsets-of-the-same-size-which-settles-half-of-the-comparison-between-the-two-cheap-subsetting-rules, sampling-validation-tasks-by-outcome-variance-cut-a-harness-search-from-117-to-30-dollars-and-landed-within-one-task-of-full-set-search, adaptive-item-selection-reproduces-full-benchmark-rankings-at-80-to-99-percent-lower-cost-so-eval-set-size-is-a-dial. This one runs the matched-size control and the margin is thin with overlapping error bars on three of four benchmarks. Selecting for verifier quality is worth doing because of what a weak verifier does to your conclusions, not because it buys points.

The two justifications should not be conflated, and the paper conflates them. Dropping 70% of a pool is a real saving whatever it does to scores; the audit that identifies which 70% is separately worth having because a VERIFIER-TOO-WEAK item produces a number that is wrong rather than merely noisy. Quoting "106%" for a selection effect that is +1.7 against the honest control is the kind of baseline choice this vault has flagged before, and it is the same shape as screening-for-tasks-sensitive-to-the-intervention-makes-a-harness-effect-measurable-and-inflates-the-number-it-reports.

What it does confirm. Cutting the pool to under 30% did not hurt. That is the finding the cost theme actually needs and it is consistent with everything else here: most of a large item pool contributes nothing, per most-of-an-89-task-pool-was-always-or-never-solved-by-both-starting-harnesses-which-is-why-a-fixed-validation-set-wastes-its-budget.

Bounds. The measurement is downstream RL performance, not eval fidelity, so it is an indirect proxy for whether the retained items are better evals. One base model at 8B for the controlled comparison, four benchmarks, error bars reported and overlapping on most cells.
