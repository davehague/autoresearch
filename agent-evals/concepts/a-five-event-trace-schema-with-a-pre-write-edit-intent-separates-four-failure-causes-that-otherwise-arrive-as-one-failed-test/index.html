A five-event trace schema with a pre-write edit intent separates four failure causes that otherwise arrive as one failed test

Grounded in working-set-of-a-coding-agent-coherence-debt; belongs to evals-that-localize-the-fix.

"Historical tool logs expose actions and observations but not the facts that justified a write." The proposed replacement is five event types, each carrying a run id, monotone event id, timestamp, actor and payload, with file versions advancing on every edit including a restoring one:

  • file_read — path, observed repository/file version, byte range. "What source reached an actor; asserts no semantic extraction by itself."
  • fact_extracted — fact identifier and value, source span and version, acquisition mode (read, prompt supply, or handoff).
  • edit_intent — target and base version, required facts, relied-on fact versions, proposed transformation. Emitted before the write.
  • test_feedback — command, oracle result, diagnostics, contradicted intents.
  • revert — restored content and version, reverted intent, triggering feedback. "An explicit compensating write, not a reversal inferred from a later diff."

The payoff is stated as a separation: the stream distinguishes "four causes that otherwise end in the same failed test: (i) a working-set miss, where a required fact has no current extraction for the editing actor; (ii) a stale read, which relies on a fact from an obsolete source version; (iii) a handoff gap, where a current fact held by a parent never reaches the assigned worker; and (iv) a speculative write, an uncovered intent later contradicted and undone."

Each of those four has a different repair, which is the whole point. "A reread repairs a missing or stale fact but not a handoff policy, serialization removes cross-worker gaps at the cost of time, and a stronger prior covers a fact with no read event." That is the theme's ambition stated exactly: a failed test that names its own repair owner. Compare assigning-each-failure-mode-to-a-component-edge-and-a-fault-side-turns-an-eval-score-into-a-repair-owner, which does the same job by taxonomy after the fact; this does it by instrumentation during the run.

edit_intent is the load-bearing and least conventional element: the agent declares what it thinks it is relying on, before it writes. No harness in this vault logs anything of the kind. It is what makes the shortfall visible ahead of the outcome rather than reconstructed from it — and it is the direct answer to a-read-derived-coverage-score-returned-a-perfect-1-000-in-the-condition-where-nothing-was-available-because-the-agent-filled-the-hole-itself, because it records the claimed support set at a moment before the agent has papered over the gap. The authors are careful about what it is worth: it "exposes missing and stale support before the outcome but requires external validation rather than establishing ground truth." A declared intent is a claim, not a measurement, and it inherits every problem the vault has recorded about grading an agent's own narration — an-agents-recorded-plan-recovers-only-part-of-the-true-prerequisite-structure-so-grading-against-the-plan-grades-the-narration is the same trap one layer up.

It is an adoptable artifact made of knowledge rather than code, in the sense a-versioned-catalog-of-193-gated-practices-with-an-evidence-ledger-is-an-adoptable-artifact-made-of-knowledge-rather-than-code introduced. Nobody ships this; you implement it. What you take from the source is the decision about what to record, and the two design choices worth taking on their own — versioned reads (a file_read without the observed version cannot distinguish a stale read from a miss) and explicit reverts (a compensating write recorded as an event rather than inferred from a later diff).

Bounds. A specification, not a result — no harness implements it, nobody has reported what it costs to emit or whether the four causes are separable in practice on real runs. The paper's own experiments use "coarser proxies" and the schema is offered as what a future coherence-aware harness should retain. Its central event depends on the agent truthfully reporting its own support set, which is unvalidated. And it is scoped to repository-scale code editing; the fact-and-version vocabulary does not obviously carry to agents whose work is not file edits.
